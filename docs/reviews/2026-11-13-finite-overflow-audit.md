# 2026-11-13 有限値のあふれと非有限値の扱いの監査

## 対象と判定の境界

- 対象: `926af7f`。外部監査が挙げた 3 件（欠陥 1〜3）を製品のコードと再現テストで確かめ、同じ型の誤りを同じ経路とほかの経路で探した。
- 精読したのは、音の値を足す・掛ける・狭める箇所の全てである。
  - エンジン: `mix.rs`（フェーダー）、`playback.rs`（クリップの面、フォルダバス、マスター、ガード、メトロノーム）、
    `plugins.rs`（段の入力・配置音声の合流・非有限値の検査・遅延線）、`voice.rs`、`declick.rs`、`plugin_declick.rs`、
    `delay.rs`、`meter.rs`、`audition.rs`、`render.rs`。
  - 機器の出力: `echode-audio-io` の `clips.rs`（素材の準備）、`stream.rs`・`audition.rs`（機器への書込み）。
  - 書出し: `echode-cli` の `lib.rs`（WAV の書込み）と `normalization.rs`。
- 抜き取りで見たのは、取込み（`echode-history/src/media.rs`）、モデルの値の範囲、Swift の dB 表示である。
- 機器・実画面・聴感は使っていない。値は製品のバッファと書出しのファイルで確かめた。
- 製品のコードは変えていない。追加したのは、この記録、索引とデバッグ手順の追記、再現テスト、試験用プラグインの `huge` である。

## 総評

外部監査の 3 件は、どれも成立する。ただし欠陥 1 の「減衰して範囲へ戻ったフレームだけ突然大音量が出る」は成立しない。
範囲へ戻った最初の標本はまだ +18 dBFS を大きく超えるので、マスターのガードがその標本から無音にする。
機器へガードを超える値は出ない（`a_device_never_hears_an_overflow_decay_into_range` で確かめた）。
機器で起きるのは、**理由の記録がない無音**である。書出しで起きるのは、**成功として書かれる無音のファイル**である。

3 件の根は 1 つである。[ADR 0282](../decisions/0282-plugin-nan-and-master-auto-mute.md) の「残る範囲」は、
フェーダー・マスターの「非有限値を 0 にする」処理を「段の検出の後は届かない値の防御」と書いた。
これは、有限の入力からは有限の値しか生まれないという前提に立つ。
実際は、有限の値の積と和が f32 を超える。その値を作るのはプラグインではなくホスト自身の演算なので、段の検出は通らない。

同じ型を探して、外部監査にない 3 件を見つけた（NFA-03・06・07）。
うち NFA-07 は値の大きさに関係なく起きる。普通の NaN の障害で、PDC の遅延がある親トラックだけ、再生し直しても戻らない。

発生の条件は正直に書く。NFA-01〜05 は、標本が 1e31〜3.4e38 の範囲にないと起きない。
普通の音声と、暴走して値が育つプラグインでは、そこへ届く前にガードが止める。
届くのは、float の WAV にその値が入っている時と、プラグインが初期化していないメモリを返す時である。
したがって耳と機材の危険ではなく、起きたことを隠す誤り（ADR 0281 の Transparent）と、書出しの値を黙って変える誤りである。

## 指摘の詳細

### NFA-01 フェーダーの積のあふれ

- **事実**: `FaderState::add` は `scaled(sample, gain)` を f32 で計算し、結果が有限でなければ 0 を返す。
  ピークもその 0 から取るので、トラックのメーターは空になる。フェーダーは 4.0 まで許す（`GAIN_MAX`）。
- **再現**: `crates/echode-engine/tests/audit_overflow.rs` の
  `audit_nfa01_an_export_does_not_write_silence_where_the_fader_overflows`（3.0e38 の音声、フェーダー 2.0。書出しは全標本 0 で成功）と
  `audit_nfa01_a_device_reports_a_fader_overflow`（機器の経路。出力は 0、メーターは 0、自動ミュートの記録なし）。
- **契約との差**: ADR 0281 は「書出しの値は変えない」「音を作り変えて正常に見せない」と決めた。0 への置換は両方に反する。
- **直し方の案**: フェーダーの積を f64 で計算し、そのまま f64 のバスへ足す。ピークも f64 の積から取り、f32 を超えたら `f32::MAX` を出す
  （`TrackMeter::publish` は既に非有限値を `f32::MAX` にする）。値を 0 にする分岐はなくなる。
  積を f64 にすると既存の音が変わらないことを、`block_size` の全件と基準音声で確かめる（f32 の積を f64 へ広げた値と、f64 の積を最後に狭めた値は丸めが違い得る）。
  変わるなら、あふれた標本だけを別扱いにする。

### NFA-02 マスターの和のあふれ

- **事実**: `Prepared::render` は f64 の `mix_left`・`mix_right` を `finite_f32` で f32 へ狭め、有限でなければ 0 にする。
  `guard_master` はその後に呼ばれるので、0 しか見ない。書出しはガードを使わず、0 がそのままファイルへ入る。
- **再現**: エンジンの `audit_nfa02_*` 2 件（2.0e38 の 2 トラック。メーターは 2.0e38 を示し、マスターは 0、自動ミュートなし）。
  製品の経路は `crates/echode-cli/tests/render.rs` の
  `audit_nfa02_an_export_of_an_imported_file_does_not_replace_its_overflow_with_silence`
  （float の WAV を取り込み、2 トラックへ置いて書き出す。`render_to_wav` は成功し、ファイルは全標本 0）。
- **直し方の案**: 狭めた結果が有限でない標本を、0 ではなく障害として扱う。
  - 機器: `guard_master` に f64 の和を見せる（狭める前に判定する）。あふれた標本は NaN と同じく、その標本からマスターを自動ミュートする。
    `MasterAutoMute::peak` は `f32::MAX`（または無限大）を持てばよい。
  - 書出し: 型付きのエラーにして、最初の標本の位置を示す（ADR 0247 の「隠さずエラーにする」）。

### NFA-03 フォルダバスの和を f32 に狭める

- **事実**: `Block::sum_children` は子のフェーダー後の和を f64 で作り、親のクリップの面（f32）へ `finite_f32` で足す。
  親のフェーダーはその後にある。子の和が f32 を超えると、親のフェーダーが範囲へ戻す場合も 0 になる。
- **再現**: `audit_nfa03_a_folder_bus_keeps_a_sum_its_fader_brings_back_into_range`。
  2.0e38 の子 2 本、親のフェーダー 0.25 で、正しいマスターは 1.0e38（f32 で表せる）だが、書出しは 0 である。
- **既知との関係**: [ADR 0338](../decisions/0338-folder-bus.md) の後に入った箇所で、ADR 0282 の「残る範囲」の列挙にない。
- **直し方の案**: 親の面は f32 のまま保つ（プラグインへ渡す形だから）。狭める時に有限でなければ、NFA-02 と同じ障害にする。
  原因のトラックは親と特定できるので、親トラックの自動ミュートにできる。

### NFA-04 素材の不変条件がエンジンの入口にない

- **事実**: 標本の有限性と `(window.peak * placement.gain).is_finite()` は `echode-audio-io/src/clips.rs` だけが確かめる。
  `Prepared::new` は `clip_gain_allowed`・左右の長さ・トラックの有無だけを見る。`set_cached_tracks` は標本を見ない。
  `faded_sample` は `sample * gain * promotion * pair_gain` を f32 で計算するので、積が無限大になり、フェードの端（係数 0）で NaN になる。
- **再現**:
  - `audit_nfa04_the_engine_refuses_a_clip_whose_gain_overflows_its_samples`（プラグインなしのトラックは無音で成功）。
  - `audit_nfa04_the_engine_refuses_a_cached_track_with_a_nan`（NaN の入ったキャッシュを受け取る）。
  - `hosted_playback/overflow.rs` の `audit_nfa04_an_effect_never_receives_an_infinity_from_placed_audio`
    （実ヘルパー。先頭のエフェクトが無限大を入力に受け取り、その装置が自動ミュートの原因として記録される）。
- **範囲**: 製品の読込み（機器の再生、CLI・GUI の書出し）は `prepare_media` を通るので、利用者はこの経路へ届かない。
  届くのは `set_clip_loader`・`render_offline_blocks_with_clips`・`set_cached_tracks` を直接呼ぶコードで、今はテストだけである。
  Phase 3 のレンダリングキャッシュは `CachedTrack` を使う予定なので、その実装の前に入口を塞ぐ。
- **同じ規則の別の現れ**:
  - モデルはクリップゲインを 2^20 まで許し、素材のピークを知らない。ピーク 1e33 の素材に大きなゲインを付ける編集は確定し、
    その後の読込みが `PlaybackError::Media` で断られる。表示は「audio file could not be read」で、原因（ゲインと素材の積）を言わない。
  - 取込みは素材のレートで有限性を見る。機器のレートへの変換の後に有限でなくなった時も、同じ `Media` になる（`device_planes` の後の `Planes::new`）。
- **直し方の案**: 検査を 1 か所へ集める（ADR 0276 の「同じ規則を層ごとに別の論理で実装しない」）。
  `LoadedClip` と `CachedTrack` を、有限性とピークを確かめた型（作る時に検査し、ピークを持つ）にして、`echode-audio-io` もその型を作る。
  `Prepared::new` はピークとゲインの積だけを見るので、PCM の走査は増えない。断る理由は `Media` と分けた型にする。

### NFA-05 ホストの和のあふれを音源の障害にする

- **事実**: `TrackHost::advance` は `mix_injected`（配置音声と子のバスを音源の出力へ f32 で足す）の後に `contain_nonfinite` を呼ぶ。
  和が f32 を超えると、その段の装置が `FAULT_NONFINITE` と `StageFault` に入る。昇格したモノの音源（`dry * FRAC_1_SQRT_2 + source`）も同じである。
- **再現**: `hosted_playback/overflow.rs` の `audit_nfa05_an_instrument_is_not_blamed_for_the_sum_with_its_tracks_clip`。
  試験用プラグインの `huge`（有限の 2.0e38 を書く）と、同じトラックの 2.0e38 のクリップで、自動ミュートの原因が音源になる。
  対照の `a_loud_finite_instrument_is_not_a_faulty_device` は、音源だけなら障害にならないことを保つ（ADR 0282 の「段ごとの大きさは見ない」）。
- **重さ**: 条件は狭い（両方が 1e31 以上）。その時トラックを止めること自体は正しい。誤っているのは理由だけである。
  書出しは「device … returned a NaN or an infinity」で断り、利用者を正常なプラグインの調査へ向かわせる。
- **直し方の案**: 検査を 2 回に分ける。遅延と合流の前に音源自身の出力を調べ、合流の後の非有限値は装置なしの障害（トラック自身の合流）として記録する。
  NFA-07 も同じ並べ替えで直る。

### NFA-06 試聴の出力にガードがない

- **事実**: サンプルの試聴は別の IOProc で、`AuditionAudio::mix` の結果をそのまま `write_planes` で機器へ書く。
  マスターのガード（+18 dBFS）は再生のエンジンだけにある。試聴の音量は 0〜1 で、下げることしかできない。
  差し替えの時は前の声の 5 ms の減衰と新しい声を f32 で足す。モノの機器では `(left + right) * FRAC_1_SQRT_2` も f32 である。
- **再現**: `audit_nfa06_an_audition_past_the_guard_does_not_reach_the_device`（+40 dBFS の有限の音がそのままバッファに入る）と
  `audit_nfa06_an_audition_never_writes_an_infinity`（3.0e38 の音を差し替えると、バッファに無限大が入る）。
- **なぜ重いか**: ここは NFA-01〜05 と違い、普通に起き得る。壊れた float のファイルに最初に出会うのはブラウザの試聴で、
  ADR 0282 がマスターにガードを置いた理由（暴走した値を機器へ出さない）がそのまま当てはまる。無限大を受けた機器の挙動は機器による。
- **直し方の案**: 試聴の出力に同じガードを置き、超えた標本から無音にして、試聴の状態（`audition` の段階）に理由を出す。
  次の試聴で解除する。聴感は実機の確認になる。

### NFA-07 遅延線の NaN が解除の後に戻る

- **事実**: `mix_injected` は段 0 の音源の出力を `instrument_delay`（子の経路に合わせる PDC の線、ADR 0339）へ通してから、`contain_nonfinite` を呼ぶ。
  音源が NaN を書く間、線には NaN が入る。再生の開始は自動ミュートを解除してプラグインをリセットするが（`release_auto_mutes`）、線は空にしない。
  解除の直後のブロックで線の NaN が出て、同じトラックがもう一度自動ミュートされる。
- **再現**: `hosted_playback/overflow.rs` の `audit_nfa07_a_delayed_instrument_sounds_again_once_its_auto_mute_is_released`。
  親に `nan` の音源、子に 64 フレームの遅延を置く。再生し直した後も親は自動ミュートのままで、音源の 0.5 は聞こえない。
- **契約との差**: ADR 0281 の Frictionless Recovery（原因の状態も一緒に戻し、同じ異常をすぐに繰り返さない）と、
  ADR 0282 の「解除の時は、原因のプラグインの処理状態を戻してから音を通す」。遅延線は ADR 0282 の後に入った。
  もう一度再生すれば線は入れ替わって戻るが、利用者には 1 回目が効かない理由が分からない。
- **直し方の案**: 検査を遅延の前へ移す（NFA-05 と同じ並べ替え）。線には 0 しか入らないので、解除で空にする必要もなくなる。
  記録の位置（`fault.frame`）は聞こえる位置からずれるので、線の長さを足して合わせる。

### NFA-08 書出しの拒否が届かない

- **事実**: `echode-cli` は PCM16・24 とノーマライズで非有限値を拒否する（`NonFinitePcm`、`NonFiniteNormalized`）。
  エンジンはマスターで全ての非有限値を 0 にするので、製品の描画からこの分岐へ値は届かない。届くのは `write_wav` を直接呼ぶ時だけである。
  float32 の書出しには検査がない（ADR 0247 が従来どおりとした）。
- **影響**: 「NaN・無限大はエラーとし、無音へ隠さない」（ADR 0247）は、書込みの境界では守られているが、製品全体では逆になっている。
- **案**: NFA-02 の修正で、エンジンが書出しへ型付きのエラーを返す。書込み側の検査は、その後も最後の防御として残す。
  float32 にも同じ検査を置くかは、その時に決める。

### NFA-09 確かめて問題がなかった項目

- メトロノーム: 狭めた後のマスターへ足す。クリックは 1 以下で、`f32::MAX` に足しても値は変わらない。ガードの前である。
- `OutputDeclick`: ガードの後で動く。継ぎ目の加算は ±16 の範囲に収まり、非有限値を消す分岐へ届く値はない。
- `PluginDeclick`: 段の検出の後で動き、f64 の内挿で有限の極値を保つ。
- 遅延線（`Delay`）とバイパス・段の間の複写: 値を写すだけで、演算がない。
- 自分の音のゲート（`GateRamp`）と停止の減衰・ループの継ぎ目: 0〜1 の係数を掛けるだけで、有限の入力は有限のままである。
- 同じトラックのクリップの重なり: モデルが重なりを拒否するので、面への加算は 1 フレームに 1 クリップである。
- ノーマライズ: 係数は f64 で、`|標本| ≤ ピーク` なので結果は目標以下である。
- フェーダーの値: モデル・プレビューとも有限と範囲（0〜4、-1〜1）を確かめる。プラグインのパラメーターは親とヘルパーの両方が有限を確かめる。
- 取込み: 復号した全標本の有限性を確かめる。有限の大きな値は受け取る（仕様。float の素材は 0 dBFS を超えてよい）。
- Swift の dB 表示: 0 と非有限値を分けて扱い、`master_auto_mute` の NaN は `null` で受ける。

## 直す順番の案

1. NFA-07（普通の障害で起きる。検査を遅延と合流の前へ移す。NFA-05 も一緒に直る）。
2. NFA-06（普通のファイルで起きる。試聴のガード）。
3. NFA-02・03・01（あふれを 0 ではなく障害にする。書出しは型付きのエラー、機器は自動ミュート）。NFA-08 はここで閉じる。
4. NFA-04（素材の型。Phase 3 のキャッシュの前）。

1 と 3 は ADR 0282 の「残る範囲」の記述を置き換えるので、修正の時に ADR を足す。
