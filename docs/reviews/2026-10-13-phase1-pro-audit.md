- 状態: **修正済み（2026-10-13）**。[ADR 0075](../decisions/0075-declared-audio-ports.md)。非アクティブなメインスレッドで audio-ports を調べ、宣言どおりのポートとチャンネルで `process` する。拡張がないプラグインは、内蔵音源へ置き換える前に理由付きで拒否する。トラックへ返すのは最初の出力ポートで、複数チャンネルは平均する。下記は監査対象 HEAD の修正前の記録である。
- 区分: 実用 CLAP との互換性の未完成。実行確認済み。

- 親は常に入力2・出力2チャンネルを選び、ヘルパーは入力も出力も最大チャンネル数で確保する。CLAP の audio-ports 拡張を照会する経路がない。ヘルパーが `process` に渡す配列も、常に1入力ポート・1出力ポートである。
- 再現: 正規の audio-ports 拡張で「入力0、モノ出力1」を宣言する監査用楽器を作った。適切な共有領域0/1でも `fits` が偽になり、期待値0.25の音は無音の `Ok(0.0)`。製品が使う2/2では楽器がポート不一致を拒否し、ヘルパーが終了した。

- 外部根拠: CLAP は process のポート数と宣言の一致を要求する。[process.h](https://github.com/free-audio/clap/blob/main/include/clap/process.h)、[audio-ports.h](https://github.com/free-audio/clap/blob/main/include/clap/ext/audio-ports.h)。

- 根拠: [plugins.rs](../../crates/echode-engine/src/plugins.rs)、260・321行。[threads.rs](../../crates/echode-plugin-host/src/threads.rs)、647行にも同じ reserve の誤用がある。

### PRO-06 / P1: 短いループを1ブロック内で複数周回すると、再生全体が止まる

- 状態: **修正済み（2026-10-13）**。[ADR 0077](../decisions/0077-event-reserve.md)。制御スレッドで、ノート数にブロック長を掛けたイベント領域を用意する。100サンプルのループは、64フレームでも512フレームでも失敗せず音が残る。下記は修正前の記録である。
- 区分: 新規。製品の公開 API で実行確認済み。
- 根拠: [playback.rs](../../crates/echode-engine/src/playback.rs)、196・211・373行。
- イベント領域は全ノート数×3程度で準備する。区間領域は短いループを想定しているが、同じブロック内で繰り返し発生するノートオン・オフの量を考慮していない。
- 再現: 48 kHz、長音1つ、100サンプルのループ。64フレームなら継続、512フレームでは `failed=true, playing=false, sample=0` で全体が無音。同じ音楽がブロックの長さで再生不能になる。
- 対応: ループ長と最大ブロック長から必要量を用意するか、区間ごとに作業領域を再利用する。比較テストの24,000サンプルのループだけでは複数周回を捕まえられない。

### PRO-07 / P1: CLAP の処理失敗・起動失敗を含む WAV が成功として完成する

- 状態: **修正済み（2026-10-14）**。[ADR 0079](../decisions/0079-failed-export.md)。書き出しは全デバイスの起動と各ブロックの処理成功を要求し、失敗したら WAV を残さない。ライブ再生の期限超過は無音のままで、`failed` は立てない。下記は監査対象 HEAD の修正前の記録である。
- 区分: AUD-10 の修正不足。公開再生 API と実際の CLI 書き出し関数で実行確認済み。
- 根拠: [plugins.rs](../../crates/echode-engine/src/plugins.rs)、133・293行。[CLI lib.rs](../../crates/echode-cli/src/lib.rs)、219行。
- 起動失敗は `continue` で飛ばす。処理失敗・ハング・クラッシュはブロックを無音にするが、`PlaybackStatus.failed` に反映しない。書き出しはそのフラグしか確認しない。
- 再現: 再生 API では crash/hang が `failed=false, playing=true, peak=0`。さらに実際の `render_to_wav` で、正規 CLAP が process を拒否した場合に `Ok(())` と全 PCM 無音の WAV、ファイルは存在するが ID の生成に失敗した場合に `Ok(())` と内蔵シンセの WAV が完成した。
- 対応: 書き出しには全デバイスの起動・処理成功を要求する。再生中の期限超過による無音化を、完成ファイルの成功条件に使わない。失敗はデバイス ID・理由を伴って返し、不完全な出力を完成品として残さない。
- 必須検査: キャッシュ欠落だけでなく、生成・activate・process の失敗、途中クラッシュ、ハング、後段だけの失敗。

### PRO-08 / P1: ヘルパーの音声処理にメモリ確保・解放とスピンロックが残る

- 状態: **修正済み（2026-10-14）**。[ADR 0080](../decisions/0080-helper-realtime.md)。制御スレッドがバッファを用意し、処理スレッドは入れ替えるだけにする。ポート配列と停止プロセッサの `Box`、処理側の無期限ロックをやめた。デバッグのヘルパーは処理区間の確保で止まり、RTSan も同じ区間を見る。下記は監査対象 HEAD の修正前の記録である。
- 区分: 製品経路の検査不足。イベント変換の確保は実行確認、他の経路はコード確認。
- 根拠: [threads.rs](../../crates/echode-plugin-host/src/threads.rs)、91・596・647・693・976行。[events.rs](../../crates/echode-plugin-host/src/events.rs)、22行。
- `EventBuffer::new()` の空バッファへ初回の process で push する。既存の公開 `write_input` を確保計数器で囲うと、ノート1つで2回確保した。共有領域拡張後は処理スレッド自身が decoded を reserve する。再起動では停止プロセッサを Box に入れる・取り出す処理が確保・解放を伴う。マッピング交換は処理側でも `lock_map` の無期限スピンを使う。
- 「バッファは開始時に一度確保する」という ADR 0049 とコメントを満たしていない。現在の `rtsan` と確保検出は本体のシンセ・計画交換・HAL バッファを検査し、ヘルパーのこの処理を覆わない。
- 対応: 制御側で完全に準備したバッファを渡し、古い資源は制御側で回収する。処理側の共有状態交換を無期限のロック待ちにしない。ヘルパー本体にも冷えた初回・容量拡張・再起動の確保検出と RTSan 検査を追加する。

### PRO-10 / P2: 失敗から戻すため、各編集の前に全編集履歴を複製する

- 状態: **修正済み（2026-10-14）**。[ADR 0083](../decisions/0083-history-commit.md)。Redo だけを退避し、追記の失敗では積んだ 1 件を外して戻す。Undo の履歴は複製しない。ノート順序の記録は [ADR 0084](../decisions/0084-note-diff.md)。下記は監査対象 HEAD の修正前の記録である。
- 区分: MOD-12 の未解決に AUD-03 の修正が追加した負荷。Release 計測済み。
- 根拠: [host.rs](../../crates/echode-history/src/host.rs)、339・359・378行。[session.rs](../../crates/echode-actions/src/session.rs)、35行。
- `Session::clone()` は現在の Project だけでなく、Undo / Redo の各版、全ジャーナルの Action / ChangeSet を複製する。ノート追加の差分は変更前・変更後のノート順序配列を持つため、累積履歴自体が二次的に増える。

### PRO-13 / P2: 編集 API の組み合わせで整数境界を越え、不正状態や panic になる

- 状態: **修正済み（2026-10-14）**。[ADR 0086](../decisions/0086-checked-time.md)。原点、ノートの絶対終端、不変条件の小節計算は、変更前に検査付き演算で拒否する。下記は監査対象 HEAD の修正前の記録である。
- 区分: 不変条件の境界漏れ。Debug / Release で実行確認済み。
- 根拠: [model.rs](../../crates/echode-model/src/model.rs)、810行。[placement.rs](../../crates/echode-model/src/placement.rs)、468行。[invariants.rs](../../crates/echode-model/src/invariants.rs)、185行。
- `resize_clip(start=i64::MIN,length=1)` の後に `link_clip(start=0)` すると操作は成功するが原点が計算できない。MAX側の窓・リンク・ノート追加の組み合わせは中身のノート終端が溢れる。Debug の Session は panic、Release の Model は不正状態を返す。極端な不正 Auto 配置の読み込みでも、不変条件検査自身の乗算で panic した。
- 対応: 原点・変換したノート終端・リンク先の絶対時刻を、変更前に checked arithmetic で検証する。不変条件検査も不正入力を panic せず拒否する。
- 必須検査: MIN / MAX 近傍、非ゼロ offset、リンク配置の組み合わせを生成し、拒否後に状態が維持されることを確認する。現在の短い時間範囲の proptest は届かない。

### PRO-14 / P2: 完了コールバックから文書を停止すると、自己 join で abort する

- 状態: **修正済み（2026-10-14）**。[ADR 0087](../decisions/0087-callback-shutdown.md)。ワーカー自身からの停止と解放は `join` しない。別スレッドからの停止がハンドルを待つ。下記は監査対象 HEAD の修正前の記録である。
- 区分: C ABI の再入・所有権契約の穴。実行確認済み。現在の Swift 包みの通常 callback では行わないため P2。
- 根拠: `crates/echode-ffi/src/queue.rs`（当時）、101・513行。[lib.rs](../../crates/echode-ffi/src/lib.rs)、276行。
- 正常に作った文書へ snapshot を問い合わせ、成功 callback 内から、まだ所有する同じ文書の shutdown を呼んだ。`Resource deadlock avoided` の自己 join panic が C ABI 境界へ出て **SIGABRT (-6)**。無効なポインタや二重解放は使っていない。ヘッダにこの呼出しの禁止もない。
- 対応: worker 自身からの停止・最終解放を安全に処理するか、完了の配送を worker 外へ分ける。callback 内の停止・最終解放・再送と、外部停止との競合を検査する。

### PRO-15 / P2: スキャン結果を読み始めるのが遅く、正常な大量出力をハング扱いする

- 状態: **修正済み（2026-10-14）**。[ADR 0088](../decisions/0088-scan-pipes.md)。子の実行中に標準出力と標準エラーを読む。標準エラーは 64 KiB で打ち切り、読んだスレッドは期限でも成功でも待ち終える。下記は監査対象 HEAD の修正前の記録である。
- 区分: 新規。公開スキャン関数で実行確認済み。
- 根拠: [scan.rs](../../crates/echode-plugin-host/src/scan.rs)、159〜185行。
- stdout / stderr を pipe にした子の終了を先に待つ。パイプ容量を超える出力は子の書込を止めるので、正常な処理でも5秒後に kill する。失敗はそのバンドルの版としてキャッシュされ、変更まで再試行されない。
- 再現: 即座に正規 JSON を書くだけの監査用 helper で、名前1,024文字の1記述子は成功、128記述子は5.025秒で `plugin scan timed out`。実際の CLAP バンドルを大量生成した試験ではなく、終了・pipe 処理の再現。
- 対応: 子の実行中から両方を読み、必要な出力を段階的に解析する。stderr は容量を制限して排出する。期限と中断、読込スレッドの終了も一体で管理する。

### PRO-16 / P2: 書き出し版の ID と成功表示が、実際の出力を特定しない
