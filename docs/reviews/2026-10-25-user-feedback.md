# 2026-10-25 操作の報告と追加の要望の照合

ユーザーから届いた問題 6 件と追加の要望 2 件を、操作要件・ADR・実装に照らして確認した。
問題は機器と実画面を使わない製品経路の回帰で再現してから直した（FB-02 を除く）。
アプリの起動、実画面の操作、機器を開く検査はしていない。操作感と聴感はユーザー担当である。
この記録は発見時点の証拠であり、対応後も書き換えない。

## FB-01: 開始位置の変更で一瞬操作できない

- ルーラーのクリックと「開始拍」欄は `transport.set_start` を送る。応答は `transport.json` の書込みと位置移動の後に返る。
- 応答待ちの間、`ProjectController.audioBusy` がメトロノーム・「移動」・ループのボタン、両ルーラー、ループ・メトロノーム・出力・新規・開くのコマンド
  （ツールバーを含む）を無効にした。ルーラーは無効の間の押下を捨て、再生以外の要求も捨てていた。
- 再現: `TransportOrderTests` で最初の応答を保留し、修正前の判定でロック・コマンド・ルーラーの 2 回目のクリックの 3 つが失敗した。
- 対応後は再生・停止以外を順番待ちにし、操作子は文書の交換・終了の間だけ無効にする。

## FB-02: サンプル一覧での Space

- Space はメニューの「再生／停止」（修飾キーなし）である。トラックヘッダは Space を上位へ渡す（CU-05）。
- 一覧の表（`FileListTable`）を、ウィンドウなしとキーにならないウィンドウのテストで調べたところ、Space を上位へ渡していた。
  製品で止まる場所は再現していない。候補は、メニューの文字入力中の判定（`workspaceTextEntry`）が一覧のフォーカスで残る経路と、
  SwiftUI の上位の部品がキーを受ける経路である。
- 対応後は一覧が Space を受けて「再生／停止」を直接呼ぶ。止まる場所の特定は、実画面でのユーザー確認の結果を待つ。

## FB-03: 波形の表示

- [ADR 0151](../decisions/0151-streaming-sample-audition.md) は、試聴した素材だけの部分波形を、未試聴の先行読込みやキャッシュなしで表示すると決めていた。
  自動試聴をオフにした選択では波形が出ず、試聴の報告が消えると波形も消える。長い素材は再生に合わせて伸びる。
- 「切り替えたらすぐ全体が表示されるのが好ましい」という希望を受け、選択で全体を別に読み、直近のものを保持する設計に改めた。

## FB-04: 置いたサンプルの自動フェード

- `Project::place_audio` が新しい配置の両端に `DEFAULT_FADE_FLICKS`（5 ms）を付けていた。
  ブラウザのダブルクリック・Return・ドロップ、Finder のドロップ、「音声を取り込む」、CLI と MCP の取込みが同じ経路である。
- 対応後は 0 で置く。以前のジャーナルは 5 ms で再生する。フェード 0 のハンドルがクリップの端から外れて押せない問題も同時に直した。

## FB-05: FX の候補一覧

- SwiftUI の `List` の行の文字の部分にだけダブルクリック・ドラッグ・メニューを付けていた。
  行の余白のダブルクリックは追加されず、再走査中（フォルダの監視の新しい版のたび）は追加をすべて拒否していた。
  [ADR 0143](../decisions/0143-browser-click-and-audition-timing.md) が「候補の一覧に同じ構成が残る」と記録していた箇所である。
- 重さの量は計測していない。選択と検索のたびに全行の SwiftUI の部品を作り直していたことは、ソースで確認した。

## FB-06: ノートの端からの再生

- 追いかけの集合が終端ちょうどのノートを含み、追いかけのノートオンが同じ時刻のノートオフの後に並んだ。
  ルーラーの吸着で開始位置がノートの終端と一致しやすい。
- 再現: 実ヘルパーの楽器で、ノートの終端への位置移動から再生した出力が余韻の分を過ぎても鳴り続けた
  （手元の証拠 `target/note-edge-hold-repro.log`）。

## FB-07・FB-08: 追加の要望

- インスペクターは挿入済みの名前と削除だけを持ち、追加の入口は未定義だった。
- アレンジのノートはレーンの高さの帯で、音高を使っていなかった。
- 両者の要件・時期は [ADR 0165](../decisions/0165-inspector-fx-add-and-arrange-note-pitch.md) と
  [操作要件](../interaction-design.md) に置き、[Phase 2 の進め方](../phase2.md) の P2-02 と P2-07 へ加えた。

## ユーザー確認が必要なこと

- FB-01: 開始位置の変更・ループのドラッグ中に、ボタンとツールバーが暗転しないこと。
- FB-02: 実アプリでサンプル一覧にフォーカスがある時、Space で曲が再生・停止すること。直らない場合は、検索欄に触れた後かどうかを知らせてほしい。
- FB-03: 選択した直後に全体の波形が表示され、試聴の停止で消えないこと。長いファイルでの待ち時間。
- FB-04: 置いた素材の頭と終わりのクリック音が許容できること（必要ならハンドルでフェードを付ける）。
- FB-05: 多数の候補での一覧の軽さと、行のどこでもダブルクリックで追加されること。
- FB-06: 実際の音源で、ノートの終端からの再生で音が残らないこと。
