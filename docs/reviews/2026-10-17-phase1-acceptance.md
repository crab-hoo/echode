# P1完了条件の最終照合（2026-10-17）

対象はPLANの「打ち込んで、鳴らして、残す」。開始時のHEADは`6ed327c`、本作業の差分はループ先頭の保持とフェーダー前の差し替え口、自動回帰と文書である。過去の監査の失敗・未実施は当時の証拠として残す。

## 4つの完了条件

1. **CLAPシンセのあるトラックに打ち込んで再生**: `ProjectTests.insertingAPluginKeepsTheMixerAndSurvivesReopen`、`PianoTests.aDragIsOneDurableEditAndPreservesIdentityAndVelocity`がSwiftのcontrollerから挿入・編集・保存へ接続する。`macos-plugin-bundle` / `plugin-onset`が実バンドル・別プロセス・ノート時刻・音源そのものの波形を検査する。下記の統合契約では復旧した同じノートをCLAPで発音し、無音を拒否する。ピアノのこのテストは全マウス操作やVoiceOverの実操作を通した証拠ではない。
2. **強制終了後の復旧**: `phase1-acceptance`が一時パッケージを編集する子プロセスを作り、トラック・CLAP・ノートの成功応答後に強制終了する。DocumentHostを開き直してIDを含むプロジェクトを回復し、その音を再生・書出しへ渡す。ユーザーが開いているアプリは終了しない。既存のABIの強制終了回帰、ジャーナルの途切れ・失敗・二重書き手の検査も維持する。電源断や任意の同期ソフトへの耐性を認証する検査ではない。
3. **保存履歴への復帰**: 同じ統合契約でチェックポイントを保存し、追加編集後にその版へ戻す。元の履歴が残り、新しい保存版になること、復帰のUndo / Redoと再オープン後の音が一致することを確認する。Swiftの`restoringAnOlderAutosaveBecomesANewUndoableVersion`も既存の履歴操作を通す。
4. **同じプロジェクトのCLI WAVと基準の一致**: 統合契約は実際の`echode render`を実行し、上記プロジェクトの製品再生バッファとWAVのサンプルを比較する。履歴復帰後も同じWAVバイト列になる。固定した基準ファイルとの比較は既存の`a_package_renders_to_the_committed_reference`も維持し、基準音声の再生成はしていない。

統合契約の正式名は`contract_phase1_project_survives_crash_history_and_cli_export`（`crates/echode-cli/tests/render.rs`）。通常検査と必須契約へ登録し、CLI出力を無音へ壊したコピーで失敗することも要求する。入力の固定長は検証範囲であり、製品の長さ上限ではない。

- モデル・アクション・Undo / Redo・保存・オートセーブ・ジャーナル・履歴復帰は上記と既存のhistoryの障害注入・操作列検査へ接続している。
- 再生・停止・ループ・メトロノーム・MIDIと音声配置・rubatoのSRC・ミックス・マスター・ピーク・出力選択と通知処理がある。今回、準備済みPCMをループ変更で読み直す問題を修正した。先頭は計画採用前に全体準備へ含めて保持する。ブロックを変えたループ波形と実際のフェーダー前の差し替え口を必須回帰に加えた（[ADR 0108](../decisions/0108-phase1-loop-readiness.md)）。
