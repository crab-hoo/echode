# Echode 現状監査（2026-10-13）

- 対象コミット: `cf43ef2910a4500046ba3e8e2db0f95e40795592`。着手時の作業ツリーはクリーン。
- 範囲: Rust の製品経路（保存、モデル・アクション、再生、CLAP 隔離、CLI / API、C ABI）、Swift のワークスペース・橋渡し、配布と検査の仕組み。計画、設計、前回監査、関連 ADR と照合した。
- 方法: 実装レビュー、全自動検査、依存の脆弱性検査、一時プロジェクトによる障害注入、無音のヘルパー処理。UI の実操作と聴感検査は含めない。
- この文書は監査結果であり、製品コードの修正は行っていない。第三者認証や網羅的な安全証明ではない。

## 判定

**開発の土台は整っているが、現時点でプロの制作データを預ける品質には達していない。Phase 2 の形式追加より先に、保存の障害処理と製品の CLAP 再生を修正する必要がある。**

新規指摘は 13 件（P0 が 2 件、P1 が 9 件、P2 が 2 件）。新規のうち 11 件は実行で再現し、2 件はコードと仕様から確認した。前回から残る API-3 も再現した。API-3 は前回の P2 から、ファイルを削除する影響を踏まえ、今回は P1 相当として扱う。前回の状態一覧はこの監査では書き換えていない。

今回の優先度は、P0 がデータ消失・通常経路で復旧不能、P1 が制作の正しさ・リアルタイム安全性・Phase 1 の完了を妨げるもの、P2 が拡大前に整える性能・保護の不足である。実装されていない Phase 2 以降の機能を不具合には数えていない。

## 良い土台と、合格の限界

不変スナップショット、ChangeSet、Undo / Redo、モデルの不変条件、スキーマの移行、内容ハッシュによる素材管理が分離されている。CLAP を本体へ読み込まず、ヘルパーで実行する境界もある。音声のブロック長比較、基準 WAV、ランダムな操作列、Swift の厳密な並行性、ASan / TSan / Miri と検査選択の共通化は、継続開発のための有効な安全網である。

ただし、既存の合格ケースが中心としているのは、内蔵シンセ、通常の保存、容量を最初に用意できた再生、橋渡しの寿命・競合である。今回の不具合は、**障害から復旧してさらに編集する経路、複数の書き手、既存ヘルパーを保った編集、CLAP を含む信号と書き出し**の境界に集中した。自動検査の合格から、この境界の安全性までは判断できない。

## 最優先の保存不具合

### AUD-01 / P0: 同じパッケージを二重に開くと確定済みの編集が失われる

- 種類: 再現した不具合
- 根拠: [crates/echode-history/src/host.rs](../../crates/echode-history/src/host.rs)、77 行付近。
- 確認結果: 二つのホストが A と B をそれぞれ成功と返したが、再オープンの結果は A のみ。B が失われた。
- 対応: パッケージの正準パスを単位に、プロセスをまたぐ所有権を取得してから復旧する。二重オープンは拒否するか同じホストへ接続する。
- 完了条件: 二重オープンを同一プロセス・別プロセス・シンボリックリンクの別名から試し、二重の書き手を許さない。成功と返した全操作が強制終了後も残る。
- 対応（2026-10-13）: 正準パスをプロセス内で記録し、`host.lock` をプロセス間で排他する。別プロセスが編集して `_exit` したあとも、その編集は残る。[ADR 0062](../decisions/0062-package-single-writer.md)。

アプリと `echode serve` は、それぞれ `DocumentHost::open` を呼べる。ホスト内のスレッドを一本にしても、パッケージ全体の書き手は一本にならない。再現では二つのホストを先に開き、A の保存完了後に B を編集した。両方が成功と返したが、復旧結果は A のみだった。自動保存の失敗が通知されないことも、消失を見えにくくしている（前回 HIS-4 / HIS-2 に関係）。

### AUD-02 / P0: 途切れたジャーナルから復旧して編集すると、次の復旧が失敗する

- 種類: 再現した不具合
- 根拠: [crates/echode-history/src/document.rs](../../crates/echode-history/src/document.rs)、1147 行付近。
- 確認結果: 未完了の末尾から一度は開けた。続く編集も成功と返したが、次の復旧は「journal entry is not valid」。UTF-8 の途中で切れた末尾は最初の復旧も失敗。
- 対応: 復旧時にバイト列で確定した改行までを判断し、追記開始前に未完了の末尾を切り詰めて同期する。UTF-8 の検証も確定した部分だけに行う。
- 完了条件: 末尾の全バイト位置で打ち切ったジャーナルを、開く → 編集 → 強制終了 → 再オープンする。日本語の名前を含め、確定した操作を復旧できる。
- 対応（2026-10-13）: 最後の改行まで切り詰めて同期してから追記する。UTF-8 は確定した部分だけを見る。全オフセットで「ピアノ」を復旧し、切れた UTF-8 のあとにホストから「確定」を足して開き直せる。[ADR 0062](../decisions/0062-package-single-writer.md)。

`read_log` はメモリ中の文字列を切り詰めるだけで、ディスク上の末尾を修復しない。`append_journal` はその末尾へ新しい JSON を直接追記するため、未完了行が壊れた「完了行」になる。さらに UTF-8 への変換を切り詰める前に行うので、日本語の途中で切れたログも扱えない。読める先端コミットがあっても、`recover` は先にログを解析して失敗する（前回 HIS-2 の完了範囲に穴がある）。

### AUD-03 / P1: 永続化に失敗した操作が、次の成功した操作に混ざって保存される

- 種類: 再現した不具合
- 根拠: [crates/echode-history/src/host.rs](../../crates/echode-history/src/host.rs)、243 行付近。
- 確認結果: ジャーナルを一時的に書けなくして rejected を実行するとエラー。書ける状態にして accepted を実行すると、rejected と accepted の両方が公開・保存された。
- 対応: Session と Undo / Redo を確定前の段階で扱い、ジャーナルの同期成功後だけ公開する。書き込みや同期の成否が不明な場合は追加編集を止め、復旧へ誘導する。
- 完了条件: 追記・部分書き込み・同期の失敗を注入し、プロジェクト、Undo、Redo、公開スナップショットが整合する。失敗した操作を次の操作へ混ぜない。
- 対応（2026-10-13）: 同期に成功するまで公開しない。失敗したら Session を戻す。成否が不明なときは追加編集を止め、開き直すとその操作だけが残る。[ADR 0062](../decisions/0062-package-single-writer.md)。

`session.perform` / Undo / Redo のあとでジャーナルを書き、書き込みに失敗しても Session を戻さない。公開されない変更と実際の Session が食い違い、次の成功で失敗した操作まで公開される。モデル内のトランザクションだけでは、永続化まで含めた原子性を満たせない。

## リアルタイムと制作の正しさ

### AUD-04 / P1: プラグイン計画の交換と大量イベントの整列で音声スレッドが確保・解放する

- 種類: 再現した不具合
- 根拠: [crates/echode-engine/src/playback.rs](../../crates/echode-engine/src/playback.rs)、673 行付近。
- 確認結果: 確保検出を有効にした再生計画の交換と 1,000 件のイベント整列が、ともに SIGABRT（終了コード -6）。
- 対応: HostGraph の Box 自体を往復させ、コールバックで Box を作り直さない。イベント整列は制御側が確保した作業領域を使い、安定した順序を維持する。
- 完了条件: 確保検出と RTSan を有効にし、CLAP 接続済みの再生へトラック・デバイスの追加、削除、並べ替え、Undo / Redo と大量イベントを流す。確保・解放・禁止待機がない。
- 対応（2026-10-13）: グラフの箱を交換する。整列はその場で安定に行い、ヒープを使わない。[ADR 0063](../decisions/0063-audio-thread-plan-swap.md)。空チェインの交換と 1,000 件は確保検出下で通る。接続済み CLAP の Undo / Redo と RTSan は未実施。

計画交換は `*next` で Box の中身を移し、旧グラフを `Box::new(previous)` で包み直す。コールバック上で解放と確保が起こる。プラグインが解決できない空のチェインでも、トラックの構成変更でこの経路に入る。別の再現では [イベント整列](../../crates/echode-realtime/src/event.rs)の `sort_events` に 1,000 件の順序が混在したイベントを渡し、安定ソートの作業領域の確保を検出した。どちらも GuardAlloc を有効にしたデバッグ実行の SIGABRT で、release では禁止操作が消えるわけではなく検出が無効になる。ヘルパー側も `EventBuffer::new()` の容量準備がないため、イベント初回・増加時の確保を別途検査する必要がある（前回 ENG-3 / ENG-12）。

### AUD-05 / P1: プラグインを先に挿すと、その後に追加したノートが取りこぼされる

- 種類: 再現した不具合
- 根拠: [crates/echode-engine/src/plugins.rs](../../crates/echode-engine/src/plugins.rs)、163 行付近。
- 確認結果: 空のトラックにプラグインを挿してから和音を 3 音追加すると、受け取ったノートオンは 1 音。3 音を先に置いてから起動すると 3 音。
- 対応: ノート数の増加に合わせてイベント容量も制御スレッドで更新する。処理中の状態を保ち、ノートオフを黙って落とす処理をなくす。
- 完了条件: プラグインを先に挿してからイベント容量を超えるノートを追加する。ノートオン・ノートオフが全件届き、更新でもプラグインの状態を保つ。
- 対応（2026-10-13）: 並びが同じときは、制御スレッドが生きているヘルパーのイベント容量を広げる。[ADR 0065](../decisions/0065-plugin-event-capacity.md)。空のトラックへ挿してから 3 音を足すと、ノートオンとノートオフが 3 ずつ届く。先に 1 音を鳴らしてから足した 2 音でも、最初のノートオンは残る。

新しい Prepared はノート数に合わせたイベント領域を持つが、チェインが変わらない編集では HostGraph を更新しない。古い Stage と共有領域の容量が残り、`routed.capacity()` に達すると残りを黙って捨てる。挿入順序だけで和音の結果が変わる。テスト楽器は受信したノートオン数を一定の音声値に変換し、同じ3音のプロジェクトで 0.70710677 と 2.1213202 の差を確認した。

### AUD-06 / P1: 再生位置の移動とノート削除でプラグインの音が鳴り続ける

- 種類: 再現した不具合
- 根拠: [crates/echode-engine/src/playback.rs](../../crates/echode-engine/src/playback.rs)、208 行付近。
- 確認結果: ノート終端より先へ移動しても、ノートを削除しても、テスト楽器の出力は 0.70710677 のまま。終了イベントが届かず鳴り続ける。
- 対応: 旧計画で鳴っていたノートへの終了イベントをヘルパーへ届け、移動先の追跡より先に処理する。削除・変更・ループ・停止を同じ契約で検査する。
- 完了条件: CLAP 楽器で、鳴っているノートの削除・音高変更・位置移動・ループを検査する。取り残したノートがなく、ノート ID と実際に開始したキーが一致する。
- 対応（2026-10-13）: 削除・移動・停止は、プラグインへ届いているノートのノートオフを先に置く。音高だけの変更はオフしない。ループの戻りは、既存の再生カーソルが境界でオフしてから頭を鳴らす。[ADR 0066](../decisions/0066-plugin-note-off.md)。削除・移動・停止のあと出力はノートオフ済みの値になり、音高を 60 から 64 へ変えて消すとノートオフのキーは 60 のまま。停止のコールバック自体がオフを届け、そのバッファは無音のまま。

`place` は内蔵シンセを止め、カーソルを置き直すが、旧ノートの終了をヘルパーへ届けない。`carry` も内蔵ボイスを引き継ぐだけで、削除したノートの終了イベントを出さない。再現の終了先には鳴るノートがなく、期待値は 0。停止・一時停止は製品 Session がストリームを閉じる場合もあるため、この再現結果を停止の全経路へ一般化していない。

### AUD-07 / P1: 独立したプラグイントラックが直列に待ち、それぞれに一ブロックの期限を与える

- 種類: 再現した不具合
- 根拠: [crates/echode-engine/src/plugins.rs](../../crates/echode-engine/src/plugins.rs)、149 行付近。
- 確認結果: 48 kHz / 2,048 フレームの一ブロックは 42.67 ms。ハングするトラック 1 本で 43.92 ms、4 本で 175.97 ms 待った（無音・デバッグの障害再現）。
- 対応: 一つのコールバックに一つの絶対期限を渡す。入力のそろった独立トラックには先に依頼を出し、fan-in でまとめて回収する。
- 完了条件: 複数のハング・遅延・クラッシュを含む製品コールバックが、トラック数分の期限を積み上げない。独立した正常トラックの結果を回収し、全体の期限を守る。
- 対応（2026-10-13）: 独立トラックを先に依頼し、一つの絶対時刻で受け取る。[ADR 0064](../decisions/0064-one-callback-deadline.md)。ゲイン 1 本とハング 3 本で、ゲイン後の音が残り、待ちは積み上がらない。クラッシュと遅延の分離は未実施。

各トラックの `HostGraph::process` が呼ばれるたびに `Instant::now() + block_duration` を作り直し、そのトラックが終わるまで次へ進まない。[ADR 0043](../decisions/0043-plugin-submit-collect.md) の「ヘルパーごとに締め切りを足さない」という決定と、製品経路が食い違う。42.67 ms の検証バッファは、ハングの待ちの積み上がりを確かめるためだけのもの。上記の時間は通常負荷、標準バッファ、実機の音切れ率の計測値ではない。

### AUD-08 / P1: 取り込んだ音声がトラックの CLAP エフェクトを通らない

- 種類: 再現した不具合
- 根拠: [crates/echode-engine/src/playback.rs](../../crates/echode-engine/src/playback.rs)、335 行付近。
- 確認結果: 0.25 の音声クリップは、ゲイン 2 の CLAP を挿す前も後も出力 0.17677669。エフェクト入力へ音声が合流しない。
- 対応: シンセと配置した音声を、トラックのエフェクトに入る前に合流する。楽器への MIDI と音声入力の扱いも明示する。
- 完了条件: 音声素材だけ、MIDI だけ、両方を置いたトラックに既知のゲインエフェクトを通し、処理前後の波形を比較する。
- 対応（2026-10-13）: 内蔵シンセと配置した音声を、エフェクトの前で足す。楽器はノートと無音を受け、配置した音声はその出力へ足してから後段へ渡す。[ADR 0067](../decisions/0067-track-audio-into-effects.md)。0.25 のクリップはゲイン 2 のあと 0.35355338 になる。ノートだけ、ノートとクリップの和も、処理前の 2 倍になる。楽器はクリップを入力にせず、出力のあとに足す。

製品の順序は内蔵シンセ → CLAP → 音声クリップの追加 → フェーダーである。音声素材を取り込んだ後のトラックエフェクトとして成立しない。CLAP のゲインが2なら同じ検証サンプルは 0.35355338 になるべきだが、処理前後で変わらなかった。前回の CLAP テストはシンセ入力中心で、この経路を検出しない。

### AUD-09 / P1: 音声クリップのゲインをゼロにしても音が鳴る

- 種類: 再現した不具合
- 根拠: [crates/echode-audio-io/src/clips.rs](../../crates/echode-audio-io/src/clips.rs)、68 行付近。
- 確認結果: 音声クリップの gain を 1 / 0 / 2 にしても、準備された音声の最大値はすべて 0.25。書き出しのピークも変わらない。
- 対応: 配置の gain を準備した音声に掛けるか、実行計画に持たせて再生と書き出しの両方で適用する。
- 完了条件: gain 0 / 0.5 / 1 / 2 が無音・半分・同じ・2 倍になることを、再生と CLI、Undo / Redo、保存・復旧後で確認する。
- 対応（2026-10-13）: 配置の線形ゲインを、準備したサンプルに掛ける。フェードはそのあと。[ADR 0068](../decisions/0068-clip-gain.md)。0.25 の定数は、ゲイン 0 / 0.5 / 1 / 2 で無音・半分・同じ・2 倍になる。再生、CLI、Undo / Redo、保存して recover したあとも同じ比になる。

`clip.set_gain` は API とモデルで値を受け付け、保存する。しかし読み込みで `placement.gain` を使用せず、LoadedClip にも gain を持たない。フェードは接続されているが、ゲインは音へ反映されていない。実際のオフライン出力のピークも、gain 1 / 0 / 2 で全て 0.17677669 だった。[ADR 0022](../decisions/0022-clip-content-and-placement.md) の音声参照後にゲインを接続する約束が残っている。

### AUD-10 / P1: CLAP を含むプロジェクトの書き出しが再生と異なる音になる

- 種類: 製品経路の不足（既存 ADR の制限）
- 根拠: [crates/echode-cli/src/lib.rs](../../crates/echode-cli/src/lib.rs)、128 行付近。
- 確認結果: 同じプロジェクトの同じサンプルで、隔離した楽器による再生は 0.70710677、オフライン書き出しは内蔵シンセの 0.07418562。
- 対応: 書き出しも隔離したデバイスと同じチェイン・状態を使う。実装までの間は該当プロジェクトの書き出しを明示的に拒否する。
- 完了条件: CLAP 楽器とエフェクト、配置した音声を含む同じ版を、再生と CLI で比較する。欠けたプラグインを利用者へ明示する。
- 対応（2026-10-13）: CLAP があるプロジェクトの書き出しは、製品の再生と同じヘルパーとチェインを使う。プラグインかヘルパーが無いときは書き出しを拒否し、欠けた id を出す。ノートだけの基準 WAV は変えていない。[ADR 0069](../decisions/0069-plugin-export.md)。楽器のあとにゲイン 2 を通した 0.25 のクリップは、再生と CLI で同じ 0.35355338 になる。

CLI のレンダラーは TestSynth と配置した音声だけを使い、プラグインの記録を処理しない。これは [ADR 0019](../decisions/0019-offline-wav.md) と [ADR 0057](../decisions/0057-crash-recovery.md) に記載された制限で、最近の変更の偶発的な回帰としては扱わない。しかし、CLAP 楽器で制作した曲を取り出す製品経路が不足しており、ノートだけの基準 WAV の一致はその曲の再生一致を保証しない。機能として許すなら、成功と返しながら音源を置き換える挙動を利用者に隠せない。

### AUD-11 / P1: CLI がジャーナルを復旧せず、確定済みの編集を含まない版を書き出す

- 種類: 再現した不具合
- 根拠: [crates/echode-cli/src/lib.rs](../../crates/echode-cli/src/lib.rs)、119 行付近。
- 確認結果: 自動保存だけを失敗させると、ジャーナルに確定したトラックとノートは recover で残るが、CLI が読む read_package にはない。実際の WAV は全サンプル 0。
- 対応: 一貫した復旧済みスナップショットを使う。書き込み中のパッケージを混ざったファイルとして読まず、文書ホストから対象の版を受け取る。
- 完了条件: ジャーナルに確定したノートが未コミットでも書き出しに残る。保存途中のファイルを混ぜて読まず、対象の版を特定できる。
- 対応（2026-10-13）: 書き出しは文書ホストの復旧済みスナップショットを使う。作業ツリーにノートが無くてもジャーナルにあれば WAV に残る。`save.pending` があり自動保存の基点が無いときは拒否する。基点がある保存途中は、作業ツリーではなくその基点を書く。成功時は stderr に `exported <id>` を出す。[ADR 0070](../decisions/0070-export-recovered-snapshot.md)。

自動保存の失敗を `save.pending` が書けない状況で注入し、トラックとノートをジャーナルへ同期した。復旧結果の音声ピークは 0.45777583 だったが、実際に `render_to_wav` が出した WAV は全サンプル0。`read_package` は復旧済みの版を読む API ではない。障害時だけでなく、非同期保存が追い付いていない時や保存途中の複数ファイルを読む時も、一貫した版の確保が必要になる。

## 性能・配布と既知の不具合

### AUD-12 / P2: 音声コールバックで、その区間に鳴らない全クリップを走査する

- 種類: 実装レビュー
- 根拠: [crates/echode-engine/src/playback.rs](../../crates/echode-engine/src/playback.rs)、348 行付近。
- 確認結果: コードで確認。全配置数×span 数の走査。実時間の増分は未測定。
- 対応: 開始と終了の索引から対象の配置だけを選ぶ。遠い将来のクリップを増やしてもコールバック時間が増えないことを計測する。
- 完了条件: 鳴るクリップ数を固定し、遠い将来の配置数だけを増やして release 計測する。通常の correctness テストには時間の閾値を入れない。
- 対応（2026-10-13）: コールバックは、開始順に並んだ配置を二分探索し、その区間に重なるものだけを足す。終わる直前の配置と、ブロックの直後から始まる配置は鳴らない。8,000 個の将来の配置を足しても波形は同じである。release で 2,000 回測ると、鳴るクリップ 1 つの 1.10 ms に対し、10 万個を足しても 0.85 ms で、3 倍未満だった。この比は計測用の無視したテストだけが持つ。[ADR 0071](../decisions/0071-clip-overlap-index.md)。

`StoredClip` は開始順に並んでいるが、製品の `add_stored_clips` は一件ずつ一要素の配列に変えて全件を走査する。下位の `render_faded_clips` の二分探索がプロジェクト全体へ効かない。別途、イベントもトラックごとに全イベントを走査している。処理量の増え方はコードで確認したが、どの規模で音切れになるかは今回測っていない。

### AUD-13 / P2: 本体の library validation を有効にする署名設定がない

- 種類: 実装レビュー
- 根拠: [scripts/distribution.py](../../scripts/distribution.py)、236 行付近。
- 確認結果: project.yml は Hardened Runtime が NO。署名にも runtime / library の指定がない。
- 対応: 本体に求める実行時保護を署名フラグで明示する。本体が外部ライブラリを拒否し、ヘルパーだけが許可することを動作で検査する。
- 完了条件: 署名後の本体・ヘルパーのフラグを検査し、別途用意した外部ライブラリの読み込み可否を実際に確認する。
- 対応（2026-10-13）: `Echode Local` の署名に `--options runtime` を付け、Xcode の Hardened Runtime も有効にする。本体には library validation を外す権限を付けない。アドホック署名の外部ライブラリは本体が拒否し、ヘルパーは読み込める。公証はしない。[ADR 0072](../decisions/0072-hardened-runtime.md)。

[project.yml](../../project.yml) は `ENABLE_HARDENED_RUNTIME: NO`、署名コマンドには `--options runtime` や library validation を有効にする指定がない。ヘルパーだけに disable-library-validation entitlement を入れ、本体に入れないという検査では、本体側の保護が有効であることまで確認できない。Apple は [library validation が Hardened Runtime で既定有効になる](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.disable-library-validation)と説明している。ここは署名設定と公式仕様からの判断で、コード注入の実証ではない。公証を行わないという既存方針とは別に、必要な保護を明示して検査する必要がある。

### API-3 / P1: ソケットを作るとき同名の通常ファイルを削除する（前回から未修正）

- 種類: 前回からの未解決不具合
- 根拠: [crates/echode-api/src/serve.rs](../../crates/echode-api/src/serve.rs)、35 行付近。
- 確認結果: make known-bugs は API-3 のテストだけが失敗。同名の通常ファイルがソケットで置き換わる。
- 対応: 既存パスの型と稼働中のサーバーを確認し、通常ファイルを保持する。接続の期限と異常終了の影響も既存 API-3 の範囲で対応する。
- 完了条件: 既存の通常ファイルを一切変更せずにエラーにする。稼働中ソケットを奪わず、古いソケットだけを適切に片付ける。
- 対応（2026-10-13）: 通常ファイル、シンボリックリンク、ソケット以外のパスは消さずにエラーにする。接続できるソケットは残し、拒否される古いソケットだけを消す。接続相手の uid は `getpeereid` で自分と比較する。1 行は 1 MiB まで、無応答は 30 秒でその接続だけを終える。複数接続の同時処理は足していない。[ADR 0073](../decisions/0073-socket-path.md)。

## 検査結果と再現の範囲

- 着手時の `make verify-plan`: 差分なし。現状全体を対象に `scripts/verify.py --all` を実行した。
- 自動検査7件は合格: `check`、`rtsan`、`check-input`、`check-bridge-features`、`check-bridge-asan`、`check-bridge-tsan`、`check-bridge-miri`。

- `make known-bugs`: API-3 の既存テストが予定どおり失敗。この不具合が未修正であることを確認した。通常検査の失敗や見送りとは区別する。
- 最初のサンドボックス内の通常検査は、一時署名キーチェーンの作成が拒否されて失敗。許可された実行環境で再実行して上の合格を確認した。プラグインの再現も、プロセス間通知を許可した環境で実行した。

監査対象コードの検査結果は [保存した検査記録](../../target/verification/audit-2026-10-13-baseline.md) とその JSON、各検査のログに残してある。監査文書を追加するとソース識別値は変わるため、最後に `make verify` を実行する。その記録は [通常の検査報告](../../target/verification/report.md) にある。記録が有効なソースの識別値を混同しないこと。

### 再現プログラム

一時的な検証用パッケージは `/private/tmp/echode-audit-20261013/`。リポジトリの製品 crate を絶対パスで参照し、本体にはプラグインをロードしない。テスト用 CLAP はヘルパー内で、受信したノート数を一定出力へ変換するだけの楽器と、既存の Test Gain を使った。

主な実行モードは `two_hosts`、`torn_journal`、`torn_utf8`、`journal_error`、`rt_replace`、`rt_sort`、`event_capacity`、`plugin_seek`、`plugin_delete`、`audio_effect`、`clip_gain`、`offline_plugin`、`stale_export`、`host_deadlines`。結果は同じフォルダの `results-core.json` と `results-plugins.json` に保存した。終了コード0は「不具合のない合格」を意味せず、上の異常な結果を取得できたという意味である。確保検出の2モードは SIGABRT を取得した。

再現コードと生の結果を [監査の再現資料](2026-10-13-audit-reproduction.json) にも保存した。これは今回の観測を再確認する資料で、通常の自動検査へ追加したものではない。一時フォルダを消しても、コードと結果はこの資料に残る。

### 実施していない確認

以下は実施せず、検査記録に `deferred` と理由を記録した。合格とは扱わない。

- `spike-isolation`: 正式な release の隔離・小さい実時間ブロックでの計測。今回の無音の障害再現は、この正式計測の代用ではない。
- `spike-draw`、`spike-arrange-frame`、`spike-piano-frame`、`spike-app`: GPU / 実表示の再測定。既存文書の測定値は今回の実施結果として使っていない。
- `spike-history`、`spike-engine`、`spike-audio`、`spike-bridge`、`spike-render`: 大規模・実機・耐久・release 性能の再測定。
- `spike-input`: ピンチ・触覚・感圧の実操作。

他社の実用 CLAP 楽器、プラグイン GUI と状態の完全な復元、実機の抜き差し・聴感、VoiceOver とキーボードだけでの全制作、同期フォルダ・iCloud、電源断の実験もしていない。特に音声オブジェクトの保存は `fs::write` → rename で、オブジェクトとディレクトリの同期がない。ジャーナルの fsync とプロセス強制終了の合格を、素材を含む電源断耐性の保証へ拡張できない。
