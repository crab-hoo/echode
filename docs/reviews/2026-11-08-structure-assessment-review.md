# 2026-11-08 構造の評価の精査

## 対象と判定の境界

- 対象: ユーザーから受け取った構造の評価。良い点 5 項目、懸念 4 項目、整理の優先順位 4 項目からなる。
  評価は GitHub の最新ソースの静的レビューで、テストの再実行はしていないと自ら述べている。
- 精査は `1df6843` で行い、コード・監査の記録・計画書と照合した。
- `Draft::finish` の消費数の検査を種類ごとに外す変異試験を、作業ツリーの外に展開した HEAD で実行した。
- 判定は「事実」「一部事実」「既知」（既存の監査に記録済み）に分ける。数値の誤りは根拠の欄に書く。
- 実機・音声機器・アプリの操作は使っていない。

## 結論

- 評価の大筋（基礎設計は保たれ、複雑な編集規則が急速に育っている）は、コードと一致する。
- 懸念 ① の芯は、検査の経路が 3 つあることではない。
  `Draft::finish` だけが持つ「下書きを残らず使ったか」の検査が手書きで、種類を足しても型が知らせないことにある。
- 懸念 ② の placement.rs は、1 つの規則（ノートの変更に自動配置と共有する中身を追従させる）の実装である。
  複雑さの源は、編集中のトラックの 2 つの見え方を手で同期することにある。
  クリップ FX はこの経路を通らない。PLAN の重ね置きと自動クロスフェードは、配置の発見の前提を崩す。
- 懸念 ③ は FCA-05 の残り、④ は 2026-11-06 の精査で計測済みであり、新しい事実はない。

## ① 整合性の検査の分担

### 3 つの経路の役割

- `Project::check_invariants`（invariants.rs）は、完成したスナップショットの規則の正本である。
- `Project::try_assemble`（model.rs 1441 行）は、保存から読んだ部品を型のある `ModelError` で拒否する。
  最後に `check_invariants` を呼ぶ。前段は `check_invariants` の部分集合の重複である。
  前段の規則がずれても不正な状態は受け入れず、返る誤りの種類が変わるだけである。
- `Draft::finish`（changeset.rs 737 行）は、下書きの全オブジェクトが所有者の順序表から使われたかを数える。
  使われなかったオブジェクトは完成したスナップショットに現れないため、後の不変条件の検査には原理的に見えない。
  2026-11-07 のパラメーターの不具合は、この種類である。

### 今の網羅と残る形

- テンポ点・中身・トラックは全件を走査し、配置・ノート・デバイス・パラメーターは使用数を下書きの総数と比べる。
  今の `ObjectKind` の 7 種類に漏れはない。
- `ObjectKind` を足しても、`Draft::insert` と `remove` は既定の腕（`_ =>`）で拒否するため、コンパイルは通る。
  状態の表、`from_project`、消費数の検査は手で足す。
- [SPG-09](2026-10-30-structure-audit.md) の項目表（ADR 0226）は、スカラー項目の転記を生成した。
  所有関係と子の解決は、その時「変えない」とした範囲の外にある。
- PLAN の Phase 2 のクリップ FX は、配置が所有するデバイスを足す。
  今の下書きは、デバイスの所有者をトラックに限る（changeset_device.rs の `DeviceState::track`）。

### 変異試験

- `Draft::finish` の使用数の比較から、配置・ノート・デバイス・パラメーターを 1 つずつ外した（常に偽にした）。
- 外す前は `cargo test -q -p echode-model -p echode-history --no-fail-fast` が合格した。
- 4 つの変異は、どれも既存の回帰が失敗させた（終了コード 101）。
  - 配置: placement_changesets.rs と track_changesets.rs の子の解決の回帰（各 1 件）。
  - ノート: content_changesets.rs の `content_changesets_keep_child_resolution_and_order_step_checks`。
  - デバイス: model_device_apply_tests.rs の `device_ownership_validation_rejects_unlisted_missing_and_wrong_owner_devices`。
  - パラメーター: parameter_ownership.rs の 2 件（変更セットの拒否と、復旧の拒否）。
- 今ある種類の消費の検査は、回帰で守られている。
  守られていないのは、種類を足す時に、検査とその回帰を一緒に足すことだけである。

### 製品で変更セットを適用する経路

- 通常の Undo / Redo は、スナップショットを積む（echode-actions の session.rs）。変更セットは適用しない。
- 製品で `apply_changeset` を通るのは、ジャーナルの再生と、host.rs の `connecting_changeset` だけである。
  再生は行ごとに `check_invariants` を呼ぶ（document.rs）。`connecting_changeset` は結果を目標のスナップショットと比べる。
- 公開の `echode_actions::replay` は不変条件を検査しない。製品からは呼ばれず、テストだけが使う。

## ② placement.rs

- 公開するのは `insert`・`delete`・`edit`・`drop_unreferenced` の 4 つで、model.rs と clip_move.rs だけが呼ぶ。
- 全体が「ノートの変更に、自動配置の小節合わせ・結合と、共有する中身の参照を追従させる」規則を実装する。
  変更理由が 1 つなので、行数だけを理由に分ける根拠は弱い。
- 複雑さの源は、編集中のトラックを `current` として取り出しつつ、公開側の `tracks` に古い写しが残ることである。
  別トラックの自動配置を再適合して結合すると、`retarget` は古い写しを書き換える。
  `refit_auto`（506〜532 行）が、その参照と位置を `current` へ手で戻す。
- 今の呼び順では、`current` にだけある配置が再適合より前に生まれないため、この同期は足りている。
  再適合の前に配置を作る編集を足すと、戻す対象から漏れて結合で消した中身を指す形になり得る。
- 回帰: [properties.rs](../../crates/echode-history/tests/properties.rs) の操作列は、別トラックへのリンクと共有する中身の種を含む。
  変更セットの往復と不変条件を、操作ごとに照合する。

### 今後の機能との関係

- クリップ FX は、配置の項目と所有関係の追加である。ノートの再適合の経路は通らず、影響は ① の側に出る。
- PLAN の「重ねる／置き換えるの切替」と自動クロスフェードは、同じトラックの配置の重なりを許す。
  `refit_hosts` は開始順で重ならない窓を前提にし（562 行）、`FixedBars` と `overlaps_others` も重なりを拒否に使う。
  この機能では、自動配置の発見の前提を先に決め直す必要がある。

## ③ 全体を調べる操作

- FCA-05 の残りとして記録済みである（ADR 0242 の「残る範囲」、[2026-11-06 の精査](2026-11-06-assessment-review.md)）。
- `id_in_use` と `ids_free`（model.rs 1365〜1400 行）は、全ノート・全パラメーターを 1 回走査する。
  `track_index`、`edit_clip` のトラック探索、`locate_parameter` も線形である。
- 編集はどれも中身とトラックの `Vec<Arc<_>>` を複製するため、トラック数・中身数に比例する費用は既にある。
  線形のトラック探索はこれと同じ次数で、効くのはノート数に比例する `id_in_use` である。
- 評価の「ID 探索と索引の共通方針」は FCA-05 の残りと同じ範囲なので、新しい項目にしない。

## ④ 検証基盤の規模

- 2026-11-06 の精査で計測済みである。2026-11-08 は 211,936 バイト、検査 33、契約 257 だった。
- 計算量の計数は 25 種類で、製品コード 10 ファイルの 40 か所にある。
  どれも `#[cfg(test)]` の内側で、リリースビルドには入らない。

## 今回の対応

- 製品のコードと検査の選択は変えず、この精査の記録だけを足した。
  上の変異は、どれも既存の回帰が捉えたため、新しい回帰は足していない。
- 評価の整理の優先順位のうち、1 と 2 は上の判定で答えた。3 は FCA-05、4 は 2026-11-06 の精査の範囲である。
- 所有関係を足す機能（クリップ FX、テイク）に着手する時は、先に次を行う。
  - `Draft::insert` と `remove` の既定の腕を除き、`ObjectKind` を足すとコンパイルが止まる形にする。
  - 新しい種類の未列挙・所有者違い・重複の拒否を、上の回帰と同じ形で足す。
- 配置の重なりを許す機能に着手する時は、先に `refit_hosts` の「重ならない窓」の前提と、`current` の同期を決め直す。
