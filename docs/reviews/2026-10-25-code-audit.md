| ID | 優先度 | 内容 | 状態 |

### CUR-01: PCM のバイト長計算が桁あふれする

- 場所: [media.rs](../../crates/echode-history/src/media.rs) の `decode_pcm`、117〜120 行。
- `frames * channels` は検査するが、その後の `count * 4` は未検査である。
  ハッシュ照合は形式の検証ではないので、正しい BLAKE3 を持つ壊れた素材でも到達する。
- 再現入力は 24 バイトだけの正準 PCM ヘッダで、48 kHz・モノラル・`frames = 2^62`、ペイロードなし。
  `write_object` で保存し、公開関数 `read_pcm` で読む。巨大なファイルや実メモリ確保は不要。
- debug は乗算の overflow で panic、release は乗算が 0 へ回り、長さ検査を通過した後の
  `Vec::with_capacity` で `capacity overflow` の panic になる。どちらも期待する `PackageError` を返さない。
- 波形の `load_hash` と再生準備の `source_planes` は `read_pcm` を呼ぶ。
  `.ok()` / `map_err` では panic をエラーへ変換できない。
  FFI ワーカーの panic 時の受付停止、CLI の終了への伝播はコードで確認した経路であり、今回 UI からは再現していない。
- 修正条件: ヘッダから期待バイト長まで checked 演算で求め、不一致を確保前に拒否する。
  debug / release の両方で、同じ小さな不正入力が panic なしのエラーになること。

### CUR-02: 素材の終端で波形の表示範囲を切らない

- 場所: [peaks.rs](../../crates/echode-history/src/peaks.rs) の `Waveforms::fill`、156〜171 行。
- `last.min(frames)` で素材の範囲だけを短くする一方、渡す表示列は元の配置幅のままである。
  `fill_columns` が残りの素材をその全幅へ等分するので、終端後の無音にも波形が描かれる。
- 再現: 120 BPM で 1 秒の一定値 0.5 の素材を配置し、60 BPM へ変更する。
  2 拍の窓は 2 秒になり、後半 1 秒は無音である。
  全幅の 4 列を問い合わせると、期待する `[0.5, 0.5, 0, 0]` でなく全列が 0.5 になる。
  プロジェクトの不変条件は満たしている。
- 影響: 音声の変更ではなく、編集位置を判断する波形の誤表示。
  表示を終端後だけに絞ると無音になるため、ズーム・スクロールでも見え方が変わる。
- 修正条件: 列ごとの時間区間に対応する素材区間を求め、EOF 後は無音の列に保つ。
  テンポ変更と配置窓の伸長、全幅と部分幅の問い合わせを比較すること。

### CUR-03: 波形の列を素材フレームの等分で割り当てる

- 場所: [peaks.rs](../../crates/echode-history/src/peaks.rs) の `source_span` と `fill_columns`、245〜305 行。
- 可視範囲の両端だけをテンポ積分し、その間はフレーム数を等分する。
  表示の列は tick の等間隔なので、途中でテンポが変わる時には対応しない。
- 再現: 第 1 拍は 120 BPM（24,000 フレーム）、第 2 拍は 60 BPM（48,000 フレーム）。
  1.5 秒の素材の先頭 24,000 フレームを 0.25、残りを 0.75 とし、2 拍へ配置する。
  EOF 超過はないので CUR-02 とは独立である。
- 1 拍ずつの 2 列の期待値は `[0.25..0.25, 0.75..0.75]`。
  実際は `[0.25..0.75, 0.75..0.75]` で、第 2 拍の音が第 1 拍にも現れる。
  素材は 36,000 フレームずつに等分されている。
- 修正条件: 各列の tick 境界を `media_sample_at` 等の再生と同じ時間変換へ通す。
  テンポ点を増やした場合も、全体・部分表示で同じ位置へ波形が出ること。
  CUR-02 と同時に直せるが、EOF だけの修正ではこの誤りは残る。

### CUR-04: API の書込みにはタイムアウトがない

- 場所: [serve.rs](../../crates/echode-api/src/serve.rs) の `serve_connection_limited`、70〜99 行。
  `serve` は同じファイルの 148〜156 行で接続を直列に処理する。
- `set_read_timeout` は設定するが、複製した writer に書込みの期限がない。
  クライアントが要求を送りながら応答を読まず、送信バッファが埋まると `writeln!` が待ち続ける。
  その間は次のクライアントも MCP の backend 呼出しも処理されない。
- 再現: `UnixStream::pair` のサーバー側を未読のデータで満たし、
  `protocol.version` を 1 件送って製品の接続処理へ渡す。
  読込み期限はテスト用に 100 ms とするが、1 秒後も返らず、相手を閉じて初めて戻る。
  テストは失敗の判定前に必ず相手を閉じ、スレッドを回収する。
- [ADR 0073](../decisions/0073-socket-path.md) の無応答接続の解放は、読込み待ちだけでは不足する。
  複数接続の同時処理を実装しなくても、書込みの期限とその接続だけの終了は必要である。
- 修正条件: 応答を書けない接続にも期限を設け、正常な後続クライアントが処理されることを確認する。
  部分的に実行された編集を安易にリトライしないこと。
