# Computer Use エラーの切り分けと再検査

日付: 2026-10-14。対象は `534ca6467f425475f5f5c7c83aa96af316e51522` と、この上の未コミットの ADR 0091 の修正。`make app` で作り直したアプリを Computer Use で操作した。製品ソースは変更していない。バイナリ、画像、診断の要約は [検査資料](../../target/verification/reinvestigation-20261014/evidence.json) にある。前回の検査文書は履歴として残す。

**CU-01 の受け入れ条件は実画面で通過した。前回未確認だったマウス移動・伸縮、音声取り込み、履歴復帰も確認した。CU-02 は実ウインドウの回帰を `make spike-playhead` へ移した。この環境の実行は現在の Space に無く遮蔽されていたため、主要な期待値は未検証のまま不合格とした。**

## 操作エラーの原因

### 別デスクトップのウインドウと `noWindowsAvailable`

再起動後のフォルダ選択で再現した。パネルのアクセシビリティの木と 1,760 × 896 の画像は取得できたが、画像の「開く」の座標 `[1628, 832]` をクリックすると `noWindowsAvailable` になった。

直後の公開 API `CGWindowListCopyWindowInfo` の読み取りでは、PID 68494 の本体ウインドウ 47469 と選択パネル 47479 は全ウインドウ一覧にあり、現在の画面の一覧には両方とも無かった。画面は点灯していた。同じアプリへ Computer Use で `ctrl+Left` を送り、再び読み取ると、同じ PID と同じ2つのウインドウが現在の画面の一覧に戻った。パネル画像を取得し直し、**同じ座標**をクリックすると選択が完了し、ファイル一覧が読み込まれた。アプリや操作ツールの再起動、権限変更、製品の変更は、この復帰の間にしていない。

これにより、少なくともこの再現の座標エラーは、対象が現在の表示デスクトップに無いことに結び付いた入力先の問題と判定する。アクセシビリティと画像の取得成功を、現在の画面で座標操作できる証拠にしてはいけない。ウインドウの Raise だけでは、この再現で座標エラーは解消しなかった。前回の全エラーについては当時のウインドウ状態が無く、すべてがこの原因だったとまでは断定しない。

本体の表示中は、画像のピクセル座標で位置移動とノートのドラッグが通った。画像を半分の座標へ変換すると目的のボタンを押せなかった。今回の本体は 2,400 × 1,480 の画像で、ネイティブウインドウは 1,200 × 740 ポイント。アプリのフルパスと bundle ID の両方で、表示中の座標クリックが通った。識別子だけの問題ではなかった。

### ScreenCaptureKit `-3811` と接続切断

前回の失敗時刻に限定したシステム診断ログで、次の4件を確認した。

- 16:45:34.270 と .271: `SkyComputerUseService` PID 42355 が `failed display lookup for windowBounds=<private> cgError=0 found=0`。
- 16:45:43.503 の2件: 同じ PID、同じエラー。

さらに macOS のクラッシュ記録 `SkyComputerUseService-2026-10-14-164917.ips` は、同じ PID 42355 の画面取得サービスが 16:49:00.897 に `EXC_BAD_ACCESS` / `SIGSEGV`、アドレス0へのアクセスで停止したことを示す。主スレッドのスタックにはサービス自身と、ウインドウシステムの通知処理がある。個人情報を含む全文の代わりに [診断の要約](../../target/verification/reinvestigation-20261014/capture-helper-crash-summary.json) を保存した。

`-3811` はローカルの公開 SDK `SCError.h` の `SCStreamErrorInternalError`。Apple も [画面取得の内部エラー](https://developer.apple.com/documentation/screencapturekit/scstreamerror/internalerror) と説明している。音声専用の開始エラーは別の値 `-3818`。今回のログが示す失敗箇所は画面と対象ウインドウの対応付けであり、Echode の音声エンジンが停止した証拠ではない。前回の native pipe の切断は、取得サービス自体のクラッシュと整合する。

サービスのどの命令がアドレス0を呼んだか、画面取得失敗がそのクラッシュを直接起こしたかは、公開シンボルとこの記録だけでは確定できない。前回の各タイムアウトとクラッシュの因果も個別には確定しない。Echode の前回のサンプルで主スレッドが通常のイベント待ちだったことと合わせ、タイムアウトだけから製品のデッドロックを認定しない。

今回の読み取りでは Stage Manager は無効。設定を切り替える対応はしていない。画面録画・アクセシビリティの権限も変更していない。表示が戻った同じサービスで取得と入力が通るため、この再現を一律の権限不足として扱わない。

### 非同期の反映と古い操作番号

フォルダパネルの最初の木では「開く」が無効でも、その後の取得で有効になった。ファイルの単クリック直後の木が無変化でも、画像と次の完全な木では選択済み・「開く」が有効だった。単クリックの不具合とは認定しない。描画側にも非同期で可視要素を発行する処理があり、操作直後の1回の木だけでは反映完了を証明できない。

完全な木の取得は操作番号を振り直す。今回、資料保存のために完全な木を取った後、こちらが古い番号を再利用し、再生ボタンのつもりでメニューを開いた操作ミスが1回あった。メニューの公開 Cancel 操作で閉じ、最新の番号から再開した。製品の不具合には数えない。

Dock は通常の対象ウインドウを持つアプリとして選択できず、取得がタイムアウトした。この経路は使わず、Echode のキーボード操作で表示を復帰できた。OS の読み取りで通常の権限ではプロセス一覧が取得できなかった件と、診断用の Swift 断片の構文エラーも、製品の失敗から区別した。

## 実画面で通過した項目

検査には前回の一時プロジェクトのコピー `Recheck.echode` を使い、既存のユーザープロジェクトへ編集しなかった。

- **CU-01**: 停止中の0→2拍で両画面の縦線が2拍へ移動。再生画像の数値2.94拍と縦線も同じ位置へ進んだ。一時停止の1.99拍で両画面もその位置へ停止。数分停止した後の3拍への移動、ノートエディタを閉じて再表示した後、別文書への切り替え後の0→3拍、元の文書へ戻った0拍の描画も通過。編集で描画を起こす必要は無かった。
- **マウス移動と伸縮**: C♯4・開始1拍・長さ6拍の中心を右1拍・上1音へドラッグし、D4・開始2拍・長さ6拍になった。右端を1拍伸ばして長さ7拍。Undo で D4／2／6、さらに Undo で C♯4／1／6へ戻った。数値欄、インスペクター、画面の位置を照合した。
- **フォルダ選択と音声取り込み**: 一時フォルダを選択して一覧を読み込んだ。既存クリップに重ねる取り込みは `clip would overlap another clip` と拒否された。空のトラック2へ選び直し、2秒・48kHz・モノラルのテスト音声を2拍の位置へ取り込めた。前半の小さい振幅と後半の大きい振幅が順番どおり表示された。Undo でクリップが消え、Redo で同じIDが戻った。
- **トリム済み波形**: 別の一時パッケージ `WaveTrim.echode` に、上の取り込みデータの offset=2拍・length=2拍（後半1秒だけ）を準備して開いた。2〜4拍の区間が先頭から後半の大きい振幅を示した。これはデータに定義されたトリムの読み込み・描画検査であり、UI から音声をトリムする編集操作の検査ではない。
- **履歴復帰**: 音声の Redo 後の版 `39aab4144fe0` から、Undo 後の版 `1c2f5d754f9a` の「戻す」を画像の座標で押した。新しい現在の版 `70abef919932` が増え、閉じると音声クリップが消えた。復帰の Undo で同じ音声クリップIDが戻った。元の版が残ることも一覧で確認した。木では「戻す」は行に結合されていたため、行クリックをボタン押下の証拠にしていない。
- **保存と終了**: 文書を切り替えて再読込し、さらに通常終了と再起動を行い、3トラック、元のノートと Vital、取り込んだ音声と波形を保持していた。通常終了は完了した。強制終了の復旧は前回の版での検査であり、今回もう一度行ったとは記録しない。

画像は [停止中2拍](../../target/verification/reinvestigation-20261014/locate-two.png)、[再生中](../../target/verification/reinvestigation-20261014/playing.png)、[一時停止](../../target/verification/reinvestigation-20261014/paused-visible.png)、[取り込み](../../target/verification/reinvestigation-20261014/audio-import.png)、[履歴復帰](../../target/verification/reinvestigation-20261014/history-restored.png)、[復帰のUndo](../../target/verification/reinvestigation-20261014/history-undo.png)、[トリム](../../target/verification/reinvestigation-20261014/wave-trim.png)、[再起動](../../target/verification/reinvestigation-20261014/after-normal-restart.png) にある。

## 描画計測

この調査で再実行した `make spike-app` は終了コード0、分類 `normal`。画面1枚、点灯、本体は可視・現在の Space・非遮蔽。アレンジ、ピアノロールとも93コールバック・93フレーム、全件メインスレッド外、メイン処理の負荷中31フレーム。フレーム枠の不足0、休止解除1回、ヘッダ位置・アクセシビリティも通過した。[結果](../../target/verification/reinvestigation-20261014/spike-app-first.json)。閾値を下げていない。

実行役が同じ修正で残した「非アクティブ Space・遮蔽」の結果は、アレンジ1・ピアノロール2フレームで休止解除は済んでいた。前回の1／2フレームの失敗と一致する。今回の正常な表示条件の93／93と合わせ、前回の計測失敗は表示条件の不足が有力。ただし前回の版はその表示状態を計測しておらず、旧実装の寄与を排除した主張にはしない。

## CU-02 / P2: 実機と時間に依存する回帰が通常検査へ混入

`swift/EchodeApp/Tests/EchodeAppTests/PlayheadTests.swift:35` 以降の4つのテストは、実際の NSWindow と Metal の表示リンクを作り、描画完了を3秒の期限で待つ。通常の `@Test` のため、実機検査を実行すると明示していなくても `make check` に入る。再生継続と一時停止の描画の主要な検査は `window.occlusionState.contains(.visible)` のときだけ行われる。遮蔽環境の合格は、その条件内の検証の合格を意味しない。

AGENTS.md の「時間を測るテストと、実機が要るテストは `#[ignore]` にし、`make spike-*` で動かす」に相当する Swift 側の区分が必要。今回通過した実画面の修正とは分け、次を実行役へ依頼する。

1. 描画に依存しない世代・操作結果の検査を通常検査へ残す。実ウインドウを作る4件は、Swift Testing の明示実行用の条件と `spike-*` の入口へ移す。
2. 入口を Makefile と `scripts/verification.json` に登録し、選択のテストを追加する。通常の `make check` は画面条件で成否が変わらないことを確認する。
3. 明示した実機回帰では、必要なウインドウが現在の Space で非遮蔽になるまで確認する。条件不足なら、その理由と未検証項目を記録する。主要な期待値を省略して、その期待値まで合格したように扱わない。
4. `beginMeasurement()` に頼らない0→2拍、再生継続、一時停止、停止中の休止、破棄、計画交換、文書交換の期待値は維持する。

## CU-02 の対応

世代と操作結果の検査は通常の `PlayheadTests` に残した。実ウインドウの4件は `ECHODE_SPIKE_PLAYHEAD=1` のときだけ有効で、入口は `make spike-playhead`（[ADR 0092](../decisions/0092-playhead-spike.md)）。遮蔽中に再生継続と一時停止を飛ばして合格する分岐は削除した。ウインドウが現在の Space で非遮蔽・非最小化になるまで待ち、足りなければ `target/spike-playhead.json` に理由と未検証項目を書いて失敗する。

フラグなしの Swift テストでは4件は skipped、世代の検査は通過した。画面条件ではその成否が変わらない。

この環境の `make spike-playhead` は終了コード 1、状態 `insufficient-environment`。画面1枚、点灯、visible、現在の Space ではない、遮蔽。未検証は 0→2拍、停止中の休止、同じ feed の再描画なし、再生継続、一時停止、破棄、開き直したビュー、計画交換、文書交換。これらを合格にしていない。`spike-app` の閾値は変えていない。

## 検査記録と範囲

着手時に `make verify-plan` を実行した。`make verify` は終了コード0で、通常検査と RTSan、橋渡しの全 feature・ASan・TSan・Miriの自動検査6件、描画読み戻し2件、無音の実機音声、実機アプリ描画の計10件が通過した。結果は [検査記録](../../target/verification/report.md) を参照する。選択された `spike-draw`（大規模描画の性能）、`spike-engine`（10分間の負荷）、`spike-bridge`（橋渡しの性能）の3件は、今回の操作エラーと機能の再検査では未実施として理由を記録した。この文書の訂正後にも同じ入口を再実行して、最終のソース識別値に対する結果を確認する。

ピンチ、感圧、触覚、聴感の一致、機器の抜き差し、実用CLAPのパラメーター・状態の往復は今回の合格に含めない。ツール側のクラッシュ命令の特定や恒久修正も、この製品リポジトリで行ったとは主張しない。
