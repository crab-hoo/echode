# 2026-11-03 コード全体の監査（実装の妥当性とプロの水準）

## 対象と判定の境界

- 対象: `5565b4d` と、開始時の未コミット変更 23 件。
  未コミット分は別セッションが進行中の ADR 0238 の作業であり、指摘の対象にしていない。
- 製品の Rust（約 5.8 万行）と Swift（約 1.4 万行）を領域ごとに読み、各実装が要件に対して最適かを問い直した。
  精読したのは、`echode-realtime`、エンジンの再生（`playback.rs`・`plugins.rs`・`plan.rs`・`mix.rs`）、CoreAudio のコールバック、
  共有領域の読取り、モデルの編集と読込みの検証、ジャーナルの追記、試聴の IOProc、素材の準備、描画の橋渡しとラベル、CLI の書出しである。
  ヘルパーの CLAP 処理、走査、文書ワーカー、FFI、API、描画クエリ、Swift の画面は抜き取りで読んだ。全行の通読ではない。
- 既存の監査（XCA・SPG・外部監査）の指摘は繰り返さない。新しい指摘と、既存の範囲を超えて分かった事実だけを書く。
- 計測はリポジトリの外の Cargo プロジェクトから、製品の公開 API を release で呼んだ。
  手順・プログラム・出力は [規模の計測](../evidence/2026-11-03-scale-measurements.md) にある。
- 機器は Apple M4（24 GB）、macOS 27.0。計測の一部は別セッションの検査と同時に走った。
  通常ブロックの p50 は 236〜433 µs で揺れたので、比は同じ回の値どうしで読む。
- 実機・聴感・実画面・第三者プラグインは使っていない。音声機器を開いていない。
- 製品のコードは変えていない。監査の記録と、利用者に残る制約の追記だけをした。
- 同じ日に、再現 4 件（FCA-01・03・06・16）を `#[ignore]` の `audit_` テストとして登録し、規模の計測を `make spike-scale` にした。
  修正の順番と完了条件は [実行指示](2026-11-03-fix-instructions.md) にある。

## 総評

正しさの規律は高い。検査付きの算術、所有権のリングによる解放、共有領域の範囲検査、描画スレッドの分離は、プロの水準にある。
弱点は規模である。モデルとエンジンは、整列した `Vec` の線形探索と、全体の作り直しで正しさを保つ設計になっている。
その結果、オーディオスレッドの 2 つの経路が、プロジェクトのノート数に比例する（FCA-01・02）。
AGENTS の「オーディオスレッドで、プロジェクト全体の大きさに比例する処理をしない」に反し、現在の計測（`spike-plugin-tracks`）は定常のブロックしか見ないので検出しない。
制御スレッドとメモリも同じ形で増え、1 ノートあたり親で約 1 KB、プラグイン 1 つあたりさらに約 1 KB の固定メモリを使う（FCA-03〜05）。
プロの DAW との意味の差は、フォルダのミックス操作、プラグインの遅延、締め切り超過の無音化の 3 つが大きい（FCA-06〜08）。

| 領域 | 評価 | 根拠 |
|---|---|---|
| リアルタイムの正しさ | A- | 確保の禁止、解放の返送、範囲検査。panic の捕捉（ADR 0238） |
| リアルタイムの規模 | C | ループの折り返しと再生中の編集がノート数に比例する（FCA-01・02） |
| メモリの規模 | C | イベントの容量を全ノート数で取り、固定メモリへ載せる（FCA-03） |
| 編集・読込みの規模 | C+ | 線形探索で 2 乗になる経路が複数ある（FCA-04・05） |
| プラグインのホスト | B | 隔離は堅い。遅延・主要な拡張が未対応（FCA-07） |
| ミックスの意味 | B- | フォルダの操作が効かない。締め切り超過が急な無音（FCA-06・08） |
| 保存 | B+ | 耐久性は前回の修正どおり。1 編集ごとに全同期と全読込み（FCA-14） |
| Swift の描画 | A- | 表示リンクを描画スレッドに置き、バッファを再利用する。ラベルの作り直しが残る（FCA-17） |
| 依存と FFI | B+ | 自前の宣言が規則より多い（FCA-12） |

評価は監査者の判断であり、測定値ではない。

## P1 の詳細

### FCA-01: ループの折り返しで全ノートを走査する

- [lib.rs](../../crates/echode-realtime/src/lib.rs) の `release_covering`（415 行）は、折り返しのたびに各トラックの `notes[..partition_point(on < release)]` を全部たどる。
  ループ終端より前に始まった全ノートであり、鳴っているノートではない。鳴っていないノートにもノートオフを送る。
- 計測（プラグインなし、128 フレーム、期限 2.67 ms）:

| トラック | ノート/トラック | 通常ブロック p50 | 折り返し p50 | 折り返し最大 |
|---:|---:|---:|---:|---:|
| 64 | 4,000 | 54 µs | 320 µs | 1.10 ms |
| 256 | 4,000 | 237 µs | 2.68 ms | 3.78 ms |
| 256 | 16,000 | 238 µs | 8.09 ms | 51.2 ms |

- 256 × 4,000 で、折り返しのブロックが期限そのものを使う。ループは制作で最も多い操作の一つであり、毎周音が切れる。
- プラグインのある再生では、この後に投入と回収が続くので、余裕はさらに少ない。
- 修正方針: 鳴っている集合（`mark` の世代）か、既にある `EndIndex` の区間木で、終端をまたぐノートだけを訪ねる（O(k log n)）。
  折り返しと再生中の編集を `spike-plugin-tracks` の場合に足し、ブロックの最大値を見る。
  時間に依らない回帰として、1 ブロックで訪ねたノート数をテスト用の計数で数え、ノート数を変えても増えないことを固定する。

### FCA-02: 再生中の編集で全ノートと全トラックを走査する

- 編集のたびに、オーディオスレッドの `Prepared::carry`（[playback.rs](../../crates/echode-engine/src/playback.rs) 481 行）が次を行う。
  - `release_replaced`（[lib.rs](../../crates/echode-realtime/src/lib.rs) 337 行）は `sounding[..sounding_len]` を全部たどる。
    `hold` は追記するだけで、ノートオフは印を消すだけなので、この列は前回の位置合わせ以降に鳴らした全ノートになる。
  - 鳴っているノートごとに `covers`（583 行）が全トラックを線形に探し、そのトラックの全ノートを線形に探す。
  - `keep_live_keys` の `live_key_of`（598 行）も、ノートごとに全トラックと前の列を線形に探す。
  - 位置移動の `queue_all_offs`（playback.rs 441 行）も同じ `release_replaced` を通る。
- 計測（プラグインなし、256 トラック × 4,000 ノート、編集 20 回）:

| 位置合わせ後に鳴らしたブロック | 採用ブロック p50 | 最大 |
|---:|---:|---:|
| 100 | 1.53 ms | 2.36 ms |
| 1,000 | 1.83 ms | 3.36 ms |
| 2,000 | 2.20 ms | 4.68 ms |
| 3,500 | 2.83 ms | 5.66 ms |

- 最初の採用はキャッシュが冷えていて 10.2〜13.4 ms だった。同じ回の通常ブロックは 0.24 ms である。
- 鳴らしたノートに比例して増える。ADR 0236 は定常のブロックのイベントを直したが、計画の採用は測っていなかった。
- 修正方針: ノートオフで鳴っている集合から取り除く（位置の索引で swap-remove）。
  ノートのモデル ID からの索引を制御スレッドで作り、トラックは既存の `track_indices` で引く。FCA-01 と同じ回帰で固定する。

2026-11-03 の対応: FCA-01・02 は [ADR 0239](../decisions/0239-live-note-cursor-work.md) で修正した。
鳴っている集合の削除と ID の索引を使い、折り返し・差替え・位置移動の訪問数を通常回帰へ追加した。
当時の失敗と上の測定値は保持する。採用の固定費用、全体の作り直し、実機の聴感は別に残る。

## P2 の詳細

### FCA-03: イベントの容量を全ノート数で取る

- `track_event_demand`（playback.rs 1084 行）は、トラックの全ノートに 3 件ずつ（ループの中は周回数倍）を数え、追いかけに全ノート数を足す。
  これが 1 ブロックの容量になる。実際の上限は、1 ブロックの幅に入る端の数と、1 点で重なるノート数である。
- 親の `Prepared` は `events` と `filtered`（1 件約 100 バイト）と `sort_order` をこの数で取る。
  256 × 4,000 ノートで予約は 4,096,001 件、再生の準備だけで約 985 MB を使った（プロジェクトのモデルは 199 MB）。編集中は 2 つが同時に生きる。
- ヘルパーの共有領域も同じ数で取る（`plugins.rs` の `fit_stage`、1335 行）。
  1 件 128 バイト、2 スロットなので、1 ノートあたりデバイス 1 つで約 1 KB になり、`mlock` で固定される。
  2 万ノートのトラックに 4 つのデバイスがあれば、約 80 MB の固定メモリになる。
- 容量が 1 でも変われば `prepare_mapping` で領域を作り直し、ヘルパーと往復する。プラグインのトラックでノートを足すたびに、チェインの全ヘルパーを再マップする。
- 修正方針: 整列済みの端を幅 `frames` の窓で数えて 1 ブロックの最大を求め、重なりの最大を追いかけの数にする。
  容量は 2 のべき乗へ切り上げ、増えた時だけ再マップする。

2026-11-03: [ADR 0240](../decisions/0240-block-local-event-capacity.md) で対応した。
ブロック内の端の最大・重なりと旧計画の解放分から予約し、共有領域は 2 のべき乗で増やす時だけ交換する。
`audit_fca03` と隔離ヘルパーの容量・和音の一括削除の回帰を追加した。全体の作り直し（FCA-04）は残る。

### FCA-04: 1 編集ごとの全体の作り直し

- `PlaybackControl::replace` は、全トラックの `build_plan`、全クリップの `MediaInputs::of`、全トラックの `Prepared` を毎回作る。
- 256 × 4,000 ノートで、`replace` は 1 回平均 278 ms だった（300 回）。
  標本では `build_plan` が大半で、ノートごとの `PlaybackIds` の `HashMap`（SipHash、u128 の鍵）と、端ごとの i128 の除算が目立った。
- 再生中の編集は、その分だけ聞こえるのが遅れる。描画の索引は `ArrangeIndex::update` で変わらないトラックを共有しており、同じ考え方が使える。
- 修正方針: `Arc<Track>`・`Arc<Content>` の同一性で、変わらないトラックの計画とバッファを使い回す。番号表は軽いハッシュか整列済みの列にする。

2026-11-06 の対応: [ADR 0274](../decisions/0274-reused-track-plans.md) で、変わらないトラックの計画・カーソルの索引・番号順の組・必要量を使い回し、番号表は使用数で差分だけを更新する。
同じ条件の `replace_p50_ms` は 411.9 ms から 7.1 ms になった。計画の複写と声の表の初期化はノート数に比例して残る。上の監査時の値は保持する。

### FCA-05: モデルの線形探索と 2 乗の経路

- [model.rs](../../crates/echode-model/src/model.rs) の `Project::content`（453 行）は線形である。読込みで ID 順に整列するのに、二分探索していない。
- ノートの編集は `drop_unreferenced`（placement.rs 663 行）で、内容ごとに全トラックの全クリップを調べる。
- `id_in_use`（1311 行）は、新しい ID のたびに全ノート・全パラメーターを調べる。
- 読込みの `try_assemble` は、クリップごとに内容を線形に探し（1418 行）、`overlaps_others` をクリップごとに全クリップへ当てる（1426 行）。開始で整列しているので隣どうしで足りる。
- 計測（クリップごとに別の内容、8 ノート）:

| トラック × クリップ | 読込みの検証 | ノートの編集 1 回 | トラックの追加 |
|---:|---:|---:|---:|
| 16 × 16 | 0.50 ms | 0.06 ms | 0.05 ms |
| 64 × 64 | 39.8 ms | 8.3 ms | 0.38 ms |
| 128 × 64 | 167 ms | 36.0 ms | 1.03 ms |

- クリップが 2 倍で 4 倍になる。8,192 クリップで、ノートの編集 1 回が 36 ms かかる。これに FCA-04 と FCA-14 の時間が加わる。
- 修正方針: 内容を ID 順に保って二分探索する。参照数を持ち、未参照の除去を変えた配置だけで判定する。重なりは隣だけを比べる。

2026-11-03 の先行対応: [ADR 0242](../decisions/0242-model-content-lookup-and-references.md) で、内容の二分探索、参照の一括照合、隣接配置の検証を接続した。
同条件の `spike-scale` の前後値と、時間に依らない回帰は ADR に記録する。
`id_in_use` の線形探索と、変更した配置だけによる参照更新は残す。上の監査時の失敗と計測は保持する。

2026-11-06 の追加対応: 共有内容のノート時刻を配置ごとに検証する経路も除いた。
`check_invariants` は内容ごとに開始の最小値と最後の発音 tick の最大値を集計し、配置の原点と自動小節範囲を両端で検証する。
修正前の製品入口の回帰では、64 ノート・256 配置の組立てがノートを 16,512 回、直接の検証が 16,448 回訪ねた。
`shared_content_validation_does_not_rescan_notes_per_placement` は、組立てをノート数の 2 倍以下、直接検証を 1 倍以下に制限する。
整数の上下端・負の位置・空の内容・先頭ノートが最長の自動配置も検査し、拒否時の最初の問題ノートの診断を保つ。
範囲と現在の実装は [モデル設計](../architecture/model-and-history.md#42-不変スナップショット) を参照する。

同日の追加調査では、深いフォルダの親検証にも重複探索があった。
64 段の製品組立てで親の探索が 45,696 回、直接の不変条件検査で 2,016 回になった。
組立てと不変条件検査を共通の反復走査へ集め、解決済みの祖先を再探索しないようにした。
`nested_forest_validation_does_not_revisit_resolved_ancestors` は、それぞれトラック数の 2 倍以内・1 倍以内に制限する。
逆順入力の順序違反、孤立した循環・自己参照・欠けた親の拒否と、小さい親グラフの全列挙も通常回帰へ加えた。
保存形式・公開モデル・音声処理は変更していない。

同日の親変更の調査では、`set_parent` が移動先の祖先ごとに全トラックを線形探索していた。
64 段と別の 2 トラックの入力で、移動が親を 2,208 回、循環の拒否が 2,205 回探索することを製品入口で再現した。
変更後の親グラフを共通の `check_forest` で一度だけ検証し、祖先ごとの線形探索を削除した。
`model_scale_tests::nested_reparent*` は 64・256 段の移動と循環拒否をトラック数以内の親訪問に制限する。
移動後の部分木順・未変更トラックの共有・元の版の保持・同じ親への無変更・親なしへの移動・存在しない親の拒否も確認する。

共有内容の追加・編集・複製で通る `placement::check_shared_notes` にも、配置ごとの全ノート走査が残っていた。
64 ノート・256 配置を 2 トラックで共有し、ノートの音高を一度変える製品回帰で、ノートを 16,384 回検証することを再現した。
変更後はローカル終端と開始・発音終端の両端を一度集計し、配置ごとには両端だけを検証する。検証用のノート列の複製も除いた。
`model_scale_tests::shared_content_edits_do_not_rescan_notes_per_placement` は追加・編集・複製それぞれをノート数 + 1 回以内に制限する。
`placement::tests` は独立した i128 の照合、同一・別トラックのリンク、整数の上下端の受入と 1 tick 超過の拒否、元の版の保持を確認する。
これは共有配置の時刻検証の費用の修正であり、編集全体の費用や下記の未対応項目の解消とはしない。
`spike-scale` も Apple M4・release・機器とプラグインなしで前後に実行した。64 / 128 トラック × 64 クリップの `edit_note_ms` は 0.40 / 0.87 → 0.40 / 0.76 ms だった。
この計測は各配置が別の内容を持ち、共有配置の増加を測らないため、今回の改善の根拠は時間に依らない検証回数とする。単回の時間差を改善率として扱わない。

ノート編集後の `content_of_note` による全内容の探索も除いた。
64 内容の最後のノートを編集する製品回帰で、対象内と編集後の所属探索が合計 65 ノートを訪ねることを修正前に再現した。
再適合・結合から残った内容 ID を返し、追加・編集・複製の後の共有配置検証へ直接渡す。
`note_edits_do_not_search_unrelated_contents_after_refitting` は 64・256 内容で、対象内の探索を編集 1 回・追加 0 回・複製 2 回に固定する。
`placement::tests::merged_note_edits*` は同一・別トラックの結合、固定リンクの発音位置、16 bit の強弱と元の版の保持を検査する。
結合で残る内容のリンクが整数上端を超える時も拒否する。時間の改善率や編集全体が一定時間であるとは主張しない。

別トラックの自動配置の再適合後に、固定リンクごとに元のトラックと配置を再探索する経路も除いた。
64 配置の製品編集で同期のキーを 2,208 回比較し、自動配置のない場合にも無関係な 65 トラックを複製することを修正前に再現した。
同期は編集トラックの配置 ID を一度索引化し、自動配置の探索とリンク付替えは対象を借用で確認してからトラックを複製する。
`model_scale_tests::refit::linked_refit` は 1・64・256 配置、所有トラックの前後、追加・編集・複製・削除を検査する。
同期のキー訪問を T + 2P 以内、再適合・付替え内のトラック複製を対象の有無と結合に応じて 0・1・2 回に制限する。
固定リンクの内容・オフセット・発音位置・窓の保持、無関係な `Arc` の共有、変更セットの往復も検査する。
計数はテスト時だけで、編集全体の一定時間化や実画面の改善率を示すものではない。

クリップ移動で、分割しない場合にも全ノートの ID を集める経路を除いた。
64 内容の空き領域への移動が 64 ノートの ID を収集することを、製品の `move_clip` の回帰で修正前に再現した。
`model_scale_tests::clip_move` は 64・256 内容で、空き領域・空トラック・全置換・片側の切詰め・元との重なりの移動を検査する。
現行と旧ジャーナルの両経路で ID 集合の収集を 0 回とし、分割時には全 ID の収集を 1 回に保つ。
窓・ミックス値・内容の共有と変更セットの往復を確認し、`split_piece_ids_cannot_reuse_any_stored_identity` でテイクを含む各種 ID との衝突を拒否する。
分割と複製では従来どおり全 ID を収集し、移動全体の一定時間化や実画面の改善率とはしない。

ノート削除で共有内容を配置ごとに複製・探索する経路も除いた。
各 64 ノートの 2 内容を交互に参照する 256 配置と末尾の 1 ノートで、削除と不正 ID の拒否がそれぞれ 16,385 ノートを探索することを製品入口で再現した。
内容を一度ずつ借用で探索し、`model_scale_tests::delete` は同じ入力を 129 回、空の内容の参照解決を異なる内容数に応じた回数に制限する。
最後のノートの削除では、自動配置を持たない別の 65 トラックも複製していた。除去対象を先に調べ、実際に自動配置を除く別トラックだけを複製する。
指定外トラックのノートの拒否・固定リンクと 16 bit の強弱・未変更の共有・参照の回収・変更セットの往復も通常回帰で確認する。
この計数は所属探索と自動配置の除去の範囲だけで、編集全体の一定時間化や実画面の速度改善の測定ではない。
`spike-scale` も同じ Apple M4・release・機器とプラグインなしの条件で前後に実行した。
64 / 128 トラック × 64 クリップの `edit_note_ms` は 0.45 / 0.91 → 0.41 / 0.83 ms だった。
この計測はノート削除を含まないため、今回の改善の根拠は探索と複製の回数とし、単回の時間差を改善率にしない。

ID の探索と配置参照の差分更新は引き続き未対応であり、FCA-05 全体の完了ではない。

### FCA-06: フォルダのミックス操作が子に効かない

- エンジンはトラックの親子を知らない（`echode-engine` に `parent` の参照がない）。各トラックの音量・パン・ミュート・ソロは、そのトラックの音にだけ掛かる。
- フォルダのトラックにも同じ操作子が出る（`ArrangeHeaderView.swift` の `TrackControlLayout` は行の種類で分けない）。フォルダの音量やミュートを動かしても、子の音は変わらない。
- フォルダをソロにすると、ソロでない子は消音になる（playback.rs 327 行の `solo && track.solo == 0.0`）。
- フォルダのバス化は P2-03、ソロ・ミュートの意味は ADR 0116 で未決である。今の挙動は [現在の制約](../status.md) になかったので追記した。
- 修正方針: バス化までは、ミュートとソロを子孫へ伝えるか、フォルダの操作子を無効にする。どちらかを ADR で決める。

2026-11-03 の先行対応: [ADR 0244](../decisions/0244-folder-mute-and-solo-gates.md) で、ミュート・ソロを子孫の実効フェーダーへ反映した。
監査の再現を通常テストへ戻し、`block_size/folder_mix.rs` で入れ子・複数ソロ・ミュート優先・親の付替え・補間と書出しを照合する。
音量・パンとバス化は残す。上の監査時の挙動は保持する。

### FCA-07: プラグインの遅延と主要なホスト拡張

- ヘルパーは `clap.latency` を一度も問い合わせない。再起動の通知は `latency_samples: 0` を固定で送る（threads.rs 1433 行）。
- PDC は P2-03 の予定だが、遅延のあるプラグイン（線形位相 EQ、先読みのコンプレッサー）を挿すと、そのトラックだけが黙って遅れる。
  利用者には見えないので [現在の制約](../status.md) に追記した。
- ホストが提供する拡張は `state`・`gui`・`params` だけである（threads.rs 595 行）。
  `latency`・`tail`・`log`・`thread-check`・`timer-support`・`audio-ports`・`note-ports` のホスト側がない。
  遅延・ポート構成の変更の要求を受け取れず、プラグインの記録も残らない。
- 修正方針: 起動時と再起動の要求で遅延を読み、親へ送り、デバイスビューに出す。`clap_host_latency` と `log`・`thread-check` を先に足す。

2026-11-03 の先行対応: [ADR 0246](../decisions/0246-plugin-latency-reporting.md) で初回・再起動の遅延の取得と表示、`clap_host_latency` を接続した。
別プロセスの `hosted_playback/latency.rs` は主スレッドでの取得と 0 への更新を通す。
PDC と `clap.log`・`clap.thread-check` 等の拡張は残り、実画面・第三者の報告値は UC-51 に残す。

### FCA-08: 締め切り超過の急な無音

- `HostGraph::apply`（plugins.rs 922 行）は、間に合わなかったトラックを 0 で埋める。次のブロックで元の音へ戻る。
  出力の減衰（`OutputDeclick`）は出力の版が変わった時だけ働き、プラグインの取りこぼしでは版を変えない。
- [設計書の 9.4](../architecture/plugins-and-devices.md) は「対象デバイスだけを無音（短いフェード付き）にして先へ進む」と書く。実装と食い違う。
- 1 回の取りこぼしで、落ちる時と戻る時の 2 回のクリックが出る。
- 修正方針: 前のブロックの末尾から数 ms で 0 へ下げ、戻りも数 ms で上げる。決めた挙動に合わせて設計書を直す。

2026-11-03 の対応: [ADR 0245](../decisions/0245-plugin-deadline-fades.md) で、トラックごとの 5 ms の減衰・復帰と計画交換時の保持を接続した。
`hosted_playback/deadline_fade.rs` は別プロセスの保留で失敗・復帰を確定し、`block_size/plugin_deadline.rs` は分割長・途中の反転を照合する。
上の監査時の挙動は保持し、実機と第三者プラグインの聴感は UC-50 に残す。

### FCA-09: 待ちの期限と試聴の IOProc

- 出力のコールバックは、入った時刻からブロック長の 7/8 までヘルパーを待つ（stream.rs 1039 行、plugins.rs 1265 行の `collect_deadline`）。
- 試聴は同じ機器に別の IOProc を開く（[ADR 0135](../decisions/0135-sample-audition.md)）。HAL は同じ機器の IOProc を同じ I/O スレッドで順に呼ぶ。
  遅いヘルパーで出力側が期限まで待つと、試聴の IOProc と HAL の安全余白の時間が残らない。
- 期限は `inOutputTime` と機器の安全余白から求めておらず、機器の都合を見ない。
- 読解による指摘で、実機では確かめていない。2 つの IOProc の実機の確認は UC-16 にある。
- 修正方針: 試聴の IOProc が動く間は待ちの割合を下げるか、再生中の試聴を出力のコールバックで加算する。期限は出力時刻から求める。

### FCA-10: クリップゲインの焼き込み

- [clips.rs](../../crates/echode-audio-io/src/clips.rs) は、配置の窓ごとにゲインを掛けた PCM を作る。窓の鍵にゲインのビットが入る（199 行）。
  ゲインを変えるたびに配置全体を複製し、その読込みが終わるまで新しい計画を出さない（ADR 0147 の待ち）。
- `Prepared::new`（playback.rs 310 行）は、ステレオの配置があるトラックのモノの配置を、計画を作るたびに 1/√2 倍で複製する。
- 長い素材ほど、ゲインの操作が遅くなり、メモリが増える。
- 修正方針: ゲインとモノの昇格を、ミックスの時の係数で掛ける。窓の鍵からゲインを外す。

2026-11-03 の対応: [ADR 0241](../decisions/0241-unscaled-placement-pcm.md) で、配置の未スケール PCM を共有し、ゲインとモノの昇格をブロックの係数にした。
ゲイン変更前後と計画の `Arc` の共有、桁あふれの拒否、旧来の焼込みとのビット単位の一致を回帰にした。実機の操作感・聴感は UC-48 に残る。

## P3 の詳細

### FCA-11: 使わないコードと届かない分岐

- `crates/echode-engine/src/handoff.rs`（`Control`・`Audio`・`pair`）は製品から使われず、自分のテストだけが使う。
  `spike` の feature にも入っておらず（SPG-10 の分離から漏れた）、`lib.rs` 46 行で公開している。`std::mem::forget` の経路を含む。
  その中だけが使う `Plan::write_mixer`（realtime 177 行）はトラックを線形に探す。
- オーディオスレッドの `step` に、制御側で変換済みの `SetLoop`・`ClearLoop` の分岐が残る。
  `PreviewFader` は `std::process::abort()` で止める（playback.rs 2293 行）。型でなく実行時の停止で不変条件を守っている。
- 修正方針: `handoff.rs` を消すか `spike` へ移す。リングに載せる命令を別の列挙型にし、届かない分岐を型から消す。

2026-11-03 の対応: [ADR 0253](../decisions/0253-product-only-playback-commands.md) で、未使用の受渡しと専用テスト・公開型・ミキサー書込みを削除した。
製品のリングは専用の命令型だけを運び、ループと単一フェーダーの変換を制御側の網羅的な分岐へ限定する。
`playback_command_tests.rs` は製品入口の順序・受領番号・入力拒否・往復の満杯と回収を確認する。
当時の観測は保持する。所有権の返却失敗に対する別の `abort` は今回の対象外である。

### FCA-12: 手で宣言した FFI

- [sync.rs](../../crates/echode-sandbox/src/sync.rs) は `os_sync_wait_on_address`・`os_sync_wait_on_address_with_timeout`・`os_sync_wake_by_address_any`・`pthread_set_qos_class_self_np` を手で宣言する。
  どれも `libc` 0.2.190 にある。`scripts/ffi-allowlist.txt` は、手で宣言してよいのをどの crate にもない API（今は `os_workgroup_*`）に限っている。
- `check-ffi.sh` はファイル単位なので、一覧にあるファイルへ足した宣言を止めない。
- エンジンの `device.rs` は CoreAudio を手で宣言し、`echode-audio-io` は同じ API を `objc2-core-audio` から使う。機器の問い合わせが 2 系統ある。
- 修正方針: `libc` へ置き換え、許可を関数名の単位にする。

2026-11-05 の対応: [ADR 0265](../decisions/0265-symbol-scoped-foreign-declarations.md) で、待機・起床・QoS と Mach 時計・signal を libc、CoreAudio の API と型を objc2 へ置き換えた。
許可はパスとシンボルの組に限定し、同じファイルへの追加・古い許可・`link_name` の差替えを回帰で拒否する。
Workgroup 等の未提供の宣言と SDK の全件照合は ENG-15 の残りであり、今回の対応と区別する。

### FCA-13: 時間の換算の重複

- 丸めの `div_round` が 4 か所にある（model `time.rs`、engine `clock.rs`・`plan.rs`、realtime `lib.rs`）。毎秒のフリック数とブロック長の計算も 2 か所ずつある。
  今は同じ区間ごとの丸めで一致するが、片方だけを直すと UI と音が 1 サンプルずれる。
- モデルの `integrate` はテンポ点の数に比例し、エンジンの `tempo_at`（plan.rs 46 行）は境界ごとに先頭から探す（2 乗）。リアルタイム側だけが二分探索である。
- 修正方針: 依存のない小さな時間の crate を 1 つにし、モデルとエンジンから使う。

2026-11-06 の対応: [ADR 0275](../decisions/0275-shared-integer-tempo-index.md) で、外部依存のない `echode-time` へ丸め・単位・テンポ索引・ブロック期間の整数計算を集めた。
モデルが索引を構築して再生計画へ共有し、換算は二分探索、計画側の積分の再構築はなくした。
原点前のテンポ点を含む計画とモデルの不一致も製品回帰で再現し、モデルの区間ごとの丸めを正本にした。
旧モデルとの独立照合、境界の訪問数、ブロック長を変える回帰を通常検査へ加えた。実機・聴感は UC-62 に残す。
最終の `make verify` は 2026-11-06 に容量不足（`Errno 28`）で製品契約の実行・結果保存中に中断した。
中断時点では未完了の自動検査を見送りや合格にはせず、空き確保の同意待ちとした。
同日にユーザーの同意を得て `target/debug/incremental` だけを整理し、既存成果物と検査記録を残して `make verify` を再実行した。
選択された自動検査の未完了を解消した。実機・聴感は UC-62 のままで、全体検査の未確認とも区別する。

### FCA-14: 1 編集ごとのジャーナルの同期

- `append_journal`（document.rs 133 行）は、毎回 `repair_journal` でジャーナル全体を読み（204 行）、`File::sync_all`（macOS では `F_FULLFSYNC`）を待つ。
- この機器で、1 行の追記と同期は `F_FULLFSYNC` が p50 4.0 ms・最大 44.6 ms、`fsync` が 0.03 ms、`F_BARRIERFSYNC` が p50 0.31 ms だった。
- 確定した編集を失わない設計として正しいが、編集の応答の下限になる。末尾の部分行の確認は最後の 1 バイトで足りる。
- 修正方針: 末尾だけを読む。続けて届いた編集の行をまとめて 1 回で同期する（確定の返答は同期の後のまま）。

2026-11-03 の先行対応: [ADR 0252](../decisions/0252-bounded-journal-tail-repair.md) で、通常の追記前確認を末尾の 1 バイトだけへ変えた。
未完の末尾は 4 KiB の作業領域で後ろから探し、完結した行を保持してから従来どおり短縮・同期する。
`document::journal_tests` は製品の追記で読んだバイト数、境界・非 UTF-8 の末尾、4 GiB を超える疎ファイルと復旧を検査する。
編集ごとの `F_FULLFSYNC` は維持する。まとめ書きは確定の意味に触れるため、ユーザーの判断待ちのままである。

### FCA-15: Sine Pad の依存

- 同梱の [Sine Pad](../../crates/echode-sine-pad/Cargo.toml) は `echode-engine` に依存し、`TestSynth` を使う。製品のプラグインがホストのエンジンの crate をリンクし、名前も試験用のままである。
- 修正方針: 音源の DSP を Sine Pad の crate か小さな DSP の crate へ移し、名前を直す。

2026-11-05 の対応: [ADR 0266](../decisions/0266-host-independent-sine-pad-dsp.md) で、DSP と確保の検出をホスト非依存の `echode-dsp` へ移した。
同梱 CLAP は `SinePad` を直接使い、エンジンの `TestSynth` は既存検査用アダプターに限定する。
依存の逆流を回帰で拒否し、ピン留めした wavesynth の標本・状態・声の引継ぎと、従来の製品経路の回帰を維持する。

### FCA-16: 書出しの形式

- [CLI](../../crates/echode-cli/src/lib.rs) の `wav_header`（493 行）は、IEEE float の WAV を 16 バイトの `fmt` で書き、`fact` を書かない。
  float の WAV は 18 バイトの `fmt` と `fact` を持つのが通例で、厳密な読み手は拒否し得る。
- 4 GiB（48 kHz ステレオで約 3.1 時間）を超えるとエラーにし、RF64・BW64 へ切り替えない。16・24 bit とディザもない。
- 修正方針: `fmt` を 18 バイトにして `fact` を足す。RF64 への切り替えと、TPDF ディザ付きの整数形式を選べるようにする。

2026-11-03 の先行対応: [ADR 0243](../decisions/0243-float-wav-metadata.md) で、18 バイトの `fmt` とフレーム数の `fact` を接続した。
再現は通常テストへ移し、基準音声は再生成せず全サンプルを保持する。RF64・整数形式・ディザは残る。

追加対応: [ADR 0247](../decisions/0247-pcm24-wav-export.md) で、CLI の 24 bit PCM 選択と飽和・丸め・出力保全を接続した。
RF64・16 bit・ディザは残り、当時の指摘全体の完了とはしない。

追加対応: [ADR 0248](../decisions/0248-pcm16-wav-export.md) で、CLI の 16 bit PCM と同じ出力保全を接続した。
RF64・ディザは未接続であり、過去の観測を変更せず一部対応のままとする。

追加対応: [ADR 0249](../decisions/0249-rf64-wav-export.md) で、大容量の全形式を RF64 に自動切替した。
`rf64_tests` はサイズ境界と疎ファイルの独立復号、`tests/rf64.rs` は CLI のストリーミングと出力保全を検査する。
ディザは残り、FCA-16 全体の完了ではない。

追加対応: [ADR 0251](../decisions/0251-tpdf-export-dither.md) で、CLI の TPDF を既存の三角分布と PRNG へ接続した。
既定の出力保持、分割不変性、分布・量子化誤差、実 CLI と独立した復号、故障時の出力保全を回帰化した。
指摘の実装は対応し、実機の聴感と利用者の読み手は UC-52 に残す。

### FCA-17: Swift のポーリングとラベル

- `observeAudio`（ProjectController.swift 568 行）は、表示中は 50 ms ごとに文書ワーカーへ状態の要求を送り、JSON で往復する。変化がなくても止まらない。
- ラベルのテクスチャは幅を鍵にし（ArrangeLabels.swift 70 行）、そのフレームに見えたものだけを残す（84 行）。
  ズームや幅の変更の間は、毎フレーム全ラベルを Core Text で描き直し、テクスチャを作る。計測はしていない。
- 修正方針: 状態は変わった時に知らせる。ラベルは幅に依らない描画か、字形のアトラスにする。

### FCA-18: 保管庫の PCM の形式

- [media.rs](../../crates/echode-history/src/media.rs) は、素材をファイルの率の非圧縮 f32 で保管する。
  元のファイルに比べ、24 bit の WAV は 1.33 倍、16 bit の WAV は 2 倍、FLAC は数倍、MP3・AAC は 10 倍以上になる。
- `encode_pcm` は標本とバイト列を同時に持つので、長い素材で一時的に 2 倍のメモリを使う。ディスクの逐次読込みは既知の未実装である。
- 修正方針: 可逆圧縮で保管するか、元のファイルと検証の値を持つ。書込みは流して行う。

### FCA-19: 減らない記録

- Undo の段とメモリ上のジャーナルは、メモリだけを上限にする（session.rs の冒頭の方針）。長い作業でメモリが増え続け、上限の監視もない。
- 再生の `PlaybackIds` の表は、消えたノートの番号も持ち続ける。
- 修正方針: メモリの予算を決め、超えた古い段を Git の履歴へ任せる。計画の作り直しで今のノートだけを残す。

2026-11-05 の先行対応: [ADR 0267](../decisions/0267-current-playback-id-mappings.md) で、成功した現在の計画にないノート・トラックの対応と表の容量を制御側で解放する。
残る ID の番号は保ち、古い計画が使い得る番号は再利用しない。追加・削除の反復と失敗後の再試行を `plan_tests.rs` に置く。
Undo とジャーナルの予算はユーザーの判断待ちのまま残し、FCA-19 全体を完了扱いにしない。

### FCA-20: 走査の期限

- 走査はバンドルごとに別プロセスで、5 秒で止める（scan.rs 47 行）。
  起動時に認証を確かめる市販プラグインは、初回の読込みに 5 秒を超えることがある。読解と一般的な事例からの推定で、確かめていない。
- 修正方針: 初回は長い期限にし、時間切れのバンドルを再試行できるようにする。期限を設定にする。

## 確かめて問題がなかった点

- 共有領域の値で範囲外を読む: 件数はホスト側の `layout` で切り、音声は写すだけで、非有限は段の後で 0 にする（`region.rs` の `collect_ready`）。
- API の要求の大きさ: ソケットも MCP も 1 MiB で切る（`serve.rs` の `MAX_REQUEST_LINE`）。
- 記述子の上限: 最初のヘルパーの前に soft の上限を上げる（[ADR 0237](../decisions/0237-helper-descriptor-limit.md)）。
- `Snapshot` の `@unchecked Sendable`: 可変の作業領域は `visibleLock` の内側でだけ使う。
- 描画: `CAMetalDisplayLink` を描画スレッドで作り、命令のバッファはスロットごとに再利用する（`CanvasRenderer.swift` 333 行）。
- 走査の隔離: バンドルごとのプロセスグループを期限で殺し、標準エラーには上限がある。
- 時間の換算: モデルとリアルタイムは同じ区間ごとの丸めで、今は一致する（重複は FCA-13）。

## 保たれている構造

- オーディオスレッドは計画を受け取って返すだけで、解放しない。確保の検出と RTSan の二重の検査がある。
- 描画の索引は `Arc` の同一性で変わらないトラックを共有し、区間木で見える範囲だけを引く。FCA-04・05 の手本になる。
- 共有領域はホスト側の配置で検査し、ヘルパーの値を信用しない。
- 編集・保存・復旧の正しさは、不変条件と性質テストで守られている。規模の修正はこの検査の下で行える。
