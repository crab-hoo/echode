# モデル・アクション・履歴アーキテクチャ（§4〜§6）

- 全体索引: [../ARCHITECTURE.md](../ARCHITECTURE.md)
- 操作要件の正本: [../interaction-design.md](../interaction-design.md)
- 現在の実装範囲: [../status.md](../status.md)

製品モデルは `echode_model::Project` だけを使う。
Phase 0 の履歴の別モデル・形式・Git 保存は、`echode-history` の非既定の `spike` feature に閉じる
（[ADR 0211](../decisions/0211-opt-in-history-spike.md)）。通常の製品ビルドには含めない。

## 4. ドキュメントモデル

### 4.1 主なオブジェクト

- **Project**: グローバルマーカー、リージョン、コードトラック、トラックの木、マスター、設定
- **Track**: 種別を持たない。MIDI、オーディオ、オートメーションのどのクリップも置ける。
  デバイスチェイン、静的チャンネル、ルーティング、子トラック（フォルダ）を持つ
- **Content（中身）**: ノート列、オーディオの参照、テイクの ID。内容時刻 0 は作成時に固定し、配置は中身の ID を持つ
  （[ADR 0022](../decisions/0022-clip-content-and-placement.md)）
- **Placement（配置）**: トラック上の窓。開始、長さ、内容オフセット、自動か固定か、線形ゲイン、入りと出のフェード。
  内容位置 0 は `start - offset` に固定し、負のオフセットはファイルより前の無音とする。
  保存上の名前は `clip`。Phase 2 で配置ごとのクリップ FX チェインを持つ
  （§4.8、[ADR 0109](../decisions/0109-placement-bounds-and-plugin-capture.md)）
- **Note**: 音高、開始位置、長さ、16 ビットのベロシティとリリースベロシティ、アーティキュレーションの参照。
  表情の曲線（Pitch、Timbre、Pressure）は中身の別配列にノート ID で置く
  （[ADR 0027](../decisions/0027-note-expression.md)）
- **Device**: プラグイン、内蔵デバイス、コンテナ、モジュレーター、レシーバー。それぞれパラメータを持つ。
  Phase 1 のトラックは CLAP デバイスを挿入順に並べ、末尾をミキサーにする
  （[ADR 0048](../decisions/0048-clap-device.md)）。
  再生はデバイスごとにヘルパーへ通し、内蔵シンセの前で処理する（[ADR 0049](../decisions/0049-hosted-playback.md)）
- **Parameter**: ベース値（固定値かオートメーション）と、変調の割り当て
- **Marker**: テンポ（瞬時の変化か直線的な変化）、拍子、キー（主音と旋法）、汎用のマーカー
- **Region**: 名前付きの時間範囲。範囲内にある全トラックの内容をまとめて移動・複製できる
- **Media**: 音声ファイルへの参照（内容のハッシュ、元の名前、形式、サンプルレート、長さ）
- `note.velocity` は配置から共有内容を解決し、ノートの発音ベロシティだけを変更する。
  時刻・音高・リリース・表情・配置窓は保持し、既存の 7 bit 入力から 16 bit への変換を使う
  （[ADR 0173](../decisions/0173-piano-note-velocity.md)）。
- `note.duplicate` は指定配置の共有内容へ新 ID のノートを追加し、元の長さ・16 bit の強弱・表情を保つ。
  時刻と音高だけを指定し、配置の拡張は `note.edit` と同じ経路を使う。ID は省略時に生成し、ジャーナルへ確定値を記録する
  （[ADR 0184](../decisions/0184-piano-note-duplicate-drag.md)）。

### 4.2 不変スナップショット

モデルは不変のスナップショットで持つ。アクションを 1 つ適用するたびに、新しい版と変更一覧（ChangeSet）を作る。
Phase 1 は変わっていないトラックを `Arc` で共有し、ノート列の永続データ構造（`imbl`）は Undo が重いと判明した段階で導入する
（[ADR 0007](../decisions/0007-s5-confirmed-phase1.md)）。

- **UI**: ChangeSet を受け取り、関係する画面だけを更新する。描画スレッドは任意の版を安全に読める
- **エンジン**: ChangeSet からグラフの差分を作り、裏で組み立ててから差し替える
- **履歴**: 版を JSON に書き出してコミットする
- **Undo**: 過去の版を保持しておくだけで実現できる

全オブジェクトとプロジェクト拍子の `*_fields.rs` を、モデル宣言・変更セット・保存の共通の正本にする。
差分・作成・下書き・設定・復元、保存の Serde と変換を生成し、既存の順序・ビット・整数と旧形式の互換を保つ。
中身・トラック・プロジェクトの子と同一性は、スカラーのメタデータと分けて復号・解決し、公開前に全体の不変条件を検査する。
配置はモデル型を直接保存し、テンポ点の平らな分数表現も同じ表から生成する。
`Property` の名前と `Value` の種類・ジャーナルの変換も、それぞれ 1 つの登録簿から生成する。
FFI は同じ項目表の投影指定から安全なスカラー問い合わせ・配置コントロールへの転記を生成する。
C ABI のレイアウトとポインタ処理は明示的な境界に残し、自動公開しない。
階層・表示行・描画幾何・ミキサーの操作子・テンポ積分したフェード長は派生値であり、項目の転記とは分ける。
生成と形の復号を、参照・子の解決や有効なプロジェクトの受入と混同しない。
経緯と回帰は [ADR 0226](../decisions/0226-model-field-registry-completion.md) を参照する（SPG-09 完了）。

不変条件の時刻検証は、内容ごとに全ノートの最初の開始と最後の発音 tick を一度集計し、配置の原点を足せるかを両端で検査する。
自動クリップの小節範囲も同じ両端から求め、共有内容のノートを配置ごとに走査しない。
範囲外の配置だけは最初の問題ノートの診断を保つため再走査する。
集計は検査内の一時値で、保存形式・スナップショットのフィールド・音声コールバックへ追加しない。

ノートの追加・編集・複製の共有配置検証も、変更後の内容から最初の開始と最後の発音 tick を一度だけ集計する。
ノートのローカル終端を検証してから、各配置の原点を両端に加えられるか調べる。
ノート数 N・全配置数 P・トラック数 T に対し O(N + P + T) とし、配置ごとの全ノート走査をしない。
固定窓の外にあるノートも含め、整数の上下端での拒否と元の版の保持を変えない。内容のノート列は借用し、検証のために複製しない。

親の存在と循環の検証は、組立てと不変条件の検査で `hierarchy::check_forest` を共有する。
一時的な ID 索引と未訪問・探索中・解決済みの状態を使い、親を各トラック一度だけ訪ねる（期待 O(T)、T はトラック数）。
入力のアレンジ順に依存せず、再帰や深さの上限を設けない。順序キーとアレンジ順の検証は別に維持する。
トラックの親変更も、変更後の親グラフを同じ検証器で一度だけ調べる。
移動先の祖先ごとに全トラックを探索せず、循環・自己参照を拒否し、親が同じ操作は検証前に無変更で返す。

### 4.3 ID と並び順

- 全オブジェクトに UUIDv7 を振り、参照はすべて ID で行う
- 内容の配列は ID 順を不変条件とし、参照解決に二分探索を使う。
  配置の参照は制御側で集合へまとめ、内容ごとに全配置を走査しない。
  集合は編集・検証ごとに作り、永続的な参照数や全 ID の索引はまだ持たない（[ADR 0242](../decisions/0242-model-content-lookup-and-references.md)）。
- トラックの並び順は、同じ親の兄弟ごとに分数インデックスの文字列で持つ。
  アレンジ画面の順はそのキーで木から作る（[ADR 0024](../decisions/0024-track-order.md)）。
  デバイスの並びも同じ形にする
- `track.insert` は指定トラックの下、または子を持つフォルダの末尾へ追加する。
  新規トラックのキーだけを決め、既存トラックを保持する（[ADR 0127](../decisions/0127-positioned-track-insertion.md)）。
- `track.duplicate` は部分木を元の直後へ複製し、根だけに新しいキーを振る。
  複製の ID は記録した `seed` と元 ID から導出し、配置の中身とノートは元と独立させる（[ADR 0129](../decisions/0129-track-duplication.md)）。

### 4.4 時間の表現

| 種類 | 単位 | 用途 |
|---|---|---|
| 音楽上の時間 | tick（1 拍 = 705,600） | ノート、クリップ、マーカーなど、拍に乗るもの |
| 実時間 | flick（1 秒 = 705,600,000） | 時刻に固定するもの（効果音、将来の映像同期）、オーディオファイル内の位置 |
| サンプル | 整数のサンプル番号 | エンジンの内部だけで使う |

705,600 は $2^6 \times 3^2 \times 5^2 \times 7^2$ であり、3・5・7 連符とその入れ子、1/256 音符まで割り切れる。
flick は 44.1kHz 系と 48kHz 系の主要なサンプルレート（8kHz〜192kHz）と一般的な映像フレームレート（23.976fps 等）で割り切れる。
デバイスのサンプルレートを変えてもモデルは変わらない。
テンポマップは区間ごとの一定テンポと直線的なテンポ変化で構成し、tick と flick を閉じた式で相互に変換する。

Swift の時間単位と拍の入出力は、製品 C ABI を読む `ModelLimits` と `Tick` へ集める。
モデルと別の数値を定義せず、保存の整数表現と既存の丸めを保つ
（[ADR 0200](../decisions/0200-shared-model-units-and-limits.md)）。

整数の丸め・サンプル換算とテンポ積分の索引は、外部依存のない `echode-time` に置く。
`TempoMap` はソート済みの点から原点を基準に索引を一度作り、スナップショットと再生計画が `Arc` で共有する。
問合せは O(log T)、構築は整列後 O(T)。原点の前後で区間ごとに丸め、モデルの既存の flick / tick の結果を保つ。
原点前の部分区間の順変換は右端、逆変換は従来どおり左端を基準にする（[ADR 0275](../decisions/0275-shared-integer-tempo-index.md)）。
保存には元のテンポ点だけを書き、合成する原点の境界や派生索引は保存しない。定数の旧公開パスは再公開で維持する。

### 4.5 スマートクリップ

配置は `auto`（自動）と `fixed`（確定）の 2 つの状態を持つ。ノートは中身にあり、自動配置は中身につき 1 つまでとする。
窓を前へ伸ばすときは開始とオフセットを同じだけ動かし、既存ノートの `start` は書き直さない
（[ADR 0022](../decisions/0022-clip-content-and-placement.md)）。
鳴らすのはノートと窓の共通部分だけである（[ADR 0025](../decisions/0025-clip-window-cuts-notes.md)）。

- クリップのない場所にノートを置くと、そのノートを含む 1 小節分の `auto` クリップができる
- `auto` の窓は `origin = start - offset` から数えた中身の小節でノートを覆う最小範囲へ合わせる。
  ノートの挿入・編集・削除で伸縮し、小節未満の移動・複製でも `auto` のまま原点と一緒に動く
  （[ADR 0170](../decisions/0170-content-relative-auto-bars.md)）。
- クリップの端を手で編集（伸縮、分割）すると `fixed` になり、挿入・削除による自動の合わせ直しを止める
- `note.edit` の時刻変更は、対象の `fixed` 窓もノート全体を含むまで広げる。小節へ丸めず、短縮で窓を縮めない。
  左へ広げる時は開始とオフセットを同じ量だけ変え、他ノートの発音位置を保つ。
  音高だけの変更と他の固定リンクの境界は変えず、重複する拡張は編集全体を拒否する
  （[ADR 0168](../decisions/0168-note-edit-clip-growth.md)）。
  所属を位置で決め、固定も中身の小節で伸ばし、隣の配置で止める残りの見直し案は
  [ADR 0169](../decisions/0169-clip-growth-follows-notes-and-stops-at-walls.md)（草案・その部分は未採用）にある。
- `auto` クリップのノートがすべて消えたら、クリップも消える
- P2 のオーディオ端ドラッグは非破壊トリム（素材終端で停止）、自動クロスフェード、分割端の短フェードに対応する
  （[構成編集の要件](../interaction-design.md#アレンジの選択と編集)）
- 同一トラックの配置重複は現行モデルでは拒否される。P2 の重ねるモードでは不変条件・アクション・保存・可視問い合わせ・音声索引をまとめて変更する
- `clip.move` と `clip.duplicate` は置き換えで着地し、移動先の重なる配置を削除・切詰め・分割する。
  残した部分は `fixed` で、切り口に既定のフェードを付ける。移動・複製自体では元の `kind` を保つ。
  複製と分割の ID は記録した `seed` から導出する（[ADR 0154](../decisions/0154-clip-move-and-duplicate.md)）。
  新しい操作は `content_bars: true` を記録し、印のない旧ジャーナルは従来の移動規則で再生する（ADR 0170）。
  （[ADR 0117](../decisions/0117-workflow-interactions.md)）

### 4.6 パラメータと変調

最終値は、「ベース値に加算型の変調の合計を足し、範囲内に収めた値」に乗算型の変調の積を掛けたものとする。

- **ベース値**: 固定値、またはオートメーションの値（正規化 0〜1）
- **加算型**: 双極（−1〜+1）か単極（0〜1）の変調源に深さを掛けた量
- **乗算型**: 0〜1 の値を掛ける
- **CLAP / VST3 / AU**: CLAP にはベース値イベントと変調イベントを分けて送り、VST3 / AU には最終値をサンプル位置付きイベントで送る
- **アドレス**: トラック FX は `track/<id>/device/<id>/param/<id>`、Phase 2 のクリップ FX は `clip/<id>/device/<id>/param/<id>`
  （[ADR 0026](../decisions/0026-parameters.md)）
- **CLAP の値**: プラグインの状態バイトが正本で、モデルのパラメーター配列には複製しない。
  パラメーターの `<id>` は CLAP の `u32` ID とし、ホストの編集は状態の記録として履歴に入る（[ADR 0130](../decisions/0130-clap-parameter-editing.md)）。
  一覧のピン留めは値ではなく ID の集合で、デバイスの設定として `device.pin_parameter` で記録する（[ADR 0131](../decisions/0131-device-view-and-responsive-parameters.md)）

### 4.7 オートメーション

- オートメーションはパラメータのベース値を時間で変える。レーンはパラメータごとに 1 本
- **オートメーションクリップ**: レーン上に置く独立オブジェクト（移動、複製、ループ、リンク複製が可能）
- **曲線とモード**: 直線、ベジェ、ステップ、S 字。書き込みモードは読み取り、タッチ、ラッチ、書き込み
- **P2 の表示と編集**: オートメーションモード有効時はクリップ領域を曲線表示へ切り替え、最後に操作したパラメータを自動表示する。
  点追加・ドラッグ・曲率調整・試聴復帰の仕様は [操作要件](../interaction-design.md#オートメーションの表示と編集) を参照

### 4.8 クリップ FX

Phase 2 で配置ごとの非破壊デバイスチェインを追加する（[ADR 0059](../decisions/0059-clip-fx.md)）。

- **所有**: チェイン、パラメータ、プラグイン状態、FX オートメーションは配置が持ち、Content 共有配置間でも FX は共有しない
- **時刻**: FX オートメーションは内容時刻で持ち、`placement.start + point.time - placement.offset` でプロジェクト時刻へ変換する
- **複製・分割・スマートクリップ**: 複製と分割では新しい ID を振って状態を引き継ぐ。最初の FX 追加と配置の `fixed` 化を 1 回の Undo にまとめる
- **保存**: トラック JSON に配置チェインと曲線を書き、プラグイン状態は `media/objects/` のハッシュで参照する

## 5. アクションシステム

アクションは ID、日英の表示名と説明、JSON Schema、実行条件、既定ショートカット、Undo 扱いを持つ定義として登録する。
モデルを変えるアクションは Rust 側（`echode-actions`）、UI だけのアクションは Swift 側に実装し、同じ登録簿に載せる。

- **トランザクションと Undo**: 操作前のスナップショットを積み、未変更トラックは `Arc` で共有する。
  連続ドラッグは 1 つの Undo 単位にまとめる（[ADR 0008](../decisions/0008-actions-undo-journal.md)）
  外部音声の取込みもトランザクション内で PCM 保存と `audio.place` へ解決し、トラック追加と 1 回の Undo にできる
  （[ADR 0145](../decisions/0145-sample-browser-file-drops.md)）。
  PCM は一時の名前で同期して待たせ、編集が受理された時だけハッシュへ改名して索引とピークを作る。
  拒否した編集は一時の名前を消すので、素材を残さない（[ADR 0272](../decisions/0272-staged-import-media.md)）。
  記録する `audio.place` は両端のフェードを持ち、新しい配置は 0 を書く。欄のない以前のジャーナルは 5 ms で再生する
  （[ADR 0161](../decisions/0161-placed-audio-without-fades.md)）。
  無変更の単一編集と、正味の変更が残らない束は成功として返し、Undo・Redo・公開・ジャーナル・自動保存を変えない
  （[ADR 0182](../decisions/0182-noop-edits.md)）。
  C ABI の perform 完了も `historyReport.changed` を返し、Swift の件数と入力長の履歴枠は真の時だけ増やす。
- **ジャーナル**: 採番した ID を含めた操作を 1 行ずつ追記し、Undo した操作は先端から外す。クラッシュ後は最後の自動コミットに再生して復旧する
- **キーマップ・マウスコマンド・コマンドパレット**: 画面ごとの TOML キーマップ（Space＝再生／停止、Return＝一時停止／再開等）、
  修飾キー×対象のマウスコマンド表、`nucleo` によるあいまい検索パレットを提供する

## 6. プロジェクト形式と履歴

### 6.1 パッケージの構成

```text
MySong.echode/
  project.json          プロジェクト全体（マーカー、リージョン、中身の ID、トラックの並び、マスター）
  contents/<id>.json    中身ごとに 1 ファイル（ノート、オーディオの参照、テイク）
  tracks/<id>.json      トラックごとに 1 ファイル（デバイス、状態のハッシュ、配置）
  media/index.json      メディアの一覧（ハッシュ → 元の名前、形式、長さ）
  media/objects/...     音声とプラグインの状態（BLAKE3 で命名し、書き換えない）。Git の外で管理する
  cache/                波形のピーク、解析結果、ストレッチのキャッシュ（履歴に入れない）
  transport.json        記憶した再生開始位置（履歴・Undo に入れない。ADR 0155）
  export.json           前回の GUI 書出し設定（履歴・Undo に入れない。ADR 0257）
  .git/                 履歴（ユーザーには見せない）
```

### 6.2 差分の取りやすい JSON

- 開いた親ディレクトリを基準にリンクを辿らず操作し、一時ファイルを排他的に作って置換する
  （[ADR 0074](../decisions/0074-package-entry-io.md)）
- キー順序を固定し、時間は整数、1 ノート 1 行で出力する。スキーマは 1 段ずつマイグレーションして読む
  （[ADR 0028](../decisions/0028-package-schema.md)）
- 現行スキーマは 6。デバイスの `bypassed`・`offline` と、一覧の最上部に固定する CLAP パラメーター ID の `pinned` を保存する
  （[ADR 0131](../decisions/0131-device-view-and-responsive-parameters.md)）。
  3 以前はバイパス解除、4 以前はオンライン、5 以前はピン留めなしとして段階変換する。
  旧リーダーが新しい音声状態を無視しないよう版を進める
  （[ADR 0120](../decisions/0120-device-bypass.md)、[ADR 0125](../decisions/0125-device-offline.md)）。
- 配置ゲインとミキサーパラメーターの浮動小数点は、読み戻して元の値を保つ十進表記にする。
  旧表記が正確な時はそのバイトを保ち、小さい正の値を 0 に丸めない。0 の正規化とスキーマ 6 は維持する
  （[ADR 0196](../decisions/0196-lossless-package-floats.md)）。

### 6.3 メディアの保管庫

音声とプラグイン状態は BLAKE3-256 小文字 16 進で `media/objects/` に不変保存し、トラック JSON の `state` から参照する
（[ADR 0031](../decisions/0031-content-addressed-store.md)、[ADR 0056](../decisions/0056-audio-import.md)）。
波形ピークは `cache/peaks/<hash>` に置き、履歴には入れない（[ADR 0058](../decisions/0058-waveform-peaks.md)）。
現行の識別子は `ECHDPK02`。有限ステレオの平均は構築・マップとも `f64` で加算・除算してから `f32` へ戻す。
旧版の誤った無音を残さないよう、`ECHDPK01` は PCM から再生成する。PCM がなければ波形なしとし、原本を変更しない。
保管庫の除外規則は `.gitignore` の正確な行を照合し、不足分だけを既存テキストの末尾へ加える。
コメントや部分一致を除外規則と見なさず、CRLF と末尾改行なしの正確な規則も保持する
（[ADR 0031 の後続修正](../decisions/0031-content-addressed-store.md#除外規則の行単位の照合2026-10-29)）。

### 6.4 保存とコミット

- **自動保存**: `refs/echode/autosave/<オルタネイト>`（Phase 1 は `refs/echode/autosave/main`）。
  先端コミットの連番より後のジャーナル行を再生し、先端が無いパッケージは編集前に同期コミットする
  （[ADR 0009](../decisions/0009-package-autosave.md)、[ADR 0033](../decisions/0033-journal-log.md)、[ADR 0057](../decisions/0057-crash-recovery.md)）
  再生する各行の適用後にモデルの不変条件を検査し、不成立なら連番と理由を返してオープンを拒否する。
  完結した行を黙って切り捨てず、不正な状態を公開・自動保存しない（[ADR 0180](../decisions/0180-journal-replay-invariants.md)）。
  読めない先端を飛ばした時は、先端・基点・復旧済み連番を通知し、明示同意まで全書込みを拒否する。
  同意は復旧状態の同期保存後に成立し、Swift はそれまで既存文書を保持する
  （[ADR 0183](../decisions/0183-recovery-consent.md)）。
  コミットは新しいオブジェクト・振り分けディレクトリ・参照を `fsync` で書き出し、チェーンの追記の `F_FULLFSYNC` で確定させてから完了する。
  ジャーナルの短縮はその完了の後に行う。保管物はディレクトリまで同期してから、それを名指す行を書く。
  参照がチェーンの最新より古ければ最新から続け、連番の欠けと状態の保管物の欠落は同意へ送る（[ADR 0230](../decisions/0230-save-durability.md)）。
  追記前の確認は末尾の 1 バイトだけを読み、未完の末尾がある時だけ一定の作業領域で後方へ探す。
  完結した行は削らず、短縮の同期と編集ごとの同期は保持する（[ADR 0252](../decisions/0252-bounded-journal-tail-repair.md)）。
  Git の初期化失敗中も終了要求を受け付ける。初回保存を拒否した後の破棄で待ち続けず、開く処理へエラーを返してパッケージのロックを解放する。
- **Cmd+S と間引き**: `refs/heads/<オルタネイト>` の保存ポイントは間引かず、自動保存だけを `gix-pack` で間引く
  （[ADR 0046](../decisions/0046-history-thin.md)）。
  `gix-pack` は `streaming-input` 機能を入れるための直接の依存で、gix が解決する版と完全一致で固定する
  （[ADR 0270](../decisions/0270-gix-0-90-and-github-advisories.md)）

### 6.5〜6.7 要約・履歴 UI・オルタネイト

- **自動要約（§6.5）**: 2 版間の構造化差分から要約とタグを生成する
- **履歴 UI と試聴（§6.6）**: Phase 1 は自動保存コミットの一覧と全体復帰（履歴を書き換えず新しい版として記録、Undo 可能）を実装する
  （[ADR 0054](../decisions/0054-history-restore.md)）。トラック単位復帰と試聴は後続 Phase で扱う
- **オルタネイトとセマンティック・マージ（§6.7）**: Git ブランチを並行プロジェクトとして見せ、テキストマージではなくモデル上で依存関係を含めてマージする
