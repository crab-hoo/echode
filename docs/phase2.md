# Phase 2 の進め方

開始: 2026-10-17。ユーザーの「Phase 2に移行しよう」を受けて開始する。P1 の根拠は[最終照合](reviews/2026-10-17-phase1-acceptance.md)を保持する。Phase 2 全体の範囲と完了条件の正本は [PLAN の Phase 2](PLAN.md)。この文書は依存関係に沿った実装順と、各単位を完了にするための証拠をまとめる。予定の機能を現在の実装と混同しない。

現在は P2-01 のヘッドレス MCP の実装と自動受入を完了した。通常回帰、必須契約と負の対照を含む自動検査9項目が正式な入口で合格した。最新の有効性は `target/verification/report.md` を参照する。次の単位は P2-02。外部クライアントの設定・GUI 接続・実機確認は P2-01 の自動合格と区別する。

## 引き継ぐ条件

- macOS 27 以降、M4 ファミリー以降。自前のビルドは固定 M4、汎用設定が速い場合は比較を残す（[ADR 0114](decisions/0114-m4-build-baseline.md)）。
- 各単位を製品の入口から保存・復旧・Undo / Redo・再生／書出しへつなぎ、必要な資料・回帰・診断を同時に更新する。音に関わる単位はブロック長比較と RT の検査を持つ。
- プラグインは本体外、RT の確保・ロック・待機は禁止。固定したトラック数やチャンネル数、階層の深さを上限にしない。
- 実機・聴感はユーザー担当。自動検査で保証しない点を明記する。未解決の HAL / errno の TSan 条件は [status](status.md#検査基盤で区別すること) に残し、P2 開始を解決の根拠にしない。
- 通常の確認は `make verify`。各単位の受入を完了したことと、Phase 2 全体の完了を区別する。

## 実装順と受入条件

### P2-01: MCP から既存の編集経路を検査する

最初の実装単位。[ADR 0115](decisions/0115-phase2-mcp.md) のヘッドレス版を実装した。既存アクションのツール、まとめた編集、Undo / Redo、概要とトラックのリソースを提供し、DocumentHost とジャーナルを共有する。

受入は実 `echode mcp` と実 `echode serve` を一時パッケージで起動し、トラック＋ノートの一括編集、1回の Undo、Redo、途中で失敗する一括編集の巻戻し、別クライアントからの同じ結果の読取り、プロセス終了後の復旧を確認する。通知や不正な ID で編集せず、標準出力へ診断が混ざらず、EOF で接続先を終了しない。誤りを戻したコピーを必須契約で拒否する。

この初版には GUI のソケット接続・音声操作を含めない。外部 MCP クライアントへの登録も設定しただけで合格にせず、別の確認とする。

### P2-02: デバイスビューとパラメーター編集

まず既存の CLAP で、チェインの追加・削除・並べ替え・バイパス・オフライン化とパラメーター編集、ヘルパー所有の GUI の開閉を製品へ接続する。トラック／クリップの編集対象を表示し、クリップ FX を足す時に同じ入口を拡張できる形にする。ブラウザの開閉・挿入先・サムネイルもこの経路に結び付ける。

受入は実 View 入力、アクション、プラグイン状態の取得・再読込と Undo を通す。GUI のイベント・フォーカス・クラッシュ・再起動の確認は、状態の自動検査と実ウィンドウを区別する。GUI アプリの MCP 入口は同じ書き手を共有し、別の DocumentHost でパッケージを開き直さない。

### P2-03: ルーティング・フォルダバス・PDC

ミキサーへ接続する前に、フォルダの入れ子、センド／リターン、サイドチェーンと PDC を制御側の実行計画へ組み込む。循環の拒否、チャンネルの意味、加算順序、レイテンシ変更と計画交換を定義する。将来のクリップ FX の合流も PDC の対象とする。

受入は独立した基準信号の到着位置と振幅、階層・センド・サイドチェーンの経路、レイテンシ変更、停止・ループ・シーク、ブロック長の違い、RT の禁止操作を製品バッファで確認する。UI の親子関係だけを音声バスの完成にしない。

### P2-04: オートメーションとクリップ FX

パラメーターのアドレス・モード・曲線と書込みを整え、配置ごとのチェイン、状態、追従する曲線、テールを実装する。最初の FX 追加でスマートクリップを固定し、移動・複製・分割、リンクした中身と独立した FX の関係を守る。デバイスビューと PDC に接続してからバウンスへ進む。

受入は PLAN のクリップ FX 条件をそのまま使う。特定の配置だけに効くこと、状態と曲線の保持、余韻・PDC、Undo / Redo、保存・復旧、再生と書出しの一致を自動検査する。処理中の編集と別トラックへのバウンス取込みも確認する。

### P2-05: VST3 / AU とブラウザの対応形式

共通チェインの契約へ VST3、AUv2、AUv3 を順に加える。AUv3 は OS の XPC extension にヘルパーを重ねない（[ADR 0111](decisions/0111-macos-helper-notices.md)）。追加検知、状態、イベント、バス、GUI、再起動を形式ごとに確認する。

受入は実形式の fixture と別プロセスを使い、スキャンから製品再生・書出しまで確認する。無料プラグインの実機互換性は形式の自動回帰と別に記録する。依存を選ぶ時に公開 API と GPL の両立を確認する。

### P2-06: ミキサーと内蔵基本デバイス

ルーティングとパラメーターをコンソール表示へ接続し、内蔵ユーティリティ、EQ、ダイナミクス、LUFS・トゥルーピーク等のメーターを加える。定番 DSP は既存の GPL と両立する実装を調べて測り、既存実装より完全に劣るものを除いて選択肢を保つ。

受入はバイパス、係数・状態更新、ステレオとチャンネル、遅延、既知の測定信号、クリッピング、ブロック長と RT の契約で行う。グラフやメーターの見た目だけを正しい DSP の証拠にしない。

### P2-07: マーカー・録音・ピアノロール

テンポ・拍子・キーのグローバルマーカーとリージョン、MIDI / QWERTY / 外部 MIDI の録音、ループ重ね録り、単一テイクのオーディオ録音、クオンタイズ、MIDI 割当を実装する。ゴーストノートとトラックセレクター、調表示も同じ時刻と選択へつなぐ。

受入は注入した時刻付きイベントと入力バッファ、ループ境界・テンポ変更、1回の Undo、保存・復旧を先に自動化する。マイク・MIDI 機器の許可、実入力の遅延、聴感はユーザーの確認範囲として残す。

### P2-08: 書出しとプロジェクト管理

各種形式、ステム、ノーマライズ、ディザ、SRC の選択、プリセット、テンプレート、再リンク、収集して保存、履歴 UI の一覧・復帰・変更要約・タグ、定期バックアップを順に接続する。CLI の別プロセスで処理し、編集中の文書を上書きしない。SRC は PLAN の既存候補を同じ条件で比較する。

受入は再生との一致、形式・レート・チャンネル、失敗時の原本保持、処理中の編集、素材の hash、復旧・Undo を確認する。実装の選択肢と計測条件は ADR に残す。Phase 3 のプレビューキャッシュを完成扱いにしない。

### P2-09: Mac の操作と1曲の受入

ジェスチャーの選択肢、触覚、ホットコーナー、初期ショートカットを上記の編集・ミックスへ接続する。機器なしの入力回帰を先に作り、ユーザーの実操作・聴感で1曲を打込みからミックスまで制作する。

Phase 2 の終了は、各単位の自動検査と理由付きの未確認を照合し、PLAN の「作者自身が1曲を Echode だけで作れる」をユーザーが確認した時とする。最初の MCP だけではこの条件を満たさない。
