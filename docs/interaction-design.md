# 制作ワークフローとインタラクションの検討

更新: 2026-10-20。
コード入力から、メロディ・ドラム・ベース、構成編集、楽器追加による編曲、ミックス、オートメーション、書き出しまでの対話を一括整理した操作要件と未決事項の正本である。
判断の理由と旧方針との関係は [ADR 0117](decisions/0117-workflow-interactions.md)、実装済みの範囲は [status](status.md)、実装順と単位別受入条件は [Phase 2 の進め方](phase2.md) を参照する。

## 最初の制作シナリオ: コードを打ち込んで聴き直す

1. 空のトラックを追加する。音源を選ぶ画面は自動で開かず、自分で開く。
2. そのトラックへ音源プラグインを挿す。挿した音源の GUI は自動で開く。
3. そのトラックのアレンジ上の空白をダブルクリックし、その位置をピアノロールで開く（記憶した再生開始位置は変えない）。
   コードの構成音をベタ打ちし、シングルクリックでは記憶した入力長、空白からのドラッグでは左右で長さ・上下で音高を調整する。
   入力・単一ノートの伸縮・単一選択で、そのノートの長さを次へ引き継ぐ。
4. 最初のコードと音色を確認した後も、そのままシングルクリックで構成音を置き、先の小節へはトラックパッドの横スクロールで移動する。
5. 停止後は毎回、記憶した再生開始位置から鳴らす。一時停止した場合は、その位置から再開できる。
6. 別の箇所から確認したい時はルーラーをクリックする。再生中なら直ちにその位置へ移動して再生を続け、次回の再生開始位置もそこへ更新する。

## 次の制作シナリオ: コードを参照してメロディを置く

1. 別のトラックにメロディを打ち込む。
2. メロディの編集対象を明示的に開き、他トラックのノートを背景に薄く表示（ゴーストノート）して参照する。
   初期状態では他の全トラックを表示し、右のトラックセレクターで表示をオン／オフする。
3. マウスでノートを置いてメロディを作る。入力長は全トラックで共通の値を引き継ぐ。
4. コードとメロディの編集対象を切り替えても、時間方向のズーム・スクロール位置と音高方向の表示を保ち、同じ小節・音域を見比べる。
5. 参照ノートは直接編集せず、その上をクリックした場合も現在の入力先へノートを置けるようにする。

## その後の制作シナリオ: ドラムを打ち込む

1. Echode 内蔵のドラムラックをフォルダトラックとして用意する（[ADR 0116](decisions/0116-folder-drum-rack.md)）。親フォルダに MIDI を置き、音ごとの子側にサンプルを持たせる。
2. キック・スネアなど、音色名が並ぶ行でノートを置く。
3. 短いパターンを作って複製・変更しながら展開する方法と、曲全体を見ながら順に置く方法の両方を使う。通常のパターン複製では、複製先のノートを直しても元のパターンを変えない。
4. ファイルブラウザからラックへサンプルをドロップすると、音ごとの子トラックとサンプラーを自動で作る。既存の音の行へのドロップはサンプルを差し替える。
5. ミックスでは音ごとの子トラックで個別に調整し、親でドラム全体をまとめる。

## ベース・構成・編曲から書き出しまで

1. ベースなど他のパートも別トラックのピアノロールへマウスで一音ずつ置く。
2. 各パートがそろったら、「Aメロ」「サビ」等のリージョンを使い、全トラックの該当区間とオートメーションをまとめて扱う。
3. 空トラックから新しいフレーズを作る方法と、既存トラックを複製して音色・フレーズを変える方法の両方で編曲を進める。
4. 音量・パン・ミュート・ソロ、FX とセンドを操作する。オートメーションは点や線をマウスで描く方法を中心にする。
5. 普段の書き出しは曲全体のミックスを 1 ファイルにまとめる。再生時のミュート・ソロと関連 FX を反映し、末尾の余韻も含める。

## 確認した操作の要件

### ノートの入力

- 次に入力するノートの長さ（「入力長」）を編集中のプロジェクト内で全トラック共通に記憶する。
- まだ入力・選択・伸縮で長さを記憶していない時、またはプロジェクトを開き直した時は、その時点のグリッド幅を初期入力長にする（永続保存しない）。
- 既存ノート 1 つの端ドラッグ伸縮、単一選択、新規ドラッグ追加で、そのノートの長さを次の入力長へ引き継ぐ。
- 複数ノートの一括伸縮、または長さが異なる複数ノートの選択では、直前の入力長を保つ。
- ノートの追加や長さ変更を Undo した時は、入力長もその操作前の値へ戻す。
- 空白を押したままドラッグすると、開始位置を押した位置に固定したまま、右へ動かして長さ、上下で音高を変更できる。左へ戻した場合はグリッド 1 区画の最小幅で止める。
- 入力長を記憶した後は、グリッド幅やズームを変えても入力長を丸め直さず維持する。
- 既存ノートの移動・左右端の伸縮は通常グリッドへ吸着し、Shift を押している間だけ一時的に吸着を解除する（Shift 伸縮時はグリッド 1 区画未満も可）。
- グリッドの間にあるノートを後から Shift なしで動かす場合は、つかんだ開始位置を絶対グリッド線へそろえる（複数選択では同じ時間差を全体へ適用して相対間隔を保つ）。

### ベロシティの編集

- ノート全般で、ノート上の Option＋上下ドラッグと、下部のベロシティ欄の棒の上下ドラッグの両方で同じベロシティを編集し、表示と値を同期する（参照専用のゴーストノートは編集しない）。
- 複数選択したノートは、全ノートのベロシティを同じ量だけ増減し、元の強弱の差を保つ。
- 新しいノートは、直前に単一ノートを選択・調整した時のベロシティを全トラック共通で引き継ぐ。
- 複数ノートのベロシティを一括変更した後は、ドラッグでつかんだノートの変更後の値を次の入力へ引き継ぐ（入力長の一括伸縮規則とは区別する）。
- Command＋ドラッグは複製移動、Option＋上下ドラッグはベロシティ編集として区別する。

### 構成を考えながら入力する

- トラックパッドの横スクロール等の表示位置移動自体では、入力長や記憶した再生開始位置を変えない。
- 再生ヘッドが画面の端を越える時は表示を追従させる。手動スクロールしたら追従を解除し、明示的にオンへ戻すまで停止・再開後もオフを保つ。
- 通常のピンチはポインター位置の時刻を固定して時間方向だけを拡大・縮小する（修飾キー付き別軸ズームは [設計 §13.4](ARCHITECTURE.md#134-トラックパッドとジェスチャー) に従う）。
- グリッドの初期状態はズーム連動の自動調整とし、固定幅にも切り替えられるようにする。

### コードを参照してメロディを入力する

- 初期状態では他の全トラックのノートをゴーストノートとして背景に薄く表示し、右のトラックセレクターでトラックごとに表示をオン／オフする。
- 編集オフのトラックのゴーストノートは参照専用とし、その上をクリックしても参照元へ編集対象を切り替えず、現在の入力先トラックへノートを追加する。
- ゴーストノートと編集ノートが重なる場所では、編集ノートの選択・移動・伸縮・削除を優先し、参照専用ノートを混ぜない。
- 編集対象トラックを切り替えても、時間方向のズーム・スクロール位置と音域の表示を保つ。

### トラックセレクター

- 右端のトラックセレクター（[設計 §14](ARCHITECTURE.md#14-midi-とピアノロール)）は、各トラックの「表示」「編集」「ソロ」「ミュート」を独立したボタンで切り替える。
- 「表示」はゴーストノートの参照表示、「編集」は編集対象のオン／オフ、「ソロ」「ミュート」はトラックの音声状態へ接続する。
- 新規入力は単一トラック編集を中心とし、複数トラック編集は既存ノートの一括編集・微修正を主な用途とする。
- 複数トラック編集時の新規ノートの「入力先」は、個別に編集・単一選択したノートが属するトラックとする。
- 複数選択したノートの一括移動・伸縮では、つかんだノートのトラックへ入力先を切り替えず、操作前の入力先を維持する。
- 入力先トラックの「編集」がオフになり、編集可能なトラックが 1 つ残る場合は、そこへ自動で入力先を移す。専用の入力先切替 UI は追加しない。

### ドラムの入力とミックス

- 内蔵ドラムラックはフォルダトラックを形成し、親フォルダで MIDI を編集し、子トラックに音ごとのサンプルとサンプラーを持たせる（[ADR 0116](decisions/0116-folder-drum-rack.md)）。
- 入力画面はキック・スネア等の音色名が並ぶ行を使う。ミックスは音ごとの子トラックで行い、親でドラム全体をまとめる。
- ファイルブラウザからドラムラックへサンプルをドロップすると子トラックとサンプラーを自動作成し、既存行へのドロップはサンプルのみを差し替えて MIDI 割当とミックス先を保つ。
- ドラムパターンの通常の複製はノートの中身を独立させ、複製先の編集が元へ伝播しないようにする（「リンクして複製」は別操作として維持する）。
- 子サンプラーはノート長に従うゲート再生＋音量 ADSR を基本とし、ワンショットにも切り替えられるようにする。
- 同じ音を連続発音した時は、前の音のリリースと新しい音の発音を独立した ADSR で重ねる（チョークグループは初期範囲に含めない）。
  停止・一時停止はノートを解放して余韻を残し、シーク・未発音の準備取消ではワンショットを含め発音状態を消去する。

### 音源を挿して編集に入る

- 空トラック追加時は音源選択画面を自動で開かない。
- トラック一覧末尾の追加ボタンは末尾へ追加し、ショートカット等は選択トラックの下（フォルダ展開中は最後の子、折りたたみ中は部分木の直後の外側）へ追加する。
- 通常のトラック複製は音源・FX・クリップ・オートメーションをまとめてコピーし、GUI は手動で開く。
- 単体で音源や FX を追加した直後は、その GUI を自動で開く（一括追加時は手動）。
- 音源 GUI はピアノロール操作中も前面に残し、前面表示とキーボードフォーカスを分離する。
- アレンジの空白のダブルクリックは、再生開始位置を変えずにそのトラックのその位置をピアノロールで開く。
- アレンジでの単なるトラック選択変更ではピアノロールの編集対象を変えず、明示的に開いた時に切り替える。

### ノート操作の試聴

- ノートの入力・選択・上下ドラッグでは、停止中・一時停止中・再生中を問わずそのトラックの音源で短く試聴音を鳴らす。
- 複数選択したノートを上下ドラッグする時は、選択した全ノートを同時に鳴らす。

### ノートの選択

- 複数ノートの範囲選択は右ドラッグ（一部でも触れたら選択）、空白からの左ドラッグはノート追加とする。
- 選択済みノート上の右クリックはその複数選択を保ってメニューを開き、「削除」は選択全体に適用する。未選択ノート上の右クリックはその 1 音だけを選択してメニューを開く。
- 選択済みノートの左ドラッグは選択全体を移動し、端のドラッグは選択全体を同じ量だけ伸縮する。
- Command＋クリックは選択の追加・解除、Command＋ドラッグは選択対象（未選択ならその 1 音）の複製移動とし、操作後は複製側を選択する。
- Delete は選択ノートを削除する（入力欄フォーカス時は文字削除を優先）。

### 初期の操作図と残る案

- 初期の操作図は単一トラック・音なしの検討用であり、製品や最新要件の検証には使わない。
- ドラッグ中の仮表示、Escape による取消、右ボタン押下時のメニュー保留（ドラッグにならず離した時のみメニュー表示）、Command＋クリック／ドラッグの移動判定は実装時の参考案として保持する。

### 再生の開始位置

- 記憶する「再生開始位置」と、再生で進む「現在位置」を区別する。
- 停止からの再生は記憶した開始位置から行い、停止指示では再生ヘッドを開始位置へ戻す。
- 一時停止はその位置に再生ヘッドを保ち、再開は止めた位置から続ける（開始位置は変えない）。
- アレンジとピアノロールのルーラーは同じ再生開始位置を共有し、クリックでグリッドに吸着して更新する（再生中は直ちにその位置へシークして再生を続ける）。
- 再生開始位置はプロジェクトごとに保存し、開き直した時も保持する。
- 2026-10-21 の回答により、停止・一時停止はノートと素材の再生を止め、プラグインの処理と出力は続ける。
  余韻とプラグイン内の鍵盤の音は出す。ライブ処理は [ADR 0133](decisions/0133-stopped-plugin-processing-and-edit-input.md) で接続した。

### ループ再生

- ルーラーのドラッグでループ範囲を指定し、ループのオン／オフ自体は別操作にする。
- ループがオンでも、停止からの再生は記憶した開始位置から始める。
- 開始位置がループ終端より前にある場合（例: ループ 2〜6 小節、開始位置 1 小節目）は、開始位置から再生してループ終端（6 小節目）でループ先頭（2 小節目）へ戻る。
- 開始位置がループ終端以降にある場合（例: 開始位置 8 小節目）は、その位置から先へ進み、過ぎたループ範囲へ戻らない。

### キーボードの初期割当と入力欄

- Space は再生／停止（停止中・一時停止中は再生／再開、再生中は停止して開始位置へ戻す）。
- Return は一時停止／再開（停止中・一時停止中は再生／再開、再生中は現在位置で一時停止）。
- 入力欄や IME にフォーカスがある時は、Return・Space・Delete・選択・コピー・Undo を入力欄が処理し、再生やノート削除へ漏らさない。

### 共通サンプルブラウザ

- フォルダ移動と登録素材全体のファイル名検索を併用する共通ブラウザとする。
- サンプルを選択すると素の素材音で 1 回自動試聴し、別のサンプルを選んだら前の試聴を止めて新しいサンプルだけを鳴らす（曲の再生中も重ねて試聴可能）。
- ダブルクリックは、選択中トラックのその瞬間の再生ヘッド位置へグリッドに丸めず配置し、サンプルブラウザは開いたままにする。

### オーディオクリップとテンポ

- 通常の端ドラッグは非破壊トリムとし、素材の終端で止める（自動反復はしない）。
- 複製等の基準は元ファイル長ではなく現在のクリップ範囲・長さとする。
- 同トラックでオーディオクリップが重なる区間は自動クロスフェードとし、分割・トリムの切り口にも短いフェードを自動で付け、左上・右上のハンドルで調整・解除できるようにする。
- **後続 Phase（Phase 4）の希望要件**:
  Option＋端ドラッグによる音高保持伸縮、ループ素材の BPM 自動推定・テンポ追従、クリップごとのストレッチ方式選択（[PLAN §2.1](PLAN.md#21-ライセンス方針の影響)、[設計 §11](ARCHITECTURE.md#11-オーディオファイルと解析)）、1.0 倍へ戻した時点の曲テンポを新しい追従基準にする動作は Phase 4 の範囲とし、Phase 2 へ前倒ししない。

### アレンジの選択と編集

- 右ドラッグでクリップ全体を枠選択し、空白からの左ドラッグで時間とまたいだトラックの「編集区間」を指定する（ループ範囲とは別）。
- 編集区間のコピーは区間内の中身だけをコピーし、Delete は中身を消して空白を残す（後続クリップの時刻は保つ）。
- クリップ本体の左ドラッグは移動、Command＋ドラッグは複製移動、Command＋D は選択クリップの直後へ現在のクリップ長で複製する。
- Command＋V はコピーした編集区間の先頭を現在の再生ヘッド位置へ合わせ、選択トラックを起点に上下の並びを保って貼り付ける。

### 重ねる・置き換える

- ノートとクリップは「重ねる」（初期値）と「置き換える」をアレンジとピアノロールで独立して切り替えられるようにする。
- ノートの置換は同じ音高・同時刻のノートだけを対象とし、別音高の和音は消さない。クリップの置換は同一トラック上で時間が重なる配置を対象とする。

### リージョンと編集区間

- ルーラーで指定したループ区間から名前付きリージョン（「Aメロ」「サビ」等）を作成する（ループのオン／オフは変えない）。
- リージョンを選ぶと、その区間が全トラックの編集区間として選択される（ループ区間や再生開始位置は変えない）。
- リージョンの移動・複製は区間内のノート・オーディオ・オートメーションを一緒に扱い、通常の複製・削除では後続時刻を詰めたり押し出したりしない。

### ミキサーの複数選択

- 選択した複数トラックのうち 1 つのフェーダー・パンを動かすと、全選択トラックを同じ dB 差・同じパン差だけ動かし、相対関係を保つ。
- 複数選択中のミュート／ソロは、クリックしたボタンの操作後の状態へ全選択トラックをそろえる。
- ソロの通常クリックは追加・解除として扱う（複数トラックの同時ソロが可能）。

### FX 候補とチェインの操作

- 各トラックの FX 空欄クリックで候補リストを開き、ダブルクリックまたは Return は最後に選択したトラックへ追加する（ダブルクリック後は閉じ、Return・ドラッグ後は開いたままにする）。
- 右クリックメニューからは選択トラック全てへ一括追加でき、D&D はドロップ先のトラックまたはクリップへ追加する。
- 同一チェイン内の通常ドラッグは順番変更、Command＋ドラッグは複製、別トラックへの通常ドラッグは元を残して同じ設定をコピーする（[ADR 0118](decisions/0118-track-fx-chain-editing.md)）。
- 操作開始時に確定した対象 ID と文書セッションを非同期完了まで保ち、途中で削除・文書交換された場合は別対象へ付け替えない。

名前クリックでの独自 GUI は [ADR 0132](decisions/0132-helper-plugin-windows.md) で接続した。
展開・折りたたみ、複数選択時の対象は未接続である。

- 下部は音源・FX などを処理順に横へ並べ、各デバイス内に全パラメータの一覧を持たせる。
  プラグイン独自 GUI は別ウィンドウとする既存方針を保つ（[PLAN §2](PLAN.md#2-決定事項)）。
- トラックヘッダ・インスペクター・ミキサーは FX の一覧を扱う場所とする。
  同じチェインの別表示であり、下部専用のデバイス列や別の設定値を作らない。
  挿入済みのプラグイン名をクリックした時は、そのプラグイン独自 GUI を直接開く。
- パラメータの一覧には検索とピン留めを備える。
  同日の後続回答で「推奨セットを追加・入替する」案を置き換えた。全パラメータを補助画面だけへ置く構成にはしない。
  一覧の対象はプラグインがホストへ公開し、表示を許すパラメータである。非公開の内部値まで推測して補わない。
- ピン留めは挿したデバイスごとにプロジェクトへ保存する。
  同じプラグインでもベース用・パッド用などの用途に合わせて異なる項目を選べる。
  ピン留めした項目は各デバイスのパラメータ一覧の上部に固定し、検索中も検索語にかかわらず表示する。
- 同日の回答で次を決めた。
  一覧にはプラグインが報告する全パラメータを並べ、ピン留めした項目をそのデバイスの最上部に出す。
  ピン留め同士と残りはそれぞれプラグインの順とし、並べ替えの操作は設けない。
  複製・別トラックへのコピー・トラック複製はピン留めを引き継ぎ、1 回の切替を 1 回の Undo にする。
  検索は空白区切りの全語が名前かモジュール名に含まれる行を残し、検索語はデバイスごとに起動中だけ保持して保存しない。
- デバイスビューは常に選択トラックへ追従し、表示トラックをピン留めで固定する機能は設けない。
  パラメータのピン留めとは別の操作である。
  トラック選択で、ピアノロール等からデバイスビューへ表示モードまで自動で切り替える決定ではない。
- ピアノロール等のエディタとデバイスビューは通常切替で使い、必要なら上下に同時表示できるようにする。
  表示の開閉・配置変更と、それぞれの編集対象を分ける。
- マクロの割当機能は既存の Phase 3 計画との境界を別途決める。
  パラメータのピン留めだけで、複数パラメータを動かすマクロを実装済みとはしない。

独自 GUI について、2026-10-20・21 の回答で次を決めた（[ADR 0132](decisions/0132-helper-plugin-windows.md)）。

- 名前クリックで開く・前面へ出す時も、入力フォーカスは取らない。
  プラグインのウィンドウは、ユーザーがその中をクリックした時だけフォーカスを得る。Echode のメニューバーは奪わない。
- 開いたウィンドウは、ユーザーが閉じるか、デバイスの削除・オフライン化・文書の終了まで残す。別トラックを選んでも残す。
  Echode または同じ親のヘルパーを操作している間は Echode の上に浮かぶ。
  別アプリがアクティブになると隠れ、戻ると再表示する。
- 自動で開くのは候補パネルからの単体追加（ダブルクリック・Return・ドラッグ）だけとする。
  デバイスの複製・コピー、選択トラックへの一括追加、トラック複製では開かない。
- プラグイン画面でのジェスチャーは、終了時に 1 回の Undo にする。
  ジェスチャーのない変更（プリセット切替、値の変化、`mark_dirty` だけの変更）は、そのウィンドウが開いている間だけ記録する。
  約 0.5 秒静止した後に状態が変わっていれば 1 回の Undo にする。
  ウィンドウが閉じている時のプラグイン自身の変化は自動保存だけにする。読み取り専用の値は Undo に入れない。
- 2026-10-21 の追加要望で、GUI フォーカス中の Space と既存の DAW キーを Echode へ中継する。
  文字入力中はプラグインに渡す（[ADR 0134](decisions/0134-plugin-window-lifetime-and-shortcuts.md)）。
- FX 追加ボタンはデバイスビューの最後のプラグインの右に置く。空のチェインでも追加できる。

検討中の操作案:

- デバイスの枠に名前・有効状態・独自 GUI を開く入口を置き、展開・折りたたみと横スクロールでチェインをたどる。
  名前・有効状態・横スクロールと、名前クリックの独自 GUI は接続済みで、展開・折りたたみは未接続である。
- 複数トラックの選択集合とデバイスビューの単一表示対象を分ける。
  複数選択時の表示対象、トラック／クリップ切替、独自 GUI の追従は別々に確認する。
- 候補を開く FX 空欄と、挿入済みデバイスの操作入口を区別する。
  FX 空欄からは従来の候補を開き、挿入済みの名前クリックからは独自 GUI を開く。
  デバイスビューの列とインスペクターの名前は接続済みで、トラックヘッダの FX ボタンの区別は未接続である。

比較の参考:
[Live の Device View](https://www.ableton.com/en/manual/working-with-instruments-and-effects/#device-view)
は下部でデバイスを調整し、Clip View との上下同時表示も持つ。
他製品の挿入先・修飾キー・トラック種別の規則まで Echode へ移す決定ではない。

### 処理中も作業を続ける

2026-10-20 に、ユーザーから「プラグイン付きトラックを選ぶたびに GUI が止まる」と、
「現行 FX の汎用パラメーター画面が特に重い」の 2 症状が報告された。
原因は未確定であり、読み込みが走っているという見え方と、実際のヘルパー起動を区別する。

- GUI の応答と作業継続を、プラグインに限らず読込み・保存・解析・レンダリングの共通要件とする。
  画面が描かれるだけでなく、選択・スクロール・入力・無関係な対象の編集を続けられることを確認する。
- パラメーター確定・バイパス・オフライン等の通常編集で、全体のボタンを一瞬だけ無効にしない。
  編集順序の保持と文書交換の排他を分ける（[ADR 0133](decisions/0133-stopped-plugin-processing-and-edit-input.md)）。
- 選択や表示の切替の完了を、プラグインの準備・パラメータ取得・状態保存の完了に依存させない。
  準備が必要でも、表示できる名前・順序・状態から先に表示する。

以下は要件を満たすための設計案であり、個別操作の確定・取消規則は実装前に詰める。

- 読込みや失敗の表示、操作制限はそのデバイス・素材・処理へ限定する。
  長いプラグイン応答待ちを文書全体の編集待ちへ広げず、無関係な編集と停止・取消を受け付ける。
- デバイス表示の寿命と稼働するプラグインの寿命を分け、別トラックへ移っただけでロード・解放を繰り返さない。
  明示的なオフライン化、削除、文書終了、障害時の再起動は独立した操作として扱う。
- パラメータの説明と表示構成を保持し、見える操作部品だけを生成・更新する。
  値の正本はプラグイン状態のままとし、表示用キャッシュを保存状態や Undo の代用にしない。
  パラメータ数を固定上限で切り捨てて軽くする方法は使わない。
  全パラメータの検索対象と画面に生成する行を分け、画面外のパラメータも検索・ピン留めで到達できるようにする。
  ピン留めの参照はデバイスとプラグインのパラメータ ID を使い、検索後の行番号を値変更の対象にしない。
- 準備完了と表示先を文書・デバイス・要求世代で照合し、遅れた結果で新しい選択を戻したり、削除済みデバイスを復活させたりしない。
  完了通知で入力フォーカスを奪わない。
- 変更の受付、保存への確定、音声への適用を区別する。
  プラグインの準備が遅くても操作受付は返し、現在の音声計画を保持して準備済みの結果へ交換する。
  初回準備でまだ音が出せない場合は対象の準備中を示す。無断のバイパスで完了したように見せない。
- 失敗は対象内に表示し、再試行・オフライン化・削除などの復旧へつなぐ。
  同じ対象への連続編集の順序、Undo と準備完了の競合、途中取消の保存上の扱いは明示する。

背景レンダリング本体は Phase 3 のままである。
GUI の応答性と編集継続は P2 のデバイス表示・読込みから守る要件とし、その実装を Phase 3 まで待たせない。

### オートメーションの表示と編集

- オートメーションモード有効時は全トラックのクリップ表示領域を曲線表示へ置き換え、各トラックで最後に操作したパラメータを自動表示する。
- モード無効時は通常のトラック配下レーンとし、最後に操作したパラメータのレーンをそのトラックの一番上へ自動表示する。
- 空白・線上のシングルクリックで点を追加し（最初の 1 点はその前後にも同じ値を適用）、左ドラッグで移動（Shift でグリッド吸着解除）、右ドラッグで枠選択する。
- 線の上下ドラッグは両端の 2 点を同じ量だけ上下し、Option＋上下ドラッグで曲率を変える。
- 既存のオートメーション再生中に手動で値を試聴した時は、手を離すと現在時刻のオートメーション値へ復帰する（明示的な記録モードとは区別する）。

### センドとレシーブ

- 送り元の D&D、送り側の一覧、受け側の一覧から同じ接続を作成・編集する（[設計 §8.3](ARCHITECTURE.md#83-センドレシーバーサイドチェーン)）。
- 新規センドは FX 後・音量フェーダー前の 0 dB とし、元フェーダーを下げても送る量は維持するが、送り元をミュートしたらセンドも止める。
- 送り元をソロにした時は関連する受け側（リバーブ等）も聴こえるようにし、同じ受け側を共有する非ソロの送り元までは開放しない。

### 書き出し

- 初期範囲は曲全体のミックス 1 ファイル（初回デフォルトは WAV・24 bit・プロジェクトのサンプルレート、以後はプロジェクトごとの前回設定を保持）。
- 再生時のミュート・ソロと関連 FX、および末尾の余韻（長さ調整可能）を反映する。
- 実行時の版と設定を固定して別プロセスの CLI で書き出し、処理中もメイン文書の編集・再生を続けられるようにする。

## 実装へ進む時の受入と基盤の保守

各実装単位（P2-01〜P2-09）の具体的な自動受入条件は [Phase 2 の進め方](phase2.md) を正本とする。
実装を進める際は、以下のテスト・診断・ドキュメント保守を同じ作業で行う（[開発手順](development.md#基盤の保守を同じ作業で行う)）。

- **製品経路の自動回帰**:
  実 View のマウス・キー入力、アクション生成（`properties.rs`）、ブロック長独立性（`block_size.rs`）と RTSan、Undo / Redo、保存・復旧、再生と CLI 書き出しの一致を通す。
  主要境界には [scripts/verification.json](../scripts/verification.json) の `product_contracts` と負の対照（`negative_control`）を登録する。
- **診断で区別する状態**:
  記憶した開始位置・現在位置・ループ・編集区間、保留中の再生要求、選択・編集・入力・FX の対象 ID、重なりモード、最後に操作したパラメータと手動試聴、センドの接続 ID・取り出し位置・ミュート／ソロ可聴性、ドラムのボイス・ノートオフと全消去、書き出しの版と設定を追跡できるようにする。
- **実機と自動検査の分離**:
  実機での操作感と聴感はユーザー担当とし、機器を使わない入力・音声回帰の合格と区別する。
