# エージェントの情報取得と実行

必要な根拠を短い往復で取得し、規則・失敗情報・依存入力を保ったまま作業する。
判断と反例は [ADR 0126](decisions/0126-agent-context-and-source-reading.md)、検査の正本は [検査手順](verification.md) を参照する。

## 開始時に一度まとめて取得する

```sh
make agent-context
```

`doctor` と同じ診断経路と `verify-plan` と同じ検査選択を使い、診断用のツール情報収集を一度で済ませる。
環境、アプリの鮮度、検査ロック、変更、検査状態、関連領域と資料の参照先を短く表示する。
共通資料は常に案内し、関連資料の候補は既存の `scripts/verification.json` の領域から求める。
未編集の領域を調べる時は `make agent-context CONTEXT_ARGS='--area isolation'` のように候補を追加する。
`--area` は既存変更の領域や検査対象を除外しない。

全変更、検査の選択根拠・目的、資料のハッシュと見出しは `target/agent-context.json` に保存する。
全文 JSON が必要な時だけ `--json` を使う。
自動検査の失敗・未完了・古い結果は個別に表示し、手動検査は状態・鮮度・理由がすべて同じものだけをまとめる。
診断の成功は検査の合格ではなく、最後の `make verify` は引き続き必要である。

差分の基準は新しい `make verify-plan` と同じく現在の `VERIFY_BASE`、未指定なら HEAD を使う。
単独の `doctor` が診断用に引き継ぐ過去のレポートの基準は、ここでは引き継がない。
ソースが収集中に変わった時、案内先が欠けた時、領域対応が古い時はエラーにし、部分的な成功を返さない。
その場合は原因を直し、必要なら `make doctor` と `make verify-plan` を個別に使う。
既存の JSON は過去の証拠であり、現在のソースと一致することを確かめずに再利用しない。

## 必要な根拠を正確に読む

```sh
python3 -B scripts/agent_context.py --outline docs/development.md
python3 -B scripts/agent_context.py --read docs/development.md --section '検査をまとめて進める'
python3 -B scripts/agent_context.py --read scripts/diagnose.py --lines 26:41
```

見出し・行範囲と SHA-256 を付け、原文を要約せずに返す。
Markdown の節は子見出しを含み、コードフェンス内の見出し風の行を境界にしない。
同名の節が複数ある時は選ばず、`--outline` の行番号で範囲を指定する。
見出しを持たないコードは `rg --files`、`rg -n` で所在と識別子を探してから読む。
保存した行番号を使う時は、案内されたハッシュを `--expect-sha256` に渡すと、編集後の誤読を拒否できる。

原文・見出しを返す表示予算は標準で 6,000 UTF-8 バイトとし、メタデータや JSON の整形後も超過を確認する。
超過した出力を切り詰めて成功にしない。
より狭い範囲を指定するか、必要な全文量を `--max-bytes` で明示する。
予算は情報取得の目安であり、必須規則を読まなくてよい理由にはならない。
共通規則は [AGENTS.md](../AGENTS.md)、実装範囲は [status.md](status.md)、設計・監査の案内は [資料の入口](README.md) が正本である。
案内の領域だけが変更の影響範囲だと決めず、依存先・不変条件・関連 ADR の参照もたどる。
リポジトリ外への参照、古いハッシュ、存在しない行、曖昧な節は終了コード付きの失敗として扱う。

## 実行と引継ぎの原則

- 独立した検索・読込はまとめ、依存する操作・編集・検査は順番を守る。
  出力件数や範囲を先に絞り、ツール側の出力切捨てで根拠が欠けることを防ぐ。
- 長い処理はログへまとめて保存して完了を待ち、状況共有は要約する。
  失敗時は終了コードと該当箇所から調べ、成功ログを繰り返し展開しない。
  検査の具体的な運用は [開発手順](development.md#検査をまとめて進める) に従う。
- 引継ぎには目的、決定、変更ファイル、確認した版と証拠、未解決事項、次の操作を残す。
  要約を合格や実装済みの証拠に置き換えず、再開時に現在のソースと照合する。

アプリの鮮度は引き続き全非無視ファイルで保守的に判定する。
文書の一律除外や永続的な読込キャッシュは、ビルド依存や古い根拠の見落としを防ぐ仕組みが整うまで導入しない。
実トークンの削減率は未測定であり、表示の UTF-8 バイト数や往復回数とは区別する。
