# ADR 0354: 文書の作成・オープンの失敗を同期の借用 callback で渡す

- 日付: 2026-11-15
- 状態: 現行。決定
- 領域: モデル・履歴・保存・API
- 関連: IQA-03、ADR 0292、ADR 0322、ADR 0350

## 問題

`echode_document_create` と `echode_document_open` は失敗時に null しか返さず、
型付きの原因が Swift の固定文へ置き換わり、製品ログにも残らなかった。
既に開いているパッケージ、既存の作成先、JSON の破損、I/O を利用者が区別できない。

Swift の製品入口を通る回帰を先に追加し、修正前には理由を確認する 5 個のアサーションが失敗した。
開く操作は失敗しており、汎用文しか返らないことが失敗の理由だった。

## 比べた案

1. スレッド局所の last-error を問い合わせる。
   呼出し順と同じスレッドという隠れた条件が増え、古い失敗の誤読も起きるので採らない。
2. 呼出し側の固定バッファへ書く。
   長い診断を切り詰めるか、長さの取得後に開く操作を再実行する設計になるので採らない。
3. Rust が確保した C 文字列と解放の関数を返す。
   全文は渡せるが、失敗だけのために別の所有権と解放規則を増やすので採らない。
4. 失敗時に同期 callback へ診断を貸す。
   既存の編集の完了と同じ借用規則を使え、確保した文字列を ABI の外へ所有させず全文を渡せるので採る。

## 決定

- 両方の C 関数に `context` と nullable な `DocumentFailure` を足す。
  失敗は同じ呼出しスレッドから、null を返す前に 1 回通知する。成功は通知しない。
  context とメッセージは関数の返却後に保持しない。
- `DocumentError`・`PackageError` の原因は C ABI の直前まで型で持ち、操作・パスとともに表示する。
  callback の有無によらず `echode_ffi::document` の error ログへ同じ診断を書く。
- callback 中にだけ有効な UTF-8 の NUL 終端文字列を Swift がコピーし、`BridgeError.message` へ渡す。
  診断中の NUL は `\0` に置き換え、メッセージ全体を捨てない。文字数の上限は設けない。
- cbindgen 0.29.4 では `Option<関数ポインターの別名>` が不完全な構造体になるため、
  `DocumentFailure` 自体を `Option<extern "C" fn(...)>` の別名にする。
  生成ヘッダのテストも通常の関数ポインターであることを照合する。
- C ABI の引数は変更になる。生成ヘッダと静的ライブラリを一緒に再ビルドし、
  Swift と Rust の全呼出し元を同じ作業で更新する。旧シグネチャの入口は残さない。

## 回帰と基盤

- `document_open_tests.rs`: 成功時の非通知、失敗の 1 回通知、ロック、既存パス、
  作成時の I/O、JSON の元の理由、ログの操作・パス・診断、null・不正 UTF-8、長い診断と NUL。
- 橋渡しの `DocumentOpenErrorTests.swift`: 製品の作成・オープンを通し、
  汎用文へ戻らないことと、拒否後も既存のデータ・文書を保つことを確認する。
- アプリの同名のテスト: `ProjectController.errorMessage` へ理由が届き、
  失敗した文書を公開せず、元の文書で後続の編集を続けられることを確認する。
- 既存の Rust・Swift の通常検査が新しいファイルも実行するため、選択規則は変えない。
  収集対象は既存の製品ログで足りる。調査手順とコードの所在を更新する。

## 残る範囲

実画面の長いパスの折返し・VoiceOver と署名したアプリの記録は UC-84 に残す。
保存・復旧の判断、既存文書を開く順序、プラグイン走査の汎用エラーは変更しない。
