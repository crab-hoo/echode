# 0366. HAL の機器単位の失敗を分離し、過負荷は集約して記録する

- 日付: 2026-11-15
- 状態: 現行
- 領域: 音声エンジン・書き出し

## 背景

品質監査の IQA-06 は、選んでいない 1 台の読取り失敗でも正常な出力を開けない点を指摘した。
横断監査の PCA-10 は、エンジン自身の期限外の音切れについて HAL の過負荷通知が記録されない点を指摘した。
一覧の全体が失敗した時の再試行・警告抑制は [ADR 0360](0360-background-recording-retry-policy.md) を維持する。

## 比較と決定

- 一覧全体を失敗させる案は、無関係な機器の不良で正常な出力を止めるため採らない。
  無言で飛ばす案も原因が残らないので採らず、機器単位の読取り・値検証の失敗を ID と原因付きで警告して除く。
  死亡・入力専用・出力チャンネルなし・バッファ長ゼロは、従来どおり候補にしない。
  安全余白だけは従来の 0 への代替を維持し、出力開始を妨げない（ADR 0283）。
  システムの既定出力と ID 一覧の読取りは全体のエラーにする。空の出力候補は成功であり、出力を要求した時に機器なしとなる。
  除いた機器は次の一覧更新で読み直す。機器ごとの常設キャッシュや新しい周期ポーリングは追加しない。
- 過負荷を既存の機器変更の epoch に載せる案は、通知のたびに無音化・出力再構築するため採らない。
  曲と試聴で共通の専用リスナを使い、開いている機器の寿命にだけ結び付ける。
  診断の登録に失敗して正常な出力まで止める案も採らず、機器 ID・OSStatus を一度警告し、その出力は続ける。
- [公開 API](https://docs.rs/objc2-core-audio/0.3.2/objc2_core_audio/fn.AudioObjectAddPropertyListenerBlock.html) と Xcode SDK の `AudioHardware.h` は、
  過負荷通知を IO スレッドから同期実行する場合があると明記する。監査の案の「通知は音声スレッドの外」は仮定できない。
  通知でログを書く案は採らず、atomic の通知数と最後の Mach host 時刻だけを更新する。
  HAL が保持するブロックは自身の Arc だけを捕まえ、出力や借用したポインタを参照しない。
  登録解除に遅れた通知があっても寿命を守り、音声の処理・機器一覧の照会・確保・ロック・待機を持ち込まない。
- 全通知のリング記録は、容量とあふれの別の規則が必要になるため採らない。
  制御側が初回と以後最大毎秒 1 行へ集約し、出力を閉じる時は抑制中の残りも書く。
  ログの時刻と再生位置は制御側の観測であり、原因ブロックと偽らない。
  最後の通知の host 時刻も独立した atomic の観測で、同時の通知により回数より先へ進む場合がある。
  曲と試聴の通知を足して機器の音切れ回数とせず、通知がないことも音切れなしの証拠にしない。

## 根拠と検査の境界

- `hardware_tests.rs` の `audit_iqa06_*` は修正前、1 台の故障で `Err` になり正常な機器も失う期待値で失敗した。
  ID が先頭・既定・末尾の各場合、HAL・レート・チャンネル・名前のエラー、正常候補・選択・復帰・原因ログを調べる。
  システム読取りの失敗、候補なし、全機器が読めない場合は別の通常テストで区別する。
- `stream_overload_tests.rs` の `audit_pca10_*` は、通知を入れて service を呼んでもログが 0 行となる期待値で失敗した。
  通知側の無記録と確保禁止、制御側の位置付き記録、機器変更の epoch の保持、出力の継続と閉鎖時の排出を調べる。
  `overload_tests.rs` は仮想時計で 100 通知の集約、1 秒の境界、強制排出、保持されたブロックの寿命を調べる。
  100 はこの回帰の入力数であり製品の上限ではない。`audition_overload_tests.rs` は試聴の制御経路と閉鎖を通す。
- 時間と CPU 費用の実機計測はしていない。上記の回数と行数は測定時間ではなく、機器なしの回帰の観測値である。
  実ドライバの抜去・復帰と実 HAL の通知の到着・聴感は UC-87・88 としてユーザー確認へ残す。
  実機を開く検査は明示依頼がなく実行しない。検査結果と個別の見送り理由は `target/verification/report.md` に記録する。
