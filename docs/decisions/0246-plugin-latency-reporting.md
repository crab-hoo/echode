# 0246. CLAP の遅延を隔離ヘルパーから表示まで運ぶ

日付: 2026-11-03
状態: 採用（FCA-07 の遅延報告だけ。PDC は [ADR 0339](0339-plugin-delay-compensation.md) で接続した。ほかのホスト拡張は残る）

## 背景

[全体監査の FCA-07](../reviews/2026-11-03-full-code-audit.md) は、実際の遅延を読まず、再起動通知が常に 0 を送ることを指摘した。
遅延補正は P2-03 の別の単位だが、未補正の値すら利用者から見えないことを先に解消する。
`hosted_playback/latency.rs` の初回の再現は、遅延を宣言するプラグインから報告を受け取れず失敗した。

## 決定

- 成功した `activate` の直後、同じメインスレッドで `clap_plugin_latency.get` を読む。
  拡張または `get` がなければ 0 とし、`u32` の値を上限や単位変換なしで保持する。
  音声・制御スレッドから CLAP の遅延 API を呼ばない（[ADR 0041](0041-helper-threads.md)）。
- `clap_host_latency.changed` を公開する。CLAP が許す呼出しは `activate` の中だけなので、コールバック内では問い合わせをせず、毎回の有効化の後に必ず読む。
  不正な実行中の遅延変更をポーリングで追いかけたり、自動で再起動したりはしない。
- 初回値は既存の `Ports` フレームの末尾に tail とともに載せる。再有効化は既存の `PluginRestarted.latency_samples` を使う。
  ヘルパーと本体は同時にビルドする内部プロトコルであり、旧ヘルパーとの混用は支援しない。保存形式・モデル・C ABI は変えない。
- 親はソケットで受信した時点で共有の原子変数へ保持する。
  `PluginControl::latency_samples` はソケットのロックを取らず読み、別の要求や背景保存が通知を先に読んでも値を失わない。
  変化は既存の活動列の独立した `latency_samples` に載せ、0 への変更も列の結合・滞留の圧縮で残す。
- `device.parameters` の応答にも現在値を足し、初めて列を開く時に活動通知を取り逃がしても表示できる。
  Swift の応答と活動のフィールドは optional とし、旧応答や未取得を測定済みの 0 と区別する。
  デバイス列に出力サンプルレートでのサンプル数と未補正を表示し、折りたたみでも残す。オフライン・取得失敗では表示しない。
  更新は文書・デバイスの寿命を確認し、保存・Undo・音声バッファに影響させない。

## 回帰と診断

- `echode-test-plugin/src/latency.rs` は有効化ごとに 256、512、0 サンプルを宣言し、問い合わせが有効化したスレッドであることを照合する。
  実際の音声遅延は作らず、製品の PDC を証明するテストとは扱わない。
- `hosted_playback/latency.rs` は初回の報告、音声処理からの再起動、0 への更新、拡張なしを別プロセスで通す。
  親の保持・古い要求番号・活動の結合・JSON の圧縮は sandbox と document の単体回帰で扱う。
- Swift の `DeviceTests` は旧応答と 0・512・最大値の復号、`PluginLatencyTests` は表示・折りたたみ・VoiceOver 属性・履歴不変・文書交換を扱う。
  既存の通常検査の対象なので、新しい検査入口・選択規則は足さない。
- 調査時は [遅延表示の切分け](../debugging/audio-and-plugins.md#プラグインの遅延表示が更新されない音がずれる) を使う。
  ログ形式と収集先は変わらず、新しい外部入力や実機操作も増やさない。

## 残る範囲

PDC、チェイン全体の合計遅延、録音の補正、`clap.log`・`clap.thread-check` と残る主要ホスト拡張は未接続である。
FCA-07 全体を完了にはしない。第三者 CLAP の報告の正しさ、実画面と VoiceOver は UC-51 でユーザーが確かめる。
