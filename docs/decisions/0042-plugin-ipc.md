# 0042. プラグインの往復は共有メモリ、制御はソケットに分ける

- 日付: 2026-10-09
- 状態: 採用
- 項目: PLG-3

## 背景

今の共有メモリは、ステレオで 512 フレームまでしか置けず、イベントを運ばない。実体は `$TMPDIR` のファイルで、親が落ちると残り、ページはファイルへ書き戻せる。スロットが 1 つなので、締め切りに遅れた応答と次のブロックの入力が同じ場所を奪い合う。状態の保存、プラグインからの処理再開の要求、終了の検知は、この経路に載っていない。標準エラーは上限なく文字列に積む。

イベントの形は ADR 0037 の `Event` である。処理スレッドと制御スレッドは ADR 0041 で分かれている。`request_process` を親へ知らせるのも、この制御の経路である。

## 決定

リアルタイムの経路と制御の経路は混ぜない。処理スレッドが触るのは共有メモリだけである。制御スレッドがソケットと kqueue を読む。オーディオスレッドは、ロックもメモリの確保もファイルの読み書きもしない。

共有メモリは `shm_open` で作り、マップしたあと名前はすぐ消す。ファイル記述子を子へ渡す。`$TMPDIR` には置かない。子は `posix_spawn` で起動し、`fork` しない。親は多スレッドなので、`fork` した子の側で libSystem の fork ハンドラが、ほかのスレッドが初期化している途中の状態を引き継ぐと、子は SIGKILL で落ちる。子が受け取る記述子は、標準入出力と共有メモリと制御ソケットだけである。ほかは `POSIX_SPAWN_CLOEXEC_DEFAULT` で閉じ、別のヘルパーの記述子を持たせない。親と子が `MAP_SHARED` でマップし、全体を `mlock` する。`mlock` に失敗したら、そのセッションは開始しない。作り直しのときも、失敗したら古いマッピングを残す。宣言は `libc` のものを使う。

マッピングの大きさは、セッションを作るときに決める。フレーム数、入力チャンネル数、出力チャンネル数、入力イベント数、出力イベント数である。フレーム数 0 は拒否する。入力 0 と出力 0 は許す。シンセサイザーは入力を持たない。両方のチャンネル数と両方のイベント数が 0 のときだけ拒否する。2 や 512 はプロトコルの上限ではない。足りなくなったら、制御スレッドが新しい共有メモリを作り、ソケットの `Remap` でファイル記述子を渡す。処理スレッドはブロックのあいだに切り替える。古いマッピングは、切り替わったあとで解放する。

中身はヘッダと、2 つのスロットである。2 は同時に飛んでいるブロックの数で、チャンネルの上限ではない。スロットには、その世代のフレーム数、入力の平面、出力の平面、入力イベント、出力イベントを分ける。イベントは `Event` のメモリ表現を直接読まない。タグとフィールドを並べた固定長のレコードにし、不正なタグ、真偽値、途中で切れたバイト列は捨てる。保存形式にはしない。

親は、完了していないスロットを上書きしない。2 つとも未完了なら、そのブロックは待たずに欠落とし、無音にする。遅れて返った出力は、親がすでにその世代を諦めたあとでは読まない。ヘルパーは、公開された世代だけを処理し、書き終えてから完了の番号を進める。起床は今どおり `os_sync_wait_on_address` の共有モードである。

制御は `socketpair` の 1 本である。メッセージは長さ、種別、本体である。種別は、準備完了、状態の要求、状態のバイト列、復元、復元の完了、`request_process`、`Dirty`、`PluginRestarted`、`Remap`（新しいマッピングのファイル記述子付き）、`Remapped` である。ヘルパーの制御スレッドが読み、処理スレッドは触らない。`request_process` と `Dirty` と `PluginRestarted` は親への通知で、処理スレッドは待たない。`PluginRestarted` は、ヘルパーが自分で再起動を終えたあとに送る。長さが 64 MiB を超えるメッセージは拒否する。これは状態の上限ではなく、壊れた相手にメモリを確保させないためである。`Dirty` をジャーナルへ書くのは、この項目の外である。

ヘルパーの終了は、親の制御スレッドが `kqueue` の `EVFILT_PROC` と `NOTE_EXIT` で知る。分かった時点で処理側の待ちを起こし、以降のブロックは待たずに無音にする。ハングはプロセスが終わらないので、呼び出し側の締め切りのままである。欠ける `request_restart` のメッセージが、その締め切りを使い切る原因にはならない。再起動は、処理スレッドがマッピングを使っていないあいだに親がヘッダとスロットを既知の世代へ戻し、同じファイル記述子を新しいヘルパーへ渡す。名前は消したままである。壊れた世代を名前で付け直すことはしない。最後に受け取った状態のバイト列を復元してから、処理を再開する。短いフェードは呼び出し側が付ける。

標準エラーは末尾 64 KiB だけ残す。それより前は捨てる。

コピーだけの経路は、入力の各チャンネルを同じ番号の出力へコピーし、余った出力は無音にし、入力イベントを出力イベントの領域へコピーする。テストは、入力 0 を含むチャンネル数、1 個以上のイベントの往復、壊れたレコードで落ちないこと、終了を kqueue で知ること、復元のバイト列が戻ること、`Dirty` が届くこと、`Remap` でマッピングが替わることを見る。実装のあと `make spike-isolation` で S3 を測り直す。

GUI のメッセージと、CLAP の thread-pool は、この項目では運ばない。

## 結果

採用した。共有メモリは名前を消したファイル記述子で渡し、イベントは検証してから読む。入力チャンネル数 0 のセッション、イベントの往復、kqueue による終了、状態の復元、`Dirty`、`Remap` をテストした。測定は S3 に書く。

（2026-11-11 追記: 64 MiB は 1 枠の上限として働き、それを超える状態を送れずにヘルパーが止まっていた。[ADR 0318](0318-split-control-messages.md) で、長いメッセージを `PART` の枠に分けて送るようにした。）
