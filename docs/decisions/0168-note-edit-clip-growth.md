# ADR 0168: ノートの時刻編集で対象の固定クリップも必要な分だけ広げる

- 日付: 2026-10-26
- 状態: 採用。実画面の見え方・聴感はユーザー確認待ち
- 範囲: `note.edit` の配置境界、ピアノロールの確定表示と履歴
  後続の [ADR 0170](0170-content-relative-auto-bars.md) 以降、小節未満の移動だけでは固定にならない。
  この ADR の固定窓の回帰は、明示的な端の編集でも同じ境界を確認する。

## 背景と再現

実機監査で、クリップ外までノートの音価を伸ばすと、はみ出た部分が見えず、クリップも伸びないとの報告を受けた。
`885a2ce` の製品 View・controller・ABI を通す回帰で、アレンジの 1 拍移動後に再現した。
新規の自動配置では再現せず、小節の整数倍でない移動により固定配置になった場合に再現した。

最小入力は、4/4 の空トラックに開始 1 拍・長さ 1 拍のノートを置き、クリップを開始 1 拍へ移す操作である。
ノートの右端を Shift で 3.75 拍延ばすと、ノート自体の長さだけが保存され、窓は `[1, 5)` 拍のままだった。
左端の延長でも表示が切れ、ノート全体を窓の外へ移すと問い合わせから消えた。
期待終了コードと固有のアサーションは `target/focused-checks/piano-bounds-red/` に記録した。

[ADR 0022](0022-clip-content-and-placement.md) の固定配置は、ノート編集でも境界を保っていた。
[ADR 0025](0025-clip-window-cuts-notes.md) の窓による再生制限と同じ区間を表示するため、これは描画だけの欠落ではない。
ノート編集で窓を越す時の仕様を狭く置き換え、手動トリムと別配置の境界は引き続き尊重する。

## 決定

- `note.edit` で開始または長さが変わる時は、編集した固定配置の窓を、そのノート全体を含むところまで広げる。
  固定のまま、既存の窓と編集後のノート区間の包絡を使う。小節へ丸めず、短縮や削除で固定窓を縮めない。
- 左へ広げる時は開始とオフセットを同じ量だけ変え、中身の原点・他ノートの発音位置を保つ。
  音高だけの変更では、既にトリムされたノートを窓の外まで露出させない。
- 自動配置は従来どおり最小の小節範囲へ合わせ、必要なら他の自動配置と結合する。
  共有内容の自動所有者の結合・固定リンクの参照先更新を先に行い、その後に編集対象の窓だけを広げる。
- 別の固定リンクの境界は変えない。ノート内容の共有と、各配置の窓による再生・表示の制限は維持する。
- 他配置との重複や算術の桁あふれは編集全体を拒否し、ノートだけを残さない。
  同一トラックの配置重複禁止は変えず、隣のクリップを削除・置換しない。
- ノートと配置の変更を既存の 1 アクションへ含め、単一 Undo / Redo・ジャーナル・保存へ接続する。
  アクションの引数、保存形式、音声スレッドと描画の窓制限自体は変更しない。

## 受入と基盤

- `PianoDragTests` の必須契約 `piano-note-clip-bounds-ui` は、自動配置と移動後の固定配置で、
  実 View の左右端・移動、ノート全長の確定フレーム、ID・ベロシティ、単一 Undo / Redo と保存再読込を確認する。
  UI の送信音価を旧値へ戻す負の対照と、選択の回帰を登録する。
- モデルの `note_edit` は、他ノートの発音位置、共有リンク、自動所有者の結合、短縮時の窓保持、
  音高だけの変更、左右の重複拒否と隣接境界を確認する。
  必須契約 `piano-note-clip-bounds` では固定窓の拡張を無効にする反例を Rust 側で再ビルドして検出する。
  履歴の `properties.rs` に固定窓の端を 1 tick 越える編集の生成を足す。
- 既存の `check-shell` / `check-product-contracts` が実行するため、新しい Makefile の入口は不要である。
  音を生成する処理は追加せず、発音区間のモデル回帰と既存のブロック長比較・RTSan を使う。
- [設計 §4.5](../architecture/model-and-history.md#45-スマートクリップ) と状態・デバッグ手順を更新する。
  外部入力・ログ形式・成果物の追加はなく、`doctor` / `debug-report` の収集範囲は変更不要である。
- ウィンドウと機器を開かない回帰を先に使う。実画面のドラッグの見え方と延長分の聴感はユーザー担当とする。
