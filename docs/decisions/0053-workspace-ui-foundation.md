# ADR 0053: Phase 1 のワークスペースの状態と操作を分離する

- 日付: 2026-10-10
- 状態: 採用
- 範囲: 今ある 3 ペイン、アレンジ、ピアノロール、数値入力、ファイルと CLAP の一覧、コマンド、再生・出力設定

## 背景

最初の `WorkspaceView` には、プロジェクト操作、ペインの配置、検索、ファイル読み込み、ノートの数値、再生表示が集まっていた。メニューとパレットの有効条件も別々に書かれていた。ノートを数値の形だけで識別すると、同じ値の別ノートへ移った時に下書きが残る。インスペクターは選択中のノートではなく挿入用の数値を表示していた。プラグインを選ぶ間にトラックが変わると挿入先も変わった。再生位置をルートで読むため、毎秒 20 回の更新がペイン全体にも届いていた。

トラックヘッダとタイムライン、鍵盤とピアノロールは既に同じフレームへ統合した（ADR 0051、0052）。その土台を保ち、現在の操作を増やしても状態の所有者が曖昧にならないようにする。

## 決定

状態を次の所有者へ分ける。

- `ProjectController`: Rust の文書、不変のスナップショット、選択トラックとノート、編集の実行中状態、Undo / Redo。選択したトラックに属し、現存するノートだけをフォーカスできる。文書を開くごとに新しいセッション ID を振る。成功したアクションだけを表示と履歴へ反映する。ノートとプラグインの操作は、操作部が生成された時の文書セッション ID も渡す。同じオブジェクト ID を持つ複製プロジェクトでも、切り替え前の操作を受け付けない。
- `WorkspaceState`: ウィンドウのペインの開閉・幅・高さ、表示用の調、入力の下書き、ファイル一覧、モーダル表示。配置は UserDefaults に保存し、プロジェクトの履歴へ入れない。調も現在は画面の設定であり、調マーカーではない。
- `NoteDraft`: 文書 ID、トラック ID、ノート ID と確定した形を持つ。文字列をそのまま保持し、現在のロケールで最後まで解析でき、整数 tick に変換できる値だけを確定できる。違うノートへの移動や外部の編集・Undo で下書きを置き換え、関係しない更新では保持する。
- `CanvasNavigationState`: アレンジのカメラとトラック名の幅、トラックごとのピアノロールのカメラ。スクロールのたびに SwiftUI を更新しない。ペインの開閉・トラックの切り替えを越えて保持し、文書を変えた時にリセットする。削除されたトラックの記憶は捨てる。ビューが記憶を書き戻す時にも所有する文書と現存するトラックを確認し、閉じかけの古いビューからの上書きを防ぐ。アプリの再起動を越えるカメラの保存は今回の範囲外。
- `WorkspaceCommand` と `WorkspaceSession`: コマンド名、ショートカット、有効条件と実行先を一つにする。メニュー、ツールバー、パレットから共用する。パレット、プラグイン、出力設定の表示は排他的にする。プラグインの挿入先は一覧を開いた時の文書とトラックに固定する。
- 各ペインの View: その表示に必要な状態だけを読む。再生位置と機器の表示は専用の View へ閉じ込める。Metal へ渡すのは不変のスナップショット、カメラ、選択とライブの再生位置である。

共通の `CanvasRenderer` をアレンジの View から分離し、描画スレッドとフレーム枠の所有を保つ。再生位置だけが動く時には、同じヒット領域やアクセシビリティの列を MainActor へ再送しない。提出したフレームのコールバックにはレンダラーの世代と入力の版を対応させ、停止したレンダラー、古い版、切り替え前の文書・トラックを受け入れない。ピアノロールのマウス編集は現在のカメラと大きさに合うフレームのヒット領域を使う。これは GPU へ提出した状態の管理であり、画面への表示完了時刻を測るものではない。

## 現在の操作

ペインの仕切りはドラッグとキーボード・アクセシビリティの増減で動かせる。最小幅は中央 520 ポイントと表示中の左右各 180 ポイントを確保し、エディタを表示する時はアレンジと入力部の両方に必要な高さを確保する。閉じても以前の幅・高さを保持する。

ノートエディタに対象のトラック名を表示する。選択中は「変更を適用」「入力を戻す」「削除」、未選択は「挿入」を表示し、誤った数値を入力した時は説明を出す。インスペクターには確定した選択ノートの値を表示する。数値欄や検索欄に入力する Space は再生へ送らず、テキストの Undo / Redo はネイティブの入力欄へ送る。

パレットと CLAP 一覧は、検索後に選んだ行を矢印キーと Return で実行する。CLAP の Return は一覧を保ち、ダブルクリックと挿入ボタンは成功後に閉じる。挿入に失敗した場合は一覧内にエラーを出す。ファイル一覧は検索、フォルダの移動、親へ戻る、更新、選択行の Return / ダブルクリックを扱う。読み込みはバックグラウンドで行い、遅れて届いた古い一覧で上書きしない。

## 後の Phase との境界

今回は UI の所有関係と既存操作を整える。ミキサー、センド、オートメーション、録音、デバイスビュー、ゴーストノート、ホットコーナー、プラグインのサムネイル、履歴の試聴 UI は追加しない。空のペインや未実装のコマンドも先に置かない。Phase 1 の履歴復元、ループ・メトロノームの操作、音声素材の取り込みは別の作業として残す。

後続の編集画面は、選択とスナップショットから対象を決め、画面固有のカメラ・下書きを所有し、確定した操作だけを `ProjectController` のアクションへ送る。コマンドは同じカタログに追加する。個別の行の高さやフォルダの折り畳みは Rust の可視問い合わせと共有の行配置を一緒に変える。これらの実装を推測した汎用フレームワークや空の crate は作らない。

## 検証と限界

画面を開かない Swift の検査で、配置と保存、数値の検証、同じ形の別ノートへの移動、Undo と下書き、挿入先、コマンドの有効条件、非同期の一覧、ネイティブ View を作り直した際のカメラ、ズームの支点、古いフレームの拒否を確認する。製品と同じ描画器のオフスクリーン GPU 検査と橋渡しの検査も実行する。

computer use はユーザーの明示許可時のみなので、ウィンドウでのレイアウト・マウス・キー・VoiceOver の操作確認、`spike-app` と `spike-draw` は未実施。単体検査とオフスクリーン描画の合格を、実際の操作感や表示遅延の保証にはしない。
