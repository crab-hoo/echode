# 0356. CLAP のノート形式の対応を公開し、終了処理を処理器と一緒に渡す

- 日付: 2026-11-15
- 状態: 一部置換（[0375](0375-midi-1-notes-for-midi-only-clap-ports.md)）
- 領域: プラグイン・隔離

## 背景

ホストは native CLAP のノート・表情を送るが、`clap.note-ports` のホスト側を公開していなかった。
入力ポートの MIDI 対応から作る全発音停止の一覧も初回のままで、無効化中に構成が変わると古いポートへ送っていた。
CLAP 1.2.2 の note-ports は、全走査を初期化・無効化中だけに許し、有効化中の構成変更は先に `request_restart` を求める。

## 比べた案と決定

- **MIDI・MPE・MIDI 2.0 も対応と答える**: 不採用。
  曲から送るイベントは native CLAP であり、MIDI の全発音停止だけでは通常ノートの変換・配布の対応を保証できない。
- **対応形式だけを公開し、再走査は初回の一覧のままにする**: 不採用。
  名前の通知には十分だが、合法な無効化中の増減で終了処理が欠けたり、削除済みのポートへ送ったりする。
- **一覧を atomic 等の別の交換路で更新する**: 不採用。
  再起動で既に処理器の所有権を主スレッドへ渡すため、別の世代・退役・同期の仕組みは必要ない。
- **native CLAP だけを公開し、毎回の有効化前に一覧を作る**: 採用。
  `Processor<P>` が停止中・処理中の処理器と一覧を一緒に持ち、既存の `ProcessorHandoff` で渡す。
  無効化後の読込みの失敗では再起動を完了扱いせず、既存の失敗経路でヘルパーを止める。

名前と出力ポートの記述は保持していないため、名前の通知に仕事はない。
全走査も通知の callback 内で再入せず、初期化・無効化が戻った後の有効化直前に、入力の終了処理に要る記述を読む。
通知がなくても各有効化で読み直すので、別の無効化フラグや古い一覧の写しは持たない。
比較用の inert host にも、同じ状態を持たない拡張を公開する。

音声側は、ローカルの NOTE_CHOKE・保持した MIDI 停止・曲のイベントを clack の参照の組でつなぐ。
終了処理はすべて時刻 0 で曲のイベントより先に置き、共有領域のイベント容量に依存させない。
ポートの増加でも音声側の確保・解放・ロックは増えず、一覧の作成と破棄は主スレッドだけで行う。
音声ポートの構造変更、MIDI 入力への変換、出力ノートの配布、ポート名の表示は範囲外である。
保存形式・IPC・C ABI・依存は変えない。

## 回帰と基盤

`echode-test-plugin` の `note-ports` は初期化・主スレッド callback・無効化中の通知を送り、有効化中の記述読込みを失敗として記録する。
実ヘルパーの回帰は修正前に終了コード 101 と `note-port capability probe failed: [128, 1, 1]` で失敗した。
古い終了処理を再利用する差分でも `wrong note/reset stream for 3 ports` で失敗した。
証拠はそれぞれ `target/focused-checks/note-ports-red/`・`target/focused-checks/note-ports-stale-red/` に残す。

1 → 3 → 0 → 1 ポート、native のみと MIDI 停止も使うポート、16 チャンネルの欠落・重複、通常ノートとの順序を検査する。
1・32・127・256 フレームを使い、名前だけで再有効化・親の再起動通知が起きないことも確認する。
既存の通常テストと `under_rtsan` の選択に入り、新しい実行入口は足さない。
既存のリセットと MIDI 終了処理の必須契約の反例は、新しい処理器と一覧の読込みの位置へ追従させる。
設計書・Phase 2・監査の現在欄・コードの所在・診断手順を更新する。
実画面の操作を足さないので新しい UC は作らず、第三者互換は UC-80〜83 の範囲に残す。
