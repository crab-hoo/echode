# ADR 0302: FFI の目録も C ABI の直前まで原因の型を保つ

- 日付: 2026-11-10
- 状態: 採用
- 対象: 統合表 M1、DEV-7・SPG-11・XCA-16
- 続き: [ADR 0301](0301-typed-history-spike-errors.md)
- 補足: [ADR 0295](0295-typed-plugin-host-errors.md) の目録の FFI 境界

## 問題と再現

開始時の HEAD は `1d1010c`。
`echode-ffi/src/catalog.rs` には、文字列の結果が 3 か所、元の原因を文へ戻す `map_err` が 4 か所あった。
既に型になった `echode_plugin_host::CatalogError` と JSON の原因を捨て、ヘルパー未検出のパスも文に埋めていた。
C ABI の目録と監視開始は失敗時に `-1` だけを返すので、この文を作る必要もなかった。
ADR 0295 で例外として残した境界を、今回は内部の型を保つ形に揃える。

回帰を先に加え、同じ `plugins_json`・`start_watch` と C ABI の入口を通す。
旧実装は `plugin catalog lost its typed cause` で失敗した。
期待終了コード 101 と固有のアサーションは `target/focused-checks/ffi-catalog-red-assertion/` に記録した。
最初の fixture は有効でない UUID の feature を使ってコンパイルに失敗したため、標準ライブラリの一時パスへ直した。
そのコンパイル失敗は red の証拠に数えない。

## 比べた案

| 案 | 判断 |
|---|---|
| ABI が数値を返すので内部は文字列のままにする | 採らない。内部の調査と回帰で原因を区別できず、不要な文を作る |
| 目録の原因を FFI 用の変種へ全部写し直す | 採らない。元の目録と同じ分類・I/O の保持を二重に実装する |
| FFI 固有の未検出と JSON だけを足し、目録のエラーはそのまま包む | 採る。境界に必要な区別を持ち、元の型と表示を再利用できる |
| C ABI にエラーの文・種類を返す入口を足す | 採らない。今回の内部の型付けには不要で、Swift と ABI の変更を増やす |

性能の改善を目的とせず、新しい時間・メモリの計測は判断の根拠にしない。
根拠は 7 か所の境界の除去と、製品入口の失敗、元の errno、従来の文・数値・JSON の照合である。

## 決定と境界

- `catalog::CatalogError` は `MissingHost(Option<PathBuf>)`・`Catalog(echode_plugin_host::CatalogError)`・`Json(serde_json::Error)` を持つ。
  `Display` は従来の文を作り、`Error::source` は元の目録または JSON を返す。
- `plugins_json`・`start_watch`・`require_host` はこの型を返す。元の原因を `to_string` へ戻さない。
- C ABI の戻り値、必要容量とコピー、目録の JSON、監視の寿命・再開始の扱いは変えない。
  内部の型は公開する C ヘッダへ追加しない。
- キャッシュの判定、走査の期限と隔離、保存形式、音声経路は変えない。

## 回帰と基盤

- `catalog_tests.rs` は子プロセスごとに環境・`ECHODE_CLAP_ROOTS`・キャッシュ・監視の状態を隔離する。
  実機・実際のインストール済みプラグインを使わず、同じ製品の入口を通す。
- ヘルパー未検出、キャッシュの親がファイル、キャッシュがディレクトリの失敗で、パス・元の I/O の errno と文を照合する。
  塞いだファイルを変更しないことも確認する。
- 空の目録の C ABI の容量・JSON、監視の開始・重複開始・待機と、キャッシュ済みの名前のエスケープ・`fresh:false` を確認する。
  JSON とスレッド開始の失敗は、実際の確保・スレッドの失敗を起こさず、変種の元の原因と表示を照合する。
- `check_typed_errors.py` の `TYPED_CRATES` に `echode-ffi` を登録する。
  Python 回帰は目録と新規・入れ子のモジュールへの文字列の結果・原因の文字列化の再導入を拒否する。
- 既存の `check-base` と Python 検査が追加回帰を通す。
  新しい実行入口・必須契約・外部入力はなく、Makefile・検査選択・fuzz の対象の追加は不要である。
- 領域の設計書、コードの所在、既存の走査失敗と再導入のデバッグ手順、監査の統合表を更新する。
  利用者の制約は変わらず、`status.md` とユーザー確認の追加は不要である。

## 検査後の空き容量

選択された検査の終了後、空きは約 403 MiB だった。
検査ロックを取得し、Cargo・rustc・rustfmt がいないことを確かめ、再生成できる `target/debug/incremental`（論理サイズ 13 GB）だけを整理した。
空きは約 11 GiB になった。検査記録・ユーザーデータ・完成済みバイナリと依存の成果物・鮮度情報は残した。
同じ Cargo の目録回帰を再実行し、FFI の `.a`・`.rlib` のサイズと更新時刻が変わらないことを照合した。
ソースを変えた次のビルドは増分キャッシュを作り直す分だけ遅くなり得る。その時間は未測定で、既存成果物の再利用とは区別する。
手順は既存の [空き容量不足](../debugging/verification-and-build.md#空き容量不足no-space-left-on-device--errno-28) に従い、検査の選択・基準は変えない。

## 残る範囲

M1 全体の完了ではない。
次はモデルの `derived_order` の文字列結果と、不変条件の原因を文に戻している所である。
実機・アプリ操作・聴感と、音声・画面・橋渡しの性能の計測は、この変更では行わない。
