# 0375. CLAP 形式を受けないノート入力ポートへ曲のノートを MIDI 1.0 で送る

- 日付: 2026-11-15
- 状態: 一部置換（[0379](0379-midi2-notes-for-clap-ports.md)）
- 領域: プラグイン・隔離
- 対象: F2・FCA-07・P2-03 の `clap.note-ports`
- 一部置換: [ADR 0356](0356-clap-note-port-capabilities-and-lifecycle.md) の「native CLAP だけを対応と答える」判断

## 背景

曲のノートは native CLAP のイベント（ポート 0・チャンネル 0・音高・ノート ID）でヘルパーへ届く。
CLAP 1.2.2 の [note-ports.h](https://github.com/free-audio/clap/blob/1.2.2/include/clap/ext/note-ports.h) では、入力ポートごとに受けられる形式を宣言する。
MIDI 1.0 だけを宣言するポートへ native のノートを送っても、そのプラグインは鳴らない。
ADR 0356 は、変換がないため MIDI の対応を答えず、全発音停止だけを MIDI で送ると決めた。

## 比べた案と決定

- **native CLAP だけを送り続ける**: 不採用。MIDI だけを受ける音源が黙って鳴らない。
- **MIDI を受ける全ポートへ MIDI で送る**: 不採用。
  CLAP も受けるポートでは、ノート ID と音ごとの表情が失われる。今鳴っているプラグインの挙動も変わる。
- **`preferred_dialect` が MIDI なら MIDI で送る**: 不採用。好みの表明であり、CLAP を受けるなら ID を保てる native の方が情報を失わない。
- **親（エンジン）で変換する**: 不採用。ポートの形式を知るのは有効化前のヘルパーだけで、共有領域の形式と配布を変える必要が出る。
- **MPE のチャンネル割当や MIDI 2.0 の UMP まで作る**: 今回は見送る。
  音ごとのチャンネル割当・MPE の設定メッセージ・表情の写像が必要になる。モデルの音ごとの表情は空の一覧しか受けず、曲から生まれない。
- **同じ音高の重なりをキーごとの参照数で隠す**: 見送る。
  ポートごとに 16 チャンネル × 128 音の状態と、リセット・再起動での初期化を音声側に足す。今回は MIDI 1.0 の意味（最初のノートオフでその音高が止まる）に従い、制約として示す。
- **CLAP を宣言せず MIDI 1.0 を宣言するポートだけ、ヘルパーで MIDI 1.0 に変換する**: 採用。

ホストの `supported_dialects` は CLAP と MIDI を答え、MPE と MIDI 2.0 は答えない。
有効化の直前に、既存の全発音停止の一覧と同じ記述の走査で、ポートごとの変換の要否を `NoteInputs` に作る。
一覧は処理器と一緒に `ProcessorHandoff` で渡し、無効化中の構成変更は次の有効化で読み直す。
65,536 番目以降のポートには曲のノートを宛てられないので、CLAP だけのポートは従来どおり受け入れ、MIDI を受けるポートは従来どおり失敗とする。

`events.rs::write_input` は、宛先のポートが MIDI だけのノートの出来事を、高々 1 つの MIDI メッセージにする。

- ノートオン: `0x9n`、ベロシティ `round(v × 127)`、ただし最小 1（0 はノートオフになる）。
- ノートオフ: `0x8n`、離鍵のベロシティを同じ式で送る。
- チョーク: MIDI 1.0 に該当がないので、ベロシティ 0 のノートオフにする。
- 圧力の表情: ポリフォニックキープレッシャー `0xAn`。音程・明るさは 1 チャンネルでは表せないので送らない。
- チャンネル・音高のワイルドカード、16 以上のチャンネルは 1 つのメッセージで表せないので送らない。ノート ID は落ちる。
- ポートのワイルドカードと、宣言より後ろのポートは従来どおり native で送る。パラメーターとトランスポートは変えない。

0〜1 の外の値は端へ寄せ、NaN は 0 にする。保存された 7 bit のベロシティ（0〜127）は、変換を往復しても同じ値に戻る。
MIDI のイベントは置き換える native のイベントより小さく、イベント領域は最大のイベントの大きさで確保済みなので、音声側で確保しない。
全発音停止の時刻 0 の native チョークと MIDI の CC 120 は従来どおりで、曲のイベントより先に置く。

## 回帰と基盤

- `events_tests.rs`: 2 ポートの混在、順序と時刻、ポリプレッシャー、捨てる出来事、ワイルドカードのポート、宣言外のポート、`ForbidAlloc` 下での確保なし、128 段のベロシティの往復、範囲外と NaN。
- `note_ports.rs` の単体テスト: 形式の組合せごとの変換の要否と全発音停止、65,536 番目のポートの扱い。
- `isolation/midi_notes.rs`: 実ヘルパーで CLAP だけのポートと MIDI だけのポートへ同時に送り、ホストの対応形式を照合する。
  無効化中に両ポートの形式を入れ替え、再有効化後に変換先も入れ替わることを 8・256 フレームで確かめる。
- `hosted_playback/midi_notes.rs`: エンジンのノートを MIDI だけの検査用音源（`onset-midi`）へ通す。
  48 kHz と 96 kHz、7・64・512 フレームの出力が native の `onset` と標本単位で一致することを確かめる。検査用音源は native のノートを受けると 1.0 を出す。

変換を止めた差分では、両方が終了コード 101 で失敗した。
`isolation` は `8 frames` の記録の不一致、`hosted_playback` は `MIDI-only notes differ from native CLAP notes` だった。
最初の有効化の形式を使い続ける差分では、`isolation` が入替え後の記録の不一致で 101 だった。
証拠は `target/focused-checks/midi-notes-red/` と `target/focused-checks/midi-notes-stale-red/` に残す。
時間とメモリの改善量は計測していない。

既存のテストと `under_rtsan` の選択に入れ、新しい実行入口は足さない。
必須契約 `plugin-onset`・`plugin-midi-panic` の反例が置き換える文字列は変えていない。
第三者の MIDI だけの音源の聴感は UC-90 に残す。
設計書・Phase 2・制約・監査の現在欄・コードの所在・診断手順を更新する。
