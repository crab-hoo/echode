# ADR 0214: パラメーターの変更セットを項目表から生成する

- 日付: 2026-11-02
- 状態: 採用
- 対象: SPG-09 の先行分。モデルの `Parameter` と変更セットの間の変換
- 関連: [ADR 0021](0021-changeset.md)、[構造監査](../reviews/2026-10-30-structure-audit.md#spg-09-モデルの項目追加の手数)

## 背景

`changeset.rs` は、パラメーターの最小値・最大値・既定値・現在値を、差分・作成と削除・下書きの構造・
スナップショットからの変換・作成の適用・値の設定・モデルへの復元に繰り返し記述していた。
項目を増やす時に一部だけ更新すると、ジャーナルの再生や逆適用で値を失う。

構造監査は、性質テストを先に補強してから項目表を導入する順番を勧めている。
全オブジェクトを一度に変えず、同じ `u32` の浮動小数点ビット表現を使うパラメーターの 4 項目から始める。
製品の誤動作を修正する作業ではなく、既存の結果を保つ構造整理である。

## 決定

- `changeset_parameter.rs` の `parameter_fields!` に、`Property` と `Parameter` のフィールドの対応を 1 回だけ書く。
  その表から差分、作成・削除のフィールド列、`ParamState`、両方向の変換、作成の読出し、設定を生成する。
- 下書きは引き続き浮動小数点のビットを `u32` で持つ。
  比較も `to_bits` を使い、符号付きゼロ・非正規化数・NaN のペイロードを低水準 API で失わない。
- ID・所属デバイス・不変のキーは、書き換えられる項目の表に入れない。
  設定は ID でパラメーターの下書きへ振り分け、表にないプロパティと誤った `Value` の種類を拒否する。
  キーの解釈は従来どおり最終復元時に行う。
- 作成時の `Owner`・`Key` と 4 項目の順序、必須フィールド、`Value::Bits`、公開列挙型を保つ。
  ジャーナル・パッケージの形式やスキーマ、Undo の意味、音声処理は変えない。
- ほかのオブジェクト、`Property` / `Value` の宣言、保存・FFI の項目表への統合は残す。
  SPG-09 全体を完了とはしない。

## 回帰と診断

補強した回帰を、製品の変更セットとジャーナルの公開入口へ先に通してから実装を置き換えた。

- `echode-history/tests/parameter_changesets.rs` は独立した期待値を持つ。
  任意の 4 組のビットと決定的な境界値で、項目間の取り違え、正確なフィールド順、無変更、作成・削除・更新、
  逆適用と二重反転、ジャーナルの符号化と再生を検査する。
- 同じ回帰で、作成の必須フィールドの欠落・誤った型、設定の誤った型、未知の ID、所属とキーの変更を拒否する。
  期待値は生成マクロを参照せず、誤った表を両方向で共有しても見逃さない。
- 既存の `properties.rs` は空とミキサー付きの初期状態を使い、パラメーターの非正規化数・ランダムな有限値・不正値を増やす。
  操作ごとの照合に加え、操作列全体の差分と逆適用も照合する。
  不変条件、Undo / Redo、ジャーナル、保存往復は従来どおり検査する。
- パッケージは負のゼロを `0` に正規化する（[ADR 0196](0196-lossless-package-floats.md)）。
  準備中の性質テストでこの既存仕様と全ビット一致の期待値が衝突したため、保存往復の生成から負のゼロを除いた。
  変更セットの負のゼロは専用回帰で確認し、保存仕様を変更したことにはしない。
- 低水準 API の非有限ビットの回帰は、有効なミキサー値の受入ではない。
  `DocumentHost` の公開前の不変条件検査は維持する。

新しい実行入口や依存は追加せず、通常の `check` が両テストを実行する。
フィールド名・境界名を持つアサーションと既存の検査ログを診断に使い、証拠の収集先は変えない。
性能計測・実画面・VoiceOver・聴感は今回の構造整理の合否とは別であり、実機は開かない。
