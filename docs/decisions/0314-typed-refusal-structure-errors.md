# ADR 0314: 拒否ペイロードの構造の原因を保持する

日付: 2026-11-10
状態: 採用
関連: M1（DEV-7・SPG-11・XCA-16）、[ADR 0313](0313-typed-launch-refusal-decoding.md)

## 問題と再現

開始時の HEAD は `a668469`。
`read_plugin_failure` は、不足・余分なペイロード、未知の種類、不正なポートの向きを `None` にしていた。
外側の `read_refusal` も、種類・固定長・応答のコードの拒否を定数の文だけの `io::Error` にしていた。
表示文は残るが、受けた値・フィールド・期待と実際の長さを型で読めなかった。

製品の `Socket::recv_tagged` に不正な拒否の生フレームを送る回帰を先に追加した。
修正前は `malformed refusal must retain its typed structural cause` で失敗した。
期待終了コード 101 と固有のアサーションの照合は `target/focused-checks/refusal-decode-red/` に残す。

## 比べた案と決定

1. `Option` と定数の文を残す。異なる構造の失敗が同じ文へ消えるので採らない。
2. プラグインと外側に別々のエラー階層を作る。どちらも拒否の構造の読込みで、元の外部エラーはないため、層を増やさない。
3. **共通の `RefusalDecodeError` で種類・構造を保持し、固定長の検証を一つにする。**

3 を採る。`RefusalField` は呼出し番号・パラメーター ID・応答の組・プラグインのペイロードを区別する。
固定長の不一致はフィールド・必要なバイト数・実際のバイト数を持つ。
欠けた種類、未知の種類・期待／実際の応答コード、不正なポートの向きも型で分ける。
プラグインの種類を先に読み、その種類が必要とする長さを検証してから中身を読む。
ポートの長さと向きが両方不正なら長さを返す。未知の種類はペイロードより先に返す。

`io::Error::get_ref` から同じ型を読み、公開操作の `SessionError::Io` でも保持する。
起動拒否の `LaunchDecodeError` は既存の独立した型のままにし、UTF-8 の元の原因を保つ。
表示文・`InvalidData`・通信の形式と受理する入力は変えない。不正な生バイトは保存しない。
音声処理・期限・保存・C ABI は変えず、性能改善は主張しない。

## 回帰と基盤

- `control_refusal_tests.rs` は、ポート・状態・パラメーター・窓の全拒否経路を実ソケットに通す。
  未知コード・不正な向きの全値、各固定長の不足と超過、単純な拒否の余分なバイトを型と従来の文面で照合する。
  正しい値と既存の全種類の往復・正規性の回帰も維持する。
- `session_refusal_tests.rs` は、公開するパラメーター操作で構造の全原因の保持を検査する。
- 制御ソケットの fuzz の種に、全拒否経路の不正な構造を追加する。
  通常の Rust 検査と既存の `control_inputs_replay` が通すため、Makefile と検査選択は増やさない。
- 領域別設計、コードの所在、診断手順と索引、監査の状態を更新する。
  利用者の制約・実機の確認場面は増えず、status.md とユーザー確認の一覧は変えない。

## 残り

M1 全体の完了とはしない。次は `control.rs` の拒否以外のメタデータ検証で、固定長・種類・ポートの列の原因を定数の文へ畳む境界である。
検査結果と各検査の見送り理由は `target/verification/report.md` を正本とする。
