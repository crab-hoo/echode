# 0037. ブロックのイベントは CLAP の形にし、番号は再生のあいだ固定する

- 日付: 2026-10-09
- 状態: 採用
- 項目: ENG-4

## 背景

ブロックのイベントはノートの開始と終了だけで、トラックとノートの ID がそれぞれ 16 バイトある。CLAP が主な形式で、内蔵デバイスも同じ考え方にする（ARCHITECTURE §10）。パラメータの値、変調、ノートの表情、トランスポートも、同じ列でデバイスへ渡す（§4.6、§9.3）。

CLAP のノートは、ポート、チャンネル、キー、`note_id` で声を指す。`note_id` は `0..i32::MAX` の整数で、同じキーが重なったときの区別に使う。モデルの ID は UUIDv7 で、この範囲には入らない。計画を作り直すたびに番号を振り直すと、鳴り続けている声（[ADR 0036](0036-audio-handoff.md)）へ届くノートオフの番号が、ノートオンのときと食い違う。

## 調査

`clack-common` 0.2.0 の入力イベントは、`NoteOn`、`NoteOff`、`NoteChoke`、`NoteExpression`、`ParamValue`、`ParamMod`、`Transport` である。時刻はブロック先頭からのサンプル、ベロシティとパラメータ値は `f64` である。番号やポートを指定しないときは、CLAP の -1 に当たる。`NoteEnd` はプラグインからホストへの通知で、入力の列には入らない。

イベントの C の並びは `clack` がすでに持っている。オーディオスレッドの crate にその ABI を持ち込む必要はない。

共有メモリの計測用の領域は、ヘッダと音声バッファだけで、64 KiB 未満に収まっている。イベントのバイト列をそこへ足すのは、製品のグラフがプロセスをまたぐときである。

## 決定

- イベントの型は `echode-realtime` に置く。`Copy` で、ヒープも `clack` も持たない。呼び出し側のバッファへ書き、オーディオスレッドでは確保しない。`echode-engine` の `MidiEvent` と、今の `Edge` は、この型に替える
- 種類は次のとおりである。時刻はどの種類も持つ。トランスポート以外はトラックの `u32` を持つ。トランスポートはトラックを持たない
  - ノートオン、ノートオフ。トラック、ポート、チャンネル、キー、`note_id`、ベロシティ
  - チョーク。トラック、ポート、チャンネル、キー、`note_id`
  - ノートの表情。トラックと宛先、種類（`pitch`、`timbre`、`pressure` の順）、`f64`。値は CLAP の単位で、ピッチはセミトーン、ほかは 0 以上 1 以下である
  - パラメータの値、パラメータの変調。トラック、パラメータの `u32`、宛先、`f64`。CLAP の cookie ポインタはイベントに入れない。ホストがパラメータ番号から引く
  - トランスポート。再生中か、録音中か、ループが有効か、テンポと増分、拍と秒の位置、ループの拍と秒、小節の開始と番号、拍子。トラック番号は付けない
- ポート、チャンネル、キー、`note_id` は、それぞれ `Option` である。`None` はホストで CLAP の -1 になる。`note_id` の `Some` は `0..i32::MAX` の `u32` で、負数も `u32` の番兵も使わない。エンジンが打つノートは、ポート 0、チャンネル 0、キー、`note_id` をすべて `Some` で持つ
- ベロシティは 0 以上 1 以下の `f64` で、保存した 0〜65535 を 65535 で割った値である（[ADR 0027](0027-note-expression.md)）。65535 は 1 になり、今のベロシティ 127 の音量と一致する。ノートオフのベロシティは 0 のままである。ベロシティ 0 のノートオンはノートオフにしない
- 計画に残すモデルの ID は `u128` のままである。イベントに載せる `note_id` とトラック番号は、計画を作る制御スレッドが振り、計画のノートとトラックに控える。初めて見たモデルの ID には次の番号を振り、同じ再生では同じ番号を使い続ける。計画を作り直しても変えない。番号は再利用しない。`i32::MAX` に達したら、計画の組み立ては失敗する。これは同時に鳴る数の上限ではない
- カーソルが出すのはノートオンとノートオフだけである。ループで止めるのもノートオフのままで、チョークにはしない（[ADR 0010](0010-playback-samples.md)）。表情は、モデルが空以外を拒んでいるあいだは出さない。パラメータのイベントはデバイスのパラメータ用で、ミキサーのゲイン、パン、ミュート、ソロは計画のフィールドのままである（ADR 0036）。鳴り続けるノートのノートオフは、ノートオンを出したときのキーを使う。差し替え後の音高では出さない
- トランスポートはカーソルが出さない。ブロックを埋める関数が、そのブロックの各スパンの先頭サンプルに 1 つ、呼び出し側の同じバッファへ書いてから、ノートと一緒に 1 回だけ並べる。別のバッファは作らない。ノートだけの `schedule` はトランスポートを書かない
- 並べる順は、サンプル、種類（トランスポート、ノートオフ、チョーク、ノートオン、表情、パラメータの値、変調）、トラック番号、ポート、チャンネル、キー、`note_id`、表情の種類、パラメータ番号である。無い宛先は、ある宛先より前である。ここまで同じものは、書く前の順を保つ安定なソートにする
- テスト用シンセとプラグインホストは、この列を同じ型で受ける。シンセはノートオンとノートオフだけを声に使い、ほかは読み飛ばす。声の対応は `note_id` である。ホストは `clack` の入力バッファへ翻訳してから `process` に渡す。翻訳はホストの crate で行う
- 計測用の共有メモリにはイベントを足さない。ホストのプロセス内の処理と、列を渡されたヘルパーの `process` が、この翻訳を使う。スパイクが音声だけを渡す経路は、空の列のままである

## 結果

`make check` が通った。同じサンプルのパラメータと表情は、パラメータ番号と表情の種類で決まり、無い宛先は前に来る。同じキーが並んだときは、書いた順が残る。トランスポートはトラックを持たず、ブロックの各スパンの先頭に 1 つ書いてからノートと一緒に並べる。`note_id` が無い宛先は CLAP の -1 になる。音高を変えて計画を差し替えても、ノートオフのキーはノートオンのときのままである。テスト用シンセとプラグインホストは同じイベント列を受ける。
