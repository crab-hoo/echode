# ADR 0140: パラメーター一覧の失敗をデバイス列から再試行する

- 日付: 2026-10-21
- 状態: 採用。P2-02 の失敗時の復旧入口を接続。実画面と VoiceOver はユーザー確認待ち
- 範囲: デバイス列の一覧取得の再試行、読込み表示と重複要求の抑止、古い対象の拒否

## 背景

[操作要件](../interaction-design.md#処理中も作業を続ける)は、失敗を対象内に表示し、再試行・オフライン化・削除へつなぐことを求める。
[ADR 0131](0131-device-view-and-responsive-parameters.md)で一覧の失敗は列へ表示するようになったが、列内の再試行入口はなかった。
機器なしの実 `DeviceColumnView` に取得失敗を渡す回帰を先に追加し、再試行ボタンが存在しないことで失敗させた。

## 決定

- 失敗した一覧の本文に「パラメーターを再読込み」を表示する。アクセシビリティ名は対象のデバイス名を含む。
  読込み中・正常な空の一覧・オフライン・折りたたみ中には表示しない。文書交換などの排他操作中は無効にする。
- クリック時の文書 ID とデバイス ID を保持し、そのデバイスの一覧だけを既存のデバイス要求経路で読み直す。
  表示するトラックの選択へ付け替えず、他の列の一覧を要求し直さない。
- 非同期の手番を渡す前に取得失敗を消して読込み中へ移る。連続クリックは追加要求を作らない。
  読込み中も名前・チェイン操作・追加ボタン・無関係な編集と停止を残し、再失敗は同じ列の復旧入口へ戻す。
- 読込み開始と応答適用の両方で文書と状態の同一性を検査し、応答は要求世代も照合する。
  オフライン化・削除・文書交換の後に古い列が再試行を要求しても送信しない。
- 再試行はプラグイン状態の読込・ヘルパーの再起動・文書アクションではない。
  検索語・ピン留め・選択・保存・Undo / Redo を変えない。保存形式と音声処理の変更はない。

## 検査と診断

- 必須契約 `device-list-retry-ui` は実ボタンからの失敗→読込み→成功と再失敗→成功を通す。
  代役のプラグインの応答を保留し、連打の集約、他の列の保持、他の編集と停止の完了、検索・選択・履歴の保持を確認する。
  負の対照はボタンのコールバックを切り、クリックが要求へ届かない時に期待値で失敗させる。
- `DeviceParameterRetryTests` は表示条件・アクセシビリティ名・配置、オフライン・削除・旧文書の拒否、
  遅れた再試行が新しい一覧や閉じた文書を上書きしないことも確認する。
- 検査の登録と選択の回帰を更新する。既存の `make check-product-contracts` と Swift の通常・ASan・TSan の経路を使い、新しい検査ターゲットは増やさない。
- エラー文による原因の切分けは[デバッグ手順](../debugging/audio-and-plugins.md#プラグイン)へ追記する。
  ログ・成果物・ヘルパーの形式は変えないため、診断資料の収集器は変更しない。

## 残る範囲

- ヘルパーのクラッシュやプラグインの未検出を、このボタンだけで復旧できるとは限らない。
  明示的なオフライン化・再有効化・削除とは別の操作である。
- 実画面の操作感と VoiceOver、第三者プラグインの取得失敗と復旧はユーザー確認とする。
- 初回の出力準備と一覧の応答待ちの表示の区別、開いた出力への新しいヘルパーの準備は引き続き別の範囲である。
