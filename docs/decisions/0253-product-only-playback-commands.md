# ADR 0253: 製品だけの計画受渡しと音声側の命令型

- 日付: 2026-11-03
- 状態: 採用
- 対象: 全体監査の FCA-11。製品の音・操作・保存形式は変えない。

## 背景と確認

[全体監査](../reviews/2026-11-03-full-code-audit.md#fca-11-使わないコードと届かない分岐) は、製品から使われない計画受渡しと、音声側へ届かない命令を指摘した。
`handoff.rs` の `pair`・`Control`・`Audio`・`Cycle` は専用テストだけが使い、`Plan::write_mixer` もこの経路だけから呼ばれていた。
製品の計画とプラグインの所有権交換は既に `playback.rs` にあり（[ADR 0102](0102-exclusive-audio-graph.md)）、同じ機能の別の公開経路を残す理由がない。

公開の `PlaybackCommand` は、制御側で処理する `SetLoop`・`ClearLoop`・`PreviewFader` も含む。
制御側がそれらを変換しても、従来の `QueuedCommand::Transport(PlaybackCommand)` は元の型をリングへ載せられた。
音声側には実行されないループの分岐と、単一フェーダーを受けた時の `abort` が残り、型ではその不在を表せなかった。

正規の製品入口からその `abort` へ到達する不具合は再現していない。今回の目的は構造上の不整合の除去である。
先に `PlaybackControl::command` と製品のコールバックを使う境界回帰を追加し、変更前の順序・受領番号・変換・拒否・返却待ちを確認した。
前後の個別ログは `target/focused-checks/fca11-before/`・`fca11-after/`・`fca11-boundaries/` に残す。
音の基準の再生成や、意図した red を装ったビルド失敗は行わない。

## 決定

- 未使用の `handoff.rs` と専用テスト、公開の `pair`・`Control`・`Audio`・`Cycle` を削除する。
  そこだけが使う `MixerKey`・`MixerChange`・`Plan::write_mixer` も削除し、製品は既存の `playback` の入口だけを使う。
- 音声リングの内部型 `QueuedCommand` は、再生・一時停止・停止・位置移動・停止復帰・メトロノーム・試聴解除・所有権付きの試聴集合だけを持つ。
  公開型を中に包まず、制御側で全 variant を網羅的に対応付ける。新しい公開命令の追加は、この境界のコンパイル検査も受ける。
- ループは制御側で容量を含む次の計画を準備する。無効なエンジン直入力でループを解除する従来の意味も保つ。
  単一フェーダーは制御側で全 ID・値を検証した集合に変換する。いずれも音声側の専用型には存在しない。
- 命令の順序・受領番号の周回・満杯時の拒否は変えない。
  試聴集合と古い計画は従来の復路へ返し、制御側が解放する。復路が満杯なら未適用の所有物をリングに残す。
- 音声側の命令の処理で `PreviewFader` の `abort` と実行されないループの分岐をなくす。
  返却先を予約した後の push が失敗する場合の、別の所有権不変条件の `abort` は今回変更しない。

## 回帰と基盤

`playback_command_tests.rs` に製品入口を通す回帰をまとめる。

- 公開の全トランスポート命令、複数命令の順序、受領番号と適用の遅れ、メトロノーム。
- ループが命令リングを消費せず、計画の採用で切り替わること。ゼロ長・逆向きの既存の解除動作。
- 単一フェーダーの不正 ID・NaN・無限大・範囲外の全体拒否と、所有権付きの集合への変換・解除・制御側の回収。
- 往路の満杯で受領番号が進まないことと、回収後の再受付。
- 試聴集合の復路が満杯でも所有物を落とさず、制御側の回収後に未適用の命令を進めること。
- 実際に準備した計画で復路を埋め、次の計画を残したまま試聴を適用し、制御側の回収後に計画の採用を再開すること。

製品コールバックの確保検出と RTSan、既存の 1 万回の製品交換・停止復帰・ループ・一括試聴の PCM とブロック長回帰を維持する。
新しい音源・DSP・モデルアクションはなく、別の音声生成や履歴操作の生成は追加しない。
通常のモデルとエンジンの検査・必須契約へ含まれるため、Makefile と `scripts/verification.json` の入口・選択は変更不要である。
既存の反例の置換文字列も保持する。

設計・コードの所在・監査の対応を更新し、旧 ADR 0036 の結果は当時の別実装の証拠として残す。
デバッグ手順には、命令の受付と適用、計画の準備と採用、復路の回収待ちを区別する手順を足す。
ログ形式・収集先・外部入力は変わらず、doctor と debug-report の追加改修は不要である。
利用者の操作・制約を変えないため `status.md` とユーザー確認の項目は追加しない。

## 範囲外

全体の計画の作り直し（FCA-04）、モデルの索引の残り（FCA-05）、音源 DSP の依存（FCA-15）は残す。
機器・GUI・第三者プラグインを使う確認は行わない。既存の実機・聴感の確認待ちを、この構造変更の自動回帰の結果で合格へ置き換えない。
