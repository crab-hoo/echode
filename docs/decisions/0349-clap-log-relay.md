# 0349. CLAP のログは固定量の診断スロットから制御側へ渡す

- 日付: 2026-11-14
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: FCA-07 の `clap.log`

## 背景

CLAP のログは任意のプラグインスレッドから来る。
音声から直接 stderr や製品のロガーへ書くと、確保・ロック・I/O が処理区間へ入る。
既存のパラメーター通知のリングは単一の書き手用なので、メイン・音声・補助スレッドで共有できない。

## 比べた案と決定

- **その場で stderr / `log` へ書く**: 不採用。音声スレッドの禁止操作になる。
- **無制限の待ち行列、または Mutex 付きの `try_send`**: 不採用。
  確保・ロックを持ち込み、大量のログで音声やメモリを圧迫する。
- **単一書き手の既存リングを流用する**: 不採用。CLAP の任意スレッドの契約に合わない。
- **複数書き手の診断スロット**: 採用。
  起動時に 64 スロットを確保し、1 件は先頭 1,024 byte まで写す。
  書き手は原子カウンターで選んだ 1 スロットを 1 回だけ取り、使用中なら再試行せず破棄数を増やす。
  空きがほかにあっても競合した件は落とす。診断だけの上限で、プラグイン数やポート数は制限しない。

スロットは empty → busy → ready → busy → empty の所有で、公開と引継ぎを release / acquire でつなぐ。
文字列を借りたまま残さず、取り出す側もローカルへ写してから空きを公開する。
制御側は 1 回に全スロットを 1 周だけ読み、大量の記録が続いても読み尽くすまでループしない。
到着順の保存は保証せず、使用中・満杯の破棄は `dropped` で知らせる。

書き手は最大 1,024 byte を調べ、NUL を見つけたら止める。
上限まで達した時は `truncated=true` とし、その直後の NUL か続きを調べない。
null は無視する。不正な UTF-8 や途中で切れた多 byte 文字の表示は制御側で置換する。
7 種の重大度と未知の整数値をそのまま残し、fatal や misbehaving でもホストの停止・プラグインの削除を自動実行しない。

## 記録と寿命

プラグイン ID はインスタンス生成前に設定し、初期化中のログにも付ける。
制御ループとメイン応答・再起動の待ちで取り出し、既存の stderr 収集へ 1 件 1 行で書く。
改行・制御文字は引用して、プラグインが診断の行を偽装しないようにする。
初期化・有効化の拒否は、拒否の応答を送る前に取り出す。
最後の残りは、作成したスレッドがワーカーの join とプラグインの破棄を終えてから取り出す。
異常終了前の未読分は失われ、親が製品のログへ残すのは従来どおり終了時の stderr の末尾である。
比較用の同一プロセス計測は bridge を持たず、ログを捨てる。製品にプラグインを読み込む経路は増やさない。
保存・Undo・IPC と依存ライブラリは変えない。

## 回帰と基盤

`echode-test-plugin` の `host-log` はメインと 4 補助スレッド、音声処理から記録する。
実ヘルパーの `isolation/plugin_log.rs` は重大度・ID・長い文字列・UTF-8・改行と、4 種のブロック長で変わらない音を照合する。
`host-log-refuse` では初期化を拒否し、その直前のログが起動エラーに残ることを照合する。
登録前の回帰は終了コード 101 と `spawn plugin host: ... clap.log extension is unavailable` を照合した。
その記録は `target/focused-checks/clap-log-red/` にある。

単体回帰は確保検出下の投入、NUL と長さの境界、元の文字列の寿命、満杯・競合と復帰を確認する。
4 書き手 × 500 件を消費と並行させ、読めた件数と破棄数の合計と、各件の重大度・文字列の一致を検証する。
処理時間の比較計測はしていない。投入は 1 回の所有権取得と固定量のコピーで、実機の期限内の完走の証明ではない。
`under_rtsan` の隔離回帰を既存の全体検査にも含め、新しい検査入口や選択条件は増やさない。
新しい外部ファイル・IPC のパーサーはなく、fuzz の対象も変えない。

設計書・監査の現在欄と診断手順を更新し、第三者 CLAP での互換は UC-81 へ分ける。
`timer-support` 等の残る拡張と P2-03 全体の受入は完了扱いしない。
