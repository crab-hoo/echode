# ADR 0158: 両ルーラーの既存ループ端をドラッグする

- 日付: 2026-10-25
- 状態: 採用。P2-07 のトランスポートの続き
- 関連: [ADR 0156](0156-ruler-loop-range-and-entry.md)、[ADR 0157](0157-arrange-ruler.md)

## 背景と再現

両ルーラーは新しい範囲を指定できるが、既存端をつかんでも片端の調整にはならなかった。
変更前の実 View に、1〜4 拍の範囲の先頭から 2.3 拍へのドラッグを送ると、
反対端の 4 拍が失われ、新規の 1〜2 拍（ピアノロールは 1〜2.25 拍）になった。
端の単クリックは開始位置を変えていた。
`RulerHandleTests.contractLoopHandlesResizeOneEdgeWithoutSeekingInBothEditors` でこの差を再現した。

## 決定

- ルーラー上端の 8 pt に左右端のグリップを描く。時間軸の外とノート・行領域へはみ出さない。
  実際の端が画面外ならグリップを作らず、帯の切れ目を端として扱わない。
  入力は端の左右 5 pt を時間軸内へ制限し、両端が近い時はポインターに近い端を選ぶ。
  通常の開始位置クリックと新規範囲指定は、残りのルーラー領域で引き続き使える。
- `RulerHandles` が両エディタの入力・描画・リサイズカーソルの幾何を共有する。
  オン／オフは既存の緑／灰色に合わせ、開始位置の印はグリップより上へ描く。
- `RulerPress` はつかんだ端と元の範囲を保持する。3 pt 以上動いた後は片端だけを変え、
  つかんだ位置と端のずれを保って、押下時や最初の移動でポインターへ跳ばさない。
  アレンジは四分音符、ピアノロールは現在のノートグリッドへ動く端だけを吸着する。
  Shift は動く端の吸着だけを外し、反対端は端数も含め元の tick を保つ。
- 端を反対側へ越しても左右を交換しない。
  吸着中は反対端より内側の最寄りのグリッド位置、Shift 中は 1 tick の長さで止める。
  先頭は 0 未満にせず、有効な整数範囲を作れない場合は送信しない。
- 端のクリック・微小な揺れは何も送らず、開始位置の変更へ戻さない。
  元の範囲に戻して離した時も何も送らない。
  ドラッグ中は帯とグリップだけを仮表示し、解放時に変更後の範囲を 1 回送る。
- 範囲の確定には既存の controller と製品ブリッジを使う。
  オフ中は下書きだけ、オン中は `transport.loop` を更新する。
  開始位置・現在位置・選択・Undo、範囲の保存方針は変えない。
- 既存の Escape・フォーカス喪失・リサイズ・カメラ・文書・スナップショット変更・終了による取消を共有する。
  さらに、別エディタや範囲欄による範囲・オンオフ変更でも未確定の操作を破棄し、古い解放で上書きしない。
  ピアノロールにも AppKit の `mouseCancelled` を接続する。

## 受入と基盤

- 必須契約 `loop-handles-ui` は両実 View から片端調整、単一送信、吸着・Shift・つかむ位置の保持を確認する。
  製品ブリッジでオンオフ・開始位置・現在位置・選択・Undo の不変を確認する。
  反例は左右の役割の逆転と、各エディタからのグリップ描画の除去とする。
- `loop-handles-cancel-ui` は取消後の遅れた解放を検査する。
  外部の範囲変更による取消を各エディタから外す反例を持つ。
  通常回帰では交差・0・端数の固定端・整数境界、近い端の選択と描画境界も確認する。
- 両オフスクリーン GPU プローブは倍率 1・2、有効／無効で端の画素と、画面外の端を代用しないことを確認する。
  新しい検査種別は作らず、既存の Makefile 入口と検査選択へ登録する。
- モデル・音声処理・保存形式・外部入力・ログ形式は変えない。
  診断の収集範囲は維持し、デバッグ手順へ端の入力領域と外部変更による取消の識別を加える。
- 実画面の見え方・つかみやすさ・VoiceOver はユーザー確認とする。
  自動スクロールと Return の一時停止／再開はこの単位には含めない。
