# ADR 0281: 障害は静かに安全側へ倒し、起きたことと行ったことを隠さない

- 日付: 2026-11-08
- 状態: 採用（ユーザーの方針）
- 関連: [ADR 0276](0276-priority-order-and-delegated-decisions.md)（優先順位）、[操作要件「処理中も作業を続ける」](../interaction-design.md#処理中も作業を続ける)、
  [クラッシュとハング](../architecture/plugins-and-devices.md#94-クラッシュとハング)
- 置き換え: ADR 0276 の「段の間の非有限値と安全な出力（XCA-21）」の決定（実機への出力だけに安全な上限を置く）

## 背景

2026-11-08、統合表の R2（段の間の非有限値と出力の上限）を進める前に、ユーザーが次の方針を示した。

- 出力に黙って上限を付けず、自動のマスターまたはトラックのミュートにする。
- 内部がブラックボックスにならないようにし、問題が起きた時に何が起きたかをユーザーが分かるようにする。同時に作業の邪魔をしない。
- 安全性と透明性を保ちながら、ユーザーの注意と操作への介入を最小にする。Calm Technology、Fail-Safe と Frictionless Recovery、Transparent を採る。
- 自動ミュートは見た目では手動と区別しなくてよいが、内部では区別し、再生の開始で自動で解除する（REAPER と同じ）。

近い扱いは既に場面ごとにあった。プラグインの締め切り超過・クラッシュはそのトラックだけを無音にし、デバイスビューで再起動を提案する（ARCHITECTURE §9.4、[ADR 0245](0245-plugin-deadline-fades.md)）。
失敗はその対象の中に表示し、フォーカスを奪わない（操作要件）。書出しの NaN・無限大は無音へ隠さずエラーにする（[ADR 0247](0247-pcm24-wav-export.md)）。
しかし製品全体の原則としては書かれておらず、ADR 0276 の R2 の決定（黙った上限）はこの考え方に反していた。

REAPER は、設定の Audio > Mute/Solo で、しきい値を超えたトラックやマスターを自動でミュートする（利用者の報告による）。
再生を始め直すまでミュートが続くという報告もある。公式の文書では確かめていないので、Echode の振る舞いはユーザーの指定に基づく。

## 決定

障害（プラグインの異常な出力、締め切り超過、クラッシュ、読めない素材など）への振る舞いを、次の 4 つで決める。
これは堅牢性（ADR 0276）を実現する時の作法であり、優先順位の段を新しく作るものではない。

### Fail-Safe: 最小の範囲で安全側へ倒す

- 異常を検知したら、影響の範囲を最も小さい単位（デバイス、トラック、マスターの順）に限り、安全な状態にする。安全な状態は、無音、自動ミュート、要求の拒否である。
- 音を作り変えて正常に見せない。黙った上限・丸め・リミッター、無断のバイパスで、異常をなかったことにしない。
- 安全な状態に倒した後も、ほかのトラック・GUI・編集は止めない。

### Transparent: 起きたことと行ったことを隠さない

- 何が起きたか（対象、種類、時刻）と、Echode が何をしたか（自動ミュート、無音化、拒否、再起動）を記録する。
- ユーザーが確かめられる場所に出す。対象の近くの表示、VoiceOver の説明、API・MCP の状態である。
- 自動の処置は、ユーザーの操作による状態（手動のミュートなど）と内部で区別する。表示が同じでも、理由を辿れるようにする。

### Calm: 注意と操作への介入を最小にする

- ダイアログ、フォーカスの奪取、再生や編集の停止で知らせない。
- 表示は対象の近くに一度だけ出し、同じ原因で繰り返さない。解消すれば消える。

### Frictionless Recovery: 普段の操作で戻る

- 復旧は 1 回の操作か、ユーザーの自然な次の操作で起きるようにする。
- 自動の処置は保存・Undo・書出しの対象にしない。ユーザーの設定を書き換えない。
- 復旧の時は、原因の状態（壊れたプラグインの内部状態など）も一緒に戻し、同じ異常をすぐに繰り返さない。

### 自動ミュート（R2 への適用）

- 段の間で NaN・無限大、または有限でも異常に大きい値を検知したら、そのトラックを自動でミュートする。後ろの段には 0 を渡し、次のプラグインの状態を守る。
  原因のトラックを特定できない時（マスターの段など）は、マスターを自動でミュートする。
- 値を上限で丸めない。「異常に大きい」のしきい値は、R2 の実装の ADR で理由と測定を付けて決める。
- 自動ミュートは手動のミュートと内部で区別し、保存・Undo・書出しに入れない。ミュートの表示は手動と同じでよい。
  理由（どのトラックのどのプラグインが、何を出したか）は、トラックの近くの表示、VoiceOver、API で示す。
- 再生の開始で自動で解除する。解除の時は、原因のプラグインの処理状態を戻してから音を通す。解除の後に同じ異常が起きれば、また自動でミュートする。
- 書出しでは、従来どおりエラーにして原因の場所を示す（ADR 0247）。書出しの値は変えない。

## 理由

- 黙った上限は、耳と機材を守っても、何が起きたかを隠す。ユーザーは壊れたプラグインに気付かず、そのまま作業を続ける。
- 自動ミュートは、最小の範囲で音を止め、原因を示せる。再生の開始で解除されるので、ユーザーは特別な操作を覚えずに戻れる。
- 内部で区別することで、自動の処置が保存やユーザーの設定へ漏れない。保存されたミュートを後で誤って解除することもない。

## 影響

- [開発計画](../PLAN.md) §1 の「止まらない」と、[操作要件](../interaction-design.md#障害の知らせ方と戻し方) から参照する。
- ADR 0276 の XCA-21 の行と、[統合表](../reviews/2026-11-08-open-items-register.md) の R2、[横断監査](../reviews/2026-11-02-cross-cutting-audit.md#xca-21-製品の設定) の XCA-21 を、この決定へ向けた。
- 既存の §9.4 の無音化と再起動の提案は、この原則に沿っている。自動ミュートとの関係（同じ表示と状態に揃えるか）は、R2 の実装で決める。
- 製品のコードはまだ変えていない。
