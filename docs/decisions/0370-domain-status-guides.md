# ADR 0370: 制約を領域別に分け、開始時は索引だけを読む

## 背景

[PCA-03](../reviews/2026-11-13-professional-cross-audit.md#pca-03-全文を読む資料が上限まで-6-バイト) は、全文を読む 4 文書が上限 44,000 B に対して 43,994 B であることを指摘した。
制約の追記が容量不足で止まり、DIA-09 の既存の Undo の挙動も未記載だった。
[ADR 0235](0235-reading-budget-and-split-guides.md) の上限は維持し、制約を削らずに追記できる構成へ変える。

## 比較と決定

- 上限を上げる案は採らない。開始時の読込量が増え、無関係な領域の制約まで毎回読む問題が残る。
- 表現をさらに縮めて 1 ファイルに保つ案も採らない。制約・UC 番号・根拠の欠落を招き、追記のたびに同じ問題が戻る。
- **領域別に分ける案を採る**。`docs/status.md` は対象環境・進捗・制約の索引だけとし、制約の本文は `docs/status/` の 6 ファイルを正本にする。
  保存、API と文書、音声、プラグイン、ピアノロール、アレンジと画面の既存の区切りを保つ。
  API と文書は保存・プラグインとは異なる入口なので独立させる。
- 全文を読む 4 ファイルは変えない。領域別の制約は見出しから必要な節だけを読む。
  `agent_context.py` の既存の領域別案内に分割先を足し、全分割先を節の容量検査に含める。
  文書の案内は検査の選択条件ではない。`scripts/verification.json` の選択規則・製品の検査範囲は変更しない。
- 保守手順と必須規則の制約の追記先を領域別の正本へ改める。
  新しい制約ファイルが索引・領域別案内・容量検査から漏れないことと、リンク・行長・make の参照の整合を既存の `check-verification` で検査する。
- `docs/verification.md` の「自動検査」は本文を変えず、子見出しで読込単位を分ける。既存の見出しへのリンクは保つ。

## 情報の保全と未反映の指摘

元の制約の本文・UC 番号・ADR と監査への参照は分割先へ移し、相対リンクだけを直す。
古い監査の「当時は容量不足で足せなかった」という証拠は残し、対応を追記する。

- IQA-01 は既に ADR 0350 によるオープン拒否が制約に反映されている。古い不具合を現在の制約として足し直さない。
- DIA-01 は ADR 0365、DIA-02・04 は ADR 0346・0348 で対応済みで、残る通信と実機の制約も既存の記載を移す。
- DIA-09 は `Session::absorb_plugin_state` が現在の版だけを更新し、`Session::undo` が版を交換することを再照合した。
  無関係な編集の Undo でも背景保存の状態が戻る現行の制約をプラグインのファイルへ足す。
  過去の版へ合成するなどの挙動変更は行わない。既存の設計を変える判断はこの作業に含めない。

## 測定と確認

2026-11-15、開始時の HEAD と変更後の作業ツリーを比較する。

| 対象 | 前 | 後 |
|---|---|---|
| 全文を読む 4 文書の合計 | 43,997 B | 26,762 B |
| `docs/status.md` | 20,108 B | 2,570 B |
| 案内する資料の最大の節 | 11,894 B（検査手順「自動検査」） | 11,556 B（開発手順「モデルの項目表と変更セット」） |

開始時の全文読込を 17,235 B 減らし、上限まで 17,238 B の余裕を確保した。
これは UTF-8 のバイト数であり、実トークンの削減率や製品の性能の測定ではない。

`test_status_details_are_indexed_bounded_and_selected_by_area` は、分割前に制約ファイルがない固有のアサーションで失敗することを確かめた。
分割後は領域別案内・索引・容量検査への登録を確認する。
移動前の制約本文 112 行は、相対リンクを正規化して分割先と比較し、追加した DIA-09 の 2 行以外に欠落・重複・変更がないことを照合した。
製品コード・音声・機器の経路は変更せず、新しい実機確認項目や製品回帰は不要である。
診断の保存先やログの形式も変えず、既存の容量超過の表示と文書の整合検査を使う。
検査結果は従来どおり `target/verification/report.md` に記録する。
