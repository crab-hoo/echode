# 0199. ヘルパーの制御要求を所有し、応答を要求番号で照合する

- 日付: 2026-10-30
- 状態: 採用
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-01、SPG-06 の旧経路

## 背景

ヘルパーはメインスレッドへの 9 種類の操作に、種類番号と同じ入出力バイト列を使っていた。
保存が時間切れになってもメインスレッドでは実行が続き、次の復元の入力を保存の出力で上書きした。
親も種類だけで応答を選び、遅れた拒否を次の同種の操作へ返していた。
`slow-save` の実ヘルパーで、復元要求 `[128]` の代わりに保存結果 `[64]` が読み込まれることを修正前に再現した。

## 決定

### 制御スレッドとメインスレッド

`main_requests.rs` の `MainRequests` に、連番と入力・結果を所有する `MainCall` を置く。
入力は `MainRequest`、結果は `MainReply` とし、容量・パラメーター ID・文字・窓の報告を型のまま渡す。
種類番号、入出力共有のバイト列、別枠のパラメーター読取り結果、未知の種類を復元として扱う既定の腕を廃止する。

制御スレッドだけが要求を投入し、メインスレッドだけが取り出して完了する。
プラグインを呼ぶ間は mailbox のロックを保持しない。
投入待ち・実行中を合わせて 1 件だけを保持し、完了前の後続は明示的な busy エラーで拒否する。
音声スレッドはこの mailbox に触らず、従来の再起動・領域交換・パラメーター flush の RT 経路を保つ。

時間切れは実行の取消や巻戻しではなく、結果不明である。
呼出し側が離れても要求を保持し、完了はその要求へだけ書き込む。
前の要求が終わった後の新しい要求は、別の入力と結果を持つ。
音量等の変更も、先行するメインスレッド要求で busy の間は flush を投入しない。
再起動等の残りのアトミック全体を分割する作業は、この修正には含めない。

### 親とヘルパーの制御ソケット

制御フレームを「長さ・種類・64 bit 要求番号・本体」とする。
親は同じソケットの寿命内で 0 以外の番号を単調増加させ、ヘルパーはその番号を応答に写す。
起動時のポート情報と非同期通知は 0 とし、番号の枯渇は再利用せず拒否する。
状態・パラメーター・窓に加え、チェイン・FD 付きの領域交換と取消も同じ照合を使う。
この内部形式は保存形式ではなく、親とヘルパーは同じビルドの組で使用する。

親は処理中の番号だけを保持し、期限切れ・完了済みの応答を捨てる。
背景保存と同期保存は別の番号で回収し、古い背景保存を後で回収しても、新しい適用済み状態を上書きしない。
窓の寿命と Dirty・パラメーター・ショートカットの通知は、引き続き受信順で別に集める。
時間切れの要求は自動で再送しない。実行中のプラグイン自体を強制的に取消すものではない。

### 製品と回帰の通り道

エンジンのテスト専用だった `device_parameters`・`set_device_parameters`・`capture_device_state` を削除する。
回帰も製品のデバイスレーンと同じ `device_control_handle` の `PluginControl` を使う。
各公開操作を一つの汎用要求 API に置き換えることはせず、残りの SPG-06 は別の整理とする。

## 回帰と診断

- `audit_spg01_a_timed_out_save_does_not_replace_the_next_restore_bytes` を通常回帰へ移す。
  実ヘルパーの保存時間切れ、後続の安全な拒否または正しい復元、完了後の復元・保存・出力サンプルを検査する。
- `main_requests_tests.rs` は待機せず、実行中の置換拒否と古い完了の非干渉を検査する。
- `session_correlation_tests.rs` は実ソケットで遅れた応答・同種の背景保存・通知・適用済み状態を検査する。
  `Duration::ZERO` で親の期限を確定させ、時間の計測に依存しない。
- `control_tagged_tests.rs` は番号・FD の対応、短いヘッダの拒否、部分フレームの保持を検査する。
- 必須契約と反例は `scripts/verification.json` に登録し、既存の隔離回帰と RTSan も維持する。

時間切れにはメイン要求の番号と結果不明を、後続の拒否には busy を返す。
実機の期限・聴感と第三者プラグインの GUI の遅延は、自動回帰と区別してユーザーが確認する。
実機計測の `spike-isolation` は依頼がないため実行せず、過去の S3 の数値は更新しない。
