# 0049. 再生は CLAP をヘルパーへ通し、内蔵シンセの前に置く

- 日付: 2026-10-10
- 状態: 採用
- 項目: Phase 1 の CLAP 再生

## 背景

ADR 0048 は CLAP をトラックへ記録したが、製品の再生は内蔵の Sine Pad だけを鳴らしていた。ヘルパーは 1 つのプラグインを読み、サンプルレートは 48 kHz、処理バッファは 512 フレームに固定され、共有メモリのイベントは CLAP の `process` へ渡していなかった。

## 決定

- デバイス 1 つにつきヘルパー 1 つ。ヘルパーは今もプラグインを 1 つしか読まない。同じヘルパーで別のプラグインを段にする `SetChain` は、同じプラグインを繰り返す試験のまま残す
- 起動は制御スレッド。オーディオスレッドは、用意したバッファへ依頼し、そのブロックの長さを締め切りに 1 度だけ待つ。間に合わなければそのトラックのブロックは無音にする
- トラックの並びが同じならヘルパーは生かし、ノートだけの編集では起動し直さない。並びが変わったときだけ、制御スレッドが新しいヘルパーを渡し、古いものは制御スレッドで閉じる
- 最初のデバイスが楽器（スキャン結果の `instrument`）なら、内蔵シンセは鳴らさず、無音とノートを渡す。それ以外は内蔵シンセの音を入力にする。後段はその出力を聞く
- プラグインのステレオ出力は左右を平均してモノにし、今までどおりフェーダーでパンする。ステレオのまま混ぜるのはミキサー画面のとき
- ヘルパーは、共有メモリのフレーム数と、親が渡すサンプルレートで起動する。48 kHz と 512 フレームは試験の既定であり、プロトコルの上限ではない。入力イベントは CLAP の入力バッファへ写す。バッファは処理スレッドの開始時に一度確保し、ブロックごとに確保しない
- キャッシュに無い ID は飛ばし、内蔵シンセのままにする。再生の開始時にスキャンはしない

## 確認

- テスト用ゲインをエフェクトとして挿すと、内蔵シンセの出力が 2 倍になる。同じプラグインを楽器として扱うと、内蔵シンセは鳴らない
- 2026-10-10 の通常検査では、ヘルパーに 2 秒のハング検出用の期限を与え、1、7、8、14、28、64 フレームに分けても同じ音声の出力が一致することを確認する。音声そのもののブロック長への依存と、OS による締め切り超過を混ぜない。
- 製品の再生経路でのゲイン・楽器の置き換えと、8・16・32・64 フレームの比較は実時間の締め切りを使うため、通常検査から外し、`make spike-isolation` の release 検査に含める。製品の待機期限は変更しない。デバッグの全体検査で 8 フレーム（48 kHz で約 167 µs）の応答が間に合わず、その区間が無音となる失敗が 2 回あり、単独実行では通ったことから分離した。
