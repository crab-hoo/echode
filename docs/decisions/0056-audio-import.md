# ADR 0056: 音声素材は正準 PCM として保管し、固定クリップにする

- 日付: 2026-10-11
- 状態: 採用
- 範囲: Phase 1 の取り込みと再生。波形のピーク、タイムストレッチ、Ogg、Git への索引の収録は含まない

## 背景

中身の `audio` は識別子か null で、常に null だった。フェードを音に使う経路は、オーディオ参照ができてから接続すると [ADR 0022](0022-clip-content-and-placement.md) で決めてある。保管庫は BLAKE3-256 のオブジェクトを置けるが、音声ファイルに名前を付ける `media/index.json` はまだ作っていなかった（[ADR 0031](0031-content-addressed-store.md)）。

## 決定

音声ファイルは制御スレッドで AudioToolbox の `ExtAudioFile` により、ファイル自身のサンプルレートの浮動小数へデコードする。対応するのは WAV、AIFF、CAF、MP3、AAC、ALAC、FLAC である。Ogg は後のスライスに残す。チャンネルは 1 か 2 だけを受け、それ以外は拒否する。ステレオは再生前に左右を平均してモノラルにし、トラックのパンは今まで通りフェーダーで掛ける。

保管するバイト列は、元の圧縮データではなく正準 PCM である。先頭は `ECHDPCM1`、サンプルレート、チャンネル数、フレーム数で、続きはインターリーブしたリトルエンディアンの `f32` である。ファイル名は全体の BLAKE3-256 とする。同じ内容は同じオブジェクトで、既にあるオブジェクトは書き直さない。元のファイル名、形式、レート、長さは `media/index.json` にハッシュ順で書く。同じハッシュが既にあるときは最初の名前を残す。自動保存の Git ツリーは、これまで通り `project.json` と `contents/` と `tracks/` だけを含め、索引とオブジェクトはまだコミットしない。再生に必要なレートと長さは中身の JSON にある。

プロジェクトが記録するのはオブジェクトの識別子ではなく、ハッシュ、サンプルレート、チャンネル数、フレーム数である。パッケージの版は 3 にする。版 2 の音声欄が文字列のときは、ファイルを指していなかったので null に上げる。

置く操作 `audio.place` はジャーナルに残る。トラック、開始 tick、ハッシュ、レート、チャンネル、フレームを受け、固定クリップと中身を作る。長さはファイルの時間からテンポで tick に直す。オフセットは 0、ゲインは 1、フェードは既定の 5 ミリ秒である。既存の配置と重なれば拒否する。

取り込む操作 `audio.import` はホストだけが実行する。パスはジャーナルに残さない。先にオブジェクトを書いてから `audio.place` する。配置に失敗しても、書いたオブジェクトは残す。

再生のコールバックはファイルを読まず、サンプルレート変換もしない。制御スレッドが PCM を読み、デバイスレートへ rubato で変換し、配置の範囲とオフセットで切り、フェード長をサンプル数にして計画へ載せる。オブジェクトが読めないときは再生を止める。フェード 0 はその端を減衰しない。既存の 5 ミリ秒の継ぎ目フェードは、クリップ側の関数とは別に残す。

アプリのファイル一覧では、対応する拡張子を選んだトラックの再生位置へ取り込む。この編集は Undo が増える。

## 結果

WAV の取り込み、同じ内容の二重書き込みの省略、索引の最初の名前、パッケージの版 3、ランダム操作への `audio.place` を検査する。製品の再生は、ブロック長 1、7、64、512 で同じクリップ出力になる。Swift は画面を開かず、取り込みがクリップを置き Undo で戻ることを確認する。画面での操作確認は未実施である。

波形のピークは [ADR 0058](0058-waveform-peaks.md) で CPU のキャッシュにした。ディスク先読み、可変速、Ogg、索引の Git 収録は今回含めない。

## 保存済み PCM の有限性の検証（2026-10-29）

`af9e34a` を基準に、通常の音声取込みと保存済みオブジェクトの検証が食い違うことを確認した。
`AudioFileReader::read` は非有限値を拒否するが、`read_pcm` は長さとヘッダが正しければ NaN・無限大を返していた。
正しい BLAKE3 ハッシュはバイト列の同一性を示すだけで、サンプルの妥当性を保証しない。

- `decode_pcm` は、サンプルを復号する既存のループ内で有限性を検査する。
  非有限値を 1 つでも含めば、取込みと同じ `audio contains a non-finite sample` を返す。
  0 への置換や原本の修復は行わず、有限値は符号付き 0・非正規化数・振幅 1 を超える値もビットを保つ。
- 検証は制御側の全読込みに置き、SRC とトリムより前に素材全体を拒否する。
  コールバック・保存形式・ハッシュ・依存ライブラリは変えない。
  既存の素材準備も使用するサンプルの有限性を検査しており、今回の再現を実機出力への非有限値の到達証拠とは扱わない。
- `pcm_validation.rs` は公開 `read_pcm` と製品の `load_placed_clips` を使う。
  モノラル・ステレオの各位置、符号とペイロードの異なる NaN・正負の無限大、トリム外の異常と異なる出力レート、原本保持を検査する。
  有限値のビット一致も同じ必須契約に含める。
- 修正前の公開読込みは終了コード 101 と `canonical PCM must reject non-finite samples` で失敗した。
  作業時のログは `target/focused-checks/pcm-validation-red/` に保存した。
  debug / release の通常回帰に加え、検証を外す負の対照付きのテストを `canonical-pcm-validation` の必須契約へ登録する。
- 最初の `make verify` は ASan の既存の `full_source_sharing_still_rejects_nonfinite_placement_samples` で止まった。
  メモリ診断ではなく、末尾 NaN を切り落とした場合の旧成功期待との不一致である。
  保存済み素材の全体拒否に合わせて期待値を更新し、`placed_plane` 単体では全体共有・コピー・ゲインの桁あふれの検証を残す。
  下位の配置処理で有限の部分を切り出せることと、未検証の保存素材を製品で受け入れることを区別する。
  当時の検査ログは `target/bridge/address/audio-rust-tests.failed.log` に保存した。

波形キャッシュがある時のマップ読込みと、ピーク計算内で非有限値を飛ばす規則は変更しない（[ADR 0058](0058-waveform-peaks.md)）。
キャッシュなしでは全読込みのエラーにより波形を生成しない。
実機・聴感・性能は今回の自動回帰の保証範囲ではない。

## 外部音声の一括復号と取込みの検証（2026-10-29）

`fd7bb5f` を基準に、NaN を含む IEEE float WAV の `import_audio` が成功することを再現した。
先の節で有限性を確認した外部復号は `AudioFileReader::read` の逐次経路であり、
一括の `decode_audio_file` と取込みが使う `decode_file` には同じ検証がなかった。
そのため、取込み成功後に保存済み PCM の読込みで拒否される、不整合な素材を作れていた。

- 一括復号は、実際に読めたサンプルの全体を有限性検証してから返す。
  NaN・正負の無限大は逐次復号と同じエラーにし、保管庫・索引・ピーク・除外規則を書き始める前に拒否する。
- 有限値は符号付き 0・非正規化数・振幅 1 を超える値もそのまま保つ。
  原本の置換・既存の不正素材の修復・保存形式の変更は行わない。
- `audio_import_validation.rs` はモノラル・ステレオの先頭・中間・最終サンプルと読込み単位をまたぐ WAV を通す。
  公開の取込み・一括復号・逐次復号を比較し、空および既存素材のあるパッケージと原本のバイト保持を検査する。
  `DocumentHost` の一括編集失敗時の巻戻し・Undo / Redo・再オープン、有限値の保存往復・重複取込み・取消も含める。
- 修正前は終了コード 101 と `audio import must reject non-finite samples before writing` で失敗した。
  作業時のログは `target/focused-checks/audio-import-validation-red/` に保存した。
  検証を外す負の対照付きの必須契約 `audio-import-validation` に登録する。

機器を開く前の制御側の検証であり、再生 DSP・実機出力・聴感・性能の保証範囲は変えない。
