# ADR 0091: 停止中のプレイヘッドを描く

- 日付: 2026-10-14
- 状態: 採用
- 範囲: アレンジとピアノロールのプレイヘッド。監査 CU-01（以前の候補 C-01）

## 背景

再生位置の数値は 50 ms の状態ポーリングで更新される。描画側の `PlaybackFeed` は文書の同一性だけで等しく、再生・一時停止・停止・位置移動では差し替わらない。停止中は表示リンクが休止するので、同じ feed を渡しただけではオレンジの縦線が残る。再生中も、休止したリンクはライブ位置を読まない。

位置ポーリングでワークスペースを作り直すと、ADR 0053 が禁じた再描画になる。停止中に連続描画へ戻すと、症状は隠れるが電池を使う。

## 決定

feed の差し替えと、その feed の再生状態・位置の変化は別である。`ProjectController` は再生、一時停止、停止、位置移動が成功したときだけ世代を増やす。ループ、メトロノーム、出力、再確認、状態のポーリングでは増やさない。文書を開く、閉じるときは世代を 0 に戻す。

アレンジとピアノロールは、その世代が変わったときだけ描画要求の版を上げる。同じ feed を渡しても版は変わらない。表示リンクは描画スレッドで作り、その run loop に登録する。版の更新と休止解除もその run loop 上で行う。停止中のフレームが要求された版を描いたら、リンクは再び休止する。再生中は休止せず、毎フレームが共有メモリの位置を読む。コールバックが受け取った drawable は、描くフレームが無くても提出する。提出しないと、その後の再生も位置移動もフレームを受け取れない。休止フラグは値が変わるときだけ書く。同じ値を毎回書くと、次の垂直同期が落ちる。

破棄したビューはレンダラーを持たない。世代の通知はそれを起こさない。文書の切り替え、ペインを開き直したあと、計画を差し替えたあとは、今あるビューだけが次の世代を受ける。

`spike-app` の合格条件（フレーム数、メインスレッド外、メイン処理中のフレーム）は変えない。同じ計測に、画面とウインドウの状態、描画スレッドの休止、`continuous`、版、コールバック数、休止解除の回数を残す。合格なら正常、画面が無い・消灯・非表示・遮蔽でコールバックも少ないなら環境条件不足、それ以外の未達は失敗である。

## 結果

実ウインドウの回帰は `make spike-playhead` に置く（[ADR 0092](0092-playhead-spike.md)）。`make check` に残すのは世代と操作結果だけである。`beginMeasurement()` は呼ばない。停止してリンクが休止したあと、0 拍から 2 拍への移動を両画面の描かれた位置で確認する。再生は、進んだライブ位置を描く。破棄したビューは起こさない。`spike-app` の合格条件は変えない。
