# ADR 0143: ブラウザの一覧を押した時点で選択し、試聴の各段の時刻を残す

- 日付: 2026-10-22
- 状態: 採用。[ADR 0135](0135-sample-audition.md) の「UI はブラウザの選択に従う」と診断を改める。
  UIF-05 の①・UIF-09・UIF-10 の対応（[照合](../reviews/2026-10-21-ui-feedback-audit.md#修正の進め方)）。実画面の操作感と聴感はユーザー確認待ち
- 範囲: 共通サンプルブラウザの一覧の入力、選択の変化と試聴の要求、試聴の要求ごとの記録と `make debug-report`

## 背景と再現

ユーザーの報告は次の 3 つである（[照合](../reviews/2026-10-21-ui-feedback-audit.md)）。

- クリックでの試聴は、ファイルの長さに関わらず一定の遅れがある。上下矢印キーの選択では遅れない（UIF-05）。
- 一覧をクリックしてもキーボードのフォーカスがアレンジに残る（UIF-09）。
- 停止中に、同じサンプルが頭から最後まで鳴り、また頭から鳴った（UIF-10、再現なし）。

一覧は SwiftUI の `List(selection:)` で、各行に `onTapGesture(count: 2)` を付けて配置を受けていた。
矢印キーとクリックは同じ `onChange(of: browser.selection)` から試聴へ進むため、違いは行のタップの認識だけである。
SwiftUI の一覧をテスト内のウィンドウへ載せて合成したクリックを送る一時テストは、認識の有無に関わらず選択を変えなかった
（テストのプロセスではウィンドウがキーにならない）。このため SwiftUI のままでは、クリックの経路を製品と同じ形で回帰に持てない。

試聴の要求は、ブラウザの選択の変化すべて（検索語の変更・再走査・登録解除による `preservedSelection` の付け替えを含む）で送っていた。
報告番号・段階は 1 件分だけで時刻を持たず、遅れた段も、同じパスへの要求が何で起きたかも区別できなかった。

## 決定

### 一覧は AppKit の表で、押した時点で選択する

- 一覧を `NSTableView`（`FileListTable`）に置き換え、SwiftUI からは `SampleFileList` で包む。
- `mouseDown` で、表を最初のレスポンダーにし、押した行をその場で選択する。ダブルクリックかを待たない。
  2 回目のクリック（`clickCount == 2`）だけが行を開く。行の外を押すと選択を外す。
- Return とテンキーの Enter（修飾キーなし）は選択中の行を開く。矢印キーと名前の入力による選択は表の標準の動作に任せ、キー入力として記録する。
- 開く操作は `WorkspaceSession.openInBrowser` にまとめる。音声は配置、`.echode` は開く、フォルダは移動する（[ADR 0122](0122-sample-library-search-and-placement.md) と同じ）。
- プラグイン候補とコマンドパレットの一覧にも同じ `onTapGesture(count: 2)` が残る。報告はブラウザだけのため、この ADR では変えない。

### 試聴は利用者のクリックとキーだけで変わる

- 表の選択の変化は、そのクリックかキーと一緒に `WorkspaceSession.chooseInBrowser` へ届き、ここだけが選択の変更と試聴の要求を行う。
  選択が変わらなければ要求しない。
- ブラウザ自身の付け替え（検索語の変更、再走査、登録解除、フォルダの移動による選択の解除）は表へ反映するだけで、試聴を始めも止めもしない。
  鳴っている音は自然に終わるまで続く。利用者が選んでいない素材が鳴ることを避け、UIF-10 の候補の経路を閉じる。
- フォルダ・プロジェクト・非音声・利用者による選択の解除で止める扱いは [ADR 0135](0135-sample-audition.md) のままである。

### 要求ごとに入力と各段の時刻を残す

- 要求には操作の種類（`click` / `key` / `other`）と、入力イベントから要求までのマイクロ秒を添える。
  遅れは `NSEvent.timestamp` と同じ起動後の時計で画面が測る。C ABI は `echode_document_audition` の `input` と `input_delay_us`。
- 試聴スレッドは直近 32 件の要求を `AuditionReport.history` に持つ。件数は診断の記録の上限であり、要求やファイルの数の上限ではない。
  各件は番号・パス・操作の種類・受付の時刻（Unix ミリ秒）・最後の段階と、要求からの経過（マイクロ秒、ホストの時計）を持つ。
  - スレッドが受け取った（`picked_us`）、復号の完了（`decoded_us`、素材のフレーム数とレート）、
    出力の準備（`output_us`、開き直したか）、機器レートの平面の完成（`converted_us`）、コールバックへの受渡し（`handed_us`）。
  - 発音（`heard_us`）は、その音を採用したブロックの HAL の出力時刻である。コールバックは採用した音の番号と出力時刻を
    単一生産者のリングへ置くだけで、確保・ロック・待機をしない。試聴スレッドが出力の点検のたびに読み、ナノ秒へ換算する。
  - 新しい要求が来た時に読込み中だった要求は `superseded` とする。最新の要求がこの段階になることはない。
- 画面は、これ以上記録が増えない要求（発音済み・終了・停止・失敗・置換、または最新でなくなったもの）を 1 回ずつ
  `~/Library/Logs/Echode/audition.ndjson` へ 1 行の JSON として追記する。1 MiB を超えると `audition.1.ndjson` へ移し、1 世代だけ残す。
  書き出しはアプリの起動時に `ProjectController.keepAuditionLog` を呼んだ時だけで、テストとツールは書かない。
- `make debug-report` はこの 2 つのファイルを `app-logs/` へ末尾 2 MiB まで写す。リンクはたどらない。
  素材のパスを含むため、共有前に確認するよう案内する。

## 検査

- 必須契約 `sample-browser-click-ui`: 実際の表へ合成したクリックとキーを送り、単クリックがその場で選択・フォーカス移動・要求 1 回を行い、
  ダブルクリックと Return だけが配置し（Undo 1 回ずつ）、検索による付け替えと、フォルダへの移動による解除が要求を出さないことを確認する。
  負の対照は、選択を 2 回目のクリックまで遅らせると失敗する。
- `echode-audio-io` の回帰で、各段の時刻がそろって順に並ぶこと、操作の種類と遅れの保持、出力を開き直したかの区別、
  保留した要求の `superseded`、停止の記録、記録の件数の上限、`requested` を JSON に出さないことを確認する。
  コールバックが 1 ブロックより短い音も一度だけ記録し、HAL の時刻がなければ時刻を空にすることを RTSan 下で確認する。
- FFI と Swift ブリッジは、入力の受渡しと未知の値の拒否、履歴の復号を確認する。
  `AuditionLog` は 1 件 1 回の書出し・最新の待ち・文書の切替・ファイルの世代交代を確認する。

## 未確認と残る範囲

- 実画面でクリックの遅れとフォーカスの移動が直ったか、表の見た目が従来の一覧と同等かはユーザー確認を待つ。
- 遅れの量はまだ測っていない。ユーザーの環境での記録（`app-logs/`）から段ごとの時間を読む。
- UIF-10 の原因は未確定のままである。再発時は記録の操作の種類と時刻で、利用者の操作か、それ以外の要求かを区別する。
- 先頭から読みながら鳴らす・波形・出力の常駐・音量などの試聴の操作（UIF-05 の②〜④・UIF-07）は後続の単位で扱う。
