# 0351. CLAP のタイマーをインスタンスの主スレッドで管理する

- 日付: 2026-11-14
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: P2-03・FCA-07 の `clap.timer-support`

## 背景

`thread-check` と `log` の後も、定期的な主スレッドの通知を求める `timer-support` は未接続だった。
再生ブロックや窓の有無に頼らず通知し、通知中の登録・解除とヘルパーの破棄を安全に扱う必要がある。
これは音声時計ではなく、主スレッドの定期処理のための拡張である。

## 比べた案と決定

- **処理スレッドで時刻を見て主スレッドへ送る**: 不採用。
  停止中の通知がブロックの到着に依存し、音声経路へ不要な時計と通信を足す。
- **タイマーごとに CoreFoundation のタイマーとコールバックの所有を持つ**: 不採用。
  登録表のほかに OS オブジェクトと文脈の寿命を管理する必要がある。
  今のヘルパーのイベントループ内で通知する要件には、既存の待ちを期限で短くする方が単純である。
- **主スレッドの handler に登録表を持ち、既存ループが期限で待つ**: 採用。
  `Instant` の期限のうち最も早いものと既存の 50 ms の小さい方まで待つ。
  登録がなければ既存の待ちを保ち、窓や音声のブロックがなくても通知する。
  登録表はインスタンスとともに破棄され、終了後に呼ぶ OS コールバックは作らない。

タイマーの個数に独自の上限を置かない。
ID は CLAP の範囲内で単調に払い出し、無効値 `u32::MAX` に達したら登録を拒否する。
解除済み ID を再利用しないため、通知の一覧に残った古い ID を新しい登録と取り違えない。
0 ms・null の出力・主スレッド以外の呼出しは拒否し、失敗時は出力 ID を書き換えない。

1 回のループで、期限を過ぎた各登録を最大 1 回だけ通知する。
遅れた周期を連続で取り戻さず、そのループの時刻から次の期限を置く。
一覧を取った後にも登録の存在を調べ、先の callback が解除した後続は呼ばない。
登録表の借用はプラグインを呼ぶ前に解放し、callback 自身の解除・別の解除・追加を許す。
callback 中の新規登録は次のループ以降に通知する。

主スレッドが遅い処理やプラグインの入れ子のモーダルループに入る間、通知は遅れ得る。
正確な周期・サンプル位置・実機の締め切りは保証しない。
主ループを持たない比較用の inert host では拡張を公開しない。
プロセスの境界・保存形式・C ABI・依存は変えない。

## 回帰と基盤

製品のヘルパーで初期化時に登録する検査用の `timer-support` fault を足した。
修正前は終了コード 101 と `timer-support extension is unavailable` を照合した。
証拠は `target/focused-checks/timer-support-red/` である。

`isolation/timer_support.rs` は停止中・窓なしの主スレッド通知、自己解除・後続の解除・callback 中の追加、反復を実ヘルパーで確認する。
補助スレッドと音声スレッドからの誤った登録・解除は拒否されることも調べる。
1・32・127・256 フレームの処理と、状態に記録する失敗ビットで音声と通知の境界を確認する。
`under_rtsan` の名前で既存の全体検査にも含めるが、RTSan 自体は今回の作業では実行しない。

`plugin_timers_tests.rs` は時刻を引数で進め、早過ぎる通知・遅延後の追付き・ID の枯渇・最大周期・インスタンスの独立を検証する。
実時間の精度や性能の比較計測はしていない。
既存の隔離回帰の入口と検査選択を使い、新しい検査コマンド・制御フレーム・fuzz の入口は足さない。
設計書・P2-03・監査の現在欄・診断手順を更新し、第三者の窓と周期の互換性は UC-82 としてユーザー確認へ分ける。
`tail`・`audio-ports`・`note-ports` のホスト側の残りを完了扱いしない。
