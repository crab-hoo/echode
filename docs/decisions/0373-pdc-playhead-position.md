# ADR 0373: PDC の再生ヘッドを処理の時計から分ける

- 日付: 2026-11-15
- 状態: 現行
- 領域: 音声エンジン・書き出し
- 関連: [ADR 0339](0339-plugin-delay-compensation.md)、[ADR 0155](0155-remembered-playback-start.md)、[ADR 0330](0330-playing-edit-media-and-tempo-retime.md)、[P2-03](../phase2.md#p2-03-ルーティングフォルダバスpdc)

## 背景と再現

PDC はマスターを最遅の経路だけ遅らせるが、再生ヘッドは先を処理する時計の tick を表示していた。
製品の再生器と別プロセスの `delay:37` を通す回帰では、開始から 1 フレームで表示が 29 tick へ進み、期待する 0 tick と異なった（48 kHz・既定テンポ）。
音声の 20 番目のサンプルのインパルスは 57 番目に出る。
処理の時計を表示のために戻すと、次のノート・素材・計画の追越しが変わるため、表示だけを補正する。

## 比べた案と決定

- **生のサンプル位置から遅延を引く**: ループの初回進入で原点前へ戻り、遅延がループより長い場合の周回数も失うため採らない。
- **遅延分の位置の履歴を蓄える**: 任意の軌跡を表せるが、遅延に比例する領域と、計画交換時の履歴の受渡しが増えるため採らない。
- **連続する軌跡の原点と処理済みフレーム数を持つ**: これを採る。
  原点から `max(処理済みフレーム数 - 最後のブロックの遅延, 0)` だけ進め、初回のループ終端までと、それ以降の剰余を整数で計算する。
  トラック数・遅延長・周回数に依存する記憶領域や走査を追加しない。

`PlaybackStatus::sample`・`tick` は処理の位置のまま保つ。
別の `playhead_tick` を同じ世代の状態として公開し、セッションの状態と文書の位置通知はこれを読む。
公開する C ABI・JSON の形・保存形式は変えない。
制御側の再開・計画の準備・出力の再構成には従来の処理位置を使い、二重に補正しない。

## 不連続点と停止

- 位置移動・停止での巻戻し・ループ範囲の採用は新しい軌跡を始める。
  その音がマスターへ到達するまでは新しい原点を表示し、原点前へ戻らない。
  ループ変更の前の音や余韻には、別の表示位置を付けない。
- 同じループとテンポの計画交換では原点と経過を保つ。
  遅延が変わると、そのブロックの音と同じく表示も変化分だけ繰り返すか飛ぶ。
- 一時停止・ライブの停止フェード・停止中のプラグイン処理では、表示を最後の位置に保つ。
  再開は経過を引き継ぎ、停止中に採用した遅延だけで表示を動かさない。
  新しい位置へ巻き戻す停止では、従来どおりその位置をすぐ表示する。
- テンポ編集が処理の時計を移す時は、新しいサンプル位置を原点にする。
  tick への変換は、処理と同じ採用済みのテンポ索引を使う。

## 回帰と基盤

実ヘルパーの波形と表示は `hosted_playback/compensation.rs` で 1・7・64・512 フレームに分けて比較する。
37 フレームの遅延・インパルスの到着位置・ループの折返し・16 → 48 フレームへの変更を通す。
`playback_playhead_tests.rs` は、初回進入・ループより長い遅延・終端以降の開始・負の位置・整数境界を、1 サンプルずつ進めた履歴と照合する。
ライブの一時停止・再開・位置移動・巻戻し・計画交換・テンポ編集も製品のコールバックを通す。
`session_playhead_tests.rs` は機器なしのセッションに同じ実ヘルパーを接続し、状態・文書の位置通知と処理の時計が別であることを照合する。
位置移動の後はヘルパーの後片付けを状態で待ってから比較し、固定回数のコールバックで準備完了と扱わない。
新しいコールバック処理も既存の確保禁止ガード内に置き、RTSan 対象の回帰に含める。
新しい検査コマンドや選択条件は不要で、既存の Rust 通常検査がこれらの回帰を選ぶ。

設計・現在の制約・P2-03 の進捗と、診断時に区別する 2 つの位置を更新する。
実画面と聴感の確認は UC-89 とする。
HAL の物理的な出力遅延・描画の更新間隔はこの補正の対象外で、段ごとのノートと transport の PDC 補正も残る。
