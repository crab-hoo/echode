# ADR 0081: ブロックのイベントは作業領域で整列する

- 日付: 2026-10-14
- 状態: 採用
- 範囲: 監査 PRO-09。1 ブロックのイベント整列

## 背景

ADR 0063 は、音声スレッドがヒープを使わないように、比較が小さいときだけ隣と入れ替える整列にした。同じキーは書かれた順のまま残る。逆順では比較回数が件数の二乗になり、同時刻・逆トラック順の 8,000 件は 270 ms で、128 フレーム・48 kHz の 2.667 ms を超えた（監査 PRO-09）。

## 決定

整列は標準ライブラリのインプレース整列を使い、元の位置を最後のキーにする。音楽上のキーが同じイベントは、書かれた順のまま残る。比較は時刻、種別、トラック、ポート、チャンネル、音高、ノート番号、式の種別、パラメータ番号で、ベロシティやパラメータ値では分けない。

作業用の番号列とイベント列は、制御スレッドがイベント用バッファと一緒に用意する。音声スレッドはその領域が足りなければ何も動かさず、バッファ不足として返す。番号の型は `usize` で、件数に固定の上限は置かない。

再生のイベント用バッファは、整列のあとでトラックごとに使う列を作業領域にする。オフラインの書き出しは、トラックへ振り分ける前の列を同じ用途にする。計画をその場で作る `schedule` だけは、呼び出し側が音声スレッドではないので、作業領域をその場で用意する。

## 結果

逆順、同時刻、同じキーの並び、複数トラックの製品経路は、整列の前後で順序が保たれる。1,000 件の整列は、確保検出を有効にしたコールバックで停止しない。release の 3 回中央値は、同時刻・逆トラック順の 1,000 / 2,000 / 4,000 / 8,000 件で 21 / 42 / 83 / 163 µs だった。128 フレーム・48 kHz の 2.667 ms より短い。64 トラックが同時に発音する 1 ブロックの製品経路は 19 µs だった。時間の閾値は無視した計測にだけ置く。画面での操作確認は未実施である。
