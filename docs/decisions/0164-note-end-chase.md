# ADR 0164: ノートの終端ちょうどから再生する時、そのノートを追いかけて鳴らさない

- 日付: 2026-10-25
- 状態: 採用。[2026-10-25 の操作の報告](../reviews/2026-10-25-user-feedback.md) の FB-06 への対応。実機の聴感はユーザー確認待ち
- 関連: [ADR 0099](0099-transport-plugin-state.md)、[ADR 0133](0133-stopped-plugin-processing-and-edit-input.md)、
  [ADR 0155](0155-remembered-playback-start.md)

## 背景と再現

ノートの端から再生を始めると、その音が鳴り続けることがあると報告された。
ルーラーはグリッドに吸着するため、開始位置がノートの終端と一致しやすい。

再生の開始・位置移動では、カーソルが開始位置にかかるノートを鳴っている集合へ入れ（追いかけ）、
楽器が途中から鳴るようにそのノートのノートオンを送る。
集合は `on < 開始位置 && off >= 開始位置` で選び、終端がちょうど開始位置のノートも含めていた。
同じブロックでそのノートのノートオフも開始位置の時刻に出る。
同じ時刻ではノートオフをノートオンより先に並べる規則のため、楽器にはオフ→オンの順で届き、ノートが鳴り続けた。

実ヘルパーの楽器（`tail_player`）で、2 拍のノートの終端へ位置移動・停止の復帰をしてから再生する回帰を先に追加した。
修正前はブロック長 7 の最初の組合せで出力が無音にならず、余韻の分を過ぎても鳴り続けた。
証拠は `target/note-edge-hold-repro.log` に置く。

## 決定

- 終端がちょうど開始位置のノートは、追いかけのノートオンを送らない。終わったノートであり、楽器に新しく鳴らすものではない。
- 鳴っている集合からは外さない。その時刻のノートオフは従来どおり出る。
  毎ブロック新しいカーソルで予定を作る `schedule` と、ブロック長を変えて比べる検査が、ブロックの境界にかかる終端のノートオフをこれで受け取る。
- 計画の交換（`release_replaced`）とループの継ぎ目の規則は変えない。どちらも追いかけのノートオンを送らない。
- 開始位置にちょうど始まるノートは従来どおり、追いかけではなく通常のノートオンで鳴らす。

## 検査

- 必須契約 `note-end-start` は、実ヘルパーの楽器・FX・連鎖とブロック長 7・64・512 で、
  ノートの終端への位置移動と停止の復帰から再生した出力が余韻の分を過ぎても無音のままであることを確認する。
  RTSan の対象である。反例は終端の判定を外す。
- `echode-realtime` の単体テストで、終端の 1 サンプル前からは追いかけて鳴らし、終端ちょうどでは鳴らさず、どちらもノートオフが 1 回出ることを確認する。
- ブロック長比較（`block_size.rs`）は既存の検査で変化がない。音を作る処理の追加ではないため、新しい比較は足さない。
