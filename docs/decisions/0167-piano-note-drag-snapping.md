# ADR 0167: ピアノロールの単一ノートのドラッグで Shift による吸着解除を接続する

- 日付: 2026-10-26
- 状態: 採用。実画面の操作感はユーザー確認待ち
- 範囲: 単一ノートの移動・左右端の伸縮と、解放時の確定

## 背景と再現

[操作要件](../interaction-design.md#ノートの入力) と [ADR 0117](0117-workflow-interactions.md) は、
移動・伸縮を通常グリッドへ吸着し、Shift の間だけ吸着を解除する。
既存の `PianoGesture.preview` は常に吸着し、左右端の伸縮もグリッド幅未満にできなかった。
`PianoGridView` は解放時の座標・修飾キーを読まず、最後に描いたプレビューを確定していた。

`309d28e` に回帰を追加し、実 View へ合成した押下・ドラッグ・解放で再現した。
開始 1.1 拍・長さ 0.7 拍のノートを Shift で動かしても 1.25 拍へ吸着し、
右端を長さ 0.1 拍へ縮めても 0.25 拍で止まった。
期待した失敗の終了コードと固有のアサーションは `target/focused-checks/piano-shift-red/` に記録した。

## 決定

- ドラッグのプレビューへ吸着の有無を渡す。Shift がなければ従来どおり、開始位置または動く端の絶対時刻を吸着する。
  移動量だけを丸めて、グリッド間のずれを残す実装にはしない。
- Shift の間は時刻を tick 単位で動かす。移動は長さを保ち、左端の伸縮は反対端を保つ。
  伸縮の最短長は 1 tick、開始位置は 0 以上、音高は MIDI の範囲内とする。
- 解放時はそのイベントの座標と Shift の状態で計算し直す。
  ドラッグ中に確定せず、変更がある時だけ `onEdit` から既存の `note.edit` を 1 回送る。
  押下と解放だけでは、グリッド間にある既存ノートを丸めない。
- Escape・フォーカス喪失・処理中への移行・入力取消・終了では、従来どおり下書きを捨てる。
- 不正な幾何、非有限の座標、時刻の桁あふれはプレビューを返さない。
  音高の大きな移動は整数変換の前に範囲へ収める。
- アクション・保存形式・音声処理は変えず、ID・ベロシティと既存の Undo / Redo を保持する。

複数ノートの選択・一括編集、記憶する入力長、新規ドラッグ追加、試聴は別の実装単位である。
Return は [ADR 0155](0155-remembered-playback-start.md) の既存挿入との衝突についての判断待ちを維持する。

## 受入と基盤

- `PianoDragTests` の必須契約 `piano-note-drag-ui` は実 View の移動・両端を通し、
  解放時の Shift 切替、グリッド未満の伸縮、単一 Undo / Redo・保存再読込と ID・ベロシティ保持を確認する。
- 同じテスト群で、クリックだけ・取消後の解放が編集しないこと、解放時の座標を使うことを確認する。
  幾何の境界は、時刻 0、最短 1 tick、音高の上下端、ズーム、非有限値と桁あふれを検査する。
- 必須契約は `scripts/verification.json` と選択の回帰へ登録する。
  吸着解除を無視する、古いプレビューを確定する、最短長をグリッド幅へ戻す、の 3 つを負の対照とする。
  既存の `check-shell` / `check-product-contracts` が新しいテストを実行し、新しい Makefile 入口は不要である。
- [デバッグ手順](../debugging.md#ui描画入力履歴mcp) に入力と幾何の切り分けを追加する。
  新しい出力・外部入力・ログ形式はなく、`doctor` と `debug-report` の収集範囲は変更しない。
- 機器とウィンドウを開かない回帰を先に使う。実画面の Shift 操作・ドラッグの見え方はユーザー担当である。
