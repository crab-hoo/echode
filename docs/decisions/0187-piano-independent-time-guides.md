# ADR 0187: 吸着幅と独立したピアノロールの時間目印

- 日付: 2026-10-28
- 状態: 採用。P2-07 の先行分。実画面の見やすさはユーザー確認待ち
- 関連: [ADR 0185](0185-piano-auto-and-fixed-grid.md)、[ADR 0186](0186-piano-triplet-and-dotted-grids.md)、
  [操作要件](../interaction-design.md#構成を考えながら入力する)

## 背景と再現

開始時の HEAD は `4f639ac`。ノート領域の縦線を、間引いた吸着グリッドだけから生成していた。
全音符の固定幅では拍の線が消え、三連符・付点の粗い幅や縮小時には既存の 4 拍ごとの強線も欠けた。
ルーラーの数字とノート領域の時間目印が食い違い、入力位置の見当を付けにくかった。

製品の `PianoFrame.gridInstances` を倍率 1・2 で調べる回帰を先に追加し、
原点 3.3 拍・8 pt/拍・全音符固定で 5 拍目の線がないことを確認した。
期待終了コード 1 と固有のアサーションの照合は `target/focused-checks/piano-time-guides-red/` に記録する。
このパスはローカルの一時ログであり、永続的な証拠の参照先ではない。

## 決定

- 吸着幅の細分線と独立して、曲の先頭を基準に毎拍の線と 4 拍ごとの強線を描く。
  4 拍の基準と色は既存の表示を引き継ぐ。可変拍子や拍子マーカーの実装ではない。
- `gridTicks` は従来どおり、吸着幅から作る表示用の間引いた tick 列とする。
  `gridLineTicks` は独立した時間目印を合わせ、細分線・拍・4 拍の順に描く列とする。
  同じ tick は一度だけ描き、近接する細分線が強線を上書きしない。
- 両列は共通の可視範囲生成を使い、処理と記憶量を表示幅に限定する。
  カメラの最小倍率は既存の 8 pt/拍で、拍の目印は細分線を間引いても残す。
- 追加の線は入力先ではない。吸着、Shift、入力長、矢印、ルーラーの要求値を変えない。
  カメラ、モデル、アクション、Undo、保存形式、音声処理は変更しない。

## 受入と基盤

- `piano-time-guides-ui` は製品描画フレームで、粗い通常・三連符・付点、縮小した細かい幅、
  強線の色と描画順、同位置の重複排除、吸着幅の不変を確認する。
  独立した目印の欠落・重複排除の欠落・強線の描画順の逆転を負の対照にする。
- 通常回帰は全グリッド候補・倍率・スクロール位置を変え、曲の先頭からの位相、可視範囲、
  表示幅に限定した件数、非有限値の拒否を確認する。
  既存のグリッド回帰は、吸着由来の列と実際に描く列を区別する。
- `spike-piano-frame` は既存ケースを残し、粗い幅と最小倍率の GPU 読戻しを加える。
  `checkedIndependentGuides` は吸着由来の列にはない拍・4 拍の目印を採取した件数とする。
- Makefile の既存入口、検査登録と選択回帰、利用手順・現状・Phase 2・領域設計・デバッグ手順を更新する。
  レポートには目印の採取件数だけを追加し、保存先は変えない。
  `doctor` の鮮度対象と `debug-report` の JSON 収集範囲は既存のままで有効である。
- 作業中の製品契約全体は 1800 秒で時間切れとなった。新規契約を含む個別の期待値の失敗はなかった。
  同じ入力で完了済みの契約と負の対照を再利用して残りを再実行し、予算・対象・合否基準は変えない。
  TSan 全体で既知のデバイス準備の応答待ちも再発した。競合診断はなく、同じバイナリの単独実行では再現しなかった。
  証拠と切分けは [デバッグ手順](../debugging.md#ビルド環境検査基盤) に残し、原因解消とは扱わない。
- 音を作る処理とアクションは増えず、ブロック長比較とランダム操作生成の追加は不要である。
  実画面での線の見やすさはユーザー確認に残し、機器・ウィンドウを使わない検査と区別する。
