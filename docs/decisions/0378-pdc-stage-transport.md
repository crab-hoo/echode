# ADR 0378: 各プラグイン段の曲時刻を入力音声へ揃える

- 日付: 2026-11-15
- 状態: 現行
- 領域: 音声エンジン・書き出し
- 置換: [ADR 0358](0358-product-musical-transport.md) の全段へ同じ曲位置を配る判断。時刻の生成・停止・容量の規則は維持する
- 関連: [ADR 0340](0340-latency-graph.md)、[ADR 0373](0373-pdc-playhead-position.md)、P2-03

## 問題と再現

開始時の HEAD は `cc52d93`。
音声はフォルダの合流を含めて PDC で揃うが、後段のテンポ同期 FX にも処理先頭の曲位置を渡していた。
前段に遅延があると、入力音声の拍と FX の曲時刻がずれる。

実ヘルパーの `hosted_playback/transport.rs` に、子の 37 サンプルの遅延、子と親の時刻プローブを置いた。
補正を 0 へ戻した対照では、48 kHz・1 フレームの先頭で実際が `-0.000057291647`、期待が `-0.00025` となった。
`PDC transport disagrees with input audio` と終了コード 101 を照合した証拠は `target/focused-checks/pdc-transport-red-corrected/` にある。
最初の試作ではルートの順を取り違えたため、その失敗は補正漏れの根拠にしない。

## 比べた案と決定

- **トラックの装置遅延を別に足す**: 不採用。
  フォルダの合流、最初の音源、バイパスの埋合せで音声グラフと違う式になり、共通の不変条件を失う。
- **過去の transport イベントを遅延線へ貯める**: 不採用。
  履歴の容量が遅延長やコールバックの切り方に依存し、計画交換と停止の受渡しも増える。
- **検証済みグラフの入力遅れと、既存の素材の軌跡を使う**: 採用。
  `Compensation::stage_inputs` は各装置に対応する節の `Solution::lags` を保持するだけで、計算を重ねない。
  `Playhead` の原点・経過フレーム・ループで入力位置を求め、`Timeline` と共通の `split_loop` が通知を生成する。
  テンポ点と分割用の作業領域は共有し、各段には今のブロックの通知だけを置く。

性能の比較計測は行っていない。
遅延長に比例する履歴の確保・走査と、素材の軌跡の重複実装を避けることを、堅牢性と保守性の理由にした。
通知の領域は制御側で既存のブロック局所の容量に従って確保する。
音声側に確保・解放・ロック・追加の時計読取りは足さない。

## 時刻の意味

- 最初の音源の入力遅れは 0。後段とフォルダ FX は、その入力音声と同じ曲位置を見る。
- バイパスの埋合せは従来どおりトラック出力で行うので、その後の FX の入力遅れには足さない。
- 再生開始と位置移動直後は、遅延線が満ちるまで原点前へ外挿する。
  表示の原点保持をそのまま使うと FX の時計が止まるため、入力時計だけは外挿する。
  i64 の範囲外へ出る入力位置は `PlaybackError::Time` で断り、折返さない。
- 初回のループ進入と遅延より短いループを、原点からの経過で扱う。
  折返した処理位置から単に遅延を引かない。
- 停止中・停止フェードは従来どおり保持位置と停止フラグを全段へ渡す。
  同じ軌跡の計画交換では経過を保ち、遅延変更後は新しい入力遅れを使う。

後段ノートの遅延補正は今回の範囲に含めない。
保存形式・IPC・C ABI・依存ライブラリは変えない。

## 回帰と基盤

実ヘルパーの回帰は 48・96 kHz、1・7・64・512 フレーム、負の開始、テンポ境界、30 サンプルのループを通す。
一時停止での保持、計画交換後の位置移動と再生も同じ波形の基準で比べる。
単体回帰は音源・フォルダ・バイパスの入力遅れ、整数境界、密なテンポ点と短いループの容量を検査する。
既存の確保禁止ガードを通し、実ヘルパーの回帰は既存の RTSan の対象にも含める。
RTSan 自体と全契約の反例は全体の検査へ任せる。

必須契約 `plugin-pdc-transport` と補正を 0 へ戻す反例を `scripts/verification.json` に登録する。
既存の `plugin-musical-transport` の反例は、生成と配布の分離に合わせて先頭通知の生成へ移す。
検査と選択は既存の Makefile・ポリシーの入口を使い、新しい実行コマンドは足さない。
外部入力やパーサーを増やさないので fuzz の入口も変えない。

設計書・進捗・制約・コードの所在・診断手順を更新する。
第三者の同期設定・プリロールの聴感は通知の自動比較では判定できないため、UC-91 としてユーザーへ分ける。
センド・サイドチェイン・ドラム用 MIDI 配布・後段ノートの補正と、P2-03 全体の受入は残る。
