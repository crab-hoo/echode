# ADR 0229: プラグインの窓での未記録の変更を、無関係な文書の変更から守る

- 日付: 2026-11-02
- 状態: 採用。実画面と第三者プラグインでの確認はユーザー担当
- 関連: [ADR 0132](0132-helper-plugin-windows.md)、[ADR 0130](0130-clap-parameter-editing.md)、
  [外部監査の精査](../reviews/2026-11-02-external-audit-review.md)の DOC-A1・DOC-A2、
  [実行指示](../reviews/2026-11-02-fix-instructions.md)の W1

## 背景と再現

開始時の HEAD は `53840fb`。ADR 0132 は、窓が開いている間のプラグインの変更を、静止またはジェスチャーの終了で 1 回の Undo にすると決めた。
記録までの間、文書ワーカーはそのデバイスの背景保存を保留する。次の 4 つの経路で、記録されないまま変更が消えていた。

- DOC-A1 経路 1: 窓での `dirty` の活動に `window_open` が付かない。
  ワーカーは保存を保留するが、画面は窓が閉じていると読んで静止の記録を始めない。
- DOC-A1 経路 2: 活動の受け口が 4,096 件で縮退すると、窓が開いていたことと `dirty` を落とす。
- DOC-A1 経路 3: デバイスビューで元の値へ戻したドラッグは確定を送らない。保存の保留が次の文書の変更まで残る。
- DOC-A2: 保留中の保存があるまま無関係な編集をすると、ワーカーの手番が保留を捨てる。
  続く置換はモデルの古い状態とヘルパーの適用済みの状態を比べ、ヘルパーを作り直す。値が戻り、窓が閉じる。

`plugin_gui::audit_doc_a1_...` と `plugin_gui::audit_doc_a2_...`（`hosted_playback`）は、修正前に終了コード 101 と
それぞれ「`window_open: false`」「the helper and its window were replaced」の固有のアサーションで失敗した。

## 決定

### 窓での変更の印を失わない

- ヘルパーの制御側は、`Dirty` の活動を窓が開いている時だけ作る。その活動の `window_open` を真にする。
- 受け口の縮退は、デバイスごとの失われた印に加えて、窓が開いていたこと・`dirty`・閉鎖を論理和で残す。
- 画面は、失われた印・窓の閉鎖（`closed`、`window_state=false`）が届いた時、開いているジェスチャーを終わったものとして記録する。
  終了の通知は来ない。`ParamRelay` の `lost` の約束（読み直して終わったものとして扱う）に合わせた。
- デバイスビューのドラッグは、値を 1 回でも送れば、元の値へ戻っていても確定を送る。
  等しいバイトは記録しないので Undo は増えず、保存の保留だけが解ける。押しただけで動かしていない時は送らない。

### 無関係な文書の変更はヘルパーを作り直さない

2 案を比べた。

- 先に記録する案: 文書を変える手番の前に、ワーカーが保留中の保存を 1 回の Undo として記録する。
  Undo が直前のプラグインの変更を取り消せる利点がある。
  一方、画面は Undo / Redo の数と入力長の履歴を自分で数える（`recordEdit`）。ワーカーが自分で積んだ手番を画面は知らず、Undo の可否と数がずれる。
- ヘルパーを保つ案（採用）: ワーカーは、記録を待つ編集の保存を持つデバイスをセッションへ渡す（`keep_live_plugin_edits`）。
  セッションは、その更新で記録状態・プラグイン・オフラインが変わらないデバイスについて、経路の状態を記録済みのオブジェクトではなくヘルパーの適用済みのバイトにする。
  エンジンの既存の比較（適用済みの状態と経路の状態が等しければ残す）でヘルパー・窓・値が残る。
  記録は従来どおり画面の静止・ジェスチャー終了・ドラッグ終了の確定が 1 回の Undo として行うので、数は一致する。

あわせて次を決めた。

- ワーカーの `document_changed` は、記録状態・プラグイン・オフラインが変わらないデバイスの編集中の印と保留中の保存を残す。
  変わったデバイス（そのデバイスの Undo・削除・オフライン化）は従来どおり編集を終え、前のグラフの保存を新しいグラフへ記録しない。
- 同じデバイスの保留中の保存は最新の 1 件だけを持つ。古い保存を記録する経路はなく、編集が長く続く時の保持量を抑える。
- Undo / Redo は、静止を待っているプラグインの編集を先に記録する。デバイスビューのドラッグを先に確定するのと同じ扱いである。
  Undo はその編集を取り消し、Redo で戻せる。Redo の前の記録は新しい編集として Redo の列を消す。静止を待ち終えてから押した時と同じ結果になる。
- 制御の通信形式、期限、DSP、保存形式、C ABI は変えない。追加した公開 API はセッションの `keep_live_plugin_edits` だけである。

## 残る範囲

- そのデバイス自身の記録状態を変える Undo / Redo は、画面がまだ知らない変更を記録せずに記録状態を読み込む。
  活動の読取りが遅れている間の変更と、窓でのジェスチャーの途中の変更が該当する。
- 出力機器の変更で出力を開き直すと、ヘルパーは記録状態から作り直される。開き直しは置換の経路を通らない。
- 終了を送らないジェスチャーで、窓も閉じず失われた印も来ない時は、編集中の印がそのデバイスの記録状態が変わるまで残り、背景保存の保留も続く。
  従来は次の文書の変更で解けていた。値はヘルパーに残る。
- 実画面と第三者プラグインでの確認はユーザー担当である。

## 回帰と基盤

- 実ヘルパー: `audit_doc_a1_...` は窓での `dirty` が窓の編集として届くことを、
  `audit_doc_a2_...` はセッションが渡す経路（ヘルパーの適用済みのバイト）で置換してもヘルパー・窓・値が残ることを確かめる。
  後者は修正の後もエンジンの層に残し、ワーカーとセッションの半分を次へ移した。
- ワーカー: `saves::tests::an_unrelated_edit_keeps_a_held_save_and_its_edit` は無関係な編集の後も保留とセッションへ渡す集合が残ることを、
  `a_changed_device_drops_its_saves_and_ends_its_edit` は Undo・削除で従来どおり終えることを確かめる。
  前者は `document_changed` を旧来の全消去へ戻すと固有のアサーションで失敗することを確認した。
- セッション: `session::tests::a_live_plugin_edit_survives_only_updates_that_keep_its_recorded_state` は残す対象の選別を、
  `stream::tests::a_live_device_route_carries_its_helper_bytes_instead_of_the_recorded_object` は経路の状態の差し替えを確かめる。
- 受け口: `activity::tests::a_collapsed_backlog_keeps_an_open_window_and_a_dirty_state`。
- 画面: `DeviceParameterTests.parameterDragBackToStartStillCommits` と `PluginWindowTests.unfinishedPluginEditsAreRecordedNotDropped`。
  修正前のコードで、確定の回数と Undo の数の固有のアサーションにより失敗することを確認した。
- 新しい必須契約・ログ・保存先は加えない。`doctor`・`debug-report` の収集範囲は変更しない。
  切り分けは [デバッグ手順](../debugging.md) のプラグインのウィンドウの節に追記した。
