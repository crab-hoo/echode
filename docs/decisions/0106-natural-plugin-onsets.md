# ADR 0106: 自然なプラグインの発音を直接出力と比較する

- 日付: 2026-10-16
- 状態: 採用。今回の条件ではEchodeが加える発音境界の不連続を再現しなかった。
- 範囲: 通常再生の無音からの発音と再発音。停止の修正とは区別する。

## 報告と調査

ユーザーはVital Initが無音から鳴り始める時、Reaperより大きなクリックがするように感じると報告した。最後に開いたプロジェクトの保存済みデバイスもVital・保存状態なしだった。ユーザー文書は読み取りだけとし、書き手・音声機器・画面を開かなかった。

音源の波形そのものを変える前に、別プロセスのVitalへ直接ノートを送る経路と、製品の計画・イベント配送・隔離ヘルパー・ステレオミックス・HALと共通の出力補正を通す経路を比較した。同じ音源、Init、C4、MIDIベロシティ100、同じサンプル位置でノートオン・オフを送り、最初の無音と再発音を含めた。48 / 96 kHz、7 / 64 / 512フレームの6条件で左右の全サンプルが完全一致し、プラグインの失敗は0だった。HALの機器呼出やDAC以降を再現した検査ではない。

ピークは48 kHzで約0.3559、96 kHzで約0.3625。発音後5 ms以内の最大隣接サンプル差は、それぞれ約0.3206と0.2352だった。この差は直接の音源出力にも同じ値で含まれる。隣接差だけを使ってホストがクリックを加えたと判定せず、音源のアタックとホストによる追加の変化を分ける。レート・分割間の小さい音源自身の変化も、各条件内での直接経路との一致と区別する。

今回のローカル証拠は `target/onset-audit/vital-matrix.rs`、`vital-matrix.log`、`evidence.json`。音源の版・実行ファイルと関連ソースのSHA-256も保持する。これらの生成物は別の環境に存在するとは限らない。CLAPの `constant_mask` の扱いも確認した。[仕様](https://github.com/free-audio/clap/blob/main/include/clap/audio-buffer.h) では最適化のヒントであり、全サンプルを読むホストも許されるため、これを今回の不具合とはしない。

Reaperの実出力、実機の期限内処理、ユーザーの聴感の一致は未検証である。Reaperと同じ音と断定せず、今回の条件で余分な段差を確認できなかったことを結果とする。実機・聴感はユーザー担当の方針を維持する。

## 判断と回帰

通常のノート開始をトランスポートの不連続と扱わず、音源のアタックに自動のフェードを加えない。レベル差・オーバーラン・再生位置の移動を自然な発音と混同して修正しない。今回、製品の音声処理は変更しない。

必須契約 `plugin-onset` は別プロセスの検査用音源を使い、同じ6条件で直接出力との全サンプルの一致を確認する。検査用音源はサンプル位置に従う有限のアタックと左右の異なる振幅・極性を持つ。無音だけの合格を防ぐ非ゼロの確認、最初の発音より前の無音、ブロック分割間の一致も要求する。CLAPノートオンの時刻を0へ変える負の対照を登録し、発音の前倒しを期待値で拒否する。時間の性能閾値や音楽全般への隣接差の上限は使わない。正常な検査用音源の経路はRTSanにも含める。

`block_size.rs` では緩やかなアタックと意図的に急なアタックを無音の後へ配置し、1 / 7 / 64 / 512フレームで通常の出力補正が値を変えないことを確認する。既存の停止・移動の補正は従来の回帰が担当する。

最終検査では必須契約18項目と各負の対照、通常検査、RTSan、ASan、TSan、Miriを含む自動9系統が通過した。TSanの初回は終了済みスレッドの `errno` 読取と、別スレッドの `ReadDir::next` 内の書込を同じアドレスの競合として報告した。既存の標準ライブラリだけの再現とスタックを照合し、抑制・ソース・判定条件を変えず再実行して通過した。初回を消さず `target/onset-audit/tsan-first.log` と `tsan-first-full.log`、続く検査を `verify-tsan-retry.log` に保持する。実機・聴感・他DAWの比較の合格には扱わない。

## ビルドの扱い

ユーザーの指示に従い、診断のたびに別の `.app` を増やさない。今回の調査ではアプリを作成・起動・置換しない。通常の出力先は `target/Echode.app` とし、起動中のアプリは置換しない。診断用の記録先と識別値は環境変数で指定でき、アプリを複製することを必須手順にしない。
