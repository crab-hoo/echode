# 0014. 既存の実装を選択肢として取り込む

- 日付: 2026-10-08
- 状態: 採用。[0013](0013-windowed-sinc.md) の補間の方式を置き換える

## 背景

ライセンスを GPL-3.0-or-later にしたので（[0004](0004-license-gpl.md)）、使えるライブラリが多い。一方で、既存の実装を使うか自作するかの方針がなかった。サンプルレート変換は 0013 で自作の Hann 窓の sinc に決めたが、既存のライブラリとは比べていない。

0013 の実装をリポジトリの外にコピーし、rubato 5.0.1 と比べた。Apple M4 のリリースビルドで、サンプルは f32 である。正弦波を変換し、出力の中央の半分に 4 項の Blackman-Harris 窓をかけて、折り返しが出る周波数の成分を測った。

| 方式 | 最も悪い折り返し | 可聴帯域に落ちる折り返し | 負荷（モノラル 1 本、44.1→48 kHz） |
|---|---|---|---|
| 0013（Hann 窓、片側 32 サンプル） | -55 dB | -73 dB | 1 コアの 3.5% |
| rubato の sinc 方式（既定の設定） | -141 dB | -167 dB | 1 コアの 0.79% |
| rubato の FFT 方式 | -158 dB | -175 dB | 1 コアの 0.07% |

「最も悪い折り返し」は、次の 4 つのうち最も大きいものである。48→44.1 kHz で 23 kHz、96→44.1 kHz で 30 kHz、96→48 kHz で 40 kHz を入れた時の折り返しと、44.1→96 kHz で 20 kHz を入れた時の鏡像。「可聴帯域に落ちる折り返し」は、96→44.1 kHz で 30 kHz が 14.1 kHz に出る量である。19 kHz までの周波数特性はどれも平坦で、48→44.1 kHz の 20 kHz では 0013 だけが 0.35 dB 下がった（rubato は 0.01 dB 以内）。0013 は、Hann 窓なので窓を長くしても折り返しがほとんど減らず、出力の 1 サンプルごとに sin と cos を約 130 回計算している。

作者は、既存の実装を使えるなら、ほかに完全に劣るものを除いて、できるだけ多くをユーザーが選べるようにしたい。

## 決定

- 定番の実装があって、どれを使うかで音や負荷が変わる処理は、自作する前に GPL と両立する既存の実装を調べて測る
- ほかの選択肢に完全に劣るもの（音質、負荷、遅延、できることのすべてで同等以下のもの）を除き、できるだけ多くをユーザーが選べるようにする。既定はそのうちの 1 つにする
- 自作するのは、既存の実装が要件を満たさない時か、測って上回る点がある時に限る。理由と測定値を ADR に書く
- オーディオスレッドの規則を守れない選択肢は、書き出しなどのオフライン処理でだけ選べる
- プロジェクトには選んだ実装を ID と版で記録し、プレビュー用キャッシュの鍵にも含める
- どれを使っても結果が変わらない土台のライブラリ（Git、JSON など）は選択肢にしない

サンプルレート変換には次のように当てはめる。

- 既定は rubato とする。比率が一定のクリップは FFT 方式、比率が変わるクリップ（バリスピードなど）は sinc 方式を使う。再生と書き出しで既定を同じにし、それぞれ別に変えられるようにする
- r8brain-free-src（MIT）、soxr（LGPL-2.1-or-later）、zita-resampler（GPL-3.0-or-later）、libsamplerate（BSD-2-Clause）、macOS の AudioConverter は、同じ方法で測り、ほかに完全に劣るのでなければ選択肢に加える。AudioConverter は OS の更新で出力が変わりうるので、macOS の版も記録する
- 0013 の自作の実装は、rubato の sinc 方式に音質、負荷、できること（比率を途中で変えられない）のすべてで劣るので、選択肢に出さない
- 0013 のうち、出力のサンプル 0 が入力のサンプル 0 に対応すること、範囲の外は無音とすること、同じレートでは元のサンプルをそのまま通すこと、オーディオスレッドで割り当てをしないことは引き継ぐ

## 結果

- echode-engine が rubato に依存する。rubato とその依存は、すべて GPL-3.0-or-later と両立する寛容なライセンス（MIT、Apache-2.0、0BSD、Zlib、Unicode-3.0）である
- `resample_into` を rubato に置き換える。割り当てとロックがないことは、デバッグビルドの検出で確かめる
- ライブラリの変換は状態を持ち、出力が少し遅れる。シークとループの頭では、前から処理して状態を作る（ARCHITECTURE §7.5）。rubato の sinc 方式は位置を足し算で進めるので、シークした所からの音は、頭から通した音と丸め誤差の範囲で食い違う
- 比較の測定をリポジトリに入れ、候補を足す時に同じ方法で測る
- 選択肢が増えるほど、テストと測定の手間が増える。その代わりに、音質と負荷の釣り合いをユーザーが選べる
