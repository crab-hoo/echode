# 0341. ヘルパーへ渡せなかったノートは現在の発音へ戻す

- 日付: 2026-11-14
- 状態: 採用
- 対象: RTA-03・RTA-04

## 背景

[リアルタイム監査](../reviews/2026-11-14-realtime-adversarial-audit.md)で、
ヘルパーが 2 ブロック以上遅れると、公開できなかったブロックのノートオフが消え、音が鳴り続けた。
修正前の製品経路の再現では、イベントの計数が期待した 17（オン 1・オフ 1）でなく 1 になった。
音声の締め切りと減衰は [ADR 0245](0245-plugin-deadline-fades.md) の範囲であり、待ち時間は伸ばさない。

公開済みのブロックにも、領域の交換が先に進むと処理されない経路があった。
これは公開できなかったイベントとは異なり、既に受け取った仕事の順序の誤りである。

## 比べた案

- 失ったイベントを蓄え、次のブロックで再送する。
  古いオン・オフを遅れて鳴らし、連続した失敗の長さに応じた領域が要る。
  固定の上限で捨てるか、音声側で確保する案は取れない。
- イベントが届かなかった段だけをリセットし、現在の発音を追い直す（採用）。
  バイパスの解除と同じ手順と事前確保したイベント領域を使い、古いイベントの待ち行列を増やさない。
  欠けた音声と余韻は戻らず、継続しているノートは打ち直しになる。
- 公開済みのブロックも領域の交換で捨て、すべてをリセットする。
  親が成功として公開したイベントまで捨てる契約になり、不要な打ち直しを増やすため採らない。

## 決定

現在の動作の正本は [プラグインの設計](../architecture/plugins-and-devices.md#94-クラッシュとハング)に置く。
公開できなかった段と、上流の失敗でそのブロックを受け取れなかった後段を回復の対象にする。
公開済みで単に遅い段は処理を続ける。イベントのない欠落ではリセットしない。
回復の印とリセットの保留は既存の状態を使い、計画交換でも引き継ぐ。
追い直しを載せたブロック自体も遅れた場合は、それより後の応答を処理順の受領証として扱い、同じオンを二重に送らない。

追い直しは、カーソルが持つ対象トラックの生きた集合だけから作る。
通常の計画交換の追い直しと共通の列挙を使い、元のノート数に比例した探索や確保はしない。
ループ頭で古い集合を解放するブロックでは、その集合をもう一度鳴らさない。

領域の交換は、古い領域の公開済みの世代をすべて処理してから行う。
親の音声スレッドを待たせず、領域の破棄は従来どおり制御側で行う。
共有メモリの形式、スロット数、制御通信の形式は変えない。

## 検証と残る範囲

- `hosted_playback/event_loss.rs` の `audit_rta04_*` は、イベントの計数でなく実際の発音を比較する。
  送れなかったオフ・オン、受け取れなかった後段、連続失敗、追い直し自体の遅れ、計画交換、ループ頭、不要なリセットの不在を通す。
  オフの回復は 44.1 / 48 kHz で比較する。オンの回復後は次のブロックへ波形が続き、重ねて打ち直さない。
- `isolation.rs` の `audit_rta03_*` は、領域交換の前に公開した世代が完了することを確認する。
  修正前は、古い世代が処理されないという固有のアサーションで失敗した。
- `cursor_tests.rs` の `recovery_chases_only_selected_tracks_live_notes_without_scanning_the_score` は、
  終わったノート数を 64 から 1,024 に増やし、別トラックの全ノートを発音中にしても、訪問数が対象の 2 声だけであることを比較する。
  容量不足は失敗にし、終端ちょうどの再発音を防ぐ。

実機・第三者プラグインでの打ち直しと余韻の聴感は UC-75 に残す。
試験用プラグインのソケットで処理を保留する回帰は、実機性能の測定や RTSan の合格の証拠ではない。
RTA-01・02・05〜08 はこの作業の対象外である。
