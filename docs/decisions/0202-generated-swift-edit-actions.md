# 0202. アクション登録簿から Swift の編集型を生成する

- 日付: 2026-10-30
- 状態: 採用（生成器・橋渡し・controller の全編集を移行）
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-03

## 背景と今回の範囲

Rust の `define_actions!` が命令・登録簿・JSON Schema を生成する一方、Swift の編集要求は辞書で組み立てている。
キーの改名や型の変更を Swift のコンパイル時に検出できない。
不具合の再現ではなく、この重複をなくすための段階的な構造整理である。
最初の受入単位で生成器・生成物・型付きの製品橋渡しを導入した。後続の単位でピアノロール、トラック・デバイス、ミキサーを順に移行した。

## 決定

- `echode-actions` の `swift_actions` example が `catalog()` と各アクションの公開スキーマを読み、
  `EchodeBridge.EditAction: Encodable, Sendable` を生成する。操作の一覧や項目を生成器へ再定義しない。
- case 名はスキーマの title、引数は必須項目の順と残りの項目から導く。
  Swift の snake_case → camelCase と JSON の元のキーを分け、キーワードは backtick で保護する。
  衝突する名前や未知のスキーマ構造・format は生成エラーにする。
- 文字列・真偽値・整数・Float と nullable の現在のスキーマを扱う。
  ID の構文、ノートの範囲、参照の存在、テンポ・拍子の妥当性は引き続き Rust が検証する。
  公開スキーマ上の ID は `String`、format のない整数は `Int64` とし、
  `u8` / `u16` / `u32` / `u64` と `f32` は対応する Swift の型を使う。
  既存スキーマを変更して UUID・Tick の意味を推測する生成器にはしない。
- optional の nil は明示的な JSON null にする。親・保存済み状態の解除と、末尾へのデバイス移動を保つ。
  時刻・フレーム数を Double へ変換せず、Float は `JSONEncoder` で符号化し、非有限値は送信前に拒否する。
- `Document.perform(EditAction)` と `Document.perform([EditAction])` は、
  既存の raw JSON の submit と同じ文書ワーカーへ渡す。
  配列の単一 Undo・巻戻し・no-op・送信前の取消と、送信後に編集を取り消さない契約は変えない。
- 生成物を追跡する。`make swift-actions` が再生成し、`make check-swift-actions` は変更せず鮮度だけを検査する。
  後者を通常の `make check` に組み込む。生成器は製品アプリへ同梱しない。

## 回帰と診断

- Rust の example テストは生成物の一致、全登録操作を覆う共有 wire fixture の `Command` 往復、
  未対応のスキーマ・名前の衝突・古い生成物の拒否を確認する。
- Swift の `EditActionTests` は全 case を独立した共有 fixture と比較する。
  大きい整数の表記、nullable の両側、Float の極小・極大と非有限値も確認する。
- 必須契約 `typed-edit-bridge` は実際の文書ワーカーへ単一／一括要求を送り、
  履歴・一括失敗・符号化失敗・取消・no-op とパッケージの再オープンを確認する。
  生成物のベロシティ送信を誤らせる負の対照も持つ。
- `is stale; run make swift-actions` は製品モデルの拒否ではなく生成物の不一致である。
  元の登録簿・モデル・スキーマを確認し、再生成して差分を確認する。
  未対応のスキーマは手で生成物を修正せず、生成器と両言語の回帰を同時に拡張する。
- ログや ABI の新しい出力先はなく、既存の診断収集を維持する。

## 後続: ピアノロールの controller を移行する

ノートの挿入・単一編集・削除・ベロシティと、複数移動・複製・伸縮・キー操作を生成型へ移した。
`PianoMoveChange`・`PianoResizeChange`・`PianoStep`・`PianoVelocityChange` は `[EditAction]?` を返す。
controller は一要素の要求も配列へそろえ、型付きの `Document.perform([EditAction])` に送る。
MIDI の `Int` は既存の範囲・幾何・元の値の照合後にだけ `UInt8` へ変換し、不正入力を丸めて送らない。

`performActions` と未移行の辞書の adapter は、型を保つ generic の `applyEdit` を共有する。
編集順序・文書照合・no-op 解決・履歴・入力長とベロシティの記憶を二重実装しない。
対象と no-op は順番が来てから解決し、解決できない要求で入力記憶を更新しない。
型付きの経路は `Any` や `JSONSerialization` を通さない。

`TypedPianoEditTests` は `2^53` を超える整数時刻と二つの対象、単一 Undo / Redo、古い元の値の拒否を検査する。
MIDI の境界外と旧文書を拒否した時の履歴・入力記憶、連続キーの実行順序、保存再読込も確認する。
必須契約 `typed-piano-controller` は、複数要求の先頭を落とす反例を拒否する。
既存のピアノロールの操作・リンク・取消の契約は対象と期限を維持する。
検査基盤は移行済みの組立てに辞書を戻さないことと、新しい契約の選択・反例の一意性も照合する。

## 後続: トラックとデバイスの controller を移行する

トラックの追加・位置指定の挿入・部分木の一括複製と、デバイスの単体／一括追加・削除・並べ替え・コピー・バイパス・オフライン・ピン留めを生成型へ移した。
`performActions` は `selectingAddedTrack` を共通の `applyEdit` へ渡し、追加した根の選択を同じ編集区間で行う。
対象の捕捉・手番での no-op 判定・旧文書の拒否は変えない。
並べ替え・コピーの `before: nil` は省略から明示的な null に変わるが、どちらも既存の末尾指定として扱う。

`TypedTrackDeviceEditTests` は移行前の製品経路にも通し、挿入位置・複数対象・追加後の選択・元とコピーの独立を確認する。
並べ替えのアンカーと末尾、最大の有効な CLAP ID（`UInt32.max - 1`）と予約 ID の拒否、no-op・不正要求での Redo 保持も検査する。
単一 Undo / Redo・再オープン・旧文書の拒否を通し、必須契約 `typed-track-device-controller` は複数要求の先頭を落とす反例を拒否する。
既存のトラック・FX 操作の契約も維持し、バイパスとオフラインの反例を型付きの組立てへ合わせた。
検査基盤は移行した領域へ辞書を戻さないことと、新契約の選択・反例の一意性を確認する。

## 後続: ミキサーと音声クリップの値編集を移行する

トラックの単一パラメーター、ミュート・ソロの一括要求、音量・パンの数値入力と読み上げ増減を生成型へ移した。
ピアノ行の単一ミュート・ソロ、ライブフェーダーの確定、音声クリップのゲイン・両フェードも同じ配列入口を使う。
`performActions` は `finishingPreview` を共通の `applyEdit` へ渡し、試聴中の通常編集の拒否と、終了時の一度だけの確定を保つ。
対象の捕捉・手番の現行値解決・共通限界・文書照合・履歴は変更しない。試聴の音声要求は既存の型付き経路を維持する。

`TypedMixerEditTests` は移行前の製品経路にも通し、全対象の単一 Undo / Redo、試聴の先行確定と取消、ピアノ行の単一対象を確認する。
非正規化数の Float と端数 flick・モデル上限内の長いフェード、no-op と不正要求での Redo 保持、保存と旧文書の拒否も通す。
モデル上限を超えるフェードは従来どおり拒否し、`2^53` 超の値を有効なフェードとして扱わない。
必須契約 `typed-mixer-controller` は、配列の先頭を落とす・両フェードを逆転する・試聴の確定許可を落とす反例を拒否する。
既存の実 View・文書境界・入力順・共通限界の契約は維持し、基盤検査で移行済み領域への辞書の逆戻りも止める。
ログ・ABI・保存形式・DSP は変わらず、診断収集の追加は不要である。

## 後続: クリップ移動と既存トラックへの音声配置を移行する

クリップの移動・独立した複製と、ブラウザ・既存トラックへのドロップの音声取込みを生成型へ移した。
移動の対象・変位なしの判定は編集の手番で解決し、成功後のトラックと複製側のフォーカスを保つ。
音声配置は `AudioImportRequest` に捕捉した文書・トラック・整数 tick とパスを型付きの配列へ渡す。
未使用になった辞書の遅延単一編集入口を除き、no-op の遅延判定は `performActions` に集める。

`TypedClipEditTests` は移行前の製品経路にも通し、`2^53` 超の tick・別トラック・独立複製と選択を確認する。
単一 Undo / Redo、無変位・不正な対象・桁あふれ・取込み失敗での Redo 保持、原本削除後の Redo、保存再読込と旧文書の拒否も通す。
必須契約 `typed-clip-controller` は、複製を移動へ変える反例と、移動・音声取込みの tick を Double へ丸める反例を拒否する。
既存の実 View・ドロップ・ブラウザ操作の契約は維持し、入力先を選択中のトラックへ戻す反例だけを型付きの組立てへ合わせた。
基盤検査は移行した領域への辞書の逆戻りと契約の選択を確認する。ログ・ABI・保存形式・DSP は変更しない。

## 後続: 一括編集内の結果参照を型で表す

新規トラックへの音声ドロップは `track.add` の確定 ID を次の `audio.import` で使う。
Rust の `resolve_refs` は、文字列の項目ならどれでも `{ "ref": n, "field": "..." }` を前の確定結果へ置き換える（[ADR 0034](0034-api-transaction.md)）。
この規則に合わせ、生成型の文字列の項目を型引数 `Text` にした。

- `EditActionOf<Text>` を生成し、`EditAction` は `EditActionOf<String>`、`ReferencingEditAction` は `EditActionOf<EditText>` の別名とする。
  既存の呼出しは変えず、操作の形は一か所の生成物のままである。
- `EditText` は値か結果参照を表す。項目名は確定後のアクションの項目で、公開スキーマに含まれないため文字列のまま持つ。
  誤った番号・項目は Rust が一括編集全体を拒否して巻き戻す。
- `Document.perform(referencing:)` と `performActions(referencing:)` で、参照を使う要求を通常の入口と分ける。
  型推論の曖昧さを避けるため、ラベルを別にした。

これで controller の `[String: Any]` と `JSONSerialization` の入口を除いた。テストの準備も同じ生成型を使う。
`typed-clip-controller` は、参照の番号の誤りと、追加したトラックの選択を落とす反例を拒否する。
`TypedClipEditTests` で、特殊な文字のファイル名・単一 Undo / Redo・取込み失敗時に追加トラックも残らないこと・保存と旧文書の拒否を確認する。
ABI・保存形式・DSP は変更しない。

## 残る範囲

raw JSON の `Document.perform(String)` は互換入口として保持する。
ID と時刻を UUID / Tick の値型として生成すること、文書スコープの集約（SPG-02）はこの ADR の範囲に含めない。
音声処理・描画・保存形式は変えず、実機・聴感の新しい合格を主張しない。
