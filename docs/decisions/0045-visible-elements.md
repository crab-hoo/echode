# 0045. 可視範囲は ID と役割を返す

- 日付: 2026-10-10
- 状態: 採用
- 項目: UI-1

## 背景

S1 の `visible_tracks` と `visible_notes` は、色と矩形だけの `Instance` を返す。ヒットテスト、選択、VoiceOver は、見えているものがどのトラック、配置、ノートかを知る必要がある。PLAN §6 は、Metal で描いた画面のアクセシビリティ要素の木を Phase 1 から作るとしている。

S1 の二分探索は、生成したノートが 2 拍より短いことに依存している。製品のノートに長さの上限はない。ADR 0023 はノートを開始、音高、ID の順に持ち、モデルには最大長の索引を置かない。長いノートが視界より前から伸びる問い合わせは、この項目が区間で扱う。

見えているノートの区間は、ADR 0025 の `Placement::audible` と同じである。配置の窓とノートの鳴る区間の共通部分が空なら、そのノートは見えない。同じ中身を共有する配置では、同じノート ID が複数の窓に現れる。

モデルは編集のたびに新しい `Project` を返す。変わっていない中身は同じ `Arc<Content>` のままである。トラックは、フェーダーだけ変えても新しい `Arc<Track>` になる。

## 決定

製品の問い合わせは、モデルのスナップショットから可視要素の列を返す。描画のインスタンス、ヒットテスト、VoiceOver の可視の子は、この列から作る。S1 の `Scene` と `Instance` は計測用のまま残し、`MAX_NOTE_LENGTH` も残す。製品の問い合わせへは置き換えない。

要素は次を持つ。

- 役割はトラック、配置、ノートの 3 つである
- トラックはトラック ID、配置は配置 ID、ノートは配置 ID とノート ID である。ノート ID だけでは、中身を共有する配置を区別できない
- 矩形はビューのピクセルである。重なりの判定は tick とトラックの並びで行い、ピクセルへ変えるのは矩形を書くときだけである。ノートの矩形はレーンの内側に置き、レーン全体は覆わない

ビューは、時間の原点と幅（tick）、トラックの原点と高さ（アレンジ順の実数）、横と縦のピクセル倍率である。時間範囲もトラック範囲も終端を含まない。倍率か大きさが 0 以下なら、要素は 0 個である。

トラックは ADR 0024 の配列順で、縦範囲に交わる連続区間の端は原点と高さから決める。配置とノートは時間の区間である。モデルの並びは変えない。中身ごとに、ノートの終端の最大値を持つ完全二分木を作る。配置はトラックごとに、開始順の列の上へ同じ木を作る。

この木の費用は、高さにヒット数を足したものではない。節は、その範囲の終端の最大値だけを持つ。問い合わせは、最大終端が範囲の始端以下の枝と、開始が範囲の終端以降の枝を見ない。長いノートがまばらに残ると、ヒットした葉までの経路が別々に残り、訪れる節はヒット数と `log(ノート数 / ヒット数)` をかけた桁になる。フレームごとに木は作らない。

索引は版をまたいで再利用する。中身の `Arc` が同じなら、その木を次の版へ持っていく。同一性は `Arc::ptr_eq` で見て、アドレスの数値では比べない。配置の木は、そのトラックの配置の ID、開始、長さ、オフセットが前と同じなら持っていく。フェーダーやミュートだけでは、ノートの木も配置の木も作り直さない。ノートや配置の時間区間が変わったものだけ作り直す。

ノートの内容時刻は、見えている配置ごとに `audible` の区間へ変えてからビューと交わるかを見る。窓の外だけに伸びるノートは返さない。出力の配列は呼び出し側が渡す。足りない分は数だけ返し、問い合わせはメモリを確保しない。

ヒットテストは同じ列を点で見る。重なったときはノート、配置、トラックの順で狭い役割を採る。同じ役割なら、列の後ろを採る。列はトラック、その中の配置、その中のノートの順なので、後ろが手前になる。

アクセシビリティでは、可視の子と論理的な子を分ける。可視の子は、上の可視列である。論理順は、トラックの配列順、その中の配置の開始順、その配置で鳴るノートのモデル順である。画面の外も含み、窓の外のノートは含まない。論理順の隣へ移るときは、その要素がビューに入るまで原点を動かす。要素がビューより大きいときは、始端を原点に合わせる。

フォーカスは ID で持つ。スナップショットが変わっても、そのオブジェクトが残っていれば、可視列に無くても同じ ID を保つ。消えていたら、ノートは配置へ、配置はトラックへ、トラックは配列の先頭へ戻す。OS のアクセシビリティ API、Metal、色、ピアノロールの音高軸、フェードのつまみは、この項目では作らない。

検証には、1,048,576 ノートのうち 1,024 本だけが小さい窓に掛かる分布を入れる。返る数はその 1,024 であり、訪れた節はノート全体の走査より少ない。

## 結果

採用した。可視列、ヒット、論理順、フォーカスの保持、原点の移動、索引の再利用は `echode-draw` の問い合わせである。S1 のシーンは残している。
