# ADR 0110: Apple Silicon 向けの描画周期、波形バッファ、ピーク読出、稼働表明

- 日付: 2026-10-17
- 状態: 採用
- 範囲: 表示リンク、波形の Metal バッファ、ピークキャッシュの読出、再生・書き出し・ヘルパーの稼働表明。プラグイン往復のまとめ、IOSurface、clonefile、再生準備の mmap は含まない

後日変更（2026-10-17）: ユーザー指定により対象チップを M4 ファミリー以降へ絞った（[ADR 0112](0112-m4-minimum.md)）。本文の M1〜M3 も対象とする前提と、それを理由に SME を除外する判断は置き換える。測定、採用した描画・ピーク処理、リアルタイム制約は当時の証拠として保持する。

## 背景

対象は macOS 27 以降の Apple Silicon だけである。静的な監査は、その前提に対して汎用的なコピーと制限が残っていると指摘した。新しい計測は行っていない。採用した項目は製品経路の実装と回帰で確認し、前提が全機種で成り立たないもの、音声スレッドの制約に反するもの、Phase 2 以降の機能は採用しない。

## 採用

表示リンクは画面の最大リフレッシュレートに合わせる。S1 と同じ式で、下限は 60 とその最大の小さい方、上限と希望は画面の最大である。60 Hz の画面は 60 のまま、120 Hz の画面は 120 まで出す。値はメインスレッドがウィンドウの画面から読み、描画スレッドは保存した数だけをリンクへ書く。描画スレッドから `NSScreen` は読まない。

波形のインスタンスとピークは、飛行中のフレーム枠ごとに共有モードの `MTLBuffer` を再利用する。枠は最大 3 つで、次のフレームが GPU の読んでいるバッファを上書きしない。画面を開かないプローブは枠 0 を使い、コマンドの完了を待ってから次を書く。容量は可視データに合わせて増やす。

ピークキャッシュが当たり、フレーム数とバケット幅 64 が一致するとき、正準 PCM の全読込、BLAKE3、モノラル合成はしない。粗い列はピラミッドだけを使う。要求範囲に完全に含まれる最大のピラミッドセルだけを足し、バケット境界より前の端と、64 サンプルに満たない残りだけをオブジェクトから読む。その読出は、最初に必要になった時の読み取り専用マップである。マップできないときだけ、構築時のモノラルをヒープに残す。オブジェクトを消したあとの短い読出は 0 になり、揃った粗い列はキャッシュだけで答えられる。

再生中のセッション、CLI の WAV 書き出し、プラグインヘルパーの処理プロセスは、公開の `NSProcessInfo` で `UserInteractive` の稼働を表明する。App Nap とアイドルスリープを避ける。スキャンだけのヘルパー起動では表明しない。蓋を閉じたスリープは止めない。S2 で記録された蓋閉じによるコールバック停止は、この表明では防げない。

ピアノロールの可視ノート用バッファは、可視要素と同じく容量が足りない時だけ確保し直す。

## 採用しない

対象 Mac のすべてが ARMv9.2-A や SME を持つ、という前提は置かない。M1〜M3 は NEON と、Accelerate 経由の AMX を持つ。ProMotion の 120 Hz も全機種の画面ではない。

Accelerate（vDSP）はピーク生成にもライブのミックスにも入れない。ADR 0058 の測定では、最細の列だけの vDSP はスカラーより速かったが、部分列、非有限サンプル、粗い段を同じループで扱うスカラーを製品の経路にした。vDSP は確保やロックをし得るため、音声スレッドでは使わない。ライブのブロックは短い。FFT、位相ボコーダ、マルチトラック EQ、LUFS の FIR は、その機能を実装する時に測る。

通常のヒープ確保や、先頭 24 バイトの正準 PCM を `makeBuffer(bytesNoCopy:)` で GPU へ渡すことはしない。Apple Silicon のページは 16 KiB で、ポインタと長さの両方がページ境界である必要がある。可視インスタンスは、すでに再利用している共有バッファへコピーする。ロック中の C バッファを Swift の配列へ出すコピーは残す。ポインタをロックの外へ出せない。列の `min` / `max` を一度分けてから `SIMD2` に戻すコピーは、見えている列の範囲に留まるので ABI は変えない。

プレイヘッドは、音声が最後に書いた tick をそのまま描く。表示時刻への補間はしない。供給側は tick と再生中かどうかだけを持ち、ホスト時刻を出していない。描いた tick と供給 tick が一致する契約を維持する。

## 今回は作らない

同一ヘルパーの連続デバイスを 1 往復にまとめる処理は、S3 の時点で未実装である。クリップ FX が入るまで製品経路に複数デバイスの往復はない。IOSurface によるサムネイルは、プラグイン GUI が無いので作らない。`fclonefileat` は、不変オブジェクトをバイト単位でコピーする製品経路がまだ無いので使わない。再生準備はデバイスレートへリサンプルした平面を保持し、オブジェクト読出時のハッシュ確認も残す。Phase 3 のプレビューキャッシュは接続していない。

## 検査

- 画面の最大が 60、120、40 のとき、表示リンクの範囲はそれぞれ (60, 60, 60)、(60, 120, 120)、(40, 40, 40) である。
- キャッシュがある 256 フレームは、オブジェクトを消したあとも揃った 128 フレーム列を答え、1〜2 フレームの読出は 0 になる。範囲 [2, 65) は先頭のピラミッドセルを使わず、範囲外のサンプルを含めない。
- 既存のトリム波形と負オフセットの波形検査は同じ期待値のままである。
- 稼働表明は生成して破棄できる。実機の App Nap、120 Hz の見た目、蓋閉じは自動検査の対象にしない。
