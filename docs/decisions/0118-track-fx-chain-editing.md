# ADR 0118: トラック FX のチェイン操作を既存の編集経路へ接続する

- 日付: 2026-10-19
- 状態: P2-02 の最初の接続。GUI・パラメーター編集等を含む P2-02 全体は未完了
- 範囲: CLAP の追加・削除・並べ替え・設定の複製、トラック FX ビューと候補パネル

## 背景

[操作要件](../interaction-design.md) と [ADR 0117](0117-workflow-interactions.md) の実装を開始する。既存製品は CLAP の追加・削除と状態保存を持つが、チェインの並べ替え・複製を操作する画面がなかった。候補一覧はモーダルで、開いた時のトラックに追加先を固定していたため、一覧を開いたまま別のトラックへ追加する制作手順を通せなかった。

P2-02 はヘルパー所有の GUI、パラメーター、バイパス・オフライン化、サムネイル、共通サンプルブラウザ等も含む。これらまで実装済みと扱わず、まず既存の CLAP チェインを編集・保存できる製品の経路を接続する。

## 決定と接続

- `device.reorder` は同一チェイン内の安定したデバイス ID を基準に、指定したデバイスの前へ移す。省略はミキサーの直前。外のチェインのアンカー、欠けた ID、ミキサーの移動を拒否する。画面では変化のない並べ替えを履歴に積まない。
- `device.copy` は元の CLAP ID と記録済みの状態ハッシュをコピーし、新しいデバイス ID を発行する。元は残す。不変の状態オブジェクトは共有できるが、再生ヘルパーのインスタンスは別 ID として生成する。現在の CLAP モデルはパラメーター配列を持たないため、パラメーター公開時には子 ID の再採番も具体化する。
- 両アクションを既存のカタログ・API / MCP・差分・ジャーナル・単一 Undo / Redo・保存／復旧へ通す。新しい保存フィールドは足さず、スキーマを変更しない。操作のランダム生成にも追加する。
- 下部エディタをピアノロールとトラック FX ビューで切り替える。FX の一覧から上下移動・複製・削除をネイティブのボタンで操作できる。同じトラック内のドラッグは並べ替え、Command 付きは複製、別トラックのヘッダへのドラッグは元を残すコピーとする。
- 空の FX ビューも表示領域全体でドロップを受ける。ドラッグ元の修飾キーはアプリが判定し、AppKit の既定の割当で Command の複製を上書きしない。カタログの表示名を使い、未取得・未検出なら記録されたプラグイン ID を表示する。表示名はセッション内の補助情報であり、保存形式を変更しない。
- ヘッダの FX ボタンから、クリックしたトラックを選択して候補パネルを開く。ボタンの画素はタイムラインと同じ Metal フレームに含め、ヘッダに独立した描画面を重ねない。入力・アクセシビリティも同じ矩形を使う。
- 候補一覧は非モーダルのフローティングパネルとする。開いたままトラック選択・編集ができ、ダブルクリック後だけ閉じる。Return と候補のドロップでは開いたままにする。Return の追加先も最後に選択したトラックへ統一するという追加回答を反映する。
- ダブルクリック・Return の追加先は実行時に確定し、非同期処理の完了時に選び直さない。パネルとドラッグは文書セッション ID を保持し、文書を閉じたり別の文書へ移った後に旧対象を編集しない。ドロップはそのトラックを対象にし、選択トラックを追加先の代用にしない。

## 残る範囲

今回のビューはトラックの CLAP チェインが対象である。ヘルパー GUI の表示・フォーカス・再起動、単体追加後の GUI 自動表示、パラメーターの公開と編集、バイパス・オフライン化、複数選択への一括追加、サムネイルは後続の P2-02 に残る。クリップ FX は P2-04、ドラムの発音・親子配送は関連する後続単位へ接続する。共通サンプルブラウザの検索・試聴も今回の完了には含めない。

トラック追加は、展開中のフォルダなら最後の子、折りたたみ中なら部分木の直後の外側へ置くという回答を操作要件へ反映した。フォルダ折りたたみと入口別のトラック挿入は今回未実装であり、末尾追加の現状を新要件の完成へ読み替えない。

## 検査と診断

- モデルで、並べ替えの前後、コピーの新 ID・記録状態、元とミキサーの保持、不正な対象とアンカーの拒否、差分の適用と反転を確認する。操作列の回帰は保存・読込み・ジャーナル再生・Undo / Redo を通す。
- `fx-chain-ui` は実ヘッダへの入力、ネイティブ行ボタンとドロップ先の受理処理から、チェイン順、同一トラックの複製、別トラックのコピー、単一 Undo と保存・再読込を確認する。別トラックへの通常ドラッグを移動に戻すコピーでは期待値で失敗する。通常検査は、古いセッション・不正なペイロード・処理中のドロップの拒否も含める。
- この検査は実ウィンドウを開かず、OS のドラッグセッション全体・パネルの実表示・VoiceOver の実操作・聴感を保証しない。機器なしの回帰とユーザー担当の実操作を区別する。新しい製品契約は既存の `check-product-contracts`、検査登録と選択の回帰へ接続する。
- 2026-10-19 の初回 TSan では、終了済みと新規の保存スレッドの `errno` 読み書きで ADR 0114 と同型の警告が再発した。失敗時の正式レポート・検査ログ・Swift の詳細ログは `target/fx-chain-audit/tsan-errno-before/` に保存した。FX の競合と断定せず、内部原因は未確定のまま、抑制も条件の緩和もせず正式な入口を再実行する。再実行の合格はこの警告の解決を意味しない。
- 操作の失敗は既存の文書アクションのエラーへ返す。診断では文書セッション、元デバイス、追加先トラック、アンカーを区別する。ログは既存の `target/verification/product-contracts/` に入り、debug-report の収集先は追加不要。切り分け方はデバッグ手順へ追記する。

最新の検査結果は `target/verification/report.md` を参照する。設計記録の作成時点だけで全検査の合格や P2-02 の完了を主張しない。
