# ADR 0305: CLI の原因を表示まで型で保持する

日付: 2026-11-10
状態: 採用
関連: M1（DEV-7・SPG-11・XCA-16）、ADR 0291・0294・0304

## 問題と再現

`CliError` は文・取消・保存の不確定の二つの真偽値だけを持っていた。
`render`・`serve`・`mcp` が、型になった I/O・パッケージ・通信・音声・再生の原因を文に戻していた。
`PlaybackControl::plugin_failure` も装置と失敗の種類を文にしていた。
表示から分類すると、元の errno・装置・入力値を型で確認できない。

公開入口の `tests/typed_errors.rs` を先に実行した。
存在しないパッケージの正規化、負のフレーム数、親のない WAV の作成が、それぞれ元の I/O・整数構文の原因を失って失敗した。
期待終了コード 101 と各回帰固有のアサーションを `checked_commands.py` で照合した。
ログは `target/focused-checks/cli-errors-red/` に置いた。

## 比べた案

| 案 | 判断 |
|---|---|
| 文と二つのフラグを残し、元の原因を任意のフィールドに足す | 採らない。文・分類・フラグの食い違いを表現できる |
| CLI 独自の汎用エラーコードへ写す | 採らない。既存の保存・通信・音声の分類を重複して保守することになる |
| CLI 固有の拒否を変種にし、他の層の原因をそのまま持つ | 採る。表示と分類を分離し、元の `Error::source` をたどれる |
| ブロックの失敗文を CLI で解析する | 採らない。エンジンが持つ装置と失敗コードが正本である |
| エンジンから失敗の種類と ID を返し、CLI が表示まで保持する | 採る。音声側の状態や処理は変えず、制御側の結果の型だけを変える |

時間・音質・有効な書出しのメモリ改善は主張しない。
大きな他層の原因は失敗時だけ `Box` に入れ、`CliError` のサイズが 128 バイトを超えないことを回帰で確認する。

## 決定と境界

- `echode-cli/src/error.rs` の `CliError`・`ArgumentError`・`CliIoOperation` を公開する。
  引数は入力値と構文の原因、I/O は操作・既知のパス・元の `io::Error` を持つ。
  リンクを外したノーマライズの scratch は、作成・unlink の後はパスを持たず操作だけを持つ。
- 他層の原因は元の `ApiError`・`PackageError`・`HostError`・`AudioError`・`PlaybackError` を保持する。
  `Error::source` は階層をたどれ、文は `Display` が従来と同じ内容を生成する。
- `PlaybackControl::plugin_failure` は `Option<PluginBlockFailure>` を返す。
  装置 ID・CLAP ID と、処理拒否・期限・送信・非有限値・終了の種類を持つ。
  音声側の既存の数値を制御側で読む時だけ構築する。音声コールバックの確保・待ち・期限は変えない。
- 公開前の取消は `Cancelled`、rename 後のディレクトリ同期失敗は `DurabilityUnknown` にする。
  後者は出力パスと元の I/O を持ち、既存の注入故障だけは元の I/O がない。
  公開済みファイルを削除せず、取消へ付け替えず、自動再試行しない。
- 終了コード（取消 130、その他 2）、stderr・進捗・成功通知・出力先検証の順と保存形式は変えない。
  C ABI・GUI へ新しい構造化応答は追加しない。

## 回帰と基盤

- 公開入口は原因・errno・診断・原本と出力保持、実行ファイルの終了コードと stderr を照合する。
- 単体回帰は原因の転送・引数の構文と範囲・全ブロック拒否の表示・公開後の不確定を照合する。
- ノーマライズの切詰めた scratch は `ReadScratch` と `UnexpectedEof` を保持する。
  隔離の `auto_mute`・`deadline_fade` は実ヘルパーで原因の種類と従来の表示・波形を照合する。
- `check_typed_errors.py` に crate 全体を登録し、既存・新規・入れ子のモジュールへの再導入を Python 回帰で拒否する。
- 設計書・コードの所在・デバッグ手順・監査の統合表と索引を更新する。
  外部入力と実行入口は増やさず、既存の通常検査・隔離回帰・fuzz の対象は変えない。
  Makefile と `scripts/verification.json` の選択条件の追加は不要である。
- `status.md` の制約と利用者の操作は変えず、新しい実画面・実機の確認項目も作らない。

## 残る範囲

M1 全体の完了とはしない。次はアクションの引数エラーを表示文から分類している箇所である。
検査結果と実機・計測の見送り理由は `target/verification/report.md` を正本にする。
