# ADR 0066: プラグインへ届いたノートは、消す前にノートオフを送る

- 日付: 2026-10-13
- 状態: 採用
- 範囲: 製品再生が CLAP 楽器へ渡すノートオフ。イベント容量は [ADR 0065](0065-plugin-event-capacity.md)

## 背景

再生位置の移動とノートの削除で、テスト楽器の出力が 0.70710677 のまま残った（監査 AUD-06）。`place` は内蔵シンセを止め、カーソルを置き直すが、ヘルパーへはノートオフを送らない。`carry` も内蔵ボイスの引き継ぎだけで、消したノートの終了を書かない。

音高だけ変えたノートは同じノート ID のまま鳴っている。そのノートオフは、鳴り始めたキーで届く必要がある。終了のキーを編集後の音高にすると、プラグインは別の音を止める。

停止と一時停止は、そのコールバックでは `render` に入らない。ノートオフを次の再生まで残すと、ストリームを閉じたときに届かない。

## 決定

プラグインへノートオンを届けた計画だけが、ノートオフの責任を持つ。

- 削除や、同じ位置を覆わなくなったノートは、制御スレッドが作った次の計画の先頭へノートオフを書く。まだ覆っているノート（音高だけの変更を含む）はオフしない。カーソルがすでにノートオフを出したノートへは、もう一度書かない。カーソルは、鳴り始めたキーを次の計画へコピーしてから追いかける。
- 再生位置の移動、停止、一時停止は、届いているノートをすべてノートオフにしてからカーソルを置き直す。停止と一時停止では、そのコールバックのうちにヘルパーへ届け、デバイスへ書くサンプルは無音のままにする。
- ループの境界は、再生カーソルが戻り先のノートオンより前にノートオフを書く。この経路は変えない。
- イベント領域は、そのセッションで一度でも必要になった数を下回らない。ノートを消したあとの計画でも、直前まで鳴っていたノートのオフが収まる。これは上限ではなく、開いているあいだの最大値である。音声スレッドでは広げない。

## 結果

CLAP 楽器で、削除・位置移動・停止のあとにはノートオフが届き、出力は鳴り続けない。音高を変えただけではノートオンもノートオフも増えない。そのあと消すと、ノートオフのキーは鳴り始めた音高と一致し、ノート ID はノートオンと同じである。ループが戻るブロックでは、ノートオフのあとに頭のノートオンが届く。画面での操作確認は未実施である。
