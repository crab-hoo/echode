# 0247. CLI の 24 bit PCM WAV 書出し

日付: 2026-11-03
状態: 採用（P2-08 の CLI 先行分。画面・設定保存・ディザは含めない）

## 背景と再現

P2-08 の初期書出しは WAV・24 bit を要件とするが、CLI は 32 bit float だけを出す。
FCA-16 の float メタデータは [ADR 0243](0243-float-wav-metadata.md) で対応済みであり、今回は整数形式を独立した単位として追加する。
`pcm24_cli_exports_stereo_silence_at_multiple_rates_and_block_boundaries` を実 CLI から先に実行し、`--format pcm24` が usage で拒否されることを確認した。
期待終了コードと、この回帰の `PCM24 CLI export failed` を照合する。

## 決定

- `echode render PACKAGE WAV --format pcm24` で、符号付き・リトルエンディアン・詰めた 3 バイトのステレオ PCM を選ぶ。
  `--format float32` も受理する。省略時と公開 Rust 関数 `render_to_wav` / `write_wav` は既存の float のままにし、基準音声を変えない。
- PCM は 40 バイトの `fmt`（WAVEFORMATEXTENSIBLE）を使う。
  形式コード `0xfffe`、24 bit コンテナ・有効ビット、`cbSize=22`、左右前方のチャンネルマスク `3`、PCM の subtype GUID を明記する。
  PCM に `fact` は付けない。ヘッダは 68 バイト、フレームは 6 バイト、RIFF の長さはデータ長に 60 を足す。
- 製品の float ミックスを変更せず、書込みの境界だけで `sample × 2^23` を最近接整数へ丸める。
  ちょうど半分はゼロから遠ざけ、`-8388608..=8388607` へ飽和する。範囲外の有限値を折り返さない。
  演算は f64 とし、フルスケール付近の半 LSB を f32 の途中丸めで失わない。
- ディザ・ノイズシェーピング・ノーマライズはしない。NaN・無限大はエラーとし、整数へのキャストで無音やフルスケールへ隠さない。
  float のサンプルとメタデータは従来どおりである。
- 既存の一時ファイル・バッファ書込み・flush・ファイル同期・同じディレクトリへの rename・親の同期を共用する。
  書込み前のヘッダ長・RIFF 長・バイトレートの検証も形式別に行い、失敗時は原本を保つ。
  rename 後の親の同期失敗は、出力を残して耐久性不明を返す。
- これは既存 WAV ライターへの符号化追加であり、音源・ミックス・RT 処理・保存形式・プラグインの隔離方式は変更しない。
  追加の DSP やファイル形式ライブラリは導入せず、独立した既存 AudioToolbox 読込みで互換性を検証する。

## 回帰と基盤

- `tests/pcm24.rs` は実 CLI で空・1 フレーム・完全／部分ブロックと 44.1 / 48 / 96 kHz の形式・長さ・無音を検証する。
  置いた左右で異なる音声と隔離 Sine Pad を float と比較し、クリップ後の差を半 LSB 以下に制限する。
  出力を製品の `decode_audio_file` でも読み、全サンプル・率・チャンネル・フレーム数を照合する。
- `src/wav_tests.rs` は半 LSB・符号付きゼロ・飽和・極大値・非有限値と、入力の分割を変えた全バイト一致を検査する。
  音を作るエンジン処理は変更せず、書込み側の分割独立性をここで検証する。
- RIFF とバイトレートの上限はヘッダだけで検証し、大容量の音声を確保しない。
  不正オプション・上限超過と、書込み・flush・rename・親の同期の故障注入で出力保全を確認する。
  故障注入はプロセス共通のため、ファイルを書く単体テストを同じ mutex で直列化し、並列実行時の他テストへの漏れを防ぐ。
- 既存の通常 CLI テストの入口に含まれるため、Makefile と `scripts/verification.json` の選択の追加は不要。
  README、設計、P2-08、監査の参照と WAV のデバッグ手順を更新する。ログや収集先の変更はない。
