# 0021. 操作の結果は ChangeSet として残す

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-1

## 背景

ARCHITECTURE §4.2 は、アクションを 1 つ適用するたびに新しい版と「何が変わったか」の一覧（ChangeSet）ができるとしている。今の `Action::apply` は新しい `Project` だけを返す。ジャーナルはコマンドを残し、復旧時にスマートクリップの伸縮などモデルの処理をもう一度走らせる。アプリを更新してその規則が変わると、同じジャーナルから別のプロジェクトができる。

UI の更新、エンジンの差分、自動保存（HIS-3）、履歴の要約（§6.5）は、この一覧を使う想定である。Undo は ADR 0008 のとおり、操作前の `Project` を積む。この案はそれを置き換えない。

MOD-2（クリップの中身と配置）と MOD-4（ノートの基準点と見える範囲）は、オブジェクトの中身を変える。ChangeSet の入れ物は今決め、プロパティの名前はモデルに従わせる。中身の分離とノートの基準点は、それぞれの項目でプロパティを足す。

## 決定

- `apply` は新しい `Project` と `ChangeSet` を返す。一覧は、適用前と適用後をオブジェクトの ID で比べて作る。変わっていないトラックは `Arc::ptr_eq` で読み飛ばす。各アクションが自分の副作用を手で申告する形にはしない
- 1 件は次のいずれかである
  - 作成: オブジェクトの種類、ID、プロパティの値
  - 削除: オブジェクトの種類、ID、消える直前のプロパティの値
  - 更新: オブジェクトの ID、プロパティ名、前の値、後の値
- 粒度はオブジェクトのプロパティである。ノートを 1 つ足したとき、既存のノートの行は、そのノートの保存されている値が変わったときだけ一覧に入る
- 前の版に作成と更新の「後」を当て、削除を消すと、次の版になる。次の版に逆順で、更新の「前」を戻し、作成を消し、削除を戻すと、前の版になる。どちらもスマートクリップの規則は走らせない
- ジャーナルの 1 行には、今までのコマンドに加えてこの一覧を書く。一覧がある行の復旧は、一覧を当てるだけにする。一覧のない古い行は、今までどおりコマンドを再生する
- Undo の実装は、操作前の `Project` を積むままにする。逆向きの一覧は、テストと、後の差分適用（§6.6）が使う
- 今のモデルで一覧に出すプロパティは次である
  - プロジェクト: 拍子。テンポは点ごと（位置、テンポ）
  - トラック: 名前、親、クリップ ID の並び
  - クリップ: 所属トラック、開始、長さ、自動か固定か、ノート ID の並び
  - ノート: 所属クリップ、開始、長さ、音高、ベロシティ
- トラックの並びは、各トラックの `order` で持つ。プロジェクト全体の ID 配列は差分に出さない（[ADR 0024](0024-track-order.md)）。ノートの並びは（開始、音高、ID）の順である（[ADR 0023](0023-note-order.md)）。配置は中身の ID をプロパティとして持つ（[ADR 0022](0022-clip-content-and-placement.md)）。入れ物（作成、削除、更新）は変えない
- 採用したら ADR 0008 の「復旧はジャーナルを再生する」を、一覧がある行は一覧を当てる、に直す

## 結果

`apply` は `Project` と `ChangeSet` を返す。DEV-5 のランダムな操作列で、一覧を前の版に当てると次の版になり、逆に当てると前の版に戻る。ジャーナルに一覧がある行は、コマンドを再実行せずその一覧を当てて復旧する。
