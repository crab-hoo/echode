# ADR 0054: 自動保存した版を新しい版として戻す

- 日付: 2026-10-11
- 状態: 採用
- 範囲: Phase 1 の履歴一覧と、プロジェクト全体の復帰

## 背景

自動保存は `refs/echode/autosave/main` にコミットを積む。クラッシュ後はジャーナルを再生して戻る。Phase 1 の完了条件には、履歴から前の状態へ戻すことが含まれる。ARCHITECTURE §6.6 の試聴、サムネイル、トラック単位の復帰は Phase 4 で決める。

`history.restore` を普通の編集コマンドとしてセッションへ渡すと、読み込む版がまだ無い。版は Git のコミットにあり、文書スレッドだけがリポジトリを持つ。

## 決定

一覧と復帰は文書スレッドで行う。未完了の自動保存を待ってから、先端から親を辿ってコミット ID と時刻を新しい順に返す。循環は一度見た ID で止める。

復帰は、指定したコミットのプロジェクトを読み、不変条件を確認してから現在のプロジェクトとの差分を取る。差分が空なら Undo もジャーナルも自動保存も増やさない。差分があるときは、戻す前のプロジェクトを Undo に積み、Redo を捨て、`history.restore` とその差分をジャーナルへ書く。自動保存は今の先端を親にする新しいコミットであり、過去のコミットは書き換えない。

アプリはメニュー、ツールバー、コマンドパレットから一覧を開く。いちばん新しい行が今の版である。それ以外を戻すと表示を新しいスナップショットへ替え、Undo を一つ増やす。同じ版を戻しても Undo は増えない。再生中のグラフは戻したプロジェクトへ追従する。

JSON-RPC の `actions.perform` も同じ文書スレッドを通るので、このコマンドを受け付ける。C ABI は履歴コマンドの完了スナップショットに `{revisions, changed}` を載せる。ほかの操作のスナップショットは空の一覧である。

## 結果

トラックを二回追加したあと、古い版へ戻すと名前は一つになり、Undo で戻る。文書を開き直しても戻した版が残り、古いコミット ID は一覧に残る。画面を開かない Swift の検査で、同じ経路を確認する。

トラックだけの復帰、縮小画像、要約、試聴の方式は今回含めない。
