# 0374. 音声ポートの寸法を変えない通知を許可し、再有効化前に構成を検証する

- 日付: 2026-11-15
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: F2・FCA-07・P2-03 の `clap.audio-ports`
- 一部置換: [ADR 0355](0355-clap-audio-port-name-rescans.md) の名前だけを許可する判断

## 背景

CLAP 1.2.2 の [audio-ports.h](https://github.com/free-audio/clap/blob/1.2.2/include/clap/ext/audio-ports.h) は、32 bit 音声を必須、64 bit と in-place を任意とする。
名前以外のポート変更は無効化中だけに許す。
Echode は別々の f32 バッファを使い、ポート型や精度・alias のヒントを保持していない。
このため、寸法を変えない変更まで拒否する必要はない。
一方で、再起動時に音声ポートを読み直しておらず、構成を変えたプラグインを初回のバッファで再有効化する経路があった。

## 比べた案と決定

- **名前だけを許可し続ける**: 不採用。
  フラグ・ポート型・in-place ペアは、現在の f32・非 alias・index 順の処理を変えずに受けられる。
- **全フラグを許可し、既存の再起動だけを使う**: 不採用。
  再起動は初回の共有領域・バッファ・親のルーティングを交換しない。
  ポート境界だけが変わる場合も、合計チャンネル数の一致だけでは安全を保証できない。
- **ヘルパー内で新しい寸法へ切り詰め・ゼロ補完する**: 不採用。
  不一致を隠し、音声の欠落や意図しないチャンネルの接続を作る。
- **寸法を変えない通知を許可し、初回の構成を不変条件にする**: 採用。
  対応を答えるのは単一の NAMES・FLAGS・PORT_TYPE・IN_PLACE_PAIR だけとする。
  CHANNEL_COUNT・LIST・未知のビット・0・複合の問合せには偽を返す。
  通知のビットの併用は受けるが、通知からプラグインの記述の読込みへ再入しない。

`PortShape` は入力・出力それぞれのチャンネル数と ID の index 順を初回に保持する。
再有効化する入口を `Bridge::reactivate` に集め、無効化が戻った後に記述を読み直して一致を検証する。
通知がなくても毎回検証し、ID の置換、同じ合計数でのポートの分割、入力側・出力側どちらの寸法変更も拒否する。
記述の取得失敗・ゼロポートも既存の型付き原因で失敗させる。
失敗では有効化・処理器の受渡し・再起動の完了通知をせず、固有の診断を残して隔離ヘルパーを停止する。

名前だけの通知では記述の読込みも再起動もしない。
追加の読込み・確保・比較は主スレッドの再有効化前だけであり、音声処理と IPC・保存形式は変えない。
ポート数・チャンネル数の動的変更には、共有領域と親のルーティングを一緒に交換する別の実装が必要で、対応と申告しない。
MIDI / MPE / MIDI 2.0 の曲入力も残るため、F2 全体の完了とはしない。

## 回帰と基盤

`isolation/audio_ports.rs` は実ヘルパーで全 32 ビットと無効な問合せ、初期化・主スレッド callback・無効化中の通知を通す。
有効化中の記述読込みは fixture が失敗として記録する。
名前の通知では初回の 2 記述だけを読み、メタデータを往復させる各再有効化では 2 記述ずつ読み直す。
1・32・127・256 フレームで、ヒントにかかわらず従来の音声を保つことを照合する。
入力・出力のチャンネル数、同じ合計数の分割、入力・出力の ID の置換、記述の拒否とゼロポートには停止を求める。
fixture の有効化ログで、変更の検出が再有効化より前であることも照合する。

変更前の対応フラグでは `audio-port capability/lifecycle probe failed: [128, 1, 2, 0]`、フラグだけを更新した版では `changed audio-port layout reached reactivation: mode 2` で失敗した。
期待終了コード 101 と各回帰固有のアサーションを照合した証拠は `target/focused-checks/audio-port-metadata-red/` と `target/focused-checks/audio-port-layout-red/` に残す。
時間・メモリの改善量は未計測であり、上記の記述数は fixture の動作の照合値である。

通常の workspace テストと既存の `under_rtsan` の選択を使い、新しい検査入口は作らない。
必須契約の reset・MIDI 終了処理の入口は変えない。
設計書・Phase 2・制約・監査の現在欄・コードの所在・診断手順を更新する。
新しい画面操作はなく、新規の UC は不要である。第三者互換は UC-80〜83 に残す。
