# 0043. プラグインは依頼してから、まとめて受け取る

- 日付: 2026-10-09
- 状態: 採用
- 項目: ENG-7

## 背景

プラグインは別プロセスである。今の `request` は、共有メモリへ世代を公開したあと、その完了を待ってから戻る。独立したヘルパーが 2 つあっても、2 回目の依頼は 1 回目の完了の後になる。往復が 20 µs なら 50 本で 1 ms になり、64 フレーム / 48 kHz の 1.33 ms の大半を使う。

並列にできるのは、エンジンのワーカーがプラグインを呼ぶことではない。プラグインは別プロセスで、ワーカーがそこで待ってもコアは増えない。増えるのは、入力のそろったヘルパーへ先に依頼を出し、そのあとでまとめて受け取ることである。

スロット、欠落、検証するイベント、`posix_spawn` は [ADR 0042](0042-plugin-ipc.md) のとおりである。オーディオスレッドがワーカーの完了を待たない規則は [ADR 0003](0003-audio-thread-does-not-wait.md) のとおりである。同じヘルパーで続くデバイスを 1 往復にするのは PLAN §6 である。

## 決定

1 ブロックのプラグイン処理は、依頼と受け取りに分ける。

依頼は、そのヘルパーの空いているスロットへ入力とイベントを書き、世代を公開してヘルパーを起こし、すぐ戻る。待たない。スロットが 2 つとも未完了なら、そのブロックは欠落とし、無音にする。公開した世代は上書きしない。

受け取りは、そのブロックの締め切りをひとつだけ使う。待ち時間は、その時刻までの残りである。ヘルパーごとに締め切りを足さない。時刻を過ぎたら、まだ終わっていないヘルパーはすべて欠落にし、遅い出力は読まない。ハングはプロセスが終わらないので、この同じ締め切りのままである。終了は kqueue が待ちを起こす。

待ちは、ヘルパーごとの完了アドレスではない。親が作った 1 語の fan-in を、終わったヘルパーがそれぞれ進める。`os_sync_wait_on_address` は 1 アドレスしか待てないので、遅いヘルパーの完了だけを待っていると、先に終わったヘルパーの後続ノードを起こせない。fan-in が変わったら、終わっているヘルパーだけを受け取り、そのヘルパーに依存するノードだけを準備完了にする。まだ走っているヘルパーの後続は、そのヘルパーが終わるまで準備完了にしない。

依頼のあと、オーディオスレッドは準備完了の CPU ノードを自分でも取る。残りのノードが、ワーカーで実行中か、飛び中のヘルパーだけになったときだけ、fan-in で待つ。プラグインのために待ってよいのは、そのときだけである。

ワーカーはプラグインを呼ばない。ヘルパーを待たない。

同じヘルパーで続くデバイスは、1 つの世代で処理する。順番は、制御ソケットの `SetChain` で渡す。処理スレッドは、その段の数だけ `process` を呼び、前の段の出力を次の段の入力にする。途中のバッファは、プラグインを起動したときに確保したものを使い回し、ブロックごとには確保しない。親は段の数だけ往復しない。

イベントの振り分けは、ADR 0037 の `Event` には足さない。グラフはデバイスごとのイベント列をすでに持っている。1 つの世代にまとめるとき、ホストがレコードの空きへ段の番号を書く。ヘルパーはその番号が段の数未満のレコードだけを残す。番号は列挙型として読まない。

依頼も受け取りも、オーディオスレッドではロック、メモリの確保、ファイルの読み書きをしない。触るのは、今の共有メモリと、fan-in の起床だけである。

この項目では、計測用の 1,000 ノードのグラフへプラグインを載せない。デバイスのコールバックからプロジェクトを鳴らすこともしない。テストは、ヘルパーを 2 つ依頼してから受け取り、壁時計が 1 往復に近いこと、遅いヘルパーが残っていても速いヘルパーを先に受け取ること、2 つのハングが 1 つの締め切りで戻ること、同じヘルパーの 2 段が 1 回の受け取りで入力の 4 倍になり、段の外のイベントは落ちることを見る。

## 結果

採用した。fan-in で複数のヘルパーを待ち、段の順番は `SetChain`、イベントの段番号はレコードの空きに書く。0037 の `Event` は変えていない。
