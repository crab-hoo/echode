# ADR 0104: 停止クリックの再報告を実出力の記録で切り分ける

- 日付: 2026-10-16
- 状態: 採用。ユーザー報告の停止クリックは未解決。
- 範囲: ライブ停止のループ境界、任意で有効にする出力診断。

## 分かったことと分かっていないこと

ユーザーは ADR 0103 の `target/stop-click/Echode.app` でも、複数種類の音源で停止クリックが出ると確認した。ループは無効だった。既存の位相付きPCMのテストが通ることは、報告された聴感の原因を特定できた証拠ではない。減衰時間や閾値をさらに変えて解消と扱わない。

調査では別の不具合を再現した。`render_stop_tail` がループ境界を外していたため、素材に掛かっていたループのフェードが停止時に消えた。48 kHz、停止位置120、1フレームの入力では、停止直後の期待値0.125523に対し0.25へ跳ねた。`target/noise-audit/stop-loop-before.log` に失敗を保持する。ユーザーのループ無効の再現の説明にはしない。

停止時のループ境界を保持し、素材は現在のループの末尾まで処理する。ループの次の周回や範囲外の素材は鳴らさない。現在の音源のボイスとエフェクトの処理は従来の停止減衰を使う。48/96 kHz、ループ先頭・末尾の途中、1/7/64/512フレームを独立したゲインの期待値と比較し、ブロック長からの独立性も確認する。

## 実出力を記録する

`ECHODE_STOP_TRACE_DIR` を設定した診断版だけ、HALへ返す直前の実際の出力バッファを記録する。通常のビルドでは無効。実行時の環境変数か、診断版をビルドする時の同名の環境変数で出力先を指定する。ビルド時の `ECHODE_TRACE_BUILD` はソースの識別値を記録するために使う。診断版の出所と有効化条件を別バンドルのビルド記録に残す。

もう一つの音声ストリームや再生器は作らず、マイクも開かない。録るのは出力の最初の2チャンネルで、モノは比較のため両側へ複製する。実機のチャンネル数を制限する仕様ではない。

コールバックは事前確保した約0.5秒と2ブロックの循環領域にPCMとブロック情報をコピーする。停止から50 ms分の記録後、領域の所有権をSPSCキューで制御スレッドへ渡す。制御側だけがファイルを書き、同じ領域を返す。確保・ロック・ファイルI/Oを音声側へ追加しない。制御側が領域を持つ間の診断は省略するため、連続操作の網羅的なレコーダーではない。

停止命令がワーカーに届く前の取消と、後から届く一時停止を、0/1/20ブロックの遅れで確認する。インターリーブ、平面、モノの実出力バッファと、記録したPCMがビット単位で一致することを通常検査とRTSanで確認する。循環領域の折返し、NaNのビット保持、領域の再利用も検査する。

## 証拠の形式と限界

- `.f32le`: ヘッダーなしの左右順32ビット浮動小数。出力に渡した値を無加工で保持し、NaNや過大振幅も隠さない。
- `.json`: 版、レート、対応するPCM、保持範囲、停止の位置、ブロックごとの再生位置・取消状態・出力世代・停止減衰位置・機器変更・不正バッファ・音声側のエラー・プラグイン失敗累積。
- `render_ns`: 診断コピー前までの処理時間。`elapsed_ns`: 診断コピーも含む処理時間。`entry_ns`: 同じストリーム内のコールバック開始時刻。`output_host_time`: HALが渡した出力のホスト時計。

この記録から、波形の段差、減衰の中断、無音への置換、プラグイン失敗、処理時間や呼出間隔の異常を分ける。`stop_retained=false` の記録は停止点を保持していない。時刻やフラグがあるだけで性能・聴感の合格とはしない。出力デバイスやDACの後で生じる音は、このPCMには含まれない。ファイルが作られない時も成功扱いにせず、診断版の出所、書込エラー、操作中の終了を確認する。

`stop_frame` は停止を最初に観測したブロックの先頭で、操作した正確な時刻ではない。描画中に取消を観測した場合は、その処理中のブロックを完了してから減衰するため、次のブロックの `stop_fade_offset=0` も照合する。各ブロックの `sample` は処理後の公開サンプル時計である。

記録にはユーザーが再生した音が含まれるため、通常の `debug-report` に自動でコピーしない。専用ディレクトリ内に置き、共有対象はユーザーが選ぶ。アプリの操作と実機・聴感テストはユーザーが担当する。エージェントは診断版を別の場所へビルドし、既存アプリを終了・置換・起動しない。

## 同日の実出力の調査結果

ユーザーの7回の再現から、減衰後の破棄する処理の完了待ちが、次のコールバックを遅らせていることを確認した。[ADR 0105](0105-nonblocking-stop-cleanup.md) に証拠と待機なしの修正を記録する。新しい診断には `cleanup_pending` を追加する。上記の未解決・未特定の記述は診断追加時点の経過として保持する。
