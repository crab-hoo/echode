# ADR 0124: 選択トラックへの FX 一括追加を単一の編集として保存する

- 日付: 2026-10-19
- 状態: 採用。P2-02 の一部
- 範囲: アレンジヘッダの複数選択、候補の右クリックメニュー、製品 ABI の一括編集

## 背景

[操作要件](../interaction-design.md#fx-候補とチェインの操作) は、候補の右メニューから全選択トラックへ追加する。
既存のヘッダと `ProjectController` は単一選択だけを持ち、製品 ABI も単一アクションしか受けなかった。
Swift から追加を繰り返すと、途中失敗の部分追加と複数回の Undo が生じる。

## 決定

- 選択 ID の集合と単一のフォーカストラックを UI 状態として区別する。
  ヘッダの通常クリックは置換、Command クリックは追加・解除、Shift クリックは直近の基点からの範囲選択とする。
  FX ボタンは選択内のフォーカスだけを変え、未選択ならその 1 トラックへ置換する。
  選択は保存・Undo の対象にせず、削除・文書交換時に古い ID を除く。
- 選択行の背景は既存の単一 Metal フレームへ渡し、アクセシビリティの選択状態も同じ集合を参照する。
  ノート入力、通常の候補挿入、ドロップ先は引き続き単一の対象を使う。
  複数選択したミックス操作とノートの一括編集は、それぞれ P2-06 / P2-07 の範囲に残す。
- 候補の「選択トラックすべてに追加」は、クリック時にプラグイン ID・文書セッション・表示順の選択 ID を値として保持する。
  非同期の実行中に選択が変わっても追加先を変更しない。
  成功後も候補パネルを保持する。単体のダブルクリック・Return は従来どおりフォーカストラックだけへ追加する。
- `echode_document_submit` の JSON は、従来の単一オブジェクトに加えてアクション配列を受ける。
  配列は同じ文書ワーカーから既存の `DocumentHost::apply` へ渡す。
  全要素を単一 Undo / Redo・ジャーナル行・音声計画更新として扱い、途中失敗では全要素を戻す。
  空配列は既存トランザクションと同じく履歴を変えない。C の関数・所有権・保存スキーマは変えない。
- 一括追加では各 `device.add` が別のデバイス ID を採番する。
  プラグインの生成・隔離・再生・書出しは既存経路を共有し、UI プロセスでロードしない。

## 回帰と診断

- 橋渡しの `TransactionTests` は配列が拒否される旧実装で失敗を確認した。
  成功時の単一 Undo / Redo、モデル拒否・不正要素時の全体巻戻し、空配列と失敗後の Redo 保持を検査する。
- `PluginBatchTests` は実ヘッダの Command / Shift と FX ボタン、描画入力、確定対象、別 ID の生成、保存再読込を検査する。
  必須契約は `scripts/verification.json` に登録し、一括対象を単一対象へ戻す負の対照でも期待値が失敗することを要求する。
- 欠けた対象・空選択・重複対象・旧文書は部分追加せず拒否する。
  実画面のメニュー操作・GPU 表示・聴感は自動回帰とは区別し、未確認を合格としない。
