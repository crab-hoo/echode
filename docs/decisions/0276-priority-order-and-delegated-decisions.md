# 0276. 優先順位を定め、判断をエージェントへ委ねる

- 日付: 2026-11-08
- 状態: 採用
- 関連: [PLAN §2](../PLAN.md#2-決定事項)、[AGENTS.md](../../AGENTS.md)、[ADR 0212](0212-verification-tiers.md)、[ADR 0269](0269-github-public-ci-scope.md)、
  [横断監査](../reviews/2026-11-02-cross-cutting-audit.md)、[全体のコード監査](../reviews/2026-11-03-full-code-audit.md)
- 置き換え: 監査の実行指示（[2026-11-02](../reviews/2026-11-02-fix-instructions.md#実行役が決めないこと)、[2026-11-03](../reviews/2026-11-03-fix-instructions.md#実行役が決めないこと)）の「実行役が決めないこと」のうち、下の予約の外にある項目。
  AGENTS.md の「頼まれていないコミットはしない」

## 背景

製品と作業の方針に、項目どうしの優先順位がなかった。
案を比べる基準がないため、意味・形式・既定値を選ぶ場面の多くが「ユーザーの判断待ち」として残っていた。
2026-11-08 に数えると、技術的な判断待ちが約 20 件あった（フォルダの音量・パン、ジャーナルのまとめ書き、保管庫の形式、Undo の予算、待ちと走査の期限、安全な出力、基準音声の再生成、検査の期限、キャッシュの削除、デバイスビューの複数選択、キー割当、操作の初期値など）。
同日、ユーザーが優先順位を示し、予約した事項の外の判断をエージェントへ委ねた。

## 決定

### 優先順位

**堅牢性 > 保守性 > 効率 > 見た目・機能** の順に取る。

- **堅牢性**: データを失わない。止まらない。誤った結果を黙って返さない。
  音切れ・GUI の停止・入力の取りこぼし・クラッシュからの復旧失敗は堅牢性に数え、効率には数えない。
- **保守性**: 単純で、変更しやすく、検査で守られている。暫定の意味や後で移行が要る形を作らない。
- **効率**: 処理時間・メモリ・ディスク・検査時間を、上の 2 つを下げない範囲で減らす。測ってから変える。
- **見た目・機能**: 新しい機能と外観は、上の 3 つを下げない時に足す。

案が衝突したら上の段を取る。同じ段で差がない時は、次の段で比べる。
上の段を下げて下の段を得る案は、その差を測った値と理由を ADR に書いても採らない。
例外は、下の段の不足が上の段の失敗になる時だけである（例: 遅さが音切れになる時は、その改善を堅牢性として扱う）。

### ユーザーに予約する事項

エージェントは、次の事項だけを実行の前にユーザーへ確かめる。

- リモートへのプッシュ、公開範囲の変更、配布物のリリース
- 製品名・ロゴ。決まるまで Echode を仮名、`.echode` を仮の拡張子として使う
- ライセンスと、依存のライセンス方針（[PLAN §2.1](../PLAN.md#21-ライセンス方針の影響)）の例外
- ユーザーが作ったデータ（プロジェクト・録音・取り込んだ素材）の削除。再生成できるキャッシュと生成物は含まない
- 費用の発生（有料のサービス・購入）
- 実機・聴感・第三者プラグインの確認（[ユーザー確認の一覧](../user-checks.md)）
- この ADR の方針の変更

### それ以外はエージェントが決める

- 予約の外の判断は、優先順位に従ってエージェントが決める。判断待ちとして残さない。
- 比べた案、選んだ理由、測定値を ADR に書き、最終報告で決めたことを知らせる。
  ユーザーが後で覆す時は、新しい ADR で置き換える。
- 操作の細部（キー割当、初期値、表示）は、macOS と主要な DAW の慣例を既定にする。操作感はユーザー確認の一覧で確かめる。
- 保存形式・スキーマ・ジャーナルの確定の意味を変える時も、旧版の読込み・移行・復旧の回帰を同じ作業で足せば、エージェントが決めてよい。

### コミット

- `make verify` が通った作業ごとに、自分の変更だけを `main` へコミットする。依頼を待たない。
- プッシュは頼まれた時だけ行う。

## 判断待ちだった事項の決定

各項目の実装は、それぞれの作業で ADR を書いて行う。ここでは向きだけを決める。下の「未実装」は製品が変わっていないことを示す。

| 事項 | 決定 | 理由 | 状態 |
|---|---|---|---|
| フォルダの音量・パン（FCA-06） | 祖先の音量とバランスを、子孫の実効フェーダーへ左右の係数の積として掛ける。操作子は無効にしない | 係数は線形なので、フォルダに FX がない時は P2-03 のバスで和に掛けた結果と一致する。保存値を後で急に効かせる移行がない（堅牢性・保守性） | 未実装 |
| ジャーナルのまとめ書き（FCA-14） | 行わない。編集ごとの `F_FULLFSYNC` を保つ | 確定の意味が単純なまま保てる。p50 4.0 ms は通常の編集の応答の範囲にある。連続編集の応答が期限を超えると測れた時に、確定の返答を同期の後に保つ形で見直す | 決定のみ（現状維持） |
| 保管庫の PCM の形式（FCA-18） | 非圧縮 f32 を保ち、スキーマを変えない。書込みの一時的な 2 倍のメモリは、形式を変えずに流して書いて減らす | 復号器の版に音が左右されない。ディスクの量は効率の段で、可逆圧縮はディスクが実際の制約になった時に既存の実装を測って選択肢にする | 流しの書込みは未実装 |
| Undo とジャーナルの予算（FCA-19） | 段を捨てない。先に使用量を診断へ出す。予算を入れる時は、古い段を Git の履歴へ移す方式に限り、固定の段数上限は置かない | 履歴を失わない（堅牢性）。測る前に予算の値を決めない（効率は測ってから） | 未実装 |
| 待ちの期限（FCA-09） | UC-16 を待たずに決めてよい。期限は出力時刻と機器の安全余白から求める向きにする | HAL の余白を残すことは音切れを防ぐ堅牢性の要件である。UC-16 は聴感の確認として残る | 未実装 |
| 走査の期限（FCA-20） | 初回の走査は長い期限にし、時間切れのバンドルは再試行できるようにする。値は測って ADR に書く | 遅いだけのプラグインを壊れたと誤判定しない | 未実装 |
| 段の間の非有限値と安全な出力（XCA-21） | 段の間の NaN・無限大は 0 にする。実機への出力だけに安全な上限を置き、書出しの値は変えない | 次のプラグインの状態と再生装置を守る（堅牢性）。書出しの結果は変えない | 未実装 |
| release の最適化設定（XCA-21） | 音声の経路で測って決める | 効率の段であり、測ってから変える | 未着手 |
| 基準音声の再生成（`make bless`） | 音の変化が意図した結果で、理由と差の測定値を ADR に書いた時に限り、エージェントが行ってよい。無関係な変更と同じコミットにせず、自動の検査に混ぜない | 回帰を隠さない（堅牢性）。聴感はユーザー確認の一覧へ足す | 決定 |
| 検査の期限 | 測定値と理由を ADR に書けば、エージェントが変えてよい | 待ちの理由で作業を止めない | 決定 |
| `make verify-full` の相談 | 相談しない。全体の段階は GitHub の `full` が担う | [ADR 0212](0212-verification-tiers.md)・[ADR 0269](0269-github-public-ci-scope.md) で手元の完了条件から外れている | 決定 |
| キャッシュの削除 | 再利用できない生成物は消してよい。現在有効なキャッシュは残し、空きが検査に足りない時だけ、再生成の時間を見積もって消し、報告する | 再生成できるのでユーザーのデータではない。次の検査の速さを保つ | 決定 |
| 作業ツリーの共有（XCA-07） | `main` の単一の作業ツリーを既定にする。他の作業の失敗で `make verify` が止まる時は、待って再実行し、なお止まれば自分の変更と無関係である根拠を最終報告に残す | worktree の容量はユーザーが避けている。待ちを相談に切り替えない | 決定 |
| Codex のフック（XCA-06） | エージェントが直してよい。Codex が設定を再び信頼する手順は、ユーザーが Codex を使う時に行う | ホストの操作はユーザーの画面で行う | 未着手 |
| プッシュの間隔（XCA-04） | ユーザーに予約する | リモートへの送信は予約の事項である | 予約 |
| 複数選択時のデバイスビュー（ADR 0131） | フォーカスしたトラックだけを表示する現状で確定する | 主要な DAW の慣例で、表示の対象が一つに決まる（保守性） | 決定（現状維持） |
| キー割当（ADR 0159 の追従など）とショートカットの詳細 | macOS と主要な DAW の慣例でエージェントが決める | 操作の細部は委任の範囲である | 決定 |
| 操作の初期値（[操作要件の次に詰める点](../interaction-design.md#次に詰める点)、ADR 0116 のドラム、ADR 0135 の試聴） | 各単位を実装する時に、主要な DAW の慣例を既定にして ADR に書く | 同上 | 決定 |
| テーマ配色、自動保存と履歴の間引きの初期値（PLAN §9） | 配色は macOS の標準色を既定にする。自動保存と間引きは測って決める | 見た目は最後の段。間引きは容量と復旧を測って決める | 決定 |

## 影響

- 監査の実行指示の「実行役が決めないこと」は、過去の証拠として残し、日付付きの注記でこの ADR を示す。
- 実装が要る項目（FCA-06・09・18・19・20、XCA-06・21）は、まだ製品を変えていない。[現在の制約](../status.md) は実装されるまで現在の挙動を書く。
- 実機・聴感の確認は引き続きユーザーが行い、未確認を合格にしない。
- 予約の外で判断を仰ぐ文言を新しく書かない。迷う時は、この ADR の優先順位で決める。
