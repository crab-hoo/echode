# 0028. パッケージは版を順に上げ、出力の形はスナップショットで固定する

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-10

## 背景

製品のパッケージはスキーマ 1 の JSON で、版が違うと読むのを拒むだけである。手で文字列を組んでいるので、キーの順やエスケープが変わっても、既存の往復テストは通り得る。`deny_unknown_fields` があるので、項目を足したあとのファイルは古いアプリでは開けない。これは意図どおりである。古いファイルを今の版へ直す経路が無い。

ARCHITECTURE §6.2 は、同じ状態から同じバイト列を作り、ノートは 1 行にし、スキーマの版と移行を持つとしている。

## 調査

スナップショットテストは `insta` 1.49.0（Apache-2.0）が、監査の挙げる選択肢である。開発時の依存だけで、製品のバイナリには入らない。`cargo deny` の許可するライセンスに Apache-2.0 は入っている。

## 決定

- 読み込みは、ファイルを一度 `serde_json::Value` にする。`schema` が現在の版より小さいときは、`1 → 2`、`2 → 3` のように隣の版へ上げる関数を、その順に適用する。上げたあとに、今の構造体で `deny_unknown_fields` のまま読む。現在より新しい版、欠ける版、整数でない版は拒否する
- 今の版は 1 である。1 より前のパッケージは無いので、上げる関数はまだ空である。版を 2 にするときは、1 の見本ファイルは書き換えず、`1 → 2` の関数を 1 つ足す
- 版 1 の見本は `crates/echode-history/tests/fixtures/schema-1/` に置く。`project.json`、中身 1 つ、トラック 1 つで、ID は固定する。テストは、この見本を読んで今のモデルになることを確かめる
- 出力は、値の JSON を `serde_json::to_string` で作り、改行とインデントだけをこちらで付ける。文字列のエスケープは serde が行う。ノート、テンポの点、パラメータ、配置は、それぞれ 1 つのオブジェクトを 1 行にする。キーの順は、シリアライズする構造体のフィールド順である
- `f32` の表記は ADR 0022 のままにする。0 は `0`、1 は `1`、それ以外は小数点以下 9 桁に丸めて末尾の 0 を落とす。serde_json の数値の書き出しでこの表記を使い、既定の `1.0` にはしない
- 同じプロジェクトは同じバイト列になる。そのバイト列を `insta` 1.49.0 のスナップショットで固定する。スナップショットはテストの横のファイルにし、ID は見本と同じ固定値を使う。`make check` はスナップショットを書き換えない。形を変えるときは、差分を見てからスナップショットを更新する
- ジャーナルと、計測用の古いパッケージ書き出しは、この移行の対象にしない

## 結果

`make check` が通った。版 1 の見本を読むと今のモデルになる。同じプロジェクトを書き出すと、スナップショットのバイト列になる。版 2、版 0、整数でない版、版の無いファイルは拒否する。ゲインの 0 は `0`、1 は `1`、4 は `4`、パンの下限は `-1` のままである。値の区切りは serde の詰めた形になった。
