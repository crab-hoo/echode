# ADR 0057: 開いた時に自動保存の基点を作り、書き出しは置いた音声を混ぜる

- 日付: 2026-10-11
- 状態: 採用
- 範囲: Phase 1 の強制終了からの復旧と、CLI の WAV。波形のピーク、Ogg、配布用の署名は含まない

## 背景

確定した編集は、結果を返す前にジャーナルへ同期される（[ADR 0033](0033-journal-log.md)）。復旧は、読める自動保存があればそのコミットに後続のジャーナルを重ねる。コミットが一度もなく `save.pending` があるときは、混ざった作業ツリーへログを重ねず失敗する。最初の自動保存は編集のあと非同期なので、その保存の途中でプロセスが落ちると、確定済みの編集があっても開き直せない。

CLI の書き出しはテスト用シンセだけで、置いた音声は無音だった。製品の再生は同じファイルを鳴らす（[ADR 0056](0056-audio-import.md)）。基準の WAV はノートだけである（[ADR 0019](0019-offline-wav.md)）。

## 決定

`DocumentHost::open` は、自動保存の先端が無いとき、編集を受ける前に復旧したプロジェクトを同期的にコミットする。コミットの連番は、再生したジャーナルの最後である。ジャーナルが空なら 0 である。先端が既にあるときは、開く処理ではコミットしない。

このコミットの途中で落ちた場合は、開く処理が戻っていない。`save.pending` があり先端が無ければ、これまで通り復旧は失敗する。開いたあとに確定した編集は、次の自動保存が途中で切れても、基点のコミットにジャーナルを重ねて戻る。

強制終了の確認は、製品の C ABI でトラックを追加し、完了コールバックのあと `libc::_exit` でプロセスを止めてから、同じパッケージを開き直す。デストラクタの走る終了は使わない。

`echode render` は、置いた音声を製品の再生と同じ読み込みでデバイスレートへ変換し、シンセのあとに足してからフェーダーを通す。音声だけの長さは、最後のクリップの終わりである。シンセのリリースはノートがあるときだけ足す。ループとメトロノームは書き出しに含めない。ノートだけの基準 WAV は変えない。

## 結果

基点がある状態で `save.pending` を置いても、その後のジャーナルは復旧される。C ABI の強制終了のあと、追加したトラックが残る。ノートだけの 128 フレームは基準の WAV とバイト列で一致する。置いた WAV は書き出しに残り、オフラインのクリップは製品の再生と同じサンプルになる。画面での操作確認は未実施である。
