# ADR 0065: ノートが増えたら、生きているヘルパーのイベント容量を広げる

- 日付: 2026-10-13
- 状態: 採用。容量変更中の処理省略は [ADR 0102](0102-exclusive-audio-graph.md) で撤回
- 範囲: 製品再生がプラグインへ渡すイベント数。トラックの並びが変わらないときのヘルパーの寿命は [ADR 0049](0049-hosted-playback.md)

## 背景

プラグインを空のトラックへ挿してから和音を足すと、ノートオンが 1 音しか届かなかった。ノートを先に置くと 3 音届いた（監査 AUD-05）。新しい再生計画はノート数に合わせてイベント領域を持つが、デバイスの並びが同じ編集ではヘルパーを交換しない。共有メモリと、音声スレッドが使う配送バッファは、最初の容量のままだった。足りないイベントは末尾から捨てられ、ノートオフが落ちると音が残る。

## 決定

デバイスの並びが同じで、必要なイベント数が今の容量を超えるときは、制御スレッドが各ヘルパーのマッピングを `Remap` で広げ、配送バッファも同じ数まで予約する。プラグインのプロセスは置き換えない。

コールバックがそのグラフを使っているあいだ、制御スレッドは入らない。コールバックは制御スレッドが容量を広げているブロックでは、新しい計画を消費せず、プラグイン処理を飛ばす。容量を広げる確保は制御スレッドで行う。ヘルパーは、広がったマッピングを読み始める前に、自分の復号バッファを一度だけ予約する。

音声スレッドは配送バッファを超えて確保しない。計画側のイベント数に容量を合わせるので、ブロック内のノートオンとノートオフはそのバッファに収まる。

## 結果

プラグインだけのトラックへ、開始と終了が同じブロックに入る 3 音を足すと、ノートオン 3 とノートオフ 3 が届く。1 音を鳴らしたあとで 2 音を足しても、最初のノートオンはプラグインの中に残る。画面での操作確認は未実施である。

## 2026-10-16 の訂正

容量変更中のプラグイン処理省略は音声の連続性と共有ロック禁止の規則を破っていた。[ADR 0102](0102-exclusive-audio-graph.md) でこの判断を置き換える。準備中も現在のグラフと共有メモリで処理し、用意した計画・音声バッファを境界で一緒に交換する。本文は当時の誤った判断の記録として保持する。
