# ADR 0241: 配置の PCM をゲインとモノの昇格から分ける

日付: 2026-11-03
状態: 採用
関連: [FCA-10](../reviews/2026-11-03-full-code-audit.md#fca-10-クリップゲインの焼き込み)、[ADR 0113](0113-product-macos-workgroup-and-caches.md)

## 背景

配置の窓の鍵にゲインが入り、変更するたびに配置の全サンプルを複製していた。
短いトリムしか残さないキャッシュでは、元ファイルの再読込み・SRC まで必要だった。
同じトラックにステレオの配置がある場合は、計画を作るたびにモノの配置を 1/√2 倍した平面も作っていた。

`shared_pcm_survives_placement_edits_without_rereading_media` に、ゲイン変更前後の左右の `Arc::ptr_eq` を追加した。
修正前は `clip gain copied the whole placement PCM` で失敗することを確認した。
時間ではなく、製品の素材ローダーが同じ平面を保有しているかで再現する。

## 決定

- `WindowKey` は素材・内容位置・長さだけとする。窓には未スケールの PCM を保持する。
- `LoadedClip` と計画の `StoredClip` に線形ゲインを持たせる。
  `add_stored_clips` が読むブロックの範囲だけに適用し、音声スレッドで確保・ロック・I/O はしない。
- モノの昇格も係数として適用する。モノの平面と `right: None` を計画へそのまま共有し、必要な時だけ同じ平面を左右へ読む。
- 計算順は従来どおり `sample * placement_gain * mono_promotion * edge_fade` とする。
  係数を先にまとめると `f32` の丸めが変わるので、別々の乗算を保つ。
  ループの継ぎ目、停止、トラックのパンとフェーダーは従来の後段のままとする。
- 素材と窓の左右の絶対ピークを、作成時に一度だけ検証・記録する。
  ゲイン変更時は `peak * gain` の有限性を調べ、全 PCM を走査し直さずに従来の桁あふれの拒否を保つ。
  失敗しても最後に成功した準備を失わない。トリム外の有限の極大値は、その窓のゲインを拒否する理由にしない。

公開の `render_faded_clips` は単位ゲインの入口として残す。
素材ローダーの `LoadedClip.samples` はゲイン適用前になり、独自のローダーも `gain` を別に渡す。
保存形式・クリップゲインの上限・チャンネル構成・プラグインとの通信は変えない。

## 回帰と検査の範囲

- 既存の必須契約 `shared-placement-pcm` と `loop-head-residency` で、ゲイン変更後も左右を共有し、素材がなくても準備済みの窓を再利用する。
  通常回帰では短いトリムにも適用し、`cached_window_peaks_reject_gain_overflow_without_rereading_pcm` でモノ・ステレオの桁あふれと失敗後の復帰を確認する。
- `prepared_audio_shares_unscaled_mono_planes_on_a_stereo_track` は、計画にも元のモノ平面が共有されることを確認する。
- `tests/block_size/clip_gain.rs` は 48 / 96 kHz、ブロック長 1 / 7 / 64 / 512、ゲイン 0 / 0.37 / 2.3 / 上限で比較する。
  モノだけ・モノとステレオの混在、配置の両端フェード、ループの有無で、旧来の焼込みとビット単位で一致させる。
  通常再生はブロック長 511 のオフライン出力とも比較し、RTSan の通常の対象に含める。
- 実WAVのトリム・ゲイン・SRC・左右の再生と書出しの一致は、既存の必須契約 `stereo-media` を使う。
  検査の選択・入口は既存の crate テストと RTSan で覆われるため追加しない。

## 残る境界

初回の復号・SRC と、未準備の配置形状の窓の生成は、引き続き全体準備である。
`MediaInputs` の照合と計画全体の作り直し（FCA-04）、停止中の素材準備の別スレッドへの手渡しは変えない。
ゲインだけの編集でも、その調停の費用は残る。操作の待ち時間の改善量は計測していない。
基準音声の再生成は不要で、実機の操作感・聴感は UC-48 に残す。
