# 0352. CLAP の余韻長を通知で更新し、書出しの確定前に読み直す

- 日付: 2026-11-14
- 状態: 採用
- 対象: P2-03・FCA-07 の `clap.tail`

## 背景

余韻長は初回の有効化後だけ読み、ヘルパーの再起動と `clap_host_tail.changed` を反映していなかった。
親の `PluginHost` がその値を持ち、遅延グラフの計画にも古い値が残った。
書出しの自動長は描画前に一度だけ計算しており、通知だけを足しても描き直しに古い長さを使う。

## 比べた案と決定

- **音声 callback がプラグインの値を読み、直接 IPC する**: 不採用。
  音声側へ拡張の寿命と送信の責務を増やす必要がない。
- **主スレッドの通知だけで更新する**: 通常処理には採用するが、書出しの完了条件にはしない。
  短い曲は主スレッドの通知と制御ソケットの受信より先に描画を終えることがある。
- **通常は非同期、書出しの確定前だけ番号付きで問合せる**: 採用。
  通常の処理は既存の RT-safe な主スレッド通知へ保留ビットを渡すだけとする。
  ヘルパーの主スレッドで `tail.get` を読み、制御スレッドが最新値を `TailChanged` で送る。
  有効化し直した後も、処理スレッドへ返す前に読み直す。

親の最新値は `PluginControl` の共有 atomic だけに持つ。
`PluginHost::tail_samples` も同じ値を読み、通知を無制限の待ち行列へ積まない。
ゼロと CLAP の無限値も値として更新し、古い有限値を残さない。

遅延と余韻の報告は、既存の計画ごとの読み取り・比較へまとめる。
変化したら同じ遅延グラフで計画を作り直し、親子の余韻の和を別の論理で実装しない。
余韻だけの別グラフと別世代は作らない。
書出しは既存の描き直し経路を使い、自動長を毎回計算し直す。
明示した総長と余韻長の意味は変えない。

最後のブロックの後、次のブロックを送らない間に全ヘルパーへ `TailRequest` を送り、主スレッドで値を読み直す。
返信は同じ要求番号の `TailChanged` だけを待ち、途中の番号 0 の通知を返信に使わない。
`StateRejected` は状態・余韻の問合せの拒否を共用し、busy・時間切れ等の型を保持する。
問合せは既存の状態取得の期限を使い、失敗した書出しは既存の出力を置き換えない。
受信後に計画が古ければ、新しい計画を待って先頭から描き直す。

## 境界と制約

- 新しい通信の種類は 36（通知・返信）と 37（問合せ）。35 は既存の分割フレーム `PART` である。
- プロジェクトの保存形式・C ABI・依存ライブラリは変えない。
- 通常の音声側へロック・確保・時計・主スレッド待ちを足さない。
- 主スレッドが止まる間、通常の報告の反映は遅れ得る。書出しの問合せも既存の制御要求と同じく busy・時間切れで失敗し得る。
- 遅延と同じ既存の描き直し上限を使う。余韻を変え続けて落ち着かない装置も、安全に失敗させる。
  この場合のエラー型と文面は既存の `UnsettledLatency` のままである。
- 実際の余韻の波形を推定する処理ではない。プラグインの申告値を使い、第三者の正確さと聴感は UC-83 に分ける。

## 回帰と基盤

- 検査用 `tail-changed` は初回の余韻 0 から process 中に値を変える。
  修正前は終了コード 101 と `tail extension is unavailable` を照合した。
  証拠は `target/focused-checks/tail-red/` に保存した。
- 隔離回帰は有限・ゼロ・無限・有限への復帰と処理音声を通す。
- 遅延の既存回帰に、有効化後の余韻の変更と再起動後のゼロへの復帰を足す。変更通知なしの再有効化でも読み直す。
- 製品バッファは 1・7・64・512 フレームで、親子の経路の和と最新の報告への収束を通す。
- 書出しは 1 ブロック未満と長い曲の自動長・明示した総長を検査する。
- 通信は不正長の型、通知の集約、古い番号の拒否、問合せと通知の区別、型付きの拒否を検査し、fuzz の種にも足す。

既存の隔離・Rust 通常回帰・fuzz の入口を使い、新しい検査コマンドや選択条件は作らない。
`under_rtsan` の名前は既存の全体検査にも渡すが、RTSan 自体は今回の作業では実行しない。
設計・P2-03・監査の現在欄・診断手順を更新する。`audio-ports`・`note-ports` のホスト側は残る。
