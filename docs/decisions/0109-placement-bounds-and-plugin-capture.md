# ADR 0109: 配置の原点、プラグイン状態の取り込み、クリップゲインの上限、停止中のキャッシュ範囲

- 日付: 2026-10-17
- 状態: 採用
- 範囲: 音声配置のオフセット、バックグラウンドのプラグイン状態、クリップゲイン、停止テールのキャッシュ読出

## 配置の原点

内容位置 0 はタイムラインの `origin = start - offset` に置かれる。左端のトリムで切り落とした区間は `[origin, start]` である。再生と波形は、この区間のテンポ積分をメディアの先頭スキップにする。`start` から `start + offset` までの積分は使わない。テンポが変わると二つの区間の長さは一致しない。一定テンポでも、1 tick あたりのサンプル数が整数でないとき、床関数の位置が最大 1 サンプルずれる。

`offset < 0` は、ファイルより前の無音である。原点の減算が溢れる配置だけを拒否する。負のリードは `PlaybackError::Time` にしない。波形も、ファイルより前の列を 0 にクランプして引き伸ばさない。

tick の分解能は `TICKS_PER_QUARTER = 705_600` である。960 PPQ を前提にしたサンプル数は、この製品の時刻には使わない。

## プラグイン状態の取り込み

ヘルパーが非同期に保存したバイトは、ユーザーの Undo に積まない。`Session::absorb_plugin_state` は現在のプロジェクトへハッシュを書き、Redo を消さず、Undo の深さも増やさない。文書ホストは同じ変更をジャーナルの編集として残し、自動保存する。公開に失敗したときは、取り込む前のプロジェクトへ戻す。

ユーザーが `device.set_state` を実行したときは、これまでどおり Redo を消して Undo に積む。Swift の Undo / Redo の数は画面操作の成功時だけ変わる。取り込みをユーザー操作として数えないので、そのカウンタを別経路で増減しない。

取り込みのあと、音声セッションはプラグイン状態だけの差分ではグラフを作り直さない。フェーダーの試聴も残す。文書のスナップショットが別の操作で変わったあとに残っていた保存バイトは、新しいプロジェクトへ再適用しない。

Undo / Redo のジャーナルは、保存してある差分が前後のプロジェクトをつなぐときはその差分を使う。取り込みでつながらなくなったときだけ、前後の差分を公開する。復旧はスナップショットと一致する。Redo は、取り込む前に積んであった版を戻す。取り込んだハッシュを、その版へ後から合成しない。

## クリップゲイン

トラックとマスターのフェーダー上限は 4 のままである。クリップゲインは 0 以上の有限値で、上限は `CLIP_GAIN_MAX = 1_048_576`（2^20、約 +120 dB）とする。ADR 0107 が有効と扱う 1000 はこの範囲に含まれる。`f32::MAX` は拒否する。

上限を超えないゲインでも、トラック数に上限がないため、加算結果が f32 の範囲を超えることがある。出力の段差補正、フェーダーの係数、f64 から f32 への変換では、非有限のサンプルを 0 にする。これで無限大や NaN を後続のバッファへ残さない。

## 停止中のキャッシュ

準備済みトラックは一つの領域として読む。停止テールで `started_before` があり、キャッシュの開始が停止位置以降なら、その領域は鳴らさない。停止中だけ、読み出す終端をループ終端で切る。ループの継ぎ目フェードは供給側の責任のままで、この読出では足さない（[ADR 0108](0108-phase1-loop-readiness.md)）。

すでに開始したキャッシュの中に、停止位置より後の発音が混ざっている場合、この読出では分離できない。供給側が、停止後に鳴らしてはいけない内容を平面へ入れない。

## 検査

- 120 BPM の 2 拍を切ったあと 60 BPM に変わっても、48 kHz の先頭サンプルは 48_000 サンプル地点である。同じ幅を開始位置の後で積分した 96_000 サンプル地点ではない。
- 負のオフセットは、ファイルの原点まで無音で、波形の左半分も無音である。
- 取り込みのあと Redo は成功し、Undo の段数はユーザー操作のままである。再オープン後もハッシュが残る。
- プラグイン状態だけの更新は、ストリームが無いセッションのフェーダー試聴を消さない。
- 停止テールは、未開始のキャッシュを鳴らさず、ループ終端より後のキャッシュ値を読まない。48 / 96 kHz、ブロック長 1 / 7 / 64 / 512 で比べる。
- 非有限の入力は段差補正の出力と保持値を有限のままにする。

Phase 3 のキャッシュ生成は接続していない。画面と機器を開く確認はユーザー担当である。
