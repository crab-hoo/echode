# 0052. ピアノロールの鍵盤とディグリー

- 日付: 2026-10-10
- 状態: 採用
- 関連: [ADR 0051](0051-arrange-presentation.md) の描画統合をピアノロールにも適用する。

## 決定

左からディグリー、鍵盤、ノートを配置する。鍵盤は白鍵が奥まで伸び、黒鍵が短く重なる形で描く。C に音名とオクターブを表示する。現在のスケールの主音を I とし、スケールの構成音に I〜VII のローマ数字を繰り返して表示する。スケール外は空欄。短調は既存の自然短音階を使う。調と長短調は引き続き画面内の設定である。

ノートの背景は通常鍵盤の白鍵と黒鍵の音高で固定し、スケールの内外では色を変えない。ディグリー欄には音高ごとの横線を入れる。スケール内の行をノート背景の白鍵色、スケール外を黒鍵色で塗り、調を変えるとディグリーの文字と欄の背景色が変わる。

`PianoFrame` は一回取得した不変の入力から鍵盤、ディグリー、ルーラー、背景、ノートと編集プレビューを組み立てる。文字は Core Text の被覆テクスチャを共通の描画器で描く。これらを一つの command buffer と drawable に含め、AppKit の別の描画時刻を介さない。部分行とズームも同じカメラを使う。

`PianoLayout` はディグリー 36 ポイント、鍵盤 44 ポイント、ルーラー 24 ポイントを使い、狭い表示領域では幅と高さを切り詰める。36 ポイントは 12 ポイントの I〜VII と見出しの I–VII が切れずに入る幅である。可視ノートの問い合わせとフォーカスの表示への移動はノート領域の実寸を使う。ヒットテスト、ドラッグとアクセシビリティの矩形は同じノート領域の原点で変換する。鍵盤、ディグリーとルーラーのクリックはノートを挿入しない。

## 検証

`PianoTests` は 12 の主音と長短調、オクターブをまたぐディグリー、スケール外の空欄、調に依存しない矩形・色、部分行の音高、編集座標の原点、挿入領域の境界と狭い領域を検査する。既存の移動・長さ変更・Undo / Redo と保存の検査も維持する。

`make spike-piano-frame` はウィンドウ、表示リンク、画面操作を使わず、製品と同じ描画器で GPU へ描いて読み戻す。Apple M4、倍率 1・2、部分行、縦横のスクロールとズーム、幅変更、C 長調・D 長調・F♯ 自然短調を含む 144 フレームで、調を変えた時の鍵盤・ルーラー・ノート領域の 51,159,360 画素を比較し、不一致は 0。816 の白黒の音高行、白鍵が黒鍵の奥まで伸びる形、1,632 の度数行のスケール内・外の色と横線、スケール外の空欄も検査した。ディグリーの文字が実際に描かれた画素は 20,035。結果は `target/spike-piano-frame.json`、検査画像は同じ名前の PNG を確認した。

この検査は画面への実際の表示時刻、入力遅延、実操作の確認を含まない。`spike-app` と `spike-draw` は computer use の明示許可がないため未実施。
