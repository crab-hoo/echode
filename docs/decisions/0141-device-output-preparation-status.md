# ADR 0141: デバイス列で出力の準備と一覧の応答待ちを区別する

- 日付: 2026-10-21
- 状態: 採用。P2-02 の準備中表示を接続。実画面と VoiceOver はユーザー確認待ち
- 範囲: 既存の音声状態の Swift への橋渡し、空のデバイス列の待機表示

## 背景

[ADR 0136](0136-output-opening-off-worker.md)で初回の出力準備を文書ワーカーの外へ移したが、
Swift の `AudioState` は Rust の `opening` を受け取らず、列は常に「パラメーターを読み込み中」と表示していた。
ヘルパー起動・素材準備の待ちと、準備後のプラグインの一覧の応答待ちを画面から区別できなかった。

音声状態を返す代役と一覧を保留する代役を使い、既存の状態ポーリングと実 `DeviceStripView` を通す回帰を先に追加した。
出力の準備中にも一覧の読込み表示になることで失敗した記録を `target/device-preparation-before.log` に残す。

## 決定

- Swift の `AudioState.opening` は Rust の既存フィールドをそのまま復号する。
  文書に属する一時的な状態であり、プロジェクトやデバイスへ保存しない。保存形式と C ABI の変更はない。
- 既存の `observeAudio` が状態を更新し、デバイスビューは `opening` の変化を読み取って列を更新する。
  表示のための別のポーリング、プラグイン通信、準備のやり直しは追加しない。
  画面は位置を含む `audio` 全体ではなく、変化した時だけ更新する `ProjectController.outputOpening` を観測する。
  再生位置のポーリングだけで全デバイス列を更新し直さない。
- 一覧が未取得・取得中で出力が準備中なら「音声出力を準備中」、出力の準備が終わっても一覧が未取得なら従来の読込み表示を使う。
  `opening` は共有出力全体の状態であり、特定のデバイスが原因だと推測したり、完了率を作ったりしない。
- オフラインと一覧の失敗は待機表示より優先する。
  取得済みの一覧は、値の再取得や出力の準備だけでは隠さない。出力の準備完了を一覧の取得成功として扱わない。
- 列の開閉は待機状態を保持し、展開時は最新の表示へ戻る。状態文のアクセシビリティ名はデバイス名を含む。
  名前・チェイン操作・他の編集・停止の有効性、検索・選択・保存・Undo は変えない。

## 検査と診断

- 必須契約 `device-preparation-ui` は音声状態の復号・ポーリング・実デバイス列で、準備中→一覧待ち→取得完了を確認する。
  一覧を保留中も取得済みの別の列・無関係な編集・停止を使え、検索と履歴が表示変更で変わらないことも確認する。
  負の対照は出力の準備状態を列へ渡さず、表示の期待値で失敗させる。
- 通常回帰は初期値、未生成の一覧、失敗・オフライン・正常な空の一覧の優先順、取得済みの一覧と開閉を確認する。
  `Makefile` の既存の製品契約入口、検査の登録と選択の回帰へ追加する。Swift の通常・ASan・TSan の対象になる。
  Observation の回帰で、位置だけの音声状態の更新はデバイス表示を無効化せず、準備状態の変化だけを通知することも確認する。
- 初回の出力準備そのものは既存の Rust 契約 `output-opening`・`output-opening-worker` が担当する。
  今回の画面の回帰は代役の音声状態と一覧を使い、実 HAL や第三者プラグインの時間を測った意味ではない。
- [デバッグ手順](../debugging/audio-and-plugins.md#プラグイン)へ表示と `opening` の対応を追加する。
  新しいログ・外部入力・成果物は増えず、既存の契約ログで収集できるため診断資料の収集器は変更しない。

## 残る範囲

状態は既存の約 50 ms のポーリングで反映されるため、短い準備では表示されない場合がある。
開いた出力への新しいヘルパーの準備をワーカー外へ移す方式と、その処理の表示は別の範囲である。
実画面・VoiceOver の読み上げと第三者プラグインでの操作感はユーザー確認とする。
