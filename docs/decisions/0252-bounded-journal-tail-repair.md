# 0252. ジャーナルの追記前確認を末尾から行う

日付: 2026-11-03。
状態: 採用（FCA-14 の全件読込みだけ。編集ごとの同期と確定の意味は維持する）。

## 背景と再現

`append_journal` は毎回 `repair_journal` を呼び、従来はログ全体を `Vec` に読み込んで最後の改行を探していた。
正常な追記でも、読取量と一時メモリが過去の編集の長さに比例して増えていた。
[監査の実行指示](../reviews/2026-11-03-fix-instructions.md) は、この確認を末尾だけにするよう求めている。

`a77ae25` と既存の書出し変更を保持した作業ツリーに、テスト時だけの読取バイト数の集計と
`audit_fca14_complete_journal_append_reads_only_the_last_byte` を先に追加した。
実パッケージへ `append_journal` で追記すると、長さ 1 のトラック名の入力でも 3,293 バイトを読み、期待値の 1 と不一致になった。
`checked_commands.py` で終了コード 101 と固有の `a complete journal must inspect only its final byte` を照合した。
コンパイルの失敗は再現の成功に含めていない。

## 決定

- ファイルの長さを `SeekFrom::End(0)` で取り、空なら読み込まない。
  通常は末尾の 1 バイトだけを読み、改行なら短縮も同期もせず確認を終える。
- 末尾が改行でなければ、それより前を 4 KiB の固定作業領域で後ろから読み、最後の改行の直後を求める。
  改行が無ければ 0 まで短縮し、従来どおり `set_len` の後に `sync_all` を行う。
  作業領域はレコードやログの上限ではなく、複数の領域にまたがる末尾も走査する。
- 未完の末尾が N バイトなら、成功した内容読取りは最大 N + 4,096 バイトである。
  最後の領域で完結済みの側を一部読むことはあるが、正常なログの全件読込みはしない。
  ログ全体が未完なら全体を読む必要がある。その場合もログ全体のバッファは確保しない。
- オフセットと短縮位置は `u64` のままとし、領域内の長さだけを `usize` に変換する。
  読込み・位置移動が失敗した場合は短縮へ進まない。
- 完結した不正な行や JSON の検証は従来の復旧へ残す。
  最後の改行より前を修復の都合で削除せず、不完全な UTF-8 の末尾もバイトとして扱う。
- 安全なパッケージのオープン、リンクの拒否、修復の同期、新しい行の追記・同期・失敗時の巻戻しは変更しない。
  ジャーナルの形式、スキーマ、Undo、確定の通知、自動保存の短縮の時期も変えない。
  [ADR 0033](0033-journal-log.md) の単一の書き手と編集ごとの `File::sync_all` を保つ。

## 回帰と基盤

`crates/echode-history/src/journal_tests.rs` は製品の追記・修復経路で次を検査する。

- 正常なレコードの長さを変えても追記前の内容読取りは 1 バイト。欠落・空のログなら 0 バイト。
- 4 KiB の境界の前後と複数領域にまたがる不正末尾を削除し、既存の完全なバイト列と追記を保持して復旧できる。
- ログ全体が未完の場合の空への修復、不完全な UTF-8、完結した不正行の保持と復旧の拒否。
- 4 GiB を超える疎ファイルを、巨大な読込みなしに元の 64 bit の位置へ修復する。

バイト数の集計はテストのスレッドごとで、製品ビルドには入らない。
メタデータの問い合わせ、物理ディスクの読取り、同期の所要時間を測った値ではない。
既存の `audit_aud02_*` の全切断位置と `audit_aud03_*` の追記失敗、パッケージのリンク拒否と復旧の回帰も維持する。

設計、監査と実行指示、監査の索引、デバッグ手順と索引を更新した。
通常の `cargo test -q --workspace` と history の feature 検査が新しい単体テストを含むため、Makefile と `scripts/verification.json` の選択は変更不要である。
ログや診断の出力先、収集する成果物、依存とリアルタイム処理は変えず、doctor と debug-report の収集範囲も変更しない。
`status.md` に新しく残る利用制約はなく、既存の保存耐久性と実際の電源断の未確認はそのままである。

## 残る範囲

macOS の `F_FULLFSYNC` を編集ごとに待つことは変わらず、操作全体の短縮時間を保証する変更ではない。
まとめ書きは確定の意味に触れるので、ADR とユーザーの確認が必要であり、本作業には含めない。
保存・復元全体の release 計測と実際の電源断は、この読取量の回帰では確認していない。
音、UI、保存の形式や同期の保証を変えないため、新しい実機・聴感の確認待ちは作らない。
