# ADR 0223: デバイスの項目表をモデルと保存へ共有する

- 日付: 2026-11-02
- 状態: 採用
- 対象: SPG-09 の続き。デバイスのモデル・変更セット・パッケージ間の変換
- 関連: [ADR 0215](0215-device-changeset-fields.md)、[ADR 0222](0222-parameter-package-fields.md)、[ADR 0028](0028-package-schema.md)
- 監査: [SPG-09](../reviews/2026-10-30-structure-audit.md#spg-09-モデルの項目追加の手数)

## 背景

パラメーターに続き、デバイスの 5 スカラー項目もモデル宣言・保存・変更セットで別々に列挙されていた。
履歴の `DeviceFile` と復元時の組立て、保存時の手書きのキー列は、項目の追加時に同期が必要だった。
既存の結果を保つ構造整理とし、新しい機能や保存形式の変更は行わない。

## 決定

- `echode-model/src/device_fields.rs` の crate 内の表を、モデル宣言・Serde と変更セットの生成器で共有する。
  プラグイン ID・状態ハッシュ・バイパス・オフライン・ピン留めの型と変換をこの表へ集める。
  ID・種別と子パラメーターはスカラー表の外へ残す。
- 宣言の順序を既存の保存キー順に合わせ、作成・差分の順序は表内で別々に指定する。
  作成はバイパス・オフライン・ピン・プラグイン・状態、差分はピン・オフライン・バイパス・状態の順を保つ。
  プラグイン ID を差分に含めない従来の規則と、低水準の更新の受入も変えない。
- `DeviceKind` の Serde は既存の `as_str`・`parse` を使う。
  履歴の `DeviceFile` と手書きの復元を除き、モデルの `Device` を直接復号する。
  Serde は形を検査するだけで、プラグイン ID・ピン・ミキサーの制約・ID の重複は既存の受入検証に残す。
- 履歴は状態ハッシュの形と参照オブジェクトの存在・BLAKE3 を引き続き検査する。
  モデルの直接復号は保管庫を読まないため、パッケージの受入に代えて使わない。
- 保存も `Device` の Serde を使う。
  履歴の `document_device.rs` は `parameters` 配列だけを改行する formatter とし、スカラーの一覧を持たない。
  文字列のエスケープとキー順は Serde、浮動小数点は既存の `PackageFormatter` に任せる。
  空のパラメーター配列、1 パラメーター 1 行、ピンの詰めた配列と保存バイトを保つ。
- 現行スキーマ 6 ではフラグ・ピンを必須のままにし、旧スキーマは既存の段階変換で補う。
  任意テキストの省略と明示的 null の互換を保つ。新しい省略値や自動修復は足さない。
- 不正 ID・未知の種別はトラックの復号時に拒否するため、従来の理由に `track json:` の文脈が付く。
  新しいログや収集先は追加せず、拒否時に原本を書き換えない。
- ほかのオブジェクトの保存と FFI の統合は残り、SPG-09 全体の完了とはしない。
  アクション・Undo・ジャーナル・プラグイン処理・音声処理は変更しない。

## 回帰と診断

製品コードの変更前に `echode-history/tests/device_package.rs` を追加し、同じ公開入口で整理後を照合した。

- バイパス・オフライン・状態の全組合せと境界のピン、Unicode と JSON に似た文字列を持つプラグイン ID を保存する。
  独立したキー順・改行の期待値、スキーマ 6、再読込みと再保存時のバイトを検査する。
- 必須項目の欠落・型の誤り・未知の項目・不正 ID と種別を拒否し、任意テキストの省略の互換を保つ。
- ミキサーと CLAP の不正な設定、ピンの順序・重複・無効 ID、デバイスの順序と ID の重複を受入前に拒否する。
  形だけの復号が成功しても、プロジェクトとして受け入れられるとは限らないことも確認する。
- 状態ハッシュの不正・参照先の欠落・保存バイトの破損を拒否し、原本を自動修復しない。
- 旧スキーマの段階変換と、`DocumentHost` の編集・Undo / Redo・状態の取込み・コミットからの再オープンを通す。
  既存の `device_changesets.rs`・`parameter_package.rs`・操作列の性質テストも維持する。

通常の `check` が新しい統合テストを含むため、実行入口・依存・検査選択は変更しない。
デバッグ手順に形・意味・状態オブジェクトの検証の区別と回帰の場所を追記する。
実機・実画面・聴感や性能の改善は、この構造整理の合否からは主張しない。
