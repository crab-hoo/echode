# ADR 0108: P1のループ先頭を準備済みPCMで保持し、トラックの差し替え口を接続する

- 日付: 2026-10-17
- 状態: 採用
- 範囲: ループ先頭の準備、制御側の素材保持、フェーダー前の出力元の差し替え

## 判断

P1は配置した素材全体を制御側で読み、左右別にrubatoでデバイスレートへ変換してから再生計画へ渡す。ループ先頭もこの不変PCMに含まれ、計画採用前に読み終わる。折返しのコールバックで読込・SRC・確保をしない。先頭専用のコピーを追加せず、この方式でPLANのループ先頭の先読みを満たす。

従来の`media_loader`はループ範囲変更を含む再準備のたびに同じ素材を読み直した。準備後に一時プロジェクトの素材だけを除去してループを設定する回帰を先に失敗させた。新しいローダーは最後に成功した準備を1組保持し、ループ・トランスポート・ノート・フェーダーの変更ではPCMのArcを共有する。

キーはデバイスレート、テンポマップ、音声配置のトラックID・Placement全体・AudioRefである。配置位置・窓・オフセット・ゲイン・フェード・素材ハッシュやメタデータが変われば再準備する。読込失敗では以前の準備を壊さず、古いPCMを新しい入力の成功として返さない。音声配置をなくした成功更新では保持も空になる。無制限の編集履歴キャッシュやトラック数の上限は設けない。

保持のMutexとモデル走査は制御側だけで使う。音声側は採用済み計画の平面を読む。再準備中には旧計画が以前の平面を保持するため、一時的に新旧のメモリが重なる。初回の全素材の読込時間と、素材量に比例するメモリ使用は残る。ディスクから範囲を順次読む実装を完了したという意味ではない。`loop_head_prefetch`は将来の範囲読込のための計算であり、P1の全体準備へ形だけ呼び出す用途には使わない。

## フェーダー前の差し替え口

`voice::TrackSource`だけでは単体関数に留まっていた。`PlaybackControl::set_cached_tracks`でデバイスレートの`CachedTrack`を準備し、次の`replace`へ載せる。製品の`PlaybackAudio`が同じトラックの内蔵音源・素材合成・CLAP処理の代わりに、プロジェクト上の位置からその平面を読む。キャッシュ対象のヘルパーは起動しない。範囲外は無音、左右は独立、フェーダー・マスター・ピークは差し替え後にも通る。

設定は停止中かつ投入済みトランスポート操作の応答後に限る。呼出側は更新計画の採用を待ってから再生する。異なるレート、不一致の左右長、時刻のオーバーフロー、不明なトラック、重複IDは拒否し、既存設定を壊さない。空の一覧でライブ処理へ戻せる。

これはPhase 3の供給側を接続する製品の入口である。レンダリング本体、内容キーの作成・失効、先行DSP、再生中のクロスフェードは今回作らない。供給側は音楽的な入力を変えた時に失効させ、ループ境界やデバイス処理を含むフェーダー前の音を渡す責任を持つ。フェーダー変更では作り直さない（[ADR 0011](0011-preview-cache.md)、[ADR 0012](0012-fader-after-cache.md)）。画面からキャッシュ生成を有効にできる機能を追加したという意味ではない。

## 検査

- `loop-head-residency`: 実WAVの取込・SRC後に検証用素材を除去し、ループの設定・変更・解除と3周以上の左右の波形を確認する。レート・配置・ゲイン・フェード・テンポの失効、失敗後の保持と不要素材の解放も確認する。
- `pre-fader-source`: 存在しないCLAPとヘルパーを指定しても、準備済み平面が製品から鳴る。範囲外の無音、ループ、ステレオ、フェーダー、ライブへの復帰と再生要求保留中の設定拒否を確認する。
- 両者は48 / 96 kHz、1 / 7 / 64 / 512フレームで検査し、RTSanにも含める。誤りを戻したコピーも期待値で拒否する。結果は`target/verification/report.md`。

P1の条件全体との照合とユーザーの聴感報告は[最終照合](../reviews/2026-10-17-phase1-acceptance.md)に残す。ディスクストリーミングやPhase 3のキャッシュ本体の完成へ読み替えない。
