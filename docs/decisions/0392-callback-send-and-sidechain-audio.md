# ADR 0392: Routes の辺をコールバックの加算・補助入力・依存へ接続する

- 日付: 2026-11-17
- 状態: 現行
- 領域: 音声エンジン・書き出し

## 問題

ADR 0390・0391 はモデルの経路を PDC へ写したが、製品は音声を送らず、実行の待ちも子から親だけだった。
計画だけ正しくても、鍵を受ける装置の本線に線がなく、送り元のバッファをフェーダーが変更した後で読むと時刻と振幅が違う。

## 比べた案と決定

### 依存と取り出した音の寿命

- 装置ごとの実行スケジューラへ作り直す案は、鎖の途中の取り出しがない現状では状態と失敗経路を増やす。
- **トラック単位の既存スケジューラを拡張する**。PDC が解いた同じ `Routes` の親・センド・鍵の辺から待ちの数と後続を作る。
  同じ二点のセンドと鍵、子と親へのセンドは並列辺として数え、送り元の完了で各辺を一度ずつ解放する。
  閉路の検査はモデルと既存ソルバーに任せ、別の閉路判定を追加しない。
- 受け側から送り元の出力平面を直接読む案は、先にフォルダが消費した時に出力の線・フェーダーが音を変更する。
- **辺ごとに準備した平面へ FX 後・出力の線とフェーダー前の音を写す**。辺の PDC 線もここで処理する。
  受け側は完成した平面だけを読み、全トラックや全経路を探索せず、準備済みの入辺と出辺をたどる。
  音声側は確保・解放・ロックを増やさない。期限後の受け側も既存の submit / abandon を通り、出来事を失わない。

### 補助入力の意味

- モデルへポート番号を今追加する案は、保存形式・API・操作を再度変更する。
- **今のデバイス単位の鍵は最初の補助入力（入力ポート 1）へ加算する**。主入力はポート 0 のまま。
  ほかの補助ポートは毎ブロック無音へ戻す。主入力の準備と段間コピーは補助入力を上書きしない。
  複数の鍵を接続順で f64 加算し、最後に f32 へ狭める。モノからステレオへは等電力で上げる。
  モノの補助入力へはモノのまま渡す。ステレオからモノへの暗黙の変換は行わない。
- ポートがない・幅がモノ／ステレオでない・ステレオからモノになる場合は、公開前に `SidechainMapping` で断る。
  黙ってゼロにする案は接続ミスと製品不良を区別できないため採らない。
  未ホスト・オフライン・キャッシュで走らないデバイスの鍵は ADR 0391 と同じく計画から除く。
- 鍵が入る段の本線は `StageLine::main` の線を装置の直前で処理する。バイパス中もその線と鍵の線を進める。
  初段音源に本線がない規則は既存の PDC 計画のままである。

### ゲイン、異常、計画交換

- センドの受け側はステレオの入力バスになる。子と同じく受け側のキャッシュを使わず、入力の和と自身の配置音声を FX へ渡す。
- 接続量と送り元の現在の mute / solo ゲートは辺のフェーダーで補間する。送り元の音量・パンには依存しない。
  ソロによる関連リターンの自動開放は今回の範囲外で、既存の全体ソロゲートに従う。
- 主入力・鍵の加算で有限の f32 を作れない時は、そのフレームから入力をゼロにし、受け側トラックを合流異常として自動ミュートする。
  プラグインが書いた異常値と区別し、書出しは既存の `NonFiniteMix` で拒否する。
- 接続 ID と両端が同じ辺だけ遅延線と補間を引き継ぐ。入替えや削除の音を別の辺へ渡さない。
  装置の本線は同じ `Arc` のインスタンスで引き継ぐ。位置移動など既存の不連続点で全ての線を空にする。
  辺と本線の記憶域は `Compensation::lines` の予算検査後に制御側で確保する。

## 回帰と観測値

- `tests/block_size/routes.rs`: 後方の送り元からフォルダ内のリターンへ送る。送り元フェーダー 0、センド 0.5、受け側 0.5 で、入力 L=0.25 / R=-0.125 は L=0.0625 / R=-0.03125 になる。
  製品・書出し、1 / 7 / 64 / 512 フレーム、f64 加算と mute を照合する。実装前はセンドのアサーションで失敗した。
- `hosted_playback/routes.rs`: 別プロセスの補助入力 probe を使う。37 フレーム遅れる送り元からのセンドと鍵は、原点 20 のインパルスを 57 で合流させる。
  本線 11・鍵 37 の差、前段バイパス、複数の鍵、計画交換と位置移動、モノ、削除、拒否と前の計画の保持、有限値のあふれを製品バッファで調べる。
  補助入力供給を外すと、到着・振幅固有のアサーションで失敗することも確認した。
- 必須契約は `send-callback`・`sidechain-callback`・`sidechain-main-line`。反例の全実行は全体検査の段階で行う。
- 自動の観測値は正しい申告をする fixture の範囲だけで、第三者の外部キー設定・申告値の妥当性・実機の期限・クリックの聴感を証明しない。
  聴感用の受入は UC-102・103 に分ける。画面、ポート選択、ソロのリターン開放、ドラムの MIDI 配布は残る。
