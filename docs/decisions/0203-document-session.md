# 0203. 文書の寿命の状態を DocumentSession へまとめ、文書の照合を 1 か所にする

- 日付: 2026-10-31
- 状態: 採用。実画面での文書切替・VoiceOver・聴感はユーザー確認待ち
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-02
- 関連: [ADR 0193](0193-header-mix-gesture-document-scope.md)、[ADR 0194](0194-clip-mix-gesture-document-scope.md)

## 背景と再現

開始時の HEAD は `1a05111`。
`ProjectController` は文書の寿命の状態を約 60 個の項目で持ち、`open` と `close` が手で初期化していた。
初期化の漏れと、編集の入口の `documentID: UUID? = nil`（`nil` は照合を省く）が残っていた。
読解で疑った 4 点を、修正前のコードで `DocumentSessionTests` を実行して再現した。

- **ドラッグ値の誤送信**: `parameterTask` は開き直しでも消えない。
  古い文書の値の応答を保留したまま次の文書でドラッグすると、残った処理が新しいジェスチャの値を古い文書へ送り、エラーも出た。
  新しい文書のプラグインに値は届かない。
- **音声コマンドの持越し**: `audioRequests` と `audioTail` も消えない。
  古い文書の応答を保留すると、次の文書で `audioBusy` が真のままになり、順序付きコマンドが古い応答を待った。
- **履歴復元の再照準**: `restoreRevision` は文書を照合しない。
  ドラッグの完了を待つ間に同じプロジェクトを開き直すと、待っていた復元が新しい文書の内容と履歴を変えた。
- **閉じる途中の不整合**: `close` は文書 ID を先に消し、内容はヘルパーの終了後に消していた。
  その間の描画は古い内容に `nil` の文書 ID を組み合わせる。`nil` を「今の文書」と解釈する入口と重なると、次の文書を編集できる。

## 決定

- **`DocumentSession`**: 文書の寿命の状態を 1 つの `@Observable` 参照型へ移す。
  内容の投影、選択、ピアノの入力、試聴中のミキサー、音声の状態と順序、デバイス一覧、プラグインの窓と活動が対象である。
  `open` と `close` は完成した次のセッションへ丸ごと差し替え、項目ごとの初期化をなくす。
  文書なしは、空のセッションで表す。
- **古い処理の到達先**: 非同期の処理は開始時のセッションを保持し、その状態だけを読み書きする。
  新しい項目を足しても、古い処理が新しい文書の状態へ届く経路を作らない。
  差し替え時の `retire()` は、活動の読取り・静止待ち・ジェスチャ・保留値を止めて音声の版を進める。
- **`DocumentID`**: `UUID` と区別する値型にする。トラックやデバイスの ID を取り違えるとコンパイルで止まる。
  開くたびに新しい値を作るので、同じプロジェクトの開き直しでも一致しない。
  監査の `DocumentScope` の弱参照は持たない。照合は現行セッションとの比較で足り、値型なら `Sendable` と `Codable`（ドラッグの内容）を保てる。
- **照合の 1 か所**: `session(for:)` だけが現行の文書と比較する。
  `inputSession(for:)`・`isCurrent`・`acceptsInput` はその派生である。
  ヘッダが自分に束縛した文書と操作の内容を比べる箇所だけは、ビューの中に残す。
- **省略できない文書 ID**: 製品の編集・値操作の入口から既定値と `nil` の意味を除く。
  パラメーターの操作とフェーダーの試聴・履歴復元も文書 ID を受ける。
  `setNavigation` も、保存先が持つ文書へ暗黙に戻らない。
  テストの準備用の省略形はテストターゲットの `CurrentDocumentEdits.swift` だけに置き、製品から呼べないようにする。
- **閉じる順序**: `close` も `open` と同じく先に差し替えてから旧文書を終了する。
  終了待ちの間は `busy` のまま、文書なしの画面を表示する。

## 範囲に含めないもの

- `ProjectController` には、文書をまたぐプラグイン名・エラー表示・復旧の確認・編集の順序・要求の送り口が残る。
  監査の別の型へ分ける案は、文書の状態を除いた時点で controller 自体がその役割になるため行わない。
- トラック選択とノートのフォーカスのバインディング、再生・停止・ループ切替のボタンは、押した時点の文書へ働く。
  アレンジとピアノロールは文書 ID を `.id` に持ち、文書が変わると作り直される。保存される内容を変える入口ではないので、文書 ID を要求しない。
- ID・時刻の値型の全面導入、音声処理・描画・保存形式・ABI の変更はしない。

## 回帰と基盤の保守

- `DocumentSessionTests` の 4 つの必須契約が、上の再現を製品の controller で確認する。
  - `document-session-drag-ui` は実際の値の宛先・エラーなし・単一 Undo を見る。
    `parameterTask` を次のセッションへ持ち越す反例を拒否する。
  - `document-session-audio-ui` は応答を保留したまま次の文書のコマンドが届くことを見る。
    `audioTail` と `audioBusy` をそれぞれ持ち越す反例を拒否する。
  - `document-session-restore-ui` は開き直し後の復元の拒否を見る。履歴の手番の照合を外す反例を拒否する。
  - `document-session-stale-ui` は、開き直しで ID が同じ対象に対する前の文書 ID の全操作の拒否を見る。
    `session(for:)` の照合を外す反例を拒否する。
- `closingRemovesTheDocumentAndItsContentsTogether` は通常回帰で、閉じる途中も文書 ID と内容が一緒に消えることを確認する。
  当初はポーリングと終了の順序に依存し、`Task.yield` がグローバルの実行プールを経由するため `check-bridge-asan` で一度失敗した。
  後続で `endDocument` を止めるゲートへ直した（2026-10-31、[ADR 0204](0204-document-service.md) の作業）。
  この不整合は型の構造で起きないため、反例を置かない。
- 検査基盤は、`documentID ==` の比較がヘッダ以外へ戻らないことと、関数の引数に任意の文書 ID を足さないことを確認する。
  既存の反例は差分の移動に合わせて更新し、音声の検査の選択へ `DocumentSession.swift` を加えた。
- 待ちは明示的なゲートで進め、経過時間を合否に使わない。機器・ウィンドウは開かない。
- 古い処理の不具合を調べる時は、処理が保持するセッションと `controller.session` が同一かを比べる。
  ログ形式・出力先は増えないので、`doctor` と `debug-report` の収集範囲は変更不要である。
- 新しいアクション・保存形式・DSP・依存は加えない。音を作る処理と RT の経路は変わらないので、ブロック長回帰は追加しない。
