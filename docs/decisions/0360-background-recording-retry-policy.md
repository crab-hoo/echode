# 0360. 背景の読取りと記録の再試行を共通化する

日付: 2026-11-15

## 背景

詳細監査の DIA-03・DIA-05 と品質監査の IQA-05 を一つの作業で直す。
HAL の失敗は毎周期の問い合わせと警告になり、取得済みの状態の記録失敗は毎周期のハッシュ・全列照合になる。
停止した自動保存への送信失敗は記録されなかった。
IQA-06 の機器ごとの除外、IQA-04 の作業ツリーのキャッシュ、DIA-07 の取込みの取下げは今回の対象外である。

## 比較と決定

- 各呼出し元で時刻と警告の印を持つ案は、同じ規則を別々に保守するので採らない。
  新しい共通 crate も作らず、既に音声 IO と文書が依存する `echode-history::retry::BackgroundRetry` にまとめる。
- 固定間隔より、100 ms から倍増し、最大 5 秒の間隔を選ぶ。
  一時的な失敗の復帰を早めつつ、長く失敗する時の IO と警告を抑える。
  試行の完了時から数え、成功だけが遅延と警告の印を解除する。
  新しい機器通知・保存内容でも未満の時刻には試さない。
  原因の型と詳細の Debug 表現が同じ間は黙り、初回と変化時だけ書く。
- 自動保存の送信先の切断は同じセッションでは戻らない。
  共通状態の終端停止として扱い、最初の送信失敗を error にし、以後は送らない。
  `history.usage.autosave_stopped` を追加する。既存欄は変えず、プロトコル版も変えない。
  ジャーナルと公開済みの編集は維持し、開き直して新しいワーカーへ移る。
- 保管庫全体の永続的な既知ハッシュ集合は増やさない。
  `PluginState` は一つの不変の取得内容と、同期済みの保管物のパッケージ・名前だけを覚える。
  同じ取得内容の再記録では、名前の存在を確認するだけで全列照合とハッシュを省く。
  名前が消えていれば保持した bytes で書き直す。別パッケージには使い回さない。
  既存の任意の名前を初めて受け入れる時は、従来の全列照合と同期を通す。
- 書込みの終端停止は共有状態の一つの atomic に置く。
  保管物の書込みを履歴スレッドの停止判定の後へ移し、文書ワーカーも止まった文書へ保存を送らない。
  編集中・再試行中の取得内容は無関係な編集で捨てず、そのデバイスの状態・プラグイン・offline が変わった時だけ捨てる。
  保留中のヘルパーも維持する。新しい取得内容は古い内容を置き換えるが、失敗の間隔は解除しない。

## 根拠と回帰

- 元の `audit_dia03_*` は修正前に 100 回の `service` で 100 回の読取りを報告して失敗した。
  無視を外し、別の仮想時計の回帰で境界・追加通知・原因の変化・成功後の解除・一覧と位置の保持を調べる。
- 既存の `JournalFault::Uncertain` で停止させると、修正前は拒否より先にプラグインの保管物が作られた。
  `audit_dia05_*` はその拒否と、通常の書込み失敗後の旧状態・Undo の段数・再記録・開き直しを製品のチャネル越しに調べる。
- 保管物の回帰は同じ取得内容を 100 回再利用して、全列処理の入口が 1 回だけであることを数える。
  欠落時の再生成と別パッケージへの書込みも調べる。これは呼出し回数であり、所要時間の計測ではない。
- 実際の自動保存ワーカーを終了させる `audit_iqa05_*` は、旧送信処理へ戻すと「1 回だけ記録」のアサーションで失敗する。
  error のレベル、停止の診断、確定済み編集と開き直しでの復旧を調べる。
- 取得前のヘルパーとの実ソケット・実ヘルパーの回帰は ADR 0348 の既存経路を維持する。
  今回はそのプロトコル・期限・隔離・音声コールバックを変更しない。実機や聴感での改善量は測らない。

## 基盤

現在の規則は領域別設計書、原因の区別はデバッグ手順、対応状態は各監査へ反映する。
新しい回帰は既存の通常 Rust テストで実行され、検査の選択条件・Makefile・fuzz の外部入力は変えない。
