# 0355. CLAP の音声ポートの再走査は名前の変更だけを公開する

- 日付: 2026-11-15
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: P2-03・FCA-07 の `clap.audio-ports`

## 背景

プラグイン側の音声ポートの読込みはあるが、ホスト側の拡張を公開していなかった。
現在の共有領域と処理用のバッファは初回のポート数・チャンネル数から用意し、実行中に構造を変える手順を持たない。
名前の変更まで構造の変更と同じに扱う必要はない。

## 比べた案と決定

- **拡張を公開しないままにする**: 不採用。
  安全に受け取れる名前の通知も利用できず、プラグインが対応する変更を問い合わせられない。
- **全ての再走査フラグに対応すると答え、再起動する**: 不採用。
  今の再起動は共有領域とバッファの形を交換しないため、対応を過大に申告することになる。
- **名前の変更だけを対応すると答える**: 採用。
  `is_rescan_flag_supported` は単一の `CLAP_AUDIO_PORTS_RESCAN_NAMES` だけに真を返す。
  リスト・チャンネル数・フラグ・ポート型・in-place の相手の変更、未知のビット、0 と複合値は偽にする。

名前は現在のモデル・画面・ポート表に保持していないため、名前の通知では無効化するキャッシュがない。
通知のための状態・待ち行列・再起動・親へのグラフ再作成は足さない。
将来ポート名を表示する時は、この通知から表示用の一覧を無効化する。
主ループを持たない比較用の inert host も、同じ状態を持たない拡張を公開できる。

これは構造の変更を許可するものではなく、プラグインは対応する各フラグを先に問い合わせる必要がある。
非対応の変更を通知するプラグインの誤動作を、この通知で安全な構造変更へ変換するものでもない。
構造の変更には、処理を止めた上で共有領域・バッファ・グラフを一緒に交換する別の手順が要る。
`note-ports` のホスト側、ポート名の表示、第三者プラグインの互換性全体は今回の範囲外である。
保存形式・C ABI・IPC・依存と音声処理は変えない。

## 回帰と基盤

`echode-test-plugin` の `audio-ports` は、初期化と主スレッド callback から全 32 ビットと複合値を問い合わせ、実際に名前を変えて通知する。
修正前は、実ヘルパーを通す回帰が終了コード 101 と `audio-port capability probe failed: [128, 1]` で失敗した。
証拠は `target/focused-checks/audio-port-rescan-red/` である。

`tests/isolation/audio_ports.rs` は、停止中・窓なしの通知、再有効化されないこと、親へ再起動通知を出さないことを確認する。
1・32・127・256 フレームの処理結果と通知後の状態も照合する。
通常の workspace テストと既存の `under_rtsan` の選択に入り、新しい検査の入口や選択条件は足さない。
RTSan 自体は全体の段階へ任せ、実機計測は依頼がないため行わない。
設計書・Phase 2 の範囲・監査の統合表、コードの所在とポート変更時の診断を更新する。
実画面の操作を足さないため新しい UC は作らず、第三者互換の確認待ちは既存の UC-80〜83 に残す。
