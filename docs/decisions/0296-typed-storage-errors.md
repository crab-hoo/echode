# ADR 0296: 履歴 crate の保管庫・復号のエラーを先に型にする

- 日付: 2026-11-09
- 状態: 採用
- 対象: [未完了項目の統合](../reviews/2026-11-08-open-items-register.md) の M1（XCA-16・SPG-11・DEV-7）のうち `echode-history` の素材の境界。
- 関連: [ADR 0295](0295-typed-plugin-host-errors.md)（次の境界）、[ADR 0234](0234-typed-journal-durability.md)（保存の不確定）、[ADR 0290](0290-fuzz-targets-for-external-input.md)（外部入力）。

## 問題と範囲

- 開始時の HEAD は `dc29559`。`PackageError` は文と保存の不確定の真偽値だけを持っていた。
  `io::Error`・`serde_json::Error` は文にし、AudioToolbox の状態コードとプロパティ番号は文だけか、捨てていた。
- `read_package`・`read_object` の失敗は、パスが文にあっても `Error::source` がなく、ファイルの不在とアクセスの拒否を文でしか分けられなかった。
  素材の索引の不正な JSON も同じだった。
- `echode-history` には `Result<_, String>` が 32、文にする `map_err` が 131 あり、素材以外にも Git・スキーマ・トランザクション・間引きがある。
  自動保存は失敗の文を複数の待ち手へ複製して返す。ここを変える時は、原因の共有と保存の不確定の引継ぎを一緒に検査する必要がある。

## 比べた案

| 案 | 内容 | 判断 |
|---|---|---|
| 1 | crate 全体のエラーを一度に移行する | 採らない。素材の検証と Git・保存の寿命を同時に変えると、保存の不確定の保持や複数の待ち手の失敗を分けて照合しにくい |
| 2 | 公開する `PackageError` を列挙型にし、まず保管庫・復号・ピークの原因を型にする。未移行の経路を明示する | 採る。実データの検証を変えず、製品の入口で失敗の種類と原因を確かめられる |
| 3 | 文と真偽値を残したまま、別の分類だけを足す | 採らない。同じ失敗に文・分類・真偽値という別の正本ができ、同期の漏れを増やす |
| 4 | エラーをすべて `Box<dyn Error>` にする | 採らない。元の原因は残せても、PCM の検証・取消・ネイティブの失敗を呼出し元が列挙型で分けられない |

処理時間の最適化ではないので時間の計測はしない。
根拠は、修正前に失敗する製品の入口の回帰と、移行済みの範囲への再導入の拒否である。

## 決定

- `error.rs` の `PackageError` に、`Io { path, error }`・`Audio(MediaError)`・`MediaIndex`・不正なハッシュ・ハッシュの不一致・不正なピーク名を置く。
  `Io` は元の OS のエラーを持ち、パスは従来の文にあった時だけ付ける。共通の `document::io_error` を通るパッケージの I/O も原因を保つ。
- `MediaError` は、PCM の形式・ヘッダ・長さ・桁あふれ・非有限値、取消、予約の失敗、復号の読込み・位置移動・プロパティの失敗を分ける。
  チャンネル数とレートは拒否した値を持つ。AudioToolbox は元の状態コードを持ち、プロパティは番号と、読込みなら期待・実際のサイズも持つ。
- `Error::source` は I/O・JSON・音声・メモリ予約の元の原因へつなぐ。`HostError::Action`・`Package` も原因へつなぐ。
  文は `Display` で従来のまま作る。アプリへ渡す文・PCM・キャッシュ・保存形式・復旧と書込みの判断は変えない。
- 保存の不確定は `JournalDurabilityUnknown` という 1 つの変種にする。`is_durability_unknown` の意味は変えず、同じ文を持つ別のエラーを不確定と見なさない。
- 未移行の経路は `Message(String)` として明示し、既存の非公開の `new` はその経路だけに残す。
  新しい汎用のフォールバックではなく、残っている移行対象である。`HostError::Element` のトランザクションの文も今回は変えない。

## 回帰と再導入の検査

- `tests/storage_errors.rs` の最初の 2 回帰は、修正前に `storage error lost its I/O cause` と `media index error lost its JSON cause` で失敗した。
  期待終了コード 101 と回帰固有のアサーションを `checked_commands.py` で照合した。記録は `target/focused-checks/history-storage-red/`。
- 同じテストが、I/O と JSON の原因、索引の失敗時の保管物の取下げ、ハッシュと PCM の拒否の種類、取消・読込み量・位置移動の拒否、実ファイルを開けない時の状態コードを確かめる。
  `audio_import_validation.rs` の全非有限値の取込み回帰も、文だけでなく変種を照合する。
- `error_tests.rs` は元の errno・メモリ予約の原因・プロパティの詳細・従来の文・保存の不確定の区別を照合する。
- `scripts/check_typed_errors.py` に `TYPED_FILES` を設け、エラー定義・素材・保管庫・ピークの 4 ファイルだけを登録する。
  この範囲では `Result<_, String>`・文にする `map_err` に加え、`PackageError::new`・`PackageError::Message` へ戻すことを拒否する。
  登録ファイルの欠落も拒否する。Python の回帰は、拒否・通常の型・未移行範囲の区別を照合する。
- 新しい外部入力・依存・実行入口はない。既存の音声・パッケージの fuzz の対象が同じ入口を通り、通常の Rust 検査と `check-verification` が追加回帰を実行する。
  新しい検査の入口は足さず、`scripts/verification.json` の既存の非有限値の反例の置換箇所を新しい型に合わせる。選択条件は変えない。

## 残る範囲と次の単位

- crate 全体の移行は完了として扱わない。Git・自動保存・スキーマ・文書・間引きの文字列エラーは残る。
- 次は Git と自動保存の境界で、同じ原因を複数の待ち手へ返しても型を保つ形にする。その後にスキーマ・文書・間引きを進める。
- 公開する操作や音は変わらない。実機・聴感の追加確認は作らず、今回選択された計測・実機の見送り理由は検査レポートに残す。
