# ADR 0245: プラグインの取りこぼしと復帰を標本数でつなぐ

日付: 2026-11-03
状態: 採用。実機・第三者プラグインの聴感は UC-50 でユーザー確認待ち。

## 背景と再現

FCA-08 は `HostGraph::apply` が取りこぼしたトラックを即座にゼロへ置き換え、次の成功時にも生の出力へ戻していた指摘である。
機器を開かず、別プロセスのテスト CLAP の 2 回目の `process` をソケットで保留して再現した。
最初に左右 0.5 / -0.25 のプラグイン出力と、別トラックの左右 0.03125 / 0.0625 を鳴らす。
過去の期限を渡した次のブロックは、左が 0.53125 から 0.03125 へ落ち、継続性のアサーションが失敗した。
意図した red は終了コード 101 と、そのアサーションの文を照合した。時間の短さを合否には使わない。

## 決定

- フェーダー手前のトラックごとに `PluginDeclick` を持つ。成功中の波形と自然なノートの立上りは加工しない。
- 取りこぼしの最初の標本は直前に出した左右の値と同じとし、`max(2, sample_rate / 200)` 標本で線形にゼロへ下げる。
  同じ失敗が続いても減衰を始め直さない。入力の配列に残った音声や、遅れて完了した世代は使わない。
- 成功へ戻ったら、その時点で出した値から新しい波形へ同じ長さでクロスフェードする。
  減衰の途中で戻る場合や、復帰の途中で再び失敗する場合も、現在の出力からつなぎ直す。
- 左右を独立に保持し、モノは複製した平面を処理する。途中のモノの段が失敗しても最終段のバス形を変えない。
  フェーダー・パン・ミュート・メーターはこの後にあるため、健全な別トラックは減衰しない。
- 計画交換では同じトラックの状態を音声側で値として引き継ぐ。停止中のプラグイン処理にも同じ規則を使う。
  ヘルパーのないトラックやキャッシュへ移った時は状態を捨て、次のチェインへ古い値を持ち越さない。
- 標本数だけで進め、オーディオ側の確保・ロック・追加の待ち・先読み遅延は増やさない。
  補間は有限の f32 の極値でも発散しないよう f64 で行い、不正な値は保持しない。

## 境界

これは取りこぼした処理を復元する仕組みではなく、連続した波形を合成する保証でもない。
ヘルパーの待ちの期限、再送・再起動、ノートの解放と追いかけ、PDC、通常の停止フェードは変えない。
チェイン途中の失敗でも、その後段を含むトラック出力を減衰する。個々のデバイスの出力を補完して処理を続ける設計ではない。
`plugin_missed_blocks` とデバイスごとの失敗理由は残し、オフライン書出しは取りこぼしを成功として扱わない。
第三者の実時間の取りこぼしでクリックや回復の聞こえ方がどう変わるかは、自動の PCM 比較とは分けて UC-50 で確認する。

## 回帰と基盤

`hosted_playback/deadline_fade.rs` は、隔離ヘルパーの保留と解放で失敗・復帰を確定し、左右の各標本と健全な別トラックを照合する。
48 / 96 kHz、31 / 512 フレームで、減衰途中の計画交換、連続した失敗、失敗理由の保持と復帰時の解除を確認する。
`block_size/plugin_deadline.rs` は、1 / 7 / 31 / 64 / 512 / 1024 フレームと 44.1〜192 kHz で一致を比較する。
途中での反転、最小の減衰長、空・不一致の平面、有限性、リセット、通常の立上りも確認し、確保検出と RTSan の対象にする。

必須契約 `plugin-deadline-fade` を既存の契約実行器へ登録した。
負の対照は、取りこぼしごとの状態初期化と、計画交換時の引継ぎ忘れを別々に戻す。
新しい検査コマンドではないため、既存の Makefile の製品契約・通常テスト・RTSan の入口と領域選択を使う。
デバッグ手順には失敗回数・理由と PCM の段差を見分ける手順を追加した。
結果と実機計測の見送り理由は `target/verification/report.md` に記録する。
