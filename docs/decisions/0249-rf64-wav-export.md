# 0249. 大容量 WAV の RF64 自動切替

日付: 2026-11-03
状態: 採用（FCA-16・P2-08 のコンテナ拡張。ディザ・GUI・フレーム数の型変更は含めない）

## 背景と再現

[ADR 0248](0248-pcm16-wav-export.md) の後も、全形式でメタデータ込みの RIFF 長が u32 を超えると書出しを拒否していた。
`f7dff92` に `rf64_replaces_the_riff_size_limit_for_every_export_format` を追加し、
最大 RIFF の次のフレームで `RF64 export must replace the RIFF size limit` と失敗することを先に確認した。
終了コード 101 と、そのアサーションに続く既存の `wav data does not fit in a 32-bit chunk` を照合した。

## 決定

- CLI の float32・pcm16・pcm24 と既存の公開 Rust 書出し入口を、同じ RF64 自動切替へ接続する。
  メタデータ込みの RIFF 長が u32 を超える時だけ切り替え、拡張子・CLI オプション・省略時の float は変えない。
  RIFF に収まる出力は従来と同じヘッダとサンプルのバイト列を保つ。
- [EBU Tech 3306](https://tech.ebu.ch/docs/tech/tech3306.pdf) の RF64 を使う。
  先頭は `RF64`・`0xffffffff`・`WAVE`、直後に 28 バイトの `ds64` を置く。
  `ds64` は u64 の RIFF 長（ファイル長から 8 を引く）・データ長・フレーム数と、値 0 の追加チャンク表長を持つ。
  `data` の 32 bit 長は、データだけなら u32 に収まる場合も `0xffffffff` とする。
- RF64 の `fmt` は全形式で 40 バイトの WAVEFORMATEXTENSIBLE とする。
  cbSize=22、左右のチャンネルマスク=3、valid bits は格納ビット幅と同じで、PCM と IEEE float の subtype を分ける。
  float の `fact` は残し、その値を `0xffffffff` にする。実フレーム数は `ds64` に置く。
  この sentinel の扱いは [FFmpeg n7.1 の WAV ライター](https://github.com/FFmpeg/FFmpeg/blob/n7.1/libavformat/wavenc.c) とも照合した。
- サイズ計算を u64 にし、byte rate の u32 検証はファイル生成前に保つ。
  RF64 のヘッダ長は float=116 バイト、PCM16 / PCM24=104 バイトである。
  レンダラーのフレーム数は既存の u32 のままで、無制限の長さを保証する変更ではない。
- ストリーミング・量子化・プラグイン処理・一時ファイルの公開手順は変えない。
  完了前の失敗と取消は原本を保ち、公開後の親ディレクトリ同期失敗は完成出力を残して耐久性不明を返す。
  追加の依存・DSP・RT の変更はない。

## 回帰と基盤

- `src/rf64_tests.rs` で、各形式の最大 RIFF、メタデータだけの超過、データ長の超過、u32 最大フレーム数をヘッダだけで検査する。
  `ds64` の実長、sentinel、fmt の subtype・左右・ビット幅、float の fact を照合する。
- 製品の `WavFile` に先頭と末尾だけを書いた疎ファイルを作り、公開されたヘッダとファイル長を検査する。
  製品のレンダラーが無音を飛ばす変更ではない。大容量の確保はせず、検証用の物理使用量も確認する。
  独立した AudioToolbox の `AudioFileReader` で率・左右・フレーム数、先頭・中間の無音・4 GiB 超の末尾と EOF を検査する。
- 同じ疎ファイルに Drop・write・flush・rename・親の同期の故障を適用し、原本・完成出力・`.part` の後始末を分ける。
  既存の PCM 単体テストと同じ mutex を使い、プロセス全体に効く故障注入を直列化する。
- `tests/rf64.rs` は CLI のパースから製品レンダラーを通し、最初のブロックの次に書込みを失敗させる。
  RF64 範囲でもサイズ拒否で止まらずストリーミングへ届くことと、失敗時の原本保持を巨大なレンダリングなしで確認する。
  既存の PCM16 / PCM24 の CLI 拒否テストは、大容量の拒否ではなく RF64 範囲の不正な byte rate の拒否へ更新する。
  プラグイン付きの float の u32 最大フレーム数も、書込みの故障注入で短く検査する。
- README、設計、現在の制約、P2-08、監査の参照を更新する。
  デバッグ手順に RF64 の識別と旧読み手の拒否を追加し、索引にも載せる。
  通常の CLI テストの入口と選択は既存のまま有効で、Makefile・`scripts/verification.json` の変更は不要である。
  診断ログ・収集先・音声機器の扱いは変えない。

## 残る範囲

BW64、ディザ、他形式、GUI の書出しと設定保存、u32 を超えるフレーム数は未接続である。
すべての第三者の読み手との互換性や長時間の実レンダリング性能を保証しない。
自動回帰は音声機器を開かず、サンプル値も変えないため、新しい実機・聴感の確認待ちは作らない。
P2-08 と FCA-16 全体の完了ではない。
