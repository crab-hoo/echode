# ADR 0280: 全トラックを作り直す編集の採用を、事前の位置合わせと声の照合で短くする

- 日付: 2026-11-08
- 状態: 採用。実機の聴感は UC-47 が未確認。
- 対象: [統合表](../reviews/2026-11-08-open-items-register.md) の R1 の残り（[ADR 0279](0279-unchanged-track-voice-handover.md) の「残る範囲」）。
- 置き換え: ADR 0279 の、作り直したトラックの声をノートごとの二分探索で解放・引継ぎする処理。

## 問題

ADR 0279 の後も、作り直したトラックの採用は、トラックごとに位置合わせの探索と、鳴っているノートごとの ID の探索を行った。
テンポとレートが変わると全トラックを作り直す（ADR 0274）ので、テンポの編集で全トラックがこの費用を払う。
`make spike-scale` に、基準テンポの変更（全ノートが動く）と、全ノートの後ろへのテンポ点の追加（ノートは動かないが全トラックを作り直す）の行を足した。
256 トラック × 4,000 ノート、48 kHz・128 フレームで、`9fc3324` の採用のブロックは次のとおりだった（µs）。

| 編集 | 採用までのブロック | p50 | 最大 |
|---|---:|---:|---:|
| 基準テンポ | 100 | 892.4 | 1,575.9 |
| 基準テンポ | 3,500 | 1,167.9 | 2,308.4 |
| 後ろのテンポ点 | 100 | 2,177.1 | 2,598.8 |
| 後ろのテンポ点 | 3,500 | 1,981.9 | 8,708.6 |

予算は 2.67 ms である。後ろのテンポ点は、全部の声が続くので、ノートごとの探索が最も多い。

## 比べた案

| 案 | 内容 | 判定 |
|---|---|---|
| 1 | 探索の鍵を連続した配列に置き、キャッシュの読込みを減らす | 採らない。読込みは半分程度にしかならず、トラック数に比例して残る |
| 2 | 新しいカーソルを、ブロックごとに数トラックずつ音声側で用意してから採用する | 採らない。採用が遅れ、音声側に準備中の計画という状態が増える |
| 3 | 制御側で直前の位置に置き、音声側はその後のノートだけ進める。声は ID の整列で照合する | 採る |

## 決定

- 制御側は、計画を音声側へ渡す直前（`publish_graph`）に、新しいカーソルを最後に公開された位置と追いかけの規則で置く（`Cursor::catch_up_from`）。
  位置と規則は、コールバックが状態の公開（`publish_status`）で毎ブロック書く。2 つの値は別々に読むので、組がずれることがある。
- `Cursor::take_over` は、置いた位置と規則が前のカーソルの規則と同じで、規則の起点 ≤ 置いた位置 ≤ 採用の位置の時だけ、置いた状態を使う。
  この時、作り直したトラックは、その後に始まる・終わるノートだけを進める（`advance`）。進む端が 32 を超えるトラックは、従来どおり探索で置く。
  条件に合わない時（ずれた組、間の位置移動・折り返し、遅れた採用）は、全部を探索で置く。結果は同じで、遅いだけである。
  置いた状態は、その位置と規則だけで決まり、そこに至った経緯によらない。そのため、この条件で正しさが保たれる。
- 作り直したトラックの鳴っている集合と、前のカーソルの同じトラックの集合を、モデルのノート ID で整列して 1 対 1 で照合する。
  照合できた声は発音時のキーを引き継ぎ、届いた声なら引き継いだ印を付ける。前の側の照合できない声は解放する。
  ノートごとの ID の探索（`covering`）と、そのための `NoteIndex::by_id` はなくした。
- 作り直したトラックも、前のカーソルの追いかけの規則で置く。ループの折り返しでは、ループの前から続くノートを追いかけない（ADR 0239）。
  これまでは作り直したトラックだけ全部を追いかけ、そのノートを引き継いだ扱いにしていた。そのため、鳴らしていないノートへ後でノートオフを出していた。
  これで、変わらないトラック（ADR 0279）と作り直したトラックが同じ規則に従い、引き継いだ声は前のカーソルが鳴らしている声と一致する。
- 新しく起動したヘルパーへ追いかけるノートオンは、従来どおり新しい計画の音高を使う。ノートオフは発音時のキーを使う。
- 解放の書込みに失敗した時、前のカーソルは声を保つ（集合の並びだけが変わり得る）。新しいカーソルは捨てる。変わらないトラックの入替えは、失敗し得る処理の後に行う。
- オーディオスレッドで確保・ロック・待ちはしない。整列は確保しない `sort_unstable` で、鳴っている声の数だけを並べる。

## 同条件の計測

Apple M4、release、機器・プラグインなし。同じ作業ツリーで、`9fc3324` のソースと変更後を続けて測った（`make spike-scale`、µs、`replace` は ms）。

| 編集 | 採用までのブロック | p50 前 → 後 | 最大 前 → 後 | `replace_p50_ms` 前 → 後 |
|---|---:|---:|---:|---:|
| 1 ノート | 100 | 324.4 → 304.8 | 403.7 → 327.5 | 5.9 → 7.3 |
| 1 ノート | 3,500 | 316.7 → 307.7 | 350.0 → 364.3 | 5.8 → 6.8 |
| 基準テンポ | 100 | 892.4 → 342.2 | 1,575.9 → 435.1 | 500.5 → 488.5 |
| 基準テンポ | 3,500 | 1,167.9 → 362.0 | 2,308.4 → 522.9 | 490.9 → 489.5 |
| 後ろのテンポ点 | 100 | 2,177.1 → 401.2 | 2,598.8 → 454.5 | 509.7 → 488.6 |
| 後ろのテンポ点 | 3,500 | 1,981.9 → 393.4 | 8,708.6 → 439.0 | 533.5 → 489.3 |

同じ回の通常のブロックは約 238 µs である。ループの折り返しは揺れの範囲で変わらなかった。
1 ノートの編集の `replace` は約 1 ms 増えた。制御側で全トラックを置き直すためで、変わらないトラックの分は使われずに捨てられる。
単回の経過時間の比較で、実機の期限内の完走や全入力の最悪時間は保証しない。計測は `replace` の直後に採用するので、置いた位置と採用の位置が一致する。
製品では、計画が音声側に取られるまでの間に進んだノートの分だけ、`advance` の端が増える。

プラグインありの `spike-plugin-tracks` は、検証用ヘルパーの 1 トラックの編集で、作り直しは 1 トラックだけである。
`make verify` の `--run spike-plugin-tracks` の回は、別のアプリが 1 コアを使い続けていて（負荷平均 8.9）、変更と無関係な通常のブロックも約 1.5 倍に遅かった。
そのため同じ負荷の下で `9fc3324` と交互に 2 回ずつ測った。256 トラックの採用（`plugin-edits`）の CPU p50 は、前 1,252.3・1,204.2 µs、後 1,223.8・1,222.2 µs で、
通常のブロックも前 1,081.2・948.1 µs、後 947.9・949.8 µs だった。この単位で変わらないことの確認であり、改善は主張しない。

## 回帰と基盤

- `cursor_tests::an_unchanged_track_plays_as_if_no_plan_had_been_adopted` に、事前の位置合わせ（前・後ろの位置、古い規則、なし）と、トラック全体の移動を足した。
  作り直したトラックが、前の規則で新しく置いた状態と、索引・鳴っている集合で一致し、続く声のキーを保つことを確かめる。使える置き方と使えない置き方の両方に十分届いたことも検査する。
- `an_edited_track_does_not_chase_notes_the_loop_did_not_restart` は、ループの前から続くノートを、編集したトラックでも追いかけず、ノートオフも出さないことを確かめる。
  作り直したトラックを全部追いかける旧規則にすると、このテストと上のテストが失敗することを確かめた。
- `a_placed_cursor_adopts_a_moved_score_without_reading_it` は、全ノートを動かした計画を置いた位置から採用し、探索の配置が 0 回で、読むノートの数が楽譜の大きさによらないことを確かめる。
  探索の回数はテストだけの計数（`search_placement`）で数える。置いた状態を使わないようにすると失敗することを確かめた。
- `make spike-scale` に `tempo_adoption`（基準テンポ）と `marker_adoption`（後ろのテンポ点）の行を足した。検査の選択の入力は変えていない。

## 残る範囲

- 作り直したトラックの制御側の作り直し（256 × 4,000 で約 0.49 秒）は、FCA-04 と同じく残る。テンポの編集が聞こえるまでの遅れになる。
- 1 ノートの編集でも、制御側は全トラックを置き直す（約 1 ms）。トラックごとに置いたかを持てば省けるが、状態が増えるので測ってから決める。
- 実機での期限内の完走と聴感、ループ中の編集の聴感は UC-47 に残す。
