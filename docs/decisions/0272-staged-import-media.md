# ADR 0272: 取込みの素材を受理した編集と一緒に公開する

- 日付: 2026-11-06
- 状態: 採用
- 対象: EXT-02。参照の消えた素材を保管庫から消す掃除（[ADR 0031](0031-content-addressed-store.md)）は対象外。

## 問題と再現

文書ホストは外部音声を復号して保管庫へ書き、`media/index.json` とピークを足してから、配置の編集を確かめていた。
配置や同じ要求の後続が拒否されても、素材・索引・ピークは残った（[精査](../reviews/2026-11-06-assessment-review.md)）。
`audio_import_validation::audit_ext02_a_rejected_import_leaves_no_media_in_the_package` は、無いトラックへの取込みと、後続が失敗するトランザクションの後に、素材 2 つと索引が残ることを再現していた。

## 決定

取込みを「段階」と「公開」の 2 つに分ける。

- 段階: 復号・有限値の検証・PCM 化の後、`media/objects/` の中へ一時の名前で書き、同期する。
  ハッシュの名前・索引・ピークには触れない。同じバイト列の保管物が既にあれば書かない。
- 公開: 編集が受理された時だけ、一時の名前をハッシュへ改名し、ディレクトリを同期してから、索引とピークを作る。
  ジャーナルの行はその後に書く。保管物を行より先に同期する順序（XCA-03）と、同期の回数は従来と同じである。

失敗の扱い:

- 編集やトランザクションが拒否された時は段階を捨て、一時の名前を消す。トランザクション内の全ての取込みが対象である。
- 公開の後でジャーナルの行が書けず、行が残っていないと分かる失敗では、この要求が新しく作った名前を消す。前からあった保管物は消さない。
- 耐久性が不明な時（[ADR 0230](0230-save-durability.md)）は消さない。開き直すとその行が再生され得るからである。
- 索引の書込みに失敗した時は、作った名前を消して取込みを失敗にする。

一時の名前は `write_atomic` と同じ `.<hash>.<pid>-<seq>.tmp` で、`.gitignore` の `/media/objects/` の下にある。
段階の途中でプロセスが落ちると一時ファイルが残り得る。既存の原子的な書込みと同じ扱いで、ハッシュの名前にはならない。

保存形式、保管庫の命名、公開 API の `import_audio`（段階と公開を続けて行う）は変えない。
プラグイン状態の `write_object` も同じ段階と公開の経路を使い、結果は従来と同じである。

## 回帰と基盤

- EXT-02 の再現の `#[ignore]` を外して通常テストにした。比較の対象へ `cache/` のピークも加えた。
- `host_tests::an_import_keeps_its_object_only_while_its_journal_line_can_name_it` は、注入したジャーナルの失敗で次を確かめる。
  - 書込み前と同期の失敗では、単一の取込みでもトランザクションでも、保管庫に一時ファイルも残らない。
  - 受理済みの編集が使う保管物は、後の失敗した取込みで消えない。
  - 耐久性が不明な行は開き直しで再生され、全ての配置が保管物を読める。
- 非有限値の拒否・Redo の保持・除外規則の既存の回帰は維持する。
- 通常の crate テストで実行されるため、検査の登録は追加しない。

## 残る範囲

- 保管庫の掃除は未実装のまま。Undo で外した配置や削除した配置の素材は残る。
- 段階の途中のクラッシュで残る一時ファイルは掃除しない。
- 圧縮形式での保管と流しての書込み（FCA-18）は対象外で、段階の書込みも PCM の全体を一度に持つ。
