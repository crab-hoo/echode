# 0268. 書出しの診断は先頭と末尾を一定量だけ表示する

- 日付: 2026-11-05
- 状態: 採用
- 関連: [ADR 0254](0254-gui-snapshot-export.md)、[ADR 0210](0210-sanitizer-test-width.md)

## 再現

FCA-12・15・19 の対応後の TSan 検査で、書出しの実 CLI は終了コード 0 で WAV を公開したが、
`job.detail.contains("exported ")` の検査が失敗した。
固定した TSan ランタイムのロードを照合する `DYLD_PRINT_LIBRARIES` は子の CLI にも継承される。
その標準エラーが 64 KiB を超え、`ExportJob.render` が読む先頭部分から、最後の完了・エラー情報が落ちた。
ライブラリ出力やサニタイザを止めるのではなく、通常の製品でも大量の診断の最後を読めるようにする。
初回のイベントとログは `target/focused-checks/export-diagnostics-first-failure/` に残す。

## 決定

- ファイル自体を一度にメモリへ読まず、表示する診断の読込み予算を従来どおり 64 KiB とする。
- ファイルが予算以内なら全体を変えずに表示する。
- 超過時は先頭 32 KiB と、ファイル末尾から位置指定した 32 KiB を読み、中間を省略したことを明示する。
  省略表示・終了コード・出力先等のメタデータはこの診断のバイト予算とは別である。
- UTF-8 の不正な並びや切断は従来と同じ置換復号とする。
- 読込みは既存の非主アクターの処理内で行う。音声・曲・素材の容量や、ディスク上のログの上限ではない。
- 成功・取消は従来どおりプロセスの終了理由と終了コードから決める。診断の文言で成功を作らない。

## 回帰・検査基盤

`ExportDiagnosticsTests` は空・境界直前後・超過したファイルと短い日本語を比較する。
子プロセスが大量の標準エラーを書いて正常／異常終了する経路は必須契約 `export-diagnostics-ui` とし、
先頭だけへ戻す反例で、末尾の固有の診断が失われることを検出する。
引数付きの必須契約は、Swift の `with N test cases` の成功・失敗を検査器が照合する（N は 1 以上）。
初回は引数なしの関数だけを認識する判定により正例が拒否されたため、検査器の回帰を先に失敗させて両方の判定を修正した。
0 ケース・スキップ・別関数・複数の関数・ビルド失敗を受理しない条件は維持する。

追加回帰の最初の実行は、ディスクの残量が 227 MiB の時に Swift の署名で停止し、アサーションまで進まなかった。
これは意図した red とは扱わない。空き容量の回復後、同じビルド先で追加回帰が通ることを確かめ、
先頭だけへ戻す反例が契約のテストを失敗させることは全契約の反例の検査（`check-contract-controls`）で確かめた。
検査結果と実行した反例は `target/verification/report.md` と `product-contracts.json` に記録する。
初回の失敗ログは維持し、容量不足による停止と製品修正の検査結果を分けて記録する。
