# ADR 0153: 値の操作子のクリック規則と数値入力を共通にする

- 日付: 2026-10-24
- 状態: 採用。[操作の要望](../reviews/2026-10-21-ui-feedback-audit.md#修正の進め方) の単位 6（UIF-04）を接続。
  実画面の操作感・VoiceOver・第三者プラグインの文字変換はユーザー確認待ち。
- 範囲: トラックヘッダの音量・パン、クリップのゲインとフェードのハンドル、デバイス列のパラメーター欄、CLAP の `text_to_value`
- 仕様の正本: [値の操作子の既定値と数値入力](../interaction-design.md#値の操作子の既定値と数値入力)

## 背景と再現

ヘッダの音量・パンとパラメーター欄のスライダーは、押した位置へ値が跳んでいた。
単クリックでも値が変わって Undo が増え、ダブル・トリプルクリックの各クリックも編集になる。
修正前の必須契約 `track-mix-ui` は、パンの単クリックで値が 0.5 になることを合格条件にしていた。
新しい規則へ実装を変えると、この契約は押した位置への跳びを期待する 3 か所で失敗した。
パラメーター欄は NSSlider の追跡に任せており、同じく押した位置へ跳ぶ（監査時のソースの読み取り）。
既定値へのリセットと、操作子の上での数値入力はなかった。
プラグインの文字入力に要る CLAP の `text_to_value` は未接続だった。

## 決定

### クリック規則を 1 つの部品にまとめる

- `ValueClicks`（`ValueControl.swift`）が、操作子の種類によらず押下・ドラッグ・離す・取消を受ける。
  - 単クリックは値を変えない。動かした時に初めてプレビューを始め、押した位置からの相対量で動かす。
  - ダブルクリック（2 回目の押下）は既定値をプレビューで仮に表示し、離してからダブルクリックの間隔だけ待つ。
    間隔内に 3 回目が来なければ 1 回の Undo で記録する。待つ間のドラッグは値を変えない。
  - 間隔内の 3 回目の押下は、プレビューを取り消して元の値へ戻し、入力欄を開く。
  - 待つ間の別の操作子の押下・キー入力は、表示中の既定値をその場で記録してから処理する。
    Escape・押下の取消・ビューの除去は元の値へ戻す。
- 待ち時間は `NSEvent.doubleClickInterval` で、AppKit のクリック数の判定と同じ間隔を使う。
  タイマーはメインキューで動き、マウスの追跡中も止まらない。
- 既定値は操作要件のとおり、音量 0 dB、パン中央、クリップのゲイン 0 dB、フェードなし、プラグインが報告する既定値とする。
- ミュート・ソロは値の操作子ではなく、従来どおりクリックで切り替える。
  ノート挿入・サンプル配置・FX 追加など、値以外の既存のダブルクリックは変えない。

### 各操作子の接続

- ヘッダの音量・パンは、既存のフェーダーのプレビュー（`beginFader` / `changeFader` / `finishFader`）をそのまま使う。
  相対量は操作子の幅に対する移動量で、音量は表示位置（−60 dB〜+12 dB）、パンは −1〜1 の範囲で動かす。
- クリップのハンドルは、既存の描画用の下書き（`ClipDraft`）をプレビューにし、確定時に 1 回だけ編集を送る。
  フェードは押した時のハンドル位置からの水平移動にした（従来はポインターの絶対位置）。
- パラメーター欄は NSSlider の追跡を使わず、同じ部品で押下を受ける。
  ドラッグは押した値からトラック幅に対する割合で範囲を動かし、段階値は従来どおり制御側で丸める。
  取消は従来の `finishParameter(commit: false)` で元の値をプラグインへ戻してから記録する（同じバイトは履歴に積まない）。
  キーボード・VoiceOver の 1 段階は NSSlider の処理のまま、即時に記録する。

### 入力欄

- `ValueEntryField` を操作子の上に重ねて開き（最小 72×22 pt、ホストの内側に収める）、現在の値を全選択で示す。
- Return で確定、Escape で取り消す。使えない値の Return は欄を開いたまま赤く示す。
- フォーカスが欄の外へ移った時は、使える値なら確定し、使えない値は破棄して閉じる。
  インスペクターの数値欄（フォーカス喪失で確定）と揃えた。
- 単位と範囲はインスペクターと同じにする。音量・クリップのゲインは dB と −∞、パンは %、フェードは ms。
  単位の付いた入力と全角のマイナスも受ける。
- 編集中は修飾キーなしのキーを欄で処理し、メニューの Space（再生）へ渡さない。
  ⌘Z / ⇧⌘Z は欄の入力の取消・やり直しにし、文書の Undo へ渡さない。
  SwiftUI の入力欄が使う `workspaceTextEntry` は AppKit の欄から設定できないため、欄の側でキーを先に受ける。
- 確定は 1 回の編集で、Undo も 1 回になる。値が変わらない入力は記録しない。

### プラグインの表示単位での入力

- 制御ソケットに `ParseParam { id, text }` と応答 `ParamParsed` を加えた。
  ヘルパーはプラグインのメインスレッドで `text_to_value` を呼ぶ。読むだけで、プラグインの値は変えない。
- 応答は 3 通りに分ける。値（有限）、プラグインが拒否、`text_to_value` を持たない（または `clap.params` がない）。
  NUL を含む文字列と非有限の値は拒否として扱う。
- FFI は `device.parameter.parse` を既存のデバイスレーンで扱い、`{"parsed": {id, value, converts}}` を返す。
  文書ワーカーは待たず、ミキサー・削除済み・オフラインのデバイスは従来どおり拒否する。
- 画面は、変換を持つプラグインではその値を、持たないプラグインでは入力を数値として読む。
  範囲外は使えない値とする。確定は既存の `setParameter`（適用と記録）で 1 回の Undo にする。
  入力欄の初期値はプラグインの表示文字列（なければ数値）とする。

## 検査と診断

- 必須契約 `mix-clicks-ui` はヘッダの実マウス入力で、ダブルクリックの仮表示と間隔後の 1 回の記録、
  トリプルクリックの復元・入力欄・Space の入力・使えない値・Return / Escape・Undo・保存の再読込を確認する。
  負の対照は 3 回目で既定値を記録する誤り。
- 必須契約 `clip-clicks-ui` はクリップのハンドルで、ゲインの既定値と dB・フェードの ms の入力を確認する。
- 必須契約 `fx-params-clicks-ui` は実際のパラメーター行で、単クリックで送信しないこと、相対ドラッグ、
  ダブルクリックの既定値、トリプルクリックの元の値への復帰と、変換あり・なしの入力を確認する。
  負の対照はプラグインの変換を無視する誤り。
- 必須契約 `plugin-text-parse` は実ヘルパーとテスト用 CLAP で、表示単位の変換・拒否・変換なしの区別と、値を変えないことを確認する。
- `track-mix-ui` を相対ドラッグと単クリックの不変へ改めた。`clip-mix-ui`・`fx-params-ui` は変更なしで通る。
- 状態機械の単体回帰（`ValueControlTests`）で、待ち・取消・別の操作子・拒否の遷移を確認する。
- 失敗の切り分けは [デバッグ手順](../debugging.md) に置く。
  欄が赤いままなら入力が範囲外か、プラグインが拒否した。`helper did not read the parameter text` は通信の失敗である。

## 残る範囲

- 実画面のクリックの間隔・欄の見た目・VoiceOver、Space が再生へ漏れないことの実機確認はユーザー担当とする。
- 第三者プラグインの `text_to_value` の挙動（単位の書き方、範囲外の扱い）は未確認である。
- プラグインの値の範囲外の入力は拒否し、範囲へ丸めない。
- 微調整の修飾キー（Option・Shift のドラッグ）と、スクロールでの値の変更は未定義である。
- ミキサーのコンソール表示（P2-06）とオートメーションの点（P2-04）は、同じ部品を使う前提で各単位に残す。
