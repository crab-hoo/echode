# ADR 0185: ピアノロールの自動・固定グリッド

- 日付: 2026-10-28
- 状態: 採用。P2-07 の先行分。実画面・VoiceOver はユーザー確認待ち
- 関連: [操作要件](../interaction-design.md#構成を考えながら入力する)、
  [ADR 0172](0172-piano-click-and-input-length.md)、[ADR 0174](0174-shared-piano-viewport.md)

## 背景と再現

開始時の HEAD は `36f9710`。ポインターの時刻を保つピンチは接続済みだったが、
ノートの吸着幅は常に 16 分音符で、固定幅を選ぶ入口もなかった。
製品のカメラを 2 倍にズームして実 View へ復元する回帰を先に追加し、
期待した 88,200 tick ではなく 176,400 tick のままであることを確認した。
期待終了コード 1 と固有のアサーションの照合は `target/focused-checks/piano-grid-red/` に記録する。
このパスはローカルの一時ログであり、永続的な証拠の参照先ではない。

## 決定

- `PianoCamera.gridMode` は既定を自動とし、`grid` は現在の横倍率から計算する。
  全音符〜128 分音符のストレート音価から、間隔が 18 pt 以上になる最も細かいものを選ぶ。
  倍率の既存範囲 8〜1200 pt/拍ではこの候補内に収まり、初期の 72 pt/拍は従来の 16 分音符になる。
- ネイティブの `PianoGridBar` をピアノロールの上端 28 pt に置く。
  自動／固定音価のポップアップと現在の音価を表示し、キーボードと VoiceOver からも選べる。
  固定時はズームしても tick 幅を変えない。三連符・付点・任意幅は今回の範囲に含めない。
- 入力・移動・伸縮・複製・矢印・ルーラーは既存の共通 `camera.grid` を読む。
  Shift の吸着解除と新規ドラッグ／既存伸縮の最短長の規則は変えない。
  記憶済みの入力長を丸め直さず、未記憶のクリックだけがその時のグリッドを初期長にする。
- ポインターの時刻を保つ横ピンチ、Option の音域ズーム、Shift の両軸ズームは従来どおりとする。
  グリッドの変更は未確定の押下を取り消し、古いフレームや遅れた解放で追加・編集・シークしない。
- ノート領域の縦線を現在のグリッドに合わせる。
  細かい固定幅を縮小した時は 4 pt 未満の線を 2 倍刻みで間引き、吸着幅自体は変えない。
  処理と記憶量は表示幅に比例し、曲全体の長さに比例させない。
- モードはカメラとともに文書内で共有し、トラック切替・エディタ再生成で保つ。
  別文書／再オープンは自動へ戻す。文書と現存トラックの所有確認で古い操作子の書戻しを拒否する。
  モデル・ジャーナル・Undo・保存形式・音声処理は変更しない。

## 受入と基盤

- `piano-auto-grid-ui` は実ピンチ、時刻固定、自動幅、描画の細分線、クリックの吸着と初期長を検査する。
  製品 controller と ABI から単一 Undo / Redo・保存再読込へ通し、固定幅・時刻ずれ・線の欠落の負の対照を持つ。
- `piano-fixed-grid-ui` は実操作子、固定幅と修飾キー、記憶長、矢印・ルーラー・端の吸着、
  押下の取消、トラック間共有、再生成、別文書での初期化を検査する。
  モード反映・取消・文書所有確認の欠落を負の対照にする。
- 通常回帰は自動幅の切替境界、全固定音価のズーム不変、表示幅に収まる間引きを扱う。
  `spike-piano-frame` は背景の採取位置を細分線から離し、倍率 1・2 の細分線の GPU 画素も比較する。
- 既存の Makefile 入口、検査登録と選択回帰、利用手順・現状・Phase 2・領域設計・デバッグ手順を更新する。
  診断ではカメラのモード・実効 tick 幅と提出フレームを区別する。
  製品の新しいログ・外部入力・ヘルパーはなく、`doctor` と `debug-report` の収集先は追加しない。
- 作業中に、復旧警告の既存テストが ASan 全体で 2 回、TSan 全体で 1 回期限切れになった。
  単独では再現せず、TSan の診断では最初のオープン中・未公開・エラーなしだった。原因は未確定である。
  （2026-10-31 追記: 同じ形の期限切れの原因は主アクターの占有と判明した。[デバッグ手順](../debugging.md)を参照。）
  復旧スイートを sanitizer の全体実行から別プロセスへ分け、対象と 5 秒の期限を維持する。
  分離した実行の 0 件と失敗を拒否する回帰も加え、待機の診断へ段階・文書・エラーを残す。
  追加ログ `recovery-swift-tests.log` は既存の `debug-report` の収集パターンに含まれる。
- 音を作る処理やアクションは増えないため、ブロック長比較とランダム操作生成の追加は不要である。
  実画面の密度・選びやすさ・ピンチの操作感と VoiceOver はユーザー担当とし、P2 全体の完了とはしない。
