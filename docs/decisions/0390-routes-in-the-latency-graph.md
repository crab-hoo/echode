# ADR 0390: センド・サイドチェイン・ドラムの MIDI 配布を、遅延グラフへ写す経路にする

- 日付: 2026-11-16
- 状態: 現行
- 領域: 音声エンジン・書き出し
- 一部置換: [ADR 0340](0340-latency-graph.md) の、バイパスした装置の遅延を鎖の最後にまとめる規則と、合流を足す時に段ごとの線へ変えるとした予定
- 関連: [ADR 0116](0116-folder-drum-rack.md)、[ADR 0277](0277-reaper-style-folder-bus.md)、[ADR 0338](0338-folder-bus.md)、[ADR 0339](0339-plugin-delay-compensation.md)、
  [ADR 0378](0378-pdc-stage-transport.md)、[ADR 0383](0383-pdc-stage-notes.md)、[P2-03](../phase2.md#p2-03-ルーティングフォルダバスpdc)

## 問題

開始時の HEAD は `b83de32`。
P2-03 の残りのセンド・サイドチェイン・ドラム用の MIDI 配布について、ADR 0340 は「`compensate` がグラフへ足す辺」とだけ決め、写し方は決めていなかった。
モデルには、まだどれもない。製品へつなぐ前に、合流の時刻の規則を 1 か所で決めて検証しておく。
読んで見つけた穴は次のとおり。

1. **位置の順の前提**: `compensate` は親が子より前の位置にあることを求め、そうでなければ断っていた。センドとサイドチェインの宛先は、前にも後ろにもある。
2. **鎖の途中の合流**: サイドチェインは装置の入力で鎖の音と出会う。
   バイパスした装置の遅延を鎖の最後にまとめると、グラフは揃っても、バイパスの切替で合流の時刻が動く。
   例: 鎖 `X(100)・D` の D が 50 で着く鍵を受ける。X が動けば D は 100 で鳴り、X をバイパスすると D は 50 で鳴り、出力に 100 を足すので 150 になる。
   ほかのトラックとマスターの遅れが動き、ADR 0339 の「バイパスはほかのトラックを動かさない」が崩れる。
3. **見かけの循環**: ドラムラックは親の MIDI を子へ渡し、子の音を親へ戻す。トラックを 1 つの節とすると循環に見える。ADR 0116 はこれを循環として断ることを禁じている。
4. **線の数え漏れ**: 記憶域の予算は、`compensate_plan` が 3 種の線とクリックを並べて数えていた。線の種類が増えるたびに、数える場所も直す必要があった。

## 比べた案

### 経路の表し方

1. **機能ごとに `compensate` の引数と式を足す**: ADR 0340 が避けた形である。
2. **1 つの `Routes` に写す（採用）**: トラック（親・配置音声・装置・ノートの出所）と、センド・サイドチェインの一覧を持つ。
   全てのトラックの節を先に作ってから、親・センド・サイドチェインの辺を張る。位置の順に依らない。
   循環は従来どおりソルバーが `Feedback` で断る。親が子の前にある必要はなくなった。

### 取り出す位置

センドとサイドチェインの音は、鎖の後、出力の線とフェーダーの前から取り出す（FX 後・フェーダー前）。
新規センドの既定（設計書 8.3）であり、出力の線と同じ節から出る。
鎖の途中とフェーダー後の取り出しは、取り出し位置の節を足すだけで加えられる。製品のモデルと一緒に決める。

### バイパスした装置の遅延を使う場所

1. **鎖の最後（ADR 0339・0340）**: 上の穴 2。
2. **段ごとの線（ADR 0340 の予定）**: バイパスした装置ごとに乾いた音を遅らせる。
   正しいが、合流のない鎖でも製品の音声経路へ線を足し、後ろの装置の音・ノート・トランスポートの時刻が今と変わる。合流のない鎖では得るものがない。
3. **次の合流で使う（採用）**: 他の音が鎖に入る点、つまり鍵を受ける装置の入力か出力の線が、それまでにバイパスした遅延を持つ。
   合流のない鎖は ADR 0339 と同じ音のままである。合流の時刻は切替で変わらず、変わるのはそのトラックの線だけである。
   鍵を受ける装置そのものをバイパスしても、その節は合流のまま（遅延 0）残り、自分の遅延を次の合流へ渡す。
   鍵の線は鳴り続けるので、解除で時刻が跳ばない。

### ドラムの MIDI 配布

1. **子の最初の音源を親の入力の節からつなぐ**: 子の音が親へ戻るので循環になる。変異で確かめた（下）。
2. **トラックごとにノートの節を置く（採用）**: ノートの節は時間軸を読み、遅延 0 である。
   最初の音源は、ノートを出すトラック（自分か、`notes_from` のトラック）のノートの節からつながる。
   ノートの節は親の音声の節と別なので、配布と子の音の戻りは循環にならない。
   ノートは時間軸からすぐ出るので、配布の辺が音源を遅らせることはない。
   音源が鍵で遅れる時、その辺の遅延は段の入力の遅れ（`stage_inputs`）と同じになり、ノートのカーソル（ADR 0383）がその分だけ遅らせる。
   ノートを加工する装置ができたら、その節からつなぐ。
3. **自分のノートは時間軸を読むままにし、配布だけ辺にする**: 音源 1 つにつき節と辺が 1 つ減る。
   同じ時刻の出所に 2 つの規則を持つことになるので、採らなかった。費用は下の計測のとおり小さい。

### 線の数え方

`Compensation::lines` が計画の全ての線を返し、`compensate_plan` の予算はそれだけを数える。線の種類を足すと、予算に自動で入る。

## 決定

- `compensation.rs` に `Routes { tracks, sends, sidechains }`、`TrackFlow::notes_from`、`SendFlow`、`SidechainFlow`、`StageLine` を置く。
  `Compensation` は `sends`・`sidechains`・`stage_lines`（鍵を受ける装置の本線）と `lines` を返す。
- 範囲外の位置・装置の番号は `BufferTooSmall`（内部の不整合）、循環は `Feedback` で断る。
- 取り出し元に未使用のバイパス分があれば、その元から出る全ての線が持つ（出力の線と同じ）。
- 鍵を受ける最初の音源には本線がない。音源は鎖の音を聞かず、ノートで鳴るからである。
- 鍵の経路も余韻の最大に数える。バイパスした装置の鍵は出力に届かないが、時刻を保つため辺を残すので、余韻は長めに見積もる（書出しの末尾の無音が延びる側）。
- 製品の `compensate_plan` は、今はフォルダだけを `Routes` に入れる。製品の音と線の長さは変わらない。増えるのは、音源ごとのノートの節と辺だけである。
- 保存形式・アクション・Undo・コールバックは変えない。

## 残る範囲

- **モデルと操作**: センドの接続 ID・量・取り出し位置、デバイスの鍵の出所、ドラムの音とパッドの割当、保存・Undo・アクション・API・画面。
- **コールバック**: センドの和、鍵の音をヘルパーの主でない入力ポートへ渡す経路（今はゼロ、ADR 0382）、ドラムの子へのノートの振り分け。
  受け側が送り元を待つ実行の依存（`playback_bus.rs` の待ちの数）も同じ `Routes` から作り、別の論理で書かない。
- **ミュート・ソロ**: センド・配布との関係（設計書 8.3、ADR 0116）。
- 鎖の途中・フェーダー後の取り出し、1 ブロック遅れの帰還（ADR 0340 のまま）。
- 製品から届かないので、聴感・実機の確認待ちは足さない。デバッグ手順も、製品が `Feedback` を受ける経路を足した時に更新する。

## 回帰と基盤

`compensation_tests.rs` に足した。

- センドの受け側が送り元の遅れで鳴り、送り元がマスターで受け側を待つ。バイパスした送り元のセンドの線が、出力の線と同じ分を持つ。
- 鍵を受ける装置の本線と鍵の線。鍵の前と鍵を受ける装置自身のバイパスの 3 通りで、遅れ・ほかのトラック・鍵の線が変わらない。
- ドラムラックの親のノートを 2 つのパッドが鳴らし、子の音が親へ戻っても循環にならない。鍵で遅れるパッドの音源が、その遅れでノートを受ける。
- 循環の 5 通り（相互のセンド、自分へのセンド、親から子へのセンド、自分の鍵、センドを経る鍵）と、範囲外の 6 通り。子から親へのセンドは循環でない。
- `lines` が全ての線を返す。親が子より後ろの位置でも解け、自分の親・相互の親は `Feedback` になる。
- 乱数の経路 400 個: 位置を混ぜた木・センド・鍵・ノートの出所を、コールバックが線を置く順の模型（`arrivals`）に通す。
  全ての合流で入力が揃い、各装置が音を聞く時刻が `stage_inputs` と一致し、マスターで全てが遅れに着く。
- 乱数の経路 300 個で装置を 1 つバイパスし直し、遅れ・クリック・ほかのトラックの線と装置の時刻・ほかの送り元の線が変わらない。

変異で回帰が落ちることを確かめた（記録だけで、変異は残していない。ログは `target/focused-checks/route-mutations/`）。
いずれも終了コード 101 である。

| 変異 | 落ちた回帰 |
|---|---|
| バイパスの分を合流で使わず出力へまとめる（ADR 0340 の形） | 鍵の前後のバイパス、乱数のバイパス |
| センドの線に送り元のバイパスの分を足さない | バイパスした送り元のセンド、乱数の経路、乱数のバイパス |
| 鍵を装置でなくトラックの入力へつなぐ | 鍵の本線、ドラムラック、鍵のバイパス、乱数の 2 つ、`lines` |
| 配布のノートを親の入力の節からつなぐ | ドラムラック（`Feedback`）、乱数の経路、乱数のバイパス |

検査の選択と契約は変えない。足したテストは既存の `check` の対象である。

## 計測

`compensate`（グラフを作り、解き、検証する）。release、20 回の最小。ADR 0340 と同じく、8 トラックごとのフォルダで、各トラックに音源 1 つと装置 3 つ。
同じ機器・同じ時間帯に、開始時の HEAD のコードを同じ手順で測った。

| トラック | HEAD | 今回 |
|---:|---:|---:|
| 256 | 116 µs | 136 µs |
| 10,000 | 1.92 ms | 2.30 ms |
| 100,000 | 25.0 ms | 28.7 ms |

増分は音源ごとのノートの節と辺である。制御側で計画ごとに 1 回で、コールバックでは実行しない。
ADR 0340 の記録（52 µs・1.65 ms・20.2 ms）とは機器の負荷が違うので、比べるのは同じ時に測った HEAD とだけにした。
コールバックは変えていないので、`spike-plugin-tracks` は測っていない。
