# ADR 0130: CLAP のパラメーター編集をプラグイン状態の記録として接続する

- 日付: 2026-10-20
- 状態: 採用。P2-02 のパラメーター編集の最初の接続
- 範囲: CLAP パラメーターの一覧・値の変更・単一 Undo、停止中のヘルパー起動、Undo 時の状態復元、FX ビューの汎用パラメーター欄

## 背景

P2-02 の残る範囲の中心はパラメーター編集である。
既存の CLAP デバイスはモデルにパラメーター配列を持たず（[ADR 0048](0048-clap-device.md)）、設定は状態オブジェクトのハッシュで保存する（[ADR 0109](0109-placement-bounds-and-plugin-capture.md)）。
ヘルパーは `clap.params` を使っておらず、再生していない間はヘルパー自体が起動していなかった。
ユーザー操作の `device.set_state` と Undo / Redo で状態ハッシュだけが変わった時は、音声側が稼働中のヘルパーへ反映していなかった。

## 決定

### 値の正本はプラグインの状態とする

- CLAP パラメーターの値をモデルの `Parameter` 配列へ複製しない。
  ホストからの編集は、ジェスチャーの終了時にヘルパーの `state.save` を取り込み、既存の `device.set_state` として 1 回の Undo に記録する。
  保存形式・スキーマ・アクションの登録簿は変更しない。
- 理由: プラグイン GUI・プリセット・パラメーター以外の内部状態も同じバイトに入る。
  値をモデルにも持つと二つの正本が食い違い、数千のパラメーターを持つプラグインでプロジェクト JSON が肥大する。
- 代償: Undo の単位はジェスチャーごとの状態全体であり、状態が大きいプラグインでは大きなオブジェクトが増える。
  同じバイトの取り込みは履歴に積まない。
- P2-04 のオートメーションは CLAP のパラメーター ID（`u32`）をアドレスとして参照し、値は保存しない。
  [ADR 0118](0118-track-fx-chain-editing.md) が想定した複製時のパラメーター子 ID の再採番は、モデルにパラメーターオブジェクトがないため不要になった。

### ヘルパーでの一覧と値の変更

- 読込時にメインスレッドで `clap.params` を取得する。
  説明・値・表示文字列（`count`、`get_info`、`get_value`、`value_to_text`）はメインスレッドで読む。
  CLAP の無効 ID、非有限・逆転した範囲、値を返さないパラメーターは補正せずに除く。
- 値の変更は、処理を開始済みのプラグインに対してヘルパーの処理スレッドが `params.flush` を呼ぶ。
  CLAP は有効化中の `flush` を処理スレッドで許し、`process` との同時呼出しを禁じる。
  ブロックの合間に実行するため、親がブロックを送らない停止中でも警報で起こして反映する。
- 変更の束は制御スレッドが確保し、原子ポインタで渡す。
  処理スレッドはポインタの移動だけを行い、処理済みの束を退避リストへ積む。解放は制御スレッドが行う。
  反映後の値と文字列はメインスレッドで読み直して返す。
- `clap.params` を持たないプラグインは空の一覧とし、変更は拒否する。
  無効 ID と非有限値は拒否する。ブロックのイベント変換も無効 ID で `ClapId::new` が中断しないよう読み飛ばす。
- `flush` の出力イベントは現在破棄する。プラグイン側からの値の変更・ジェスチャーの中継は GUI の単位で扱う。
- ヘルパー内の待ちは束の反映とメインスレッドの読込でそれぞれ 2 秒。
  親は 5 秒待ち、遅れた応答が次の要求の応答として読まれることを防ぐ。

### 停止中の起動と Undo の反映

- `PlaybackControl` はデバイス ID から現在のグラフのヘルパーの制御端点を引き、一覧・変更・取り込み・復元を制御スレッドで行う。
- デバイスビューが要求した時、まだ再生で開いていなければ出力を停止状態で開き、以後は停止後と同じく保持する。
  従来の準備は常に再生指令を入れていたため、一度も停止していないセッションではコールバックの取消判定を通って再生が始まる。
  開始の有無を準備の引数で明示した。稼働するプラグインがない文書では機器を照会しない。
- プラグイン状態だけが変わった差分（Undo / Redo / API）では、変わったデバイスのヘルパーが最後に保存・読込したバイトと記録を比べる。
  異なれば同じヘルパーへ記録済みのバイトを読み込む。
  既定の状態（記録なし）、読めないオブジェクト、読込の拒否は、グラフの置き換えで新しいヘルパーを作る。
  背景の自動保存で取り込んだバイトは既に一致するため再読込しない。

### FFI と画面

- `echode_document_device` に `device.parameters`、`device.parameter.set`、`device.parameter.commit` を加え、報告 JSON をスナップショットに載せる。
  取り込みはオブジェクトを書き、記録と異なる時だけ `device.set_state` を実行する。ミキサー・削除済み・オフラインのデバイスは機器に触れずに拒否する。
- FX 行の「パラメーターを表示」で、チェインの右にそのデバイスの汎用パラメーター欄を開く。
  連続値はスライダー、段階値は丸めと読める範囲の目盛り、読み取り専用は無効表示とし、隠しパラメーターは出さない。
- ドラッグ中は最新の値だけを 1 件ずつ送り、プロジェクトは変えない。終了時に 1 回だけ記録し、取消は元の値へ戻してから記録する。
  同じバイトの記録は履歴に積まないため、取消は通常 Undo を増やさない。
- 値を送ってから記録するまでのデバイスでは、背景の自動保存の取り込みを保留する。
  ホストの変更後に `mark_dirty` を呼ぶプラグインでも、編集が Undo のない取り込みへ化けないようにする。
  記録・Undo・他の編集で文書が変わった時点で保留を解く。
  キーボード・VoiceOver の 1 段階は即時に記録する。
  Undo / Redo の後は値を読み直し、オフライン化・削除・文書の切替で欄を閉じる。

## 残る範囲

- ヘルパー所有の GUI とその自動表示、プラグイン側の値変更とジェスチャーの中継、`clap_host_params`（`rescan`・`request_flush`）。
- 変調・オートメーション（P2-04）、MCP への公開、文字入力（`text_to_value`）、モジュールによる整理と検索、サムネイル。
- 汎用欄は 1 パラメーター 1 行の AppKit ビューで、数千のパラメーターでの表示性能は未測定である。
- オフラインのデバイスは稼働するヘルパーがないため、記録済みの値も表示しない。
- `CLAP_PARAM_REQUIRES_PROCESS` のパラメーターは次の処理ブロックで反映される場合があり、停止中の読み戻しが前の値を示しうる。

## 検査と診断

- 実ヘルパー越しに、停止中と合間の反映、説明の除外、読み戻しの文字列、状態の取り込みと復元、無効 ID・非有限値・拡張なしの拒否を検査する。
- 必須契約 `plugin-params` は製品エンジンから値を変えて音へ反映し、取り込み・記録で同じヘルパーが残ること、以前のバイトの読込で音が戻ることを 7 / 64 / 512 フレームで確認する。
  負の対照は処理スレッドの `flush` を止め、読み戻しの値で失敗する。
- 記録済みの値の波形を 1 / 7 / 64 / 512 フレームで全サンプル比較し、復元の判定（一致・既定・読めない・拒否）も検査する。
- 必須契約 `fx-params-ui` は FX 行からの表示、実スライダーのドラッグ中の送信、終了時の単一 Undo、段階値、取消、Undo 後の再読込を確認する。
  この検査はヘルパーの代役を使い、機器を開かない。実経路は Rust 側の契約が保証する。
- 第三者プラグインでの実操作と聴感はユーザー担当とし、自動回帰の合格と区別する。
- 失敗は欄にそのまま表示する。`the device has no running plugin`、`no output device is available`、`parameter changes timed out` などを手掛かりに、
  文書・出力機器・ヘルパーのどの境界かを [デバッグ手順](../debugging.md) で切り分ける。
