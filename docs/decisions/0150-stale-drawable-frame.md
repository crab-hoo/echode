# ADR 0150: 入力と大きさの違う drawable にも現在の入力を描く

- 日付: 2026-10-23
- 更新: 2026-10-24。行ラベルを入力境界でクリップし、余白の全画素を回帰で確認するよう修正した。
- 状態: 採用
- 範囲: [GUI のがくつきの監査](../reviews/2026-10-22-gui-jank-audit.md) の単位 4（JNK-03）。
  [ADR 0144](0144-unscaled-canvas-resizing.md) の「入力と大きさの違う drawable はクリアして再試行する」を置き換える。

## 背景

`CanvasRenderer` は、取得済みの drawable の大きさが最新の入力と違う場合、背景色だけでクリアして提出し、
次のコールバックで描き直していた。表示リンクが drawable を取得した後に主スレッドが枠と `drawableSize` を変えると、
その 1 フレームは内容のない暗い面になる。ライト表示ではヘッダの明るい背景との差が大きく、リサイズ中にちらつく。
drawable は背景色を持たず、`CAMetalLayer` も drawable を自動でクリアしないため、
表示面が広がった時の古い drawable の外側は次のフレームまで透明になる。

## 決定

- 入力と drawable の大きさが違っても、その drawable の実際の大きさへ現在の入力を描く。
  インスタンスの画素座標は入力のまま変えず、はみ出す部分は描画のクリップで切る。
  左上を原点にした同じ画素位置になるため、古い大きさのフレームでも内容が移動しない。
- シザー矩形は drawable の範囲へ制限する。アレンジのヘッダ・タイムラインは入力の高さでも制限し、
  入力より大きい drawable の余白へ行や背景を描かない。ヘッダの行ラベルも部分表示行を含むため、
  各ラベルのクリップを入力の境界と交差させ、下端を越えた文字を余白へ出さない。
  ピアノロールは既存の入力座標のクリップを使う。
- 大きさの違う drawable に描いたフレームは入力の版を消費しない。表示リンクは休止せず、
  次のコールバックで正しい大きさの drawable を待つ。休止判定は `canvasLinkPaused` に分け、
  stale drawable の間は休止しない。描画の版は別に記録し、ジオメトリの通知を毎フレーム繰り返さない。
- `CAMetalLayer.backgroundColor` を表示面の背景色（RGB 0.09, 0.10, 0.12）にそろえ、
  drawable が届く前や広がった余白を透明にしない。クリア色・オフスクリーン描画・レイヤー背景は
  `CanvasBackground` の同じ値を使う。
- 描画に失敗した場合と、入力がゼロサイズ・停止中の場合は従来どおり背景だけで提出する。

## 回帰と診断

- 必須契約 `drawable-mismatch-ui`（新規）: 製品の `ArrangeFrame` と `PianoFrame` を、
  同じ大きさのテクスチャーと、幅・高さを変えたテクスチャーへオフスクリーン描画し、
  重なる左上の全画素が一致すること、広がった余白の全画素が背景色であること、
  参照画像に内容が描かれていることを確認する。アレンジは下端が部分表示行に当たる入力を使い、
  行ラベルが余白へ出ないことも確認する。
  負の対照は 3 つ持つ。大きさの違う drawable を描かない旧判断へ戻すもの、
  オフスクリーン描画から `ArrangePainter.encode` を外して背景だけにするもの（JNK-03 の再現）、
  ラベルのクリップと入力境界の交差を外すものである。
- `canvasLinkPaused` の純粋関数テストで、stale drawable の間は休止しないこと、
  再生・メーター・連続描画・未描画の版が休止を保留することを確認する。
- 必須契約 `canvas-resize-ui` に、`CAMetalLayer.backgroundColor` が表示面の背景色と等しいことを加えた。
- `make spike-arrange-frame` と `make spike-piano-frame` に、入力と違う大きさへ描いた重なり画素と余白画素の比較を加えた。
  どちらも 0 画素の不一致を合格条件にする。
- `ArrangeMeasurement.sizeMismatches` の意味を「クリアした数」から
  「入力と違う大きさの drawable に描いた数」へ変えた。リサイズ中の一時的な増加は正常である。
- 診断は [デバッグ手順](../debugging.md) のペインのリサイズの節に記す。

## 未確認

ドラッグ中のちらつきと右端の抜けが実画面で消えたか、表示リンクが要る `sizeMismatches` の実測は、
ユーザーの実画面確認とする。自動回帰はウィンドウ・表示リンク・機器を開かない。
