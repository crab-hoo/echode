# 0029. 不変条件は 1 つの関数で検査する

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-11

## 背景

`Project::check_invariants` は既にある。ID の一意、ノートの並び（ADR 0023）、配置の重なり、自動配置の小節幅（ADR 0022）、親の森、トラックの並び（ADR 0024）、ミキサーの 4 つの値を見ている。DEV-5 は操作のたびにこれを呼ぶ。

まだ見ていないのは、配置のゲインとフェード、テイクが自分自身を指すこと、ノートの開始と長さの足し算が溢れること、ミキサーの最小・最大・既定値がそのキーの端と一致することである。これらは編集と読み込みが別の場所で拒んでいる。`try_assemble` の最後と、デバッグビルドの `Action::apply` の後では呼んでいない。一覧は crate の文書に無い。

## 決定

- 検査は `Project::check_invariants` の 1 つにまとめる。新しい関数は作らない。上の 4 つをこの関数に足す。同じトラックの配置は、ファイルに書いてある順が開始時刻の昇順であるものとし、半開区間で重ならない。並びが逆なだけのファイルも拒否する
- ベロシティとリリースは 0 以上 65535 以下のまま制限しない。ノートの負の開始も拒否しない。テンポマップは、それを作る時点で空と同時刻を拒むので、ここには入れない
- 一覧は `echode-model` の crate の文書にだけ書く。関数の文書はそこを指す
- `try_assemble` は、今の型付きのエラーを返したあと、最後にこの関数を呼ぶ。失敗は `ModelError::Invariant` で、表示はその文である。`ModelError` から `Copy` を外し、このバリアントだけ文字列を持つ。意図的に壊す `unchecked` は検査しない
- `Action::apply` は、デバッグビルドで成功した直後にこの関数を呼ぶ。壊れていたら、その文でパニックする。リリースの編集では呼ばない。オーディオスレッドでは呼ばない
- DEV-5 の呼び出しはそのまま残す。リリースのテストからも検査が落ちないようにする

## 結果

`make check` が通った。自動配置の幅がノートの小節と違うときと、配置の並びが逆なときは、`try_assemble` がその文で拒否する。溢れるノートと、自分を指すテイクは、これまでどおり型付きのエラーで拒否し、同じ関数もその文を返す。デバッグビルドでは、壊れたスナップショットを `apply` と同じ検査にかけると、その文でパニックする。一覧は `echode-model` の crate の文書にある。
