# ADR 0101: 定期保存確認とライブ出力の不連続を分ける

- 日付: 2026-10-16
- 状態: 採用
- 範囲: 再生中の保存状態の確認、停止・一時停止・位置移動の出力境界。ADR 0097・0099 を補う。

## 再生中に波形が飛んだ原因

文書ワーカーは通常20 msごとに `PlaybackControl::service` を呼ぶ。旧実装は保存通知を調べるだけでも `HostSlot` を制御側で占有した。その間にコールバックが入ると、プラグインを含まない経路へ落ち、楽器なら内蔵音源、エフェクトなら未処理の入力が一時的に出た。これはプラグインの処理期限を超えなくても起きる。

96 kHz・512フレーム、内蔵音源と実形式の別プロセスのテスト用ゲイン、1000ブロック（約5.33秒）で再現した。同じ入力で、定期確認なしは隣接サンプル差0.2超が0件、20 msごとの確認ありは40件、期限超過は両方0件だった。修正後は確認あり・なしとも0件だった。増幅率2の故障検出用入力であり、音楽全般に適用する振幅閾値ではない。ローカルの入力と記録は `target/noise-audit/probe.rs`、`gain-before.log`、`gain-tone-after.log` にある。

制御ソケット、通知の受信箱、保存した状態、保存要求の進行を `PluginControl` に分離する。再生側は共有メモリと処理用領域だけを使用する。制御側のハンドルを構造更新時に取得し、通常の保存確認は音声グラフを借用しない。制御ハンドルの mutex は制御側だけが使い、音声の submit / poll / reset では触れない。保存済み状態の照合も同じハンドルを使い、自動保存で同じヘルパーを作り直さない。

`contract_state_poll_does_not_borrow_the_audio_graph` はグラフを音声側が持ったまま保存確認を完了させる。旧処理はデッドロック防止の待ち上限に達して失敗した。これは性能の時間閾値ではなく、保存確認が音声の所有権へ依存しない契約である。別プロセスの連続音声と同時に確認する回帰、保存と再起動・永続化の既存回帰も通す。

## 停止時の段差

旧 HAL 出力は、停止や取消で直前の振幅から突然0へ切り替えていた。停止中の無音だけを検査しても、この段差によるクリックを検出できない。左右0.25・-0.5の連続入力では、旧処理の停止直後が0・0となり、新しい回帰で失敗した。

ライブ出力の境界に、サンプル数で進む5 msの補正を加える。トランスポートによる不連続の最初のサンプルを最後の提出済みサンプルへつなぎ、差分を線形に0へ下げる。通常の波形や自然なノートの余韻は変えず、先読み・音声の遅延を追加しない。補正中の次の操作も、その時点の提出済み振幅から始める。

停止と一時停止は、時計と音源の状態を直ちに止める。既に出た波形に対する5 ms以内の補正だけが残る。停止中にプラグインの余韻を鳴らし続ける処理ではない。準備中に取り消した再生は、提出済み振幅が0なので初回から無音となる。描画中に届いた取消も、新しい内容を提出する前に禁止し、補正のために再生時計を進めない。取消後に制御側の停止命令が届いても補正を繰り返し開始しない。

補正は HAL だけが使い、書き出し・基準音声の値を変えない。`contract_transport_discontinuities_declick_hal_output_under_rtsan` は48 / 96 kHz、1 / 7 / 64 / 512フレームの製品バッファで、停止・一時停止・投入時の取消、左右、時計の停止、段差の上限と収束を確認する。`block_size.rs` では補正中の再操作もブロック長を変えて比較する。保存確認と補正の省略を、別々の必須契約の負の対照で拒否する。

## 診断と限界

`PlaybackStatus` と `audio.status` に、現在の出力ストリームで累積する `plugin_missed_blocks` と `graph_unavailable_blocks` を加える。前者はプラグインの処理・投入・期限の失敗、後者は構造更新によるグラフの一時的な利用不可を区別する。コールバックで文字列を生成せず、定期保存確認の成功で過去の失敗を消さない。保持した停止・再開では累積を保ち、出力の作り直しで0へ戻る。

この変更はプラグインの処理期限を延ばさず、長時間の安定性やすべての音源・プリセットの聴感を保証しない。機器の抜き差し・不正な出力バッファは安全のため即時無音にする。プラグイン追加やイベント容量の再配置など、本当の構造更新は引き続きグラフを占有するため、再生中の大きな編集で一時的に経路を失う問題は別途残る。診断値で通常の保存確認と区別する。通常回帰・短時間の隔離と HAL 検査を使い、今回の再現に10分計測を代用しない。

## 検査時の環境記録

必須契約16件と、それぞれの負の対照が通った。通常検査、RTSan、ASan、TSan、Miri を含む全自動項目も通過した。TSan は終了済みスレッドの `errno` 周辺で2回警告したため、過去の標準ライブラリだけの再現と照合し、失敗ログを保持した。同じソースと判定条件の3回目で通過した。新しい制御ハンドルへの警告ではなく、検査の閾値変更や抑制はしていない。記録は `target/noise-audit/tsan-*-retry.log`、`tsan-*-second.log` と `target/debug-reports/20261015T172830Z-gb_vn84b/`。

96 kHz・64フレームの10秒確認は、ウォーミングアップ後の計測0件、約2.071秒で `CallbacksStopped` となり不合格だった。Computer Use は Mac のロックを報告し、電源ログには02:34:16の `Clamshell Sleep` が残った。スリープが唯一の原因と断定せず、解除して蓋を開いた環境での HAL・10秒確認と修正版の画面確認を未検証として残す。途中停止を合格には扱わない。失敗は `target/noise-audit/smoke-callbacks-stopped.log` と同名の `.txt` に保持する。

開いていた `DesktopAudit.echode` の保存済みスナップショットも読み取り専用で確認した。96 kHz・512フレーム、4秒分、Vital 2個と配置音声を製品の再生器へ通し、ピーク0.8927826、振幅1超・非数値・プラグインの失敗・グラフ利用不可はいずれも0だった。ハング検出用の10秒期限を使い、実時間性能や聴感の合格とはしない。文書の書き手を開かず、ジャーナルも再生しない保存済み内容の確認である。入力のファイルハッシュ、プログラム、結果は `target/noise-audit/project-inputs.json`、`project_probe.rs`、`project-output.log` に保持する。

## 2026-10-16 の追加修正

構造変更時にグラフを占有する残存経路も [ADR 0102](0102-exclusive-audio-graph.md) で削除した。所有権を借りる方式に依存した保存確認の旧単体契約は、初期化を保留した実プラグインと並行する出力の契約へ強化する。上の失敗・未確認・測定値は取得時点の証拠として保持する。

Mac の解除後、追加の所有権変更より前の同一ソースで HAL と10秒計測を再実行し、いずれも完走した。`target/noise-audit/resume-hardware.log` に記録する。追加変更後の合否は最新の検査報告と ADR 0102 を参照する。

## 停止の波形に関する訂正

ユーザーから停止時のクリックが残る報告があった。上記の一定値だけを使う回帰と定数補正では、周期を持つ波形の切断を保証できなかった。停止に関する判断を [ADR 0103](0103-live-stop-waveform.md) で置き換え、鳴っている波形そのものを減衰する。過去のテストや画面操作の成功は、聴感の合格の証拠にはしない。
