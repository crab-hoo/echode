# ADR 0300: 間引き・パック・バンドルの失敗を型で保持する

- 日付: 2026-11-10
- 状態: 採用
- 対象: 統合表 M1、DEV-7・SPG-11・XCA-16
- 続き: [ADR 0299](0299-typed-document-journal-and-settings-errors.md)

## 問題と再現

開始時の HEAD は `1b0f9c0`。
`thin.rs` の 12 か所の `Result<_, String>` は、Git・I/O・UTF-8 の原因と、残す点などの意味上の拒否を同じ文へ戻していた。

公開入口を通す `tests/thin_errors.rs` を先に追加した。
バンドルをディレクトリへ書く失敗、存在しないコミットを間引く失敗、不正な UTF-8 の先端を読む失敗は、
変更前に `thinning lost its typed cause` で失敗した。
期待終了コード 101 と固有のアサーションは `target/focused-checks/thin-errors-red/` にある。
最初の実行の fixture のコンパイル失敗は修正してからやり直し、red の証拠に数えない。

追加の回帰では、`objects/pack` をファイルで塞ぐとパック作成の I/O になると想定したが、
実際は最初のオブジェクト探索で Git がディレクトリを読めずに返す失敗だった。
回帰は実際の `FindObject` と内側の I/O に合わせた。この想定違いも red の証拠にはしない。
Git の内側は平坦なフレームなので、元の I/O の型を読む時は `gix::Error::downcast_any_ref` を使う。
標準の `source` の合成フレーム自体を `io::Error` に downcast する初期の照合も、検出力の証拠には数えない。

## 比べた案

| 案 | 判断 |
|---|---|
| 間引き専用のエラーに Git・I/O の表現も複製する | 採らない。履歴の既存の原因の表現と診断を重複させる |
| 全原因を `PackageError` の直下へ追加する | 採らない。間引きの意味上の拒否は保存の失敗と分ける |
| `PackageError` を再利用し、意味上の拒否と UTF-8 だけを `ThinningError` にする | 採る。Git と I/O の元の原因・操作の分類を共通に保てる |
| 既存の `GitOperation::ObjectKind` を変換全般に流用する | 採らない。この種類だけは旧経路の Debug 表示を維持しており、間引きの表示文が変わる |
| 変換の `ConvertObject` を操作に足す | 採る。元のエラーを保持し、間引きの従来の Display 表示も維持する |
| 原因の型付けと同時に間引きの同期・削除・巻戻しを変える | 採らない。保存の判断の変更を混ぜず、既存の順番と保証を維持する |

性能改善は目的でなく、時間やメモリの計測を採用の根拠にしない。
根拠は公開入口での原因の消失の再現と、種類・原因・文面・元の参照とオブジェクトの照合である。

## 決定と境界

- `thin.rs` の公開入口と内部の処理は `PackageError` を返す。
  Git・パック作成・ハッシュは操作の `GitOperation` と元の `gix::Error`、I/O は元の `io::Error` を保持する。
- `error_thin.rs` に `ThinningError` を置く。
  残す点なし・参照なし・シンボリックな自動保存参照・先端の JSON なし・UTF-8 を分ける。
  `Text` は `FromUtf8Error` をそのまま持ち、元のバイト列も `Error::source` から調べられる。
- 表示文、残す点の選択、コミットの書換え、参照更新、パック作成、旧オブジェクト削除の順番は変えない。
  パック作成より先に参照を更新するため、後の失敗が参照を巻き戻すという新しい保証はしない。
- 既存の `.keep` の削除失敗の無視、保管サイズの集計の省略規則も、この型付けでは変えない。
  外部入力・保存形式・依存・音声経路は追加しない。

## 回帰と基盤

- `tests/thin_errors.rs` は公開入口で I/O・Git・UTF-8・空の保持点・異なるオブジェクト種・
  シンボリック参照・パックディレクトリの障害・先端の JSON の欠落を照合する。
  `thin.rs` の単体テストは参照なし、既存の `tests/thin.rs` は先端とバンドルの保持を通す。
- `check_typed_errors.py` の移行済みファイルに `thin.rs`・`error_thin.rs` を足す。
  全移行済みファイルへの文字列結果・原因の文字列化・未分類メッセージの再導入を拒否する Python 回帰を維持する。
  未移行の対照は `store.rs` に移す。
- 新しい検査入口や選択条件は不要である。既存の Rust 全体・Python の検査が追加回帰を選ぶ。
  必須契約・Makefile・fuzz の外部入口は変わらない。
- 構成・コードの所在・デバッグ手順と索引・監査の状態を更新する。
  既に除いた `PackageError::Message` を残存とする古い構成説明も修正する。
  利用者に残る制約は変わらないので `status.md` とユーザー確認の追加は不要である。

## 残る範囲

M1 の完了ではない。次は非既定の履歴スパイク（`format.rs`・`store.rs`）である。
機器・アプリ・聴感の確認は実行しない。
保存・復元の規模、橋渡し、書出しの性能の計測は、エラー表現だけの今回の変更の採用根拠にしない。
