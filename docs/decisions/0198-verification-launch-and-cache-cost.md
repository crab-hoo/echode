# ADR 0198: 契約の起動コストと診断・ビルドキャッシュの境界を分ける

- 日付: 2026-10-30
- 状態: 採用
- 対象: 製品契約、検査の表示と選択、TSan のビルド先
- 前提: [ADR 0148](0148-verification-pipeline-speed.md)、[ADR 0195](0195-verification-cost-observability.md)、[ADR 0197](0197-verification-target-scopes.md)

## 再監査

開始時の HEAD は `6d7e3ef`、作業ツリーは変更なしだった。
ADR 0197 の全件 2906.430 秒、契約 1724.665 秒という記録と、その広い失効境界は確認した。
外側の契約検査の 1725.731 秒とは準備・呼出しの境界が異なる。
今回の測定と過去の異なる入力・負荷・キャッシュ状態の履歴を同条件の速度比較にはしない。

指摘の扱いは次のとおりである。

1. **製品依存からの全 Swift 失効**: 実在するが、リンク先の製品ソースを入力から外す修正はしない。
   Swift パッケージ内のテストも同一モジュールであり、補助の相互依存を証明せずファイル名だけで除外しない。
   本件でこの依存分割を完了したとは扱わない。
2. **反例の復元と直列テスト**: 実在する。時刻を巻き戻して復元ビルドを隠すことはしない。
   ただし `swift test --skip-build` は毎回マニフェスト解析・コンパイラー照会・テスト探索を行っていた。
   子プロセスの argv を照合すると、最終的には同じ SwiftPM の `swiftpm-testing-helper` を使っていた。
3. **Rust の同一反例の重複**: 実在する。異なる対象テストでも同じ置換を復元せず共有できる。
   119 個の反例と契約ごとの期待値は減らさず、Cargo のパッケージ別 feature 解決も変えない。
4. **TSan の標準ライブラリ二重ビルド**: 保存ログでも `core`・`alloc`・`std` のコンパイルが二度現れた。
   前半 37.31 秒と製品側 146 秒は標準ライブラリだけの時間ではなく、依存ビルドも含む。
5. **ASan の標準ライブラリ三重ビルド**: この解釈は確認できない。
   保存された三つの Rust ログでは `core`・`alloc`・`std` は最初にだけ現れ、後二回には現れなかった。
   各パッケージの構成とテスト用 feature が違うため、一つの workspace 実行へまとめてはならない。
   Swift 側の非計装 Rust は ABI の異なるランタイムを分ける意図した構成である。
6. **診断編集・フック編集の全件連鎖**: 診断モジュールが共通入力に入っており、選択も過大だった。
   一方、ADR 0195 が明示していた非入力の対象は元来 `timing-history.jsonl` であり、説明を区別する。
7. **全体並列化と通常・ASan・TSan の重複**: 単なる不要な重複とは扱わない。
   ADR 0148 と [ADR 0166](0166-verification-failure-detection.md) の負荷による期限切れの証拠を維持する。
   通常・ASan・TSan は別の計装であり、契約の一件実行・検出力も全体テストとは別の証拠である。

全契約・全反例を毎回実行する限り、少なくとも件数に比例する仕事は残る。
`O(N + M)` 自体を不具合とはせず、不必要な失効・起動・同一ソースの復元を削減対象とする。
数分で完了する保証や、依存分割なしの定数時間化は主張しない。

## 決定

### SwiftPM のビルドとテストプロセスの起動を分離する

ビルドは従来のテスト製品指定と警告のエラー化を維持する。
成功後に SwiftPM の `--show-bin-path` で当該 scratch の成果物を解決し、同じツールチェーンの Testing ヘルパーへ渡す。
ヘルパー・SDK の配置の解決は呼出し内で共有するが、各テストは独立した新しいプロセスで起動する。
フィルターと実テスト一件の出力検査を維持し、0 件・複数件・無視・既知の問題・ロード失敗は合格にならない。
反例はビルド時間を引いた従来の期限内に実行し、コンパイル失敗は検出に数えない。

Xcode の転送 shim を通さず、SDK の XCTest / Testing のフレームワークとライブラリの探索先を子へ渡す。
ヘルパーまたはバンドルが欠けた場合に古い成果物へ黙って戻らず失敗する。
実行スクリプトを Swift 契約と外側検査の入力へ登録し、ヘルパーの実パスとバイトの識別もツール入力に加える。
これはシステムフレームワークの非公開 API の呼出しではなく、固定した検査ツールの CLI の利用である。
ツールチェーン更新で CLI が変われば検査を更新する。

### Rust の同じ置換をまとめる

変更ファイル・置換前・置換後が同じ反例を一つのソース遷移へまとめる。
対象パッケージ・ターゲット・テストは従来のコマンドで一件ずつ実行する。
異なる反例を混ぜず、例外・中断でも新しい時刻で復元する。
全反例が終わった契約だけを保存し、途中の契約は再利用しない。
`execution.negative.rust` にソース遷移数とテストプロセス数を分けて残す。

### 診断と実行器を分ける

`verification_display.py` が Markdown と `--plan` の表示だけを受け持つ。
`verification_metrics.py` と表示モジュールの変更は基盤検査で検証し、製品の共通証拠入力にはしない。
選択・終了コード・合否・証拠の保存を扱う `verify.py` と `checked_commands.py` は共通入力のままにする。
表示変更のために実行器を編集する必要がない構造とし、実行器のハッシュを恣意的に切り出さない。

フック・CI・ロック待機アダプターは基盤検査の入力であるが、全製品検査の選択理由から外す。
常時検査の選択は維持し、入力が同じ製品の合格は再利用する。
実際のレシピ・依存入力・ツール・共通実行器が変われば従来どおり失効する。

### TSan の同一ビルド構成だけを共有する

製品とスパイクの TSan は同じ `target/bridge/thread/rust` を使用する。
固定 nightly・ターゲット・release・RUSTFLAGS・標準ライブラリの計装・実競合の負の対照は維持する。
ASan・通常・反例の Cargo ディレクトリとは共有しない。
ASan のパッケージごとの実行は、feature の混合を避けるため維持する。

## 測定と残る制約

同じ既存バンドルの画面・機器なしの `workspace-stack-ui` を、旧起動と新起動で交互に三回実行した。
`swift test --skip-build` は 1.318 / 1.307 / 1.322 秒、ヘルパーの直接起動は 0.202 / 0.204 / 0.204 秒だった。
全六回で同じ一件のテストの成功を照合し、存在しないテストも合格にならないことを確認した。
これはウォーム状態の単一起動の比較であり、全件の改善率ではない。

Swift の 194 ビルド、全製品コード変更からの広い失効、Rust の異なる反例の再コンパイルは残る。
並列ビルドの作業秒を壁時計の時間へ足さず、全体・通常・Rust / Swift 反例・テスト秒を引き続き記録する。
最初の全体実行は通常契約の `scan-deadline` で正常 JSON 前の 2 秒の期限切れとなり、反例へは進まなかった。
同じ構成の単独実行でも一度再現した後、再実行では再現しなかった。
この中断回と再開を全件一回の時間へ合算せず、起動遅延の未確定事項を [デバッグ手順](../debugging.md) に保持する。
全件強制で測り直した呼出しも、通常 workspace の `mcp_framing` の部分応答後の EOF 待ちで停止した。
同じ構成の単独で一度再現し、後の単独では再現しなかった。走査の起動前失敗とは区別し、根因は未確定とする。
これも製品契約の全件計測や成功した所要時間とは扱わない。

最後の再開では、通常契約は同じ入力の 217 件を再利用し、残り一件と全反例を実行した。
契約検査は 1305.514 秒、反例は Rust 442.710 秒・Swift 844.892 秒だった。
Rust は 113 ソース遷移で 119 回のテストを実行し、Swift は 194 ビルド・200 回のテストを実行した。
Swift の直列テスト秒は 296.818 秒、ビルド作業秒の和は 1549.331 秒だった。
TSan は 169.311 秒で、同じ出力先の標準ライブラリを再コンパイルする段は現れなかった。
呼出しは 1523.244 秒だったが、五つの検査と通常契約の大半を再利用しており、旧 2906.430 秒との全件比較は成立しない。
Rust の反例秒が旧記録より増えたことも含め、ソース遷移数の削減を実測速度の保証へ言い換えない。
全件強制の単発計測は前述の既存回帰の失敗で未完了であり、再開の合格と区別する。
正式な合否と未実施理由は `make verify` のレポートを正本とする。

## 回帰と保守

`scripts/tests/test_verification_cost.py` で、診断・フック編集の選択と失効、Rust の重複置換と中断、
TSan の共有先、Swift の起動・探索先・一件判定・ロード失敗拒否を検査する。
既存の部分反例・ソース復元・実行中変更・コンパイル失敗・個別期限の回帰も維持する。
基盤の検査自体の全件実行と、局所編集時の再利用を混同しない。
