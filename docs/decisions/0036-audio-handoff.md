# 0036. 実行計画はキューで渡し、解放は制御スレッドが行う

- 日付: 2026-10-09
- 状態: 採用
- 項目: ENG-3

## 背景

ARCHITECTURE §7.2 は、制御スレッドが実行計画を組み立て、ロックなしでオーディオスレッドへ渡し、古い計画の解放も制御スレッドが行うとしている。仕組みはまだない。計画は `Vec` を持つ（[ADR 0035](0035-playback-plan.md)）。オーディオスレッドが最後の `Arc` を落とすと、そこでメモリが解放され、リアルタイムの規則に反する。

ミキサーの現在値は gain、pan、mute、solo である（[ADR 0026](0026-parameters.md)）。計画の型には、その置き場がまだない。鳴っているノートの集合は、再生しているあいだの状態で、新しいカーソルを空のまま差し替えると、鳴り終わりが失われる。

## 調査

`rtrb` 0.4.0 は、書き手と読み手が 1 つずつのリングバッファである。MIT OR Apache-2.0 で、GPL-3.0-or-later と両立する。リングは作るときに確保し、その後の push と pop は待たず、メモリを確保しない。pop した値は、押し戻せない。復路がいっぱいのときに計画を pop すると、その場で落とすか、漏らすかしかない。

## 決定

- キューは 3 本である。計画の往路、パラメータの往路、計画の復路である。どれも `rtrb` 0.4.0 で、起動時に 1 回だけ作る。計画の往路の深さは、滞留している計画の数であり、トラック数の上限ではない。パラメータの往路はそれとは別の深さにし、計画の滞留では埋まらない。パラメータを計画と同じ列に置くと、フェーダーの連続操作で計画が送れなくなり、計画が保留されているあいだパラメータも止まる
- 渡すものは `Arc` にしない。所有権を move する。オーディオスレッドが計画を落とす道を作らない
- 計画の往路は `Replace` だけを運ぶ。中身は、計画と、制御スレッドが確保したカーソルのバッファである。計画の各トラックは、gain、pan、mute、solo の現在値を持つ。これは ADR 0035 の計画に足すフィールドで、組み立てのときにモデルから写す
- パラメータの往路のメッセージは `Copy` である。トラックの ID、キー（gain、pan、mute、solo）、値を持つ。ヒープは持たない。制御スレッドは、同じトラックの同じキーについては最新の値だけを残してから送る。オーディオスレッドは、計画の差し替えができなくても、この列は毎ブロック読む
- オーディオスレッドは、今持っている計画を復路へ push できるときだけ、計画の往路から `Replace` を pop する。空きは pop の前に見る。pop した計画を往路へ戻す手段はない。復路がいっぱいなら、往路の `Replace` は置いたままにし、今の計画も落とさない。持っている計画がまだ無いときだけ、復路を使わずに pop してよい
- 差し替えた直後、オーディオスレッドは新しいカーソルを今のサンプル位置へ chase で置く。鳴っている集合は、その位置でまだ鳴るノートから作り直す。確保はしない。前の集合にいて、新しい集合にいないノートは、そのブロックの呼び出し側バッファへノートオフを書いてから、古い組を復路へ出す。鳴り続けるノートのノートオフは、ノートオンを出したときのキーを使う（[ADR 0037](0037-clap-events.md)）。空のカーソルをそのまま鳴らすことはしない
- 制御スレッドは、再生中なら、新しい編集が無くても復路を回収して解放する。送信の直前だけにしない。回収したあと、手元に残している計画があれば往路へ再送する。往路がいっぱいの計画は制御スレッドが持ち、オーディオスレッドは待たない
- 停止とデバイスの終了では、制御スレッドが復路を空けてから、オーディオスレッドが今持っている組を復路へ push し、手元を空にしてコールバックを出る。制御スレッドは、そのスレッドの終了を待ってから復路を回収し、最後の計画を解放する。スレッドの破棄では計画を落とさない
- カーソルのバッファは制御スレッドが作る。オーディオスレッドは `Plan::cursor` を呼ばない。ワーカーは、そのブロックのあいだ計画を借りるだけで、所有しない
- 差し替え 1 万回のテストを置く。オーディオスレッド側の関数は `make rtsan` の `#[nonblocking]` の下で動かし、確保と解放が 0 であることを確かめる。復路がいっぱいのときは pop しないことも確かめる。戻った計画の解放回数は、制御スレッド側で数える。停止のあと、オーディオスレッドの手元が空であることも確かめる

## 結果

`make check` が通った。復路がいっぱいのときは新しい計画を pop せず、そのあいだもパラメータは今の計画へ入る。発音中のノートを消した差し替えはノートオフを 1 つ出し、同じノートの音高だけを変えた差し替えは出さない。同じキーの連続した値は、送る前に最新の 1 つになる。停止のあと、オーディオ側の手元は空で、戻った計画は制御側で解放される。計画の差し替え 1 万回は、オーディオ側の関数を `make rtsan` の `#[nonblocking]` の下で動かし、確保と解放は 0 だった。解放した計画の数は、制御側で 1 万と一致した。
