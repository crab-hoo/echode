# 0227. プラグイン操作の実装を制御専用ハンドルへ集める

- 日付: 2026-11-02
- 状態: 採用
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-06

## 背景

[ADR 0199](0199-owned-helper-control-requests.md) でエンジンのテスト専用の旧経路 3 件を除いたが、
`PluginControl` の 7 操作は同名の `ControlState` メソッドへの素通しだった。
`PluginHost` にも保存・復元と未使用の背景保存の素通しがあり、実ヘルパーの回帰だけが使う入口が残っていた。

## 決定

- パラメーター一覧・変更・文字解釈、状態の取得・復元、GUI の表示・閉鎖の実装は、
  `echode-sandbox/src/session_operations.rs` の `impl PluginControl` が直接持つ。
  各操作はここで検証・要求の符号化・期限・応答の解釈を行い、同名の内部メソッドへ渡さない。
- `ControlState` はソケット、要求番号、通知、適用済み状態と背景保存の管理を持つ。
  `request` / `wait_reply` を共用し、操作ごとの素通しは増やさない。
  同期保存の内部処理は背景保存との照合回帰でも使い、公開しない型の内側に残す。
- `PluginHost::request_save` / `poll_saved` / `save_state` / `restore_state` を削除する。
  起動時の状態導入、再起動と実ヘルパーの回帰も `PluginControl` を使う。
  監視・音声マッピング・起動時の通知はホストの寿命に属するため、ホスト側に残す。
- 監査時の案の汎用 `PluginRequest` / 応答列挙型は追加しない。
  既存の型付きの引数・戻り値を保つことで、呼出し側に操作と応答の組合せの実行時照合を増やさずに素通しを除ける。
  `ControlMessage` とヘルパーの `MainRequest` は、通信とスレッド間の所有という別の境界なので統合しない。

制御ソケットの形式、保存形式、公開 C ABI、メイン要求の所有、期限、拒否理由と再送しない規則は変えない。
非有限のパラメーター値はロック取得前に拒否するが、従来どおりソケットへ送信しない。
音声スレッドと DSP は変更せず、実機の性能改善を主張しない。

## 回帰と診断

構造整理前に `session_operations_tests.rs` を追加し、公開制御ハンドルを実ソケットへ通した。
7 操作の入力と型付きの結果、Unicode とバイナリの保持、要求番号の進行、背景保存の先行回収、
拒否理由と適用済み状態の保持、非有限値の送信拒否とソケットを保持中のローカル読取りを検査する。
GUI の回帰の相手はソケット上の代役であり、窓や機器は開かない。

既存の SPG-01・応答照合・背景保存・GUI 寿命の契約と負の対照は維持する。
実ヘルパーの状態・再起動・パラメーター・隔離回帰と RTSan も既存の検査経路で確認する。
新しい検査コマンドや入力形式は追加せず、通常の Cargo テストと既存の検査選択を使う。
実機・聴感はユーザー担当とし、過去の S3 の数値は更新しない。
