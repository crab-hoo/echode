# 0022. クリップは中身と配置に分ける

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-2

## 背景

クリップは、タイムライン上の位置とノート列を 1 つの値で持っている。PLAN §5 は、クリップランチャーのために配置と中身を切り離し、テイクのために中身が複数のテイクを参照できるようにするとしている。ARCHITECTURE §4.7 のリンクした複製も、中身を共有する形が要る。

エンジンは、オーディオクリップの両端に 5 ms のフェードを常にかける（`voice.rs` の `edge_gain`）。打楽器の立ち上がりが丸まるので、0 も選べるようにする。今の `seam_fade_frames` は `sample_rate * 5 / 1000` の整数除算で、44.1 kHz では 220 フレームになる（5 ms は 220.5 サンプル）。`edge_gain` は、各フェードをクリップのフレーム長までに縮め、重なる区間は小さい方のゲインを使う。

`Project::check_invariants` は、自動クリップの窓を「そのノートの絶対時刻が占める最小の小節範囲」と厳密に一致させる。同じ中身の自動配置をすべて合わせ直すと、別トラックの固定クリップに重なり、ノートを足したトラックと無関係な `Overlap` で操作全体が失敗する。

MOD-4 は、見える範囲が変わっても既存のノートの値が変わらないようにする。内容時刻 0 を「最初のノート」に取り直すと、既存の `start` が書き換わる。ノートを（開始、音高、ID）の順に並べることは MOD-4 に残す。

## 決定

- 中身と配置は別のオブジェクトである。`Project` は中身を ID 順の配列で持つ。トラックが持つのは配置だけである。配置は中身の ID を持つ。どの配置からも参照されない中身は残さない。不変条件は、配置の中身が実在すること、中身が 1 つ以上の配置から参照されること、中身ごとに自動配置が 1 つまでであることを見る
- レーンは今はタイムラインだけである。配置は `lane: timeline` を持つ。ランチャーのレーンは、後からこの値を足す
- 中身が持つもの
  - ノート列。内容時刻 0 は、中身を作ったときに固定する原点であり、最初のノートの位置ではない。それより前のノートの `start` は負でよい。既存の `start` は、ノートを前に足しても書き直さない
  - ノート ID の並び、オーディオの参照、テイクの ID の並び。テイクは別の中身であり、自分自身は指さない。オーディオは今は無く、テイクは今は空である
- 配置が持つもの
  - 所属トラック、レーン、開始、長さ、内容オフセット、自動か固定か、中身の ID
  - 内容オフセットは、配置の左端に来る内容時刻である。負の値も認める。窓を前へ伸ばすときは、開始とオフセットを同じだけ動かし、ノートは書き直さない
  - 線形ゲイン。既定は 1。0 は無音。負と非数は拒否する
  - 入りと出のフェード。単位は flick。既定はどちらも 5 ms（3,528,000 flick）。0 ならかけない。0 未満は拒否する
- ノートを配置を通して聞いたときの絶対時刻は `placement.start + note.start - placement.offset` である。今の 1 配置はオフセット 0 で、ノートに保存されている開始の数値は今と同じである
- 配置を伸縮するときは、開始と長さと、左端を動かした分のオフセットを変え、固定にする。ノートの開始は変えない。絶対時刻は今の伸縮と同じく保たれる
- 自動配置は、1 つの中身につき 1 つまでである。その窓だけを、その配置でのノートの絶対時刻が占める最小の小節範囲に合わせる。合わせると同じトラックの他の配置と重なるときは、`Overlap` でその編集を拒否する。固定の配置は、ノートが増えても動かさない
- リンク、ゲイン、フェードはアクションにする。生成する ID は、今のアクションと同じく実行時に埋める
  - `clip.link`。引数は、元の配置、置き先のトラック、新しい配置の開始 tick、新しい配置の ID である。中身は同じで、長さ、オフセット、ゲイン、フェードは元のコピー、種類は常に固定である。置き先の窓が重なれば `Overlap` で拒否する。ジャーナルにはこの 4 つが残るので、再生は置き先を推測しない
  - `clip.set_gain`。配置と、0 以上の有限な線形ゲイン
  - `clip.set_fades`。配置と、入りと出の flick。どちらも 0 以上
- 保存は、`project.json` に `contents` として中身の ID を ID 順で書く。中身の実体は `contents/<id>.json` で、読むのはこの一覧だけである。ディレクトリの走査では決めない。ID は先に検証し、シンボリックリンクは辿らない。一覧に無いファイルは読まない。一覧にあってファイルが無いときはエラーにする。スキーマ番号は 1 のままにする。このリポジトリに旧形式のパッケージは無い。旧形式は、MOD-10 が移行を持つまで読めない
- `contents/<id>.json` のフィールドは `schema`、`id`、`audio`（今は `null`）、`takes`（今は `[]`）、`notes`（`id`、`start`、`length`、`pitch`、`velocity`）である。トラックの配置のフィールドは `id`、`content`、`lane`、`start`、`length`、`offset`、`kind`、`gain`、`fade_in`、`fade_out` である。ゲインの 1 は `1`、0 は `0` と書く。それ以外は小数点以下 9 桁に丸め、末尾の 0 を落とす
- ChangeSet に `ObjectKind::Content` を足す。中身の作成と削除はこれで記録する。作成は、それを参照するノートと配置より前に置く。削除は、それらより後に置く。中身の更新は、ノートの並び、オーディオ、テイクである。ノートの所属は配置ではなく中身である。配置の更新は、中身の ID、開始、長さ、オフセット、種類、ゲイン、フェード、レーンである
- フェードのフレーム数は、i128 で計算した `(flicks * sample_rate) / FLICKS_PER_SECOND` の、0 へ向かう整数除算である。0 flick は 0 フレームである。1 フレームに満たない正の長さも 0 フレームである。商が u32 に収まらない値は、パニックにもラップにもせず、アクションとパッケージの読み込みで拒否する。拒否の判定は 768 kHz で行う。この変換はオーディオスレッドでは呼ばない
- 入りと出の合計が配置の実時間より長くても、モデルは拒否しない。実時間の長さはテンポが決めるからである。フレームへ変換したあと、各フェードは配置のフレーム長までに縮める。重なる区間のゲインは、今の `edge_gain` と同じく、両方の小さい方である
- 今のモデルにオーディオクリップは無い。テスト用シンセとサンプラーには、配置のフェードをかけない。フェードを使うのは、中身のオーディオを配置として鳴らす経路だけで、その経路はオーディオ参照ができるようになってから接続する。ループの継ぎ目の 5 ms は、配置のフェードとは別のままにする

## 結果

`make check` が通った。中身を共有する固定の配置で、片方に足したノートがもう片方の中身に見える。別トラックの自動配置は、前にノートを足すと重なるとき `Overlap` で拒否され、重ならないときはその窓だけが伸びて既存ノートの `start` は変わらない。768 kHz で u32 に収まらないフェードはアクションとパッケージの読み込みが拒否し、配置より長い入りと出はモデルが受け付ける。テスト用シンセとサンプラーには配置のフェードをかけていない。
