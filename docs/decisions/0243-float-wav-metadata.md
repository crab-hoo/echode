# ADR 0243: float WAV の形式拡張とフレーム数

- 日付: 2026-11-03
- 状態: 採用
- 範囲: FCA-16 のヘッダ。RF64・整数形式・ディザは別の作業単位。

## 背景と再現

[コード全体の監査](../reviews/2026-11-03-full-code-audit.md#fca-16-書出しの形式) は、IEEE float WAV に `cbSize` と `fact` がないことを指摘した。
製品入口 `write_wav` を使う `audit_fca16_a_float_wav_has_an_extended_format_and_a_fact_chunk` は、修正前に `fmt` が 18 ではなく 16 バイトで失敗した。
意図した red は終了コード 101 と固有のアサーション `the float format chunk has no cbSize field` を照合した。

## 決定

- `wav_header` は形式コード 3、2 チャンネル、32 bit を保ち、`fmt` を 18 バイトの WAVEFORMATEX にする。末尾の `cbSize` は 0。
- `data` の前へ 4 バイトの `fact` を置き、値はチャンネルごとのサンプル数、つまり書き出しのフレーム数とする。
- データ開始は 44 から 58 バイトへ移る。RIFF のサイズは音声データのバイト数に 50 を足す。
  空の書き出しも同じチャンクを持ち、`fact` は 0、`data` は空にする。
- 加算と乗算のオーバーフローはファイルを作る前に拒否する。RIFF のメタデータ込みの上限を使い、RF64 への暗黙の切替はしない。
- サンプルの生成・並び・ビット列と、既存出力を一時ファイルから置換する経路は変えない。

[ADR 0019](0019-offline-wav.md) の「余分なチャンクなし」とファイル全体のバイト一致は、この決定で置き換える。
基準音声は再生成しない。コミット済み WAV の基本形式 16 バイトと `data` の全バイトを照合し、コンテナの新しいメタデータは別の回帰で固定する。

## 回帰と基盤

- `audit_wav.rs` の再現を通常テストへ移し、`fmt`・`cbSize`・`fact` と音声データを検証する。
  空・1 フレーム・複数ブロック、44.1 / 48 / 96 kHz、符号付きゼロと ±2 のサンプルも含める。
- `wav_tests.rs` はヘッダだけを作り、最大の RIFF 長、その次のフレーム、データ長とバイトレートのオーバーフローを検証する。
  大容量の音声バッファは確保しない。
- `render.rs` はプラグインあり／なしの 0 フレーム、上限を超える時の既存出力と一時ファイルの保全を検証する。
- CLI の音声比較は共通の `tests/support/mod.rs` で RIFF チャンクを辿り、固定オフセットによるメタデータの音声への混入を防ぐ。
  RIFF 長、チャンク長、パディングと重複も確認する。
- 通常の CLI テストで実行されるため、Makefile と検査選択の追加は不要。既存の Phase 1 契約と失敗時の出力保全も維持する。
- [デバッグ手順](../debugging/audio-and-plugins.md) に、コンテナの差と音声の差を分ける確認先を足す。
  ログの形式・収集先・機器の経路は変えない。

## 残る範囲

出力は従来どおり 32 bit float のステレオだけである。RF64 / BW64、整数形式、ディザ、第三者の読み手全般との互換性は今回の保証に含めない。
実機・聴感の確認ではなく、製品の書き出しと既存音声の厳密な比較を使う。FCA-16 全体の完了とは扱わない。
