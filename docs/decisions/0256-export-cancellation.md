# 0256. 書出しの協調的な途中取消

日付: 2026-11-04。
状態: 採用（P2-08 の途中取消。単位全体の受入完了ではない）。

## 背景と再現

[ADR 0255](0255-export-progress.md) までの GUI は率を示すだけで、長い書出しを止められなかった。
CLI を強制終了すると、一時 WAV とスナップショットの片付けやヘルパーの正常終了を飛ばす。
既存の原子的な公開を維持し、実行側が取消を認めた時だけ「取消済み」とする。

実 CLI の新しい制御オプションを使う回帰を先に追加し、未認識によって進捗が届かない状態を再現した。
終了コード 101 と固有の `cancellable export did not start` を照合した証拠は `target/export-cancel-red/` にある。

## 決定: CLI の制御と公開の境界

- `echode render ... --cancel-stdin` を任意指定にする。指定しなければ stdin の EOF で取り消さない。
  指定時は専用スレッドが stdin の任意の 1 バイト・EOF・読込みエラーを取消要求として原子フラグへ記録する。
  進捗の stdout の切断とは独立し、進捗の観測者の切断だけでは取り消さない。
- 読込みスレッドは CLI プロセスの寿命を持ち、正常終了時に制御側の EOF を待って join しない。
  GUI は実行中は制御パイプを開いたままにし、取消時に書込み側を閉じる。シグナル・自動再送・強制 kill は使わない。
- オフラインの制御側で、準備の区切り・各ブロック・flush 前・ファイル同期後の rename 直前にフラグを調べる。
  音声コールバックや RT へ読込み・待機・確保を追加しない。音声生成・量子化・ブロック長も変えない。
- 取消を認めれば `export cancelled` と終了コード 130 を返す。
  `complete` と `exported` は出さず、一時 WAV の Drop と既存のエンジンの Drop で片付ける。
  既存の出力を削除・切詰め・置換しない。
- rename 直前の最終照合を公開の境界とする。それより遅い取消で完成ファイルを取り消したり削除したりしない。
  正常終了は成功、公開後の親ディレクトリ同期失敗は従来の耐久性不明のエラーを保つ。
- 現在の素材のコピー・復号・プラグイン初期化・処理中のブロック・ファイル同期そのものは中断しない。
  ヘルパーのブロック待ちの上限は従来の 60 秒である。即時に完了する取消とは案内しない。

## 決定: GUI の状態と寿命

- 下部に「書出しを取り消す」を置き、準備中から操作できる。最初の要求で「書出しを取消中」にし、連打を無効にする。
  停止する対象はウィンドウ所有の同じジョブで、文書の交換後も変えない。
- 準備の開始前・一時領域の作成後・スナップショットの準備後に要求を照合する。
  準備中のコピーが既に進んでいれば、その終了後に片付けて CLI の起動を避ける。
  CLI を起動しなかった取消では前回設定を保存しない。
- CLI の実行中は進捗が閉じても 100 ms の poll を続け、取消を制御パイプへ渡す。
  取消を要求した後の遅い進捗で「取消中」を上書きしない。
- ローカルな要求だけでは取消済みにしない。正常な終了コード 130 の時だけ取消済みとし、0 は成功、その他は失敗にする。
  終了待ち・ログの読取り・専用パッケージの片付けが終わるまで次のジョブを開始しない。
  取消は 100% にせず、次のジョブでは要求フラグを初期化する。
- アプリ終了後の再開や、強制終了後の一時物の探索・自動削除は今回の範囲に含めない。

## 回帰と基盤

- CLI の `tests/export_cancellation.rs` は、進捗の到着後に実制御パイプを閉じる。
  プラグインなしと隔離した Sine Pad の両経路で 130・原本保持・一時物の除去・成功通知の不在を検査する。
  制御パイプを開いたままの正常終了と、オプションなしの stdin EOF も検査する。
- 必須契約 `export-cancellation-publish` は完成した一時 WAV の公開前の取消と保全を検査する。
  原子フラグの照合を無効にする反例で、取消が成功へ進む退行を検出する。
- `ExportCancellationTests` の必須契約 `export-cancellation-ui` は、stdout を先に閉じる子から実 CLI へ引き継ぐ。
  文書交換後の取消・原本保持・スナップショットの除去・次回の成功を検査し、制御 EOF を送らない反例を検出する。
  準備前の取消と、ローカルな要求による正常／失敗の終了コードの誤分類も通常テストに加える。
- 既存の Makefile の通常テスト・製品契約の入口を共有し、新しい検査コマンドは増やさない。
  `scripts/verification.json` と選択回帰へ登録し、README・現在の制約・進捗・設計・診断の入口を更新する。
  音声の処理は変えないため、新しい発音のブロック長テストや DSP 比較は重複追加しない。
- 取消のボタン・状態表示・VoiceOver は UC-55 のユーザー確認待ちである。
  自動回帰で確認する制御の引渡しを、実画面や読み上げの確認とは扱わない。
