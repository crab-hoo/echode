# ADR 0346: デバイスの確定の失敗でも背景保存の保留を終える

日付: 2026-11-14
状態: 採用
関連: [ADR 0130](0130-clap-parameter-editing.md)、[ADR 0229](0229-plugin-window-live-edits.md)、
[DIA-02](../reviews/2026-11-13-detailed-implementation-audit.md#dia-02-確定に失敗したデバイスが編集中のまま残る)

## 問題と再現

開始時の HEAD は `17e914d`。
値を送ったデバイスの `editing` は、確定の状態取得と記録が成功した時だけ消えていた。
取得の時間切れや保管庫の書込みの失敗では、以後の背景保存も次の確定まで保留される。
画面は失敗を表示してその操作を終えるため、次の確定が来ず、後の変更まで閉じる時に失われ得る。

元の `audit_dia02_a_failed_commit_does_not_hold_later_background_saves` を修正前に実行し、
終了コード 101 と `the save waits for a commit the app never sends again` を照合した。
失敗はテスト用パッケージの `media` をファイルにして注入した。利用者の文書・音声機器・実画面は使っていない。

## 比べた案

1. **印を保ち、確定を自動で再送する**: 採らない。
   ヘルパーの時間切れは結果不明であり、自動再送しない既存の契約と合わない。
   画面のジェスチャーと Undo の段も、既に失敗を報告した後に増やすことになる。
2. **取得・記録それぞれのエラー分岐で印を消す**: 採らない。
   同じ終了規則を複数の場所へ置くと、今回のように片方だけが残る。
3. **確定の完了入口で、結果を伝播する前に印を消す（採用）**:
   `device::commit` は取得の `Result` 全体を受け、最初に対象デバイスだけを `editing` から外す。
   取得も記録も、成功・失敗にかかわらず同じ終了規則を通す。新しい状態や待ち行列は足さない。

## 決定と境界

- ワーカーはデバイスレーンから戻った結果を、`?` で先に抜かず、そのまま完了入口へ渡す。
  エラーの種類・原因・表示は保ち、要求の再送や値の巻戻しは行わない。
- 失敗した確定を成功や Undo として記録しない。
  保留していた背景保存と以後の背景保存は、次の通常の保存の手番で記録できる。
  これは背景保存であり、失敗した操作の Undo の段を後から作るものではない。
- 成功した確定は従来どおり 1 回の Undo、同じ状態の確定は Undo を増やさず編集だけを終える。
  他のデバイスの編集中の印は変えない。
- ディスクが書けない間の保存、ヘルパーが背景保存自体を断る問題（DIA-04・05）は解決しない。
  失敗時の取得バイトを新たに保管する仕組みも足さず、背景保存がない状態の復元は保証しない。
- DSP、通信の形式、期限、保存形式、C ABI、画面の操作は変えない。
  性能を目的とする変更ではなく、実時間の計測は行っていない。

## 回帰と基盤

- 元の監査回帰の無視を外し、保留済みと後から来た保存の置換、実際のジャーナルへの記録、
  Undo が増えないこと、パッケージの再オープンまで検査する。
  既存のデバイス単体テストは `device_tests.rs` に分けた。
- `worker_tests.rs` は製品のデバイスレーンへ時間切れ・busy・レーンの panic の型付きの失敗を注入し、
  ワーカーの完了、対象だけの保留解除、追加の確定なしでの背景保存と再オープンを検査する。
  取得の失敗を先に伝播する旧来の順序へ戻すと、終了コード 101 と
  `the failed capture still holds the device's background saves` で失敗することも照合した。
- 成功と同値の確定の回帰は、対象だけの保留解除と単一 Undo / Redo を検査する。
- 設計の正本・監査の状態・既存のパラメーターのデバッグ手順を更新する。
  既存の Rust の crate 単位の選択で新しい通常回帰も走るため、検査の入口は増やさない。
  ログの形式・成果物の場所は変えず、`doctor`・`debug-report` の収集範囲も変えない。
  結果と手動検査の見送りは `target/verification/report.md` に記録する。
