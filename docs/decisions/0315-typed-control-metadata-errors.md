# ADR 0315: 制御メタデータの構造の原因を保持する

日付: 2026-11-10
状態: 採用
関連: M1（DEV-7・SPG-11・XCA-16）、[ADR 0314](0314-typed-refusal-structure-errors.md)

## 問題と再現

開始時の HEAD は `6fcce0e`。
`control.rs` は、フレーム長・固定長・未知の種類とコマンド・ポートの列の不正を定数の文だけの `io::Error` にしていた。
表示文は残るが、不正なフィールド・受けた値・必要と実際のバイト数を型で読めなかった。

製品の `Socket::recv_tagged` に、1 バイトしかない `SetChain` の生フレームを送る回帰を先に追加した。
型への downcast を照合すると、修正前は `malformed control metadata must retain its typed structural cause` で失敗した。
期待終了コード 101 と固有のアサーションの照合は `target/focused-checks/control-decode-red/` に残す。
`get_ref().is_some()` だけでは文字列の原因も通るので、型まで検査する。

## 比べた案と決定

1. 定数の文を残す。異なるフィールドや宣言長が同じ文へ消えるため採らない。
2. フレーム・固定長・ポートごとに別々のエラー階層を作る。元の外部エラーはなく、同じ制御メタデータの構造なので層を増やさない。
3. **共通の `ControlDecodeError` と `ControlField` で構造を保持し、固定長の読込みを共通化する。**

3 を採る。`WrongSize` はフィールド・必要なバイト数・実際のバイト数を持つ。
固定長では完全一致、不足した可変長の列では必要な最小長を返す。
ポートの数とチャンネルの列は `input` で方向を区別する。
フレームの宣言長と許容範囲、余分なポートのバイト数、未知の種類・コマンド、対応する FD の欠落も型で分ける。
元の不正なバイトは保持しない。

`io::Error::get_ref` から同じ型を読み、公開操作の `SessionError::Io` でも保持する。
表示文・`InvalidData`・通信の形式と受理する入力は変えない。
従来の一部の空メッセージが余分な本体を無視することも、この変更では厳しくしない。
ポートの宣言数からの確保は、引き続き実際の列が足りると確認した後だけ行う。
音声処理・期限・保存・C ABI は変えず、性能改善は主張しない。

## 回帰と基盤

- `control_decode_tests.rs` は、実ソケットで固定長の不足と超過、空であるべき本体、全不正コマンド、未知の種類を通す。
  ポートの両方向の数と列の不足、余分なバイト、テールと遅延の不足、FD の欠落も型と従来の文面で照合する。
  フレーム長の上下限、全バイト位置で分けた受信、正常値の往復と従来の余分な本体の受理も固定する。
- `session_decode_tests.rs` は、公開するパラメーター操作でも同じ構造の原因が `SessionError::Io` に残ることを検査する。
- 制御ソケットの fuzz の種に、長さ・固定長・ポートの両方向・未知の種類とコマンドの不正を追加する。
  通常の Rust 検査と既存の `control_inputs_replay` が通すため、Makefile と検査選択は増やさない。
- 領域別設計、コードの所在、診断手順と索引、監査の状態を更新する。
  利用者の制約・実機の確認場面は増えず、status.md とユーザー確認の一覧は変えない。

## 残り

M1 全体の完了とはしない。
次は `params.rs` と `gui.rs` の内側の構造で、パラメーター・窓・通知の長さ・値・フラグを定数の文へ畳む境界である。
FD の受信規則の違反と送信側の引数の拒否も今回の範囲外である。
検査結果と各検査の見送り理由は `target/verification/report.md` を正本とする。
