# ADR 0134: プラグイン GUI の寿命を表示状態から分離し、ループとキー入力で保持する

- 日付: 2026-10-21
- 状態: 採用。第三者プラグインの実画面はユーザー確認待ち
- 範囲: GUI の閉鎖判定、ループ変更時のヘルパー保持、GUI フォーカス中の DAW キー、FX 追加ボタン

## 背景と再現

ユーザーから、GUI が開いてすぐ消える、ループ切替で GUI とプラグイン状態が失われる、
GUI にフォーカスすると Space などが DAW へ届かないとの報告を受けた。
FX 追加ボタンは最後のデバイスの右へ移す要望があった。

一時的な非表示を `isVisible` で閉鎖とみなし、view を破棄する経路を機器なしで再現した。
修正前は `temporary invisibility must not report a close` で失敗した。
実画面での報告すべてがこの経路によると確認したわけではない。

ループ変更はイベント領域を準備し直す際、ヘルパーの最後の保存状態と古いルートの状態を比較していた。
状態の取り込み後は差が生じ、同じデバイスでもヘルパーを生成し直していた。
製品エンジンと実ヘルパーで、GUI を開き、状態を取り込み、その後さらに値を変えてループを切り替えると、
`loop changes must keep the plugin window` で失敗した。
再現ログは `target/plugin-window-repro.log`、`target/plugin-loop-repro.log` にある。

キーを転送しないという [ADR 0132](0132-helper-plugin-windows.md) の以前の判断は、今回のユーザー要望で変更する。

## 決定

### 明示的な閉鎖でだけ view を破棄する

- ヘルパーの `NSPanel` 派生クラスは `close` を記録する。
  OS による一時的な非表示を、ユーザーの閉鎖とみなさない。
- 親 Echode、自分のヘルパー、同じ親の別ヘルパーが最前面なら、同じ作業中として表示を保つ。
  別アプリが最前面なら従来どおり隠す。最前面アプリの情報が一時的にない時は直前の判定を保つ。
  他のプロセスの親は、メインスレッドから公開 API の `proc_pidinfo` で取得する。
- 開く・前面化でフォーカスを取らない規則、明示的な閉鎖・削除・オフライン・文書終了の寿命は保つ。

### ループの準備は状態を復元しない

- 再生計画の保留項目に、記録済み状態の復元を必要とするかを持たせる。
  ループだけの準備は、デバイス ID と CLAP ID が同じヘルパーをそのまま使う。
- イベント領域の拡張は既存の共有領域交換を通す。
  GUI、未保存のパラメーター、状態バイトに含まれない値も保持する。
- 保留中のプロジェクト編集にループ変更が重なっても、先の編集が必要とする状態復元を落とさない。
  プロジェクトの交換や状態の Undo / Redo の復元規則は従来どおりである。

### GUI から既存の DAW コマンドを中継する

- ヘルパーの AppKit イベント処理で、キーウィンドウへの Space と既存の Command ショートカットを識別する。
  再生・一時停止、停止、Undo / Redo、新規・開く、トラック追加、ペイン切替、パレットが対象である。
- 編集可能な `NSTextView`、または `NSTextInputClient` が有効な選択・挿入位置を返す時は、入力をプラグインへ渡す。
  文字入力とその Undo、入力メソッドを DAW が横取りしない。未登録キーもプラグインへ渡す。
- 対象キーはプラグインへ二重配送しない。長押しのリピートでも再生状態を連続反転しない。
  音声スレッドは使わず、メインスレッドから制御スレッドへ渡し、`GuiCommand` 通知として送る。
- 通知は既存の活動受け口と Swift ブリッジを通し、`WorkspaceSession.perform` で実行する。
  文書・デバイス・窓の有効性と、モーダル表示中などの既存の実行可否を守る。
  OS のキーイベント合成やアクセシビリティ権限は使わない。
- プラグイン独自の文字入力が Cocoa の入力状態を公開しない場合の区別と、浮動型だけの GUI は実機確認を残す。

### 追加ボタンをチェインの末尾へ置く

- デバイスビューの見出しから FX 追加ボタンを移し、横スクロールする列の末尾に置く。
  デバイスがない時も同じ末尾領域に表示し、候補パネルを開く既存の操作を使う。
- Native ボタンのキーボード・VoiceOver 操作、全体の排他、末尾のドロップ領域を保つ。

## 検査と診断

- 一時非表示は製品の GUI 周回へ記録用の面を渡し、閉鎖通知も view の破棄も起こらないことを確認する。
- ループは停止中と再生中に切り替え、同じ GUI・未保存値・状態外の値が残ることを実ヘルパーで確認する。
- 実 AppKit キーイベント、制御ソケット、活動 JSON、Swift の既存コマンドへの到達をそれぞれ機器なしで確認する。
- FX 追加は空・複数・削除後の実ボタンの位置と操作、排他時の無効化を確認する。
- 必須契約と負の対照は `scripts/verification.json` に登録する。
  実ウィンドウと第三者プラグイン、機器を開く計測はユーザー担当であり、自動回帰と区別する。
