# ADR 0079: 失敗したプラグインの書き出しは完成にしない

- 日付: 2026-10-14
- 状態: 採用
- 範囲: 監査 PRO-07。書き出しと、プラグインの起動・処理の失敗

## 背景

ファイルがあるのに起動できないデバイスは飛ばし、内蔵シンセの音で WAV を完成させていた。`process` の拒否、ハング、クラッシュは、そのブロックを無音にするだけで `PlaybackStatus.failed` を立てない。書き出しはそのフラグだけを見ていた。ライブ再生で期限を超えたブロックを無音にする契約を、完成したファイルの成功条件に使っていた。

## 決定

書き出しは、すべてのデバイスが起動し、各ブロックの処理を終えることを要求する。ファイルがあるのに起動できないときは、デバイス ID と理由を返し、WAV を作らない。`process` がエラーを返した、プロセスが終了した、期限までに終わらなかった、音声を提出できなかったときは、そのブロックのあとで WAV を消し、同じ形の理由を返す。

ライブ再生は、期限を超えたブロックを無音にする。`PlaybackStatus.failed` は立てない。書き出しだけが、その期限超過を失敗として読む。

理由の種別は音声スレッドでは数値で持つ。文字列は制御スレッドで作る。`process` の拒否は、共有領域に印をつけてから親が読む。クラッシュは `SIGABRT` のハンドラが印を書いてから信号を上げ直す。クラッシュレポートが終了を遅らせても、期限の時点でプロセス終了と区別できる。ハングはプロセスが生きているので、期限超過のままである。

起動中に制御ソケットが閉じたときは、ヘルパーが標準エラーへ書いた文を理由に足す。

## 結果

生成、有効化、`process` の拒否、クラッシュ、ハングは、デバイス ID を含む理由で失敗し、WAV を残さない。前段が正常で後段だけ `process` を拒否した場合は、後段のデバイス ID だけを理由にする。ハングが隣にあっても、健康なトラックのライブ再生は `failed` を立てない。

## 後日

2026-10-17: `SIGSEGV`、`SIGBUS`、`SIGILL` も同じ印を書いてから同じ信号を上げ直す（[ADR 0111](0111-macos-helper-notices.md)）。ハングを期限超過のままにする判断は変わらない。印は、すでに待っているブロックを起床させない。
