# ADR 0058: 波形のピークは CPU で作り、見えている列だけを描く

- 日付: 2026-10-13
- 状態: 採用
- 範囲: 取り込んだ音声のアレンジ表示。スペクトログラム、テンポ、キー、トランジェント、Ogg は含まない

## 背景

Phase 1 は、波形のピークを GPU で作るとしていた。計算は帯域で決まる単純な最小・最大で、圧縮ファイルではデコードの方が長い。GPU にすると CLI でも Metal を使う `echode-gpu` が要る（監査 ENG-16）。取り込み自体は正準 PCM までできている（[ADR 0056](0056-audio-import.md)）。

## 測定

Apple M4。48 kHz、モノラル、60 秒（2,880,000 サンプル）。列は 64 サンプル（45,000 列）。入力は既にメモリ上にある。比較は `spikes/peaks/main.swift` を `swiftc -O` でコンパイルし、バッファを作ったあとの 1 回を測った。

| 方式 | 時間 | 範囲 |
|---|---|---|
| スカラーの CPU ループ | 2.4 ms | 最細の列だけ |
| `vDSP_minv` と `vDSP_maxv` を列ごと | 0.6 ms | 最細の列だけ |
| Metal のコンピュート（列ごとに 1 スレッド。投入と完了待ちを含む） | 1.4 ms | 最細の列だけ |

Swift から `vDSP_vswmin` は見えなかったので、スライド窓ではなく列ごとの vDSP を測った。Metal のバッファは計測の前に置いてあり、PCM の転送は含まない。最適化しない `swift` の直実行は CPU ループが 528 ms で、比較には使わない。

製品の経路は、粗い段も作るリリースビルドの `echode-history` で 6.6 ms だった（`cpu peaks for 60s mono: 6.550666ms`）。非有限のサンプルは飛ばす。デコードはピークの方式で変わらないので、この比較には入れていない。圧縮ファイルではデコードの方が長い。

## 決定

ピークは CPU で作る。`echode-gpu` は足さない。Metal は vDSP より遅く、最細の列だけではスカラーとの差も 1 ms 程度である。製品のピラミッドは 1 分の音声で 6.6 ms で、取り込みのあと 1 回である。vDSP は最細の列では速いが、部分列、非有限のサンプル、粗い段を同じループで扱えるスカラーを製品の経路にする。Accelerate は足さない。

取り込みの直後に `cache/peaks/<hash>` を書く。先頭は `ECHDPK01`、バケット幅、フレーム数、段である。バケット幅が今の 64 と違うファイルは無視して作り直す。キャッシュの書き込みに失敗しても取り込みは成功し、次のスナップショットが PCM から作り直す。ファイルが無い配置は、波形なしでクリップを描く。再生はそのままである。

ステレオは再生と同じく左右を平均してから最小・最大を取る。1 段目は 64 サンプル、それより粗い段は隣の列を対にする。表示が 1 列より細かい範囲は、残してあるモノラルの PCM を走査する。

文書スレッドが、プロジェクトが変わった時に参照中のハッシュを読む。同じハッシュは前のスナップショットから引き継ぐ。描画スレッドは見えている列だけを問い合わせる。オーディオスレッドはピークを読まない。

描画は今のアレンジのシェーダーである。クリップの矩形の中に包絡を描き、ノートと再生位置より下、レーンと拍線より上に置く。トラックは縦に重ならない。ヘッダへ食い込まないよう、タイムラインの範囲で切る。

## 結果

定数とインパルス、ステレオの平均、キャッシュの往復、tick からフレームへの対応を検査する。画面を開かず、前半がフルスケールで後半が無音のクリップを描き、上端の左が波形色、右がクリップ色であることを確認する。画面での操作確認は未実施である。
