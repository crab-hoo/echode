# ADR 0362: 公開済み素材を保持し、失敗したヘルパーの寿命を閉じる

- 日付: 2026-11-15
- 状態: 採用
- 関連: [詳細監査 DIA-07・08](../reviews/2026-11-13-detailed-implementation-audit.md)、[ADR 0272](0272-staged-import-media.md)、[ADR 0331](0331-off-worker-audio-import.md)
- 置き換え: ADR 0272 の「公開後の失敗で新しく作った名前を消す」という判断。

## 問題と再現

DIA-07 は、取込み A の公開後・ジャーナルの失敗前に、別スレッドで同じ素材の B を段階にすると再現する。
B は保管庫の一致する名前を使って一時ファイルを省くが、A の取下げがその名前を消す。
B の編集と再オープンは成立するのに、配置の PCM は読めなくなる。
`host_tests::audit_dia07_a_stage_survives_another_imports_clean_journal_failure` を修正前に実行し、この PCM のアサーションで失敗した。

DIA-08 は、外部で回収した子の状態をホストに知らせず、実際の `waitpid` に `ECHILD` を返させると、破棄後も終了監視が残る。
また、共有領域を ready にしない実際の子を再起動で作ると、準備の時間切れを返した後も子が残る。
`session_lifecycle_tests.rs` の 2 つの回帰は、修正前にそれぞれ join と回収のアサーションで失敗した。
待ちの上限は検査の停止用で、速度の合否を測るテストではない。実機・音声機器・アプリは使わない。

## 比較と決定

### 保管庫は公開済みの名前を取下げない

- 段階に元の PCM を保持し、公開時に欠落を検出して再作成する案は、全体 PCM の保持を延ばし、公開側へ再作成の I/O を戻す。
  存在確認の直後の取下げまで防ぐには同期か参照の所有も必要になる。
- 段階と取下げをロックや参照数で調停する案は、文書ワーカーと背景段階の間に新しい共有状態と規則を作る。
- **採用**: ハッシュの名前になった保管物は、公開の同期・索引・後続の公開・ジャーナルのどの失敗でも削除しない。
  既存の掃除未実装の制約を広げるが、他の段階が見た名前を壊さず、取下げ用の 2 つの型と巻戻し処理を削除できる。

未公開の一時ファイルは従来どおり破棄で消す。モデルの拒否は公開前なので、EXT-02 の無副作用の境界は維持する。
名前を再利用する公開も、ジャーナルの前にディレクトリを同期する。
最初の公開で改名後の同期が失敗しても、後の取込みが未同期の名前を履歴へ記録しないためである。
PCM の命名・保存形式・公開 API・編集の原子性は変えない。既に失われた素材は復元しない。
増えるのは失敗後に残る素材と、名前を再利用する公開あたり 1 回のディレクトリ同期で、処理時間の比較計測は行っていない。
容量の回収は参照の全体を考慮する掃除として別に扱い、今回その機能は追加しない。

### 終了監視の join は破棄の不変条件にする

`shutdown` の成功だけに join を任せる案では、`closed` を立てた後の待ちの失敗が領域の寿命を破る。
**採用**: `Drop` が `shutdown` の成否にかかわらず `stop_watch` を呼ぶ。
監視を取り出して join する既存の入口は冪等なので、新しい所有状態や生ポインタの規則を増やさない。

再起動は、起動の準備と最後の状態の復元を一つの結果にまとめる。
どちらが失敗しても、エラーを返す前に新しい子を強制終了・回収し、終了監視を join する。
子を残して次の再起動・破棄に任せる案は採らない。確保したプロセスの寿命を失敗した要求の中で閉じる。
成功時の再起動、期限、状態の選び方とエラーの種類は変えない。

## 回帰と基盤

- ジャーナル失敗の注入に要求単位の callback を加え、公開と失敗の間に背景段階を完了できるようにした。
  callback はテスト専用で、他のパッケージの故障注入を止めるロックを持たずに呼ぶ。
- 素材の競合は書込み前・同期の 2 種の失敗で、B の編集と再オープン後の PCM を照合する。
  単一・一括の保存失敗、索引の失敗、未公開段階の破棄、耐久性不明の行の復旧も既存・追加の回帰で扱う。
- 終了監視の回帰は、最初から破棄する場合と、明示した終了が失敗した後の破棄を通す。
  監視の代役は生ポインタを読まないので、修正前の失敗も安全に検出できる。
- 追加テストは通常の Rust テストに含まれる。検査入口と選択は既存のままで、新しい検査 ID は不要である。
  実際のプラグインの隔離回帰も通常の検査で実行する。
- 設計書、監査の状態、素材回収の制約、保存・終了失敗の診断を更新する。
  現在の検査結果と手動検査の見送り理由は `target/verification/report.md` を正本とする。
