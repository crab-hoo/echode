# ADR 0192: ヘッダの音量・パンの読み上げ増減を選択全体へ適用する

- 日付: 2026-10-28
- 状態: 採用。P2-06 の先行分。実画面・VoiceOver・聴感はユーザー確認待ち
- 関連: [ミックスの操作要件](../interaction-design.md#ミキサーの複数選択)、
  [ADR 0107](0107-mix-controls.md)、[ADR 0189](0189-selected-track-mute-and-solo.md)、
  [ADR 0191](0191-selected-track-numeric-mix.md)

## 背景と再現

開始時の HEAD は `fd1ca3f`。
数値入力は選択全体を相対調整するが、ヘッダのアクセシビリティ増減は単一トラックを変更していた。
実際の `NSAccessibilityElement.accessibilityPerformIncrement` を通る回帰を先に追加した。
音量 0.5 と 0.25 の選択で 2 回増加させると、他方は 0.25 に残り、共通の 2 dB 差にならなかった。
`target/focused-checks/mixer-step-red/` で終了コード 1 と固有のアサーションを照合した。
これは一時ログの所在であり、永続的な証拠へのリンクではない。

## 決定

- `MixActions.adjust` を数値入力と別の相対要求にする。
  ヘッダの増減は音量 ±1 dB、パン ±5% とし、押したトラックが選択内なら全選択、選択外ならそのトラックだけを扱う。
  マウスのドラッグ・既定値リセットは単一対象のまま保つ。インスペクターは既存の数値入力を使う。
- `MixerValueBatch.direction` は ±1 だけを許し、数値の要求値ではなく編集の手番の現行値から次の段を計算する。
  文書・基準 ID・選択 ID 群を捕捉し、数値入力・ミュート／ソロと同じ `mixerSwitchTail` を通す。
  先行するライブプレビューは確定してから読み、表示更新前の連打も各 1 回の Undo にする。
- MainActor 上の AppKit callback は、その呼出し中に対象を捕捉する。
  非メインスレッドからの callback は MainActor へ渡し、その手番で UI 状態を読む。
  Objective-C 境界を渡すのは Sendable な action holder だけとし、要素本体を渡さない。
- 共通倍率・差分と上下限は数値入力と共有し、各メンバーの個別クランプで相対関係を壊さない。
  複数対象の音量は有限の dB 差を保ち、単一スライダーの −60 dB の表示下端で全体を無音にしない。
  正の最小 Float と最大音量 4 で全体を止め、無音のメンバーは無音を保つ。
- 複数対象の無音の基準からの増加は、音量比が決まらないため数値入力と同じ理由を示して拒否する。
  無音の基準からの減少は no-op とする。
  単一対象は従来どおり無音から −59 dB へ上がり、−60 dB 以下への減少で無音になる。
- 増減時に読み上げ値だけを先走らせない。
  アクセシビリティの木の更新時に確定値を読み、共通限界で止まった値と異なる段を公開しない。
- 文書 ID が変わったらミックスのアクセシビリティ要素のキャッシュを破棄する。
  古い要素は元の文書・callback を保持して拒否し、再オープン後の同じトラック ID へ流用しない。
- 欠けた ID・重複・不正なフィールドや増減方向は全体を拒否する。
  既存の `param.set` 配列を 1 回送り、単一 Undo / Redo・保存・音声計画更新を共有する。
  no-op は Undo・Redo を変えない。新しいアクション・ABI・保存形式・DSP・固定上限は加えない。

## 回帰と基盤の保守

- `mixer-step-ui`: 実ヘッダの要素から連続増減、操作時の選択保持、共通差分、選択外の保持、単一 Undo / Redo と保存を確認する。
  方向の反転と、主スレッドの対象捕捉を非同期へ遅らせる誤りを負の対照にする。
- `mixer-step-bounds-ui`: 実要素から共通音量・パン限界、確定値の読戻し、no-op の Redo 保持、旧要素・要求の拒否を確認する。
  共通制限の除去と文書交換時のキャッシュ保持を負の対照にする。
- 通常回帰は編集の保留、先行する数値入力とライブプレビュー、無音・最小正値・単一対象、不正方向と欠けた対象も扱う。
  Makefile の既存入口・検査登録・選択回帰、利用手順・現状・P2・領域設計・診断手順と画面の説明を更新する。
- 音を作る処理や音声スレッドの操作は変えず、既存の配列編集とフェーダー補間を使う。
  新しいランダムアクション生成や DSP のブロック長回帰は不要である。
- 診断では主スレッドへの到着、捕捉した選択、要求の方向、手番の現行値、共通限界、確定した読上げ値を区別する。
  ログ形式・保存先・外部入力は増えず、`doctor` と `debug-report` の収集範囲は変更不要である。
- 実画面での選択・説明、VoiceOver の読上げ時刻と操作感、再生中の一括確定の聴感はユーザー担当とする。
  機器やアプリ操作は実行せず、自動の入力回帰を実機確認や P2-06 全体の完了へ読み替えない。
