# ADR 0103: 停止では最後の値ではなく鳴っている波形を減衰する

- 日付: 2026-10-16
- 状態: 採用
- 範囲: ライブ出力の停止・一時停止・取消。[ADR 0101](0101-live-output-discontinuities.md) の停止時の定数補正と、[ADR 0097](0097-cancellable-retained-transport.md) の既発音中の取消を改訂する。

## 前回の修正で残った問題

ユーザーは停止した瞬間のクリックが残ることを報告した。前回は停止後の0へ最後の1サンプルの値を加え、それを線形に0へ下げていた。一定値の入力なら段差が消えるが、周期を持つ波形は定数へ突然置き換わる。振幅だけの連続性では停止音を検証できていなかった。

製品と同じ `fill` に437 Hzと1601 Hzの左右別のPCMを通す回帰を先に追加した。旧処理は48 kHz・1フレームの停止直後が -0.07109738、連続波形の期待値が -0.08468439 となり失敗した。記録は `target/noise-audit/stop-wave-before.log`。一定値の回帰は保持し、位相と周波数を持つ入力へ保証を広げる。

## 決定

ライブ再生は、停止を受けたコールバック境界で再生位置と `playing` を止める。鳴っている音源と配置済みの素材だけを最大5 ms処理し、出力に半コサインの1→0のゲインをかける。波形の位相は継続し、減衰の両端の傾きを0にする。減衰が終わったら音源を消去し、ヘルパーのDSPリセットとMIDI発音停止を次の処理より先に配送する。

新しいノートオン、停止位置以降に始まる素材、新しいメトロノームの拍は減衰区間へ入れない。素材とメトロノームは停止位置より前に始まったものだけを継続する。再生計画の交換も減衰の完了まで保留し、現在のグラフを使う。5 msの間に別の再生・位置移動が来た場合も、旧状態の消去を新しい処理の前に要求する。

まだ1ブロックも提出していない再生を取り消した場合は、初回から無音で、位置も進めない。音が出ている状態で描画中に停止が来た場合は、処理中のブロックを完了し、次の境界から5 ms以内に減衰する。途中でそのブロックを0へ差し替えると波形が再び切れるためである。したがって出力停止の上限は処理中の1ブロックと5 msであり、準備の完了や文書ワーカーを待つ時間ではない。

通常再生へ先読みや遅延を加えない。5 ms分のPCMを常時遅らせる案は、発音の遅延を増やすため使わない。書き出しと通常の `PlaybackAudio::render` の停止は従来どおり即時無音にし、ライブ用入口だけがこの処理を使う。新しい確保・ロック・制御I/Oは音声経路へ追加しない。

既存の出力ゲインの実装として [Ardour の AudioEngine](https://github.com/Ardour/ardour/blob/master/libs/ardour/audioengine.cc) と [JUCE AudioBuffer](https://docs.juce.com/master/classjuce_1_1AudioBuffer.html) を確認した。実際の出力へゲインを掛ける処理は既存の手法であり、新しい音源の推測や波形の合成はしない。既存のRustの平面バッファと `libm` へ小さいゲイン処理を接続し、C++のエンジン全体を依存へ追加しない。比較の根拠は以下の波形の値と境界の回帰で、速度の優位を主張するものではない。

## テストと診断

必須契約 `transport-declick` は `contract_stop_preserves_waveform_while_fading_under_rtsan` へ強化する。48/96 kHz、1/7/64/512フレーム、3位相、停止・一時停止・取消の72ケースで、左右の連続PCMに独立計算した半コサインのゲインを掛けた値、5 ms後の0、時計停止を確認する。最後の値への定数補正を一時コピーへ戻す負の対照で、波形の期待値に失敗することも要求する。

一定値の回帰の期待曲線も線形から半コサインへ変更する。失敗を消すための閾値変更ではなく、端の傾きを変えた仕様に対する期待値である。ブロック長からの独立性、未来の素材・拍の排除、別プロセスで未来のノートを出さないこと、通常リセットを無視する音源を含む楽器・エフェクト・連鎖の旧音消去を追加する。描画途中の取消は、サンプル時計から決定的に停止を発生させ、既発音と未発音の両方を検査する。

これらは実機を使わない通常検査とRTSanの対象である。`plugin_missed_blocks` は減衰中のヘルパー失敗も加算する。再現が続く場合は、停止前後の波形とこの差分から、正常な減衰とプラグイン失敗による欠落を区別する。診断の形式や収集範囲は変更しない。

## 実機の担当

音声だけの変更に Computer Use を使わない。実機・聴感テストは原則としてユーザーが担当し、エージェントは波形と製品バッファの自動回帰を先に行う。開いているアプリを終了・置換せず、修正版は別のバンドルとして用意する。自動回帰の合格をユーザーの環境でのクリック解消とは言い換えない。

## 同日の再報告

ユーザーは `target/stop-click/Echode.app` でも停止クリックが残ることを確認した。複数種類の音源、ループ無効での再現である。上の波形の回帰はこの報告の原因を特定していない。減衰の追加だけで解消したと扱わず、実出力の記録と別に発見したループ境界の修正を [ADR 0104](0104-stop-output-diagnostics.md) へ記録する。
