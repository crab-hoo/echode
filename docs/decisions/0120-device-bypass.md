# ADR 0120: CLAP のホストバイパスを編集・保存・音声へ接続する

- 日付: 2026-10-19
- 状態: P2-02 のバイパスを接続。GUI・パラメーター・オフライン化等は未完了
- 範囲: トラック CLAP のバイパス、保存形式 4、ライブ再生と書出し

## 背景

[ADR 0118](0118-track-fx-chain-editing.md) でトラック FX の編集経路を接続した。
次に、デバイスを削除せず音を比較するためのバイパスを同じ経路へ加える。
プラグイン自身のバイパスパラメーターは必須ではないため、ホストが音声経路を切り替える。

## 決定

- `Device.bypassed` を保存し、`device.bypass` を登録簿・API / MCP・差分・ジャーナルへ通す。
  トラック FX 行のネイティブチェックボックスから操作し、1 操作を単一 Undo / Redo とする。
  設定コピーはこの値も引き継ぎ、ミキサーと欠けた ID の操作は拒否する。
- バイパスした FX は入力の平面をゲイン・左右を変えずに通す。
  先頭の音源はノートから発音せず、既定シンセへ戻さない。同じトラックの配置音声は引き続き鳴る。
  後続の有効なデバイス、フェーダー、パンは通常どおり処理する。
- バイパス中はヘルパーの音声処理を呼ばず、プロセスと記録済み設定は保持する。
  廃棄する後片付けブロックも省き、リセット要求は再有効化まで保持する。
  連続したバイパスは反復で通過し、再帰の深さや固定デバイス数に依存させない。
  ドライ出力は制御側で上流の平面数に合わせて準備し、処理側で確保しない。
  ウェット側のモノ出力を理由にステレオのドライ音を縮めない。
- 計画交換でバイパス状態が変わったら既存のヘルパーリセットを要求する。
  再有効化時は現在保持しているノートだけを追跡し、以前の発音・テールを再開しない。
  標準リセットを無視するプラグインにも既存の Note Choke と MIDI panic を送る。
  不正なバス接続で交換を拒否した場合は、従来のバイパス値とドライ平面数へ戻す。

## 保存の互換性

新しい再生状態を旧リーダーが無視して音を変えないよう、パッケージのスキーマを 3 から 4 へ進める。
旧版は全デバイスが有効だったため、3 以前を読む段階変換では欠けた `bypassed` を `false` で補う。
現行形式では真偽値を必須とし、欠落・別の型・ミキサーのバイパスを破損として拒否する。
旧ジャーナルのデバイス作成差分に値がない場合も有効として読み、現在の差分は 0 / 1 を記録する。
ジャーナル復旧と Undo / Redo が当てる差分も、ミキサーのバイパスと状態を拒否する。
`check_invariants` も同じ規則を持ち、復旧後に保存したパッケージが読み込みで拒否される経路を残さない。

## 検査と診断

- モデルとランダム操作で差分の適用・反転、設定コピー、Undo / Redo、保存・復旧を通す。
  保存形式の回帰で旧スキーマの移行と不正な値の拒否を確認する。
- `fx-bypass-ui` は実 FX 行のチェックボックスから文書を変更する。
  音声は別プロセスの CLAP を使う `plugin-bypass`、連鎖の左右保持、再有効化時の追跡・旧発音排除、交換失敗の復元で確認する。
  さらに実書出し経路でドライ音と音源の無音を製品再生と比べる。
  内容比較には実時間の処理期限ではなく停止防止用の期限を使い、実機の期限達成をこの検査の合格と混同しない。
- ブロック分割と RT の禁止操作も検査する。既存の `check-product-contracts` と選択回帰へ必須契約を登録し、
  UI が逆の値を送る差分とエンジンがバイパスを無視する差分を負の対照にする。
- 診断は文書セッション・デバイス ID・保存値、`requested_plan` / `applied_plan`、プラグイン失敗、ドライ／ウェットの平面数を区別する。
  実機・聴感を要しないバッファ検査とユーザー担当の聴感確認を分ける。

## 残る範囲

これはインストール済み CLAP を保持するバイパスであり、読込みを省くオフライン化は別の機能である。
プラグイン GUI・パラメーター編集・一括追加・サムネイル等も P2-02 に残す。
切替時のウェット／ドライのクロスフェードは追加しておらず、実機での切替音や全メーカーの互換性は未確認である。
