# ADR 0162: FX 候補の一覧を AppKit の表にし、押した時点で選択して行のどこでも追加する

- 日付: 2026-10-25
- 状態: 採用。[2026-10-25 の操作の報告](../reviews/2026-10-25-user-feedback.md) の FB-05 への対応。
  実画面の軽さと第三者プラグインが多い時の一覧はユーザー確認待ち
- 関連: [ADR 0118](0118-track-fx-chain-editing.md)、[ADR 0124](0124-selected-track-fx-batches.md)、
  [ADR 0143](0143-browser-click-and-audition-timing.md)

## 背景

FX を追加する時、候補の一覧が重く、ダブルクリックで追加されないことがあると報告された。
一覧は SwiftUI の `List(selection:)` で、各行の文字の部分にだけ `onTapGesture(count: 2)`・`onDrag`・`contextMenu` を付けていた。
ADR 0143 でサンプルブラウザから外した構成と同じであり、同 ADR は候補の一覧に残ることを記録していた。

- ダブルクリックを受けるのは行の文字の幅だけで、行の右側の余白では追加されない。
- 1 回目のクリックの選択が、ダブルクリックの認識と行ごとのドラッグ・メニューの部品を通る。
  選択と検索語の変化のたびに全行の SwiftUI の部品を作り直していた。
- 候補の再走査（読込み中の表示）の間は、追加をすべて拒否していた。
  フォルダの監視が新しい版を出すたびに再走査するため、一覧に見えている候補でもダブルクリックが効かない時間があった。

SwiftUI の一覧はテストのプロセスでクリックの経路を製品と同じ形にできない（ADR 0143）ため、
修正前の行の当たり判定と再走査中の拒否は、ソースの読み取りで確認した。実画面での重さは計測していない。

## 決定

- 候補の一覧を `NSTableView`（`PluginListTable`）に置き換え、SwiftUI からは `PluginCandidateList` で包む。
- 押した時点で表を最初のレスポンダーにし、行を選択する。ダブルクリックを待たない。
  2 回目のクリック（`clickCount == 2`）は、行のどこでも単体追加して候補パネルを閉じる。
  Return とテンキーの Enter は単体追加してパネルを開いたままにする（[操作要件](../interaction-design.md#fx-候補とチェインの操作)）。
- 4 pt 以上のドラッグで、従来と同じ `FXDrag` の候補をトラックヘッダとデバイスビューへ渡す。
  右クリックは押した行を選択し、「選択トラックすべてに追加」で全選択トラックへ単一の Undo で追加する（ADR 0124）。
- 行は候補の一覧が変わった時だけ作り直す。選択と検索欄の矢印の移動は、表の選択だけを変える。
  絞り込みは描画ごとに 1 回だけ計算する。
- 再走査の間も、一覧に見えている候補は追加できる。再走査の完了で消えた候補は従来どおり追加の要求で失敗を表示する。
  再走査のボタンだけは読込み中に無効にする。

## 検査

- 必須契約 `plugin-list-ui` は、ウィンドウ内の実際の表へ行の右端の押下を送る。
  押下での選択とフォーカス、2 回目のクリックだけの追加（閉じる）、Return の追加（閉じない）、
  選択の反映で行の部品を作り直さないこと、右メニューから選択トラックへ単一 Undo で追加することを確認する。
  反例は追加を 3 回目のクリックへずらす。
- 実画面の軽さ、多数の候補でのスクロール、VoiceOver はユーザー確認とする。コマンドパレットの一覧は今回変えない。
