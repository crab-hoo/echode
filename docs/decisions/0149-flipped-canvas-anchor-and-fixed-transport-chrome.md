# ADR 0149: 反転した表示面の固定位置を AppKit に合わせ、状態行・再生ボタン・縦位置・アクセシビリティ要素の寿命を固定する

- 日付: 2026-10-22
- 状態: 採用
- 範囲: [GUI のがくつきの監査](../reviews/2026-10-22-gui-jank-audit.md) の単位 1・2・3・5（JNK-01・JNK-02・JNK-04・JNK-07）。
  [ADR 0144](0144-unscaled-canvas-resizing.md) の「左上固定」の実装のうち、`contentsGravity` の上書きを置き換える。

## 背景と再現

監査で、前のフレームの固定位置と再生準備中の寸法変化を確認した。

- アレンジとピアノロールは反転した View の中にあり、`CALayer.contentsAreFlipped()` は true になる。
  CA の `top` は見た目の下を指すため、AppKit は `layerContentsPlacement = .topLeft` を `bottomLeft` に変換する。
  ADR 0144 はこれを `contentsGravity = .topLeft` で上書きし、古い絵を見た目の左下へ固定していた。
- 状態行は再生準備中だけ小さな `ProgressView` を挿入し、29 pt から 32 pt へ高くなっていた。
  再生ボタンもラベルが Play から Pause に替わる際に幅が 70 pt から 81 pt（日本語では 69 pt から 93 pt）へ変わっていた。
  どちらもペイン領域の再レイアウトを起こし、JNK-01 のずれと重なって再生開始時に見えていた。

修正前に `CanvasResizeTests` と新しい `WorkspaceChromeTests` を製品の View で実行し、次の失敗を確認した。

- 反転した階層で `contentsGravity == .topLeft`（期待は `.bottomLeft`）。
- 状態行の高さ 29 / 32 / 32 pt、再生ボタンの幅 70 / 81 pt。

## 決定

- `CanvasSurface` は `layerContentsPlacement = .topLeft` だけを設定し、`contentsGravity` を上書きしない。
  固定位置は AppKit が反転を考慮して決める。`layerContentsRedrawPolicy = .never` と、主スレッドでの `drawableSize` 更新は ADR 0144 のまま保つ。
- 状態行は表示器の場所を常に確保し、準備中だけ見せる。
  表示器は `opacity` で隠し、レイアウトから外さない。隠れている間はアクセシビリティからも外す。
- 再生ボタンは Play と Pause の両方のラベルを同じ位置に重ね、現在の状態だけを見せる。
  幅は言語ごとの広い方に固定し、ボタンのアクセシビリティラベルは現在の状態だけを読む。
- どちらも高さ・幅を数値で固定せず、実際のラベルの寸法から決める。文字サイズ・言語・アクセシビリティ設定の変更へ追従する。

### 追記: アレンジの縦位置（単位 5、JNK-07）

- `ArrangeCamera` の `originTrack` を利用者の指定値とし、`sanitize()` で有限値と 0 以上だけを保証する。
  `constrain(trackCount:height:)` は表示用のコピーにだけ適用し、高さで指定値を書き換えない。
- `ArrangePaneView` はヘッダ・タイムラインの描画入力へ制限したコピーを渡し、`CanvasNavigationState.arrange` には指定値を記憶する。
  縦スクロールと縦ズームは、指定値ではなく表示中の行を起点にする。高さを広げた後の上スクロールが
  `(指定値 - 表示値)` の分だけ空振りせず、縦ズームもカーソル位置の行を基準にする。
  横スクロール・横ズームは縦の指定値を変更しない。
- トラック選択の `reveal` は表示中の行から行い、対象が既に表示されていれば指定値を書き換えない。
- 末尾までスクロールした後に高さを大きくすると表示は上端まで詰まるが、小さく戻すと指定位置へ戻る。

### 追記: ピアノロールのアクセシビリティ要素（単位 3、JNK-04）

- 描画の通知は `submittedFrame` と `elements` の更新、`layoutChanged` の通知だけにする。
  要素は `accessibilityChildren()` の問い合わせ時に作り、同じ描画版では再利用する。
- 再利用する要素も、問い合わせのたびに画面座標・選択値・フォーカスを更新する。
  ウィンドウ移動や同じ描画版での選択変更が、古いフレームや `Selected` を残さない。
- フォーカスの通知に必要な要素だけは、フォーカスが変わった時に作る。
- `stop()` は通知済みのフォーカスを消去し、開き直した後の同じフォーカスへ再び通知する。
- 要素の組立てを `buildAccessibilityElement` に分け、画面座標の変換を閉包で受け取る。
  これによりウィンドウなしでラベル・操作・フレーム・生成回数を検査できる。
- 描画のたびに全要素を作り直す実装へ戻すと、生成回数の回帰が失敗する。

## 回帰と診断

- 必須契約 `canvas-resize-ui`: 製品の `ArrangeView`・`PianoGridView` と、`ArrangePaneView`・`PianoRollView` の中の同じ表示面で、
  `contentsAreFlipped()` に応じた `contentsGravity` を確認する。サイズ変更・ゼロ・端数の後も保つ。
  負の対照は 2 つ持つ。`layerContentsPlacement` を引き伸ばす配置へ戻す既存のものと、
  `wantsLayer` の後に `.topLeft` の上書きを戻すもの（JNK-01 の再現）である。
- 必須契約 `transport-layout-ui`（新規）: 待機中・変更適用中・再生準備中で状態行の高さが等しく、
  再生と一時停止でボタンの幅が等しいことを、画面なしの `NSHostingView` で確認する。
  負の対照は表示器を条件付きで挿入する形へ戻す。
- 必須契約 `arrange-camera-ui`（新規）: 末尾までスクロールした後、高さを大→小と往復し、
  指定の縦位置が保たれ、表示だけが高さで制限されることを確認する。
  横スクロール・横ズーム・表示中のトラック選択でも指定値が変わらない。負の対照は表示前に指定値へ制限を適用する。
- 必須契約 `arrange-camera-input-ui`（新規）: 高さを広げた後の上スクロールと縦ズームが表示中の行から始まることを確認する。
  負の対照はスクロールの起点を指定値へ戻す。
- 必須契約 `piano-accessibility-ui`（新規）: 描画通知だけでは要素を作らず、問い合わせ時に同じ要素を再利用し、
  ラベル・操作・フォーカス・フレームを返すことを確認する。負の対照は描画通知で全要素を作る呼出しを戻す。
- `docs/debugging.md` のペインのリサイズの節で、反転した階層の `bottomLeft`、再生開始時だけずれる場合の状態行、
  指定の縦位置と表示の制限値、アクセシビリティ要素の生成回数を区別する。

## 未確認

エディタ境界のドラッグとピアノロールの開閉で上下のずれが消えたか、再生開始時の見え方、
VoiceOver が状態行と再生ボタンを正しく読むかは、実画面のユーザー確認とする。
自動回帰はウィンドウ・表示リンク・機器を開かない。
