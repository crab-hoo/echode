# ADR 0133: ライブ停止中もプラグインを処理し、通常編集で画面全体を無効にしない

- 日付: 2026-10-21
- 状態: 採用。実機の聴感・第三者プラグイン・暗転解消の操作確認はユーザー担当
- 範囲: ライブ停止・一時停止、素材の停止フェード、停止中のプラグイン出力、編集順序と画面の排他

## 背景と再現

停止するとヘルパーを保持したまま `process` を送らなくなり、内部の時間が進まなかった。
停止時のリセットとマスター出力の減衰も、リリース・残響とプラグイン内の鍵盤の発音を止めていた。
2026-10-21 のユーザー回答で、ノートと素材の再生だけを止め、余韻とプラグイン内の鍵盤の音は出すと決めた。

実ヘルパーの回帰では、修正前に `stop reset a live plugin` と `stopped plugins were not processed` で失敗した。
音声デバイスと実ウィンドウは使っていない。手元のログは `target/stopped-processing-repro.log` にある。

デバイス操作の暗転は、`EditTurn` が編集順序の保持と同時に `ProjectController.busy` を立て、
各ビューが全体のボタンを無効にする経路だった。
実スライダーとバイパス・オフラインのボタンから `busy` の全遷移を観測すると、3 操作とも期待値で失敗した。
手元のログは `target/device-interaction-repro.log` にある。

## 決定

### トランスポートとライブ処理を分ける

- ライブ停止・一時停止は時計を保持し、現在のスコアのノートへ一度だけノートオフを送る。
  次のノート・素材・メトロノームは始めない。保持した CLAP の DSP はリセットしない。
- 再生中だった配置音声と準備済みキャッシュだけを、現在位置から最大 5 ms 継続して減衰する。
  減衰は音源への素材の合成・FX より前に置き、ループ境界と既存の素材フェードも守る。
  同じコールバックの残りは無音入力とし、プラグインには常にコールバック全体を処理させる。
  鳴りかけのメトロノームもその発音だけを減衰し、次の拍を始めない。
- その後も同じチェインへ無音入力を送り、出力をミキサーとメーターへ通す。
  音源のリリース、FX の残響、自発的な発音、プラグイン内の鍵盤の音をマスターで消音しない。
  一度も再生していない出力も同じ経路を使う。
- 保持した出力が開いている間は停止中も通常の処理負荷がかかる。
  バイパス・オフライン・削除の既存の寿命規則は変えない。
  文書を開くだけで出力を新規起動する変更ではない。
- 位置移動と未発音の再生準備の取消は、旧発音を消すリセットを維持する。
  破棄する後片付けは各ヘルパーへ独立に送り、ライブでは完了を待たずにポーリングする。
  その保留中に停止しても、素材の継続処理を始めてヘルパー待ちへ戻らない。
- オフライン再生器の停止と書き出しの終端は既存仕様を維持する。
  ライブ停止の新しい仕様を、オフラインの出力の長さや自然な終端へ混ぜない。

この決定は [ADR 0099](0099-transport-plugin-state.md) のライブ停止時の状態消去と、
[ADR 0103](0103-live-stop-waveform.md) のマスター停止減衰を置き換える。
[ADR 0105](0105-nonblocking-stop-cleanup.md) の非ブロック後片付けは位置移動と準備取消に残る。
停止位置と一時停止位置の分離は引き続き P2-07 の範囲である。

### 編集の直列化と画面の排他を分ける

- `EditTurn` は通常編集・状態記録・Undo / Redo の順序を引き続き保持する。
  通常の要求は `busy` を画面へ伝えず、パラメーター確定・バイパス・オフライン等で全体の有効状態を変えない。
- 文書の作成・交換・終了だけを明示的な排他要求にする。
  排他は受付時から終了まで維持し、複数要求が重なっても途中で解除しない。
- Undo / Redo の状態読込中は、その読込と競合するパラメーターのドラッグを `historyBusy` で制限する。
  デバイスの記録と他の編集を直列にする順序、文書・要求世代の照合は維持する。
- バイパス・オフライン・ピン留め・ミックス等の無変更の判定は、先の編集が反映された後の手番で行う。
  受付時の古い表示値で比較して、オンの反映待ちに押したオフを捨てない。
  先に受け付けた編集は、その後のフェーダー開始で取り消さない。
  フェーダーの終了も、その時点の記録値と比べて確定し、ドラッグ開始時の値へ戻す操作を取りこぼさない。
- 初回の出力・ヘルパー起動と、状態記録の手番を待つ後続編集は依然としてある。
  全ボタンの暗転を消すことと、すべての準備をワーカー外へ移すことを同一に扱わない。

## 検査と診断

- 必須契約 `stopped-plugin-tails` は楽器・FX・連鎖でノートオフ、停止中の余韻と自然な終端、時計保持を確認する。
  負の対照は停止中のノートオフを捨て、鳴りっぱなしの期待値で失敗させる。
- `stopped-plugin-output` は一度も再生していない時と停止後に、無入力で発音する実ヘルパーと後段 FX の出力を確認する。
  負の対照は停止中の処理を省略する。
- `transport-declick` は製品の出力バッファで素材の波形を比較する。負の対照は素材の減衰を外す。
  `block_size.rs` では素材・ループ・停止中の初回コールバックを複数のブロック長で照合する。
- `stop-cleanup` は位置移動のリセットを保留し、続く停止でも破棄する処理の完了を待たないことを確認する。
- `device-edit-enabled-ui` は実入力中の `busy` の遷移を観測する。完了時だけの検査では短い暗転を検出できない。
  負の対照は通常の要求も排他にする。編集順序と文書交換の排他は別の単体回帰で確認する。
- `stop_fade_offset` は素材側の減衰位置であり、マスター出力が 5 ms で無音になる印ではない。
  `playing = false` もプラグイン処理の停止を示さない。詳細な切り分けは [デバッグ手順](../debugging.md) に置く。
