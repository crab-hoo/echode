# ADR 0062: パッケージの書き手は一つにし、切れたジャーナル末尾は確定した改行まで戻す

- 日付: 2026-10-13
- 状態: 採用
- 範囲: パッケージの排他とジャーナルの障害。プラグインの再生経路は含まない

## 背景

同じパッケージを二つの `DocumentHost` で開くと、両方の編集が成功と返り、後から開いた側の編集は復旧で消えた（監査 AUD-01）。`flock` はプロセス単位なので、同一プロセスの二重オープンは別途断る。

切れたジャーナルは、読むときだけ末尾を捨て、ディスクには残していた。次の追記がその末尾に繋がると、確定した行まで壊れる。UTF-8 の途中で切れた末尾は、切り詰める前に文字列へ変換するので、最初の復旧も失敗した（AUD-02）。

ジャーナルの書き込みに失敗しても Session は戻らなかった。次に成功した操作が、失敗した操作ごと公開・保存された（AUD-03）。

## 決定

`DocumentHost::open` は、パスを正準化してから所有する。同一プロセスでは正準パスを記録し、他プロセスではパッケージ内の `host.lock` を排他ロックする。シンボリックリンクは同じパッケージとして拒否する。ロックはホストを落とすまで持つ。プロセスが強制終了すると、カーネルがロックを外す。

開くときと追記の前に、ジャーナルを最後の改行まで切り詰め、その長さを同期する。UTF-8 の確認は、その確定した部分だけに行う。改行の無い末尾は未完了として捨てる。

編集、Undo、Redo、トランザクションは、ジャーナルの同期が成功してから公開する。書き込みに失敗したら Session を操作の前へ戻し、公開スナップショットは変えない。同期の成否が分からないときは、そのホストでの追加編集を止め、開き直して復旧する。

## 結果

同一プロセス、別プロセス、シンボリックリンクからの二重オープンは拒否される。成功と返した編集は、強制終了のあとにも残る。ジャーナルの全バイト位置で切っても、確定した操作を復旧して次の編集を足せる。失敗した追記は次の操作に混ざらない。画面での操作確認は未実施である。
