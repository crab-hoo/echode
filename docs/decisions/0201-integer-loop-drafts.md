# 0201. ループの UI 下書きを整数で共有する

- 日付: 2026-10-30
- 状態: 採用
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-04 の残り
- 前提: [ADR 0200](0200-shared-model-units-and-limits.md) の共通単位と変換

## 背景と再現

両ルーラーの `LoopRange` は整数だが、controller は端点を `Double` の拍へ戻して保持していた。
`setLoopRange` → 下書き → `rulerLoop` / `transport.loop` の往復で整数の精度を失い得る。
開始 9,007,199,254,740,993、終端 9,007,199,254,740,995 tick を渡すと、異なる端点が同じ値へ丸まった。
機器を開かない製品 controller と音声セッションの回帰で、下書きの範囲と送信後の範囲の不一致を再現した。
これは整数の境界の再現であり、通常の制作位置で聴感上の問題を再現したものではない。

拍の入力欄も、表示用に丸めた文字列を再解析するだけでは元の整数を保証できない。
特に片端だけを入力した時、未変更の反対端まで丸め直してはならない。

## 決定

- `ProjectController.loopRange` は検証済みの整数 `LoopRange` を 1 つ保持する。
  両ルーラーの表示と音声要求はこの値をそのまま使い、送信直前の拍からの再変換をなくす。
- 初期範囲は `LoopRange.initial` の 0〜4 拍とし、開く・閉じる時も同じ値で初期化する。
  既存の範囲指定・片端調整・Shift・取消・送信順序は変えない。
- 拍の文字列は `LoopEntry` が入力境界だけで持つ。
  編集した欄だけを共通の `Tick.ticks` で一度整数化する。
  元の表示文字列と同じ欄は元の tick を返し、フォーカス移動やオンオフで失わない。
  手入力が不正・非有限・桁あふれ・負・ゼロ長・逆向きなら確定せず、入力中の文字は残す。
- オフ中の確定は下書きだけを変え、オン中は現在の順序待ち列から範囲を送る。
  不正な入力欄の確定で、以前の有効な下書きを音声へ再送しない。
- ループのオンオフ・範囲は従来どおり保存と Undo の外とし、再オープン時はオフで初期範囲へ戻す。
  モデル、保存形式、音声処理、既存の整数 ABI は変更しない。

## 回帰と基盤

- `LoopDraftTests` は精度外の整数端点を controller・拍入力・製品音声要求へ通す。
  オフ維持、オンオフ後の端点保持、開始位置・選択・Undo の不変、旧文書の拒否と再オープンを確認する。
- 通常回帰では片端だけの入力、三連符、不正文字・非有限・桁あふれ、ゼロ長、`Int64.max` の端点も確認する。
- 必須契約 `integer-loop-draft-ui` を既存の `check-product-contracts` へ登録する。
  整数から拍への往復と、未変更の左右欄の再解析を戻す 3 つの反例を持つ。
  選択の回帰は既存の検査で扱い、新しい Makefile の検査種別は作らない。
- デバッグ手順へ下書きと入力欄の照合先を追加する。
  ログ・外部入力形式・収集先は変わらず、診断スクリプトの変更は不要である。

## 未確認と境界

実画面のフォーカス移動・表示・VoiceOver と、実機のループの聴感はユーザー担当である。
自動検査は機器とウィンドウを開かず、描画の画素と実機性能の検査とは区別する。
既存の全時刻フィールドを `Tick` 値型に包む変更や、文書スコープの全体整理は含めない。
