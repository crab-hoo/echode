# 0035. 再生計画は制御スレッドが作り、オーディオスレッドはカーソルだけ進める

- 日付: 2026-10-09
- 状態: 採用
- 項目: ENG-1

## 背景

`schedule` は、ブロックのたびに全トラックの全ノートを見て、tick からサンプルへの変換をノートごとに 2 回行う。変換はテンポマップを先頭から辿り、区間を重ねて辿り直すので、テンポの点の数の 2 乗に比例する。128 フレーム・48 kHz では、100 トラックで 1 万ノートなら 311 µs、10 万ノートなら 3,117 µs だった。PLAN §1.0 の基準は、エンジン全体で 1 ブロック 266.7 µs である。テンポの点が 64 あると、1 万ノートで 809 µs だった。

オーディオスレッドは `Project` や `Arc<Track>` を直接読む。オーディオクリップも、`render_audio_clips` がサンプルごとにすべてのクリップを調べる。

再生位置はサンプルで、テンポは flick を一度だけ丸める。ループで飛んだときは、まだ鳴っているノートを着地の最初のフレームで止める（[ADR 0010](0010-playback-samples.md)）。クリップの範囲の外は鳴らさず、範囲をまたぐノートは範囲の端で切る（[ADR 0025](0025-clip-window-cuts-notes.md)）。計画の差し替えと、古い計画の解放は、この項目では決めない（ENG-3）。

シーク位置は計画を作るときには決まっていない。全サンプルの鳴っている集合を計画に持つことはできない。イベント列の途中へカーソルだけ置くと、ノートオンを見ずにノートオフだけを処理し、鳴っている集合から無いノートを消そうとする。トラックごとにバッファへ順に足すと、トラックをまたぐイベントの時刻順が崩れる。1 ブロックが隣り合うクリップの境界をまたぐときは、区間は 1 回では決まらない。

## 決定

- 計画は制御スレッドが作る。作り直すのは、公開するスナップショット、サンプルレート、ループ範囲のどれかが変わったときだけである。ブロックごとには作らない。オフラインの書き出しも、書き出しの最初に 1 回作る
- テンポは、各境界までの累積 flick をそのときに 1 回だけ計算し、点を tick で二分探索できる列にする。ノートのサンプル位置は、この列で今の `tick_to_sample` と同じ丸めにする。メトロノームも、呼び出しごとにこの列を 1 回作り、拍の数だけ変換する
- トラックごとに、鳴るノートの開始と終了をサンプル位置で持つ。範囲は `Placement::audible` で切ってから変換する。範囲の外のノートは計画に入れない。ベロシティは、今のイベントと同じく MIDI の 0〜127 にしておく。開始で並べた列と、終了で並べた添字を持つ
- 鳴っている集合は計画に入れない。位置が決まってから `place` が、開始列と終了列を二分探索し、開始がそこより前で終了がそこ以降のノートだけを集める。タイムラインの全サンプルは持たない。バッファは制御スレッドがノート数まで確保し、オーディオスレッドは印を書き換えるだけで伸ばさない
- 順方向のブロックは、そのカーソルからイベントを読む。ノートオフは、鳴っている集合に入っているノートだけ出す。途中へシークしたノートは `place` が先に集合へ入れるので、ノートオフが孤立しない。ループで戻るときは、今鳴っているノートを着地の最初のフレームで止めてから、追わないでカーソルを置き直す（ADR 0010）。そのあとのノートオンは、範囲に入ったものだけ打つ
- ブロックに集めたイベントは、出す前に、サンプル、ノートオフがノートオンより前、トラックの ID、音高、ノートの ID の順で並べる。今の `schedule` と同じである。トラックごとの列を、並べずにバッファへ足すことはしない
- オーディオクリップは、ブロックの開始以降で重なる区間を順に切り替える。1 ブロックが境界をまたぐときは、またいだ先のクリップも同じブロックで足す。サンプルごとに全クリップは調べない
- これらの型と、ブロックを埋める関数は、新しい crate `echode-realtime` に置く。`echode-model` に依存しない。ID は `u128` で持つ。この crate では `Vec::push`、`Vec::reserve`、`Box::new`、`Mutex::new`、`RwLock::new` を clippy で禁じる。計画を組み立てるコードは `echode-engine` に残し、ここでは確保してよい
- イベントとサンプルのバッファは、今どおり呼び出し側が渡す。計画の共有と、古い計画をいつ解放するかは ENG-3 が決める。オーディオスレッドは計画を解放しない

## 結果

`make check` が通った。孤立したスパンでも、ノートの途中ならノートオフが 1 回だけ出る。ループの戻りはノートオフがノートオンより先である。2 トラックのイベントは、サンプル順かつノートオフが先になる。1 ブロックが隣り合うオーディオクリップの境界をまたいでも、両方の音が入る。10 万ノートの 128 フレームは release で 15 µs であり、266.7 µs を十分に下回る。
