# ADR 0350: 読めない履歴を空の履歴として開かない

- 日付: 2026-11-14
- 状態: 現行
- 領域: モデル・履歴・保存・API
- 関連: [IQA-01・02](../reviews/2026-11-13-implementation-quality-audit.md)、
  [ADR 0230](0230-save-durability.md)、[ADR 0297](0297-typed-autosave-and-git-errors.md)

## 背景と再現

開始時は `e796850`。`autosave_tip` は Git のオープン・参照の読込みの失敗を `None` に畳んでいた。
`DocumentHost::open` はそれを未保存の文書と扱い、同期していない作業ツリーから新しい履歴を作る。
`open_or_init` も既存リポジトリのオープン失敗を初期化へ渡し、元の原因を隠していた。

製品の `DocumentHost` を使う既存の監査再現を、変更前に個別実行した。
終了コード 101 と、各再現固有のアサーションを `checked_commands.py` で照合した。

- IQA-01: 2 トラックを確定した後、作業ツリーを 1 トラックへ戻し、参照を空にすると、
  `opened ["first"] without a notice` で失敗した。
- IQA-02: 既存の `.git/config` を壊すと、`the open failure is reported as an initialization` と `Init` で失敗した。

元の証拠は監査に残し、再現ログは `target/focused-checks/iqa-recovery-red/` と
`target/focused-checks/iqa-repository-red/` にある。

## 比べた案と決定

1. **参照が読めなくてもチェーンの最後の行を採用し、参照を自動で作り直す。**
   編集を取り戻してそのまま使えるが、読める参照との親子の照合がなくなり、
   壊れた参照・チェーンの扱いと書換えの新しい信頼境界が要る。
   参照が読めても古い場合に限る ADR 0230 の経路とは分けて設計する必要がある。
2. **読込みの失敗では開かず、元の原因と原本を保つ。採用。**
   作業ツリーへの後退と親なしの自動保存を止める。
   既存の型付きエラーとオープン拒否を使い、新しい復旧・修復の状態を増やさない。
   自動修復よりデータの保全と構造の単純さを優先した。

`open_repository` を復旧と自動保存で共有する。
パッケージの記述子から `.git` の存在・種類を調べ、無い時だけ `None` を返す。
在るのに開けない時は `GitOperation::Open` と元の `gix::Error` を返し、初期化しない。

`autosave_tip` は `Result<Option<ObjectId>>` を返す。
参照の読込みの失敗は `GitOperation::FindReference`、シンボリック参照は
`DocumentError::SymbolicAutosaveReference` として拒否し、`id()` の panic にも進まない。
参照が無くてもチェーンが在るなら `MissingAutosaveReference`、チェーンの種類を読めなければパス付き I/O エラーで拒否する。
この判定はチェーンの存在だけを調べ、内容の全走査を加えない。

次のジャーナルの番号も文書を公開する前に決め、履歴の読込みの失敗を番号 1 へ畳まない。
読めないコミットからの既存の同意付き後退では、復旧済みの番号を引き続き下限にする。
自動保存ワーカーの起動時も同じ先端の判定を使い、失敗を全要求へ共有し、終了要求で抜ける。
初回の保存が必要かも復旧結果の基点から決め、自動保存スレッドの起動後に未完成の Git を再照会しない。

## 回帰と基盤

`tests/audit_quality.rs` の IQA-01・02 の無視を外し、安全な拒否を検査する形へ強めた。
空・不正・欠落・シンボリック参照、読めない設定、欠落参照と不正なチェーン、
`save.pending` の有無、未保存パッケージと未保存の Git リポジトリを扱う。
復旧・製品オープン・自動保存の読込みと保存要求を通し、拒否前後の全ファイルのバイトを比較する。
テストが注入した破損だけを戻すと、確定した 2 トラックと履歴件数がそのまま開くことも検査する。

既存の `audit_durability`・`audit_recovery` は、参照の遅れ、読めないコミット、同意とジャーナルの境界を引き続き通す。
`autosave_errors` は既存の Git が開けない場合の操作を `Open` へ改め、元の原因の共有を検査する。
起動失敗の終了待ちの必須契約には、文書が早期に拒否する前に自動保存ワーカー自体の失敗と破棄を通す経路を残す。
新規文書の並行オープンの回帰も加えた。
最初の `make verify` では、プロセスロックの回帰が子の `holding` 通知前の終了で失敗した。
単独実行と並行オープンの再現では同じ失敗は出ず、当時の子の stderr は捨てられていたため、原因を断定しない。
再調査で上記の初期化中の再照会を除き、同回帰は早期終了時に子の終了コードと stderr を残すようにした。

設計の正本と保存・復旧のデバッグ手順、監査の現在の状態を更新する。
既存の履歴領域・通常テストと必須契約で選ばれるため、検査の入口・選択条件は追加しない。
新しい外部入力や保存形式もなく、fuzz の対象は変更しない。
性能の変更を目的とせず、実機・電源断の計測はしていない。

## 残る制約

- 読めない・欠落した参照の自動修復はしない。原本を保全した上で調べる。
- 参照もチェーンも存在しない状態は、未保存の Git リポジトリと区別しない。
  `.git` 全体を消した場合の履歴を復元する機能でもない。
- オープンの詳細な原因を Swift へ渡す変更は IQA-03 に残る。
  ADR 0121 の過去の初期化失敗の実際の原因も、この再現で確定したとは扱わない。
- 従来の同意付きの後退と参照の遅れからの復旧、同期の順序、保存スキーマ、C ABI は変えない。
