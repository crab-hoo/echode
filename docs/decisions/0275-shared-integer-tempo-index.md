# ADR 0275: モデルと再生で共有する整数時間とテンポ索引

- 日付: 2026-11-06
- 状態: 採用（FCA-13。実機・聴感は UC-62）

## 背景と再現

[全体監査の FCA-13](../reviews/2026-11-03-full-code-audit.md#fca-13-時間の換算の重複) は、4 か所の丸めとモデル・計画のテンポ点の再探索を指摘した。
モデルの積分は区間ごとに先頭から探し、再生計画も全境界で同じ探索を繰り返していた。
同じテンポマップでも、モデルの問合せは二乗、再生カーソルだけは二分探索という差があった。

製品の `plan::tempo_tests::audit_fca13_playback_and_model_agree_before_and_after_zero` を先に追加した。
原点前の点を含む計画は境界を 0、負、0 の順に作っており、8 kHz、tick -79,760 で再生は -452、モデルは -396 サンプルになった。
期待終了コード 101 と、この回帰固有の `FCA-13 playback/model tick mismatch` を照合して red を確認した。
監査当時の「今は一致する」という観察は保持し、今回確認した範囲の不一致を別に記録する。

## 決定と選ばなかった案

外部ライブラリに依存しない `echode-time` に、整数の単位・丸め・分数テンポの換算・累積索引を置く。
新しい DSP や積分近似の開発ではなく、既存の区間積分と二分探索を一つの実装へ移す。
モデルの型・Serde・スキーマをこの crate に移す案は、保存とリアルタイムの依存を混ぜるので採らない。
`echode-realtime` からモデルへ依存させる案も、音声カーソルを文書モデルから独立させる境界を崩すので採らない。

- 丸めは最近接、ちょうど半分はゼロから遠い整数。各テンポ区間を flick に丸め、最後にサンプルへ丸める。
- 負の tick の順変換は従来のモデルと同じく `[tick, 0]` の積分の符号を反転する。
  区間内部は右端の累積値から残りを引く。左端からの差分では 1 flick ずれ得る。
- 逆変換は既存モデルの各区間の左端基準を保つ。原点も最初の点も入力の意味を変えない。
- 索引は点を検証・整列した制御側で O(T) で作り、原点の前後へ一度ずつ累積する。
  原点の点がなければ索引だけに合成し、先頭のテンポはそれより前にも適用する。
- `TempoMap` は元の点と索引を不変の共有領域で持ち、再生計画は索引を `Arc` で複製する。
  毎計画での O(T²) の積分をなくし、tick / flick / sample の問合せは O(log T) にする。
- 不正な空・重複・逆順・分数の索引は構築時に拒否する。整数の桁あふれは `None` で返す。
- Workgroup のブロック期間の整数式も共通化する。製品の範囲外拒否とスパイクの飽和は呼出し側に残す。

点を変更するたびに索引全体を作る方式を選ぶ。
テンポ点の局所的な累積更新は、すべての後続時刻が変わるため、差分の管理を増やす割に今回の探索の問題を改善しない。
読み取りだけの索引なので、音声側に確保・ロック・I/O・待機は加えない。

## 互換性と検査・診断

元のテンポ点だけを従来どおり保存し、合成する原点と索引は保存・ジャーナルの対象にしない。
スキーマ・C ABI・モデルの整数単位は変えない。モデルの定数と realtime の索引型は旧パスから再公開する。
モデルの flick の公開値は i64、再生内部は従来どおり i128 であり、表現範囲外の拒否まで同一とはしない。

- 共通 crate の独立した旧モデル計算で、原点なし・負の点・分数・境界の前後の丸めを照合する。
- 16〜4,096 点での境界訪問数を制限し、索引の複製が同じ共有領域を保持することを固定する。
  実時間の性能計測ではなく、アルゴリズムの仕事量の回帰である。
- engine の製品計画とモデルの両方向換算を、8〜192 kHz で比較する。
- `block_size/tempo.rs` は原点前からの製品メトロノームを複数のブロック長で比較し、RTSan の対象にもする。
- 通常の workspace 検査で実行する。新しい検査ターゲットは作らず、検査選択の領域に共通 crate を登録して選択の回帰を足す。
- 診断は [原点前のテンポ点の切分け](../debugging/audio-and-plugins.md#原点前のテンポ点で表示と再生位置がずれるテンポ点の数で換算が遅くなる) を使う。
  ログ形式・証拠の収集先は増やさない。

2026-11-06 の最終 `make verify` は、製品契約の実行と結果保存で `Errno 28` になり中断した。
中断時点では自動検査の全選択項目が未確認であり、空き容量確保後の再実行を要した。
同日にユーザーが `target/debug/incremental` の整理に同意した。既存の成果物と検査記録を保持し、整理後の再実行で選択された自動検査を完了した。
実機・聴感と全体検査はこの再実行の保証に含めない。現在の入力に対する合否は検査レポートを正本とする。

実機・聴感は自動回帰の保証に含めない。新しい確認待ちは [UC-62](../user-checks.md) に置く。
