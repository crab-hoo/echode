# ADR 0080: ヘルパーの音声処理では確保しない

- 日付: 2026-10-14
- 状態: 採用
- 範囲: 監査 PRO-08。ヘルパーの処理スレッド

## 背景

処理スレッドは、ブロックごとにポートの配列を作り、共有領域が伸びると自分でベクタを伸ばし、再起動では止めたプロセッサを `Box` で渡していた。領域の交換では、処理側がロックを取り続けた。確保の検出と RTSan は本体だけで、ヘルパーのこの処理を見ていなかった。ADR 0049 は、バッファを処理スレッドの開始時に一度確保すると定めている。

## 決定

ポートの並びは、開始時に確保したチャンネルのポインタから、標準ライブラリのイテレータで見せる。ブロックごとには配列を作らない。

フレーム数やイベント数が増えるときは、制御スレッドが新しいバッファを用意してから共有領域を渡す。処理スレッドはポインタを入れ替えるだけで、古いバッファは制御スレッドが回収する。入れ替えはロックを一度だけ試し、取れなければ待たずに譲る。前の領域がまだ残っているときは、新しい領域を戻し、処理側では解放しない。

再起動で止めたプロセッサは、確保済みの枠へ書く。処理スレッドは `Box` を作らず、捨てない。

デバッグのヘルパーは、処理の区間で確保か解放があればプロセスを止める。RTSan も同じ区間を見る。初回の処理、容量を増やしたあとの処理、再起動のあとの処理を検査する。自分を起こすためのシステムコールと、`SIGABRT` のハンドラを入れるシステムコールは、その区間の外に置く。

## 結果

冷えた初回、イベント容量の拡張、プロセッサの再起動は、ヘルパーが生きたまま音を返す。容量を増やしたあとも、ノートは欠けない。
