# 0019. オフラインの書き出しはテスト用シンセで WAV にする

- 日付: 2026-10-08
- 状態: 採用

## 背景

Phase 1 の完了条件には、同じプロジェクトを CLI で WAV にすると基準のファイルと一致することがある（PLAN、ARCHITECTURE §16）。音を出す内蔵デバイスは wavesynth の Sine Pad になった（[0018](0018-test-synth.md)）。

## 決定

- `render_offline` は、プロジェクトを先頭から指定フレーム数だけ、トラックごとに Sine Pad で鳴らしてステレオに足す。フェーダーはユニティで中央
- フレーム数を省略したときの長さは、最後のノートの終わりに Sine Pad のリリース 0.4 秒を足したもの。音声クリップだけのときは、そのクリップの終わりで、リリースは足さない（[ADR 0057](0057-crash-recovery.md)）
- 置いた音声は、製品の再生と同じ読み込みでデバイスレートへ変換し、シンセのあとに足してからフェーダーを通す。ループとメトロノームは書き出しに含めない。ノートだけの基準 WAV は変えない
- 1 ブロックの作業バッファは 64 フレーム。これは書き出し全体の長さの上限ではない
- WAV は 32bit 浮動小数点、ステレオ、余分なチャンクなし。データが 4 GiB を超えるファイルは、この書き出しでは出さない
- サンプルはレンダーのブロックごとに `BufWriter` へ書く。書き出し全体を一度にメモリへ置かない
- コマンドは `echode render PACKAGE WAV [--sample-rate 48000] [--frames N]`
- 基準は `crates/echode-cli/tests/fixtures/sine-pad-a4-128.wav`（A4、ベロシティ 127、128 フレーム、48 kHz）。意図して音を変えた時は `make bless REASON="理由"` で作り直し、理由を `tests/fixtures/bless.log` に残す

## 結果

CLI の書き出しが、その基準の WAV とバイト列で一致することをテストで確かめる。60 秒のステレオ（無音、5,760,000 サンプル）は、リリースビルドで 0.02 秒、デバッグビルドで 0.5 秒未満だった（どちらもバッファを 0 で埋める時間を含む）。1 サンプルずつ書いた時は 15.3 秒だった。
