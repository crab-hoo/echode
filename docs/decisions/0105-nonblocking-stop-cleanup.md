# ADR 0105: 停止後の破棄する処理を音声の期限で待たない

- 日付: 2026-10-16
- 状態: 採用。修正版の聴感はユーザー確認待ち。
  2026-11-03 追記: 2026-10-17 に停止・発音の聴感の受入を受領した（[Phase 1 の最終照合](../reviews/2026-10-17-phase1-acceptance.md)）。当時の記録は変えない。
- 後続仕様: [ADR 0133](0133-stopped-plugin-processing-and-edit-input.md) でライブ停止のリセットを廃止した。非ブロック後片付けは位置移動と準備取消に残る。
- 範囲: ライブ停止後のヘルパーの後片付け、途中の再開・計画交換、診断。

## 実出力で見つかった別の原因

ユーザーが ADR 0104 の診断版で再現し、7回の停止記録を取得した。同じビルドの識別値で、96 kHz・512フレーム、1ブロック約5.333 msだった。減衰するブロックの処理は約0.538〜0.708 ms。その次の破棄する処理だけが約5.297〜5.331 msを使い、診断コピーを含むと6回が周期を超えた。7回すべてで、その次のコールバックまで約11.132〜11.674 ms空いた。HALの出力ホスト時刻にも約2.1周期の間隔が記録された。

機器変更、不正なバッファ、音声側の致命的エラーは記録されず、プラグイン失敗の累積も停止前後で1のままだった。後片付けの失敗をこの累積へ加算していなかったため、以前の失敗数だけではこの経路を判別できなかった。

元の記録は `target/stop-diagnostics/captures/stop-1792111568787641000-88739-0.json` から末尾 `-6.json` の7組。集計と入力のSHA-256は `target/noise-audit/stop-capture-analysis.json` に保持する。ユーザーの音を含むPCMは既定の診断共有へ自動で含めない。

コードでは、減衰完了後に `Prepared::flush_releases` が全長の無音ブロックを送り、その出力を捨てるにもかかわらず `HostGraph::collect` でヘルパーのリセットと処理完了を待っていた。この待ちで音声の期限を消費していた。減衰を再調整する問題とは区別する。

## 待機しない後片付け

ライブ停止後は、リセット・MIDI全発音停止・既存ノートのノートオフを、全ステージへ独立に送る。出力は破棄するため、前段のPCMが完成するのを後段が待つ必要はない。CLAPの有効な最小長である1フレームの無音を使う。これは後片付けの処理単位であり、機器バッファ・トラック・チャンネルの上限ではない。

各ステージは未投入・処理中・完了を持つ。共有メモリの空きがなければ命令を保持し、以後のコールバックで投入と完了を一度ずつ調べる。ライブの音声側は後片付けのための待機を行わない。同じ後片付け中の追加の停止・位置移動は一つへまとめる。旧計画を完了前に交換せず、旧領域・イベント・設定値の所有権を保持する。

再生が先に要求されても、完了までは新しいノートを送らず、時計を進めない。セッション側の再生意図は保持し、音声側の `playing` は完了までfalseにする。完了後に新しい波形の出力世代を更新して再開する。既存の音源とエフェクトの旧音を持ち越さない回帰は、保留中の無音だけで合格にせず、実際に再開して時計が進んだ後も確認する。

既に破損したヘルパーは失敗として扱う。後片付けが5秒進まなければ要求を破棄し、制御側へ再起動を要求する。これはライフサイクルの監視期限で、音声スレッドが5秒待つものではない。実際の失敗は `plugin_missed_blocks` へ加える。単なる処理中は失敗にしない。ライブ用に保留した再生器をオフライン側から使う場合は、従来と同じ有界の完了待ちができる。通常のオフライン停止のノートオフ配送は維持する。

## 回帰と診断

`contract_live_stop_cleanup_never_waits_for_a_reset` は別プロセスのテスト音源2個のリセットをソケットで保留する。親のコールバックが戻ってからのみ保留を解除する。修正前は破棄する処理が期限切れとなり、`discarded cleanup waited for a helper` の期待値で失敗した。修正後は保留中に両方へ命令を送り、無音と時計の保持、未発音の再生状態、解除後の再開を確認する。

故障注入音源だけが意図的にリセットをブロックする。音声デバイスは開かず、時間の性能閾値で判定しない。テストの期限はハング検出のガードで、保留解除後に合成コールバックを駆動するテストスレッドだけが短く待つ。音声処理側に待ちを入れるものではない。通常の音源・楽器・エフェクト連鎖での後片付けと旧音の排除はRTSanでも確認する。

必須契約 `stop-cleanup` を既存の製品契約検査へ追加する。ライブ側へ期限付きの完了待ちを戻す負の対照は、同じ期待値で失敗しなければならない。テストの削除・無視・0件実行やコンパイル失敗では代用しない。

停止出力の診断に `cleanup_pending` を追加する。処理中は呼び出しごとの投入・完了ポーリングだけが行われる。過去の記録にこの項目がないことを、後片付けがなかった証拠へ変えない。波形、呼出間隔、`render_ns` と診断を含む `elapsed_ns`、実際の失敗数を引き続き照合する。
