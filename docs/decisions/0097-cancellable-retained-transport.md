# ADR 0097: 再生準備の取消と出力の再利用

- 日付: 2026-10-15
- 状態: 採用
- 範囲: 製品 UI、文書キュー、CoreAudio セッション、再生器。ADR 0047 の停止時の出力寿命を更新する。

## 背景

再生準備の間、`audioBusy` が再生・停止ボタンとコマンドの両方を無効にしていた。ガードを外すだけでも、停止は素材読込やプラグイン起動の後ろで待つため、遅れて音が出る。さらに停止と一時停止は毎回 HAL とヘルパーを破棄し、次の再生で全体を準備していた。意図した先行バッファではなく、準備と操作の扱いの問題である。

## 決定

- 文書の投入キューと同じ順序で取消世代を取る。停止・一時停止は投入時点で世代を進める。古い再生は実行前に捨て、準備中だった場合もコールバックが世代を比較して無音にする。音声スレッドにロック、確保、I/O は加えない。
- 取消後も再生器は操作と準備済み計画を受け取るが、時計を進めず出力を無音にする。停止中の編集を詰まらせない。提出直前にも世代を確認し、描画中に届いた停止を扱う。
- 停止と一時停止は位置を保持し、素材・CLAP ヘルパー・HAL を再利用する。停止中の HAL コールバックは継続する。文書の終了、機器の再設定、エラーでは従来どおり制御側で閉じる。再生前の文書編集だけでは機器を開かない。
- UI は未完了の意図を保持し、準備中も停止と Space の切替を受ける。古い応答や先行する状態ポーリングで新しい停止を上書きしない。準備中の表示を出す。出力設定等の別操作は引き続き待つ。
- 停止中の位置移動は、音声側で反映した操作の連番まで、要求した位置を公開する。受理直後に古い位置を返すことと、実際のコールバックの反映を混同しない。同じコールバックが後続の再生も受け取った場合と連番の周回を扱う。

初回の素材読込・サードパーティープラグインの初期化自体は残る。停止はその処理の強制終了ではなく、後から発音しないことを保証する。ヘルパーの起動や I/O の完了通知は制御側から遅れて返る場合がある。機器変更後は再準備が必要になる。

## 検証

通常の必須契約に、遅延応答中の停止・Space、投入直後の取消、準備中の取消と初回・再開後の HAL バッファを加える。誤りを戻したコピーが期待値で失敗することも要求する。停止中に32回の計画交換を行う検査はブロック長1・7・64・512で位置保持とミュートを確認する。RTSan は取消側の経路も実行する。保持した出力の位置移動は、コールバック前と後続操作をまとめて受け取った後を検査する。

`spike-audio` は素材ローダーの呼出回数が再開時に増えないこと、停止中の位置保持、再開後の進行を実機で確認する。2026-10-15 の無音・プラグインなしの事前測定は、初回準備92.4 ms、保持した再開操作の投入1.1〜1.4 µsだった。後者は発音までの時間ではない。発音の最短時間は次の出力ブロックにも依存する。記録は `target/verification/audio-transport-preflight.log`、最終ソースの結果は通常の検査レポートを使う。

## 発音状態の不足への対応（2026-10-15）

本判断の出力保持だけでは、ノートオフ後に残るプラグイン内部の音を消せなかった。[ADR 0099](0099-transport-plugin-state.md) で停止・位置移動の処理状態と互換性の境界を補った。停止中の無音や再開の速さの検査だけで、再開後の旧音が消えているとは判断しない。

## 2026-10-16 の停止境界の改訂

[ADR 0103](0103-live-stop-waveform.md) により、既に音が出ている場合は処理中のブロックを完了し、次の境界から保持した波形を5 ms以内に減衰する。初回提出前の取消は引き続き初回から無音とし、位置も進めない。描画途中の0への差し替えを、既発音にも適用してクリックを生むことを避ける。
