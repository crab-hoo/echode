# 0024. トラックの並びは兄弟ごとの分数インデックスで持つ

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-3

## 背景

ADR 0017 は、フォルダを親の ID で表し、子は親の直後からその子孫のうしろまでに並ぶとしている。同時に「親を変えても並べ替えはしない」とした。`set_parent` は配列の位置を変えないので、[A, a1, B] で A の親を B にすると、子の A が親の B より前に残る。読み込みもその並びを拒否しない。

ARCHITECTURE §4.3 と PLAN §5 は、並び順を分数インデックスで持つとしている。整数の位置を振り直すと、挿入位置より後ろの兄弟のキーが全部変わる。分数インデックスなら、動かしたトラックのキーだけで間に入れる。

デバイスの並びは、デバイスがモデルに無いので、この項目では持たない。

## 調査

分数インデックスの実装を、自作する前に見た。

- `fractional_index` 2.0.2（MIT）。`FractionalIndex::to_string` の文字列は、その値の辞書順と一致する。`new_before` と `new_after` は常に作れ、異なる 2 つの間の `new_between` も、順序が逆か同じ値のとき以外は作れる
- `lexorank` 2.0.0（ISC）。同じ種類のキーを作れる。`regex` と `lazy_static` に依存する

辞書順の文字列で足せて、監査が名指ししている `fractional_index` を使う。非推奨の `ZenoIndex` は使わない。

## 決定

- 各トラックは、同じ親を持つ兄弟の間の順序として `order` を持つ。最上位は親の無いトラック同士で 1 つの兄弟グループになる。値は `FractionalIndex::to_string()` の文字列である。別の親の下では、同じ文字列でもよい
- メモリ上のトラック配列と、`project.json` の `tracks` は、アレンジ画面の順である。これは保存の正本ではなく、次の順に木から作る。親の無いトラックを `order` の辞書順に並べ、各トラックの直後に、その直接の子を同じ規則で再帰せずにたどった部分木を続ける。子は親の直後に連続し、その間に入るのはその親の子孫だけになる
- 同じ親の下で `order` は重複しない。これで兄弟の順は ID を見なくても一意になる
- キーの割り当て
  - 最上位のトラックを足すときは、最上位の末尾の兄弟の `new_after` とする。兄弟が無ければ `FractionalIndex::default` とする
  - 子を足すときは、その親の直接の子の末尾に同じ規則で置く
  - `set_parent` は、移動先の直接の子の末尾に置く。親が変わらないときは、キーも配列も変えない。循環と欠けた親は今どおり拒否する
  - 子孫の親と `order` は変えない。部分木はまとまって動く
- 同じ親の中で、末尾以外の位置へ差し込むコマンドは足さない。キーの形は、後から `new_between` で 1 つのキーだけを変えて差し込めるようにしておく。その操作はドラッグの表現（MOD-13）まで持たない
- 変更の記録では、プロジェクト全体のトラック ID 配列（`track_order`）を出さない。変わるのは、動かしたトラックの `order` と、親を変えたときはその `parent` だけである。作成は、そのトラックの `order` を含む。適用は記録されたキーを戻したあと、上の規則で配列を作り直す。配列の記録からは戻さない
- 読み込みは並べ直さない。`order` が `FractionalIndex::from_string` で読めないとき、同じ親の下で重複しているとき、または渡された配列が上の規則の順と違うときは、`ModelError::BadOrder` で拒否する。`check_invariants` は同じ規則を見て、最初に崩れているトラックを言葉で報告する
- スキーマ番号は 1 のままである。トラックの JSON に `order` を足す。このリポジトリに、このフィールドの無いパッケージもジャーナルも無い
- 採用したら ADR 0017 の「親を変えても並べ替えはしない」を、この決定に置き換える

## 結果

`make check` が通った。`fractional_index` 2.0.2 を依存に足した。[A, a1, B] で A の親を B にすると、並びは B、A、a1 になる。他のトラックの `order` は変わらない。この例では移動先に兄弟が無く、A は移動前も先頭のキーなので文字列は同じままになり、差分に残るのは `parent` だけである。移動先に兄弟がいるときは、新しい文字列になるのも A の `order` だけである。`check_invariants` と DEV-5 のランダムな操作列は、どの `set_parent` のあとでも子が親の直後に連続することを確かめる。順の違う配列、読めないキー、同じ親の下で重複したキーは読み込みが拒否する。
