# 0382. 音声ポートの変更を、共有領域と親のルーティングの交換として接続する

- 日付: 2026-11-16
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: F2・FCA-07・P2-03 の `clap.audio-ports`
- 一部置換: [ADR 0374](0374-dimension-preserving-audio-port-rescans.md) の、ポート数・チャンネル数・ID の変更を検出したらヘルパーを停止する判断

## 背景

ADR 0374 は、再有効化前に読み直したポートが初回と違えばヘルパーを停止した。
再起動は初回の共有領域・ヘルパーのバッファ・親のルーティングを交換しないため、変更を受ければ別の形のバッファで処理するからである。
モノとステレオの切替やサイドチェイン入力の追加のように、状態や設定でポートを変えるプラグインは多い。
状態がポートを変える場合、記録した状態の復元だけでヘルパーが止まった。

## 比べた案

- **ヘルパーを作り直す**（`PluginHost::restart`）: 不採用。
  新しいヘルパーは既定の構成で起動し、状態を復元すると同じ変更が起きる。起動と状態の往復も増える。
- **ヘルパーが最新のポートでバッファを作り、親は合計チャンネル数だけを合わせる**: 不採用。
  `[2]` から `[1, 1]` のように境界だけが変わると、合計数は同じで親の主ポートの解釈と食い違い、意図しないチャンネルが接続される。
  変更が続くと、親の知らない形のバッファで処理される。
- **ヘルパー内で古い寸法へ切り詰め・ゼロ補完する**: 不採用（ADR 0374 と同じ）。不一致を隠す。
- **共有領域をポートの構成ごとに作り、一致する時だけ処理する**: 採用。
  親が共有領域をどのポートのために作ったかを宣言し、ヘルパーはそのポートでバッファを作る。
  プラグインを有効化したポートと共有領域のポートが一致するブロックだけを処理する。
  親は変更の通知を受けて計画を準備し直し、共有領域とルーティングを同じ計画で交換する。

## 決定

入出力ポートごとのチャンネル数を `echode-sandbox` の `PortLayout` とし、両プロセスで共有する。
不変条件は「処理器を有効化したポート、ヘルパーのバッファのポート、親のルーティングのポートが、同じ共有領域で一致する」である。

- **ヘルパー**: 有効化ごとに無効化後のポートを読み、`NoteInputs` と同じく処理器と一緒に渡す。
  `Remap` はレイアウトの後にポートを運ぶ。ヘルパーはそのポートでバッファを作り、レイアウトがちょうど保持しない時は拒否する。
  最初のバッファを作る前は、告知したポートの共有領域だけを受ける。
  音声スレッドは処理器とバッファのポートを比べ、違うブロックは出力を無音にしてイベントも捨てる。比較はスライスの比較で、確保・ロックをしない。
  有効化でポートが変われば `PortsChanged` を送る。再起動では完了通知より先に送る。再起動以外の有効化でも同じ確認で送る。
- **親の制御**: `PluginControl` は最新のポートと改訂番号を保持する。改訂は値が変わった時だけ増え、元の値へ戻る変更も数える。
  `PluginHost` は今の共有領域のポートを持ち、`prepare_mapping_for` で別のポートの共有領域を準備する。取消すと前のポートへ戻る。
  単独の利用者には、最新のポートへ同期で切り替える `follow_ports` を置く。
- **エンジン**: 改訂の違いを、遅延・余韻と同じ報告の違いとして扱い、計画を準備し直す。
  保持するデバイスのルーティング（平面数・主ポートの数）を最新のポートで作り直し、チェインを検証してから同じポートの共有領域を準備する。
  失敗時はルーティングを戻し、準備した共有領域を取り消す（既存の取消の経路）。
  前のポートの共有領域がコールバックの採用を待つ間は、`can_reconcile` が計画を保留する。
  コールバックは計画の採用で、共有領域とルーティングを同時に切り替える。`audio_snapshot` は両者の一致をデバッグビルドで確かめる。
  ルーティングが変わったデバイスは、バイパスの切替と同じく、ヘルパーの音声スレッドでリセットしてから鳴っているノートを送り直す。
  報告の比較に改訂が入るため、書出しは `compensation_changes` の変化で最初からやり直す。
- ポートの ID・名前・フラグ・型・in-place ペアはルーティングに影響しないので、共有領域を変えない。
  `is_rescan_flag_supported` は 6 つの単一フラグすべてに真を返す。0・未知のビット・複合の問合せには偽を返す。
- トラックが受けられない構成（ステレオの FX 母線に 1 チャンネルの主入力など）は、開く時と同じ `BusMapping` で計画を断る。
  古い計画が続き、そのデバイスは無音になる。報告は計画の準備ごとに繰り返す（遅延の拒否と同じ既存の振る舞い）。

## 残る制約

- ヘルパーの再起動から新しい計画の採用まで、そのデバイスは無音で、その間のイベントは捨てる（従来の再起動の間と同じ）。
  採用時にリセットとノートの送り直しをする。無音の実時間の長さ・クリック・第三者の切替は未計測で、UC-95 に残す。
- ホストから構成を選ぶ `clap.audio-ports-config`・`clap.configurable-audio-ports` は未対応である。
- 主ポート以外の入力はゼロ、出力は捨てる（既存）。サイドチェインの接続は P2-03 の残りである。

## 回帰と基盤

`isolation/audio_ports.rs` は実ヘルパーで、`[1]/[2]`・`[1, 1]/[2]`・`[2]/[1]` への変更を通す。
通知の改訂、古い共有領域の無音、`follow_ports` 後の 1・32・127・256 フレームの音声、元のポートへ戻る変更を照合する。
ID の変更では共有領域・改訂・音声を保ち、ポートを保持しないレイアウトの準備は親が拒否する。
fixture は各有効化が自分のポートの記述を 1 回ずつ読むことを数え、`audio-ports:<layout>` で最初のブロックの後に 1 回だけ構成を変える。
`hosted_playback/audio_ports.rs` は製品のエンジンで、再生中にステレオ出力がモノになる変更を通す。
各ブロックが古いルーティング・無音・新しいルーティングのどれか 1 つだけであること、新しいルーティングの等電力、書出しの再開の合図を照合する。
受けられない変更は `bus mapping` で断られ、そのデバイスが無音で、トランスポートが失敗しないことを照合する。
`session_correlation_tests.rs` は改訂の規則、`control_decode_tests.rs` と `session_decode_tests.rs` は `Remap` の本文の構造的な原因を照合する。

意図した red として、エンジンの追従を止めた版は `the new ports were not routed`、ヘルパーの照合を外した版は `mode 2: a mapping for the old ports reached process` で、どちらも終了コード 101 で失敗した。
証拠は `target/focused-checks/audio-port-routing-red/` と `target/focused-checks/audio-port-mapping-red/` に残す。
時間・メモリの量は未計測である。

必須契約 `plugin-audio-port-routing` と `plugin-audio-port-mapping`、上の 2 つの反例、`audio_ports` の RTSan 選択を `scripts/verification.json` に登録し、選択のテストを更新する。新しい Makefile の検査入口は作らない。
設計書・Phase 2・制約・監査の現在欄・コードの所在・診断手順・ユーザー確認を更新する。
