# ADR 0116: ドラムラックはフォルダトラックで表す

- 日付: 2026-10-18
- 状態: 設計方針を採用。製品への接続は未実装
- 範囲: Phase 2 の内蔵ドラムラック、親の MIDI と子のサンプル再生、音ごとのミックス

## 背景

作者の制作手順は、コードを打ち込んで構成を考え、別トラックにメロディを置き、その後にドラムを打ち込む流れである。ドラムは 1 トラックに MIDI をまとめ、キック・スネアなどの音色名の行で入力し、ミックスは音ごとに行いたい。外部ドラム音源だけに依存せず、Echode 内蔵のドラムラックを使いたいという希望を確認した。

作者は、ドラムラック自体をフォルダトラックとして表し、親に MIDI、子側に音ごとのサンプルを持たせる構成を指定した。既存の設計ではトラックに種別がなく、フォルダは子の音声を受けるバスになる。子の音声の加算は Phase 2 の予定である。一方、デバイスチェイン内の汎用並列コンテナとマクロは Phase 3 にある。

## 決定

- 内蔵ドラムラックは、通常のトラックの親子関係を使うフォルダ構成として表す。専用のトラック種別や、独立した仮想ミキサーの階層を追加しない。子側も通常のトラックであり、必要な場合にさらに子を持てる。数とネストに固定の上限を置かない。
- 親フォルダの MIDI にドラムのノートを置く。音ごとの子トラックがサンプラーとサンプルを持ち、親のノートを割当先の子へ振り分けて発音する。子へ MIDI の複製クリップを自動生成しない。
- 入力画面は音色名の行で表し、親の MIDI を編集する。行・ノートの割当と子トラックは安定した ID で対応させ、トラックの並び順や表示名だけから発音先を決めない。
- 最初の実装範囲はサンプル再生とする。ファイルブラウザからラックの空いている場所へサンプルをドロップすると、その音の子トラックとサンプラーを自動で作る。音声ファイルをタイムラインへ配置する通常の操作とは区別する。
- 既存の音の行へサンプルをドロップした場合は、その行のサンプルを差し替える。子トラックの ID、MIDI の割当と既存のノート、音ごとのミックス先を保つ。新しいレイヤーはこの操作で自動追加しない。
- ドラムパターンの通常の複製では、ノートの中身を論理的に独立させる。元と複製先の編集を相互に伝播させない。同じトラック内の複製でラック・サンプラー・ミックス設定は複製せず、共通の発音先を使う。不変の素材データの共有は妨げない。既存の明示的なリンク複製を保ち、ほかの種類のクリップの既定動作はこの決定の範囲外とする。
- 音ごとのサンプラーは、ノートの長さに従うゲート再生を既定とし、音量の ADSR を設定できるようにする。ノートオフを受けた時点のエンベロープ値からリリースへ移る。アタック・ディケイ中のノートオフも同じ規則とし、サンプルの終端が先ならそこで発音を終える。
- ワンショットへ切り替えると、通常のノートオフに関係なくサンプルの終端まで再生する。停止・一時停止・シーク・取消・対象削除による発音状態の消去は、両モードで既存の消音契約へ接続する。チョークグループは最初の実装範囲に含めない。
- 同じ音を再発音しても、旧音は自身の ADSR・リリースで消え続け、その上で新しい音を鳴らす。通常の再発音だけで旧音を切らない。ボイスごとのノートオフと、停止等による全発音状態の消去を区別する。
- 音ごとの音量・パン・FX は子トラックの操作として扱い、子の出力を親のフォルダバスへ加算する。親ではドラム全体を調整する。アレンジ、ミキサー、ラックの表示は同じ親子関係とパラメーターを参照する。
- 親の MIDI の生成・子へのイベント配送と、子の発音・親への音声加算は、別の処理段階として計画する。トラックを 1 個の頂点とした見かけの往復だけで循環とせず、実際の処理依存を検証する。実際のフィードバックの拒否を緩めず、回避のために 1 ブロックの遅延を入れない。
- MIDI の配送先、音ごとの処理、合流・PDC は制御側で計画する。オーディオスレッドでフォルダ全体を探索し直したり、確保・ロック・ファイル読込をしたりしない。通常のフォルダすべてへ、ドラム用の MIDI 配布を暗黙に追加しない。
- このフォルダ型ドラムラックとサンプラー自身の音量 ADSR は Phase 2 の制作範囲へ加える。汎用の並列コンテナ、マクロと汎用モジュレーターは Phase 3 のままとする。外部音源プラグインをドラムの発音元として加える範囲は、最初のサンプル再生の完成条件に含めない。子トラックの FX でも既存のプラグイン隔離を守る。

## 実装順と未決事項

P2-03 で親の MIDI 配布・子の音声合流・PDC の境界を作り、P2-06 でサンプル再生と個別ミックス、P2-07 で音色名の入力行を接続する。サンプルのドロップと子のデバイス表示は P2-02 のブラウザ・デバイス操作へ接続する。保存・復旧と素材の収集は既存の文書とメディア保管の経路を使う。

2026-11-03: 通常トラックのミュートは子孫へ継承し、ソロは自身と子孫を対象とする（[ADR 0244](0244-folder-mute-and-solo-gates.md)）。
これは出力のゲートだけであり、ドラム用の MIDI 配布を実装したものではない。

具体的なモデルのフィールド、MIDI ノート番号の初期割当、行の並べ替え、パターンの選択・複製の操作、ADSR の数値の初期値、ワンショット時のエンベロープ、出力のソロ・ミュートとドラム用 MIDI 配布の関係は、実装前に具体化する。希望と未決事項の更新は [インタラクションの検討](../interaction-design.md#ドラムの入力とミックス) に保持する。

2026-11-08: 上の未決事項は [ADR 0276](0276-priority-order-and-delegated-decisions.md) で、実装時に主要な DAW の慣例を既定にしてエージェントが決めることにした。

## 必要な受入と基盤

以下は今後追加する受入であり、実行済みの製品検査ではない。

- 実 View のサンプルドロップから、親子関係・サンプラー・音の割当を作り、1 回の Undo / Redo、保存・復旧を確認する。読込失敗や取消では、不完全な子や古い対象への挿入を残さない。
- 既存行への差替えで、親の MIDI、ノートの割当、子の ID と音ごとのミックスを保つ。差替えの Undo と読込失敗の巻戻し、旧サンプルの履歴からの復元も確認する。
- 親の MIDI から意図した子だけを発音し、イベントを二重配送しない。音色名の行の追加・改名・並べ替え、子の移動・削除の後も発音先と表示が一致することを確認する。
- 通常のパターン複製後、元と複製先のノートをそれぞれ変更し、もう一方が変わらないことを Undo / Redo、保存・再読込でも確認する。ラックと音ごとの設定は共通に保ち、明示的なリンク複製の既存の契約も守る。
- ゲート再生の ADSR とノートオフ後のリリースを、独立した振幅と時刻の期待値で確認する。アタック・ディケイ中のノートオフ、短いノート、サンプル終端が先の時も対象にする。ワンショットは通常のノートオフで切れず、両モードとも発音状態の消去で旧音を残さない。モードと ADSR の設定は Undo / Redo、保存・復旧を通す。
- 同音の旧音がリリース中に次の音を発音し、それぞれの ADSR が独立して重なることを、独立した期待波形とブロック長比較で確認する。旧音のノートオフが新しい音を誤って止めず、停止等の消去では全ボイスを片付けることも対象にする。
- 子ごとの音量・パン・FX と親全体の調整を、独立した振幅・到着位置の期待値で確認する。ステレオ、ネスト、センド、PDC、ソロ・ミュートも製品のバッファを通す。
- 停止・一時停止・シーク・ループ、サンプル差替え、子の削除で音が残らず、再生と書出しが一致することを確認する。ブロック長比較と RT の検査、必要な橋渡し検査へ含める。
- モデル・アクションの変更には不変条件とランダムな操作列を追加する。新しい必須契約と検査は Makefile、`scripts/verification.json` と選択の回帰へ登録する。
- 診断では、親の MIDI、音と子の割当、音声の合流先、子ごとの失敗、再生モード、通常のノートオフと発音状態の消去を識別できるようにする。実装時に収集する証拠とデバッグ手順を更新する。
