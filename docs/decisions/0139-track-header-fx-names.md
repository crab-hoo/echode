# ADR 0139: トラックヘッダの挿入済み FX と追加入口を分ける

- 日付: 2026-10-21
- 状態: 採用。P2-02 の入口の追加。P2-02 全体は未完了
- 範囲: アレンジヘッダの名前・追加ボタン・残りのチェインのメニュー・アクセシビリティ

## 背景

[操作要件](../interaction-design.md#デバイスビューと-fx-一覧の役割)では、追加候補を開く空欄と、挿入済みの名前から独自 GUI を開く入口を区別する。
[ADR 0132](0132-helper-plugin-windows.md) の列・インスペクターには名前の入口があるが、ヘッダは FX 追加ボタンだけだった。

## 決定

- FX 追加ボタンは、チェインが空かどうかにかかわらず候補パネルを開く。
  隣に先頭デバイスの名前を表示し、クリックで同じデバイス ID の独自 GUI を開く・前面化する。
- 2 個目以降は名前の右の「…」から、処理順のネイティブメニューで選ぶ。
  メニューの個数に固定上限は設けない。先頭名の表示数はヘッダの表示領域の制約であり、チェインの上限ではない。
- 名前は既存のカタログ表示名を使い、未取得・未検出なら保存されたプラグイン ID を使う。
  トラック名の描画幅を狭め、名前・「…」・追加ボタンの矩形を共有して、Metal の画素・入力・アクセシビリティを一致させる。
- 行高が 52 pt 未満、またはヘッダ幅・階層の字下げにより名前の領域を確保できない時は、名前と「…」を隠す。
  この場合も既存の追加入口と、下部デバイスビュー・インスペクターの全チェインへの入口は残す。
- 入力時はクリックしたトラックへフォーカスする。複数選択集合は既存の `.focus` の規則で保つ。
  複数選択時の下部の表示対象の決定は今回扱わない。
- オフラインの名前はヘルパーを開かない。メニューも無効にする。
  メニューの対象は文書 ID・トラック ID・デバイス ID で保持し、選択変更で対象を付け替えない。
  実行時にも存在とオフライン状態を再確認し、削除・文書交換後の古いメニューを拒否する。
- 開く要求は既存の `openPluginWindow` を使い、待機は文書の編集経路を塞がない。
  保存形式・アクション・Undo・音声処理は変更しない。保存・Undo による自動再表示も追加しない。

## 検査と診断

- 実装前の実ヘッダ入力は、名前を押しても開く要求を出さず失敗した。
  証拠は `target/header-fx-before.log`。正式結果は `target/verification/report.md` を参照する。
- 必須契約 `fx-header-ui` は実ヘッダのクリック、名前のアクセシビリティ入力、ネイティブメニューのアクションを通す。
  追加入口との分離、表示名・ID のフォールバック、オフライン、削除・旧文書の拒否と履歴不変を確認する。
  負の対照は、名前の要求を追加候補へ戻す。
- レイアウトの通常回帰は幅・深い階層・空と大きいチェインで名前と追加ボタンの非重複を確認する。
  同じ矩形を描画に使い、別の描画面は追加しない。
- 新しい検査種別・実行器は増やさず、既存の `check-product-contracts` と選択のテストへ登録する。
  DSP の変更がないため、新しいブロック長回帰は不要である。
- 切り分けは[デバッグ手順](../debugging.md)へ追加する。
  既存の契約ログと診断資料を使い、証拠の収集先は増やさない。

## 残る範囲

実画面での狭いヘッダの読みやすさ、メニューの操作感、VoiceOver の実際の読み上げ、第三者プラグインの窓はユーザー確認とする。
サムネイル、複数選択時のデバイスビューの表示対象、GUI アプリの MCP 入口は未完了のまま区別する。
