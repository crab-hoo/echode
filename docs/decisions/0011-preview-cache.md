# 0011. プレビュー用キャッシュを Phase 3 に入れる

- 日付: 2026-10-08
- 状態: 採用

## 背景

重いプラグインを並べると、再生の負荷が上がる。今の設計は再生を始めた位置から処理するので、途中から再生すると、前から続く余韻が鳴らない。動画編集ソフトのように、裏でレンダリングした音で再生したい。

## 決定

- 編集が止まったらトラックの音を裏でレンダリングし、再生ではそれを鳴らすプレビュー用キャッシュを、Phase 3 でフリーズと統合して作る。設計は `docs/ARCHITECTURE.md` §7.8
- Phase 1 のエンジンでは、トラックのノードを、デバイスを処理する代わりにキャッシュの音を読む形へ差し替えられるように作る
- キャッシュとは別に、リアルタイム処理のループの継ぎ目を Phase 1 で扱う。ループの頭のデータを先に読み、オーディオクリップの継ぎ目に数 ms のフェードをかける

## 結果

- キャッシュから鳴るトラックはプラグインを処理しないので、再生が軽くなる。途中から再生しても前からの余韻が鳴り、ループの継ぎ目もつながる
- 鍵は内容のハッシュなので、過去の版やオルタネイトでも、変わっていないトラックはキャッシュを使える
- ディスクを使う（48 kHz のステレオで 1 分あたり約 23 MB）。裏のレンダリングでは、大きな音源が 2 重に読み込まれる
- 触っているトラックはライブで処理する。キャッシュからライブに移る時は、プラグインの状態を作ってからつなぐ
