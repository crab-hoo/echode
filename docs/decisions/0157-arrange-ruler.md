# ADR 0157: アレンジのルーラーと共有トランスポート

- 日付: 2026-10-25
- 状態: 採用。P2-07 のトランスポートの続き
- 関連: [ADR 0155](0155-remembered-playback-start.md)、[ADR 0156](0156-ruler-loop-range-and-entry.md)

## 背景と再現

[操作要件](../interaction-design.md#再生の開始位置) は両エディタの開始位置とループ範囲の共有を求める。
アレンジにはルーラーがなく、上端のクリックは最初のトラックを選択していた。
変更前の実 `ArrangePaneView` に x=250、y=10 の押下を送り、
選択要求が発生することとヘッダが y=0 から始まることを回帰で再現した。

## 決定

- アレンジ上端に 24 pt のルーラーを置く。高さが足りなければペインの高さに制限する。
  ヘッダの見出しを除いた時間軸部分だけが開始位置と範囲指定を受ける。
- クリックとドラッグの 3 pt の分離、逆向き、長さ 0 の拒否、Shift は
  ピアノロールと同じ `RulerPress` を使う。
  アレンジは表示中の四分音符グリッド、ピアノロールは現在のノートグリッドへ吸着する。
- クリックの解放時だけ `transport.set_start` を送る。
  ドラッグは帯を仮表示し、解放時に共有の範囲下書きを 1 回だけ更新する。
  オン／オフ、開始位置、現在位置、トラック選択と Undo は範囲指定で変えない。
  保存・再読込みと再生中のシークは既存の製品セッションを使う。
- Escape、取消、フォーカス喪失、サイズ・ヘッダ幅・カメラ・選択・スナップショット・文書の変更、終了で破棄する。
  文書交換と音声要求の処理中は新しいルーラー操作を受けず、旧文書の要求は controller で拒否する。
- [ADR 0051](0051-arrange-presentation.md) の単一 drawable を保つ。
  ルーラーの数字、ループ帯と開始位置の印も既存の Metal フレームへ含める。
  有効な帯は緑、無効な下書きは灰色とし、両エディタは同じ controller の値を読む。
- `CanvasInput.arrangeTop` と `arrangeHeight` を描画・入力の共通境界とする。
  Rust の可視列は行領域の高さで問い合わせ、描画時に上端を加える。
  ヘッダのネイティブ入力領域も同じだけ下げる。
  行の選択・クリップのハンドルと移動・ファイルドロップ・ズームはこの境界を使う。
  行と文字の scissor、アクセシビリティの矩形もルーラーを除外する。
  初回の子レイアウト前の選択も親ペインの行領域高で表示へ導き、まだ高さ 0 の子ビューに依存しない。
  高さの往復で指定カメラを保持する規則は変えない。

## 受入と基盤

- 必須契約 `arrange-ruler-ui` は実 View の合成イベントと製品ブリッジで、
  クリック・吸着・Shift・逆向き・範囲の単一送信、共有と履歴不変、保存・旧文書拒否、行の位置を確認する。
  反例は範囲を開始位置要求へ置き換えるものと、行の描画から上端を除くものとする。
- `arrange-ruler-cancel-ui` は各取消後の解放から要求を送らないことを確認する。
  既存のドロップ・クリップ移動・カメラ回帰も新しい行領域を通す。
- `spike-arrange-frame` はルーラーを含む行の一致、帯・印の画素、サイズ不一致の余白を読む。
  描画時の行ずれ診断と実ウィンドウ用プローブも共通上端に合わせる。
  新しいログ出力先・外部入力・依存はなく、診断の収集範囲は変更しない。
- 実画面の見え方・操作感・VoiceOver はユーザー確認とする。
  既存ループ端のハンドル、自動スクロール、Return の割当は含めない。
