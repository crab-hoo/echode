# ADR 0055: ループとメトロノームは再生の設定にする

- 日付: 2026-10-11
- 状態: 採用
- 範囲: Phase 1 の製品再生。ループの継ぎ目フェードと先読みキャッシュは含まない

## 背景

エンジンはループとメトロノームをすでに鳴らせる。製品の再生は、デバイスのコールバックが準備済みの計画を読み、再生位置を直線に進めていた。アプリからは再生、停止、位置移動だけが操作できた。

ループはプロジェクトの内容ではない。範囲とメトロノームのオンオフを Undo やジャーナルに入れると、聴きながら切り替えるたびに編集履歴が増える。

## 決定

ループとメトロノームはオーディオセッションの設定にする。コマンドは `transport.loop` と `transport.metronome` で、モデルのアクションにはしない。

範囲はコマンドでは tick で受け取る。両方あるときだけ設定し、両方ないときに解除する。片方だけではエラーにし、以前の範囲は残す。オーディオスレッドが使うのはサンプル位置である。テンポが変わったときは、保存してある tick からサンプル位置を計算し直して送り直す。

コールバックはロックも確保もしない。ブロックより短いループは、準備したバッファ長までの区間へ分割する。区間用の領域はそのバッファ長で制御側が用意する。メトロノームは、準備済みのテンポ索引で打つ。`TempoMap` から索引を作る処理は確保をするので、コールバックでは使わない。

デバイスを開く前に、位置、ループ、メトロノーム、再生のコマンドを積む。最初のコールバックからその設定で鳴る。

プランを差し替えたときに運んだボイスは、追いかけのノートオンでは包絡をやり直さない。ブロックの先頭に当たったタイムラインのノートオンは、リリースの尾が残っていても打ち直す。

アプリのトランスポート、再生メニュー、コマンドパレットから操作する。範囲の下書きは拍で、既定は 0 拍から 4 拍である。ループがオンのときに範囲を確定すると、鳴っている範囲も更新する。

## 結果

1 拍のループとメトロノームを、ブロック長 1、7、64、512 で鳴らし、出力がビット単位で一致することを確認した。セッションは範囲の設定、不正な範囲の拒否、メトロノーム、解除をハードウェアなしで確認する。Swift は、これらの操作が Undo を増やさないことを画面を開かずに確認する。

ループ範囲のプロジェクトへの保存、継ぎ目のフェード、ループ頭の先読みは今回含めない。
