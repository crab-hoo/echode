# ADR 0076: CLAP の state をメインスレッドで保存し、ハッシュだけをプロジェクトに置く

- 日付: 2026-10-13
- 状態: 採用
- 範囲: 監査 PRO-03。プラグインの状態、製品パッケージのデバイス欄

## 背景

保存と復元はヘルパー内の変数を往復するだけで、CLAP の state 拡張を呼んでいなかった。拡張がないプラグインでも復元成功になっていた。ADR 0048 は製品のデバイス状態を `null` にしていた。

## 決定

save と load は、プラグインのメインスレッドだけから CLAP state を呼ぶ。オーディオスレッドは状態のバイト列を触らない。拡張がない、書き込みや読み込みが拒否された場合は失敗を返し、最後に成功した状態は更新しない。ホスト側の `mark_dirty` は制御側へ dirty として渡す。

製品の CLAP デバイスが持つ状態は、保存バイト列の BLAKE3-256 を小文字16進で表した文字列である。バイト列は `media/objects` に置き、パッケージの読み込みと既存コミットからの復旧で、ハッシュと中身が一致することを確認する。ミキサーの状態は `null` のまま拒否する。空の状態は「まだ保存していない」であり、0バイトを保存したプラグインとは区別しない。

同じ CLAP ID のデバイスが複数あるときは、デバイスごとにバイト列を持つ。再生と書き出しは、そのバイト列を起動後に load する。

スキーマ番号は変えない。状態欄は以前から JSON にあり、値は `null` だった。ジャーナルの差分では `plugin_state` として往復する。利用者の操作コマンドは増やさない。

## 結果

状態64で 0.25、状態128で 0.5 を出すテストプラグインで、保存、復元、dirty、再起動後の音を確認した。拡張のないプラグインの保存は失敗する。パッケージの往復は、オブジェクトがあるときだけハッシュを受け付ける。
