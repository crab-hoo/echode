# 0262. 書出しの数値欄は文字列の下書きを検証してから確定する

日付: 2026-11-04
状態: 採用

## 背景と再現

[ADR 0254](0254-gui-snapshot-export.md) は、不正なレート・余韻・換算超過を開始前に拒否するとした。
変更前の `9cef367` では、数値を直接束縛した SwiftUI の `TextField(value:format:)` を使っていた。
解析できない文字列は数値モデルへ届かず、画面に不正な入力が残っていても前の有効値で開始できた。

非表示の実 `WorkspaceExportView` と AppKit のフィールドエディターで、レート欄に非数値を入力する回帰を作った。
修正前は、開始に使用する設定が値なしにならないという固有のアサーションで失敗した。
環境・コンパイルの失敗はこの再現の証拠に含めない。

## 決定

- `ExportSettingsDraft` はシート内の参照型の表示状態として、レート・余韻・ピーク目標の入力文字列をそのまま保持する。
  `TextField(text:)` の入力を使い、確定キーやフォーカス移動を待たずに検証する。
- `validatedSettings` を開始ボタンと保存パネルの入口で共有し、有効欄の全入力が通った時だけ `ExportSettings` を作る。
  前の数値への代用・数値接頭辞だけの採用はしない。
- レートは正の u32 整数、手動の余韻は有限・非負・最近接丸め後に u32 フレーム以内、ピーク目標は有限の −120〜0 dBFS とする。
  桁区切りは認めず、小数点は表示ロケールを使う。小数と指数の全入力を照合する。
- 無効な欄の文字列は保持するが使わない。再度有効にした時は検証し直す。
  自動余韻で使わない手動秒数は、レートとの積の超過だけでは開始を止めない。有限・非負という保存値の条件は保つ。
- 不正時は `export.validation` に日英の理由を表示する。
  入力・修正だけではジョブの開始、前回設定の保存、Undo の追加をしない。
- 文書ワーカーからの前回値は、同じ下書きへ戻す。
  解析済み設定の JSON・CLI の引数・DSP・出力形式・スナップショットの寿命は変えない。
  曲本体と余韻の合計超過は、引き続き CLI が拒否する。

## 回帰と基盤

- `ExportInputTests` は実シートのフィールドエディターで、レート・余韻・ピーク目標の不正、入力中の拒否、修正した CLI 引数、設定未保存を確認する。
  ウィンドウを表示せず、音声機器・Finder・保存パネルは開かない。
- 必須契約 `export-input-ui` の反例は、下書きの検証を以前の数値の採用へ戻し、この回帰が失敗することを確認する。
  選択のテストは製品ファイル・回帰ファイルの通常 Swift・製品契約・HAL 防護を照合する。
  実行入口は既存の `make check-swift`・`make check-product-contracts` のままである。
- `ExportSettingsDraftTests` は空欄・単位付き・桁区切り・非有限・超過、ロケール別の小数点、精度、無効欄の再検証、u32 の丸め境界を確認する。
- 利用手順・UI 設計・P2-08 の範囲・開発入口・デバッグの切分けを更新した。
  診断へ入力文字列を自動収集しない。
  通常の並列 Swift 検査で既存の進捗回帰が 1 回失敗したため、再発時の状態の診断を追加した。原因未確定の記録はデバッグ手順に保持する。
- 実画面の配置・小数点の操作感・VoiceOver は自動回帰では判断せず、UC-59 のユーザー確認へ残す。
