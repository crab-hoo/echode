# ADR 0345: ホストの音声合流の異常をプラグインの障害と分ける

日付: 2026-11-14
状態: 採用。実画面と VoiceOver は UC-79 が未確認。
関連: [ADR 0282](0282-plugin-nan-and-master-auto-mute.md)、[ADR 0340](0340-latency-graph.md)、
[NFA-05](../reviews/2026-11-13-finite-overflow-audit.md#nfa-05-ホストの和のあふれを音源の障害にする)

## 問題と再現

開始時の HEAD は `dcff079`。
音源自身の出力は遅延線の前で検査しているが、配置音声・子の音声を足した後も同じ装置の障害として記録する。
有限の 2.0e38 を出す音源と同じトラックの 2.0e38 のクリップで、和だけが f32 を超える。
正常な音源が「NaN か無限大を返した」と表示され、書出しの拒否もその音源を指す。

既存の `audit_nfa05_an_instrument_is_not_blamed_for_the_sum_with_its_tracks_clip` を、修正前の製品ヘルパーで実行した。
終了コード 101 と `the track's auto-mute names the instrument` を照合した。
音声機器・アプリの操作は使っていない。

## 比べた案

1. **装置の欄へゼロかトラック ID を入れる**: 採らない。
   装置 ID の意味が変わり、表示・ログ・書出しがそれぞれ特別な値を見分ける必要がある。
2. **ホストの和だけ f64 にしてから狭める**: 採らない。
   プラグインへ渡す平面は f32 であり、範囲を超えた値にはやはり障害の帰属が要る。
   今回は正常な音の計算・レベルの方針を変えない。
3. **装置の有無で帰属を分ける（採用）**: 音源自身の出力は装置あり、ホストの和は装置なしとする。
   両方とも既存の非有限値の検出・無音化・自動ミュートを使い、書出しも同じ記録から拒否する。

## 決定と境界

- `StageFault` と `AutoMute` の `device` を `Option<u128>` にする。
  `None` はホストの合流、`Some` は装置自身の出力である。
  メーターは既存の版の番号の内側で有無も公開し、最初の障害だけを再生の開始まで保持する。
  特別な ID は予約しない。
- `contain_nonfinite` は自身の出力と合流後の面を同じ走査で検査するが、装置の失敗コードは自身の出力だけに書く。
  バイパスした音源の合流も後段へ渡す前に検査する。
  遅延線へ入る前の装置の検査と、後段へ非有限値を渡さない規則は変えない。
- `PlaybackControl::render_failure` はメーターの装置なしの記録を `RenderFailure::NonFiniteMix { track, at }` にする。
  それ以外は従来の `PluginBlockFailure` を包む。
  CLI はこの入口で書出しを拒否し、既存の完成ファイルを置き換えない。
  `plugin_failure` は装置の障害だけを読む入口として残す。
- `AudioState` の同じ `device` 欄は、合流の障害で JSON の `null` になる。
  Swift は旧来の装置 ID も読み、合流ではプラグイン名を表示しない。
  複数本の表示も原因をプラグインへ決めつけない。ログも合流では装置・CLAP ID を付けない。
- 音声側で新しい確保・ロック・待ちは行わない。
  通常の音源の面の検査回数は従来と同じで、メーターの有無の原子変数が 1 つ増える。
  時間の改善を目的とする変更ではなく、実時間の性能は今回測定していない。

## 回帰と基盤

- 元の監査回帰の無視を外し、ステレオと昇格したモノ、配置と子からの入力、後続 FX を通す。
  ブロック長 1・7・256 の全てで、合流の異常はプロジェクト標本 11 と記録される。
  出力の有限性・持続する無音・機器なしの解除・正常な装置を責めないことも照合する。
- CLI は実ファイルの取込みと隔離ヘルパーを通し、型付きの合流エラーと既存出力の保全を検査する。
- メーターの装置あり／なしの交換、ログの帰属、Swift の `null` の読込み・説明・ダイアログなしの表示を通常回帰で検査する。
- 必須契約の選択は `scripts/verification.json`、実装の正本は領域別の設計書、診断は既存の自動ミュートの節へ更新する。
  検査の結果と見送りは `target/verification/report.md` に記録する。

NFA-01〜04・08（フェーダー・バス・マスターのあふれと素材の入口）は今回の範囲外であり、直したとは扱わない。
