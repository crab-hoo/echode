# ADR 0129: トラックの通常複製を部分木単位の独立コピーにする

- 日付: 2026-10-20
- 状態: 採用。P2-02 のトラックの通常複製を接続。オートメーション・ルーティング・GUI 自動表示は対象外

## 背景

[操作要件](../interaction-design.md#音源を挿して編集に入る) は、通常のトラック複製で音源・FX・クリップ・オートメーションをまとめて写し、GUI は手動で開くとする。
ドラムパターンの通常複製は中身を独立させ、「リンクして複製」（`clip.link`）は別操作として残す（[ドラムの入力とミックス](../interaction-design.md#ドラムの入力とミックス)）。
[ADR 0127](0127-positioned-track-insertion.md) と [ADR 0128](0128-folder-disclosure-and-row-projection.md) は追加位置と開閉を接続し、通常複製を未実装として残した。

アクション定義（`define_actions!`）の `commit` は、プロジェクトを参照せずに新規 ID を確定する。
部分木の全 ID を個別に記録するには、確定時に複製対象の数を知る必要がある。

## 決定

- `track.duplicate` は `source` を受け、`source` とその子孫を元の部分木の直後へ、元と同じ親の兄弟として複製する。
  新しい順序キーは複製の根だけに振り、子孫は元の兄弟キーを新しい親の下で保つ。既存トラックのキーと `Arc` は変えない。
- アクションには `source` と `seed` を記録する。
  複製するトラック・デバイス・パラメーター・配置・中身・ノートの ID は、`seed` と元 ID から BLAKE3 の鍵導出モードで決め、UUIDv8 とする。
  ジャーナルの通常の再生は ChangeSet の新規 ID を使い、アクションだけの再生も同じ ID を再構築する。
  導出方式を変える時は文脈文字列を変え、別のアクションとして扱う。
- 配置は新しい中身を指し、ノートも新しい ID を持つ。複製先の編集は元へ伝わらない。
  複製する部分木の内側で中身を共有していた配置は、複製先でも 1 つの新しい中身を共有する。
  部分木の外側とのリンクは引き継がない。音声の中身は同じ素材ハッシュを参照し、PCM 共有（[ADR 0113](0113-product-macos-workgroup-and-caches.md)）を保つ。
- 名前、CLAP の ID、記録済みの状態ハッシュ、バイパス、オフライン、ミキサーの値（ミュート・ソロを含む）、配置の窓・ゲイン・フェードを保つ。
  プラグインの実行インスタンスは新しいデバイス ID で別に作られる（[ADR 0118](0118-track-fx-chain-editing.md) の `device.copy` と同じ扱い）。
- 導出 ID が既存 ID と衝突した時は `DuplicateId` で拒否し、別の ID へ代替しない。同じ `seed` の再利用も同じ理由で拒否される。
- UI はメニュー「トラック > トラックを複製」、コマンドパレット、トラックヘッダの右クリックメニューから同じ経路を使う。
  ⌘D はアレンジのクリップ複製（P2-07）に予約し、トラック複製へ割り当てない。
- 対象は操作時の選択トラックのうち、選択された祖先を持たないものとし、`TrackDuplicationRequest` に文書セッションと共に保持する。
  複数の対象は 1 つの編集として送り、単一 Undo とする。各複製はそれぞれの元の部分木の直後に入る。
  右クリックが選択中の行なら選択を保ち、選択外の行ならその行だけを選択してから対象を決める。
- 編集後は追加された部分木の根をすべて選択し、最初の根をフォーカスにする。
  旧文書の要求や Undo で消えた対象は拒否し、Redo を消さない。GUI は自動では開かない（プラグイン GUI は未実装）。

## 受入と基盤

- `track_duplication`（履歴）は、フォルダ・入れ子・内側と外側のリンク・音声・オフラインとバイパスの FX・ミキサー値を含む部分木の複製を確認する。
  既存 `Arc` の保持、複製先の編集が元の中身を変えないこと、Undo / Redo、ChangeSet とアクションだけのジャーナル再生、保存再読込を通す。
  子の複製位置、同じ `seed` の決定性、`seed` の再利用と存在しない対象の拒否も確認する。
- `track_duplication`（CLI）は、複製後の書出しが元の 1 トラックの出力のちょうど 2 倍になることを実 CLI で確認する。
- `TrackDuplicationTests` は、実ヘッダの Shift 選択と右メニューから、子孫の二重複製なし、操作時の対象保持、FX とノートの独立、単一 Undo / Redo、保存再読込を確認する。
  選択外の行の右クリック、選択なし、消えた対象、旧文書の拒否も通す。実ウィンドウの操作確認はユーザー担当とする。
- ランダムな編集列の `properties.rs` に複製を加える。
  必須契約 `track-duplicate-ui` と `track-duplicate-model` を `scripts/verification.json` に登録し、選択のテストと診断手順を更新する。
- 保存形式 5、ChangeSet の形式、DSP とプラグイン隔離は変えない。
  オートメーション（P2-04）、センド等のルーティング（P2-03）、クリップ FX は未実装のため、複製時の引き継ぎはそれぞれの単位で決める。
