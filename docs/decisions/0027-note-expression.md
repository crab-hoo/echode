# 0027. ノートのベロシティは 16 ビットで、表情は別の配列に置く

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-9

## 背景

ノートのベロシティは 0〜127 の `u8` である。CLAP は 0〜1 の実数、MIDI 2.0 は 16 ビットである。ARCHITECTURE §4.1 と §14 は、リリースベロシティ、ノートごとの表情（Pitch、Timbre、Pressure）、アーティキュレーションの参照もノートが持つとしている。スキーマ 1 に後から足すと、今のパッケージは開けなくなる。

表情の点をノートの行の中に入れると、1 ノート 1 行ではなくなる。曲線はノートの ID で参照する別の配列に置く。

## 決定

- 保存するベロシティは 0〜65535 の整数である。0 は無音、65535 は CLAP の 1 に当たる
- 今の操作と API が渡す 0〜127 は、次の式で 16 ビットにする。`v` は 0〜127 である
  - `(v << 9) | (v << 2) | (v >> 5)`
  - 127 は 65535 になる。0〜127 は、16 ビット値を 9 ビット右へずらすと元の整数に戻る
- テスト用シンセと、今の MIDI イベントは、保存値を 9 ビット右へずらした 0〜127 を使う。127 で作った音は今のままである。MIDI 2.0 の任意の 16 ビットをそのまま保存するのは、その入力を足すときである
- リリースベロシティも同じ 0〜65535 で、ノートの `release` に置く。今は常に 0 である。ノートオフのベロシティは 0 のままにする
- アーティキュレーションは、ノートの `articulation` に ID で置く。定義そのものは Phase 4 まで作らない。今は `null` だけを認め、`null` 以外は拒否する
- 表情は中身の `expressions` 配列に置く。1 件は、ノートの ID、種類（`pitch`、`timbre`、`pressure` のいずれか）、点の配列である
  - 点の `at` は、そのノートの内容時刻からの tick である
  - `pitch` の値は、ノートの音高からのセント（符号付き整数）である。0 がその音高である
  - `timbre` と `pressure` の値は、ベロシティと同じ 0〜65535 である
- 今は `expressions` が空であることだけを認める。中身があると拒否する。読んだものを捨てることはしない
- ノートの 1 行は `id`、`start`、`length`、`pitch`、`velocity`、`release`、`articulation` である。中身の JSON は、ノートの配列のあとに `expressions` を置く
- 並びのキーは今どおり開始、音高、ID である。ベロシティはキーにしない
- 変更の記録では、ベロシティとリリースベロシティを 16 ビットで残す。アーティキュレーションは、無いことを含め、ノートのプロパティとして残す。表情は中身の配列として残し、今は空である
- スキーマ番号は 1 のままである。この形の無いパッケージは、このリポジトリに無い

## 結果

`make check` が通った。0〜127 は 16 ビットへ広げて保存し、9 ビット右へずらすと元の整数に戻る。127 は 65535 になる。ノートの行には `release` と `articulation` があり、中身には空の `expressions` がある。`expressions` に中身があるファイルと、`articulation` が `null` でないファイルは拒否する。ベロシティ 127 の書き出しは、基準の WAV と変わらない。
