# ADR 0151: サンプルを少しずつ復号して試聴し、同じ読込みから波形を表示する

- 日付: 2026-10-24
- 状態: 採用。P2-02 の試聴の先読みと波形を接続。実機の聴感と操作感はユーザー確認待ち。
  表示中の出力保持・音量・手動の開始位置は [ADR 0152](0152-browser-audition-controls.md) で接続した。
- 置換: [ADR 0135](0135-sample-audition.md) の全体読込み・一括 SRC。
  専用 IOProc、文書ワーカーからの独立、停止・置換時の減衰は引き継ぐ。
  [ADR 0143](0143-browser-click-and-audition-timing.md) の診断は復号と変換の開始・完了を区別する。

## 背景と再現

[操作の要望](../reviews/2026-10-21-ui-feedback-audit.md) の単位 4 を分割して進める。
従来の `start` は `decode_audio_file` と `device_planes` の完了後にだけ音声を渡していた。
長い素材の先頭だけを聴く場合にも、ファイル全体の確保・読込み・SRC を待つ。

機器なしの製品コールバックの回帰を先に追加し、4 秒の WAV の受渡し時に
`decoded_us` が既に記録されていることで失敗を再現した。
証拠は `target/audition-stream-repro.log` に置く。
これは全体の復号を待つ制御経路の再現であり、実機の待ち時間の測定ではない。

## 決定

### 復号と SRC を処理の塊ごとに進める

- `echode-history::AudioFileReader` が AudioToolbox のファイルを試聴スレッド内で所有する。
  読込みは要求したフレーム数以内とし、EOF と不正な値を区別する。パッケージには書かない。
- `ResampleStream` は既存の rubato FFT と同じ設定を使う。
  ファイル全体を通して変換器の状態を保持し、先頭の遅延を一度だけ取り除く。
  EOF で遅延分を排出し、配置音声と同じ丸めによる長さで切る。同じレートは変換器を通さない。
  新しい SRC の実装・依存・方式の選択は追加しない。
- 出力を準備した後、長い素材は 100 ms 分を先読みした時点で音声へ渡す。
  0.5 秒以内の素材は EOF まで準備して渡す。
  これは準備の単位であり、素材の長さの上限ではない。

### 音声側は有限の受渡し領域を読み、制御側だけが待つ

- `AuditionSound::streaming` は機器レートで 0.5 秒分のステレオ PCM の SPSC リングを作る。
  制御側は塊ごとに復号・変換し、このリングへ書く。ファイル全体に比例する音声領域を確保しない。
- リングが埋まった時だけ試聴スレッドが出力を点検しながら待つ。
  新しい選択・停止は要求の世代で取り消す。最後のハンドルの破棄でも取消となり、コールバックの消費を待たない。
  機器変更で出力が閉じた時は、その読込みも止める。
  読込み中はアイドルとみなさず、停止・終了してから従来の 5 秒を数える。
- コールバックは PCM を加算し、リングが一時的に空なら無音を出して次のブロックで再開する。
  この場合に素材の位置を飛ばさず、EOF が通知されて領域を読み終えた時だけ終了する。
  不足した出力フレーム数は `starved_frames` に残す。
  音声側では確保・解放・ロック・待機をせず、音声の所有物は従来の返却リングで制御側へ返す。
- 置換と停止の 5 ms の減衰、モノラルの左右複製、曲の再生への加算は従来どおりである。
  プロジェクトの再生・書出し・保存形式は変えない。

### 同じ素材の読込みから部分波形を作る

- 元のサンプル位置を使って、全チャンネルの最小・最大を最大 512 個の区間へ集約する。
  区間数は表示の解像度だけを制限する。音声の長さやチャンネル数の制限ではない。
- `AuditionReport.waveform` に元の長さ・レート、読込み済みの位置、区間の幅、EOF とピークを公開する。
  音声の先読みと一緒に波形を埋める。別の復号やプロジェクトへの素材取込みは行わない。
- ブラウザの一覧の下に選択中の音声素材の波形・長さ・読込み状態を 1 つ表示する。
  `SamplePreviewView` は選択のパスと報告のパスが一致する時だけ波形とエラーを使う。
  別の選択の遅れた報告や文書なしの状態を、読込み中の波形として表示しない。
  ブラウザ自身の選択の付け替えは、従来どおり新しい試聴を要求しない。
- 試聴と波形は Undo・保存の対象外である。

### 診断と検査

- `first_decoded_us` は最初の読込み、`converted_us` は最初の変換済み音声、
  `decoded_us` は全体の復号、`handed_us` は音声への受渡しを示す。
  長い素材では全体の復号が受渡しより後になる。従来の全段の時刻の一律の大小比較は使わない。
- アプリの要求ログは、最新の要求が聞こえた後も全体の復号まで待つ。
  置換・停止・失敗した要求はそれまでの段を記録する。
  ログ収集の場所は変えず、追加した `spike-audition.json` も既存の診断の収集対象に入る。
- 初回の準備中に出力をアイドル扱いで閉じる経路も、期限を過ぎた時刻を与えて失敗させた。
  `target/audition-idle-repro.log` に証拠を保持し、`sample-audition-loading` で読込み中の保持と停止後の閉鎖を確認する。
  実時間の待機や速さの合否基準は使わない。
- 必須契約 `sample-audition-stream` は全復号前の受渡し・発音・部分波形・停止・古い波形の解除を確認する。
  早い受渡しを無効にした反例では失敗する。
  `sample-preview-ui` は実表示部品の幾何・読込み表示と、別の選択の波形の拒否を確認する。
- SRC の回帰は短い素材、端数、複数レートとステレオを一括 SRC と比較する。
  音声の回帰は不足からの再開・EOF・解放の返却、ブロック長比較と RTSan を含む。
  `make spike-audition` は機器なしの release 計測を別途行い、4 秒・60 秒の素材の各段の時刻を残す。

## 残る範囲

- ブラウザ表示中の出力の常駐、音量、自動試聴のオン／オフ、右矢印での試聴、波形クリックによる開始位置は後続とする。
  出力は従来どおりアイドルから 5 秒で閉じる。
- 波形は試聴の読込みから得たものだけであり、未試聴の素材の先行読込みやキャッシュは持たない。
- 実機の開始時間、遅いストレージでの不足、2 つの IOProc の加算、聴感と VoiceOver の操作感はユーザー確認とする。
