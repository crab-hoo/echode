# ADR 0161: 置いた音声に自動のフェードを付けない

- 日付: 2026-10-25
- 状態: 採用。[2026-10-25 の操作の報告](../reviews/2026-10-25-user-feedback.md) の FB-04 への対応。聴感はユーザー確認待ち
- 関連: [ADR 0022](0022-clip-content-and-placement.md)、[ADR 0107](0107-mix-controls.md)、
  [ADR 0145](0145-sample-browser-file-drops.md)、[ADR 0154](0154-clip-move-and-duplicate.md)

## 背景

ブラウザからサンプルを置くと、自動のフェードは要らないと報告された。
`Project::place_audio` は、新しい配置の両端に既定の 5 ms（`DEFAULT_FADE_FLICKS`）のフェードを付けていた。
ADR 0022 で、エンジンの固定の端のフェードを配置ごとの値へ移し、0 も選べるようにした時の既定値である。
ブラウザのダブルクリック・Return、ブラウザと Finder からのドロップ、「音声を取り込む」、CLI と MCP の `audio.import` は、
すべて `audio.place` で配置する。

## 決定

- `audio.place` は両端のフェードを 0 として置く。上の取込みの経路はすべてこの規則に従う。
  クリック音を避けたい場合は、クリップのハンドルかインスペクターでフェードを付ける。
- 記録するアクション（ジャーナル）の `audio.place` に `fade_in`・`fade_out` を加え、新しい配置は 0 を書く。
  欄のない以前のジャーナルは記録した時の 5 ms で再生する（`legacy_place_fade`）。
  変更集合を持つ行は従来どおり値をそのまま適用する。要求（コマンド）の形は変えない。
- モデルは `place_audio_with_fades` で値を受ける。`place_audio` は既存の呼出しのため 5 ms のまま残す。
- クリップの移動で置き換えた時の切り口（ADR 0154）は、既定の 5 ms のフェードを保つ。
  [操作要件](../interaction-design.md#オーディオクリップとテンポ) の「分割・トリムの切り口の短いフェード」と、
  重なりの自動クロスフェードはこの決定の対象外である。
- 再生側に隠れた端のフェードはない。フェード 0 のクリップは素材をそのまま鳴らす。ループの継ぎ目の 5 ms は従来どおりである。
- フェード 0 のハンドルはクリップの端に重なり、右端のハンドルは押せなかった。
  両方のハンドルの表示と当たり判定を、クリップの端から 4 pt 内側までに留める。ドラッグは押した位置からの相対量なので、値の計算は変えない。

## 検査

- 必須契約 `audio-import-transaction` に、取り込んだ配置のフェードが 0 であることを加え、
  コミットの値を 5 ms に戻す反例を足した。
- 必須契約 `journal-place-fades` は、欄のない以前の `audio.place` が 5 ms で再生され、新しい行が 0 を書いて同じ値へ戻ることを確認する。
  反例は以前の行の既定値を 0 にする。
- 必須契約 `sample-import-target` は、ブラウザの共通配置で置いたクリップのフェードが 0 のまま保存・再読込されることも確認する。
- 必須契約 `clip-mix-ui` は、フェード 0 から内側のハンドルを相対ドラッグして両端のフェードを付ける。
- 保存形式の版は変えない。配置済みのクリップの値も変えない。
