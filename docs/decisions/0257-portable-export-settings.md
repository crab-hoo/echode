# 0257. 書出し設定をプロジェクトと一緒に持ち運ぶ

日付: 2026-11-04。
状態: 採用（P2-08 の前回設定の持ち運び。単位全体の受入完了ではない）。

## 背景と再現

[ADR 0254](0254-gui-snapshot-export.md) の設定は、この Mac の正規化したパスをキーにする UserDefaults だけにあった。
プロジェクトを移動・コピーしたり別の Mac へ渡したりすると、前回の形式・レート・余韻・ディザが初期値へ戻る。
操作要件の「プロジェクトごとの前回設定」を、モデルの編集や音声の状態とは分けて保持する。

GUI と同じ `ExportJob.start` から実 CLI を完走させる回帰を先に追加し、
`Accepted export settings were not stored in the package` と終了コード 1 を照合した。
証拠は `target/export-settings-red/` にある。

## 決定: パッケージ内の任意の設定

- パッケージ直下の `export.json` に `{"version":1,"settings":...}` を保存する。
  `settings` は Swift の既存の `ExportSettings` と同じ形で、形式・レート・自動余韻・秒数・TPDF を持つ。
  出力先の絶対パスやユーザー情報は入れない。
- 曲のモデル、ジャーナル、Undo / Redo、保存スキーマは変えない。
  自動保存の Git ツリーや、CLI 用の専用スナップショットにも入れない。
  取消・失敗したレンダーでも、準備済みの書出しの設定は前回値として残す。
- 文書ワーカーの `history.export_settings` は、`settings` なしなら読取り、JSON 文字列付きなら置換する。
  書込みは文書の排他所有と復旧への同意を共有し、Swift が元パッケージへ直接書かない。
  同じ捕捉済みの文書ハンドルを使い、文書交換で次の文書へ書き込まない。
- 履歴層は 16 KiB 以下の JSON オブジェクトだけを受け付ける。
  読込みも上限の次の 1 バイトまでで止め、過大・不正 UTF-8・不正 JSON は値なしにする。
  この制限は設定レコードだけで、曲・トラック・音声の容量を制限しない。
- バージョンと値の検証は Swift が所有する。
  欠落・破損・未知の版・不正値は、その Mac の旧パス設定、なければ初期値へ戻す。
  読むだけでは作成・移行・修復しない。
- 書込みは既存の `package_io::Directory` のリンク拒否・原子的な置換を使う。
  同期はしないので、電源断後の前回値の永続性は保証しない。
  書込み失敗は詳細へ警告を残すが、完成したスナップショットからの書出し自体を妨げない。

## 決定: 画面と移行

- 設定シートは文書ワーカーから前回値を読むまで操作と確定を無効にする。
  応答後に文書 ID を再照合し、古い文書の返答で新しい文書の欄を上書きしない。
- 設定の保存は、確定済みのスナップショットの準備が成功した後に同じ編集の手番で行う。
  保存パネルの取消・準備開始前の取消・スナップショットの失敗では書かない。
  準備完了後の取消では設定が残り得る。
  この点は [ADR 0256](0256-export-cancellation.md) の「CLI を起動しなかった取消では保存しない」から変更する。
- 旧 UserDefaults の読取りと書込みは互換の予備として保つ。
  次に書出しを準備した時にパッケージへ移す。正常なパッケージ内の値を旧値より優先する。
  まだ一度も移行していない旧プロジェクトを移動すると、以前と同じく旧パスの設定は引き継がない。
- CLI の既定値・引数・DSP・WAV の処理は変更しない。CLI が `export.json` を暗黙に適用することもない。
- 保存する JSON のキー順は固定する。同じ設定を再符号化した時の順序でテストが揺れないようにする。

## 回帰と基盤

- 必須契約 `export-settings-ui` は、実 CLI を使う GUI ジョブの後で元パッケージを移動し、
  UserDefaults を消して再オープンしても同じ設定になることを確認する。
  別文書・古い文書 ID・Undo・専用スナップショットとの独立も確認する。
  書込み要求を `.list` に戻す反例で、ローカル記憶だけへの退行を検出する。
- `ExportSettingsTests` は旧設定の移行・未知の版・不正値・パッケージの優先・リンク先保全と警告・早い取消を検査する。
  `RecoveryConsentTests` は同意前の読取り許可と書込み拒否を検査する。
- 履歴の `tests/export_settings.rs` はモデル保存との共存・Git ツリーからの除外・過大入力・不正 JSON / UTF-8・非通常ファイルの拒否を検査する。
  検査の既存の入口を共有し、契約と選択回帰を `scripts/verification.json` へ登録する。
- README・設計・現在の制約・進め方・開発とデバッグの手順を更新する。
  自動の診断収集へ設定やユーザー文書を追加しない。
  発音と音声処理は変えないため、新しいブロック長の発音テストや DSP の比較は重複追加しない。
- 最終検査で既存の進捗回帰が 99% へ届かない失敗も見つかった。
  子プロセスが UI 通知の間に終了すると、既に pipe にある末尾の通知を読まずに抜けていた。
  `ExportProgressExitTests` は通知を保留したまま子を終了させて再現し、固有のアサーションと終了コード 1 を照合した（`target/export-progress-exit-red/`）。
  終了後も読める通知を排出するが、開いたままの子孫は待たず、終了後の排出を 64 KiB に限る。
  この上限は進捗の表示だけで、音声には作用しない。成功は引き続き CLI の終了コードで判定する。
  直列の HAL 防護検査では、終了を確認した後の `Process.waitUntilExit()` 内で停止も再現した。
  終了までの待ちは poll が既に行っているため、非同期の手番をまたいだ冗長な Foundation の run loop 待ちを除く。
  停止時のスタックは `target/export-settings-hal-timeout.sample`、修正後の直列回帰は `target/export-exit-serial/` に残す。
- 実画面での読込み待ち・移動後のシートと VoiceOver は UC-56 のユーザー確認待ちとする。
