# ADR 0306: アクションの引数の原因を表示文から分類しない

日付: 2026-11-10
状態: 採用
関連: M1（DEV-7・SPG-11・XCA-16）、ADR 0304・0305

## 問題と再現

`parameter_message` は Serde の表示文を検索し、ID・拍子・テンポの拒否を選んでいた。
未知のアクション名や余分なキーにも利用者の入力が引用されるため、入力に拒否の文を含めるだけで別の原因として表示した。
ID の入力に ` at line` がある場合も、Serde の位置の注記と取り違えて入力の途中で切っていた。

公開の `ApiSession::reply` から単一・一括編集を通す回帰を先に追加した。
未知のアクション名を `tempo is outside the allowed range` にすると、一般の引数不一致でなくテンポの拒否になって失敗した。
期待終了コード 101 と回帰固有のアサーションを `checked_commands.py` で照合した。
ログは `target/focused-checks/action-parameters-red/` に置いた。

## 比べた案

| 案 | 判断 |
|---|---|
| Serde の文の検索を厳密にする | 採らない。依存の表示と入力の引用を正本にする構造が残る |
| JSON Schema やキーの一覧で先に検証する | 採らない。モデルの規則と引数の形を別の論理で重複して保守する |
| 各アクションに別の入力構造体と変換を書く | 採らない。登録簿とフィールド・既定値・flatten がずれる |
| 登録簿から未検証の wire 型を生成し、既存のモデルの構築子へ渡す | 採る。形と意味を分け、アクションの項目表と検証の正本を維持できる |

実行時間・音質・メモリ改善は主張しない。音声スレッドは変更しない。

## 決定と境界

- `define_actions!` は `Command` と同じ項目・Serde 属性で内部の `WireCommand` を生成する。
  `Parameter` の関連型が ID を文字列、拍子・テンポを整数の分数として読む。
  ほかのスカラーと `NoteDraft` は既存の型で形を読む。任意の ID も同じ変換を通る。
- 意味の検証は `Id::parse`・`Meter::try_new`・`Tempo::rational` が正本である。
  拍子やテンポの許容範囲をアクション層へ写さない。
- `Command::from_value` は `ParameterError` を返す。
  `Json` は元の `serde_json::Error`、ID は項目名と入力文字列、拍子・テンポは入力の分子・分母を持つ。
  `Error::source` で JSON の原因へ届く。意味の拒否は元の値から直接生成し、文を解析しない。
- 先に全体の形を検証し、次に登録簿の項目順で意味を検証する。
  複数の不正を持つ入力では、従来の JSON キーの走査順でなくこの順を使う。
- JSON-RPC の単一編集と `DocumentHost` の一括編集は型付き入口を使い、応答の生成まで原因を持つ。
  `ElementError::Parameters` も同じ原因を持ち、失敗した添字・`-32602`・一括の取消を維持する。
- `Command` の Serde 互換入口も同じ wire と変換を使う。
  Serde の契約上、この入口だけは意味の原因を `custom` の表示文へ変える。型付きの呼出側は `from_value` を使う。
  確定済み `Action`、ジャーナル・保存形式・生成する Swift の編集型は変えない。
- 通常の拒否の文は従来どおりである。入力の引用を拒否の種類と誤認した文と、ID の途中の切詰めだけを修正する。
  C ABI と RPC に新しい構造化応答は追加しない。

## 回帰と基盤

- `echode-actions/tests/parameters.rs` は原因の種類・元の値・JSON の source、任意 ID の欠落と null、flatten、整数の端点、検証の順を検査する。
- `rpc_tests.rs` は公開応答の誤分類・ID の切詰めと、単一・一括のコード・添字・無変更を検査する。
- 履歴の `tests/document_errors.rs` は型の転送、一括失敗後のジャーナルの保持、Undo / Redo の保持を検査する。
- `check_typed_errors.py` に `echode-actions` 全体を登録し、新規・入れ子のモジュールへの文字列の結果と原因の文字列化の再導入を拒否する。
- 設計書・コードの所在・デバッグ手順・監査の記録を更新する。
  新しい外部入力・実行入口・検査ターゲットは増やさず、Makefile と `scripts/verification.json` の選択条件は変えない。
  既存の通常回帰と Swift の編集型の fixture が同じ境界を通る。
- 利用者の操作と `status.md` の制約は変えず、新しい実機・実画面の確認待ちも作らない。

## 残る範囲

M1 全体の完了とはしない。次は文書ワーカーの単一編集で、Serde 互換入口を通って意味の原因が JSON の文へ戻る境界である。
検査結果と計測・実機の見送り理由は `target/verification/report.md` を正本とする。
