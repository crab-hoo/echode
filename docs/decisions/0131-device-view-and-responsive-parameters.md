# ADR 0131: 横並びのデバイスビューと、プラグインの応答を待たない一覧

- 日付: 2026-10-20
- 状態: 採用。P2-02 のデバイスビュー改訂と応答性の受入条件の最初の接続
- 範囲: 下部のデバイスビュー、パラメーター一覧の生成・検索・ピン留め、デバイス要求の実行場所、保存形式 6

## 背景

2026-10-20 に、ユーザーから 2 つの症状が報告された。
プラグイン付きトラックを選ぶたびに GUI が止まること、FX の汎用パラメーター画面が特に重いことである。
同日の対話で、下部を縦の FX 一覧とする現状は希望と異なり、デバイスを横に並べて各デバイス内に全パラメーターを持たせると確認した
（[操作要件](../interaction-design.md#デバイスビューと-fx-一覧の役割)）。

### 再現と原因

- 旧パラメーター欄（[ADR 0130](0130-clap-parameter-editing.md)）は、全パラメーターの AppKit 行を一括生成していた。
  ウィンドウなしの計測で、800 個で約 0.68 秒、3000 個で約 2.7 秒かかった（M4、デバッグビルド）。
  欄の表示中に別トラックを選んで戻ると、SwiftUI の分岐で欄が作り直され、毎回この生成が走る。
  値の 1 回の変更でも全行を更新し、800 個で約 10 ms、3000 個で約 35 ms かかった。
- `device.parameters` / `device.parameter.set` は文書ワーカー上でヘルパーの応答を最大 5 秒待っていた。
  その間、後続の編集・Undo・状態取得は同じ待ち行列で止まる。
- 同じ制御端点の排他を、背景保存の確認（毎周回）と、グラフ交換時の適用済み状態の読取りも使っていた。
  そのため、待ちを別スレッドへ移すだけでは、制御側がその排他で止まる。
- Undo / Redo は値の読み直しを編集の手番の中で待ち、その間 `busy` が全画面の操作を止めていた。

実機・第三者プラグインでの症状の確認はユーザー担当である。上の計測は機器なしの再現であり、実機の停止時間の合格ではない。

## 決定

### 一覧は画面内の行だけを作る

- 各デバイスのパラメーター一覧は `NSTableView` の再利用行とし、画面内の行だけをビューにする。
  値の変更は画面内の行だけを更新する。行の作り直しは、ID の並び・検索語・ピン留めが変わった時だけ行う。
- 状態はデバイスごとの `DeviceParameterState`（観測可能なクラス）に持つ。
  値の変更はそのデバイスの一覧だけを再描画し、他のデバイスと文書全体の状態には触れない。
- 一覧は文書を開いている間デバイスごとに保持し、トラックを戻すと同じ列と行を再利用する。
  表示を戻した時は値だけを読み直し、ID が同じなら行は作り直さない。
- パラメーター数を固定上限で切り詰めない。検索の対象は全パラメーターとし、画面に作る行と分ける。
  値の送り先は常に CLAP のパラメーター ID であり、検索後の行番号を使わない。

### デバイス要求は文書ワーカーの外で待つ

- 文書ワーカーはデバイス要求を検査してヘルパーの制御端点を解決し、往復は文書ごとの「デバイスレーン」スレッドへ渡す。
  一覧・値の変更はレーンが完了を返す。状態の取り込みはレーンが行い、記録はワーカーへ戻して他の編集と同じ順序で行う。
- レーンは投入順に 1 件ずつ処理する。値の変更が、後の取り込みより前にヘルパーへ届く。
  取り込みの戻りを待つ間だけ、ワーカーの待ち時間を 20 ms から 1 ms に縮める。
- 制御端点の適用済みバイトは通信用の排他から分けた。背景保存の確認は通信中なら次の周回へ送る。
  グラフ交換と背景保存は、別デバイスや同じデバイスの応答待ちで止まらない。
  同じデバイスの状態読込（Undo）と写像の準備は、そのデバイスの往復の後になる。
- 文書を閉じる時は、待ち行列の要求を拒否する。応答待ちの要求は、ヘルパーの終了とともに終わる。
- 停止中の最初のデバイス表示で出力とヘルパーを開く処理は、まだワーカー上で行う（残る範囲を参照）。
  2026-10-21 に [ADR 0136](0136-output-opening-off-worker.md) で準備をワーカー外へ移した。

### 画面の手番と古い応答

- 選択と表示の切替は、プラグインの応答を待たずに完了する。名前・順序・バイパス・オフラインを先に表示し、一覧は応答ごとに埋める。
- 一覧の要求はデバイスごとの世代を持つ。文書・デバイス・世代が一致しない応答は捨て、削除・オフライン化・文書交換の後に一覧を戻さない。
  ドラッグ中のパラメーターは、届いた一覧で値を戻さない。
- Undo / Redo / 版の復元の後の読み直しは手番の外で行い、後続の編集を待たせない。
  パラメーターのドラッグは、状態を読み込みうる履歴操作の間だけ開始できない。通常の編集中は開始できる。
- 失敗はそのデバイスの列に表示し、他の列と操作を止めない。

### 横並びのデバイスビュー

- 下部は選択トラックのデバイスを処理順に横へ並べる。各列に名前・オフライン・バイパス・前後への移動・複製・削除・検索欄・一覧を置く。
  チェインが表示幅を超える時は横にスクロールし、一覧上の横方向のスワイプもチェインの移動へ渡す。
- 名前のドラッグは並べ替え、Command＋ドラッグは複製、別トラックへのドラッグはコピーで、従来の操作を保つ。
  ドロップ先は横位置で決める。
- オフラインのデバイスは設定を保持したまま一覧を出さず、その理由を表示する。
- 下部の切替を「ピアノロール」「デバイス」「両方」とし、「両方」では上下に並べる。
  デバイスビューは常に選択トラックへ追従し、表示トラックを固定する機能は設けない。

### 検索とピン留め（2026-10-20 のユーザー回答）

- 一覧はプラグインが報告し、表示を許すパラメーターをすべて並べる。`CLAP_PARAM_IS_HIDDEN` は従来どおり出さない。
- 検索は空白で区切ったすべての語が、名前またはモジュール名に含まれる行を残す（大文字小文字・記号の差を無視）。
  検索語はデバイスごとにアプリの起動中だけ保持し、保存しない。
- ピン留めした項目は一覧の最上部に固定し、検索中も検索語にかかわらず表示する。
  ピン留め同士と残りの項目は、それぞれプラグインの順に並べる。並べ替えの操作は設けない。
- ピン留めはデバイスの設定として保存し、1 回の切替を 1 回の Undo にする。
  デバイスの複製・別トラックへのコピー・トラック複製は、ほかの設定と同じく引き継ぐ。
- 同じプラグインを複数挿しても、デバイスごとに独立する。

### モデルと保存形式 6

- `Device.pinned`（昇順・重複なしの CLAP パラメーター ID、`u32::MAX` は不可）と `device.pin_parameter` を、
  モデル・登録簿・API / MCP・差分・ジャーナルへ加えた。ミキサーはピン留めを持たず、直接操作・差分・読込のすべてで拒否する。
- 一覧にまだない ID も受け付ける。プラグインは稼働中しか一覧を返さず、後の版で現れる ID を事前に検証できないためである。
- スキーマを 5 から 6 へ進め、5 以前のデバイスへ空の `pinned` を補う。
  現行形式は配列を必須とし、欠落・別の型・逆順・重複・無効 ID・ミキサーのピン留めを破損として拒否する。
  旧ジャーナルのデバイス作成差分に値がない場合は、ピン留めなしとして復旧する。
- C ABI に `echode_snapshot_device_pins` を加え、Swift の `Snapshot.devicePins` から読む。

## 残る範囲

- 停止中に最初にデバイスを表示した時の出力とヘルパーの起動は、文書ワーカーで待つ。
  開いた出力は保持するため 2 回目以降は待たないが、初回の間は後続の編集が待つ。
  再生開始の初回準備も同じであり、ヘルパーの起動自体をワーカーの外で準備して交換する方式は今後の対象とする。
  → [ADR 0136](0136-output-opening-off-worker.md) で両方の初回準備をワーカー外へ移した。開いた後の追加のヘルパー起動は残る。
- デバイスの展開・折りたたみ、FX 空欄と挿入済み名前の操作の区別、プラグイン独自 GUI の表示は未実装である。
  独自 GUI と列・インスペクターの名前クリックは [ADR 0132](0132-helper-plugin-windows.md) で接続した。
- マクロは Phase 3 の範囲であり、ピン留めはマクロの代わりではない。
- 複数トラックを選んだ時のデバイスビューの対象は、従来どおりフォーカスしたトラックである。複数選択時の表示は未決である。
- ヘルパー側で数千のパラメーターを読む時間（`count`・`get_info`・`value_to_text`）とメッセージの大きさは未測定である。
- 実機の操作感と第三者プラグインでの停止の解消は、ユーザーの確認待ちである。

## 検査と診断

- 必須契約 `device-lane-held` は、テスト用 CLAP の一覧をメインスレッドで保留し、その間に製品エンジンの制御側が
  背景保存の確認・無関係な編集のグラフ交換・適用済み状態の読取りを終えることを確認する。
  負の対照は背景保存の確認を通信用の排他で待たせ、保留中の一覧が先に終わることで失敗する。
- FFI の単体テストは、レーンの保留中もワーカーへ戻ること、取り込みが値の変更の後に戻ること、閉じる時の拒否、失敗と異常終了の報告を確認する。
- 必須契約 `device-view-slow-ui` は、一覧の応答を保留したまま選択・無関係な編集・Undo・停止・他デバイスの一覧が終わり、
  古い応答が新しい一覧・削除済みデバイス・閉じた文書へ反映されないことを確認する。負の対照は世代の照合を緩める。
- 必須契約 `device-view-long-ui` は、3000 個のパラメーターで画面内の行だけを作り、画面外・検索・ピン留めから
  同じ ID へ値を送ること、ピン留めの固定・デバイスごとの独立・Undo・複製・保存再読込を確認する。負の対照はピン留めを末尾へ回す。
- モデル・履歴の回帰で、差分の反転・複製・旧形式の移行・現行形式の破損拒否・ランダム操作列を確認する。
- 時間の実測は通常の回帰に入れない。行の生成数と、応答の保留中に完了した操作の順序で判定する。
- 保留はテスト用 CLAP の `ECHODE_TEST_FAULT=params-wait:<socket>` で行う。製品のプラグインには影響しない。
