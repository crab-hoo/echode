# ADR 0267: 再生 ID の対応表を現在の計画に限定する

- 日付: 2026-11-05
- 状態: 採用
- 対象: FCA-19 の再生 ID 表。Undo とメモリ上のジャーナルの予算は判断待ちのまま残す。

## 問題と再現

`PlaybackIds` は作ったノートとトラックの番号を、削除後も再生器の寿命中保持していた。
小さい曲でも追加・削除を繰り返すと表と予約容量が増え、曲を空にしても戻らなかった。
`plan_tests::audit_fca19_rebuilding_keeps_only_current_playback_id_mappings` は製品の `build_plan` を通す。
一つのノートを保持しながら別のトラックとノートを追加・削除すると、最初の削除で対応が 2 件残った。
期待終了コード 101 と `deleted note IDs remain in the playback table` のアサーションを照合した。

## 決定

計画を作る間に、その計画で使用するノートとトラックだけの表を制御側で作る。
成功後に旧表を交換して解放するので、以前の最大の曲や編集回数に応じた容量を持ち続けない。
途中で作成が失敗した時は、直前の成功した表を除去しない。
作成中は旧表と新表を同時に持ち、ハッシュ挿入が一回増える。全体再構築の処理量を減らす変更ではない。

残るモデル ID の番号は変えない。削除・無音化後に戻った ID には新しい番号を振る。
番号の高水位は保ち、古い計画・処理待ちの命令・ヘルパーが持つ番号を別のノートやトラックへ再利用しない。
この寿命中の番号空間の使い切りは既存どおりエラーであり、再利用で隠さない。
音声側で表の掃除・確保・解放をしない。

## 回帰と残る範囲

128 回の編集の出入りでも現在の表が一件ずつで、空の計画では容量が 0 になることを検査する。
生きている ID の安定、削除した番号の非再利用、古い計画の不変性、失敗後の再試行も確認する。
既存の再生中の編集・ノート追跡・声の解放の回帰は維持する。
通常のエンジン単体テストの入口に載せるため、検査の別登録は不要である。

Undo の段とジャーナルの保持予算を決めたものではない。FCA-19 は一部対応である。
ヘルパーのイベント用予約領域や返却待ちの旧計画の寿命も変えず、実時間の速度改善は主張しない。
領域別設計とメモリ増加の診断へ、この寿命の区別を追加する。証拠の採取先は変えない。
合否と見送り理由は `target/verification/report.md` へ記録する。
