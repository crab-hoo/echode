# 0026. パラメータを置き、フェーダーもその 1 つにする

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-8

## 背景

音量、パン、ミュート、ソロは、今は `TrackFader` としてエンジンの中だけにある。プロジェクトには残らない。ARCHITECTURE §4.6 は、パラメータのアドレスを `track/<トラック>/device/<デバイス>/param/<パラメータ>` とし、オートメーションもコントロールサーフェスも同じアドレスを動かすとしている。フェーダーだけをトラックのフィールドにすると、その経路がフェーダー専用になる。

ミックスの計算は ADR 0012 のまま、キャッシュの後ろである。この項目は、その計算に渡す値の出どころをモデルに移す。変調、オートメーションの曲線、MIDI の割り当て、コントロールサーフェスの手順は作らない。

配置のゲインは、クリップの中の音量である。トラックのフェーダーとは別のままにする。

## 決定

- 各トラックは、作られたときに内蔵デバイスを 1 つ持つ。種類は `mixer` である。プラグインではなく、デバイスの並びもまだ持たない。プラグインのデバイスは、後からこのトラックに足す
- ミキサーのパラメータは、次の 4 つで、この順に固定する。それぞれ ID、最小、最大、既定、現在値を持つ。アドレスは ID から作る文字列で、別に保存しない
  - `gain`。線形振幅。最小 0、最大 4、既定 1。0 は無音である。4 は約 +12 dB で、フェーダーの上限にする。0 未満と、非数と、4 を超える値は拒否する
  - `pan`。-1 が左、0 が中央、1 が右。最小 -1、最大 1、既定 0。この外と非数は拒否する
  - `mute`。0 か 1 だけ。既定 0。1 がミュートである
  - `solo`。0 か 1 だけ。既定 0。1 がソロである
- 現在値の同一性は、`f32` のビットで見る。プロジェクトが `Eq` のままになる。アクションは、クリップのゲインと同じくビットを保存する
- 正規化した 0〜1 は保存しない。変調が要るときは `(現在値 - 最小) / (最大 - 最小)` でその場で作る。`mute` と `solo` は 0 と 1 の段なので、この割り算の対象にしない
- 変更は `param.set` である。引数はパラメータの ID と現在値である。範囲の外は拒否する。ビットが同じなら差分は空である。トラックを足すアクションは、今までどおり実行時に ID を埋める。トラックの ID に加えて、デバイスと 4 つのパラメータの ID も記録するので、再生は ID を推測しない
- ChangeSet では、デバイスとパラメータをオブジェクトとして作る。パラメータの更新は現在値だけである。範囲と既定は、作成のときに決まり、`param.set` では変えない
- トラックの JSON に `devices` を足す。中身は `id`、`kind`（`mixer`）、`parameters` である。パラメータは `id`、`key`、`min`、`max`、`default`、`value` で、上の順に書く。数値は、クリップのゲインと同じく、0 と 1 と -1 と 4 を短い十進で書く。スキーマ番号は 1 のままである。このフィールドの無いパッケージは、このリポジトリに無い
- 不変条件は、各トラックがミキサーを 1 つだけ持ち、4 つのキーがこの順で、値が範囲の中にあり、ID がプロジェクト内で重複しないことを見る
- オフラインの書き出しは、トラックのミキサーから `TrackFader` を作る。既定のトラックは、今の無指定と同じく、振幅 1、中央、ミュートなし、ソロなしである。ソロとミュートの優先は ADR 0012 のままである
- API は `param.set` を、パラメータの ID と値で受ける

## 結果

`make check` が通った。フェーダーを 0 にすると保存したパッケージでも 0 のままで、Undo で 1 に戻る。API の `param.set` でも同じ操作ができる。0 のトラックは書き出しで無音になり、1 のトラックは今までどおり鳴る。パン、ミュート、ソロは、フェーダーを変えても動かない。
