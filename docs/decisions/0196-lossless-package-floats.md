# ADR 0196: パッケージの浮動小数点を精度を落とさず保存する

- 日付: 2026-10-29
- 状態: 採用
- 対象: トラック JSON の配置ゲインとミキサーパラメーターの `f32` 表記
- 置換: [ADR 0022](0022-clip-content-and-placement.md) の小数点以下 9 桁への無条件の丸め

## 発見と再現

開始時の HEAD は `57f61af`。
クリップの値軸と直交するドラッグ・解放時の原点復帰の回帰を追加したところ、保存往復で別の不具合を発見した。
ドラッグ中と確定後は最小の正の Float を保持するが、閉じて再オープンすると 0 になった。
これは新しいドラッグ不具合ではなく、既存のパッケージ書式による精度損失である。

`document.rs::format_gain` は `f32` を小数点以下 9 桁に丸め、末尾の 0 を落としていた。
`1e-12` や非正規化数は 0 になり、`0.00012345679` のような値でも下位ビットが変わる。
同じ formatter が配置のゲインと全ミキサーパラメーターへ使われ、負のパンも影響する。
ジャーナルはアクションの浮動小数点ビットを保持するため、ジャーナルの往復だけでは見つからない。

Rust の `float_roundtrip` を先に追加し、製品アクションから実パッケージの保存・読出しへ通した。
終了コード 101 と `package save must preserve the exact clip gain bits` の照合で red を確認した。
一時ログの所在は `target/focused-checks/package-float-red/`。
コンパイル失敗や、初期値を再設定した no-op の拒否はこの red の根拠に含めない。

## 決定

- 旧表記を `f32` として読み戻し、元の値と一致する時だけ、その表記を維持する。
  `0`・`1`・`0.100000001` など、既に正確だった保存バイトの不要な差分を避ける。
- 一致しない時は Rust 標準の `f32::to_string` で元の値へ戻せる十進表記を使う。
  独自の十進変換や依存ライブラリは追加しない。
- 0 と負の 0 を `0` とする既存の正規化は保つ。
  モデルが拒否する NaN・無限大を受け入れる変更ではない。
- JSON の数値とフィールドの意味は変わらず、既存リーダーでも読めるためスキーマは 6 のままとする。
  旧ファイルもそのまま読み、新たな書込みだけを精度を落とさない表記へする。
- 保存済みの丸め誤差から元のビットを推定・復元しない。
  既に 0 などへ変わったファイルの自動修復は対象外である。

## 回帰と保守

- `package-float-roundtrip` は非正規化数・最小の正規化数・小さい通常値・通常のゲイン・上限と負のパンを扱う。
  Undo / Redo、ジャーナル、ディスク往復のビット一致と、再保存時のバイトの安定性を確認する。
  負の対照は旧表記の無条件採用へ戻す誤りとする。
- formatter の通常回帰は、符号・指数・仮数の異なる決定的な標本を JSON として読み戻す。
  標本数は検査の範囲であり、製品の値やトラック数の上限ではない。
- `clip-drag-identity-ui` は実 View・controller・ABI から、ゲインの横ドラッグとフェードの縦ドラッグを通す。
  一度変更してから元の値軸で離す場合も、Float・端数 flick・クリップより長いフェードを完全に保持する。
  Redo の実行と保存再読込も確認し、ゲイン／フェードの恒等分岐の削除と解放時の再計算漏れを別々の負の対照にする。
- 検査登録・選択回帰・既存 Makefile 入口、資料の入口・現状・保存設計・開発・診断手順を更新する。
  新しいアクション・ABI・ログ形式は不要で、診断の収集範囲も変わらない。
- 音声処理・RT 経路・描画は変えない。
  実画面の操作感・VoiceOver・聴感・実機の性能はユーザー担当とし、自動回帰と区別する。

## 回帰の補強: 製品の自動保存と履歴復帰

直接の `write_package` だけでは、文書ワーカーの増分保存・コミットの読出し・履歴復帰を保証できないため、既存の必須契約を拡張した。
追加の製品不具合を確認した変更ではなく、ADR 0196 の修正を通す経路の補強である。

- `DocumentHost::perform` で配置ゲインとミキサー値を変え、全標本で公開値と自動保存後のビットを比較する。
- 別トラックの追加後も、元のトラックの値と保存バイトが変わらないことを確認する。
- 終了後に作業ファイルだけを古い有効な状態へ戻し、再オープンが作業ファイルではなくコミットから正しい値を復元することを確認する。
- 保存した版への `history.restore` と、その Undo / Redo・再オープンでもビットを比較する。
- 自動保存の完了は `revisions()` の待合せを使い、sleep・性能閾値・実機は使わない。
  プロセスの強制終了・保存途中の破断・実機の聴感を新たに確認する検査ではない。
- 検査の選択は既存の `package-float-roundtrip` と `check-product-contracts` の入口を保つ。
  診断は失敗した境界名と、ゲイン・ミキサーのどちらのビットが違うかを表示する。
