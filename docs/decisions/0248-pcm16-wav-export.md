# 0248. CLI の 16 bit PCM WAV 書出し

日付: 2026-11-03
状態: 採用（P2-08 の CLI 先行分。ディザ・画面・設定保存は含めない）

## 背景と再現

[ADR 0247](0247-pcm24-wav-export.md) の後も、CLI は 16 bit PCM を選べなかった。
FCA-16 の残る形式対応のうち、今回は標準的なステレオ PCM16 の符号化だけを追加する。
`5866001` に実 CLI の `pcm16_cli_exports_stereo_silence_at_multiple_rates_and_block_boundaries` を追加し、
`--format pcm16` が形式エラーで拒否されることを先に確認した。
終了コード 101 と回帰固有の `PCM16 CLI export failed: ... expected wav format` を照合した。

## 決定

- `echode render PACKAGE WAV --format pcm16` を追加する。
  符号付きリトルエンディアンの 16 bit ステレオ PCM を、標準の 16 バイト `fmt`・形式コード 1 で出す。
  拡張・`fact`・チャンネルマスクは付けない。ヘッダは 44 バイト、フレームは 4 バイトである。
- 24 bit の WAVEFORMATEXTENSIBLE と float の WAVEFORMATEX / `fact` は変えない。
  CLI の省略時と公開 Rust 関数 `render_to_wav` / `write_wav` は float を保つ。
- PCM の量子化は書込みの境界だけで行う。PCM16 は `sample × 2^15` を最近接整数へ丸め、半整数はゼロから遠ざける。
  `-32768..=32767` へ飽和し、範囲外の有限値を折り返さない。
  PCM24 と同じ f64 演算を使い、16 / 24 bit の符号化を共通化する。
- 非有限値は `non-finite sample in PCM16 export` として拒否する。
  ディザ・ノイズシェーピング・ノーマライズは加えず、低レベルの量子化誤差を消すとは扱わない。
- RIFF 長はデータ長に 36 を足し、データ長・RIFF 長・バイトレートをファイル生成前に検証する。
  一時ファイル・flush・ファイル同期・rename・親の同期は既存経路を共用する。
  公開前の失敗では原本を保ち、公開後の親の同期失敗では完成ファイルを残して耐久性不明を返す。
- 既存 WAV ライターの符号化追加であり、新しい音源・DSP・RT 処理は導入しない。
  追加の形式ライブラリは使わず、既存の独立した AudioToolbox 読込みで互換性を確認する。

## 回帰と基盤

- `tests/pcm16.rs` は実 CLI の空・短い・完全／部分ブロックと 44.1 / 48 / 96 kHz の形式・長さ・無音を検査する。
  配置した左右非対称の音声と隔離 Sine Pad を float と比較し、飽和後の誤差を半 LSB 以下に制限する。
  同じ出力を製品の `decode_audio_file` でも復号し、率・左右・フレーム数・全サンプルを照合する。
- `src/wav_tests.rs` は全 65,536 整数のバイト列、半 LSB、符号付きゼロ、フルスケールと極大値を検査する。
  複数の入力分割でファイル全体の一致を確認する。エンジンの音生成は変更せず、分割独立性はライター側で検査する。
- ヘッダだけで RIFF とバイトレートの境界を検査し、大容量の音声を確保しない。
  非有限値と書込み・flush・rename・親の同期の故障注入を PCM16 / PCM24 の双方へ適用する。
- README、P2-08、設計、制約、監査の参照と WAV のデバッグ手順を更新する。
  新規テストは既存の通常 CLI テストに含まれ、Makefile と `scripts/verification.json` の入口・選択は変更不要である。
  エラーは既存の形式別診断を使い、ログ・収集先・実機の再生経路は変えない。
