# ADR 0183: 古い保存版への復旧を通知し、同意まで編集を止める

- 日付: 2026-10-28
- 状態: 採用
- 対象: [敵対的監査](../reviews/2026-10-27-adversarial-audit.md) ADV-02、DocumentHost・C ABI・Swift

## 背景

[ADR 0033](0033-journal-log.md) は、壊れた先端を飛ばし、読める祖先と連続したジャーナルから復旧する。
短縮済みのジャーナルからは失われた編集を戻せないが、その後退がアプリへ伝わっていなかった。
古い状態を通常の文書として公開すると、利用者が気づく前に次の自動保存で先端が進む。

## 決定

- 復旧開始時の先端と、実際に読んだコミットを同じ復旧結果に持つ。
  両者が違う時だけ `RecoveryNotice` に先端 `tip`・基点 `base`・復旧済み連番 `applied_seq` を載せる。
  先端の後へ正常なジャーナルを再生しただけの場合と、初回保存は警告しない。
- `DocumentHost` は同意待ちの間、単一編集・一括編集・Undo / Redo・プラグイン状態の記録を拒否する。
  エラーには先端と基点と連番、原本のコピーを保全する案内を含める。
  C ABI はスナップショットの `historyReport.recovery` で通知し、音声・デバイスの要求も拒否する。
- 同意は `history.accept_recovery` に、表示した `tip` と `base` をそのまま返す。
  別の復旧結果への同意は拒否し、同じ文書での再送は新たな保存を作らない。
  通常の編集や Undo として扱わず、保存形式も変えない。
- 同意時は、復旧した状態を同期的に新しい保存点へ記録し、既知のジャーナル連番まで短縮してから編集を解放する。
  次の連番はディスク上の既知の連番と復旧済み連番の両方より後に置く。
  保存に失敗したら同意待ちを保ち、成功した編集を不正な先端への再生に依存させない。
  壊れたコミットや素材そのものを修復する操作ではない。
- 保存点の親は以前の先端のまま保ち、壊れた履歴を黙って書き換えない。
  履歴一覧は読めないコミット本体を飛ばし、記録済みの親の情報で読める祖先へ続ける。
- Swift は新しい文書を公開・出力準備する前に警告し、確認中は既存文書と表示を保持する。
  最近の編集が欠け得ること、キャンセルしてコピーを保全すること、続行が新しい保存点を作ることを日英で示す。
  キャンセル・タスクの取消・表示の破棄では新しいホストを閉じ、元の文書と壊れた先端を保つ。
  順序付き編集タスクへ、開く要求ごとの取消を明示して渡す。遅れた取消は別の確認を閉じない。
- CLI / API / MCP に同意の入口は追加しない。
  後退したホストの読み取りは可能だが、編集は上のエラーを返す。
  原本を保全してアプリで確認してから、ヘッドレスの書き手を開き直す。
  低レベルの読み取り用 `recover` が祖先を選ぶ規則は変更しない。

## 再現と回帰

A を保存し、次に B を追加して保存したパッケージで、先端コミットのオブジェクトだけを削除する。
修正前の製品 C ABI は A だけの文書を返し、スナップショットに復旧の通知がなかった。
`checked_commands.py` で終了コード 101 と
`recovery fallback must be reported before editing` の固有アサーションを照合した。
当時の出力は `recovery.tip` が null、期待値は削除した先端の ID だった。

`recovery_tests.rs` は通知・全編集入口の拒否・取消時の原本保持・誤った確認・保存失敗からの再試行を通す。
確認の冪等性・履歴一覧・確認直後の再オープン・その後に確定した編集の保持も検査する。
`RecoveryConsentTests` は製品ブリッジで同じ破損を作り、公開前の確認・取消・旧文書の保持・単一履歴を確認する。
タスク取消は別の通常回帰で、待機とパッケージのロックが解放されることを確認する。

必須契約 `recovery-consent` は通知の判定と書込み禁止をそれぞれ外す負の対照を持つ。
`recovery-consent-ui` はキャンセルを無視して続行する負の対照を持つ。
既存の `check-product-contracts` と検査選択の回帰へ登録し、新しい Makefile ターゲットは不要である。
実行結果は検査レポートへ記録する。

## 診断と対象外

先端・基点・復旧済み連番を警告またはエラーから記録し、コピーを保全してから破損の原因を調べる。
[デバッグ手順](../debugging.md) に案内を加える。新しいログ形式やユーザー文書の自動収集は追加しない。
機器なしの自動回帰と、実画面の警告・キャンセルの操作感・VoiceOver は別の証拠である。
後者はユーザー確認待ちとし、音声機器・第三者プラグイン・開いているアプリは操作しない。
