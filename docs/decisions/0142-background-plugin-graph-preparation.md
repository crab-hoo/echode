# ADR 0142: 開いた出力の置換ヘルパーを文書ワーカー外で準備する

- 日付: 2026-10-21
- 状態: 採用。P2-02 の応答性の追加受入の一部。実機の操作感と聴感はユーザー確認待ち
- 範囲: 出力を開いた後の FX 追加・コピー・オフライン解除などによるプラグイングラフの置換

## 背景と再現

[ADR 0136](0136-output-opening-off-worker.md) は初回の出力準備を別スレッドへ移したが、
開いた出力への `Session.update` → `OutputStream.replace` → `PlaybackControl.publish_pending` は、
文書ワーカー上で `HostGraph.reconcile` を呼び、新しいヘルパーの初期化を待っていた。
[ADR 0102](0102-exclusive-audio-graph.md) により音声は旧グラフで続くが、後続の編集・履歴・停止の手番は戻らない。

実 CLAP の `prepare-wait:<socket>` で新しいヘルパーの初期化を保留した。
修正前は `replace held the control turn: Timeout` で失敗した（`target/background-graph-before.log`）。
時間の速さではなく、初期化の解除より前に制御操作が完了する順序を受入条件とする。

## 決定

### 音声側を借りず、制御用カタログだけを渡す

- 初回の出力導入後、`PlaybackControl.prepare_in_background` を有効にする。
  オフライン書出しと初回の準備は従来の同期経路を保つ。
- 次の計画のイベント領域と素材を用意し、公開キューに空きがあり、既存の共有領域の採用が済んだら、
  制御用 `HostGraph` と対応する `Pending` を `echode-graph-prepare` スレッドへ渡す。
  ヘルパーの起動・状態復元・共有領域の準備をそこで行う。
- 音声側は既存の排他所有グラフで処理を続ける。
  準備スレッドは音声側のグラフやトランスポートのキューを所有しない。RT 区間へ確保・ロック・新しい待ちを加えない。
- 文書ワーカーは終了済みのスレッドだけを回収し、計画と音声グラフを従来の単一 `Update` として公開する。
  準備の開始時に確保したキューの空きは、この制御側だけが生産するため結果の公開まで残る。
- 並行する準備は 1 件とし、その間の後続編集は最新の `Pending` へ集約する。
  進行中の計画を公開した後に最新の計画を準備する。既に公開した計画と同じく、過渡的な旧版の採用はあり得る。
  追加後の削除・Undo も最終的に最新モデルへ収束し、文書の選択や削除済みの表示を戻さない。
- ループだけの更新が、進行中または待機中のモデル編集の状態復元を落とさないようにする。
  同じプロセス・デバイスの音声側の発音状態は、従来どおり `Arc::ptr_eq` で引き継ぐ。

### デバイス要求と状態の寿命

- 準備中も、既存ヘルパーの制御端点・活動通知・背景保存の確認は保持する。
  新しいデバイスの制御端点がまだなければ `DeviceAccess::Opening` とし、既存の FFI の投入順の待ち行列へ渡す。
- `Session.opening()` は初回または置換の準備を待つ判定に使う。
  JSON の `AudioState.opening` は初回出力だけ、置換の未反映は従来の `pending_plan` と区別する。
- 投入時点で記録済み状態が一致した既存ヘルパーを保持対象として固定する。
  初期化待ちの間に同じヘルパーで Undo や値の保存が進んでも、準備時の古い値で再生成しない。
  後続の状態だけの編集は既存ヘルパーへ復元し、準備中なら最新のモデルと経路も次の計画へ載せる。
- 失敗時は未公開の共有領域を取り消し、非同期の準備エラーを既存の出力制御へ返す。
  準備を自動で繰り返さない。通常のエラー処理は出力を閉じ、後続の明示操作で再準備する。
- 初期化の途中を中断する手段は加えない。文書終了・機器交換でこの出力を閉じる時は準備の終わりを待つ。

## 検査と診断

- 必須契約 `background-graph` は実ヘルパーの初期化を保留し、置換・状態取得・後続編集・Undo/Redo・停止の順序と、
  既存音声・時計の継続、最後の削除までの計画交換を確認する。同期の準備へ戻す負の対照で拒否する。
- 同じ実ヘルパーの回帰で、準備中の状態復元とループ変更が既存ヘルパーを再生成せず、最新バイトを保つことを確認する。
  一致状態の保持を外すと、古い制御端点の読取りが `BrokenPipe` で失敗した（`target/background-graph-state-before.log`）。
- Session の機器なし回帰で、製品の導入後に非同期置換が有効になり、新しいデバイスの要求が待つこと、
  Undo・ループ・停止の後に最新計画へ収束し、出力を開き直さないことを確認する。
  初回だけを待つ検査は `AudioState.opening` を使う。コールバックのない出力で `Session.opening()` の全置換を待つと、計画を採用できず待ち続ける。
  ヘルパー実行ファイルのないサニタイザー用ビルドでは、テストが未解決の経路とホストの場所を明示する。
  その実行ファイルをプラグインとして読み込まず、実ヘルパーの起動待ちは別の必須契約で検査する。
- 単体回帰で準備失敗が一度だけ返ること、未反映が解消され、後続の正常な置換が可能なことを確認する。
  DSP は変えないためブロック長の比較は既存の製品回帰を維持し、実ヘルパーの新契約も RTSan の対象にする。

### 検査用の初期化待ちソケット（2026-10-29）

波形平均の修正中の `make verify` で、既存の `background-graph` が約 0.09 秒で `WouldBlock` を返した。
5 秒の読込み期限に達した失敗ではなく、Darwin の `accept` がリスナーの `O_NONBLOCK` を受け継ぐ条件だった。
既存の `set_read_timeout` だけではこのフラグは解除されない。

初期化待ちの各回帰は、accept 後に共通の `initializer_peer` でブロッキングへ戻し、従来の 5 秒を設定する。
`accepted_initializer_peer_is_blocking_before_the_handshake_arrives` は、相手がまだ 1 バイトも送らない状態の記述子を検査する。
修正前は終了コード 101 と `initializer peer must block for the handshake instead of returning WouldBlock` で失敗した。
作業時の記録は `target/focused-checks/initializer-peer-red/` に保存した。
最初の製品契約の失敗ログは `target/focused-checks/initializer-peer-verify-failure.log` に保持する。
製品の IPC・処理順序・受入条件・待機期限は変えない。実機の隔離性能の証拠にも置き換えない。

## 残る範囲

- `reprepare` の素材読込み・計画生成と、`OutputStream.replace` の保存済み状態の読込みは文書ワーカーに残る。
  → 停止中の置換の素材読込みは [ADR 0147](0147-output-prewarm-and-background-media.md) で別スレッドへ移した。
  再生中の編集の素材読込みと計画生成は同期のままである。
  → 再生中の編集の素材読込みは [ADR 0330](0330-playing-edit-media-and-tempo-retime.md) で別スレッドへ移した。
  → 保存済み状態の読込みは [ADR 0329](0329-plugin-states-by-name.md) で、新しいヘルパーと状態の変わったヘルパーだけが準備スレッドで行うようにした。
  初回の出力準備中に増えたヘルパーを導入時の差分で作る経路も同期である。
- 同一デバイスへの状態復元（Undo）がそのデバイスの通信を待つ条件、文書終了時の初期化待ちは変えない。
- 置換準備専用のデバイス列の表示は未接続。初回出力の表示（[ADR 0141](0141-device-output-preparation-status.md)）と混同しない。
- 実 HAL、機器変更、第三者プラグインの GUI・操作感と聴感は、機器なしの順序・波形の検査とは別にユーザーが確認する。
