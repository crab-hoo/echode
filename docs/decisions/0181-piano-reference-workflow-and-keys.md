# ADR 0181: ピアノの入力先を分離し、参照ノートとキーボード編集を接続する

- 日付: 2026-10-28
- 状態: 採用。P2-07 の先行分。実画面・VoiceOver・聴感はユーザー確認待ち
- 関連: [操作要件](../interaction-design.md)、[ADR 0117](0117-workflow-interactions.md)、
  [ADR 0134](0134-plugin-window-lifetime-and-shortcuts.md)、[ADR 0174](0174-shared-piano-viewport.md)、
  [ADR 0176](0176-piano-note-selection-and-deletion.md)、[ADR 0178](0178-piano-batch-note-movement.md)、
  [ADR 0179](0179-piano-batch-note-resizing.md)

## 背景と再現

コードを見ながら別トラックにメロディを置くには、アレンジ・デバイスの選択とピアノの入力先を分離する必要がある。
既存の実装はトラック選択変更でノート選択を消し、参照ノートを持たず、複数選択の矢印を送らなかった。
Return は古いノート挿入に割り当てられ、操作要件の一時停止／再開と衝突していた。
実コントローラーと AppKit のキーから、選択保持と Return 転送の失敗を先に確認した。
期待終了コードと固有のアサーションは `target/focused-checks/piano-workflow-red/` に残す。

## 決定

### 単一入力先と明示オープン

- `ProjectController.pianoTrack` をアレンジ・デバイスの `selection` から分ける。
  通常の選択変更はピアノの対象とノート選択を変えない。
  初回のトラック追加、対象の削除、文書交換では現存する対象へ調停する。
- アレンジの空白・MIDI クリップのダブルクリックか、右側の「編集」で対象を明示的に開く。
  `PianoTrackTarget` は文書とトラックを保持し、古い文書の同じ UUID の操作子も拒否する。
  現段階は排他的な単一入力先とし、複数トラック同時編集と編集オフへの切替は後続へ残す。
- ダブルクリックは位置も `PianoLocation` として渡すが、再生ヘッド・記憶した開始位置・Undo を変えない。
  `CanvasNavigationState.pianoLocationID` で一度だけ消費し、その後の手動スクロールを再生成時に上書きしない。
  単なる対象切替では既存の共通時間・音域・倍率を保つ。
- 下書きとノート選択の検証にはピアノの対象を使う。
  インスペクターのトラック・デバイスはアレンジ選択のままとし、別トラックのノート値をその欄へ混ぜない。

### 参照ノートと右側の一覧

- 初期状態は他の全トラックを参照表示する。文書内だけの `hiddenPianoTracks` で非表示を記憶する。
  表示の値は入力先自身の編集ノートを隠さず、対象切替後にそのトラックが参照になった時に使う。
  保存・Undo・音声状態を変えず、文書交換で初期化する。
- `PianoRenderInput.references` から可視の時間・音域だけを問い合わせる。
  `PianoFrame.referenceNotes` を通常ノートより先に薄い色で描き、発音窓外の隠れたノートは表示しない。
  入力・描画の鮮度照合にも参照一覧を含める。
- ヒット判定・枠選択・ベロシティレーン・読み上げのノート要素へ参照を渡さない。
  参照だけの場所は現在の入力先の空白として扱う。同じ位置の編集ノートは通常どおり優先する。
- 右側は行を再利用する `NSTableView` で、表示・編集・Solo・Mute を独立した名前付きボタンにする。
  モデル値を行へ渡して表示状態の変化を観測し、行が変わらない再生位置の通知では一覧を組み直さない。
  Solo/Mute は待機列の現行値から `param.set` を送り、通常の Undo / Redo・保存を使う。
  トラック数に上限は設けず、実表示の行だけをネイティブ表に作らせる。

### 矢印と Return

- `PianoStep` は選択 ID と時刻差・音程差・右端伸縮の意図だけを保持する。
  `enqueuePianoStep` がネイティブイベント順を同期的に捕捉し、編集の手番で現行スナップショットから幾何を計算する。
  未反映のキーリピートが古い絶対幾何を再送して、前の操作を取り消すことを防ぐ。
- 上下は半音、Option＋上下はオクターブ、左右は現行グリッド幅、Shift＋左右は右端伸縮とする。
  時刻 0・MIDI 音域・整数上端・最短 1 tick の共通境界で選択全体を止め、相対間隔を保つ。
  全対象を検証し、リンクした同じ内容のノートは一度だけ編集する。失敗は既存トランザクションで全体を戻す。
  各キー入力が 1 回の Undo となり、無変化では履歴を足さない。
- 一括操作では両入力記憶と選択を保つ。単一ノートの右端伸縮だけは従来の入力長記憶を使う。
  ドラッグ中・文書交換中の矢印は送らない。モデル・アクション・DSP は追加しない。
- Return は共通の Pause コマンドへ割り当てる。ピアノは Return とテンキー Enter をレスポンダーへ渡す。
  Return の挿入との衝突を保留した [ADR 0155](0155-remembered-playback-start.md) の判断を、この割当で更新する。
  ヘルパーの物理キーにも Pause を追記し、既存の番号を変えず、既存の転送・リピート抑制を使う。
  入力欄は確定を優先し、サンプル・FX の一覧は `performKeyEquivalent` で配置を先に受ける。
  Space の再生／停止とは区別し、一時停止は現在位置から再開する。

## 受入と基盤

- `piano-target-ui`・`piano-arrange-open-ui` は独立対象、実アレンジの明示オープン、位置の一度だけの消費と旧文書拒否を確認する。
- `piano-reference-ui`・`piano-track-selector-ui` は背面描画、編集ノート優先、参照上の入力、実ボタンと履歴・保存・旧操作子の拒否を確認する。
- `piano-key-step-ui`・`piano-key-step-bounds-ui` は実矢印とキーリピート、選択全体、リンク、共通境界、入力記憶、単一 Undo / Redo・保存を確認する。
- `piano-return-ui`・`browser-return-ui` と既存の `plugin-key-events`・`plugin-key-socket`・`plugin-key-ui` はキーの経路を分けて確認する。
  各追加契約に欠落・誤入力先・参照の混入等の負の対照を登録し、選択の回帰も更新する。
- `spike-piano-frame` は製品 Metal エンコーダーの倍率 1・2 の参照色・編集優先と鍵盤・ベロシティへの非混入を読む。
  `checkedReferenceNotes` を既存レポートへ追加する。収集先・機器・外部入力は増えず、診断収集の追加は不要である。
- 利用手順・現状・Phase 2・操作要件・領域設計・デバッグ手順を更新する。
  Makefile の既存の通常検査・必須契約・オフスクリーン検査の入口を再利用し、選択対応は `verification.json` にだけ置く。
  アクションと音生成は変えないため、履歴の操作生成とブロック長回帰の追加は不要である。
- 実画面の一覧の幅・フォーカス・IME・Return のメニュー優先・キーリピート・VoiceOver と聴感はユーザー確認とする。
  ノート試聴、複数トラック同時編集、Command 複製移動、ドラム入力、録音・マーカー等は別単位であり、P2 全体の完了とはしない。
