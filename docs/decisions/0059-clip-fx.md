# ADR 0059: クリップごとに独立した FX チェインを持つ

- 日付: 2026-10-13
- 状態: 採用（計画への追加。実装は Phase 2）
- 範囲: オーディオと MIDI のクリップ FX。プレビュー用キャッシュとフリーズへの統合は Phase 3。テイクレーンとコンピングは PLAN §5 のまま

## 背景

同じトラックの特定のフレーズだけに EQ、ディレイなどをかけたい。REAPER の Item / Take FX は、トラック内のメディアのテイクごとに独立したチェインを持ち、クリップ上から開いたり、ブラウザから直接追加したりできる。テイクごとに設定を変え、FX の結果を新しいテイクとして書き出すこともできる（[公式ユーザーガイド](https://www.reaper.fm/userguide.php)の「Per Item FX」「Using Item FX with Individual Takes」「Render items as new take」、[ReaScript API](https://www.reaper.fm/sdk/reascript/reascripthelp.html)の `TakeFX_CopyToTake`、`TakeFX_GetEnvelope`）。

Echode はクリップの中身と配置を分け、リンクした配置で中身を共有する（[ADR 0022](0022-clip-content-and-placement.md)）。FX を中身に置くと、同じ素材を使った別の配置まで音が変わる。自動配置はノートの編集で結合・削除されるため、FX の設定を守る規則も必要になる。

## 決定

- 製品上の名前は「クリップ FX」とし、Phase 2 のデバイスビュー、オートメーション、PDC と一緒に実装する。オーディオ FX、MIDI FX、楽器を扱い、CLAP / VST3 / AU と内蔵デバイスの共通の抽象を再利用する
- 配置がチェイン・パラメータ・状態・FX の曲線を持つ。リンクした配置同士でも独立する。移動は ID を保ち、複製と分割は状態と曲線をコピーして新しい ID を振る。実行中のインスタンスは共有しない
- クリップごとに FX を処理してからトラックへ合流し、トラック FX を処理する。MIDI のクリップは、MIDI FX の出力をトラックの楽器へ送るか、クリップ内の楽器でオーディオにして後続の FX に渡す
- FX の曲線は内容時刻で持ち、移動に追従し、トリムと分割で素材との位置関係を保つ。パラメータのアドレスは `clip/<id>/device/<id>/param/<id>` とし、所属トラックの変更で変えない
- 最初の FX の追加で自動配置を固定にする。追加と固定は同じ Undo 単位で、FX の削除だけでは自動配置へ戻さない
- 追加・削除・並べ替え、パラメータ編集、バイパス・オフライン化、チェインのコピーとプリセットを、アクション、Undo / Redo、ジャーナル、API へ通す。配置の保存形式は実装時に移行し、旧版は空のチェインとして読む
- プラグインはトラック FX と同じ隔離方針でヘルパーに置く。PDC はクリップの合流点も含め、終端後の余韻を次のクリップと加算する。コールバックは準備された実行計画を読み、全クリップの走査やインスタンスの起動・解放をしない
- Phase 2 のバウンスでは、クリップ FX と余韻を新しいオーディオの中身・配置へ書き出す。トラック FX は含めず、結果のチェインは空にする。余韻を含む結果が既存の配置と重なる場合は別トラックへ取り込み、配置の重なりを禁止する現行モデルを守る。元の素材とチェインは履歴に残し、Undo で戻せる
- Phase 3 のトラックのキャッシュとフリーズには、クリップ FX と余韻を含める。別のクリップ単位の自動キャッシュは、この追加では作らない
- 将来の複数テイクでは、配置内の各テイクが独立した FX を持つ形へ拡張する。Phase 2 の単一テイクのチェインをそのまま移行できるようにする

## 実装前に決めること

ゲイン・フェードと FX の処理順、シーク時の先行処理、ループでの状態の引き継ぎ、未報告・無限テールの既定長と停止方法を、内蔵デバイスとテスト用プラグインで検証して記録する。途中からの再生や分割で状態を持つ FX の音が変わる条件も明らかにする。これらの詳細を REAPER と同じと仮定しない。

## 完了の条件

- クリップ FX が同じトラックの別のクリップには直接適用されず、オーディオ FX、MIDI FX、クリップ内の楽器がそれぞれ正しい信号を受ける
- 移動・複製・分割・リンクした配置で、ID、状態、曲線の時刻、独立した編集を確かめる。FX の追加で固定され、自動結合・削除で設定を失わない
- 余韻の重なり、PDC、バイパス・オフライン化、シークとループ、クラッシュとハングを検査する。同じヘルパーの障害の影響範囲と、他のヘルパーが処理を続けることも確かめる
- 再生・CLI の書き出し・バウンスを比較し、決定的なテスト用デバイスではブロック長を変えて音が一致する。第三者のプラグインがブロック長や乱数に依存する場合は、その制約を記録する
- 不変条件、Undo / Redo、保存と読み込み、旧スキーマの移行、ジャーナル復旧をランダムな編集列でも検査する。Phase 3 ではキャッシュの無効化とライブとの一致も検査する

この変更は計画と設計だけで、モデル、アクション、保存スキーマ、再生経路の実装は変更しない。新しい検査は実装時に Makefile と `scripts/verification.json` に登録する。
