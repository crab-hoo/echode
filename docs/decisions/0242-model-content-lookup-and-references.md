# ADR 0242: 内容の二分探索と参照の一括照合

- 日付: 2026-11-03
- 状態: 採用
- 対象: FCA-05 のうち、内容の探索、参照の照合、読込みの重なり検証。
  ID 重複の探索と、変更した配置だけによる参照の更新は残す。FCA-05 全体の完了ではない。

## 背景と再現

[コード全体の監査](../reviews/2026-11-03-full-code-audit.md) は、内容ごとに全配置を調べる処理と、クリップごとの内容の線形探索を指摘した。
`try_assemble` は内容を ID 順にしていたが、読込み・不変条件・ノート編集の問い合わせではその順序を利用しなかった。

修正前の製品入口を使う `model_scale_tests` では、次の非時間依存のアサーションが失敗した。

- 256 内容の存在・不存在の 258 問合わせで、内容のキーを 33,408 回比較した。
- 256 クリップの組立てで、内容のキーを 65,792 回比較した。
- 64 配置のうち 1 ノートを編集しただけで、未参照内容の除去が配置を 2,080 回訪ねた。
- 内容の ID 順を逆にしたスナップショットを、不変条件の検査が受け入れた。

意図した red は期待終了コード 101 と、上の問い合わせ回数を示す固有のアサーションを照合した。

## 決定

内容はスナップショットの境界で ID 順とし、その順序を crate の不変条件へ加える。
保存からの組立ては、従来どおり入力の内容を整列する。保存形式・スキーマ・ファイルの並びは変えない。
`Project::content` と配置編集の読み書き、組立て時の参照解決は共通の二分探索を使う。

配置から内容への参照は、一時的な `HashSet<Id>` を 1 回作って照合する。
未参照内容の除去、組立て、不変条件の検査に使い、内容ごとに全配置を走査する積をなくす。
この集合は制御側で作り、スナップショットには蓄積しない。オーディオスレッドへ確保・検査を加えない。
参照数を永続的に持つ方式と違い、すべての編集・履歴復元で派生索引を同期する責務を今回持ち込まない。

組立て時の重なりは、隣り合うクリップの半開区間だけを比較する。
開始順でない入力は、後続の不変条件の検査で引き続き拒否する。編集途中に順序が変わり得る `overlaps_others` は変更しない。
内容数を C、配置数を P とすると、内容の問い合わせは O(log C)、参照の照合は期待 O(C + P)、隣の重なりは O(P) となる。
共有内容のノート検証、トラック階層の検証、編集前後の配列の複製は別の費用である。

## 同条件の計測

Apple M4、release、機器・プラグインなしの `make spike-scale`。両版で同じ計測を実行した。
1 クリップに別々の内容と 8 ノートを置き、最初のノートの音高を 1 回変える。

| トラック × クリップ | 組立て 前 → 後 | ノート編集 前 → 後 |
|---|---:|---:|
| 64 × 64 | 40.49 → 6.85 ms | 8.07 → 0.42 ms |
| 128 × 64 | 167.44 → 14.24 ms | 35.66 → 0.96 ms |

配置数を倍にした時、組立ては約 2.08 倍、編集は約 2.29 倍になった。
単回の経過時間の比較であり、実画面の応答時間・全入力の最悪時間を保証する値ではない。
FCA-04 の再生計画の全体再構築、FCA-14 の保存待ちの解消とは扱わない。

## 回帰と基盤

- `model_scale_tests.rs` は製品の問い合わせ・組立て・編集を使い、キーの比較、参照の訪問、重なりの比較を数える。
  計数は `cfg(test)` だけにあり、release の処理・確保を変えない。
- 存在しない ID、空のプロジェクト、逆順の読込み、順序違反の拒否を確認する。
  編集前のスナップショットと、変えなかった内容の `Arc` の共有を保持する。
- 未参照内容の除去は、別トラックの固定リンクが残る時には内容を保持し、最後の配置が消えた時だけ除去する。
- 既存のモデル全体と履歴の操作生成・保存再読込みの回帰を維持する。新しい編集アクション・音声生成は追加しない。
  通常の crate テストで実行されるため、Makefile と検査の選択規則を追加する必要はない。
- [デバッグ手順](../debugging/saving-history-and-api.md) に、モデルの時間と計画・保存の時間の切分けを足す。
  新しいログ形式・収集先はなく、既存の `spike-scale.json` を使う。

## 残る範囲

`id_in_use` はノート・デバイス・パラメーターを線形に探し、参照集合も編集ごとに全配置から作る。
ノートの編集で生じる全内容と全配置の積は除いたが、変更した配置だけの差分更新や、ID の索引化を実装したものではない。
これらは FCA-05 の残りとして別の単位で扱う。実機の操作感や聴感は今回の変更では確認しない。
