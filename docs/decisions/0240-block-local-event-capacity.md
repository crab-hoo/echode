# ADR 0240: イベント容量をブロック内の密度から求める

- 日付: 2026-11-03
- 状態: 採用
- 対象: FCA-03。[監査の W2](../reviews/2026-11-03-fix-instructions.md) の先行分であり、FCA-04・05・10 は残す。

## 背景

`track_event_demand` は全ノートの 3 倍を通常イベントに、全ノート数を追いかけに予約していた。
ループ内のノートを数える処理では、加算済みの総数まで周回数倍する誤りもあった。
長い楽譜の疎なトラックでも親の作業領域とヘルパーの固定した共有領域が膨らみ、編集で領域を交換した。
修正前の製品入口による再現は、64 ノートで 257 件、2,048 ノートで 8,193 件を予約して失敗した。

## 決定

容量の計算は制御スレッドの `playback_capacity.rs` に分離する。
トラックの開始順と終了順を併合し、幅 `frames` の半開窓に入る端の最大を求める。
同一サンプルでは終了を開始より先に扱い、最大の重なりを追いかけと位置移動時の発音停止に使う。
この前計算はノート数に線形で、コールバックに探索・確保を足さない。

### ループと容量の余裕

ループ内の端と、終端でまだ鳴っている声のノートオフを、1 周の円環に載せる。
終端のノートオフはループ先頭に正規化する。終端ちょうどのノートと、ループ前から追いかけた声も含める。
完全な周回は端の総数との積、余りは円環を 2 周だけ走査する窓の最大で求める。
短いループのためにノート列を何百回も複製せず、時間算術は `i128`、容量算術は検査付きにする。

ループ前から入るブロックを落とさないよう、通常窓の最大と円環窓の最大を足す保守的な上界とする。
両方の最大が同じブロックで生じるとは限らないので、最小の予約数を主張しない。
長さではなく密度と同時発音数に依存し、トラック・ノート・周回数の固定上限は置かない。

### 旧計画の解放

新しい楽譜の重なりだけでは、大きな和音の削除やトラックの削除時のノートオフを収められない。
`PlaybackControl` は直前に公開した計画のトラックごとの重なりを保持し、次の公開の準備で解放分を加える。
プラグインなしとキャッシュ済みトラックも含め、トラックが消えた時も親のイベント領域を確保する。
残るトラックのヘルパーへの入力にも同じ余地を足す。

背景の準備を待つ間に古い計画が公開されることがあるので、この計算は背景準備の回収後に行う。
領域の採用待ちで再試行しても予約を繰り返し加算しない。
旧計画の解放用の余地は最新の公開計画から取り、プロジェクトの過去の最大ノート数は蓄積しない。

### 共有領域

通常イベントと追いかけを足した容量を、検査付きで次の 2 のべき乗へ切り上げる。
既存の共有領域が収められる時は `prepare_mapping` を呼ばず、増える時だけ二段階で交換する。
ヘルパーの処理・状態・発音を作り直さない [ADR 0102](0102-exclusive-audio-graph.md) の所有権を保つ。

同じヘルパーの領域は縮めない。必要な密度が一度大きくなれば、その容量はヘルパーの寿命まで残る。
低水準の共有領域そのものは従来どおり縮小もでき、その隔離回帰は保持する。
`plugin_event_caps()` は各トラックの最大の共有入力容量を返すようにし、親の一時バッファだけの値と区別する。
容量を超えた時の `BufferTooSmall` と `dropped_events` による失敗は維持し、黙って捨てない。

## 回帰と基盤

- `audit_fca03` の ignore を外し、ノート数を 64 から 2,048 に増やしても親の予約数が同じことを固定する。
- `playback_capacity_tests.rs` で同時刻の端、和音、空の計画、極端なサンプル位置、ループの前後、1 サンプルのループを確認する。
  小さい標本範囲の全着地とブロック長を、製品の `split_loop` と継続カーソルへ通し、追いかけとイベントが収まることを確かめる。
- トラックを全削除する製品再生と、隔離ヘルパーで 64 声をまとめて削除する回帰を足す。
- `hosted_playback/event_capacity.rs` は 2 ノートと 2,048 ノートの共有容量がともに 4 件であること、和音で拡張した後は縮めないことを確認する。
  発音とノートオフの累積数も音声バッファから読み、重複・欠落・ヘルパーの作り直しを区別する。
- 従来の連続した容量変更の回帰は、遠いノートの追加ではなく将来の和音の増減にする。新方式でも実際に領域の拡張・採用待ちを通す。
- `under_rtsan` の隔離回帰と通常のエンジンテストを既存の選択経路で実行する。検査の追加入口や選択規則は不要である。
  音声生成・モデル・保存形式は変えず、既存のブロック長比較と必須契約を維持する。
- [デバッグ手順](../debugging/audio-and-plugins.md) に、容量と密度の切分けを追加する。

## 同条件の計測

Apple M4、48 kHz、128 フレーム、release、機器・プラグインなしの `make spike-scale`。
前は [ADR 0239](0239-live-note-cursor-work.md) の記録、後は本変更で実行した同じ計測である。
256 トラック × 4,000 ノートの再生中の編集 20 回を測った。

| 項目 | 前 | 後 |
|---|---:|---:|
| 親のイベント予約 | 4,096,001 件 | 1,537 件 |
| 作り直し p50（100 ブロック後） | 約 263 ms | 239.6 ms |
| 採用 p50 / 最大（同上） | 2,103.5 / 2,477.4 µs | 2,051.2 / 2,145.0 µs |
| 採用 p50 / 最大（3,500 ブロック後） | 1,855.0 / 2,125.2 µs | 1,756.1 / 2,164.1 µs |

予約は約 99.96% 減ったが、これは予約件数でありプロセス全体の常駐メモリの測定ではない。
全体の計画・カーソルの作り直しは残り、制御側の時間の大きな改善や FCA-04 の完了とは扱わない。

機器なしの `spike-plugin-tracks` では、256 ヘルパーの通常 / 折り返し / 採用の CPU p50 は 933.4 / 1,129.5 / 1,599.8 µs だった。
同じ順の実時間最大は 3,054.0 / 2,159.1 / 2,752.6 µs。待ちの期限は 1 秒で、実際のブロック期限での完走や聴感の証拠ではない。
実機・第三者プラグイン・聴感は既存の UC-47 に残し、検査の見送り理由は検査レポートへ記録する。
