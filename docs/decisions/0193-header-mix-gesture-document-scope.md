# ADR 0193: ヘッダの値操作を押下した文書とコールバックへ束縛する

- 日付: 2026-10-29
- 状態: 採用。実画面・VoiceOver の文書切替はユーザー確認待ち
- 関連: [ADR 0153](0153-value-control-clicks-and-typed-entry.md)、
  [ADR 0191](0191-selected-track-numeric-mix.md)、[ADR 0192](0192-selected-track-accessibility-steps.md)

## 背景と再現

開始時の HEAD は `143b0ac`。
ヘッダの数値入力と読み上げ要素は文書を照合するが、マウスの押下とリセット待ちは文書交換で残っていた。
`ArrangeCanvas.updateNSView` はコールバックを更新してから文書 ID を設定する。
`ValueClicks` の開始・変更・終了が毎回その時の `mixActions` を読むため、古い操作が新文書のコールバックを借りられた。

実ヘッダの押下後に同じプロジェクトを再オープンし、旧押下からドラッグすると新文書の値と保存内容が変わった。
リセット待ちの後に再オープンして別のパン試聴を始めると、古い待ちの確定が新しい試聴を記録した。
数値欄も元のコールバックで誤編集を拒否する一方、画面には古い欄が残った。
`MixerGestureDocumentTests` を先に失敗させ、`target/focused-checks/mixer-gesture-document-red/` で終了コード 1 と固有のアサーションを照合した。
これは一時ログの所在であり、永続的な証拠へのリンクではない。

## 決定

- ヘッダの押下は、対象・幾何・元の値とともに文書 ID と `MixActions` を保持する。
  ドラッグまたはリセット開始時に文書を照合し、成功した操作だけがそのコールバック群を終了まで保持する。
- 文書 ID が変わったら `ValueClicks.cancel` でタイマーと操作を取り消し、押下を破棄し、数値欄を送信せず閉じる。
  読み上げ要素の既存のキャッシュ破棄も維持する。
- 終了は保持したコールバックを取り出してから解放し、更新済みの `mixActions` を参照しない。
  元の文書の factory が既に古ければ要求を拒否し、新文書の別の試聴を確定・取消しない。
  `updateNSView` の代入順に依存して安全性を作らない。
- 同じ文書の更新では押下を取り消さず、押下時のコールバックで単一 Undo / Redo・保存を続ける。
  単クリック・相対ドラッグ・ダブルクリック・トリプルクリックの規則は変えない。
- 選択全体の数値入力と読み上げ増減、単一対象のライブ試聴という範囲は変えない。
  一括ドラッグ・一括リセットは音声プレビューの一括化とともに残す。
  新しいアクション・ABI・保存形式・DSP・依存ライブラリは加えない。

## 回帰と基盤の保守

- `mixer-gesture-document-ui` は実マウス入力と製品 controller / ABI を通し、旧押下の取消・試聴拒否・履歴不変・保存再読込を確認する。
  文書交換時の取消を外す誤りを負の対照にする。
- `mixer-reset-document-ui` は製品と同じコールバック更新順で、リセット待ちと古い数値欄を取り消す。
  新文書の別の試聴を触らないことを確認し、最新の終了コールバックの借用と欄の取消漏れを負の対照にする。
  タイマーの満了は状態機械の明示的な確定で代用し、経過時間を合否条件にしない。
- 通常回帰は同文書の押下後の callback 更新と、その後のドラッグ・単一 Undo / Redo・保存も確認する。
  既存の `mixer-step-bounds-ui` のキャッシュ破棄の反例を新しいコード配置へ合わせる。
  検査登録・選択回帰・Makefile の既存入口、現状・領域設計・開発と診断手順を更新する。
- 音声処理と RT の操作は変わらず、新しいブロック長回帰・アクションのランダム生成は不要である。
  診断は文書 ID、`ValueClicks.phase`、押下と実行中のコールバック、現在の試聴を区別する。
  ログ形式・出力先・外部入力は増えず、`doctor` と `debug-report` の収集範囲は変更不要である。
- 実機検査はユーザー担当とし、実画面で欄が消える時のフォーカス、VoiceOver と聴感の確認は見送る。
- 後続の一括ドラッグ・リセットは [ADR 0228](0228-selected-track-live-mix.md) で接続し、ここで定めた文書境界とコールバックの保持を継承する。

## 完了検査で判明した既存 UI 回帰の実機到達

`make verify` の初回は必須契約全体の 1800 秒で中断し、完了済みの契約記録を再利用して再開した。
続く TSan は実 HAL の `write_planes` と自動保存の zlib 処理の書込みを競合と報告した。
保存ログは `target/bridge/thread/product/swift-tests.failed.log`。これは一時ログの所在である。

既存の `PluginBatchTests.invalidTargetsDoNotPartiallyInsertOrClearRedo` は単体候補の要求を通し、
`opensWindow` から未注入のデバイス要求で出力を開く経路を持っていた。
この UI 回帰に既存の `FakeParameterPlugin` を注入し、窓要求の完了と対象を照合するようにした。
再生をしないことや `preparesOutput = false` だけでは、窓を開く要求の実機到達を防げない。
失敗時の切分けと現在の制約を更新した。実 HAL の競合警告の原因は引き続き未確定で、抑制や音声処理の変更は行わない。
