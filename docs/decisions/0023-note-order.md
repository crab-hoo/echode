# 0023. ノートは開始、音高、ID の順に持つ

- 日付: 2026-10-08
- 状態: 採用
- 項目: MOD-4

## 背景

内容時刻 0 と配置の窓は ADR 0022 で分かれている。ノートの `start` は、自動配置が伸びても書き直さない。

中身のノート列は、足した順のままである。S1 の描画は `note.start` の昇順を前提に `partition_point` で範囲を切る。並んでいないと、この二分探索は使えない。同じ開始のノートが隣り合っていないと、開始だけで切った範囲から音が抜ける。

長さは並びのキーにしない。同じ開始でも長さが違うノートはある。長いノートが視界より前から伸びている場合の問い合わせは、UI-1 が区間で扱う。この案は、そのための最大長の索引は持たない。

## 決定

- 中身のノートは、次の昇順で一列に保つ。比較は内容時刻の `start`、同じなら音高、それも同じなら ID の数値（`u128`）である。`start` が負のノートは、0 より前に置く。長さ、ベロシティ、所属配置はキーにしない
- この順は中身に 1 つである。配置ごとに聞き順を持たない。絶対時刻は `配置の開始 + note.start - オフセット` なので、同じ中身をどの配置で聞いても、この順が鳴る順になる
- モデルが編集のたびにこの順へ戻す。並べ替えるアクションは足さない。挿入と、2 つの自動配置を 1 つの中身へまとめる操作のあとで並べる。削除は残ったノートの相対順を保つ。配置の伸縮、ゲイン、フェードはノート列に触らない
- 並べるために、既存ノートの `start`、音高、長さ、ベロシティ、ID は変えない。別の中身を吸収するときの `start` の書き換えは ADR 0022 のままで、そのあとで列を並べる
- 保存もこの順である。読み込みは並べ直さない。順が違う中身は `try_assemble` が `ModelError::Unsorted` で拒否する。`check_invariants` は中身ごとに同じ規則を見て、最初に崩れている組を言葉で報告する。ChangeSet の適用は記録されたノートの並びをそのまま戻し、並べ直さない。編集結果の並びが記録されるので、往復したあともこの順である
- スキーマ番号は 1 のままである。ノートのフィールドは足さない。ChangeSet では、今どおり中身のノート ID の並びが更新される。既存ノートの値は、そのノートの保存されている値が変わったときだけ更新に入る
- 音高や開始を変える操作を後から足すときも、同じ順に戻す

## 結果

`make check` が通った。後から足した開始の早いノートは列の前に来て、先にあったノートの `start` は変わらない。同じ開始では音高の低い方が前になり、開始も音高も同じなら ID の数値が小さい方が前になる。順が違う中身は `try_assemble` が `ModelError::Unsorted` で拒否し、`check_invariants` も同じ規則を報告する。
