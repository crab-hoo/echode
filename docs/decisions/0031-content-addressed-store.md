# 0031. プラグインの状態は内容のハッシュで保管する

- 日付: 2026-10-08
- 状態: 採用
- 項目: HIS-6

## 背景

ARCHITECTURE §6.1 は、プラグインの状態を `devices/<id>.state` として Git に入れる形にしている。状態は大きく、よく変わるので、履歴が膨らむ。メディアの本体は `media/objects/` に置くと §6.3 にあるが、ハッシュの方式は決まっていない。今のデバイスはミキサーだけで、状態のファイルは無い。

## 調査

内容のハッシュは `blake3` 1.8.7 が、監査の挙げる選択肢である。ライセンスは CC0-1.0 OR Apache-2.0 OR Apache-2.0 WITH LLVM-exception で、`cargo deny` の許可に入っている。`rayon` は使わない。

## 決定

- ハッシュは BLAKE3-256 とする。JSON とファイル名は、小文字の 16 進 64 文字だけを認める。計算は `echode-history` の `hash_bytes` が行う
- バイト列は `media/objects/<ハッシュ>` に置く。同じ内容は同じファイルで、置いたら書き換えない。音声の本体も、プラグインの状態も、ここを使う。`media/index.json` は、音声ファイルに名前を付ける時まで作らない
- 自動保存のコミットは、今どおり `project.json` と `contents/` と `tracks/` だけを入れる。パッケージのリポジトリには `.gitignore` を置き、`/media/objects/` と `/cache/` を履歴の外にする
- トラックのデバイスに `state` を足す。ミキサーは `null` と書く。64 文字でない値は拒否する。正しいハッシュでも、プラグインのデバイスが無い今は「plugin state is not accepted yet」として拒否し、その文字列をエラーに含める。スキーマは 1 のままにする。版 1 の見本とスナップショットは、このキーを足した今の形へ更新する
- 状態を読めるようにする時は、`media/objects/<ハッシュ>` が実在し、シンボリックリンクでなく、中身の BLAKE3 が名前と一致することを確かめてから使う。その関数は今テストする
- 掃除は、今のパッケージと、残っているすべてのコミットが指すハッシュの和に無いファイルだけを消す。音声も状態も同じ規則にする。この項目では判定だけを関数にしてテストし、自動では消さない
- モデルの `Device` と ChangeSet には、まだ状態を持たせない。ミキサーの JSON は常に `null` である

## 結果

`make check` が通った。ミキサーの `state` は `null` で往復する。64 文字でないハッシュは拒否し、空のバイト列の BLAKE3 でも「plugin state is not accepted yet」とそのハッシュで拒否する。空のバイト列のハッシュは既知の値と一致する。オブジェクトの検査は、シンボリックリンクと、中身が名前と違うファイルを拒否する。参照されていないハッシュだけが掃除の対象になる。パッケージの `.gitignore` は `media/objects/` と `cache/` を履歴の外にする。
