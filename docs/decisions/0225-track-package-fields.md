# ADR 0225: トラックの項目表をモデルと保存へ共有する

- 日付: 2026-11-02
- 状態: 採用
- 対象: SPG-09 の続き。トラックのスカラー項目とパッケージ間の変換
- 関連: [ADR 0217](0217-track-changeset-fields.md)、[ADR 0224](0224-note-package-fields.md)、[ADR 0024](0024-track-order.md)、[ADR 0028](0028-package-schema.md)
- 監査: [SPG-09](../reviews/2026-10-30-structure-audit.md#spg-09-モデルの項目追加の手数)

## 背景

ノートに続き、トラックの名前・親・兄弟順もモデル宣言・保存・変更セットで別々に列挙されていた。
履歴の `TrackFile` と保存・復元の列挙は、スカラー項目の追加時に同期が必要だった。
既存の結果を保つ構造整理とし、新しいトラック操作や保存形式の変更は行わない。

## 決定

- `echode-model/src/track_fields.rs` の crate 内の表を、モデル宣言・変更セットと保存のスカラー型で共有する。
  名前・親・兄弟順の型と変換、保存とジャーナルのスカラー順序をこの表へ集める。
  `Track` の公開フィールドと、変更セットの子の ID 列・解決・適用規則は変えない。
- 同じ表から `TrackMetadata` の宣言・Serde と、`Track` との両方向の変換を作る。
  同一性と子はスカラーと分け、ID・配置・デバイスを復元時に渡す。
  パッケージの子の検証を迂回する、`Track` 全体の直接の Serde は追加しない。
- 履歴の `TrackFile` はスキーマ・ID・子を復号し、残りのキーを `TrackMetadata` の Serde で復号する。
  `flatten` と `deny_unknown_fields` の未対応の組合せに依存せず、スカラーと子の両方の未知の項目を拒否する。
  名前・兄弟順は必須、親の省略と明示的 null は既存の互換を保ち、既定値・丸め・自動修復は足さない。
- スキーマの段階変換、ファイル名と ID の照合、子の検証と状態オブジェクトの読込みは履歴へ残す。
  メタデータの復号・子との結合だけでは、親の存在・循環・兄弟キー・ID の一意性を検証しない。
  公開前の `Project::try_assemble` と不変条件の検査を引き続き通す。
- 保存は `TrackMetadata` の Serde と `document_track.rs` のレイアウト専用 formatter を使う。
  スカラーのキー順・文字列のエスケープ・改行と、デバイス・配置の既存 formatter を保つ。
  スキーマ 6 と旧版の段階変換、既存の UUID 入力の互換も変えない。
- 不正な親 ID は形の復号で拒否するため、従来の理由に `track json:` の文脈が付く。
  診断の収集先は増やさず、拒否時に原本を書き換えない。
- ほかのオブジェクトの保存と FFI の統合は残り、SPG-09 全体の完了とはしない。
  アクション・Undo・ジャーナル・プラグイン処理・音声処理は変更しない。

## 回帰と診断

製品コードの変更前に `echode-history/tests/track_package.rs` の公開保存経路の互換回帰を追加した。
整理後も同じ入口を通し、メタデータの直接復号とプロジェクトの受入を区別する回帰も加えた。

- 空の名前・Unicode・制御文字・JSON に似た文字列、親の有無と異なる兄弟キーの組合せを通す。
  独立したキー順・表記・改行の期待値、入れ子のフォルダ・子の保持と再保存時のバイトを検査する。
- 必須項目の欠落・型の誤り・未知の項目・不正 ID と、親の省略・UUID の別表記の互換を検査する。
  参照先のない親・自己参照と祖先の循環、不正・重複した兄弟キー、ファイル名と ID の不一致を拒否する。
- 子の ID の重複・存在しない中身・ミキサーの欠落を受入前に拒否し、プロジェクトと全ノードの原本を保持する。
- 旧スキーマの段階変換と、`DocumentHost` の部分木の移動・複製・Undo / Redo・保存・コミット再オープンを通す。
  既存の `track_changesets.rs`・保存のスナップショット・操作列の性質テストも維持する。

通常の `check` が新しい統合テストを含むため、実行入口・依存・検査選択は変更しない。
デバッグ手順に形・同一性・子・階層の検証の区別と回帰の場所を追記する。
実機・実画面・聴感や性能の改善は、この構造整理の合否からは主張しない。
