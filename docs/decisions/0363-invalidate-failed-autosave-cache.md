# ADR 0363: 失敗した自動保存のキャッシュを次へ渡さない

- 日付: 2026-11-15
- 状態: 採用
- 関連: [品質監査 IQA-04](../reviews/2026-11-13-implementation-quality-audit.md#iqa-04-失敗した自動保存の後のキャッシュ)、[ADR 0009](0009-package-autosave.md)、[ADR 0297](0297-typed-autosave-and-git-errors.md)

## 問題と再現

自動保存は作業ツリーを書いてからコミットする。
途中で失敗しても、キャッシュは前回成功時の `Arc`・JSON・blob のままだった。
Undo でその `Arc` へ戻ると、次の保存は失敗時に書き換えたファイルを省き、新たな余剰ファイルも掃かなかった。
コミット自体は正しくても、作業ツリーが食い違う。

公開の `Autosave` で基点を保存し、テンポ・ゲイン・既存ノートの強弱を変え、ノート付きトラックを足す。
内容の一時ファイル名をディレクトリで塞ぐと、先行する JSON の書込み後に I/O が失敗する。
参照ロックを塞ぐと、全 JSON の書込み後に Git のコミットが失敗する。
同じ `Session` の Undo 後に保存すると、修正前は両方の回帰が作業ツリーの全バイトとファイル集合の不一致で失敗した。
期待終了コード 101 と IQA-04 固有のアサーションを `checked_commands.py` で照合した。

## 比較と決定

1. ワーカーで失敗を受けてキャッシュを消す: 小さいが、保存処理とキャッシュの成立条件が別の関数へ分かれる。
2. 保存を内部関数へ包み、失敗時に消す: 成立条件は近いが、引数の多い保存処理をもう一段に分ける必要がある。
3. 保存開始時に `Option::take` し、完了時だけ戻す: すべての早期リターンで、追加の分岐なしにキャッシュが空になる。

3 を採る。旧キャッシュは試行のローカルに保持し、その試行内の増分判定と blob の再利用には従来どおり使う。
作業ツリー・コミット・完了マーカーの処理がすべて成功した時だけ、新しいキャッシュを公開する。
失敗後は既存のキャッシュなしの経路で全量を書き、列挙にない JSON を掃く。
成功後は通常の増分保存へ戻る。失敗の段階を別のフラグで追わず、キャッシュの成立条件を一つにする。

保存開始マーカー自体の失敗でも無効化する。書込みの有無を判定する追加状態より、失敗後一度の全量保存を選ぶ。
正常時の同期・親の更新・ジャーナル連番・エラーの共有・保存形式は変えない。
性能の比較計測はしておらず、失敗後の全量保存の所要時間は今回の保証に含めない。

## 回帰と基盤

`tests/autosave_retry.rs` は途中の書込み失敗とコミット失敗それぞれで、Undo 後と同じ編集の再保存を通す。
全 JSON のバイトと余剰ファイル、作業ツリーの読込み、Git からの読込み、復旧、親と連番、再オープンを照合する。
修復後に同じスナップショットを再保存し、開いたままのファイルの inode と比べて、正常時の増分保存が戻ることも検査する。
時刻・実機・計測用 feature・製品の故障注入フックは使わない。

回帰は既存の Rust 通常テストが自動収集する。新しい検査入口・外部入力・公開 API はない。
`Makefile`・`scripts/verification.json` の選択と必須契約、既存のパッケージ fuzz の入口は変更不要である。
設計書・監査と索引・保存のデバッグ手順を更新する。新しい利用者の制約や実機確認待ちは作らない。
失敗直後の JSON の巻戻しや電源断の耐久性を追加で保証するものではなく、次の正常完了の保存で整合を回復する。
