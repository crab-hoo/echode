# ADR 0228: 選択トラックのドラッグと既定値リセットを一括試聴する

- 日付: 2026-11-02
- 状態: 採用。実画面・VoiceOver・聴感はユーザー確認待ち
- 関連: [ADR 0191](0191-selected-track-numeric-mix.md)、[ADR 0193](0193-header-mix-gesture-document-scope.md)、
  [操作要件](../interaction-design.md#ミキサーの複数選択)

## 背景と再現

開始時の HEAD は `0104720`。
数値入力と読み上げの増減は選択全体を扱うが、ヘッダのドラッグと既定値リセットは単一トラックだった。
音量 0.5 と 0.25 の選択をドラッグしても他方は変わらず、パン −0.5 と 0.25 のリセットでも他方は 0.25 に残った。
`MixerDragBatchTests` を先に追加し、期待終了コード 1 と一括ドラッグ・共通限界の固有アサーションを照合した。
一時ログの所在は `target/focused-checks/mixer-drag-red/`。永続的な証拠へのリンクではない。

## 決定

- ネイティブの押下で文書・基準・選択 ID と元のミキサー値を捕捉する。
  ドラッグ開始までに選択が変わっても対象を変えず、文書や捕捉した値が古ければ開始・確定を拒否する。
  前のドラッグ／リセットの確定を誘う別ノブの押下では、その時に表示されている全対象の値を捕捉する。
  新しいドラッグの開始時に前の確定結果との一致を確かめ、原点をそこへ置き直す。
  選択外の操作は単一対象、子孫の自動追加はしない。
- `MixerFaderBatch` は `MixerValueBatch` の共通倍率・パン差と上下限を共有する。
  音量の有限倍率では無音のメンバーを保ち、無音の基準からの増加・リセットは理由を示して拒否する。
  グループの横移動は表示下限未満も有限の dB 差とし、ゼロ移動は元の Float を保つ。
- ダブルクリックは基準の 0 dB／中央を目指す相対変更とする。
  他の対象の上限・パン端に先に達すれば基準もそこで止まる。全対象を同じ絶対値へそろえない。
  3 回目のクリック・Escape・文書交換はグループ全体の試聴を取り消す。
- `FaderPreview` が全対象の仮の値を持ち、Metal のヘッダと音声へ同じ集合を渡す。
  既存の単一対象の入口は保持し、グループは `audio.preview_faders` の完全な集合を送る。
  Swift の送信は実行中 1 件と最新 1 件だけを保持し、マウス頻度で要求列を増やさない。
- 制御側で全 ID・重複・有限値・範囲を検証し、集合を確保して 1 コマンドで音声側へ移す。
  コールバックは対象の索引だけを引き、対象外のプレビューを復元してから新しい集合を使う。
  古い集合の所有権は戻りリングで制御側へ返し、コールバックで確保・解放しない。
  キュー深さは待機中の操作だけを制限し、トラック数の上限にしない。
- 確定は全対象を編集の手番で再照合し、既存の `param.set` 配列を 1 回だけ送る。
  単一 Undo / Redo・ジャーナル・保存を共有し、確定計画が採用されるまで試聴を解除しない。
  取消と no-op は Redo を保つ。出力準備中も完全な集合を保持して導入時に差分を反映する。
- 新しいモデルアクション・保存形式・C ABI・依存ライブラリは加えない。
  音声 JSON コマンドと内部の所有権受渡しだけを拡張する。
  フォルダの親子を両方選んだ時の将来のバス音量は P2-03 の受入で別途扱う。

## 回帰と基盤

- `mixer-drag-batch-ui` は実マウスのドラッグ・リセット、対象保持、単一 Undo / Redo・再オープンを検査する。
- `mixer-drag-bounds-ui` は共通限界、取消・原点復帰と Redo 保持を検査する。
- `mixer-group-audio` は製品のステレオ PCM で、40 トラックの一括試聴・確定計画待ち・対象交換・取消を比較する。
  複数ブロック長・48 / 96 kHz と RTSan を通し、40 はこの検証だけの規模とする。
- 通常回帰はパン端・表示下限未満・無音・3 回目・文書交換・古いメンバーの拒否、ヘッダの描画位置、送信の集約と wire 表記も扱う。
  音声セッションは不正な集合の全体拒否と、出力準備中の集合変更を機器なしで確認する。
- 検査登録・選択回帰・Makefile の既存入口と、利用手順・現状・P2・領域設計・デバッグ手順を更新する。
  新規アクションはなく、ランダム生成の操作種別は変更しない。
- 完了検査では、既存の `mixer-reset-target-ui` が「リセット待ち中に同じトラックの別ノブを押す」回帰を検出した。
  前の試聴結果を押下時の期待値として捕捉し、開始時の一致を確かめた上で原点を更新して修正した。
  一括リセットからパンへ移る通常回帰と、前の表示値を無視する反例も追加した。
- 診断では押下時の集合、`FaderPreview.members`、送信中と最新の集合、確定計画の版を区別する。
  ログの形式・保存先・外部機器は増えないため、`doctor`・`debug-report` の収集範囲は変更しない。
- 実画面の同時移動・既定値の表示、VoiceOver、再生中の一括試聴と確定・取消の聴感はユーザー担当とする。
  機器を開く検査とアプリ操作は行わず、自動回帰での確認と区別する。
