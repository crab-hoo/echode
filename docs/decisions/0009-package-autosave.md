# 0009. プロジェクトの保存とジャーナルの基点

- 日付: 2026-10-08
- 状態: 採用

## 背景

アクションと Undo はメモリ上で動く。落ちたあとに戻すには、確定したスナップショットと、その後の操作をディスクに残す必要がある。作業ツリーの書き込みが途中で切れると、ファイルだけを信用できない。

## 決定

- 製品のパッケージはスキーマ 1 の JSON にする。`project.json` に拍子、テンポ、中身の ID、トラックの並びを書く。中身は `contents/<id>.json`、トラックは `tracks/<id>.json` に 1 つずつ書く。ノートは中身に 1 行で書く（[ADR 0022](0022-clip-content-and-placement.md)）
- 自動保存のコミット先は `refs/echode/autosave/main` とする。保存の依頼は呼び出し側を止めず、コミットは履歴スレッドで行う
- `journal.jsonl` は追記だけのログである。各行に連番があり、コミットは `Echode-Journal` で取り込んだ最後の番号を残す。復旧はその番号の続きだけを再生する（[ADR 0033](0033-journal-log.md)）

## 結果

同じプロジェクトは同じバイト列になり、ジャーナルを再生した状態と、その後の自動保存から読んだ状態が一致することをテストで確認する。変わっていないトラックと中身の判定は、アドレスの数値ではなく、キャッシュが持っている `Arc` の同一性で行う（HIS-1）。
