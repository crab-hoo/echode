# 0009. プロジェクトの保存とジャーナルの基点

- 日付: 2026-10-08
- 状態: 採用

## 背景

アクションと Undo はメモリ上で動く。落ちたあとに戻すには、確定したスナップショットと、その後の操作をディスクに残す必要がある。作業ツリーの書き込みが途中で切れると、ファイルだけを信用できない。

## 決定

- 製品のパッケージはスキーマ 1 の JSON にする。`project.json` に拍子、テンポ、トラックの並びを書き、トラックは `tracks/<id>.json` に 1 つずつ書く。ノートは 1 行にする
- 自動保存のコミット先は `refs/echode/autosave/main` とする。保存の依頼は呼び出し側を止めず、コミットは履歴スレッドで行う
- `journal.jsonl` の先頭に、再生の基点を書く。まだコミットが無ければパッケージのファイル、あればそのコミットの ID である
- 復旧は、基点が最新の自動保存と一致するときだけジャーナルを再生する。一致しなければ最新のコミットを使い、古いジャーナルは重ねない

## 結果

同じプロジェクトは同じバイト列になり、ジャーナルを再生した状態と、その後の自動保存から読んだ状態が一致することをテストで確認する。変わっていないトラックの判定は、アドレスの数値ではなく、キャッシュが持っている `Arc` の同一性で行う（HIS-1）。
