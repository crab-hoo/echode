# 0032. ドキュメントは 1 つのスレッドが持つ

- 日付: 2026-10-08
- 状態: 採用
- 項目: HIS-4

## 背景

`echode serve` は `read_package` で読み、`ApiSession` が自分の `Session` をメモリに持つ。プロセスが終わると編集は消え、`recover` も通らない。アプリ、API、MCP が同じドキュメントを変えるのに、持ち主が決まっていない。

ジャーナルの追記形式、連番、fsync、コミットとの食い違いは HIS-2 で決める。この項目は、その書き手を 1 つにすることである。

## 決定

- `echode-history` に `DocumentHost` を置く。パッケージ 1 つにつき、スレッド 1 つが `Session` を持つ。コマンドはキューで受け、そのスレッドだけが `Session` を変える
- 開く時は `recover` を通す。`read_package` だけで開かない
- 操作が成功したら、そのスレッドが今の `write_journal` でジャーナルを書いてから結果を返す。自動保存の依頼も、このスレッドだけが行う。呼び出し側はコミットの完了を待たない
- 変えたあとに `Arc<Project>` を公開する。読む側はロックをすぐ放して、その `Arc` だけを使う。オーディオスレッドへの渡し方は ENG-3 で決める。このスレッドはオーディオスレッドではない
- `echode serve` は、このホストを開いてソケットの操作を渡す。`ApiSession` は自分の `Session` を持たない
- まだコミットが無いパッケージで、操作が返ったあとホストを落とし、次に開くと `recover` で同じプロジェクトになることをテストする。コミットの途中で確定した操作が消える窓は、HIS-2 が塞ぐ

## 結果

`make check` が通った。まだコミットが無いパッケージでトラックを足し、ホストを落として開き直すと、そのトラックが残る。`echode serve` は `DocumentHost` を開き、`ApiSession` は自分の `Session` を持たない。
