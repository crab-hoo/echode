# ADR 0359: f32 を超える有限の積と和を 0 にせず障害にする

- 日付: 2026-11-15
- 状態: 現行。実画面と VoiceOver は UC-86 が未確認。
- 領域: 音声エンジン・書き出し
- 関連: [ADR 0282](0282-plugin-nan-and-master-auto-mute.md)（「残る範囲」の 3 行目を置き換える）、[ADR 0345](0345-track-mix-fault-attribution.md)、
  [ADR 0247](0247-pcm24-wav-export.md)、[監査の NFA-01〜03・08](../reviews/2026-11-13-finite-overflow-audit.md#指摘の一覧)

## 問題と再現

開始時の HEAD は `9ee3ef1`。
フェーダーの積（`mix.rs` の `scaled`）、フォルダバスの子の和（`Block::sum_children`）、マスターの和（`Prepared::render`）は、
f32 に収まらない値を 0 にしていた。ADR 0282 はこれを「段の検出の後は届かない値の防御」としたが、
有限の値の積と和はホスト自身の演算で f32 を超えるので、段の検出を通らない。
書出しは無音のファイルを成功として書き、機器ではメーターが空のまま、マスターの自動ミュートも起きなかった。
書出しの非有限値の拒否（PCM・ノーマライズ）も、0 になった値しか見なかった（NFA-08）。

監査の再現 6 件を修正前の製品の経路で実行し、すべてが監査の書いた理由で失敗することを確かめた。

- エンジンの `audit_nfa01_*` 2 件・`audit_nfa02_*` 2 件・`audit_nfa03_*`: 終了コード 101。
  `the export succeeded and wrote 0 for every sample`、`silence with an empty meter and no auto-mute`、
  `a master 100 dB past the guard did not auto-mute`、`expected 1.0e38 on every sample, the first is 0`。
- CLI の `audit_nfa02_an_export_of_an_imported_file_*`（float の WAV の取込みから書出しまで）: 全標本 0 のファイルで成功。

音声機器・アプリの操作は使っていない。

## 比べた案

| 案 | 内容 | 判定 |
|---|---|---|
| 1 | トラックとバスの面を全部 f64 にする | 採らない。プラグインへ渡す面は f32 で、どこかで狭める。狭めた所の規則は結局要る |
| 2 | f32 の範囲へ飽和させる（±`f32::MAX`） | 採らない。書出しの値を黙って変える（ADR 0281）。機器ではガードが止めるが、書出しは成功して偽の値を書く |
| 3 | 狭める所で有限でなければ、その標本からの障害にする | 採る。機器は自動ミュート、書出しは型付きの拒否。値を作り変えない |

### フェーダーの積の精度

監査の案は「積を f64 で計算する」だった。f32 の 2 数の積は f64 で丸めなしに表せる。
ただ、従来の値（f32 で丸めた積を f64 へ広げて足す）とは丸めが違う。
`block_size` の全 56 件と基準音声（`a_package_renders_to_the_committed_reference`）は、どちらでも変わらなかった。
固定具の多くが 2 の冪のゲインと 1 本のトラックで、差が出ない形だからである。
一様な乱数の標本（−1〜1）とゲイン（0〜1.5）で 20 万標本ずつ比べると、狭めた後のマスターが違う標本は次のとおりだった
（作業ツリーの外の Python で f32 の丸めを模した。リポジトリには置いていない）。

| トラック数 | 違う標本の割合 |
|---|---|
| 1 | 0 % |
| 2 | 35.2 % |
| 4 | 39.3 % |
| 8 | 41.5 % |

違いは丸め 1 回分で聞こえないが、既存のプロジェクトの書出しがビットで変わる。
そこで、f32 の積が有限ならその値を従来どおり使い、有限でない時だけ f64 の積を使う（作業の指示の「あふれた標本だけ別扱い」）。
有限の積の値は変わらないので、既存の音は 1 ビットも変わらない。ピークは f64 の積の最大から取り、f32 を超えたら `f32::MAX` を返す。

### フォルダバスの扱い

監査の再現 `audit_nfa03_*` は、親のフェーダー 1/4 で範囲へ戻る 1.0e38 が書き出されることを期待していた。
一方で監査の直し方の案は「親の面は f32 のまま保つ（プラグインへ渡す形だから）」である。両方は満たせない。
プラグインのない親だけ f64 の面にすると、親へ透過なプラグインを挿しただけで結果が 1.0e38 から障害に変わる。
音がプラグインの有無で変わる構造は避ける（ADR 0276 の入り組んだ構造）。親の f32 の面に収まらない和を、親の障害とする。
再現のテストは期待を「親を名指しする型付きの拒否」へ改め、名前も `audit_nfa03_a_folder_bus_past_the_f32_range_refuses_the_export_naming_its_parent` にした。

## 決定

### 一つの述語

`output_guard.rs` の `first_past` が「最初の NaN か、大きさが上限を超える標本」を返す。

- `first_fault`（上限 +18 dBFS）: 機器のマスターと試聴（ADR 0282・0344、従来どおり）。
- `first_nonfinite`（上限 `f32::MAX`。超えるのは無限大だけ）: 書出しのマスターと全てのフォルダバス。

f64 の和を `as f32` で狭めると、範囲を超えた値は無限大になる。狭めた面をこの述語で調べるので、狭める前の和を見たのと同じ判定になる。

### マスター（NFA-01・02）

- `Prepared::render` は和を `as f32` で狭め、0 へ置き換えない。
- `guard_master` は機器でも書出しでも呼ぶ。機器は `first_fault`、書出しは `first_nonfinite` で、その標本から 0 にし、`MasterAutoMute` を記録する。
  書出しは +18 dBFS を超える有限の値をそのまま保つ（ADR 0282 のとおり、書出しに上限はない）。
- `MasterAutoMute::peak` は、和があふれた時に無限大を持つ。位置は従来どおりブロックの開始と標本の和で、PDC の遅れは引かない（ADR 0340 のトラックの記録と同じ）。
- アプリへの `AudioState` では、無限大を `f32::MAX` にする。JSON は無限大を持てず、`null` は NaN の意味だからである。
  トランスポートの横の 1 行は `+770.6 dBFS` になる（`20 log10(f32::MAX)`）。Swift の表示の規則は変えていない。
- `PlaybackControl::render_failure` は、非有限の値を持つマスターの記録を `RenderFailure::NonFiniteMaster { at }` にする。
  順はトラックの合流（`NonFiniteMix`）、装置（`Plugin`）、マスターである。

### フォルダバス（NFA-03）

- `sum_children` は子の和を親の f32 の面へ狭め、`first_nonfinite` が見つけた標本から両方の面を 0 にする。親のプラグインは無限大を受け取らない。
  その標本を `Track::bus_fault` に置く。
- `Block::finish` は、ヘルパーの障害とバスの障害の早い方を、装置なし（`device: None`）の自動ミュートとして記録する。
  書出しは ADR 0345 の同じ記録から `RenderFailure::NonFiniteMix { track: 親, at }` で拒否する。
- 減衰と解除は、ヘルパーのあるトラックとないトラックで同じ `PluginDeclick::conceal` を使う（障害の標本まで鳴らし、そこから 5 ms で消す）。
  `HostGraph::apply` は `muted` の代わりに「どこまで鳴らすか」の標本を受ける。
- ヘルパーのないトラックは、これまで毎ブロック `PluginDeclick::reset` で直前の値を忘れていた。
  そのままでは、障害がブロックの先頭に来るブロック長（1 や 7）だけ減衰なしに 0 へ落ちた（新しい `block_size` の回帰で見つけた）。
  `PluginDeclick::follow` で最後のフレームを覚え（O(1)）、ブロック長によらず同じ値から減衰させる。
- 副作用として、自動ミュートの間にプラグインを外したトラックも再生の開始まで無音を保つ（ADR 0282 の「自動ミュートの間は無音を保つ」に揃う）。
  ヘルパーを挿した直後の最初の欠けは、0 ではなく直前の音から減衰する。

### 書出し（NFA-02・08）

- プラグインのない書出し（`render_offline_blocks_with_clips`）も、毎ブロック `render_failure` を読み、`OfflineError::Render` で拒否する。
  そのブロックは書込み側へ渡さない。`render_offline` は `PlaybackError::Render` で返す。
- CLI は両方の経路で `CliError::RenderBlock` にし、既存の出力を置き換えない。最初の標本の位置を文に含む。
- NFA-08: 製品の書出しでは、エンジンの拒否が書込みの検査より先に働く。書込み側の PCM・ノーマライズの検査は最後の防御として残す。
  監査が保留した float32 にも同じ検査を置いた（`CliError::NonFiniteFloat`）。値が有限なら書くバイトは変わらず、基準音声も変わらない。
  `write_wav` を直接呼ぶ利用者が NaN を書けなくなる。テストの素材の作成に非有限値を使うものはなかった。

### 実時間の制約

- 音声側で新しい確保・ロック・待ちはしない。
- 増えた処理は、フォルダごとに 1 ブロック 1 回の面の走査と、書出しのマスターの 1 回の走査である。機器のマスターは従来も走査していた。
  ヘルパーのないトラックの `follow` は O(1)。音声スレッドの実時間の性能は測っていない。
- 書込みの検査を足した後の `make spike-render`（release）は通った。float32 の 60 秒のステレオの一括書込みは期限 2 秒の内で、
  同じ実行の PCM16 は 44.98 ms、PCM24 は 43.94 ms（ディザなし）だった。変更前の値は同じ機械で測っていない。

## 回帰と基盤

- エンジンの監査の再現 5 件の `#[ignore]` を外し、型付きの拒否・位置・メーターの `f32::MAX`・マスターの記録まで照合する。
  あふれから範囲へ戻る減衰の回帰は、ミュートの位置が「最初に範囲へ戻った標本」から「最初にあふれた標本」へ移ったことを確かめる。
  機器の経路でフォルダが自動ミュートされ、外のトラックが鳴り続けることも足した。
- `block_size/overflow.rs` は、ブロック長 1・7・64・512 で、フェーダーのあふれとフォルダバスのあふれが同じ標本で障害になり、
  減衰・保持・再生の開始での復帰が同じ音になり、書出しが障害の前のブロックだけを渡して拒否することを確かめる。
- 実ヘルパーの `a_folder_bus_overflow_mutes_a_hosted_parent_without_blaming_its_devices` は、エフェクトと音源の親で、装置を責めずに親を止めることを確かめる。
- CLI の `audit_nfa02_*` は、取込みから float32・PCM16・PCM24 とそれぞれのノーマライズまで、同じ型付きの拒否と既存出力の保全を確かめる。
- `mix_tests` は有限の積がビットで変わらないこと、`output_guard_tests` は述語の境界、`session_tests` は JSON の値を確かめる。
- 必須契約に `fader-overflow`・`folder-bus-overflow`・`master-overflow-export` を足した（`scripts/verification.json`）。
- 監査の表、統合表の R2、設計書（§7.5・§8.4 と隔離の節）、デバッグの手順を更新した。

## 残る範囲

- NFA-04（エンジンの入口で素材の有限性とゲインの積を確かめる）は未対応で、再現 3 件は `#[ignore]` のままである。
  クリップの再現は、マスターの NaN で書出しが拒否されるようになったので、入口での拒否（`OfflineError::Playback`）を求める形に締めた。
  （2026-11-15 追記: [ADR 0369](0369-checked-sample-planes-at-the-engine-entrance.md) で対応した。）
- 欠けの減衰（`PluginDeclick`）の非有限値の 0 への置換は残る。入るのは段の検出と合流の検査を通った面だけである。
- 公開の `mix_buses`・`mix_tracks`（製品の経路では使わない）は f32 で足し、あふれは無限大のまま返す。変えていない。
