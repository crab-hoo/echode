# 0261. 完了した書出しのファイルを Finder で表示する

日付: 2026-11-04。
状態: 採用（P2-08 の完了後の操作。DSP・保存形式・書出し範囲は変更しない）。

## 背景と再現

GUI の書出しには完了メッセージと診断があったが、完成したファイルを選択表示する操作がなかった。
文書の現在のパスや保存パネルのリンクから表示先を作り直すと、文書交換・リンク切替後に別の場所を案内し得る。
[ADR 0260](0260-pinned-gui-export-destination.md) の固定した出力先を完了結果にも引き継ぐ。

`ExportRevealTests` を製品の `ExportJob`・実 CLI から先に実行した。
未接続の表示先と操作の入口だけを置き、正常な WAV の公開後も表示先がないことを確認した。
終了コード 1 と `Reveal must retain the successfully published destination` を照合し、証拠は `target/export-reveal-red/` に残した。

## 決定

- ウィンドウ所有の `ExportJob.completedOutput` は、CLI の正常終了時だけ固定した出力 URL を保持する。
  準備・レンダリング・後片付け中は表示操作を受け付けず、完了後だけ下部に「Finder で表示」を出す。
- ボタンの明示操作で `NSWorkspace.activateFileViewerSelecting` へ渡す。完了時に自動で Finder を開かず、音声ファイルも開かない。
  日本語・英語のラベル、`export.reveal` の識別子とパスのツールチップを用意する。
- 保持するのは開始時に親を解決し、葉の名前を残した URL である。
  元文書を閉じたり別文書を開いたりしても表示先を変更しない。葉リンクの参照先や一時スナップショットも案内しない。
- 新しい要求を受け付けた時に前回の URL を消し、起動失敗・CLI の失敗・取消・出力先の拒否で前回のボタンを残さない。
  古い文書・不正な設定等で要求自体を受け付けなかった場合と、実行中の二重要求では既存ジョブの結果を変更しない。
- 公開後の同期失敗は既存どおり失敗として扱い、ファイルが残ってもこの操作は出さない。
  取消より公開が先に完了した場合は CLI の正常終了を優先する。片付けだけの警告では完成した出力を表示できる。
- 完了後に外部から移動・削除されたファイルの追跡や、敵対的なディレクトリ置換の防御は追加しない。
  Finder の表示完了をアプリが保証するものでもない。

## 回帰と基盤

- `ExportRevealTests` は表示要求の送り先だけを代役にし、実 CLI で WAV を作る。Finder・実機は開かない。
  親リンクの切替・葉リンクの置換・文書交換を通し、初期状態と処理中の無効、完了後の固定 URL を確認する。
- 必須契約 `export-reveal-ui` は保持先を元の URL に戻す反例と、表示要求を捨てる反例を検出する。
  通常の引数付き回帰は成功後の起動失敗・CLI の失敗・準備前の取消・出力先の拒否で、前回の表示先が残らないことを確認する。
- `scripts/verification.json` と選択のテストを更新する。Makefile の既存の Swift・製品契約の入口で実行し、新しい検査コマンドは増やさない。
  音声処理・アクション・FFI は変えないため、発音・ブロック長・操作列の新しい回帰は不要である。
- README・設計・進め方・開発／デバッグ手順を更新する。ログや自動収集の対象は増やさない。
  実画面のボタン・VoiceOver・Finder 連携は UC-58 のユーザー確認待ちとし、`status.md` から参照する。
