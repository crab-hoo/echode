# ADR 0283: 出力のブロックを HAL の出力時刻と機器の安全余白から終える

- 日付: 2026-11-08
- 状態: 採用。実機の HAL の書込み時間と聴感は UC-64 が未確認。
- 対象: [統合表](../reviews/2026-11-08-open-items-register.md) の R3（[FCA-09](../reviews/2026-11-03-full-code-audit.md#fca-09-待ちの期限と試聴の-ioproc)）。
- 方針: [ADR 0276](0276-priority-order-and-delegated-decisions.md) の「期限は出力時刻と機器の安全余白から求める」。
- 置き換え: [ADR 0082](0082-callback-deadline.md) と [ADR 0090](0090-reaudit-playback.md) の「入口の時刻に 1 ブロックを足す」期限の起点。
  エンジンが期限からブロックの 1/8 を混合に残す規則は変えない。

## 問題

- 出力のコールバックは、入った時刻に 1 ブロックを足した時刻を期限にし、そこからブロックの 1/8 前までヘルパーを待っていた。
- HAL がこのブロックを要するのは、機器が出力時刻から安全余白の分だけ手前に達する時である。
  試聴の IOProc と HAL 自身の書込みも、このコールバックが戻った後に同じ区間で動く（[ADR 0135](0135-sample-audition.md)）。
- 入口が遅れる（スレッドの起床の遅れ、先に呼ばれた試聴の IOProc）ほど、期限は HAL の締め切りより後ろへずれた。
  遅いヘルパーを期限まで待つと、HAL の締め切りを越え、全トラックが途切れ得た。試聴と HAL の書込みに残す時間もなかった。

## 比べた案

ヘルパーの待ちの終わり（入口が遅れない時の、起床からの時間）を 48 kHz で比べる。旧来は入口から 7/8 ブロックである。

| 案 | 内容 | 128 フレームの待ち | 判定 |
|---|---|---|---|
| 1 | 旧来のまま（入口 + 1 ブロック） | 2.333 ms | 採らない。入口の遅れの分だけ HAL の締め切りを越える |
| 2 | 出力時刻 − 安全余白をそのまま終わりにする | 2.333 ms | 採らない。試聴の IOProc と HAL の書込みに時間が残らない |
| 3 | 2 からさらにブロックの 1/16 を残す | 2.167 ms | 採る |
| 4 | 2 からさらにブロックの 1/8 を残す | 2.000 ms | 採らない。3 より多く残す根拠の測定がなく、重いプラグインの取りこぼしを増やす |
| 5 | 試聴の出力が開いている時だけ残す | 2.167 / 2.333 ms | 採らない。2 つのストリームが状態を共有する構造になり、HAL の書込みの分は試聴がなくても要る |
| 6 | 再生中の試聴を出力のコールバックで加算する（監査の別案） | — | 今は採らない。ADR 0135 の構成を変える大きな変更で、HAL の書込みの余白は別に要る |

- 案 3 の残りは、64 フレームで 83 µs、128 で 167 µs、256 で 333 µs、512 で 667 µs である。
  ブロック長に比例させるのは、HAL の書込みと試聴の処理がフレーム数に比例するからで、エンジンの混合の 1/8 と同じ考え方である。
- 案 3 で減るヘルパーの待ちは、入口が遅れない時でブロックの 1/16 である。
  1 トラックの取りこぼしは 5 ms で減衰して他のトラックを守る（[ADR 0245](0245-plugin-deadline-fades.md)）が、HAL の締め切りの超過は全体を途切れさせる。
  堅牢性の順（ADR 0276）で、局所の取りこぼしの方を受け入れる。
- 2026-11-08 にこの機械で、ストリームを開かずに属性だけを読んだ出力側の安全余白は次のとおり（48 kHz、バッファ 512 フレーム）。
  内蔵スピーカー 48 フレーム（1.0 ms）、集約デバイス 25〜48 フレーム、仮想デバイス 0 フレーム。

## 決定

- 出力の IOProc は、入口で `Instant` と Mach のホスト時計を続けて読む。HAL の出力時刻が有効なら、ブロックの終わりを次の時刻にする。
  `入口 + min(出力時刻 − 現在 − 安全余白 − ブロック/16, 1 ブロック)`
  - 出力時刻が既に安全余白の内側なら、終わりは入口である。ヘルパーは 1 回だけ確かめ、待っても間に合わないブロックを待たない。
  - 出力時刻が無効、または時計の換算を読めない時は、従来どおり入口から 1 ブロックである。
  - 1 ブロックで頭を打つので、旧来より長く待つことはない。壊れた時刻でも `Instant` の加算はあふれない。
- 安全余白は出力側の `kAudioDevicePropertySafetyOffset` を機器の一覧で読み、`OutputDevice::safety_frames` に持つ。
  読めない時は 0 として出力を止めない。変化の通知を受け、変われば機器の変更としてストリームを開き直す。
- 計算は `echode-audio-io` の `io_cycle` に置く。コールバックは制御側で読んだ時計の換算と余白で演算だけを行い、HAL を呼ばない。
- ブロックの長さの計算は、エンジンの `block_duration` の 1 か所にまとめた（`stream.rs` の写しを除いた）。
- 停止の診断（`ECHODE_STOP_TRACE_DIR`）の各ブロックに、入口から終わりまでの `deadline_ns` を足した。

## 回帰と基盤

- `io_cycle_tests.rs` は、遅れた入口・遅れない入口・遠い出力時刻・余白内の出力時刻・無効な時刻、Apple シリコンの時計の換算（125/3）を確かめる。
- 契約 `output-safety-deadline`（`stream::tests::contract_the_output_block_ends_before_the_device_safety_offset`）は、製品のコールバックが機器の余白を使って終わりを決めることを確かめる。
  反例は出力時刻を渡さない旧来の経路で、期待値（0.917 ms に対して 1.333 ms）で失敗することを確かめた。
- 試聴の IOProc は待たないので変えない。オフラインの書出しの期限も変えない。

## 残る範囲

- 実機の HAL の書込み時間、同じ機器の 2 つの IOProc の順番、小さいバッファでの取りこぼしの増減は測っていない。UC-64 で確認する。
- 測って 1/16 が足りない、または余る時は、この ADR に測定値を書いて変える。
