# 0200. モデルの時間単位と値の範囲を Swift と共有する

- 日付: 2026-10-30
- 状態: 採用
- 対象: [構造監査](../reviews/2026-10-30-structure-audit.md) SPG-04 の定数と変換

## 背景

Swift のアレンジ・ピアノロール・トランスポートが、1 拍の tick 数を別々に直書きしていた。
ミキサーの上限、パン、配置ゲイン、フェードの単位も Rust の定義と独立していた。
拍から tick への変換は、関係のない操作まで `PianoCamera.ticks` に依存していた。
今回は構造の整理であり、利用者の誤動作を新たに再現した修正ではない。

## 決定

- 正本は `echode-model` とする。既存の時間・ゲイン・フェードの定数に加え、
  MIDI 1.0 の最大値とパンの端点もモデルの検証・既定値で共用する。
- `echode_model_constants()` は `repr(C)` の `ModelConstants` を値で返す。
  cbindgen が構造と関数を生成し、Swift の `ModelLimits` はリンクした製品から値を取得する。
  依存 crate の定数を解析させるためにモデル全体を C へ公開せず、数値を FFI に再定義もしない。
  文書・機器・ポインター・割当・終了処理を必要としない経路とする。
- `EchodeBridge.Tick` が整数を保持し、拍への表示と拍からの丸めを受け持つ。
  既存と同じ、最も近い整数・中間はゼロから離れる方向の丸めを使う。
  非有限値と `Int64` を越す入力は `nil` とし、負の tick は型として保持できる。
  位置を非負とするかは既存の各操作が検証する。
- アレンジ・ピアノロール・トランスポートの変換を共通化し、`PianoCamera.ticks` を除く。
  通常・三連符・付点のグリッドも、同じ 1 拍から整数で導く。
  座標の倍率には `Tick.perBeat`、整数の範囲には `Tick.perQuarter` を使う。
- モデルの範囲と、表示の下限・ドラッグの感度・百分率などの UI 方針を区別する。
  -60 dB の表示下端や 1 dB の読み上げの段は変更しない。

## 回帰と診断

- `ModelLimitsTests` は全定数、三連符、端数 tick、正負の中間丸め、非有限・桁あふれ、整数の保持を検査する。
- `model-constants-abi` は製品 C ABI の値とモデル正本を照合する。
- `model-units-ui` は共通単位を実ノート追加・再生位置・ミックスへ通し、保存後の再オープンも確認する。
  独立した期待値を持ち、消費側が同じ誤った単位を使っても通らないようにする。
- 上記 2 契約と反例を `scripts/verification.json` に登録し、既存の入力・履歴・描画の契約も維持する。
  置換した式を使う既存の反例は、新しい式でも同じ誤りを戻すように更新する。
- 新しい ABI の未解決シンボルは、まず製品ライブラリ・生成ヘッダ・Swift の再リンクを照合する。
  データ・ログの新しい出力先はなく、診断の収集対象は変えない。

## 境界と残る範囲

保存形式・アクション JSON・C ABI の既存の時刻フィールドは整数のままで、形式を変えない。
既存の幾何の全フィールドを Swift の `Tick` に包む変更は行わない。
ループ範囲の UI 下書きも従来の `Double` の拍を保ち、送信時の共通変換を使う。
この下書きの整数化は SPG-04 の残りであり、監査全体を完了とはしない。

描画と音声の実機計測・VoiceOver・聴感はユーザー担当とし、自動検査の結果と区別する。
