# 0040. 音を決める計算は libm で行い、足す順を固定する

- 日付: 2026-10-09
- 状態: 採用
- 項目: ENG-9

## 背景

メトロノームのクリックは `f32::exp` と `cos`、モノのパンは `cos` と `sin` を使う。Rust のこれらの関数は OS の数学ライブラリを呼ぶ。macOS を更新すると最下位ビットが変わり、ゴールデンテストとプレビュー用キャッシュの一致が OS の版に依存する。

wavesynth 0.1.0 は、すでに `libm` 0.2.16 を使っている。`libm` は MIT OR Apache-2.0 で、musl の数学を Rust に写したものであり、OS の版では結果が変わらない。

rubato 5.0.1 の sinc 係数は、標準ライブラリの `sin` で作る。ARCHITECTURE §7.5 は、その方式のシークを丸め誤差の範囲としている。§7.8 のキャッシュの鍵は、選んだ実装とその版を含む。macOS の版は含まない。

## 決定

- Echode が音を決めるために書く `exp`、`sin`、`cos` は、`libm` 0.2.16 の `expf`、`sinf`、`cosf` を使う。標準ライブラリの同名の関数は使わない。対象は、メトロノームのクリックと、モノをステレオへ振る等電力のパンである。計測用の信号発生は対象にしない
- 表を新しく作って三角関数を置き換えない。`libm` がすでに要件を満たす
- 依存実装が OS の数学ライブラリで係数やサンプルを作る場合は、キャッシュの鍵に macOS の版を足す。版は `sw_vers` のプロダクト版である。rubato の sinc はこれに当たる。実装の識別子と版は、今どおり鍵に含める
- サンプルの足し算は、呼び出し側が渡したトラックの順、その中ではチャンネルの並びの順、左から右へ足す。並列にしても、この順の総和とビット単位で同じになるようにする。対ごとに足して木にする並びにはしない
- この方針は ARCHITECTURE §7.8 の鍵の説明にも一行足す

## 結果

`make check` が通った。クリックと等電力のパンは `libm` 0.2.16 を使う。キャッシュの鍵に macOS の版を足す条件は、ARCHITECTURE §7.8 に書いた。
