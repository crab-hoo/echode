# ADR 0132: プラグイン独自のウィンドウをヘルパーが持ち、プラグイン側の変更を履歴へ中継する

- 日付: 2026-10-21
- 状態: 採用。P2-02 のプラグイン GUI の最初の接続
- 範囲: CLAP `clap.gui` のヘルパー所有ウィンドウ、開閉とフォーカス、`clap_host_params`、プラグイン側の値変更とジェスチャーの中継、単一 Undo

## 背景

P2-02 の残る範囲に、ヘルパー所有の GUI と、プラグイン側の値変更の中継があった
（[ADR 0130](0130-clap-parameter-editing.md)、[ADR 0131](0131-device-view-and-responsive-parameters.md)）。
ヘルパーは `flush` と `process` の出力イベントを捨てており、プラグイン画面で変えた値は背景の自動保存でだけ取り込まれていた。
その変更は Undo に入らず、デバイスビューの一覧にも即時には出なかった。

ウィンドウはヘルパーのメインスレッドの run loop が持つ（[ADR 0041](0041-helper-threads.md)）。
キーウィンドウにしてメニューバー・ショートカット・Space を奪わないことは [ADR 0111](0111-macos-helper-notices.md) で決めていた。

### 2026-10-20 のユーザー回答

1. 名前クリックで開く・前面へ出す時も、入力フォーカスは取らない。プラグインのウィンドウは、ユーザーがその中をクリックした時だけフォーカスを得る。
2. 開いたウィンドウは、ユーザーが閉じるか、デバイスの削除・オフライン化・文書の終了まで残る。別トラックを選んでも残す。
   Echode がアクティブな間は Echode の上に浮かび、別アプリがアクティブになると隠れ、戻ると再表示する。
3. 開始・終了（ジェスチャー）のない変更は、値の変化も `mark_dirty` だけの変更も、約 0.5 秒静止した後に状態が変わっていれば 1 回の Undo にする。
   待つ間は背景の自動保存を保留する。読み取り専用の値は Undo に入れない。
4. 自動で開くのは候補パネルからの単体追加（ダブルクリック・Return・ドラッグ）だけとする。
   デバイスの複製・コピー、選択トラックへの一括追加、トラック複製では開かない。
5. プラグイン画面が入力を受けている間、プラグインが使わないキー（Space、Command＋Z など）は今回は Echode へ転送しない。

2026-10-21 の回答で、3 は該当プラグインのウィンドウが開いている間だけとした。
ウィンドウが閉じている時のプラグイン自身の変化（読込直後の `mark_dirty` など）は、従来どおり自動保存だけにする。

## 決定

### ウィンドウはヘルパーのパネルとする

- 埋め込み型（Cocoa、非浮動）を優先する。ヘルパーが `NSPanel` を作り、その content view を `set_parent` へ渡す。
  浮動型だけに対応するプラグインは、プラグイン自身のウィンドウを `suggest_title` と `show` / `hide` で扱う。
- パネルは titled・closable・nonactivatingPanel で、floating level、`hidesOnDeactivate` を切る。
  前面化は `orderFrontRegardless` で行い、キーウィンドウにしない。中のクリックでだけキーになる。
- ヘルパーは最初のウィンドウで `NSApplication` を accessory として起動し、以後は同じメインループで AppKit のイベントも回す。
  ウィンドウを開かないヘルパーは従来どおり `CFRunLoop` だけを回す。
- 開く・前面化・隠す規則は AppKit から分けた `WindowPolicy` が決める。
  ヘルパーは各周回で最前面のアプリが親（`getppid`）かを見て、親が非アクティブの間は隠す。
- ユーザーが閉じた時と、プラグインが `closed` / `request_hide` を呼んだ時は、プラグインの view を `destroy` し、親へ一度だけ通知する。
  次の表示は作り直す。プラグインを止める前にも view を壊す。
- サイズは CLAP の Cocoa の約束どおり point で扱う。リサイズ可能なら、ユーザーの変更を `adjust_size` / `set_size` で伝え、`request_resize` にも従う。

### 開閉の経路

- 制御メッセージ `GuiShow(title)` / `GuiClose` を加えた。返答は `GuiShown{created, visible, key}`、`GuiClosedReply`、`GuiRejected(理由)`。
  `clap.gui` を持たないプラグインは「the plugin has no window」で拒否する。
- 画面は `device.gui.show` / `device.gui.close` を送る。文書ワーカーは検査と制御端点の解決だけを行い、往復はデバイスレーンで待つ。
  閉じる要求は出力もヘルパーも開かない。
- 題は「トラック名 — プラグイン名」とする。同じプラグインを複数開いても区別できる。

### プラグイン側の変更の中継

- `process` と `flush` の出力イベントのうち、値・ジェスチャー開始・終了を、事前確保の SPSC リングへ書く。処理スレッドは確保・ロック・待機をしない。
  リングが溢れたら「失われた」印を立て、親は一覧を読み直して変更を終わったものとして扱う。
- `clap_host_params` を実装した。`request_flush` は処理スレッドを起こし、停止中も空の入力で `flush` する。
  `rescan` は親へ一覧の読み直しを伝える。オートメーション・変調はまだないため `clear` は何もしない。
- 制御スレッドはリングを読み、関係する ID の値と文字列をメインスレッドで読み直して、1 件の `ParamRelay` 通知で送る。
  読み取り専用と、プラグインが記述しない ID は除く。
- 親の制御端点は、受け取った順に通知を振り分ける。中継・閉鎖・窓が開いている間の `Dirty` はソケットの排他と別の保管に移し、要求の返答待ちが取らない。
  中継には、届いた時に窓が開いていたかを付ける。
- 文書ワーカーは各周回で活動を集め、文書単位の受け口へ移す。
  ジェスチャー、または窓が開いている間の値・失われた印・`Dirty` があれば、そのデバイスを編集中として背景保存の記録を保留する。
- 画面は `echode_document_plugin_activity` を専用スレッドで待ち、ワーカーを待たずに読む。

### 履歴

- 画面はデバイスごとに開いているジェスチャーを数え、全部が終わった時に既存の `device.parameter.commit` で記録する（[ADR 0130](0130-clap-parameter-editing.md)）。
  同じバイトの記録は履歴に積まないため、終了が重なっても Undo は増えない。
- ジェスチャー外の値・`Dirty`・失われた印は、窓が開いている時だけ 0.5 秒の静止を待って記録する。
- デバイスビューでそのデバイスのパラメーターをドラッグしている間は、プラグイン側の記録を始めない。ドラッグの終了が同じ状態を記録する。
- 途中の値は記録を待たずにそのデバイスの一覧へ反映する。ポインタ下のパラメーターは値を戻さない。

## 残る範囲

- プラグイン画面が受けたキーの Echode への転送（Space・Command＋Z など）。今回はプラグイン側に届くだけである。
- 実ウィンドウの表示・前面化・アプリ切替時の隠れ方、第三者プラグインの GUI・リサイズ・浮動型の挙動はユーザー確認とする。
  自動回帰は記録用の窓を使い、実際の画面を開かない。
- 停止中の最初の表示で出力とヘルパーを開く間は、後続の編集が待つ（[ADR 0131](0131-device-view-and-responsive-parameters.md) の残る範囲と同じ）。
- 状態に GUI の大きさを含むプラグインは、窓を開いた後の `mark_dirty` で Undo が 1 回増えうる。実機で確かめる。
- デバイスビューに窓が開いていることの表示、FX 空欄と名前の入口の区別、サムネイル、複数選択時の追従は未実装である。
- 浮動型のプラグインは自分のウィンドウを持つため、フォーカスと隠れ方をホストが保証できない。

## 検査と診断

- 必須契約 `plugin-window-helper` は製品エンジンと実ヘルパーで、開く・前面化・閉じる・プラグイン側の閉鎖・再表示と、キーウィンドウにならないことを確認する。
  負の対照は前面化をキーウィンドウにする。
- 必須契約 `plugin-window-relay` は、停止中と再生中のジェスチャーと値、読み戻しの文字列、読み取り専用の除外、窓が開いている間の `Dirty` を確認する。
  負の対照はジェスチャー開始を値として読む。
- 必須契約 `plugin-window-undo-ui` は、ジェスチャー終了での単一 Undo、途中の値の即時反映、静止後の記録、窓が閉じている時の非記録を確認する。
  負の対照はジェスチャー終了で記録しない。
- 必須契約 `plugin-window-open-ui` は、列の名前クリック、前面化、単体追加とドロップの自動表示、一括追加・コピー・トラック複製・オフラインで開かないことを確認する。
  負の対照は一括追加でも開く。
- テスト用 CLAP の `ECHODE_TEST_FAULT=gui:<socket>` は、ヘルパーに記録用の窓を選ばせ、プラグイン画面での操作をソケットから行う。製品のプラグインには影響しない。
- 単体テストは、通知の振り分け、符号化、リングの溢れ、`WindowPolicy`、受け口の待機と滞留、背景保存の保留条件を確認する。
- 失敗の手掛かりは `the plugin has no window`、`the plugin has no Cocoa window`、`plugin window timed out`、`the plugin refused the window`。
  切り分けは [デバッグ手順](../debugging.md) に置く。
