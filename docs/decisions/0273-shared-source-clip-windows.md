# ADR 0273: 長いトリムは共有の PCM の窓を読む

- 日付: 2026-11-06
- 状態: 採用
- 対象: EXT-01。ディスクからの逐次読込み（[ADR 0108](0108-phase1-loop-readiness.md)）と、準備中の一時的な複製は対象外。

## 問題と再現

`clips.rs` は配置の形（素材・先頭位置・長さ）ごとに窓の PCM を新しく作った。
同じ形どうしは共有したが、トリムの違う長い配置が多いと、素材の何倍もの PCM を持った（[精査](../reviews/2026-11-06-assessment-review.md)）。
`clips::tests::audit_ext01_long_trims_of_one_source_hold_one_copy_of_its_pcm` は、1 秒のステレオ素材（384,000 バイト）を 8 か所に別のトリムで置き、準備後に 2,856,000 バイト（7.4 倍）を持つことを再現していた。

## 決定

`LoadedClip` に任意の `ClipWindow { lead, frames }` を足す。
配置のフレーム `i` は面の `lead + i` を読み、面の外は無音である。`None` は従来どおり面の全体を先頭から読む。
エンジンの `StoredClip` と `FadedClip` は、この窓で終端・フェードの長さ・読む位置を決める。
オーディオスレッドに増えるのは整数の加算と範囲の判定だけで、確保・ロック・待ちは加えない。

読込みは素材ごとに、異なる窓の長さの和を、素材自身のデバイスレートのフレーム数と比べる。

- 和が素材以上なら、素材の面を 1 つだけ持ち、全ての配置がその窓を読む。
- 和が素材未満なら、従来どおり窓だけを複写し、最後の配置で素材の全体を手放す（M27-03 の短いトリム）。

どちらでも、素材 1 つあたりの常駐は、素材と窓の和の小さい方を超えない。

ゲインの桁あふれは、配置が読むフレームのピークで判定する（[ADR 0241](0241-unscaled-placement-pcm.md) の意味を保つ）。
共有の窓は準備の時に範囲を 1 回走査し、そのピークを窓ごとに保持する。
ライブの読込みは前回の窓を再利用するが、共有と複写の種類が今回の判定と違う窓は使わない。2 つ目の複製を持たないためである。
種類が変わる時は、前回の素材の面があればそれを使い、なければ素材を読み直す。

## 回帰と基盤

- EXT-01 の再現の `#[ignore]` を外して通常テストにした。
- `block_size/clip_window.rs` は、素材内のトリム・素材前の無音・素材後の無音・両側にはみ出す窓を、モノとステレオ、ループの有無、ブロック長 1・7・64・512 で、複写した窓とビット単位で比べる。
  `under_rtsan` の名前で、`make rtsan` にも含まれる。
- 負のオフセットの回帰は、面が素材の長さのままで、前の無音を窓で読むことを確かめる。
- 短いトリムの解放、ゲイン変更で読み直さないこと、非有限値の拒否の既存の回帰は維持する。
- 通常の crate テストで実行されるため、検査の登録は追加しない。

## 残る範囲

- 準備中は素材の全体を復号・分離・変換し、一時的に複数の複製を持つ。復号中の最大量と実際の RSS は測っていない。
- ディスクからの逐次読込みは未実装で、48 kHz ステレオ 1 時間の素材は 1 コピー約 1.38 GB を常駐させる。
- 実際のプロジェクトでの削減量と聴感は確認していない。音はビット単位で同じであり、聴感の確認は追加しない。
