# ADR 0274: 変わらないトラックの再生計画を使い回す

- 日付: 2026-11-06
- 状態: 採用
- 対象: FCA-04。計画の複写と声の表の初期化はノート数に比例して残る。
- 後続: 番号順の組（`by_number`）は [ADR 0279](0279-unchanged-track-voice-handover.md) でなくした。

## 問題と再現

`PlaybackControl::replace` は 1 回の編集ごとに、全トラックの計画を作り直した（[コード全体の監査](../reviews/2026-11-03-full-code-audit.md)）。
作り直したのは、ノートの時刻変換と番号付け、2 つの整列、カーソルの索引、番号順の組、イベントの必要量である。
`playback::tests::audit_fca04_an_edit_replans_only_the_track_it_changed` は、16 トラック × 64 ノートで 1 トラックに 1 ノートを足した時に計画したノート数を数える。
修正前は 65 であるべきところ 1,025 で、期待終了コード 101 と `one edited track replanned every track` のアサーションを照合した。
番号表は、[ADR 0267](0267-current-playback-id-mappings.md) で現在の計画のものだけを毎回作り直す形にしていた。

## 決定

制御側の `PlaybackIds` に、最後に成功した計画のトラックごとの記録を持つ。
記録は、トラックの `Arc<Track>`、各クリップの内容の `Arc<Content>`、計画、カーソルの索引（`NoteIndex`）、番号順の組、イベントの必要量である。
次の計画では、トラックと全ての内容が同じ `Arc` で、テンポマップとレートも同じなら、そのトラックの記録をそのまま使う。
記録が `Arc` を持つので、比較の相手のアドレスが別の物に再利用されることはない。
モデルには、この比較のために `Project::shared_content` を足した。

番号表はノートの番号と使用数を持つ。使用数は、そのノート ID を指す現在の計画の区間の数である（同じ内容を 2 回置くと 2）。

- 作り直したトラックの区間を数えてから、置き換えられた計画の区間を引く。0 になった番号は解放する。
- トラックの間を移ったノートも番号を保つ。
- 使い回したトラックは表に触れない。
- 消えた番号を再利用しないこと、失敗した計画が直前の表を変えないこと、空の計画で容量を 0 に戻すことは ADR 0267 のまま保つ。
- 失敗した計画で新しく振った番号は捨て、その番号も使わない。

カーソルの索引は `echode_realtime::NoteIndex` として `Arc` で共有し、`Plan::cursor_with` が受け取る。
退いた計画は制御スレッドへ返して解放するので、オーディオスレッドが最後の参照を落とすことはない（`carried_notes` と同じ）。
イベントの必要量は、ループの範囲とブロック長が同じ時だけ使い回す。
読み込んだクリップの検証とトラックへの振分けも、トラック数 × クリップ数の走査をやめ、1 回の分類にした。
音とイベントの順序は変えない。

## 同条件の計測

Apple M4、release、機器・プラグインなしの `make spike-scale`。両版を同じ作業ツリーの前後で続けて計測した。
256 トラック × 4,000 ノートで、トラック 0 の 1 ノートの音高を 20 回変える。

| 採用までのブロック | `replace_p50_ms` 前 → 後 | `adoption_p50_us` 前 → 後 |
|---:|---:|---:|
| 100 | 411.9 → 7.1 | 2,019.9 → 1,297.7 |
| 3,500 | 405.4 → 6.2 | 1,816.6 → 1,212.7 |

ループの折り返しとモデルの編集の値は、計測の揺れの範囲で変わらなかった。
プラグイン付きの `make spike-plugin-tracks` も修正後に合格した。採用のブロック（`plugin-edits`）の CPU の p50 は 256 トラックで 1,590.6 µs で、取りこぼしは 0 だった。
同じ条件の修正前の値はないため、この値で改善を主張しない。
単回の経過時間の比較であり、実画面の応答時間や全入力の最悪時間を保証する値ではない。
監査時の 278 ms は、その後の変更を含む前の値と同じ条件ではないため、比べていない。

## 回帰と基盤

- `audit_fca04_*` は、編集した 1 トラックだけを計画し、派生の計算がそのノート数の 2 倍以内で、ループの変更では計画しないことを数える。
  計数は `cfg(test)` の欄だけにあり、release の処理・確保を変えない。
- `plan_tests::reused_track_plans_match_full_rebuilds_across_edits_and_undo` は、乱数の 400 手の編集と Undo で、毎回の全体の作り直しと同じ区間・ミキサー値・終端順になることを比べる。
  手はノートの追加・削除・変更、ミキサーのゲイン、テンポ、別トラックへのリンク配置、古いスナップショットへの戻りである。
  生き残ったノートの番号の保持、使用数と表の件数の一致、使い回した索引と番号順の組が作り直した物と等しいことも確かめる。
  使い回し・全体の作り直し・共有されたノート ID のそれぞれに十分届いたことも検査する。内容の同一性の比較を外すと失敗することを手で確かめた。
- ADR 0267 の番号表の回帰と、ブロック長・ループ・再生中の編集の既存の回帰は維持する。
- 通常の crate テストで実行される。検証基盤の肥大化の指摘（[精査](../reviews/2026-11-06-assessment-review.md)）を踏まえ、必須契約は追加しない。

## 残る範囲

- 使い回したトラックも、計画への複写と、カーソルの声の表（ノート数の長さ）の初期化は毎回行う。256 × 4,000 ノートで約 6〜7 ms である。
- テンポやレートが変わると全トラックを作り直す。テンポの索引の作成がテンポ点の数の 2 乗であることは FCA-13 で扱う。
  → 作り直す時も、変わらないノートの番号は前回の計画から位置で取り、使用数を数え直さない（[ADR 0335](0335-retimed-plans-keep-note-numbers.md)）。
- `MediaInputs::of` とクリップの読込みの照合は、クリップ数に比例する。
- プラグイン付きの採用は修正後の値だけで、制御側の `replace` の時間は `spike-plugin-tracks` では測っていない。
