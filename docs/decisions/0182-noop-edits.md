# ADR 0182: 無変更の編集を成功として受け、履歴を増やさない

- 日付: 2026-10-27
- 状態: 採用
- 対象: [敵対的監査](../reviews/2026-10-27-adversarial-audit.md) ADV-04、Session・DocumentHost・API / MCP

## 背景

同じベロシティを設定するだけで、空の変更集合が Undo とジャーナルへ記録されていた。
最初の Undo が何も戻さず、Undo 後の無変更の依頼も Redo を失わせる。
履歴復帰では既に空の差分を記録しない（[ADR 0054](0054-history-restore.md)）。
通常の編集もこの規則へそろえる。

## 決定

- 無変更は拒否ではなく成功とする。単一編集は Action、一括編集は受理した全 Action を元の配列位置で返す。
  JSON-RPC v1 の応答形と MCP の `isError: false`、テキスト・構造化結果の対応は変えない。
  成功は依頼の受理であり、Undo の段を作ったことを意味しない。MCP のツール説明にも明記する。
- `Session::perform` とトランザクション内の個別操作は、変更集合が空ならモデル・履歴を変えない。
  同値に見える入力でも、モデルの検証は省略しない。存在しない対象や範囲外の値は従来どおりエラーにする。
- トランザクションは、成功時だけ Undo・ジャーナル・Redo を更新する。
  全操作が無変更の場合と、途中で変更しても最終プロジェクトが元と等しい場合は、元のスナップショットと Redo を保つ。
  実際の変更が残る束だけを 1 回の Undo として記録し、途中失敗ならモデルを元へ戻す。
- `DocumentHost` は、セッションのジャーナルが増えた時だけ新しい編集を公開・追記・自動保存する。
  受理した Action の個数を記録の有無と混同しない。無変更なら退避した Redo を戻す。
  過去の記録を読み替えることや、旧ジャーナルの空の行の削除はしない。
- 比較と履歴の処理は制御側だけで行う。音声スレッド、プラグイン隔離、保存形式は変更しない。

## 再現と回帰

修正前の `audit_adv04_an_edit_that_changes_nothing_adds_no_undo_step` は終了コード 101 で、
`the first undo removed an empty step, not the note`（ノート数 1、期待 0）により失敗した。
追加した製品ホストの回帰も `a no-op must not publish` で失敗することを確認した。
これは `checked_commands.py` で期待終了コードと固有のアサーションを照合した結果であり、ビルド失敗とは区別する。

監査の再現は `#[ignore]` を外して通常回帰へ移す。
C ABI の perform 完了は既存の `historyReport` に空の revisions と changed を載せる。
Swift は changed が真の時だけ Undo 件数と入力長の履歴枠を増やし、無変更で Redo を消さない。
この追加の回帰は修正前に `a no-op must not consume visible history` で失敗した。
`crates/echode-history/tests/noop_edits.rs` は同値・相殺・混在・途中失敗・参照位置を通し、
公開する Arc、ジャーナルのバイト列、自動保存の版数、Redo と再オープンを確認する。
Session の単体回帰と編集列の性質テストも、空の差分で履歴が増えないことを検査する。
実 CLI の MCP → Unix ソケット → API → DocumentHost で、無変更の成功応答・Undo・Redo・復旧を通す。

必須契約 `noop-edits` は単一操作の空差分判定と一括操作の正味の判定を外す負の対照を持つ。
`mcp-noop-edits` は相殺する一括編集を再び履歴へ積む負の対照を持つ。
`noop-edits-ui` は Swift 側で無条件に履歴を増やす負の対照を持つ。
既存の `check-product-contracts` と検査選択の回帰へ登録し、正式な結果は検査レポートに記録する。
初回の `make verify` は `check-product-contracts` 全体の 1800 秒で時間切れとなった。
通常回帰や新しい契約の個別アサーションの失敗ではなく、負の対照の一括処理が未完了だった。
対象や期限は緩めず、同じ入力で完了した契約だけを既存の仕組みで再利用して再実行する。
2026-10-28 の再検査では、Swift の全負の対照が終わるまで完了分を保存しない基盤の不備も判明した。
[ADR 0148](0148-verification-pipeline-speed.md) の契約単位の保存を実装へ反映し、既存の全反例と期限を保ったまま再実行する。
中断を模した回帰で先行契約の保存と、複数反例の途中結果を再利用しないことを検査する。

## 診断と対象外

空の Undo の調査では同値の依頼と `changes: []`、その前後の連番・Redo の有無を照合する。
[デバッグ手順](../debugging.md) へ症状と回帰の入口を追加する。新しいログ形式や収集先は不要である。
実機・聴感・実画面の操作は、この履歴制御の機器なし回帰と別の確認である。
[ADV-02 / ADV-03](../reviews/2026-10-27-adversarial-audit.md) は今回の対象外とする。
