# ADR 0297: 自動保存の待ち手へ元のエラーを共有して返す

- 日付: 2026-11-09
- 状態: 採用
- 対象: [未完了項目の統合](../reviews/2026-11-08-open-items-register.md) の M1 のうち、製品の Git と自動保存。
- 関連: [ADR 0296](0296-typed-storage-errors.md)（保管庫・復号）、[ADR 0234](0234-typed-journal-durability.md)（保存の不確定）。

## 問題と範囲

開始時の HEAD は `68df8b0`。保管庫から返す I/O は型になっていたが、
自動保存の `answer` は失敗を文へ変えて、各待ち手へ `PackageError::Message` として複製していた。
元の errno と原因に加えて、`JournalDurabilityUnknown` の区別も失われる形だった。
Git の初期化の失敗も文を保持し、後の全要求へ文のコピーを返していた。

製品の `Autosave::load` で存在しないコミットを読む回帰は、修正前に
`autosave revision load lost its Git cause` で失敗した。
期待終了コード 101 と固有のアサーションを照合した記録は `target/focused-checks/autosave-errors-red/` にある。
同時に追加した保存・初期化の試験の最初の入力は、ワーカーより前のレイアウト検証で拒否されていた。
その 2 試験は再現の証拠に数えず、保存側は起動完了後の障害、初期化側は `.git/config` の不正へ修正した。

## 比べた案

| 案 | 判断 |
|---|---|
| 文を複製し、種類の印も別に複製する | 採らない。原因と印が別の正本になり、errno・Git の原因を保持できない |
| `PackageError` 全体を `Clone` にするため、I/O・JSON などの各ペイロードを `Arc` に変える | 採らない。自動保存の配達だけのために、移行済みの素材の変種と利用側まで変わる |
| 全公開メソッドを `Result<_, Arc<PackageError>>` に変える | 採らない。自動保存以外の境界と署名を揃え直す範囲が広い |
| 自動保存の配達だけ `Shared(Arc<PackageError>)` にし、元の変種へ共通の入口を設ける | 採る。既存の署名と原因を保ち、待ち手が同じ失敗を読む |

時間の最適化ではないため、性能の計測はしない。
根拠は製品の入口の回帰、同一の `Arc` と原因の照合、再導入を拒否する検査である。

## 決定

- `PackageError::Shared` は配達の包みで、`original()` は包みを除いた元の変種を返す。
  内部の `into_shared()` は既存の共有を再利用し、配達ごとに包みを積まない。
  `Display` と `Error::source` も元の原因へつなぐ。
- `is_durability_unknown()` は `original()` の 1 つの規則で判定する。
  複数の待ち手や受信側がなくなった要求が混じっても、不確定を文へ戻さない。
  同じ文の `Message` を不確定と見なすことはない。
- Git は `Git { operation: GitOperation, error: gix::Error }` とする。
  初期化、オブジェクトの読書き、コミット、参照、時刻などを操作の種類で分け、gix の原因・分類をそのまま保つ。
  型変換の拒否だけは従来の Debug 表示を保ち、ほかの文は Display で作る。
- ワーカーの終了、受信の時間切れ、増分保存の内部契約の違反は `AutosaveError` とする。
  30 秒の期限は変えず、従来の時間切れ時の誤った `autosave thread stopped` は `autosave request timed out` に分ける。
  取消・自動再送は追加しない。
- Git の木の読込みと同期コミットは `document_git.rs` に分ける。
  トラックと内容のファイルの読込みは同じ関数を使い、欠落・UTF-8・オブジェクトの種類の拒否も型で返す。
  JSON の検証、復旧の同意、ジャーナルの短縮条件、同期の順番、保存形式は変えない。

## 回帰と基盤

- `tests/autosave_errors.rs` は公開の `Autosave` で、保存の I/O、初期化の失敗の継続配達、
  存在しない版の読込み、参照へのコミット失敗、版のファイルの欠落・種類・UTF-8 を照合する。
  障害に使ったファイルを消さず、元の内容が残ることも照合する。
- `autosave_tests.rs` はキューの合流を決定的に通し、受信側の消失を挟んでも全待ち手が同じ原因を持つことを `Arc::ptr_eq` で確かめる。
  I/O・Git・保存の不確定、受信の未完了・完了・切断を照合する。
  `error_tests.rs` は共有の再利用、元の errno、文からの誤判定防止、期限と切断の変換を照合する。
- `check_typed_errors.py` の `TYPED_FILES` に `autosave.rs`・`document_git.rs` を足す。
  Python の回帰は全登録ファイルで文の再導入を拒否する。
  新しい外部入力・依存・検査の入口はなく、既存の Rust・Python 検査とパッケージの fuzz が同じ入口を通す。
  `scripts/verification.json` の選択と反例の置換箇所は引き続き有効で、変更しない。
- 調査方法は保存のデバッグ手順へ足す。計測の見送りは検査レポートに理由を記録する。

## 残る範囲

`echode-history` 全体の型付けの完了ではない。
次はスキーマ・パッケージの検証、その後に文書のトランザクション・間引き・非既定の履歴スパイクを扱う。
ユーザーの実操作・聴感を変える作業ではなく、新しい実機確認待ちは作らない。
