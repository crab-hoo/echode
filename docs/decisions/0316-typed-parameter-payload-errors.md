# ADR 0316: パラメーター・窓・通知の内側の構造の原因を保持する

日付: 2026-11-11
状態: 採用
関連: M1（DEV-7・SPG-11・XCA-16）、[ADR 0315](0315-typed-control-metadata-errors.md)、[ADR 0312](0312-typed-control-text-errors.md)

## 問題と再現

開始時の HEAD は `1038a86`。
`params.rs` と `gui.rs` は、パラメーターの一覧・変更・読み戻し・文字入力の応答、プラグイン自身の変更の通知、窓の報告の不正を、定数の文だけの `io::Error` にしていた。
表示文は残るが、どのペイロードのどのフィールドで何番目の項目が切れたか、受けた値やコードが何だったかを型で読めなかった。
切詰めは通知でも `parameter message is truncated` の 1 文で、数百のパラメーターのどこで尽きたかは分からなかった。

製品の `Socket::recv_tagged` に不正なペイロードの生フレームを送る回帰を先に追加した。
修正前は 6 つの回帰すべてが `malformed parameter payload must retain its typed structural cause` で失敗した。
種類（`InvalidData`）と表示文の照合は修正前も通るので、失敗は型の欠落だけを示す。
期待終了コード 101 と固有のアサーションの照合は `target/focused-checks/payload-decode-red/` に残す。

## 比べた案と決定

1. 定数の文を残す。別のフィールド・項目・値が同じ文へ消えるので採らない。
2. `ControlDecodeError` に変種を足す。あちらはメッセージになる前の外側の構造で、項目の番号や値のビットを持たない。
   一つの型に二つの層の読み方が混ざるので採らない。
3. パラメーター・通知・窓ごとに別々の型を作る。通知は読み戻しの列を共有し、窓の報告は 2 変種だけなので、層を増やさない。
4. **共通の `PayloadDecodeError` で構造を保持し、列の読込みを `Cursor::list` の一つにする。**

4 を採る。

- `Truncated` は `ParamPayload`（一覧・変更・読み戻し・文字入力の要求と応答・通知）、`ParamField`、列の中の項目の番号、必要なバイト数と残りを持つ。
  文字列の本体では、必要なバイト数は宣言された長さである。列の外のフィールドの項目は `None` にする。
- `TrailingBytes` はペイロードと余ったバイト数を持つ。
- 有限でない値は、変更なら項目の番号・パラメーター ID・IEEE-754 のビット、文字入力の応答ならビットを持つ。
  `f64` ではなくビットで持つのは、NaN の中身を保ち、原因を `Eq` で照合できるようにするためである。
- 未知の応答の種類・通知のフラグ（既知のビットを含む 1 バイト全体）・イベントの種類（項目の番号と ID 付き）は受けた値を持つ。
- 窓の報告は、長さの不一致（必要と実際）と、不正なフラグ（`WindowFlag` と受けた値）を分ける。

4 か所にあった「数を読み、確保を残りのバイト数で抑え、項目を順に読む」処理は `Cursor::list` へ移した。
エラーが指す項目の番号と、不正な数からの確保の上限を、同じ場所で決める。
確保の上限は残りのバイト数を項目の最小の大きさで割った値で、従来（本体全体の長さで割る）より大きくならない。

`io::Error::get_ref` から同じ型を読み、公開操作の `SessionError::Io` でも保持する。
文字列の UTF-8 の不正は、引き続き `ControlTextError` と元の `Utf8Error` で返す。
表示文・`InvalidData`・通信の形式・受理する入力・複数の不正がある時に先に返る原因は変えない。
一覧と読み戻しの有限でない値は従来どおり受理する（除外はヘルパーと `ParamInfo::usable` が行う）。
不正な生バイトは保持しない。音声処理・期限・保存・C ABI は変えず、性能改善は主張しない。

## 回帰と基盤

- `control_payload_tests.rs` は、製品の書込みと照合したフィールドの並びのモデルから、実ソケットで全バイト位置の切詰めを通す。
  対象は一覧・変更・読み戻し・通知・文字入力の応答で、空の文字列の次のフィールドへ進むことも含む。
  巨大な数と文字列長、余分なバイト、有限でない値（信号 NaN を含む）、全不正コード、窓の長さと最初の不正なフラグも型と従来の文面で照合する。
  正常値の往復はビット単位で照合し、一覧と読み戻しの有限でない値の受理を固定する。
- `session_payload_tests.rs` は、一覧・変更・文字入力・窓の表示の公開操作で同じ原因が `SessionError::Io` に残ることを検査する。
- 制御ソケットの fuzz の種に、これらのペイロードの不正な構造を追加する。
  通常の Rust 検査と既存の `control_inputs_replay` が通すため、Makefile と検査選択は増やさない。
- 領域別設計、コードの所在、診断手順と索引、監査の状態を更新する。
  利用者の制約・実機の確認場面は増えず、status.md とユーザー確認の一覧は変えない。

## 残り

M1 全体の完了とはしない。
`echode-sandbox` の制御ソケットに残る文だけの原因は、FD の受信規則の違反（3 種）と、送信側の引数の拒否（FD 付きの remap・64 MiB 超）である。
時間切れ・切断・書込み 0 バイトは `ErrorKind` で区別でき、文は補足である。次はこの FD と送信側の境界を扱う。
その後に、この crate の `io::Error::new` へ文字列リテラルを渡す再導入を `check_typed_errors.py` で拒否できるかを決める。
検査結果と各検査の見送り理由は `target/verification/report.md` を正本とする。
