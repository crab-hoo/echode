# 0357. パラメーターの再走査通知を読取り中にも受ける

日付: 2026-11-15

## 背景

値の通知の中継は、未知・読取専用のパラメーターを除くために説明のフラグを主スレッドで読む。
従来は `RefCell` の可変借用を保ったまま `params.get_info` を呼んでいた。
プラグインがその呼出しから `params.rescan(INFO)` を通知すると、キャッシュの無効化が同じセルを借り、ヘルパーが abort する。
実ヘルパーの回帰で、終了コード 101、`control socket closed`、`RefCell already borrowed` を確認した。
再現のログは `target/focused-checks/param-rescan-red/1.log` に残す。

## 比べた案と決定

- **通知中の借用失敗を無視する**: 不採用。異常終了は避けても、古いフラグを使い続ける。
- **通知のたびに全説明を読み、キャッシュをなくす**: 不採用。関係しない値の通知でも全パラメーターを列挙する。
- **借用を解放してから読み、無効化の世代を照合する**: 採用。
  読取り中に通知が来た結果はその回のスナップショットだけにし、次の読取り用に保存しない。
  読取りを自動反復せず、通知を毎回送るプラグインでも主ループを止めない。

キャッシュと無効化は `ParamFlags` に集約する。
同じ主スレッド内の読取りは `Rc` で共有し、従来の通知ごとの全マップの複製もなくす。
インスタンス生成前にキャッシュを無効化し、同じスレッドで次のインスタンスを動かす時も古い ID を使わない。
音声スレッド・IPC・保存形式・公開 ABI は変えない。性能の実時間の比較は行っていない。

## 回帰と基盤

`echode-test-plugin` の `params-rescan` は、停止中の `flush` で値を通知し、説明の読取り中に名前等の再走査を通知する。
実ヘルパーで繰返しの通知・変更後の値・継続する音声を確認する。
単体回帰はキャッシュの共有・通常の無効化・読取り中の無効化と、無効な読取り結果を次回へ残さないことを確認する。
通常の Rust 検査と既存の `under_rtsan` の選択に入り、新しい実行入口や選択規則は足さない。
設計書・コードの所在・診断手順を更新する。
画面・操作・機器の経路は増やさず、新しいユーザー確認項目は作らない。第三者互換・聴感の未確認は既存の UC-21〜23 に残る。
