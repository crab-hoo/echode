# ADR 0383: ノートを各段の入力音声の時刻で生成する

- 日付: 2026-11-16
- 状態: 現行
- 領域: 音声エンジン・書き出し
- 一部置換: [ADR 0236](0236-callback-work-per-track.md) の全体カーソルからのイベント配布。トラックのキーの索引と全体を繰り返し走査しない規則は維持する
- 関連: [ADR 0340](0340-latency-graph.md)、[ADR 0378](0378-pdc-stage-transport.md)、F2・FCA-07・P2-03

## 問題と再現

差分の基準は `38f05ec`。
音声とトランスポートは段の入力遅れへ揃うが、ノートは全段へ処理先頭の時刻で配っていた。
前段に遅延があると、ノートを受ける後段 FX が入力音声より早く反応する。

`hosted_playback/pdc_notes.rs` に実ヘルパーの 37 サンプルの遅延と、ノートの時刻通りに鳴るプローブを置いた。
修正前は `PDC notes disagree with input audio` と終了コード 101 で失敗した。
証拠は `target/focused-checks/pdc-notes-red-corrected/` にある。
最初の試作はノートの tick 長が短すぎてサンプル長が 0 になったため、その成功は根拠にしない。

## 比べた案と決定

- **入力イベントを段ごとの遅延キューへ貯める**: 不採用。
  保持量が局所のブロック密度だけでなく遅延長にも依存し、停止での破棄と計画交換での未来のイベントの取扱いが増える。
- **最初の音源だけ補正する**: 不採用。後段のノート応答とフォルダ FX のずれを残す。
- **各段が入力音声と同じ軌跡の楽譜を読む**: 採用。
  `Compensation::stage_inputs` をそのまま使い、遅延の式や別の時刻変換を増やさない。
  既存の `Cursor`・`NoteIndex`・`split_loop` を再利用し、発音中の集合だけを段ごとに持つ。

楽譜のコピーと索引はトラック単位で共有し、変わらないトラックは次の計画にも引き継ぐ。
全体カーソル・全体イベント列・振分け・トラックごとの再コピーは削除し、二重の配布経路を残さない。
イベントの領域は既存の局所密度・追いかけ・前の計画の終了通知の予約から制御側で確保する。
段のカーソルの記憶域はそのトラックのノート数、イベントの領域はブロック局所の需要に比例する。
使用メモリと修正前後の時間の比較は未計測であり、高速化は主張しない。

`spike-plugin-tracks` の現在の構成での release 計測（48 kHz・128 フレーム、200 ブロックの準備後に 2,000 ブロックを進め、折返し・採用は該当ブロックだけ採取）は次の通り。
値はコールバック自身の CPU 中央値をトラック数で割った ns で、機器は開いていない。

| 場面 | 1 | 16 | 64 | 256 |
|---|---:|---:|---:|---:|
| FX ありの通常処理 | 8,042 | 4,180 | 4,139 | 4,371 |
| プラグインなしの和音 | 1,083 | 565 | 572 | 572 |
| FX と和音の折返し | 7,500 | 4,672 | 4,639 | 5,205 |
| FX と和音の計画採用 | 7,917 | 4,464 | 4,458 | 5,112 |

この範囲ではトラック数に伴う 2 乗の形は見えないが、チェインの深さと長い楽譜の記憶域は別の測定範囲である。
ヘルパーの期限は採取用に 1 秒とするため、取りこぼし 0 を実機の締切保証とは扱わない。
256 トラックの折返しの CPU は p99 2.616 ms・最大 2.883 ms、壁時計は最大 3.384 ms で、128 / 48 kHz の 2.667 ms を超える採取もある。
原データは `target/spike-plugin-tracks.json`、実行記録は `target/verification/spike-plugin-tracks.log`。

## 時刻と終了の規則

- 初回と位置移動の後は、遅延線が満ちるまではノートを生成しない。
  トランスポートの原点前への外挿とは分け、原点の保持ノートも到着フレームで追いかける。
- 遅延より短いループでも原点と経過フレームから求める。終端ちょうどは `split_loop` へ終端として渡し、解放してからループ頭を発音する。
- 計画の採用は同じノート ID と開始時の音高を引き継ぎ、残るノートを二重に発音しない。
  遅延の増加で再びプリロールへ入る場合は古い声を解放して待つ。
- 停止と位置移動の終了通知は各段の保持集合から作る。
  元の音源側のノートが終わっていても、後段に残る声を解放する。リセットだけで通知を捨てない。
- 取りこぼしも段ごとのイベントで判定する。
  源流にイベントがないブロックでも後段の終了通知を失うので、源流の有無では判定しない。
- 音声側の確保・解放・ロック・時計読取りは増やさない。失敗した計画の所有権も制御側へ返してからエラーにする。

保存形式・IPC・C ABI・依存ライブラリは変えない。

## 回帰と基盤

実ヘルパーの回帰は 48・96 kHz、1・7・64・512 フレーム、負の開始と保持中への開始、30 サンプルのループ、後段とフォルダを比較する。
計画交換・音源側の終了後の停止・取りこぼした遅延ノートオフの復帰も製品の再生器を通す。
単体回帰は exact な折返し・原点前からの追いかけ・ID と音高の引継ぎ・削除・遅延の増加を確保禁止ガードで検査する。
イベント列の参照も境界を検査し、不正な長さと容量不足は panic や黙った破棄にせずエラーへ戻す回帰を加える。

必須契約 `plugin-pdc-notes`・`plugin-pdc-note-lifecycle`・`plugin-pdc-note-recovery` と反例を追加する。
`track-event-routing` の反例は、削除した全体の振分けから、段へ誤ったトラックの楽譜を渡す対照へ移す。
`stopped-plugin-tails` の反例も、削除した全体カーソルの解放から、停止時の `Notes::stop` を外す対照へ移す。
後者は `held note survived` と終了コード 101 の意図した失敗を確認した（`target/focused-checks/pdc-stopped-control-red/`）。
古い振分け専用の単体テストは削除し、実ヘルパーのトラックごとのオン・オフ・追いかけの契約は維持する。
選択のテストと設計・制約・進捗・監査・診断手順を更新する。
既存の Makefile の入口と `under_rtsan` の選択を使い、新しいパーサーを増やさないので fuzz の入口は変えない。

第三者のノート応答の設定・プリロール時の解釈と聴感は UC-96 に残す。
`audio-ports-config`・曲からの表情生成・センド等は残り、F2・FCA-07・P2-03 全体の完了とはしない。
