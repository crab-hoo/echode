# 0381. MPE の表情は単独所有中のメンバーへ送り、ノートオン前に初期値を送る

- 日付: 2026-11-16
- 状態: 現行
- 領域: プラグイン・隔離
- 対象: P2-03・F2・FCA-07 の MPE 表情のホスト境界
- 一部置換: [ADR 0380](0380-mpe-member-channels-for-clap-ports.md) の表情を送らない判断

## 問題と再現

開始時の HEAD は `3af4f71`。MPE の曲のノートは鳴るが、共有イベントへ届いた音程・明るさ・圧力の表情は捨てていた。
表情の曲からの生成・編集は別の未接続であり、今回はヘルパーの受信・変換の境界だけを扱う。
`isolation/midi_notes.rs` で実ヘルパーへノートと表情を送り、変更前は終了コード 101 と `MPE expression/default stream: id=0, reset=false` を照合した。
証拠は `target/focused-checks/mpe-expression-red/` にある。

## 根拠

- [CLAP 1.2.2 の events.h](https://github.com/free-audio/clap/blob/1.2.2/include/clap/events.h) は音程を相対半音、明るさ・圧力を 0〜1 とする。
- [JUCE 8.0.6 の MPEInstrument](https://github.com/juce-framework/JUCE/blob/8.0.6/modules/juce_audio_basics/mpe/juce_MPEInstrument.cpp) はメンバーのピッチベンド・チャンネルプレッシャー・CC74 を受ける。
  初期値は音程と明るさが中央、圧力が 0 である。
- [同版の MPEMessages](https://github.com/juce-framework/JUCE/blob/8.0.6/modules/juce_audio_basics/mpe/juce_MPEMessages.cpp) は RPN 0 を下位ゾーンの最初のメンバーへ送り、全メンバーのピッチベンド幅を設定する。
  単体テストの既定値は ±48 半音である。実装は追加依存として取り込まず、通信形式の根拠として読む。

## 比べた案と決定

- **全メンバーへ表情を送る**: 不採用。共有中は他のノートへ音程・圧力・明るさが漏れる。
- **15 音を超えるノートを捨てる**: 不採用。従来鳴っていた曲の音を失う。
- **チャンネルの値を戻さず、表情だけを追加する**: 不採用。再利用したメンバーが前の音の表情で発音する。
- **単独所有中だけ表情を送り、ノートオン前に初期値を送る**: 採用。
  同じ `MpeZone` の所有・共有の数だけで判定し、別の発音表を増やさない。
  共有開始時にはそのチャンネルを中立へ戻すため、既存の所有ノートの表情も中立になる。
  共有が終われば所有ノートへの次の表情は送れるが、共有中に捨てた表情を再送しない。

ピッチベンド幅は固定の仮定にせず、処理開始・リセットごとにゾーン設定の後へ RPN 0 の ±48 半音を続ける。
この値は設定と変換が同じ定数を使う。MIDI 1.0・2.0・native の経路、形式の優先順位は変えない。

時間の比較計測は行っていない。最大の展開はノートオン 1 個から MIDI 4 個である。
ヘルパーの変換用バッファと任意の容量準備拡張は制御側でこの上界を確保し、u32 を超える容量は型付きの拒否にする。
音声側の確保・解放・ロック・新しい IPC は足さず、共有領域の容量自体は曲のイベント数のままである。

## 範囲と回帰

表情は指定ポートの所有ノート ID で宛先を決め、イベントのチャンネル・音高は使わない。
音程は ±48 半音へ、明るさ・圧力は 0〜1 へ収め、NaN・無限は送らない。
未保持・ID なし・共有中の宛先には送らず、ワイルドカードのポートを複数の MIDI ポートへ展開しない。
ノートオン前の順序は、ピッチベンド中央・圧力 0・CC74 中央・ノートオンとする。

- `mpe_expression_tests.rs`: 共有の開始・終了、他の所有者との分離、非有限値と範囲の端、ノートオンだけの高密度ブロックと確保禁止。
- `isolation/midi_notes.rs`: 実ヘルパーで表情のバイト列・時刻、16 回の再利用、リセット、共有中の抑止と 8 入力から 32 出力への展開を照合する。
- `hosted_playback/midi_notes.rs`: 既存の 48・96 kHz、7・64・512 フレームの製品波形比較を維持する。
  onset 専用の検査用音源は新しい中立値と RPN を許すが、表情の変化を音へ適用した証拠にはしない。

必須契約 `plugin-mpe-expression` と有限値の送信を止める反例を登録し、選択のテストを更新する。
ソースのコピー上でその反例を入れ、終了コード 101 と上記の回帰固有のアサーションで失敗することを照合した（`target/focused-checks/mpe-expression-control/`）。
既存の Makefile の契約・隔離検査の入口を使い、新しいコマンドは足さない。
外部入力やパーサーは増やさず、既存の共有イベントの境界を使うため fuzz の入口は変えない。
設計・進捗・制約・監査の現在欄・コードの所在と診断手順を更新する。
第三者の解釈と聴感は UC-94 に分け、曲からの表情生成・動的な音声ポートの寸法変更・後段ノートの PDC 補正は残す。
