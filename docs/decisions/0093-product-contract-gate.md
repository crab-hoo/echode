# 0093. 利用経路の回帰検査と、その検査が不具合を拒否することを必須にする

- 日付: 2026-10-15
- 状態: 採用
- 対象: 自動検査と終了フック、CU-03〜CU-06
- 後続: [ADR 0324](0324-no-agent-hooks.md) が終了フックをなくした。同じ検査は `make verify` と GitHub Actions から呼ぶ。

## 背景

通常の検査が通っても、実物と違う入力、安定した後だけの観測、操作関数の直接呼び出しでは利用経路の不具合を捕まえられなかった。macOS の CLAP バンドルは再生で飛ばされ、再生開始前の位置0が公開され、トラックヘッダの Space は上位へ届かなかった。

## 決定

`check-product-contracts` を全変更で選ぶ自動検査とする。`make check`、`make verify`、既存の Cursor の終了フック、GitHub Actions から同じ検査を使う。必須のテストと、検査用の誤りの定義は `scripts/verification.json` に置く。

- macOS 形式のバンドルを作り、別プロセスでスキャンし、キャッシュから解決したパスを再生へ渡す。楽器による内蔵音源の置き換え、エフェクトの出力、壊れたバンドルのエラーを確認する。寛大な待機期限はハングの保護であり、性能の合格条件ではない。
- HAL にコールバックを登録する製品と同じ準備を使い、コールバックをまだ呼ばない時点の位置と、初回処理後の位置を確認する。開始位置はエンジンの時計と公開ステータスの双方へ初期化する。稼働中の位置へ別の書き手を追加しない。
- ネイティブ View の `keyDown` に実際のキーイベントを渡し、Space と未処理キーが同じイベントのまま上位へ1回届くことを確認する。選択関数の直接呼び出しでは代用しない。

2 つ目の検査は再生開始時の位置の巻き戻り（CU-04）、3 つ目はトラックヘッダの Space の転送（CU-05）を回帰として保つ（2026-11-03 追記: 番号の対応は以前 status.md にだけあった）。

終了コード0だけで合格にしない。指定したテスト1件の成功を出力でも確認し、削除、無視、条件によるスキップ、0件実行を失敗にする。

さらに、現在のソースを一時コピーし、上記の既知の誤りを1つずつ戻す。そのコピーのテストが期待値の検査で失敗しなければ、検査の仕組み全体を失敗にする。コンパイル失敗やツール不足を「不具合を検出した」証拠には数えない。作業ツリー、Git のインデックス、ユーザーのプラグインやプロジェクトは変更しない。

## 実ウィンドウと範囲

実際の Space、遮蔽、表示リンク、アプリの前面への復帰は、画面なしのキー転送検査だけで合格にしない。実機回帰は引き続き明示した `spike-*` に置く。CU-03 のプレイヘッド回帰は、検査本体を専用モジュールへ移し、AppKit の `NSApplication.run()` 上で4件を順に実行する。通常の Swift テストは実ウィンドウの検査を呼ばない。起動完了の通知から検査を始める。計測の読み取りには現在の要求世代を含め、一時停止の確認はその世代が描かれたことも待つ。待機時間や無描画の期待値は緩めない。表示状態はウィンドウを閉じる前に保存する。

プラグインGUIは未実装であり、この検査の合格でGUIやPhase 1全体の完成を宣言しない。新しい機能は、その実物の入力と境界の期待値を検査へ追加する。未知のすべての不具合を自動で証明できる仕組みではない。

## 確認

修正前に3件ともテスト本体の期待値で失敗した。修正後は3件とも通過し、一時コピーへ戻した3種類の誤りもすべて拒否した。失敗と成功の記録は `target/verification/contracts-before-fix.log`、`contracts-with-controls.log`。最新の記録は `target/verification/product-contracts.json` と各ログに置く。検査選択、0件・無視・コンパイル失敗の区別も単体検査する。

実機の4件も正式な `make spike-playhead` から通過した。表示条件は現在の Space・非遮蔽・visible=true、未検証項目は空だった。記録は `target/verification/playhead-appkit.log`。
