# ADR 0077: イベントバッファは長さとの差で広げる

- 日付: 2026-10-13
- 状態: 採用
- 範囲: 監査 PRO-04。再生のノートイベントと、ヘルパー内の配送バッファ

## 背景

`Vec::reserve` の引数は、現在の長さに加える要素数である。目標容量から現在の容量を引いた値を渡すと、空のバッファは目標に届かない。共有領域だけが広がり、配送側がノートオフを捨てても、再生は失敗しなかった。

## 決定

容量が目標未満のときだけ、目標容量から現在の長さを引いた数を `reserve` に渡す。ヘルパーの共有領域と、親の配送リストの両方で同じ計算をする。配送リストに入りきらないイベントがあるブロックは、再生を失敗にする。

短いループが1ブロックで何度もノートを出す量は、制御スレッドでノート数にそのブロック長を掛けて用意する。コールバックではこのバッファを広げない。48 kHz で 100 サンプルのループは、64 フレームでも 512 フレームでも再生を止めない。

## 結果

すでに余裕があるバッファを、その容量より先まで広げる単体テストを追加した。3つの短いノートのあとへさらに3つ足しても、ノートオンとノートオフがプラグインに届き、再生は失敗しない。
