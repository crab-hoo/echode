# 0380. MPE だけを受ける CLAP ポートへ下位ゾーンを設定し、ノートをメンバーチャンネルで送る

- 日付: 2026-11-16
- 状態: 一部置換（表情を送らない判断は [ADR 0381](0381-mpe-note-expression.md) で置換。割当と共有は現行）
- 領域: プラグイン・隔離
- 対象: F2・FCA-07・P2-03 の `clap.note-ports`
- 一部置換: [ADR 0379](0379-midi2-notes-for-clap-ports.md) の MPE を対応と答えない判断

## 問題と再現

開始時の HEAD は `5448e32`。
CLAP・MIDI 1.0・MIDI 2.0 を受けず MPE だけを宣言するノート入力にも native のノートを送るため、その音源は鳴らない。
実ヘルパーの検査用音源 `onset-mpe` は、下位ゾーンの設定の前・マネージャーチャンネル・他の形式でノートを受けると出力を 1.0 にする。
変更前の製品経路は終了コード 101 と `MPE-only notes differ from native CLAP notes` で失敗した。
証拠は `target/focused-checks/mpe-notes-red/` に残す。

## 根拠

- CLAP 1.2.2 の [note-ports.h](https://github.com/free-audio/clap/blob/1.2.2/include/clap/ext/note-ports.h) は、MPE を「`clap_event_midi` を使い、ポリフォニックな表情を持つ」形式（ビット 2）とする。
- ゾーンの設定（MCM）は RPN 6 をマネージャーチャンネルで送り、値をメンバーチャンネルの数とする。
  下位ゾーンのマネージャーは MIDI チャンネル 1 である。
  バイト列と順序は JUCE の [`MPEMessages::setLowerZone`](https://github.com/juce-framework/JUCE/blob/master/modules/juce_audio_basics/mpe/juce_MPEMessages.cpp) と同じ `B0 64 06`・`B0 65 00`・`B0 06 0F` にした。
- MPE の仕様書（M1-100-UM v1.1）は会員向けで、本文を読めていない。上の形式は JUCE の送受信の実装と単体テストで確かめた。

## 比べた案と決定

- **MPE を対応と答えるだけ**: 不採用。ゾーンの設定とメンバーチャンネルの割当がないと、MPE の受け手は曲のノートを正しく扱えない。
- **MPE と MIDI 1.0 の両方を受けるポートも MPE に切り替える**: 不採用。
  ゾーンの設定は受け手の動作を変え（メンバーのピッチベンド幅の既定 48 半音など）、既に鳴る MIDI 1.0 の経路を変える。
- **ノート ID から決まった式でチャンネルを選ぶ（状態なし）**: 不採用。
  ノート番号は編集の順に振られるので、和音の音が 15 で割った余りで重なる。
  番号が散らばると、4 音の和音の約 35% で 2 音以上が同じチャンネルに重なる。メンバーごとに単音で鳴らす MPE 音源では音が切れる。
- **16 音目からは発音しない、または古い音を止める**: 不採用。曲の音が欠ける（堅牢性の損失）。MPE は共有を許している。
- **固定量の割当表**: 採用（`mpe.rs::MpeZone`）。
  空いたメンバーは最初のノートが ID で所有し、15 音までは同じ音高でも別のチャンネルに置く。
  全員がふさがった後のノートは、最も空いたチャンネルを共有し、チャンネルと音高ごとの数で数える。
  ノートオフは、所有なら ID、共有なら音高で元のチャンネルを見つける。このゾーンが始めていないノートオフは送らない。
  探索は前回の割当の次から始め、離したばかりのチャンネルの余韻を最後まで使わない。
  表はポートごとに約 8 KB で、主スレッドが有効化前に作る。音声側は消去と数の増減だけをする。

優先順は native CLAP、MIDI 1.0、MIDI 2.0、MPE の順とし、MPE は他の 3 形式を受けないポートだけに使う。
ホストの `supported_dialects` は 4 形式を答える。
公開 Rust 関数 `write_input` はゾーンの列も受ける。保存形式・共有領域・IPC・C ABI・依存は変えない。
比較の時間計測はしていない。和音の重なりの率は、番号を散らした時の 4 音の計算（1 − 14/15 × 13/15 × 12/15）である。

## 送る内容

- ゾーンの設定は、処理の開始ごととリセットごとに、ネイティブのチョークと CC120 の後、曲のノートの前に時刻 0 で送る。
  リセットと開始では割当表も消す。
  1 回の処理で同じ処理器を何段も通す時も、イベントの変換と割当は 1 ブロックに 1 回だけ行い、各段へ同じ列を渡す。
- ノートオン・オフはメンバーチャンネル（MIDI 2〜16）の MIDI 1.0 で送り、ベロシティは MIDI 1.0 の経路と同じ 7 bit にする。チョークはベロシティ 0 のノートオフにする。
- 宛先のチャンネルは使わない。音高とノート ID がない宛先、ワイルドカードのポートは送らない。
- 音程・明るさ・圧力の表情は送らない。チャンネル全体に効く値で、共有中の他のノートへ漏れる。
  ノートごとの初期値の送信は 1 イベント 1 メッセージの容量の規則を超える。曲からの表情の生成も未接続である。

## 回帰と基盤

- `mpe_tests.rs`: 設定のバイト列と位置、15 音の別チャンネル・16 音目からの共有・消去、乱数の重なりとリセットの性質の検査。
  性質の検査は、受け手の数を負にしない、所有のノートオフが元のチャンネルへ行く、15 音までは共有しない、全部離すと無音になることを確かめる。
- `events_tests.rs`: 同じ音高の別 ID、宛先のチャンネルの無視、表情・未保持・宛先不足の不送信、MIDI 1.0 の経路の維持、確保禁止。
- `note_ports_tests.rs`: 全 16 通りの形式の組合せ、MPE のポートだけのゾーン、リセットと開始ごとの設定。
- `isolation/midi_notes.rs`: 実ヘルパーで、処理の開始とリセットごとの設定の位置、割当の続き、無効化中の形式の変更・入替え・MIDI 1.0 への戻しを照合する。
- `hosted_playback/midi_notes.rs`: エンジンの曲を通し、48・96 kHz、7・64・512 フレームで native とステレオ PCM が一致する。

必須契約 `plugin-mpe-notes`・`plugin-mpe-lifecycle` と、形式の選択・リセット時の消去を止める反例を登録した。
両方の反例が、回帰固有のアサーションで失敗することを確かめた（`target/focused-checks/mpe-notes-control/`・`mpe-lifecycle-control/`）。
`mpe*.rs` を音声の領域へ加え、単独の変更でも RTSan の対象にする。全反例・RTSan 自体は全体検査へ任せる。
外部入力・パーサーは足さず、既存の共有イベント境界を使うので fuzz の入口は変えない。
設計・進捗・制約・監査の現在欄・コードの所在・診断手順を更新する。
第三者の MPE 音源のゾーン設定の解釈・聴感は自動の検査用音源で判定できず、UC-93 とする。
動的な音声ポートの寸法変更、後段ノートの PDC 補正、表情の生成と MPE での送信は残り、F2 全体は完了にしない。
