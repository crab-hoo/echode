# ADR 0339: プラグインの遅延を合流点の遅延線で揃える（PDC）

日付: 2026-11-13
状態: 採用。聴感と第三者プラグインは UC-74、遅延表示は UC-51
関連: [ADR 0246](0246-plugin-latency-reporting.md)、[ADR 0277](0277-reaper-style-folder-bus.md)、[ADR 0338](0338-folder-bus.md)、
[ADR 0120](0120-device-bypass.md)、[ADR 0003](0003-audio-thread-does-not-wait.md)、
[FCA-07](../reviews/2026-11-03-full-code-audit.md#fca-07-プラグインの遅延と主要なホスト拡張)、[P2-03](../phase2.md#p2-03-ルーティングフォルダバスpdc)

## 問題

開始時の HEAD は `97674c9`。フォルダバス（ADR 0338）を接続し、P2-03 の残りは PDC・センド・サイドチェイン・ドラムの MIDI 配布になった。
遅延の取得と表示は ADR 0246 で済んでいたが、音の時刻は補正していなかった。
先読みのリミッターや線形位相 EQ を 1 トラックに挿すと、そのトラックだけが報告値の分だけ遅れて鳴る。
フォルダバスでは、遅延の違う子が親の入力で合流するので、兄弟の間のずれが親の FX を通って残る。
センドとサイドチェインも合流点を足すので、先に合流の規則を決める。

`hosted_playback/compensation.rs` の 5 件と CLI の書出しの 1 件は、変更前のエンジンで全て失敗した。

## 比べた案

### 揃え方

1. **合流点の遅延線（採用）**: 各経路の到着の遅れを制御側で計算し、合流点で早い経路を遅らせる。
   カーソルは 1 つのまま、マスターは最も遅い経路の分だけ時間軸より遅れる。書出しはその分を先頭から捨てる。
2. **先読み**: 遅い経路ほど早くノートと素材を渡し、マスターを時間軸に合わせる。
   トラックごとにカーソルの位置がずれ、ループの折返し・位置移動・追いかけ（chase）の規則がトラックごとに分かれる。
   ライブの入力には使えない。ADR 0276 の「同じ規則を層ごとに別の論理で実装しない」に反する。

### 合流点

トラックの配置音声と最初の音源は、子の和と合わせて次のデバイスへ入る（ADR 0095、ADR 0338）。
そこで、トラックごとに「自分の素材・最初の音源・子が出会う時刻」を置き、そこへ揃える。

- 最初の音源の出力は、出会う時刻 − 音源の遅延だけ遅らせる（ヘルパーのグラフの中、注入の前）。
- 配置音声は、出会う時刻だけ遅らせる（`Track::prepare_source`）。
- 子は、親の出会う時刻 − 子の到着だけ、フェーダーの前で遅らせる（`Track::mix_into`）。最上位はマスターの遅れに揃える。
- フェーダーの前に置くので、フェーダー・ミュートとソロのゲート・メーターは聞こえる音に掛かる。

### バイパスした装置

1. **遅延を数え、トラックの出力で乾いた音を遅らせる（採用）**: バイパスの切替で他のトラックの位置が動かない。
   線は増やさず、出力の遅延にバイパスした装置の遅延を足す。後ろの装置は、その分だけ早い乾いた音を聞く。
2. **遅延を数えない**: 切り替えるたびに全トラックの補正が変わり、全体の時刻が跳ぶ。
3. **バイパスした段の中で遅らせる**: 後ろの装置まで正確だが、段ごとに線と引継ぎが要る。

オフラインの装置は実行グラフから外れて遅延を報告しないので、0 として扱う。

### 計画の交換での履歴

再生中の編集ごとに計画が替わる。遅延線の中身を捨てると、編集のたびに全トラックが遅延の長さだけ途切れる。

1. **容量の違う線へ写す**: 256 本・容量 4,096 で 1.7 ms、65,536 で 30.3 ms をコールバックで使い、取りこぼす。
2. **捨てる**: 途切れる。
3. **前の環を保ち、そこから古い分を読む（採用）**: 同じ容量なら環を交換し、違えば前の環を `older` に移す。どちらも O(1)。
   新しい環が遅延の分を書き終えるまで、それより前の時刻は `older` から読む。

### 1 サンプルずつか、塊か

最初の実装は 1 サンプルずつ読み書きした。環の容量を「遅延 + 計画のブロック長」の 2 の冪にして、
ブロックを書いてから 2 つまでの切片で読む形に変えた（下の計測）。計画より長いブロックは容量に収まる長さへ分ける。

### 実行中の遅延の変化

ヘルパーは再起動のたびに遅延を報告し直す（ADR 0246）。

1. **ループの変更と同じ経路で計画を作り直す（採用）**: 制御側の `service` が公開時の報告値と比べ、違えば `reprepare(false)` する。
   作り直し中・保留中・素材の読込み中は待ち、公開した計画が新しい値で補正する。
2. **遅延だけの命令**: 新しい線と古い線の返却の経路が別に要る。

## 決定

- `compensation.rs::compensate` が計画の順（親が先）で、往復 2 回、再帰なしに各トラックの遅延を決める。
  出会う時刻 = max(最初の音源の遅延, 子の到着の最大)、到着 = 出会う時刻 + 後ろの装置の遅延の和。
  マスターの遅れは最上位の到着の最大。和の桁あふれは `PlaybackError::Latency` で計画を拒否する。
- 宣言した余韻も同じ計算で、根までの経路で足す。子の余韻は親の装置を通って続くので、書出しの余韻は経路の和の最大になる（ADR 0338 の残り）。
- `delay.rs::Delay` がステレオの遅延線。制御側で確保し（`try_reserve_exact`、失敗は拒否）、コールバックは確保・解放・写しをしない。
  遅延 0 は領域を持たず、遅延のない曲は前と同じ経路を通る。
- `PlaybackControl::publish_graph` と出力の最初の準備が `compensate_plan` で線を用意し、最初の音源の線はヘルパーのグラフの写しへ渡す。
- 計画の採用で `Prepared::carry` と `HostGraph::carry` がトラックのキーで線を引き継ぐ。
- 位置移動など、プラグインを初期化する不連続点で全ての線を空にする（`clear`、線ごとに O(1)）。ループの折返しでは空にしない。
- メトロノームもマスターの遅れだけ遅らせ、曲と合わせる。停止中のライブ処理では残りを流し、無効にした時は空にする。
- `PlaybackStatus::latency_samples` が採用した計画の遅れ、`PlaybackControl::latency_samples` が公開した計画の遅れを返す。
- CLI と GUI の書出し（同じ `echode render`）は、公開した計画の遅れの分を先頭から捨て、同じだけ長く描く。ファイルは曲の先頭から始まる。
- デバイス列の遅延の表示から「未補正」を外し、補正することを説明に書いた（UC-51）。
- 保存形式・アクション・Undo は変えない。

## 回帰と基盤

- `compensation_tests.rs`: 兄弟・フォルダ・音源と子の前後・バイパス・余韻の経路の和と無限・深さ 10,000・桁あふれと順序違反。
- `delay_tests.rs`: ブロック長 1・7・64・512 と計画のブロック長の分割、モノの履歴、空にする、引継ぎの交換と前の環の読み、2 回続く引継ぎ、確保できない遅延。
- `hosted_playback/compensation.rs`（実ヘルパー、テスト用 CLAP の `delay:<frames>`）:
  兄弟が 48・96 kHz、ブロック長 1・7・64・512 でマスターに同時に着く。フォルダの配置音声・音源・子と外のトラックが揃う。
  バイパスしても位置が動かない。再起動で遅延が変わると `service` が追い、位置移動の後に新しい値で揃う。メトロノームが曲と同じだけ遅れる。
  名前の `under_rtsan` で `make rtsan` の対象になる。
- `echode-cli/tests/render.rs::a_compensated_export_starts_every_track_at_the_projects_start`: 遅れた経路と乾いた経路が書出しの先頭から揃う。
- テスト用 CLAP の `delay:<frames>`・`delay:<first>:<then>` は、報告した遅延と同じだけ実際に遅らせる。ADR 0246 の `latency` は音を遅らせない。
- AGENTS.md の `block_size.rs` への追加は、遅延がヘルパーにしかないので、実ヘルパーのブロック長比較（上）と `delay_tests.rs` で代えた。
- 検査の選択と契約は変えない。変更したテストは既存の `check` の対象である。デバッグ手順の遅延の節を書き直した。

## 計測

`make spike-plugin-tracks`（release、機器なし、遅延のない構成）を ADR 0338 の記録と比べた。cpu の p50、取りこぼしは 0。

| 場合 | ADR 0338 | 今回 1 回目 | 今回 2 回目（最終のコード、検査の記録） |
|---|---:|---:|---:|
| プラグイン 256 トラック | 1,057.2 µs | 1,081.4 µs | 1,091.5 µs |
| 和音だけ 256 トラック | 154.8 µs | 157.1 µs | 157.3 µs |
| プラグインとループ 256 トラック | 1,232.5 µs | 1,284.9 µs | 1,285.5 µs |

どれも単回の記録で、2〜4% の差が揺れか増分かは分けていない。遅延 0 の線は領域を持たず、処理は最初の比較で戻る。

遅延線だけを release で測った（一時的なテスト、2,000 ブロックの p50 / p99、ステレオ 256 本）。

| 遅延 | ブロック長 | 1 サンプルずつ（最初の実装） | 塊（採用） |
|---:|---:|---:|---:|
| 2,048 | 512 | 157.4 µs | 110.1 / 273.9 µs |
| 2,048 | 64 | 23.2 µs | 11.5 / 39.7 µs |
| 48,000 | 512 | 569.3 µs | 537.7 / 903.2 µs |

前の環を読む形を 1 サンプルずつ書いた版は、2,048・512 で 825.6 µs だった。
引継ぎは 256 本で、同じ容量 3.3 µs、容量の変化 7.8 µs（写す案は 1.7 ms と 30.3 ms）。
容量が変わった直後の遅延の長さの間は `older` を 1 サンプルずつ読み、2,048 の時に p50 313.6 µs、最大 860.4 µs だった。
48,000 の遅延はキャッシュに収まらず、メモリの読み書きで決まる。

## 残る範囲

- 再生ヘッドの表示はマスターの遅れを引かず、その分だけ音より先に進む。`PlaybackStatus::latency_samples` を表示へつなぐのは別の作業とする。
- マスターの遅れは出力の遅延に加わる。停止中にプラグインの窓の鍵盤で弾く音も、そのトラックの出力の遅延だけ遅れる。録音のモニター用の低遅延の切替は未実装（設計書 7.3）。
- 遅延が同じ容量の中で変わると、読む位置が跳び、変化分だけ繰り返すか飛ばす。容量が変わると、前の環が持たない分は無音になる。クロスフェードはしない。
- 引継ぎが 2 回続き、前の線がまだ自分の `older` を読んでいた時は、その分を捨てる。
- オフラインの装置の遅延は 0 として扱い、オフラインの切替で他のトラックの補正が変わる。
- 書出しの途中で遅延が変わると、先頭で捨てた量は変わらず、それ以降の位置がずれる。
- 遅延を変え続けるプラグインは、そのたびに計画を作り直させる。回数の上限は置かない。
- センド・サイドチェイン・クリップ FX の合流は、それぞれの機能と同時に、この規則で揃える。
- 第三者プラグインの報告値の正しさと聴感は UC-74、表示は UC-51 でユーザーが確かめる。
