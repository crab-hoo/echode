# ADR 0298: スキーマとパッケージの拒否を原因の型で返す

- 日付: 2026-11-10
- 状態: 採用
- 対象: [未完了項目の統合](../reviews/2026-11-08-open-items-register.md) の M1 のうち、スキーマ移行と製品パッケージの検証。
- 関連: [ADR 0296](0296-typed-storage-errors.md)、[ADR 0297](0297-typed-autosave-and-git-errors.md)。

## 問題と再現

開始時の HEAD は `f305d62`。
I/O と Git の原因は保持していたが、`document.rs` のスキーマ移行は `Result<_, String>`、
JSON とモデルの検証は `PackageError::Message` に変えていた。
呼出し元は、不正な JSON、非対応の版、移行途中の形の不正、モデルの拒否を文でしか分けられなかった。

公開の `read_package` に壊れた JSON を渡す回帰は、変更前に
`package validation lost its JSON cause` で失敗した。
同じ入口でトラック ID の列を重複させる回帰は、`package validation lost its model cause` で失敗した。
どちらも期待終了コード 101 と固有のアサーションを照合した。
記録は `target/focused-checks/package-errors-red/` と `package-model-red/` にある。

## 比べた案

| 案 | 判断 |
|---|---|
| 文のまま種類のフラグだけを足す | 採らない。原因が失われ、種類と文が別の正本になる |
| `PackageError` の直下に全検証の変種を足す | 採らない。I/O・Git・音声と、ファイルの構造上の拒否が同じ長い列へ混ざる |
| `Validation(PackageValidationError)` へまとめ、元の JSON・モデルの原因を持つ | 採る。公開境界の一つの変種から、検証の種類と原因を読める |
| 大きい `document.rs` に移行済みと未移行を混ぜ、検査の除外を作る | 採らない。再導入を拒否する範囲が曖昧になる |
| 共通の読込みを `document_parse.rs` へ分ける | 採る。作業ファイルと Git の版が同じ移行・検証を通り、ファイル単位で再導入を拒否できる |

速度の改善が目的ではないので、時間の計測を判断の根拠にしない。
根拠は上の製品入口の反例と、種類・原因・元の文面・原本の保持を照合する回帰である。

## 決定

- `PackageKind` は project・track・content を表す。
  `PackageValidationError` は JSON、版の欠落・型・非対応、移行の段階と形、テンポ、ID、
  デバイスの整合、未対応のノート表現、モデルの拒否を分ける。
- JSON は元の `serde_json::Error`、モデルは元の `ModelError` を保持し、`Error::source` へつなぐ。
  非対応の版は `u64` で保持し、`u32::MAX` を超える入力を丸めない。
  移行の拒否は `MigrationError` と、その処理に入った版を持つ。
- 旧版のデバイスへ既定値を補う共通処理を一つにする。
  既存値を上書きしない規則と、plugin・bypassed・offline・pinned の補完順は変えない。
  schema 2 の音声参照を消す段階と schema 3 のハッシュ参照を保つ規則も維持する。
- 現行版を確定するのは共通の `migrate` だけにする。
  その後の 3 種のファイルで同じ版を再判定していた到達不能な拒否は除く。
  モデルの不変条件は従来どおり `ProjectMetadata::try_assemble` と既存の述語で検証する。
- 保存形式は schema 6 のまま。表示文面、拒否の順番、復旧の同意、ジャーナルと同期の順番は変えない。

## 回帰と基盤

- `tests/package_errors.rs` は、公開の読込みで JSON・モデルの原因、3 種のファイルの版と形、
  旧版の不正なデバイス、テンポと ID の拒否、全対象ファイルの非書換えを照合する。
- `tests/autosave_errors.rs` は実 Git の不正な版をワーカー経由で読み、JSON の原因と非対応版の種類を照合する。
  読込み要求の返信は単独所有で、保存の合流の返信とは異なり `Shared` を必須にしない。
- `document_parse_tests.rs` は内部の組立て境界の件数・順序と、パスになる前の ID 正規化を検査する。
  既存のデバイス・ノート・項目表・パッケージの回帰で、旧版と正準バイトの互換性も維持する。
- `check_typed_errors.py` に読込みと検証のエラーの 2 ファイルを登録する。
  全移行済みファイルで文字列の結果・原因の文字列化・未分類のメッセージの再導入を拒否する Python 回帰を維持する。
- 構成の正本とコードの所在、保存のデバッグ手順と索引、監査の状態を更新する。
  新しい検査入口・依存・外部入力はない。既存の検査選択とパッケージ fuzz が同じ境界を通すため、
  `Makefile` と `scripts/verification.json` の変更は不要である。

## 検査環境の容量

最終検査の最初の実行は、空き 1.7 GiB が必要な 3 GiB に足りず、事前確認で止まった。
ADR 0276 と既存の空き容量の手順に従い、今回選ばれない ASan・TSan・Miri の Rust キャッシュだけを整理した。
対象は `target/bridge/address/rust`・`thread/rust`・`miri/miri`。
検査ロックを取得し、コンパイラーの停止を確認してから実行し、検査ログ・ユーザーデータ・アプリを残した。
空きは 5.74 GiB になった。全体の検査での再生成費用は、既存の同環境の計測で ASan 432 秒・TSan 328 秒・Miri 75 秒を目安にする。
今回の作業の段階ではこの 3 検査を選ばず、その再生成は発生しない。

## 残る範囲

M1 の完了ではない。次は文書のトランザクション・ジャーナル・設定、その後に間引き・非既定の履歴スパイクを扱う。
`PackageError::Message` は未移行の経路だけに残す。
ユーザーの操作・聴感は変わらず、新しい実機確認待ちは作らない。
