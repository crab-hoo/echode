# 0379. MIDI 2.0 だけを受ける CLAP ポートへ曲のノートを UMP で送る

- 日付: 2026-11-15
- 状態: 一部置換（[0380](0380-mpe-member-channels-for-clap-ports.md)）
- 領域: プラグイン・隔離
- 対象: F2・FCA-07・P2-03 の `clap.note-ports`
- 一部置換: [ADR 0375](0375-midi-1-notes-for-midi-only-clap-ports.md) の MIDI 2.0 を未対応とする判断

## 問題と再現

開始時の HEAD は `21e5cb8`。
MIDI 2.0 だけを宣言するノート入力にも native のノートを送るため、その音源は鳴らない。
実ヘルパーの検査用音源 `onset-midi2` は、native や MIDI 1.0 のノートを受けると出力を 1.0 にする。
変更前の製品経路は終了コード 101 と `MIDI2-only notes differ from native CLAP notes` で失敗した。
証拠は `target/focused-checks/midi2-notes-red/` に残す。

## 比べた案と決定

- **MIDI 2.0 の対応を答えるだけ**: 不採用。通常ノートだけでなく、停止・位置移動の全発音停止も UMP が要る。
- **MIDI 2.0 を宣言する既存の全ポートへ切り替える**: 不採用。
  native のノート ID が失われ、MIDI 1.0 を含めて既に鳴るプラグインの入力形式も変わる。
- **MPE・全グループ・全表情まで同時に足す**: 見送る。
  MPE のチャンネル割当・設定や、ピッチの範囲・音色の表情の写像は別の規則が必要で、曲からの表情生成も未接続である。
- **既存経路を保ち、MIDI 2.0 しか送れる形式がないポートだけヘルパーで変換する**: 採用。
  優先順は native CLAP、MIDI 1.0、MIDI 2.0 とし、`preferred_dialect` では変えない。
  追加の IPC・モデル・発音状態・確保上限を作らず、既存の `NoteInputs` と処理器の受渡しを使う。

ホストは CLAP・MIDI 1.0・MIDI 2.0 を対応と答え、MPE は答えない。
ポートごとの変換形式は真偽値から `NoteDialect` に変え、毎回の有効化直前に記述から作る。
公開 Rust 関数 `write_input` もこの列を受ける。保存形式・共有領域・C ABI・依存は変えない。
比較計測はしていない。状態と同期経路を増やさないことを堅牢性・保守性の理由にした。

## UMP の範囲

根拠は CLAP 1.2.2 の [events.h](https://github.com/free-audio/clap/blob/1.2.2/include/clap/events.h) と
[M2-104-UM v1.1.2](https://amei-music.github.io/midi2.0-docs/amei-pdf/M2-104-UM_v1-1-2_UMP_and_MIDI_2-0_Protocol_Specification.pdf) §7.4.1〜3・6 である。

- グループは 0。チャンネルと音高は元の宛先を保ち、属性なしの 64 bit MIDI 2.0 channel voice UMP を 1 つ送る。残る 2 word は 0。
- ノートオン・オフのベロシティは `round(clamp(v, 0, 1) × 65535)`。NaN は 0。モデルの全 65,536 段が往復で同じになる。
  MIDI 2.0 のノートオンの 0 は発音であり、MIDI 1.0 のように 1 へ寄せない。
- 圧力は 32 bit のポリプレッシャー。チョークはベロシティ 0 のノートオフへ近似する。
- ノート ID、ワイルドカードのチャンネル・音高、音程・明るさの表情は送らない。同じ音高の重なりを別の ID で扱うこともできない。
- パラメーター・トランスポートと、ワイルドカード・宣言外のポートの既存経路は変えない。
- 全発音停止は、MIDI 2.0 を宣言する各ポートのグループ 0・全 16 チャンネルへ CC120 を送る。
  native のチョーク・MIDI 1.0 の停止と同じく時刻 0 で、曲のイベントより先に借用でつなぐ。
  一覧の作成と破棄は主スレッドだけで、音声側で確保・拡張・ロックしない。

## 回帰と基盤

- `events_tests.rs`: 3 形式の混在、時刻と順序、0 ベロシティ、全 16 bit の往復、圧力、範囲外・非有限値、未変換の宛先、確保禁止。
- `note_ports_tests.rs`: 全 16 通りの形式の組合せ、両形式の終了処理、u16 の末尾とその次のポート。
- `isolation/midi_notes.rs`: 実ヘルパーの全 UMP word と時刻、全チャンネルの停止と先頭ノートの順序。
  無効化中に MIDI 1.0 → MIDI 2.0 → ポート入替え → native のみ → MIDI 2.0 と変え、8・256 フレームで読み直しを照合する。
- `hosted_playback/midi_notes.rs`: エンジンの曲を通し、48・96 kHz、7・64・512 フレームで native とステレオ PCM が一致する。

必須契約 `plugin-midi2-notes`・`plugin-midi2-lifecycle` と、形式選択・終了処理を止める反例を登録する。
通常テストと RTSan 選択へ入り、実行コマンドは既存の Makefile の入口を使う。
選択の回帰で、イベント変換とノートポートの単独変更が音声領域に入っていないことが分かった。
これらと MIDI 形式の隔離回帰・検査用プラグインを `scripts/verification.json` の音声領域へ加え、単独変更でも RTSan の対象にする。
全反例・RTSan 自体は全体検査へ任せる。外部入力・パーサーは足さず、既存の共有イベント境界を使うので fuzz の入口は変えない。
設計・進捗・制約・監査の現在欄・コードの所在・診断手順を更新する。
第三者音源のグループ解釈・音色・聴感は自動の検査用音源で判定できず、UC-92 とする。
MPE、動的な音声ポートの寸法変更、後段ノートの PDC 補正などは残り、F2 全体は完了にしない。
