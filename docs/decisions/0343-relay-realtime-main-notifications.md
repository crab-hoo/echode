# 0343. 処理スレッドのメイン通知を制御側から起こす

- 日付: 2026-11-14
- 状態: 採用
- 対象: RTA-01

## 背景

[リアルタイム監査](../reviews/2026-11-14-realtime-adversarial-audit.md)の RTA-01 は、
CLAP の `process` 内の `request_callback` が CoreFoundation のロックを取る。
同じ `Bridge::signal` は処理側の起動要求と、どのスレッドからも来る GUI の通知でも使う。
[ADR 0041](0041-helper-threads.md) の直接の source 起床を、処理スレッドについて置き換える。

着手時の `58f5038` の通知処理を `MainSignal` に移し、直接起こす動作を保った状態で単体回帰を実行した。
終了コード 101 と `realtime notification must be relayed` のアサーションを照合した。
記録は `target/focused-checks/rta01-red/` に置く。
監査時の RTSan の失敗の証拠は元の監査に保持する。今回、計装した別構成は手元では実行しない。

## 比べた案

- **各 callback だけに処理スレッドの分岐を足す**: 不採用。
  起動要求や GUI の通知も同じ CoreFoundation の呼出しを通るため、共通入口で守る。
- **既存の制御スレッドが中継する**: 採用。
  `ON_AUDIO` と既存の `control_alarm` を使い、スレッド・ソケット・メイン要求の列を増やさない。
  `MainSignal` に保留ビットと CoreFoundation の呼出しを閉じ込め、単体でも中継の境界を検証できる。
- **通知専用のスレッドや、新しいソケット・内部通知の統合待ちを置く**: 今回は不採用。
  前者はヘルパーごとの資源を増やす。後者は通常の 20 ms ポーリングも置き換えられるが、
  待ちと寿命の境界を広げる。今回のロックの除去には必要ない。

性能の比較計測はしていない。今回の基準は、処理スレッドからロックを取る関数を呼ばない構造と、
次の音声ブロックがなくても通知を届ける回帰であり、機器の期限や GUI 更新の速さを数値で保証しない。

## 決定

`Bridge::signal` は処理スレッドから呼ばれた時、保留ビットを立て、制御の警報を進めてすぐ戻る。
`request_callback` の世代番号と、起動要求・GUI の各状態は今までどおり正本のままである。
保留ビットは「source を起こす必要がある」だけを持ち、個々の要求を複製しない。

制御側は通常ループ・再起動の内部待ち・メイン応答の待ちで保留を取り出す。
ビットを消費してから source を起こすため、その間に来た要求は次の保留として残る。
`CFRunLoopSourceSignal` と `CFRunLoopWakeUp` は処理スレッドでは呼ばない。
それ以外のスレッドからは従来どおり直接起こし、制御側自身が中継待ちになることを避ける。
source と run loop は従来どおり、ワーカーの join とプラグイン破棄まで保持する。

通常の制御ソケットの 20 ms ポーリングは残る（RTA-05）。
制御要求の処理中やプラグイン自身のメイン処理が戻らない間も含め、callback の完了期限は保証しない。
処理スレッドはその完了を待たない。

## 回帰と残る確認

単体回帰は通知の集約・消費後の再通知を検査する。
実 source の回帰は、処理側の要求だけでは source が動かず、制御側の中継で実行されること、
実行中の次の要求を失わないこと、非処理側の直接通知を保つことを確認する。

`audit_rta01_*` の feature 条件と無視を外し、複数のブロック長で音声を比較する。
各ブロック後は次を送らず、メイン callback と制御応答が届くことを確かめる。
必須契約 `plugin-main-signal` と `plugin-main-callback` に登録した。
後者の callback 世代の更新を外す反例も作業中に実行し、終了コード 101 と通知未達のアサーションを照合した。
記録は `target/focused-checks/rta01-callback-negative/` に置く。
両契約の反例と全体の段階の RTSan は GitHub の `full` が実行する。

実機・第三者 CLAP の GUI 更新と音切れの聴感は [UC-77](../user-checks.md)。
通常の自動回帰はそれらの代用ではなく、検査結果と見送り理由は `target/verification/report.md` に残す。
