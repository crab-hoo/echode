# ADR 0136: 出力とヘルパーの準備を文書ワーカーの外で行う

- 日付: 2026-10-21
- 状態: 採用。P2-02 の応答性の残る条件のうち、停止中の最初の出力準備を接続。実機の操作感はユーザー確認待ち
- 範囲: 停止中の最初のデバイス要求と最初の再生で出力を開く経路、準備中の要求の順序、準備後の反映、機器なしの検査用出力

## 背景

[ADR 0131](0131-device-view-and-responsive-parameters.md) でデバイス要求の往復はワーカー外のレーンへ移したが、
停止中の最初のデバイス表示は文書ワーカー上で `Session.open_engine` を呼び、出力を開き終えるまで後続の編集を待たせていた。
最初の再生も同じ `reconcile` で出力を開くため、同じ間は編集・Undo・停止の要求も待った。

待つのは HAL の登録ではなく、`prepare_playback_mode` が行うヘルパーの起動（`HostGraph::open`）と素材の準備である。
HAL の機器確認・Workgroup の取得・IOProc の登録は短い。
`OutputStream` は HAL の通知ブロックを持つため別スレッドへ移せないが、準備の結果（`PlaybackControl`・`PlaybackAudio`）と
Workgroup・素材の読込関数は `Send` である。

修正前の製品経路を機器なしで再現する手段がなかった。HAL を開く Session の検査はすべて `#[ignore]` で、`make spike-audio` だけが通っていた。

## 決定

### 準備だけを別スレッドで行う

- 出力を開く手順を 3 段に分ける（`crates/echode-audio-io/src/opening.rs`）。
  1. 文書ワーカーで機器を確認し、Workgroup の変更通知を登録してから Workgroup を取得する（`Claim`）。
  2. 準備スレッド（`echode-output-open`）でヘルパーを起動し、素材と再生計画を準備する（`Prepared`）。
  3. 文書ワーカーが `service` で結果を受け取り、コールバックを組み立てて HAL へ登録する。
- 準備はその時点の文書・位置・ループ・メトロノーム・フェーダー試聴・再生要求（`Basis`）から作る。
  準備中の編集・位置移動・ループ・メトロノーム・試聴・再生・停止は、出力がない時と同じく Session の状態だけを変える。
- 導入時は、出力が最初から開いていたものとして差分を送る。文書の差分は通常の `update` と同じ扱い（状態だけの差分は同じヘルパーへ読込み）で、
  その後に位置・ループ・メトロノーム・試聴・再生／停止を送る。
  すべての命令を送ってから IOProc を登録するので、位置・ループ・再生／停止は最初のブロックより前に届き、古い位置から鳴り始めない。
  文書の差分は、開いている出力への編集と同じく、準備できた計画から交換する（[ADR 0102](0102-exclusive-audio-graph.md)）。
- 再生は `basis` の再生要求と取消世代が今も有効なら命令を重ねず、停止・別の再生があれば一時停止または新しい世代で再開する。
  準備中の停止は投入時の取消世代でも止まる（[ADR 0097](0097-cancellable-retained-transport.md)）。
- 準備は途中で中断できない（ヘルパー起動の最中に止める手段がない）。
  出力機器の変更・Workgroup の変更で不要になった準備は退避し、スレッドが終わった時点で結果ごと捨てる。
  文書を閉じる時は、同期で開いていた時と同じく準備の終わりを待つ。
- 失敗は `AudioState.error` に入れ、準備のやり直しは次の要求まで行わない。`service` が失敗を繰り返し準備しない。

### 待つのはデバイス要求だけ

- `Session::device_control` は出力を開き始めると `DeviceAccess::Opening` を返す。準備中の 2 回目以降の要求は準備をやり直さない。
- FFI のワーカーは、準備を待つデバイス要求とその後のデバイス要求を投入順に保持し、準備が終わった周回でレーンへ渡す。
  閉じる要求も、先に待っている要求があればその後ろに並ぶ。表示と閉鎖の順序を入れ替えない。
- 準備後にデバイスを再確認する。削除・オフライン化・ヘルパーの不在・準備の失敗は、その要求の失敗として返す。
  パラメーター変更の「編集中」の印は、要求をレーンへ渡す時に付ける。
- 編集・Undo / Redo・状態取得・停止・音声コマンドは待たない。準備中は 1 ms ごとに結果を確かめる。
- 文書を閉じると、待っている要求を `document thread stopped` で終える。
- `AudioState.opening` は準備中を示す。`playing` が真でも `running` は導入まで偽である。Swift の表示は従来どおり `playing` に従う。

### 機器なしの検査用出力

- Session の機器一覧・通知・登録は `Outputs` の実装を通す。製品は `HalOutputs`、検査は `HeadlessOutput`（`headless-output` 機能と単体検査だけ）である。
- `HeadlessOutput` は固定の機器を 1 台返し、通知と IOProc を持たない。準備は製品と同じ `Prepared::new` を使い、
  `hold` / `release` で準備を保留し、`fail_next` で失敗させる。コールバックは検査が `OutputStream::pump` で回す。
- 機器の固定値（48 kHz・128 フレーム・2 チャンネル）は検査用であり、製品の上限ではない。

## 残る範囲

- 出力を開いた後の編集でヘルパーが新たに必要になった時（候補からの追加・オフライン解除・コピー）は、
  `update` → `replace` → `HostGraph::reconcile` がワーカー上でヘルパーを起動して待つ。
  素材の読込関数も `reprepare` から同期で呼ぶ。グラフの交換を準備スレッドへ移す設計は別に決める。
  → 開いた出力の置換ヘルパーと共有領域の準備は [ADR 0142](0142-background-plugin-graph-preparation.md) でワーカー外へ移した。
  素材・保存済み状態の読込みと初回導入時の差分による追加は同期のままである。
- 準備中にデバイス列が「準備中」と表示する画面の区別は持たない。一覧の要求が保留のままになる。
  後続の [ADR 0141](0141-device-output-preparation-status.md) で、初回の出力準備と一覧の応答待ちの表示を接続した。
- HAL を開く経路（実機の登録・機器の変更中の準備・2 つの IOProc の加算）と操作感は、`make spike-audio` と実機でのユーザー確認とする。

## 検査と診断

- 必須契約 `output-opening` は、機器なしの出力で準備を保留し、最初のデバイス要求がすぐ戻ること、
  準備中の文書の追加・位置移動・ループ・再生が導入時に反映され、追加したトラックが移動先から鳴ること、準備が 1 回だけであることを
  製品のコールバックで確かめる（RTSan の対象）。負の対照は導入時の文書の差分を送らない。
- 必須契約 `output-opening-worker` は、C ABI から最初のデバイス要求を投入して準備を保留し、
  後続の編集・Undo・状態取得・停止が終わること、デバイス要求が準備後に投入順に終わること、2 回目の要求が準備し直さないことを確かめる。
  負の対照はワーカーが準備の終わりを待つ。
- 単体回帰は、準備中の停止で止まったまま導入されること、失敗が 1 回だけ報告されて繰り返し準備しないこと、
  準備中に文書を閉じると待っている要求が拒否されることを確かめる。
- 実機の HAL を開く `#[ignore]` の検査は、再生の後に導入を待ってから計測する。
- 初回だけ止まるという報告では、`AudioState.opening` が真の間に編集が終わるかを先に分ける。
  終わらないならワーカーの手番、終わるが一覧が出ないならヘルパーの起動時間か一覧の応答である。
