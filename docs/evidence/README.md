# 監査・設計判断の証拠の保全

## 新しい記録

監査・ADR・スパイクの結論を支える証拠は、このディレクトリの Markdown / JSON、
または引用元の本文に要約して Git の追跡対象にする。
通常回帰に移したものは、テストのパス・名前と実行手順も記す。
巨大なログ・画像・バイナリ、ユーザープロジェクト、素材の絶対パス、秘密情報をそのまま追加しない。

要約には次を含める。

- 日付、対象コミット、未コミット変更の有無と対象範囲。
- 最小入力・初期状態・操作順、再生成コマンドと必要な環境。
- 終了コード、回帰固有の期待値と実際の出力の抜粋。
- 判定の範囲、未実行の理由、未確定の原因。

`target/` は再生成可能な作業領域で、長期保管先ではない。
コマンドの出力先としてコード表記で案内することは許すが、新しい証拠への Markdown リンクは作らない。
検査中のローカルログの参照だけで、監査の恒久的な根拠を置き換えない。
現在の正式な合否は引き続き `target/verification/report.md` を確認する。

## 過去のローカル記録

2026-10-27 の ADV-03 で、監査・ADR 等が参照するローカル証拠の多くは既に失われていた。
既存の `target/` 参照はすべて「当時のローカル記録」として扱い、現存・再現・現行版の合格を保証しない。
引用元に残る対象版・手順・数値・出力の要約だけが、追跡される当時の証拠である。
消えた画像・完全ログを推測で復元したり、現在の検査ログを同じ場所へ置いて当時の証拠とみなしたりしない。
不足する証拠が必要なら、別の日付・対象版の新しい調査として再生成し、元の判定と区別する。
実機・聴感・実画面の再生成はユーザーの明示依頼なしに行わない。

[既存リンクの例外一覧](legacy-local-links.json) は、対応前に存在した文書とリンク先の組だけを列挙する。
削除済みファイルの存在を要求せず、引用元には当時のローカル記録という注意書きを要求する。
新しい証拠をこの例外へ追加しない。
例外外の `target/` リンクは、ファイルが現存していても `check-verification` で拒否する。
コード表記のパスはリンクではないため検査対象外だが、保管方針は同じである。
