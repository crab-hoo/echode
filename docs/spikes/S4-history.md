# S4: プレーンテキストのプロジェクトと自動コミット

- 日付: 2026-10-08
- 状態: 確定（2026-10-08 に確認）
- 実装: `crates/echode-history`

## 何を確かめたか

1,000 トラック、各 100 ノートのプロジェクトを JSON で保存し、裏で gix がコミットする。gix は MIT OR Apache-2.0 で、Echode の GPL-3.0-or-later と両立する。

トラックは不変で、変更したトラックだけを複製する。保存を頼む側はスナップショットを履歴スレッドへ渡すだけで、JSON 化とコミットはそのスレッドが行う。変わっていないトラックのファイルと blob は書き直さない。

JSON はキーの順を固定し、ノートは 1 行に 1 つ書く。同じ内容からは同じバイト列になる。過去の版は、作業ツリーではなく git のオブジェクトから読み直す。

1,000 という件数は計測用で、製品の上限ではない。

## 測定

release ビルド。

| 項目 | 結果 | 合格の目安 |
|---|---:|---|
| 初回保存を依頼して戻るまで | 0.001 ms 未満 | UI が止まらない（1 フレームは約 16ms） |
| 1 トラック編集後の保存を依頼して戻るまで | 0.002 ms | 同上 |
| 初回の 1,000 ファイルのコミット（裏側） | 323 ms | 依頼側は待たない |
| 1 トラックだけのコミット（裏側） | 1.3 ms | 依頼側は待たない |
| 1 つ前の版を読み直す | 27 ms | 1 秒以内 |

編集の前後でコミットは別物になり、古い版を読むとゲインは編集前の値に戻る。ノートの内容は一致する。

## 再現

```sh
make spike-history
```
