# Echode 開発計画

- 版: ドラフト v0.1（2026-10-07）
- 対象: macOS 27 Golden Gate 以降、Apple Silicon 専用
- 技術設計: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 目指すもの

Echode は macOS 専用の、フリーかつオープンソースの DAW です。打ち込み中心の制作と、ミキシング・マスタリングを主な用途にします。既存の DAW とは次の 3 点で差をつけます。

1. **止まらない。** プラグインは別プロセスで動かすので、プラグインがクラッシュしても本体と他のトラックは鳴り続けます。操作はすべて記録しているので、強制終了しても直前の操作まで復旧できます。
2. **履歴を意識しなくてよい。** プロジェクトはプレーンテキストで保存し、裏で Git が管理しますが、ユーザーに Git は見せません。Time Machine のような画面で過去の状態を試聴して戻せ、別アレンジは「オルタネイト」として並べて管理できます。
3. **Mac に最適化している。** リアルタイムエンジンは Rust で、UI は Swift と Metal で作ります。トラックパッドのジェスチャー、触覚フィードバック、感圧入力、オンデバイス LLM まで、Mac のハードウェアと OS の機能を活かします。

### 1.0 の合格基準

「製品品質」を次の基準で定義します。

| 観点 | 基準 |
|---|---|
| 安定性 | プラグインがクラッシュやハングをしても本体が落ちない（自動テストで常に検証する） |
| データの保全 | 強制終了や電源断のあとでも、最後に確定した操作まで復旧できる |
| 音声処理の性能 | 100 トラック規模のプロジェクトで、エンジン自体の処理時間（プラグインを除く）が 128 サンプル / 48kHz の 1 ブロックの 10% 未満 |
| 描画の性能 | 1,000 トラック・10 万ノートでも、スクロールとズームがディスプレイのリフレッシュレートに追従する |
| 上限 | トラック数、プラグイン数、チャンネル数、ネストの深さに固定の上限がない（上限は CPU とメモリだけ） |
| アクセシビリティ | VoiceOver とキーボードだけで主要な操作が完結する |
| 実用性 | 作者自身が 1 曲を Echode だけで完成させられる |

### 2.1 ライセンス方針の影響

GPL-3.0-or-later にしたので、GPL-3.0 と両立するライセンスのライブラリなら組み込めます。

- **使える**: 寛容なライセンス（MIT、BSD、Apache-2.0、ISC、zlib など）、MPL-2.0、LGPL、GPL-2.0-or-later、GPL-3.0、AGPL-3.0
- **使えない**: GPL-2.0-only（版 2 に限ったもの）、宣伝条項付きの BSD、EPL、CDDL、ソース非公開のライブラリ。MPL-2.0 でも「Incompatible With Secondary Licenses」と表示されたファイルは使えない
- AGPL-3.0 のライブラリを入れると、組み合わせた全体に、ネットワーク越しに使わせる場合のソース公開の条件（AGPL 第 13 条）が加わる
- Apple のシステムフレームワーク（CoreAudio、Metal、Foundation Models など）は、GPL のシステムライブラリの例外に当たるので使える
- プラグインのライセンスは問わない。GPL が条件を付けるのは配布で、利用者が手元でプラグインを読み込むことには条件がない。プラグイン自体も、Echode ではなく CLAP、VST3、AU の API に対して作られている
- バイナリを配布する時は、同じ版のソースを公開し、同梱したライブラリのライセンス表記を付ける

確認済みの主な候補は次のとおりです。

| 用途 | ライブラリ | ライセンス |
|---|---|---|
| CLAP | CLAP SDK、clack（Rust バインディング） | MIT、MIT OR Apache-2.0 |
| VST3 | VST3 SDK 3.8、vst3 crate | MIT、MIT OR Apache-2.0 |
| タイムストレッチ | Rubber Band、Signalsmith Stretch、Bungee | GPL-2.0-or-later、MIT、MPL-2.0 |
| サンプルレート変換 | rubato、r8brain-free-src、soxr、zita-resampler、libsamplerate、macOS の AudioConverter | MIT OR Apache-2.0、MIT、LGPL-2.1-or-later、GPL-3.0-or-later、BSD-2-Clause、システムのフレームワーク |
| テスト用の発振器とサンプラー | wavesynth、dasp、fundsp、rustysynth、oxisynth、FluidSynth、sfizz | MIT OR Apache-2.0、MIT OR Apache-2.0、MIT OR Apache-2.0、MIT、LGPL-2.1、LGPL-2.1-or-later、BSD-2-Clause |
| デコード | Symphonia（macOS の AudioToolbox と併用） | MPL-2.0 |
| Git | gitoxide（gix） | MIT OR Apache-2.0 |
| アプリ間のテンポ同期 | Ableton Link | GPL-2.0-or-later |
| MP3 のエンコード | LAME | LGPL |

Rubber Band、Ableton Link、LAME、soxr、zita-resampler は、MIT / Apache-2.0 だった時には同梱できなかったものです。

使えるライブラリが多いことを活かすため、次の方針で取り込みます（[ADR 0014](decisions/0014-existing-implementations-as-options.md)）。

- サンプルレート変換やタイムストレッチのように、定番の実装があって、どれを使うかで音や負荷が変わる処理は、自作する前に既存の実装を調べて測る
- ほかの選択肢に完全に劣るもの（音質、負荷、遅延、できることのすべてで同等以下のもの）を除き、できるだけ多くをユーザーが選べるようにする。既定はそのうちの 1 つにする
- 自作するのは、既存の実装が要件を満たさない時か、測って上回る点がある時に限る。理由と測定値を ADR に書く。自作のものも、ほかに完全に劣るなら選択肢に出さない
- オーディオスレッドで動かす選択肢は、ほかのコードと同じ規則を守る（ロック、メモリ確保、待機をしない）。守れないものは、書き出しなどのオフライン処理でだけ選べるようにする
- プロジェクトには、選んだ実装を ID と版で記録する。開いた環境にない時は既定に置き換えて、そのことを知らせる
- Git や JSON のように、どれを使っても結果が変わらない土台のライブラリは、選択肢にしない

どれを取り込むかは、その機能に着手する時に測って決めます（サンプルレート変換は ARCHITECTURE §7.5、タイムストレッチは §6、Link は §5、MP3 の書き出しは ARCHITECTURE §11）。

### 2.2 置いた前提

確認していませんが、次の前提で計画しています。変えたいものがあれば指摘してください。

- 複数のプロジェクトを同時に開けるが、音を出すのは前面のプロジェクトだけにする（切り替えは即時）。
- 内部の信号処理は 32bit 浮動小数点で行い、ミックスの加算だけ 64bit で行う。
- 最初から入れる内蔵デバイスは最小限にする（ユーティリティ、EQ、コンプレッサー、リミッター、ゲート、メーター類、テスト用の簡易シンセとサンプラー）。
- 保存するかどうかの確認ダイアログは出さない（常に自動保存しているため）。Cmd+S は「名前付きの保存ポイントを作る」操作になる。
- ミキサー画面（コンソール表示）は要件にないが、ミキシングが主な用途なので Phase 2 で作る。

## 3. アーキテクチャの要約

詳細は [ARCHITECTURE.md](ARCHITECTURE.md) にまとめました。要点は次のとおりです。

- **プロセス構成**: `Echode.app`（Swift の UI と Rust のコア・エンジンが同居）、プラグインを動かすヘルパープロセス群（既定ではメーカーごとに 1 プロセス）、ヘッドレスの `echode` CLI（バウンス、フリーズ、自動化、MCP）の 3 種類です。
- **モデルが唯一の真実**: ドキュメントモデルは Rust 側に置き、変更のたびに不変のスナップショットを作ります。UI、エンジン、履歴、API はスナップショットを読むだけなので、ロックなしで並行に動けます。
- **すべての操作はアクション**: マウス、ショートカット、コマンドパレット、API、LLM、MCP は、すべて同じアクションを呼びます。Undo、マクロ、クラッシュ復旧用の操作ジャーナルもこの仕組みに乗ります。
- **時間は整数で持つ**: 音楽上の時間は 1 拍を 705,600 tick、実時間は 1 秒を 705,600,000 flick で表します。主要なサンプルレートとフレームレートで割り切れるので、サンプルレートの違うファイルを混ぜても丸め誤差が出ません。
- **リアルタイムスレッドは何も待たない**: ロック、メモリ確保、ファイル I/O、GPU の完了待ちを禁止します。プラグインとのやり取りも共有メモリで行い、応答が締め切りに間に合わなければ、そのブロックだけ無音にして先へ進みます。
- **ヘッドレスで全機能が動く**: UI はクライアントの 1 つという位置づけです。バウンスやフリーズは CLI のプロセスがプロジェクトのスナップショットを読んで実行するので、その間も編集を続けられます。

## 4. ロードマップ

期間は、ひとり＋AI エージェントがフルタイムで取り組んだ場合のおおよその目安です。不確実性はかなり大きく、学業と並行するならさらに伸びます。各フェーズは完了条件を満たすまで次へ進みません。

### Phase 0: 土台づくりと技術検証（1〜2 か月）

失敗すると設計を変えなければならない部分を、最初に小さく作って測ります。

| 検証 | 内容 | 合格の目安 |
|---|---|---|
| S1 描画 | AppKit のアプリから Rust の静的ライブラリを呼び、Metal で 1,000 トラック・10 万ノートを描く | スクロールとズームがリフレッシュレートに追従する。測定済み。結果は [spikes/S1-drawing.md](spikes/S1-drawing.md) |
| S2 エンジン | Rust から CoreAudio を直接動かし、ワーカースレッドを Audio Workgroup に参加させて、1,000 ノードのグラフを処理する | 64 サンプル / 48kHz で 10 分間音切れしない。測定済み。オーディオスレッドだけで処理する構成は超過 0。結果は [spikes/S2-engine.md](spikes/S2-engine.md) |
| S3 プラグインの隔離 | 別プロセスで CLAP プラグインを動かし、共有メモリでやり取りする。わざとクラッシュやハングをするテスト用プラグインも作る | 往復の中央値 30µs 以下（暫定）。クラッシュしても音が止まらない。測定済み。結果は [spikes/S3-plugin-isolation.md](spikes/S3-plugin-isolation.md) |
| S4 履歴 | JSON 形式での保存と、gix による自動コミット | 1,000 トラック規模の保存で UI が止まらない。過去の版を 1 秒以内に読み込める（プラグインの読み込みを除く）。測定済み。結果は [spikes/S4-history.md](spikes/S4-history.md) |
| S5 入力 | トラックパッドの縦横独立のピンチ、触覚フィードバック、キーボードで和音を押さえながらの感圧入力 | 確定。実機で操作として成立した。ズーム方式の決め方は [ADR 0007](decisions/0007-s5-confirmed-phase1.md)。結果は [spikes/S5-input.md](spikes/S5-input.md) |

並行して、次のものを整えます。

- リポジトリの骨組み（Cargo workspace、定義ファイルから生成する Xcode プロジェクト、`just` のタスク）
- AI エージェント向けの開発規約（`AGENTS.md`）と、設計判断の記録（`docs/decisions/`）
- 各形式の初版: モデルのスキーマ、アクションの定義、プラグインとの IPC プロトコル

**完了条件**: 5 つの検証すべてに測定結果があり、主要な技術選定（Rust と Swift の橋渡しの方式、IPC の待機方式、描画方式、JSON の書式）が設計判断として記録されている。

**状態**: 2026-10-08 に完了。S1 から S5 まで確定した。

### Phase 1: 打ち込んで、鳴らして、残す（3〜4 か月）

現在の制約は [status.md](status.md)、監査の対応は [資料の入口](README.md) を参照する。以下の「進捗」の実機未実施などの記述は日付時点の記録であり、最新の検証結果ではない。

一通り動く最小の縦切りを作ります。

- モデル、アクション、Undo / Redo、プロジェクトの保存と読み込み、オートセーブ（自動コミット）、操作ジャーナルによるクラッシュ復旧
- エンジン: 再生・停止・ループ（継ぎ目のフェードと、ループの頭の先読みを含む）、メトロノーム、MIDI クリップとオーディオクリップの再生（サンプルレートの変換を含む。既定は rubato）、音量・パン・ミュート・ソロ、マスター、ピークメーター、オーディオデバイスの設定と抜き差しへの追従。トラックの出力は、処理する代わりにプレビュー用キャッシュから読む形に差し替えられるようにしておく（キャッシュの本体は Phase 3）
- CLAP のホスティング（隔離あり）と、プラグインのスキャン。追加、更新、削除をバックグラウンドで検知し、再起動せずに一覧とブラウザへ反映する
- 種別のないトラックと、フォルダトラック
- UI: 3 ペインのレイアウトと開閉、アレンジ画面（Reaper 風のトラックヘッダの基本、クリップのゲインとフェード）、ピアノロール（スマートクリップ、鍵盤とディグリー）、インスペクター、ファイルブラウザ、プラグインブラウザ（基本）、コマンドパレット（あいまい検索）
- テスト用の簡易シンセとサンプラー、波形の表示（ピークは CPU で作り、シェーダーで描く）
- テスト用の最小限の API（JSON-RPC）と、CLI でのレンダリング

**完了条件**: CLAP のシンセを入れたトラックにピアノロールで打ち込んで再生できる。アプリを強制終了しても、再起動で復旧できる。履歴から前の状態に戻せる。同じプロジェクトを CLI で WAV に書き出すと、基準のファイルと一致する。

**進捗（2026-10-11）**: モデル、アクション、保存・ジャーナル、エンジン、隔離、CLI / API と UI の前提検証を実装済み。アプリの最初の骨組みは `swift/EchodeApp`。3 ペインと開閉、プロジェクトの作成・再読込、トラックとノートの追加、Undo / Redo、フォルダのファイル一覧、あいまい検索のコマンドパレットを Rust の製品経路へつないだ。Metal のアレンジは専用スレッドと 3 組のバッファを使い、可視要素をヒットテストとアクセシビリティにも渡す。画面の文字列は日英の String Catalog に置く。`make app` が開発用バンドル、`make spike-app` がメインスレッドの負荷中の描画を確認する。

ピアノロールの左部は長い白鍵と短い黒鍵で描き、その左にスケールのディグリー（I〜VII のローマ数字、スケール外は空欄）を表示する。度数欄は 36 ポイント、鍵盤は 44 ポイント。度数欄を音高ごとの横線で区切り、スケール内はノート背景の白鍵色、スケール外は黒鍵色で塗る。ノートの背景の白黒は通常の鍵盤に固定し、調によって変えない。鍵盤とノートを同じ Metal フレームへ統合した。画面を開かない GPU 検査は 144 フレーム、51,159,360 画素と音高行・度数欄の色・区切り線・空欄の検査で不一致 0（[ADR 0052](decisions/0052-piano-keyboard.md)）。ピアノロールには表示する調と長短調、空白への挿入、ノートの移動・両端からの長さ変更・削除、数値による選択ノートの編集を接続した。ドラッグの確定は 1 回の Undo とジャーナルに記録する。時間と音高で絞る可視問い合わせ、画面外までの論理移動、アクセシビリティの編集操作も追加した。自動クリップ内から伸ばしたノートが別の自動クリップに届く場合の結合（監査 MOD-6）を修正した。表示する調は画面内の設定で、Phase 2 のプロジェクトの調マーカーとは別。今回のピアノロールの実機描画・操作確認は未実施で、computer use は明示許可時のみという方針に従っている。

アプリの再生・一時停止・停止、拍を指定する位置移動、出力機器の選択と現在のサンプルレート・バッファ表示を接続した。停止と一時停止は再生位置を保ち、次の再生はその位置から始まる。ノートは既存の内蔵 Sine Pad で鳴らし、ブロック長を変えても CLI の書き出しとビット単位で一致する。製品の CoreAudio は `echode-audio-io` に分け、公開 API の objc2 の型を使う。機器の通知と再設定、計画の組み立て・解放は文書の制御スレッドで行う。アレンジとピアノロールの再生位置は、描画スレッドが Rust のアトミックな位置を読む。無音の実機接続・停止検査は `make spike-audio`。画面での操作・描画確認は明示許可がないため未実施。

アプリから CLAP を選び、トラックのミキサーの前へ挿入できるようにした。識別はパスではなく CLAP の ID で、パッケージの版は 2 である。スキャンはヘルパープロセスが行い、本体はバンドルを読み込まない。ダブルクリックと挿入ボタンでは成功後にブラウザを閉じ、Return では選択した行を挿入して開いたままにする。

再生は、キャッシュにある CLAP をデバイスごとにヘルパーへ渡す。最初の楽器は内蔵シンセを置き換え、配置音声をその出力へ加える。エフェクトと後続デバイスは前段の音を受け取る。モノは等電力でステレオへ分け、ステレオは左右を保ってフェーダーへ渡す。ステレオのパンはバランスである。ゲイン・パン・ミュート・ソロの変化は 5 ms で補間し、製品のマスターは f64 で加算する（[ADR 0095](decisions/0095-product-audio-buses-and-continuity.md)）。ノートだけの編集ではヘルパーを起動し直さない。サムネイルはまだない。

2026-10-16にトラックの音量・パン・ミュート・ソロ・ピークをヘッダとインスペクターへ接続した。音量・パンのドラッグ中は一時的に試聴し、離すと1回のUndoとして確定する。選択した音声クリップのゲイン・両フェードはハンドルと数値入力で編集できる。フェードのmsと配置のtickは文書のテンポマップで変換する。実Viewの入力・保存の往復と製品バッファの自動回帰を追加し、実表示・聴感はユーザー確認待ちとする（[ADR 0107](decisions/0107-mix-controls.md)）。

UI の配置は、トラックヘッダとタイムラインで表示領域を一つにした。行の高さ・縦の原点・可視範囲を共有するだけでは、AppKit と Metal の表示時刻の差が残ったため、名前を含む左右の描画も一つの Metal フレームへ統合した。入力とアクセシビリティはネイティブの透明な領域で受け取る。配置と入力の単体検査、Rust の可視列との比較、入力を間引いたフレームの保持、画面を開かない GPU の描画と読み戻しを検査した。161 フレーム、50,758 走査線で左右の不一致は 0。実際の画面での描画・操作確認は未実施である（[ADR 0050](decisions/0050-arrange-viewport.md)、[ADR 0051](decisions/0051-arrange-presentation.md)）。

ワークスペースの状態と操作も分離した。選択は文書とノートの ID で管理し、数値入力の下書きと確定値を分ける。メニュー・ツールバー・パレットは同じコマンド経路を使い、検索した行をキーで選べる。ペインの開閉と大きさを保存し、表示を戻した時のカメラを保持する。再生位置の更新は専用の表示部へ閉じ込め、遅れた描画結果の文書・トラック・世代・版を検査する。Phase 2 以降の操作・画面は追加していない（[ADR 0053](decisions/0053-workspace-ui-foundation.md)）。

履歴は、自動保存したコミットを新しい順に一覧し、選んだ版のプロジェクト全体を新しい版として戻せる。元のコミットは残り、戻した操作は Undo できる。今の版と同じ内容は記録しない。トラック単位の復帰と試聴用の画面は後の Phase である（[ADR 0054](decisions/0054-history-restore.md)）。

ループとメトロノームは、プロジェクトの編集ではなく再生の設定としてアプリから操作できる。範囲は拍で指定し、既定は 0 拍から 4 拍である。オンのあいだは範囲の終わりで先頭へ戻り、鳴っているノートを止めてから打ち直す。メトロノームは拍の頭で鳴る。テンポを変えるとサンプル位置を送り直す。ブロック長を変えても出力は一致する。画面での操作確認は未実施である（[ADR 0055](decisions/0055-loop-metronome.md)）。

音声ファイルは AudioToolbox でファイル自身のレートの浮動小数へデコードし、BLAKE3 の正準 PCM として保管する。中身はハッシュ、レート、チャンネル数、フレーム数を記録し、パッケージの版は 3 である。選んだトラックの再生位置へ固定クリップとして置き、デバイスレートへの変換は制御スレッドで行う。ステレオは左右を別々に変換し、再生・書き出しまで保つ。配置音声のループ継ぎ目に最大 5 ms のフェードを接続した。先読みとキャッシュの製品接続、Ogg はまだない（[ADR 0056](decisions/0056-audio-import.md)、[ADR 0095](decisions/0095-product-audio-buses-and-continuity.md)）。

パッケージを開くとき、自動保存の先端が無ければ、復旧したプロジェクトをその場でコミットしてから編集を受ける。確定した編集のあとにプロセスを `_exit` で止めても、再オープンでその編集が残る。最初のコミット自体の途中で落ちた場合は、まだ開いていないので復旧は失敗する。CLI の書き出しは、置いた音声を製品の再生と同じバッファでシンセのあとに足す。ノートだけの基準 WAV はバイト列で一致する。ループとメトロノームは書き出しに含めない。画面での操作確認は未実施である（[ADR 0057](decisions/0057-crash-recovery.md)）。

取り込んだ音声の波形は、正準 PCM から CPU で最小・最大のピラミッドを作り、`cache/peaks/` に置く。アレンジは見えている列だけをシェーダーで描く。1 分のモノラルはリリースビルドで 6.6 ms で、Metal のコンピュートは採用しない。ファイルが無いときはクリップだけを描く。画面での操作確認は未実施である（[ADR 0058](decisions/0058-waveform-peaks.md)）。

プラグインブラウザを開くと、CLAP フォルダの監視を始め、プロセスがいるあいだ変化を一覧へ届ける。変わったバンドルは 2 秒止まってからヘルパーが記述子を読む。最初の一覧よりあとで現れたプラグインには「新着」を付ける。消したバンドルは一覧から外れる。サムネイルと、使用中インスタンスの差し替えはまだしない。画面での操作確認は未実施である（[ADR 0060](decisions/0060-plugin-folder-watch.md)）。

配布バンドルは `project.yml` から Xcode プロジェクトを生成し、`Echode Local` で署名する。ヘルパーは `Contents/Helpers/EchodePluginHost.app` で、library validation を外す権限はヘルパーだけが持つ。証明書が無いときの `make app` はアドホックのまま動く。公証と自動アップデートは Phase 6 のままである。画面での操作確認は未実施である（[ADR 0061](decisions/0061-distribution-signing.md)）。

同じパッケージの二重オープンは拒否し、切れたジャーナルは最後の改行まで戻してから追記する。書き込みに失敗した操作は、次の成功に混ぜない（[ADR 0062](decisions/0062-package-single-writer.md)、監査 AUD-01 / 02 / 03）。

音声スレッドはプラグイン計画の箱を使い回し、イベントはその場で整列する（[ADR 0063](decisions/0063-audio-thread-plan-swap.md)、監査 AUD-04）。製品のコールバックは締め切りを一つだけ使い、独立したトラックを先に依頼する（[ADR 0064](decisions/0064-one-callback-deadline.md)、監査 AUD-07）。

ノートが増えてもプラグインのプロセスは替えず、イベント容量だけを制御スレッドで広げる（[ADR 0065](decisions/0065-plugin-event-capacity.md)、監査 AUD-05）。

鳴っているノートを消したとき、音高だけ変えたとき、再生位置を移したとき、ループが戻ったとき、停止したときに、プラグインへノートオフを届ける。音高の変更は、鳴り始めたキーのまま残す（[ADR 0066](decisions/0066-plugin-note-off.md)、監査 AUD-06）。

トラックのエフェクトは、内蔵シンセと配置した音声を合わせたものを入力にする。楽器はノートと無音を受け、配置した音声はその出力に足してから後段のエフェクトへ渡す（[ADR 0067](decisions/0067-track-audio-into-effects.md)、監査 AUD-08）。

配置の線形ゲインは、準備した音声の各サンプルに掛ける。0 は無音、0.5 は半分、1 はそのまま、2 は 2 倍で、再生と CLI、Undo / Redo、保存・復旧のあとも同じ比になる（[ADR 0068](decisions/0068-clip-gain.md)、監査 AUD-09）。

CLAP を含む書き出しは、再生と同じ隔離したチェインで鳴らす。プラグインかヘルパーが無いときは、内蔵シンセに置き換えず拒否して、欠けた id を出す。ノートだけの基準 WAV はそのままである（[ADR 0069](decisions/0069-plugin-export.md)、監査 AUD-10）。

CLI の書き出しは、文書ホストが復旧したスナップショットを使う。ジャーナルに確定して作業ツリーへ届いていないノートも残り、保存途中で基点が無いパッケージは拒否する。成功した書き出しは、自動保存の版の id を出す（[ADR 0070](decisions/0070-export-recovered-snapshot.md)、監査 AUD-11）。

音声コールバックは、開始順の配置からその区間に重なるものだけを選ぶ。鳴るクリップを 1 つに固定し、10 万個の将来の配置を足しても、2,000 回のコールバックは 1.10 ms と 0.85 ms で、遅くならない（[ADR 0071](decisions/0071-clip-overlap-index.md)、監査 AUD-12）。

`Echode Local` の署名は Hardened Runtime を付ける。本体は外部の動的ライブラリを拒否し、library validation を外す権限はヘルパーだけが持つ。証明書が無いときのアドホック署名には runtime を付けない。公証はしない（[ADR 0072](decisions/0072-hardened-runtime.md)、監査 AUD-13）。

ローカルソケットは、通常ファイルや使用中のソケットを消さない。拒否される古いソケットだけを片付け、接続相手の uid を確かめ、1 行と無応答の待ちに上限を置く（[ADR 0073](decisions/0073-socket-path.md)、監査 API-3）。

**次の作業**: 2026-10-13 の再監査（PRO-01 から PRO-16、および PRO-17）と、2026-10-14 の再監査（REA-01 から REA-10、HAL の期限起点）は対応済みである。同日の Computer Use 監査 CU-01 は [ADR 0091](decisions/0091-playhead-wake.md) で対応し、再検査の実画面で通過した。CU-02 は [ADR 0092](decisions/0092-playhead-spike.md) で、実ウインドウの回帰を `make spike-playhead` へ移した。通常の `make check` はその画面条件で成否が変わらない。`spike-app` の合格条件は変えていない。VST3 / AU には着手しない。Ogg は後のスライスである。クリップ FX はデバイスビューと一緒に実装する。公証は Phase 6 である。

### Phase 2: 制作とミックスの基本（4〜5 か月）

- VST3 と AU のホスティング（バックグラウンドでの検知を含む）、デバイスビュー、プラグインブラウザの完成（サムネイル、自動で閉じる挙動）
- クリップ FX（REAPER の Item / Take FX に相当）: オーディオと MIDI のクリップごとに独立したデバイスチェイン、パラメータ、状態、クリップに追従するオートメーションを持つ。追加・削除・並べ替え、バイパス・オフライン化、チェインのコピーとプリセットに対応する
- ミキサー画面、センドとリターン、フォルダのバス化、サイドチェーン、レイテンシ補正（PDC）
- オートメーション: レーン、オートメーションモード、オートメーションクリップ、書き込みモード
- グローバルマーカー（テンポ・拍子・キー）、リージョン
- 録音: MIDI（QWERTY キーボードと外部 MIDI 機器、ループ中の重ね録り）、オーディオ（単一テイク）、クオンタイズ、MIDI コントローラーへのパラメータ割り当て
- ピアノロールのゴーストノートとトラックセレクター
- 内蔵デバイスの基本セット、LUFS とトゥルーピークのメーター
- 書き出し（各種形式、ステム、ノーマライズ、ディザ）。CLI のプロセスで実行するので、書き出し中も編集を続けられる
- サンプルレート変換の選択肢（再生用と書き出し用）。r8brain-free-src、soxr、zita-resampler、libsamplerate、macOS の AudioConverter を測って加える
- プリセット、テンプレート、見つからないファイルの再リンク、「収集して保存」

- 最小限の MCP サーバー（以降は AI エージェントが Echode を直接操作して動作を確認できる）

クリップ FX は、例えば同じボーカルトラックの最後の 1 フレーズだけにディレイをかけるために使う。処理はクリップごとに行ってからトラックへ合流する。MIDI のクリップでは MIDI エフェクトと楽器も置ける。トラック側の楽器が作る音にオーディオ FX をかけたい場合は、トラック FX を使うか、楽器とオーディオ FX をクリップ側に置く。プラグインの対応形式と隔離方針はトラック FX と共通にする（[ARCHITECTURE §4.8](ARCHITECTURE.md#48-クリップ-fx)、[ADR 0059](decisions/0059-clip-fx.md)）。

クリップの FX ボタン、コンテキストメニュー、コマンドパレットから開き、ブラウザからクリップへ直接ドロップできる。下部のデバイスビューには「トラック」と「クリップ」の対象と名前を表示する。移動・複製・分割では FX とオートメーションを引き継ぐ。中身をリンクした複製でも FX は独立させる。スマートクリップへ最初の FX を追加すると配置を固定し、自動結合で別の音作りが失われることを防ぐ。

PDC はクリップからトラックへの合流も対象にし、クリップの終端後も設定した範囲の余韻を鳴らす。編集、Undo / Redo、保存・復旧、CLI の書き出しで同じチェインと状態を扱う。Phase 2 ではクリップ FX の結果を新しいオーディオの中身・配置として取り込むバウンスも用意し、元の素材と FX を保ったまま Undo できる。Phase 3 のプレビュー用キャッシュとフリーズにもクリップ FX を含める。

**完了条件**: 作者自身が、打ち込みからミックスまで 1 曲を Echode だけで作れる。クリップ FX は、特定のクリップだけへの適用、移動・複製・分割後の状態とオートメーションの保持、余韻と PDC、Undo / Redo と保存・復旧、再生と書き出しの一致を自動検査で確かめる。

## 5. 後回しにする機能と、最初に入れておく布石

要件リストにない追加機能は、どれも 1.0 以降に回します。ただし、後から入れると土台を作り直すことになるものは、データ構造やインターフェースだけを先に用意しておきます。

| 機能 | 最初に入れておく布石 |
|---|---|
| クリップランチャー（Session View） | クリップを配置と切り離して持つ。トラックの再生元を「タイムライン」と「ランチャー」で切り替えられる構造にする |
| サラウンド / Dolby Atmos / 空間オーディオ | チャンネル数に加えて、スピーカー配置（アンビソニックスを含む）をデータとして持つ |
| 動画トラック | 時間を flick で持ち、フレーム単位で正確に扱えるようにする |
| ARA2（Melodyne などとの連携） | メディアの保管場所をヘルパープロセスからも読めるようにし、音声データへのアクセスを抽象化する |
| コントロールサーフェス（MCU / HUI / OSC） | 全パラメータに安定したアドレスを振り、アクションとパラメータの API から制御できるようにする |
| Ableton Link / MIDI クロック / MTC | トランスポートの時刻源を差し替えられる構造にする |
| AI オーディオ機能（ステム分離、オーディオ→MIDI 変換） | 解析処理を共通のパイプラインにして、Neural Engine で動くモデルを後から差し込めるようにする |
| リアルタイム共同編集 | 全オブジェクトに固定の ID を振り、並び順は分数インデックスで持ち、変更をプロパティ単位の操作として記録する（セマンティック・マージにも必要） |
| ユーザースクリプト（Lua など） | スクリプトは API のクライアントとして作る前提で、API を先に固める |
| 内蔵インストゥルメント、本格的なエフェクト群 | 内蔵デバイスのインターフェースを最初に決め、テスト用シンセと基本エフェクトで検証しておく |
| テイクレーン / コンピング | 録音したテイクはすべて残し、クリップが複数のテイクを参照できるようにしておく。クリップ FX のチェインと状態をテイクごとに保持できる所有関係に拡張する（ARCHITECTURE §4.8） |

## 6. 主なリスクと対策

| リスク | 起きること | 対策 | 確認する時期 |
|---|---|---|---|
| プラグイン隔離の通信コスト | 小さいバッファで CPU を食い、音切れする | 同じプロセス内で続くデバイスはまとめて 1 往復で処理する。Audio Workgroup を共有する。プロセスの分け方を選べるようにする | Phase 0（S3） |
| プラグインの互換性 | 別プロセスで動かすと、一部の機能が動かない（同じメーカーのプラグイン同士の連携など） | 既定ではメーカー単位でプロセスをまとめる。無料プラグインで互換性の確認表を作る | Phase 1 から継続 |
| 開発の規模 | ひとり＋AI では全部が終わらない | フェーズごとの完了条件を守り、追加機能は §5 のとおり後回しにする | 常に |
| 独自描画の UI とアクセシビリティ | Metal で描いた部分は、そのままでは VoiceOver から見えない | 描画と並行してアクセシビリティ要素の木を作る設計にし、Phase 1 から組み込む | Phase 1 |
| 履歴の容量と速度 | 自動コミットが積み重なってリポジトリが膨らむ | 音声ファイルは Git に入れず、別の保管庫で管理する。自動保存の履歴は時間とともに間引く | Phase 0（S4） |
| プレビュー用キャッシュの容量 | ディスクを圧迫する（48 kHz のステレオで 1 分あたり約 23 MB）。裏のレンダリングで、大きな音源が 2 重に読み込まれる | 容量の上限を設け、使われていないものから消す。レンダリングは 1 トラックずつ行い、終わったら解放する | Phase 3 |
| タイムストレッチの品質 | 素材によっては、伸縮した音が劣化する | Rubber Band、Signalsmith Stretch、Bungee を比較評価し、ほかに完全に劣るもの以外はすべて選べるようにする（§2.1） | Phase 4 の前 |
| 公証なしの配布 | インストールの手間で利用者が離れる | 手順を丁寧に案内する。将来 Developer Program に加入すれば公証できる構成にしておく | Phase 6 |
| オンデバイス LLM の制約 | 文脈長が短い。Apple Intelligence が無効な環境では使えない | 関係するアクションだけを検索して渡す。使えない環境では通常のコマンドパレットとして動かす | Phase 5 |
| OS とフレームワークの変化 | macOS の更新で UI や API の挙動が変わる | 非公開 API を使わない。OS に依存する部分を薄い層に閉じ込める | 常に |

## 7. AI エージェント前提の進め方

具体的な作業の入口は [開発手順](development.md)、検査は [検査手順](verification.md)、再現と証拠の収集は [デバッグ手順](debugging.md) に置く。AGENTS は必須規則、PLAN は方針、ADR は判断、日付付き監査は発見時の証拠を持つ。検査対応を複数の文書へ複製しない。

ひとりで製品品質を保つには、AI エージェントが自分の変更を自分で検証できることが前提になります。

- **規約を明文化する**: リポジトリ直下の `AGENTS.md` に、モジュールの境界、リアルタイム処理での禁止事項、命名、テストの実行方法を書きます。
- **設計判断を残す**: 重要な判断は `docs/decisions/` に ADR として記録し、エージェントが経緯を読めるようにします。
- **ヘッドレスで検証する**: エンジンは CLI でレンダリングし、基準の音声と比べます（ゴールデンテスト）。UI はオフスクリーンで描いた画像を比べます。
- **ランダムな操作で壊してみる**: ランダムなアクション列を流し、Undo / Redo の対称性、保存と読み込みの往復、マージの性質を検査します（プロパティベーステスト）。
- **わざと壊れるプラグインを用意する**: クラッシュ、ハング、メモリ確保、大量のパラメータ送信をするテスト用の CLAP プラグインで、隔離の仕組みを常に検査します。
- **MCP で操作して確かめる**: Phase 2 以降は、開発中の Echode を Cursor のエージェントが MCP 経由で操作して動作を確認します。
- **1 つの入口で確認する**: エージェントは着手時に `make verify-plan`、変更を終えたら `make verify` を実行します。通常の検査と変更箇所に応じた追加検査を選び、計測や実機検査の未実行理由も記録します。対応は `scripts/verification.json` に一つだけ置き、終了フックと CI も共有します。詳細は [検査の手順](verification.md)。

## 8. 開発を始める前に必要な準備

1. **Xcode 27 のインストール（必須）**: 今は Command Line Tools だけが入っていて、Swift も 6.2.1 と古い版です。アプリのビルド、Metal シェーダーのコンパイル、Instruments での性能計測に Xcode 27（Swift 6.4）が必要です。App Store から無料で入手できます。
2. **開発用の自己署名証明書（推奨）**: アドホック署名のままだと、ビルドのたびにマイクなどの許可がリセットされます。`make sign-setup` がログインキーチェーンへ `Echode Local` を一度入れます。以降の `make app` と `make dist` はその証明書で署名します。
3. **テスト用の無料プラグイン（Phase 0 の途中から）**: Surge XT、Airwindows Consolidated、Dexed、u-he の無料プラグイン（Podolski、TyrellN6、Protoverb）、Valhalla Supermassive など。

## 9. 後で決めること

- 製品名とロゴ（Echode はコードネーム）
- GitHub でリポジトリを公開する時期（GPL なので、遅くともバイナリを配布する時にはソースも公開する）
- ショートカットの細かい割り当てと、テーマ（配色）のデザイン
- プロジェクトファイルの拡張子（仮に `.echode`）
- 自動保存の間隔と、履歴を間引く規則の初期値
- リアルタイムで動かせない高音質の方式（Rubber Band のオフラインモードなど）を、再生でも聴けるようにするか。今は書き出しでだけ選べる（§2.1）。クリップごとに裏でレンダリングして鳴らす案は、効果が測れていないのに、ディスクと差し替えの管理が増えるので見送った。Phase 4 の前のタイムストレッチの比較で差が大きければ、プレビュー用キャッシュを作る時にだけその方式を使う形（ディスクは増えない）を検討する
