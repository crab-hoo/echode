# Echode 開発計画

- 版: ドラフト v0.1（2026-10-07）
- 対象: macOS 27 Golden Gate 以降、M4 ファミリー以降の Apple Silicon 専用（[ADR 0112](decisions/0112-m4-minimum.md)）
- 技術設計: [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 目指すもの

Echode は macOS 専用の、フリーかつオープンソースの DAW です。
打ち込み中心の制作と、ミキシング・マスタリングを主な用途にします。
既存の DAW とは次の 3 点で差をつけます。

1. **止まらない。**
   プラグインは別プロセスで動かすので、プラグインがクラッシュしても本体と他のトラックは鳴り続けます。
   操作はすべて記録しているので、強制終了しても直前の操作まで復旧できます。
   読込み・保存・解析・レンダリングなどの処理中も GUI の応答と無関係な編集を保ち、作業を続けられることを目指します。
   描画の継続だけで達成とせず、入力・編集の受付も確認します
   （[操作要件](interaction-design.md#処理中も作業を続ける)）。
   障害が起きた時は、最小の範囲で静かに安全側へ倒し、何が起きて何をしたかを隠さず、普段の操作で戻せるようにします
   （Calm Technology・Fail-Safe・Frictionless Recovery・Transparent、[ADR 0281](decisions/0281-calm-transparent-failure.md)）。
2. **履歴を意識しなくてよい。**
   プロジェクトはプレーンテキストで保存し、裏で Git が管理しますが、ユーザーに Git は見せません。
   Time Machine のような画面で過去の状態を試聴して戻せ、別アレンジは「オルタネイト」として並べて管理できます。
3. **Mac に最適化している。**
   リアルタイムエンジンは Rust で、UI は Swift と Metal で作ります。
   トラックパッドのジェスチャー、触覚フィードバック、感圧入力、オンデバイス LLM まで、Mac のハードウェアと OS の機能を活かします。

### 1.0 の合格基準

「製品品質」を次の基準で定義します。

| 観点 | 基準 |
|---|---|
| 安定性 | プラグインがクラッシュやハングをしても本体が落ちない（自動テストで常に検証する） |
| データの保全 | 強制終了や電源断のあとでも、最後に確定した操作まで復旧できる |
| 音声処理の性能 | 100 トラック規模のプロジェクトで、エンジン自体の処理時間（プラグインを除く）が 128 サンプル / 48kHz の 1 ブロックの 10% 未満 |
| 描画の性能 | 1,000 トラック・10 万ノートでも、スクロールとズームがディスプレイのリフレッシュレートに追従する |
| 上限 | トラック数、プラグイン数、チャンネル数、ネストの深さに固定の上限がない（上限は CPU とメモリだけ） |
| アクセシビリティ | VoiceOver とキーボードだけで主要な操作が完結する |
| 実用性 | 作者自身が 1 曲を Echode だけで完成させられる |

| 外部の AI との連携 | MCP サーバーを提供する | Claude や Cursor などのエージェントから Echode を操作できる |
| 主な用途 | 打ち込み中心の制作、ミキシング / マスタリング | 録音、映像、ライブは優先度を下げる |
| 開発体制 | ひとり＋AI エージェント | AI が自分の変更を自分で検証できる仕組みを最初に作る（§7） |
| 配布 | Apple Developer Program に加入せず、GitHub Releases で配布する | 初回起動時は「システム設定 → プライバシーとセキュリティ」で許可する |
| 言語 | UI は日本語と英語。計画書と設計書は日本語、コードとコメントは英語 | |

### 2.1 ライセンス方針の影響

GPL-3.0-or-later にしたので、GPL-3.0 と両立するライセンスのライブラリなら組み込めます。

- **使える**: 寛容なライセンス（MIT、BSD、Apache-2.0、ISC、zlib など）、MPL-2.0、LGPL、GPL-2.0-or-later、GPL-3.0、AGPL-3.0
- **使えない**: GPL-2.0-only（版 2 に限ったもの）、宣伝条項付きの BSD、EPL、CDDL、ソース非公開のライブラリ。MPL-2.0 でも「Incompatible With Secondary Licenses」と表示されたファイルは使えない
- AGPL-3.0 のライブラリを入れると、ネットワーク越しに使わせる場合のソース公開条件（AGPL 第 13 条）が加わる
- Apple のシステムフレームワーク（CoreAudio、Metal、Foundation Models など）は、GPL のシステムライブラリ例外に当たるので使える
- プラグインのライセンスは問わない（利用者が手元でプラグインを読み込むことには GPL の配布条件は及ばない）
- バイナリを配布する時は、同じ版のソースを公開し、同梱したライブラリのライセンス表記を付ける

確認済みの主な候補は次のとおりです。

| 用途 | ライブラリ | ライセンス |
|---|---|---|
| CLAP | CLAP SDK、clack（Rust バインディング） | MIT、MIT OR Apache-2.0 |
| VST3 | VST3 SDK 3.8、vst3 crate | MIT、MIT OR Apache-2.0 |
| タイムストレッチ | Rubber Band、Signalsmith Stretch、Bungee | GPL-2.0-or-later、MIT、MPL-2.0 |
| サンプルレート変換 | rubato、r8brain-free-src、soxr、zita-resampler、libsamplerate、AudioConverter | MIT OR Apache-2.0、MIT、LGPL-2.1+、GPL-3.0+、BSD-2-Clause、システム |
| テスト用の発振器とサンプラー | wavesynth、dasp、fundsp、rustysynth、oxisynth、FluidSynth、sfizz | MIT OR Apache-2.0、MIT、LGPL-2.1、LGPL-2.1+、BSD-2-Clause |
| デコード | Symphonia（macOS の AudioToolbox と併用） | MPL-2.0 |
| Git | gitoxide（gix） | MIT OR Apache-2.0 |
| アプリ間のテンポ同期 | Ableton Link | GPL-2.0-or-later |
| MP3 のエンコード | LAME | LGPL |

使えるライブラリが多いことを活かすため、次の方針で取り込みます（[ADR 0014](decisions/0014-existing-implementations-as-options.md)）。

- サンプルレート変換やタイムストレッチのように定番の実装がある処理は、自作する前に既存の実装を調べて測る
- ほかの選択肢に完全に劣るものを除き、できるだけ多くをユーザーが選べるようにする（既定はそのうちの 1 つにする）
- 自作するのは、既存の実装が要件を満たさない時か、測って上回る点がある時に限る（理由と測定値を ADR に書く）
- オーディオスレッドで動かす選択肢は、ロック・メモリ確保・待機禁止を守る。守れないものはオフライン処理（書き出し等）専用にする
- プロジェクトには選んだ実装を ID と版で記録し、開いた環境にない時は既定に置き換えて通知する
- Git や JSON のように結果が変わらない土台のライブラリは選択肢にしない

### 2.2 置いた前提

- 複数のプロジェクトを同時に開けるが、音を出すのは前面のプロジェクトだけにする（切り替えは即時）。
- 内部の信号処理は 32bit 浮動小数点で行い、ミックスの加算だけ 64bit で行う。
- 最初から入れる内蔵デバイスは最小限にする（ユーティリティ、EQ、コンプレッサー、リミッター、ゲート、メーター類、テスト用の簡易シンセとサンプラー）。
- 保存確認ダイアログは出さない（常時自動保存）。Cmd+S は「名前付きの保存ポイントを作る」操作になる。
- ミキサー画面（コンソール表示）は Phase 2 で作る。

## 3. アーキテクチャの要約

詳細は [ARCHITECTURE.md](ARCHITECTURE.md) と `docs/architecture/` 配下の領域別設計書にまとめています。

- **プロセス構成**: `Echode.app`（Swift UI + Rust コア・エンジン）、プラグインヘルパープロセス群、ヘッドレスの `echode` CLI（バウンス、フリーズ、自動化、MCP）の 3 種類。
- **モデルが唯一の真実**: ドキュメントモデルは Rust 側に置き、変更のたびに不変のスナップショットを作る。UI、エンジン、履歴、API はロックなしで並行に読める。
- **すべての操作はアクション**: マウス、ショートカット、コマンドパレット、API、LLM、MCP はすべて同じアクションを呼ぶ。Undo、マクロ、クラッシュ復旧ジャーナルもこの仕組みに乗る。
- **時間は整数で持つ**: 音楽時間は 1 拍 = 705,600 tick、実時間は 1 秒 = 705,600,000 flick で表し、丸め誤差を出さない。
- **リアルタイムスレッドは何も待たない**: ロック、メモリ確保、ファイル I/O、GPU の完了待ちを禁止し、プラグインとの共有メモリ往復も締め切りを超えればそのブロックだけ無音にして進む。
- **ヘッドレスで全機能が動く**: バウンスやフリーズは CLI プロセスがスナップショットを読んで実行し、その間も編集を続けられる。

### Phase 0: 土台づくりと技術検証（完了）

### Phase 1: 打ち込んで、鳴らして、残す（完了）

- モデル、アクション、Undo / Redo、保存・読み込み、オートセーブ（自動コミット）、操作ジャーナルによるクラッシュ復旧
- エンジン: 再生・停止・ループ（継ぎ目フェードとループ先頭の事前保持を含む）、メトロノーム、MIDI / オーディオクリップ再生（既定 SRC は `rubato`）、音量・パン・ミュート・ソロ、マスター、ピークメーター、出力デバイス設定と追従、フェーダー前のキャッシュ差し替え口（`CachedTrack`）
- CLAP の別プロセスホスティングとバックグラウンドフォルダ監視・スキャン
- 種別のないトラックとフォルダトラック
- UI: 3 ペインのレイアウトと開閉、Metal アレンジ画面（トラックヘッダとタイムラインの一体描画、クリップのゲイン・フェード）、ピアノロール（スマートクリップ、鍵盤とディグリー）、インスペクター、ファイルブラウザ、プラグインブラウザ、コマンドパレット
- テスト用簡易シンセ、波形ピーク生成（CPU ピラミッド + Metal シェーダー描画）、JSON-RPC API、CLI での WAV レンダリング

**完了条件**: CLAP のシンセを入れたトラックにピアノロールで打ち込んで再生できる。アプリを強制終了しても再起動で復旧できる。履歴から前の状態に戻せる。同じプロジェクトを CLI で WAV に書き出すと基準ファイルと一致する。

**状態**: 2026-10-17 に完了（[最終照合](reviews/2026-10-17-phase1-acceptance.md)、[現在の範囲と制約](status.md)）。
Phase 1 期間中の各機能の設計判断と監査対応は [ADR 0048](decisions/0048-clap-device.md)〜[ADR 0114](decisions/0114-m4-build-baseline.md) および [監査の読み順](README.md#監査の読み順) を参照する。

### Phase 2: 制作とミックスの基本（進行中・目安 4〜5 か月）

2026-10-17 に開始。依存関係に沿った着手順と各単位（P2-01〜P2-09）の受入条件は [Phase 2 の進め方](phase2.md)、制作フローの操作要件は [制作ワークフローとインタラクション](interaction-design.md)（[ADR 0117](decisions/0117-workflow-interactions.md)）、実装の現状は [status.md](status.md) を参照する。

- VST3 と AU のホスティング（バックグラウンド検知を含む）、デバイスビュー、プラグインブラウザの完成（サムネイル、非モーダル候補とチェイン操作、[ADR 0118](decisions/0118-track-fx-chain-editing.md)）
- クリップ FX（REAPER の Item / Take FX 相当）: オーディオと MIDI クリップごとの独立デバイスチェイン、パラメータ、状態、追従するオートメーション、余韻と PDC、別トラックへのバウンス取り込み（[ARCHITECTURE §4.8](ARCHITECTURE.md#48-クリップ-fx)、[ADR 0059](decisions/0059-clip-fx.md)）
- ミキサー画面、複数選択トラックの相対音量・パン・一括ミュート／ソロ、センド／リターン（FX 後・フェーダー前 0 dB、送り元ミュートで停止、ソロ時の関連リターン連動）、フォルダのバス化、サイドチェーン、PDC
- オートメーション: レーン、オートメーションモード（有効時は全トラックのクリップ領域を曲線表示へ置換、無効時は最上段レーンに表示）、オートメーションクリップ、書き込みモード、手動試聴後の曲線値復帰
- グローバルマーカー（テンポ・拍子・キー）、ループ区間からのリージョン作成と全トラック編集区間選択
- 録音: MIDI（QWERTY / 外部 MIDI、ループ重ね録り）、オーディオ（単一テイク）、クオンタイズ、MIDI 割り当て
- ピアノロールのクリック・ドラッグ入力、入力長とベロシティの共通記憶、ゴーストノートとトラックセレクター、Option＋上下ドラッグと下部レーンによるベロシティ編集、記憶する再生開始位置と停止／一時停止の分離
- アレンジの枠選択と区間選択、部分コピー・貼付け・削除・複製、重ねる／置き換えるの切替、同トラック配置の自動クロスフェードと分割・トリム時の短いフェード
- 共通サンプルブラウザのフォルダ移動・ファイル名検索、単発試聴、再生ヘッド位置への音声配置、トラック追加・複製
- フォルダ型の内蔵ドラムラック: 親に MIDI、音ごとの子にサンプラーとサンプルを持ち、サンプルのドロップによる子作成・差替え、ADSR ゲート再生とワンショット切替、子・親のミックスを接続する（[ADR 0116](decisions/0116-folder-drum-rack.md)）
- 内蔵デバイスの基本セット、LUFS とトゥルーピークのメーター
- 書き出し（各種形式、ステム、ノーマライズ、ディザ、CLI 別プロセス実行）と SRC 選択肢の比較追加
- プリセット、テンプレート、再リンク、「収集して保存」、履歴 UI 初版（一覧・復帰・自動要約・タグ）、定期バックアップ
- トラックパッドのジェスチャーと触覚フィードバック、ホットコーナー、初期ショートカット
- 最小限の MCP サーバー（ヘッドレス版は P2-01 で実装済み、[ADR 0115](decisions/0115-phase2-mcp.md)）

**完了条件**: 作者自身が、打ち込みから構成・編曲、ミックス、書出しまで 1 曲を Echode だけで作れる。クリップ FX は特定のクリップへの適用、移動・複製・分割後の状態とオートメーション保持、余韻と PDC、Undo / Redo と保存・復旧、再生と書き出しの一致を自動検査で確かめる。

### Phase 3: Echode らしさ ①「音作り」（4〜5 か月）

- モジュレーション: LFO、エンベロープフォロワー、数式など（Bitwig 方式：オートメーションをベース値とし、モジュレーターが加算・乗算する）
- CLAP のポリフォニック・モジュレーション（ノートごとの変調）
- コンテナ（並列チェイン）とマクロのフロントパネル
- 静的チャンネル（トラックごとに任意のチャンネル数）とピンのルーティング、オーディオレシーバー
- MPE: ピアノロール内のマイクロレーン編集と、キーボード＋トラックパッドによる疑似 MPE 入力
- プレビュー用キャッシュ（編集停止時に裏でトラックを書き出し、再生で差し替える）とフリーズ、オフライン化、先読み処理

**完了条件**: Bitwig で作るような、変調を中心にしたサウンドデザインが Echode だけでできる。

### Phase 4: Echode らしさ ②「履歴・アレンジ・オーディオ編集」（4〜5 か月）

- オルタネイト（裏では Git のブランチ）と、トラック単位のセマンティック・マージ
- 複数プロジェクトの同時オープンと、別プロジェクトのトラックを D&D で取り込む機能
- Time Machine 風の履歴 UI: 過去の版の試聴と、全体または一部トラックだけの復帰
- オーディオエディタ: ワープマーカー、スライス、トランジェントごとのピッチ編集、複数のストレッチアルゴリズム
- テンポとキーの検出（GPU 解析）、ループ素材の BPM 推定・テンポ追従・Option＋端ドラッグ伸縮・クリップごとの伸縮方式選択（[希望操作](interaction-design.md#オーディオクリップとテンポ)）
- マルチトラック EQ、コード検出とコードトラック、アーティキュレーション、トラックの自動色分け

**完了条件**: サビの別アレンジを作って聴き比べ、良い方のトラックだけをメインに取り込める。

### Phase 5: 外部制御と AI（2〜3 か月）

- 全アクションを外部から呼べる API、CLI、ヘッドレスモード、MCP の完成
- コマンドパレットへの自然言語入力（Foundation Models がアクション列の実行計画を作り、確認後に単一 Undo 単位で実行する）
- マクロ（アクションの記録と再生）、マウスコマンドとショートカットの編集画面

**完了条件**: 外部の AI エージェントが MCP 経由で曲の土台を作れ、自然言語で複数手順の操作を実行できる。

### Phase 6: 1.0 に向けた仕上げ（3〜4 か月）

- アクセシビリティの監査（VoiceOver、キーボード操作、色覚、コントラスト）
- 日本語と英語の UI（String Catalog による翻訳仕上げ）、ユーザーマニュアル
- 性能の最適化、長時間の耐久テストと長時間のファジング、プラグイン互換性の確認表
  （外部入力の fuzz の対象と全体の段階の短い実行は Phase 2 で置いた。[ADR 0290](decisions/0290-fuzz-targets-for-external-input.md)）
- 配布（GitHub Releases、自動アップデート、インストール手順の案内）

**完了条件**: §1 の合格基準をすべて満たす。

## 5. 後回しにする機能と、最初に入れておく布石

| 機能 | 最初に入れておく布石 |
|---|---|
| クリップランチャー（Session View） | クリップを配置と切り離して持ち、トラックの再生元を「タイムライン」と「ランチャー」で切り替えられる構造にする |
| サラウンド / Dolby Atmos / 空間オーディオ | チャンネル数に加えてスピーカー配置（アンビソニックスを含む）をデータとして持つ |
| 動画トラック | 時間を flick で持ち、フレーム単位で正確に扱えるようにする |
| ARA2（Melodyne 連携） | メディアの保管場所をヘルパーからも読めるようにし、音声データアクセスを抽象化する |
| コントロールサーフェス（MCU / HUI / OSC） | 全パラメータに安定したアドレスを振り、アクションとパラメータの API から制御できるようにする |
| Ableton Link / MIDI クロック / MTC | トランスポートの時刻源を差し替えられる構造にする |
| AI オーディオ機能（ステム分離、音声→MIDI） | 解析処理を共通パイプラインにし、Neural Engine モデルを後から差し込めるようにする |
| リアルタイム共同編集 | 全オブジェクトに固定 ID、並び順に分数インデックスを使い、変更を操作として記録する |
| ユーザースクリプト（Lua など） | スクリプトは API のクライアントとして作る前提で、API を先に固める |
| 本格的な内蔵音源・エフェクト群 | 同梱音源も隔離プラグインとして共通チェインに置き、Sine Pad と基本エフェクトで検証する（ADR 0123） |
| テイクレーン / コンピング | 録音テイクをすべて残し、クリップ FX のチェインと状態をテイクごとに保持できる所有関係に拡張する（ARCHITECTURE §4.8） |

構成編集のマグネティックタイムラインは将来の検討候補として保持し、Phase 2 の通常編集は後続時刻を保つ。

## 6. 主なリスクと対策

| リスク | 起きること | 対策 | 確認時期 |
|---|---|---|---|
| プラグイン隔離の通信コスト | 小さいバッファで CPU を食い音切れする | 同一プロセス内で続くデバイスは 1 往復で処理し、Audio Workgroup を共有する | Phase 0（S3） |
| プラグインの互換性 | 別プロセス化で一部機能が動かない | 既定ではメーカー単位でプロセスをまとめ、無料プラグインで互換性表を作る | Phase 1〜 |
| 開発の規模 | ひとり＋AI では全部が終わらない | フェーズごとの完了条件を守り、追加機能は §5 のとおり後回しにする | 常に |
| 独自描画 UI とアクセシビリティ | Metal 描画が VoiceOver から見えない | 描画と並行してアクセシビリティ要素の木を作る設計にする | Phase 1〜 |
| 履歴の容量と速度 | 自動コミットでリポジトリが膨らむ | 音声ファイルは Git 外の CAS 保管庫で管理し、自動保存履歴は間引く | Phase 0（S4） |
| プレビュー用キャッシュの容量 | ディスクとメモリを圧迫する | 容量上限と LRU 削除を設け、レンダリングは 1 トラックずつ行う | Phase 3 |
| タイムストレッチの品質 | 素材によって伸縮音が劣化する | Rubber Band、Signalsmith Stretch、Bungee を比較評価し選択肢にする（§2.1） | Phase 4 前 |
| 公証なしの配布 | 初回起動の手間で利用者が離れる | 手順を丁寧に案内し、将来公証にも対応できる構成にしておく | Phase 6 |
| オンデバイス LLM の制約 | 文脈長が短く、無効環境では使えない | 関連アクションだけを検索して渡し、無効環境では通常のパレットとして動かす | Phase 5 |
| OS とフレームワークの変化 | macOS 更新で挙動が変わる | 非公開 API を使わず、OS 依存層を薄く閉じ込める | 常に |

## 7. AI エージェント前提の進め方

具体的な作業手順は [開発手順](development.md)、検査は [検査手順](verification.md)、診断は [デバッグ手順](debugging.md) に置く。

- **規約と設計判断の明文化**: `AGENTS.md` に必須規則、`docs/decisions/` に ADR を記録する。
- **ヘッドレス検証とプロパティテスト**: CLI の基準 WAV 比較、オフスクリーン GPU 描画比較、ランダムなアクション列による不変条件・Undo / Redo・保存往復テストを常時回す。
- **故障注入プラグイン**: クラッシュ・ハング・確保・大量イベントを起こす `echode-test-plugin` で隔離を検証する。
- **単一入口の確認**: 着手時に `make verify-plan`、完了時に `make verify`、節目に `make verify-full` を実行し、`scripts/verification.json` の単一ポリシーをエージェントと CI で共有する。

## 8. 開発環境の準備

1. **Xcode 27（Swift 6.4）**: アプリと Metal シェーダーのビルドに必須。
2. **開発用の自己署名証明書**: `make sign-setup` でログインキーチェーンへ `Echode Local` を作成する。
3. **テスト用の無料プラグイン**: Surge XT、Airwindows Consolidated、Dexed、u-he 無料プラグイン、Valhalla Supermassive など。

## 9. 後で決めること

- 製品名とロゴはユーザーが決める。決まるまで Echode を仮名、`.echode` を仮の拡張子とする。
- ショートカットの詳細、テーマ配色、自動保存と履歴の間引きの初期値は、エージェントが決める（[ADR 0276](decisions/0276-priority-order-and-delegated-decisions.md)）。
- GitHub での公開は 2026-11-05 に決めた（[ADR 0269](decisions/0269-github-public-ci-scope.md)）。製品名は公開後も未定のまま。
- オフライン専用の高音質タイムストレッチを Phase 3/4 のプレビュー用キャッシュ生成時にも選べるようにするか（Phase 4 前の比較測定で判断する）。
